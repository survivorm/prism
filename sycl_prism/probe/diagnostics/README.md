# Диагностические скрипты (16.11.2026)

Это **инструменты расследования**, а не часть прибора. Основной прибор —
`../src/`, `../py/`, `../probe/*.cpp`; всё, что нужно для сборки и паритета,
живёт уровнем выше. Здесь лежит то, что помогло найти дефект, и что можно
переиспользовать, если класс дефекта повторится.

**Зачем они здесь, а не удалены:** дефект, найденный 16.11.2026, был
**тихим** — ни один изолированный тест его не видел, все гейты были зелёными.
Диагностика обязана оставаться воспроизводимой: тот, кто захочет проверить
вывод, должен иметь возможность запустить то же самое.

## Что здесь

| Файл | Что делает |
|---|---|
| `bisect_header3.py` | **Главный воспроизводитель.** Берёт **точный** текст проб из `src/prism_sycl_compat.h` и собирает из него namespace, сравнивая с эталонной пробой. Показывает, что опечатка в имени члена (`fence_scope` вместо `fence_space`) тихо превращала `true` в `false`. |
| `bisect_header.py` | Бисекция «вырезать блок из header'а» — локализует, какой именно блок влияет на ответ пробы. |
| `bisect_header2.py` | Бисекция «наращивание»: собирает namespace блок за блоком и смотрит, на каком шаге ответ меняется. |
| `bisect_sfinae.cpp` | Сравнение четырёх написаний одной идеи (алиас / `decltype` / конкретный тип / `requires`) — показывает, что все четыре эквивалентны, если написаны правильно. |
| `probe_sfinae_replica.cpp` | Тот же вопрос в виде отдельной пробы: печатает значения всех форм барьера. |

## Как запускать

Все скрипты используют **относительные** пути (корень дерева вычисляется от
расположения файла) ⇒ их можно запускать откуда угодно:

```bash
python3 probe/diagnostics/bisect_header3.py
```

Требуется только `g++` (и `python3`). GPU, `icpx` и oneAPI **не нужны**.

## Ожидаемый вывод (после исправления)

```
A) alias из header'а + ЭТАЛОННАЯ проба      : 1
B) alias из header'а + ТОЧНАЯ проба header'а: 1
C) свой alias      + ТОЧНАЯ проба header'а: 1
...
```

**Если в `B` снова появится `0`** — опечатка вернулась (или появилась новая):
две семантически одинаковые пробы разошлись ⇒ это тот же класс дефекта.

## Чего эти скрипты НЕ делают

* Не проверяют поведение на **карте** — для этого `probe/probe_kernel_name.cpp`
  (шаг 1c-3) и `probe/probe_local_mem.cpp` (шаг 1d) из уровнем выше.
* Не являются частью гейта: гейт их не запускает, чтобы он не зависел от
  Python-скриптов с побочными эффектами.
