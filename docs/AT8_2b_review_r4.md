## 2. Мажорные

### F1 ⚠️ LEARN_ASYMM измеряется на n=16, а читается для E_phr@n2 — тот же класс, что M3

§9 дословно:
> «если `block-CE_L2(16) / block-CE_L1(16) > 3` ИЛИ `< 1/3` → тег `LEARN_ASYMM`»

§17 дословно:
> «`LEARN_ASYMM` — phrase2 обучается иначе phrase1: **E_phr** читается с оговоркой «содержимое + обучаемость»»

E_phr primary = **n=2**. Оговорка для контраста на n=2 измеряется на n=16 — ровно дефект, который вы только что закрыли для слойного тега (M3), но в другом месте.

**Хуже: на n=16 тег практически мёртв.** Пререг-ожидание §9: block-CE_L2(16) ~ 0.3–1.0, L1(16) = 0.38–0.51 → отношение 0.6–2.6, порог 3× не срабатывает никогда. То есть единственная защита интерпретации E_phr от конфаунда обучаемости — недостижимая ветка (G10).

На n=2 обе фразы **не выучены** (L1 = 3.29 док-медиана), и различие обучаемости там реально может быть большим — именно там оговорка и нужна.

**Фикс (цена 0, block-CE обоих фраз на обеих дозах уже в store §13):**
- считать отношение на **обеих** первичных дозах, тег привязать к дозе контраста (`LEARN_ASYMM_N2` для E_phr, `LEARN_ASYMM_N16` для контекста REP);
- порог 3× калиброван на n=16 (обе у пола) — на n=2 он не осмыслен; либо объявить доз-специфичный порог, либо отчитывать отношение как непрерывную диагностику и conditioning чтения на нём.

### F2 ⚠️ Дозовый тег: формула требует 4 дозы, доступно 2 → мёртвый enum или IndexError

§9: «Дозовый тег L2 (по док-медианным, **как R2 §9**): DOSE_FLAT / DOSE_SATURATING / DOSE_MONOTONIC / DOSE_NOT_RESOLVED».

Правило R2 §9:
```
FLAT:       I16/I2 ≤ 2
SATURATING: I16/I2 > 2  И  I16/I8 ≤ 2
MONOTONIC:  I16/I8 > 2  И строго растёт на каждом шаге
```

Дозы 2b = **{2, 16}**. `I16/I8` не определено (n=8 не гоняется, §9 явно). Два исхода при имплементации:
- кодер переносит `_dose_tag` verbatim с `N_DOSE=[2,4,8,16]` → `vals = [v2, None, None, v16]` → `any(v is None)` → **DOSE_NOT_RESOLVED навсегда**;
- кодер берёт `vals` по фактическим дозам (длина 2) → `vals[3]` → **IndexError**.

В обоих случаях `DOSE_SATURATING` — недостижимое значение enum, объявленное в пре-реге. Прямое нарушение G10 («пре-рег перечисляет ≥2 достижимых исхода; ни один не форсирован тождеством»).

**Фикс:** переписать правило под 2 дозы явно:
```
I16/I2 ≤ 2                → DOSE_FLAT
I16/I2 > 2 и I16 > I2      → DOSE_MONOTONIC
иначе / не-finite          → DOSE_NOT_RESOLVED
DOSE_SATURATING            → удалён (требует промежуточной дозы)
```
И убрать «как R2 §9» — ссылка на несовместимую формулу и есть источник ловушки.

## 3. Умеренные

### F3. `δ_L(C)` используется в §11, но не определён per-layer в §8

§11 шаг 6: ««значим» = `near_C_L > δ_L(C)` (порог своего контраста на своём слое)». §8 определяет `δ_PHR/δ_REP` **без слоевого индекса** (28 значений = 14 доков × 2 дозы, подразумеваемо L23).

Тот же класс, что C1 (спека-пробел, форсирующий импровизацию), только мягче: кодер должен догадаться считать δ на каждом из 5 слоёв, на своей наблюдаемой. Одна строка в §8:
> `δ_PHR(L)`, `δ_far_PHR(L)` — те же формулы на norm_delta, per L ∈ {6,12,18,19,23}; `δ_REP(L)`, `δ_far_REP(L)` — на cos_raw. Primary — L23.

### F4. «Draw-робастность» из отрицательной ковариации не переносится на |·|

§7.2 и ответка m5 утверждают: отрицательная `Cov(REP, N_perm) = −σ²/2` ⇒ «высокий draw-уровень S-строк одновременно снижает статистику и повышает порог — оба в anti-firing сторону».

Это утверждение о **знаковых** величинах. Вердиктные статистики — `p90|·|`. Контрпример (уровни строк, скалярно):

| m_L | m_S | m_S' | REP = m_L−m_S | N_perm = m_S−m_S' |
|---|---|---|---|---|
| 10 | 0 | 0 | **10** | **0** |

Тихие S-draws → статистика велика, порог нулевой → **fires**. Отрицательная ковариация здесь не помогает: она говорит о знаках, а модуль их стирает.

Реальная защита — только σ_L/σ_S (m3, измерено 1.22 для norm_delta@n2). Формулировку «draw-робастность» надо снять или явно квалифицировать: «знаковая ковариация отрицательна; на модульных статистиках знак не сохраняется, защита — p95-маржин и измеренное σ_L/σ_S».

### F5. Порог INT-тега: ни одна из доступных δ не калибрована под него

§11 шаг 5: `CI_low(near_INT(n=2), norm_delta) > δ_PHR` → INTERACT_SIGNIFICANT.

Считаем дисперсии:
```
Var(INT)   = Var(D_L − D_S) = (σ_L² + σ_S²)/2  ≈ σ²   при σ_L=σ_S
Var(N_PHR) = 2σ_S²                              = 2σ²
Var(N_perm)= σ_S²                               = σ²
```
То есть по **структуре** INT сматчен с `N_perm` (δ_REP), а не с `N_PHR` (δ_PHR): текущий порог шире в √2 ≈ 1.41×. Но `δ_REP` — на **cos_raw**, а INT считается на norm_delta → брать его нельзя (это ровно C1).

Калиброванного нуля для INT в дизайне нет (нужна вторая независимая L-пара, а лупы детерминированы — draw'а нет). **Фикс:** объявить тег эвристикой без калибровки («порог δ_PHR — консервативный суррогат, ×√2 по дисперсии; type-I не контролируется»), либо снять порог и отчитывать INT непрерывно с CI. Сейчас §11 подаёт его как тест.

### F6. G_inside_rep гейтит E_phr на чувствительность к **порядку**, а это не премисса E_phr

§10: провал `CE(L1)<CE(S1) ∧ CE(L2)<CE(S2)` на n=2 → **E_phr нерешён**.

Но E_phr = L1−L2 — контраст двух **периодических** строк по содержимому. Его премисса — «содержимое различается» (гарантировано построением: непересекающиеся контент-токены). Чувствительность к порядку — премисса **REP**, не E_phr.

Плюс: на n=2 маржа мала. Оценка по вашим же числам: L1(2) = 3.29; S1 — перемешанные 18 токенов, первая девятка непредсказуема (~5), вторая — мультисет известен (~3) → ~4. Маржа ~0.7 nat против ~2.1 на n=16. Гейт бинарный (`<`), минимальной маржи нет: 11 доков с маржой 0.05 пройдут, и клетка будет считаться «видящей стимул».

**Фикс (одно из):**
- объявить логику явно: «провал order-sensitivity на n=2 означает, что периодическая строка на этой дозе не представлена как периодическая ⇒ H_phr («запоминание повторённой фразы») там не тестируема» — это законное чтение, но его надо написать, иначе гейт выглядит нерелевантным;
- и добавить пре-рег **минимальную медианную маржу** на n=2 (например ≥0.3 nat), иначе «pass» ничего не гарантирует.

## 4. Минорные / конструктивные

**m1'. Полная проверка уникальности сидов вместо одной пары.** §15 проверяет конкретную коллизионную пару старой формулы. Но набор из 112 сидов детерминирован — коллизии проверяются исчерпывающе за 0:
```python
seeds = [crc32(f"S{i}|{doc}|{n}".encode()) for i in (1,2,3,4) for doc in DOCS14 for n in (2,16)]
assert len(set(seeds)) == 112, "seed collision"
```
Это превращает вероятностный аргумент (1.5e-6) в проверенный факт.Birthday-оценка ответки, кстати, верна: 112·111/2 = 6216; 6216/99991 → 6.0 %, 6216/2³² → 1.45e-6 ✓.

**m2'. Прямой пост-прогоновый σ_L/σ_S.** Текущий P0 — прокси через `e_spec/e_null` (смешивает филлер), сам TZ это признаёт. После прогона величина измеряется **напрямую и бесплатно**: `SD_docs(near_E_phr) / SD_docs(near_N_PHR)` на norm_delta@n2 и аналог для REP. Объявить действие: если > 1.5 → тег `CALIBRATION_WARN`, вердикт читается с оговоркой «порог анти-консервативен». Сейчас прямого чека нет, а он дороже прокси ровно на ноль.

**m3'. Row-type асимметрия E_phr vs N_PHR — намеренная и несущая.** Статистика — loop−loop, нуль — shuffle−shuffle. Это **и есть** тест («контентное различие больше при повторении?»), но в §7.2 он подан просто как «терм-непересекающийся нуль». Одна фраза закрывает петлю r1 (там row-type mismatch был скрытым конфаундом, здесь — объявленная конструкция): «нуль другого row-type by design; валидность = σ_L ≈ σ_S, измерено 1.22».

**m4'. Синтетика: адверсарный bag-случай.** Тест 7 проверяет ожидаемый bag (`D_L≈D_S≈шкала нуля` → не fires). Но §17 признаёт остаточный type-I: `D_L=D_S` **велики**, а `N_PHR` в этой выборке мал → fires без INT. Этот путь чтения («контент (bag), порядок не установлен») не покрыт ни одним тестом. Добавить сценарий 10 — проверяет, что тег/чтение отрабатывают, а не только happy path.

**m5'. BOTH_SPECIFIC с одним `_AMBIGUOUS`.** §11 шаг 3, скобка: «substructure _AMBIGUOUS по **единственному** значимому → NOT_RESOLVED». Случай «оба fires, у одного substructure неразрешён» не покрыт. Прописать: вердикт BOTH_SPECIFIC сохраняется, `_AMBIGUOUS` остаётся тегом канала (или явное иное решение).
