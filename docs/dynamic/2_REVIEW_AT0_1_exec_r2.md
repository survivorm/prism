## 4. P5 sign-тест (новый баг r1 → проверка)

Код (`AT0_1_accounting.py`, p2s): `p2s(n,pos,neg) = min(1, 2·P(X ≤ min(pos,neg)))`, X~Bin(n,0.5).

**(а) Корректность формулы** — подтверждено алгеброй + численно:
- Без нулей neg = n−pos. По симметрии Bin(n,0.5): P(X ≥ pos) = P(X ≤ n−pos) = P(X ≤ neg).
  Значит 2·min(P(X≤pos), P(X≥pos)) = 2·min(P(X≤pos), P(X≤n−pos)) = 2·P(X≤min(pos,neg)) = p2s
  (с капом min(1,·), стандартным для двустороннего sign-теста). Классическая двухсторонняя
  формула — получена точно.
- Численно: для всех 6 пар (n,pos) из артефакта p2s == 2·min(P(X≤pos), P(X≥pos)) побитово
  (`classical_eq=True` ×6). На данных нулей нет (pos+neg = 53 во всех 6 случаях) — условие
  эквивалентности выполнено. Старая формула r1 на тех же данных дала бы ~2.0 (напр., 1.9992
  до капа) — баг устранён.
**(б) p-значения** — пересчитаны из посчитанных pos/neg, bit-eq с артефактом:
- h_raw: n=53, pos3=15/neg3=38 → p3 = **0.0021901868838920535** (bit-eq); pos4=21/32 → p4 = 0.16897782228771874 (bit-eq).
- du_unit: pos3=14/neg3=39 → p3 = **0.00080233088689496412** (bit-eq); pos4=21/32 → p4 = 0.16897782228771874 (bit-eq).
- v_tangent: pos3=35/neg3=18 → p3 = **0.027008317653722358** (bit-eq); pos4=34/19 → p4 = 0.053438810537711046 (bit-eq).
  e3/e4-медианы — тоже bit-eq (−0.021743/−0.004543, −0.023320/−0.005918, +0.019324/+0.013050).
**(в) Вердикты** — h_raw: «confirmed: excess(3,4) ≠ 0, знак negative (excess < 0 — анти-горб)»;
du_unit: то же; v_tangent: «confirmed: excess(3,4) ≠ 0, знак positive (excess > 0)».
Совпадает с ожидаемым (h_raw/du_unit — confirmed анти-горб, v_tangent — confirmed positive).
Знак берётся из знака среднего excess (p-тест лишь отвергает =0) — корректно на этих данных
(знак среднего и большинства совпадают во всех 3 объектах).

## 6. Новые замечания

### n1. MINOR (mёртвая ветка в P6-сканере)
`_bad_names`: `bad = ("dmed","delta_med","d_med","s0","S(0)")`, проверка `b in str(k).lower()`.
Строка `"S(0)"` НИКОГДА не срабатывает (ключ приводится к нижнему регистру, заглавная S уже не встретится),
а `"s0"` не покрывает имя `s(0)` (между s и 0 стоит `(`). Т.е. ключ буквально `S(0)`/`s(0)`
просочился бы мимо сетки. Артефакт при этом чист (собственный скан с правильной регуляркой
`dmed|delta_med|d_med|s0|s\(0\)` — пусто, §5.5), и основная гарантия — конструктивная (S(0) не
вычисляется нигде в коде), поэтому не блокирует. **Фикс (1 строчка):** в `bad` заменить
`"S(0)"` на `"s(0)"`.

### n2. MINOR (латентная робастность, не блокирующее): `p2s` включает нули в n
`p2s(n, pos, neg)` берёт `n = len(e3)` — если бы в выборке были точные нули
(e3_i = rho_Tk[2] − f_dc = 0 в fp64), они вошли бы в Bin(n, 0.5), не входя в pos/neg;
при фиксированном min(pos,neg) большее n → меньший хвост → p антиконсервативна
(стандартная обработка ties — исключить их: n' = pos+neg).
**Факт на текущих данных: нулей нет** (15+38=53, 14+39=53, 35+18=53, 21+32=53, 34+19=53 —
проверено в артефакте и пересчётом), все p-значения точны, вердикты не затрагиваются.
**Фикс (1 строка, при будущем перепуске/AT0_2):** `n = pos + neg` в `p2s` (или явный assert
`pos+neg==len(e)` перед тестом). (Найдено в частичном предшествующем прогоне этого же ревью —
на диске, подтверждено независимо.)
