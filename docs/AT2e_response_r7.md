## 3. Шум κ: что теперь в функции, а что — только в r4 (N4)

В артефакте r3 есть только **сырые** s_k = |2κ_k−q_k|/max(q_k,floor) и
q_k/floor (в `linear_gate_decomp.kappa_stats_per_k`) — и только это
отчёчивается. Шумовая классификация (шумовой/решительный) **не делается**:
S_floor,k в r3 не измерим. Оценка порядком (декларация, не результат):
множитель 2√2 — верхняя оценка, ≈1 — центральный сценарий (κ квадратична по
δz ≈ 2.8e-6: κ_noise ≈ ½Var_p(δz) ≈ 4e-12 ≈ 0.3·floor, коррелирована с
q-шумом); при ≈1 все 5 флагов (c1 k8, c9 k7,8, c12 k7, c13 k8) — решительные
(4.2–36× «шума»; минимальный — c1 k8: 4.2×), при 2√2 — только c1 k8 на
границе (1.5× < 3), остальные решительные (3.7–12.7×). Гигиена: 2√2/18 = 0.157
(у меня 0.153), 2√2/6 = 0.471 (0.50) — принято, таблица из прозы убрана.

Фикс (TZ r6 п.2): (a) pre-pass хранит **все q_k и κ_k при a_floor**
(0 доп. forward — уже посчитаны в `probe`); (b) S_floor,k = max по ≥2
направлениям (b0[0] + **v*** — перенос шума с top-PCA на найденное
направление, +2 ф.-э./клетку; опц. b0[v0_idx]); (c) правило: решительный
только если s_k > 0.5 И s_k > 3·S_floor,k·floor/max(q_k,floor), иначе
`kappa_noise_unresolved_k` (отчёт, НЕ сбивает linear); (d) **до замера —
никакой per-cell классификации**; (e) в r4 классификация публикуется только
измеренной.
