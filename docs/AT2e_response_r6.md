### 2.3 Фикс (принят формула ревью, без изменений)

```python
g_scale = (qs[0] + Dden) * np.linalg.norm(Ov) \
          + 2.0 * qbar_k1 * (np.linalg.norm(Cv) + eps_reg)   # eps_reg = tau*eps0
if gn <= 1e-6 * max(g_scale, 1e-300):
    converged = True
```
+ `rel_gn = gn/g_scale` в каждой записи traj (и в v0_recheck). Применяется к
**обоим** подъёмам (t и t' — одна функция `ascent`). `ascent_not_converged`
при 8 итерациях сохраняет смысл (недостигнуто относительного сходимости) —
отчитывается как power-лимит (§4.3).

Это изменение пре-рег-правила §3.4 → TZ r6 + перепуск. r3 — frozen.

### 3.2 κ-шумовой анализ (новый: отвечает на «0.51 и 5.0 — разные выводы»)

κ-статистика s_k = |2κ_k − q_k|/max(q_k, floor) — разность почти равных
величин; её шумовая составляющая ~ 2√2·floor/q_k (dz-шум в обоих членах;
floor T4 = 1.33e-11 — измерен pre-pass в том же прогоне).

| клетка | k | s_k | q_k/floor | шум ~2√2·floor/q | s/шум |
|---|---|---|---|---|---|
| **c1** | 8 | 0.708 | **6** | 0.50 | **~1×** |
| **c9** | 7 | 0.546 | 66 | 0.043 | **13×** |
| **c9** | 8 | 0.819 | 18 | 0.153 | **5×** |
| c12 | 7 | 0.802 | 13 | 0.218 | 4× |
| c13 | 8 | 0.537 | 44 | 0.064 | 8× |

**Флаги гетерогенны**: у c1 единственный решающий флаг (k=8) сидит НА
шумовом поле (q8 = 6×floor — едва выше квант-пола); у c9/c12/c13 флаги в
4–13× выше шумового уровня. Это ровно «0.51 vs 5.0», о котором писал
ревьюер, — и данные разделяют эти случаи.

Оценка честная, но грубая (порядок величины, не измерение) — поэтому в TZ r6
шумовой запас не гадается, а **самокалибруется из того же прогона** (п.3.3).

### 3.3 Фикс (дизайн-решение, на ревью)

Две меры, ни одна не ослабляет гейт:

**(a) Шумовой запас κ — самокалибруемый (0 доп. forward).** В pre-pass
a_floor = 1e-9·‖h‖ (уже гоняется per (doc, L, t) для q-floor) квадратичный
сигнал ~1e-8 от шума (q_signal ≈ (a_floor/a_hi)²·q(a_hi) ~ 1e-19 << floor
1.3e-11) — статистика S_floor,k = |2κ_k−q_k|/max(q_k, floor) там — чистый шум
замера разности (абсолютный масштаб ~ S_floor,k·floor). Правило:
```
flag_реши́тельный  :  s_k > 0.5  И  s_k > 3 · S_floor,k · floor / max(q_k, floor)
flag_шумовой     :  s_k > 0.5  но  s_k ≤ 3 · S_floor,k · floor / max(q_k, floor)
                   -> kappa_noise_unresolved_k (отчёт, НЕ сбивает linear)
```
Для клеток с высоким Ш/С (S_floor·floor/q_k << 0.5/3) правило вырождается в
объявленные 0.5 — гейт не ослаблен; для шумоограниченных — перестаёт
принимать решения на чистом шуме. (На r3-данных: c1 k=8 → шумовой, c9 k=7,8 /
c12 k=7 / c13 k=8 → решительные.)

**(b) Recovery-сетка по амплитуде для провала линейности.** Сетка
{a_lo_r = 1e-4·‖h‖, a_hi_r = 3e-4·‖h‖} (верхняя точка = первичная a_lo).
Триггер: линейный провал на первичной сетке (L1/L2/κ-реши́тельный). Действие:
**полный перепуск клетки на recovery-сетке** (подъём, verify, 1d, rank,
pos-spec — та же per-cell-функция с другими амплитудами). Вердикт — по
прошедшей сетке, с меткой `amplitude_grid: recovery` — **более слабое
утверждение** («линеен при 1/3 первичной дозы»), декларируется явно и
считается в глобальном счёте отдельно от первичных (verdict_detail).
Линейность провалилась на обеих сетках → NOT_TESTABLE
(`linear_fail_both_grids`). Триггер НЕ включает below_floor/denom-провалы
(c3/c11 — recovery не помогает). Бюджет: ~4 клетки × ~65 ф. ≈ +5–7 мин T4.

Это закрывает «дыру дизайна»: путь назад при провале линейности появляется,
не ослабляя первичный гейт.

## 4. Умеренные (принято, проверено)

1. **Fallback 2/16** (c3: 1.89, c11: 3.32 < 100) — опровергнутое пре-рег-

   device-зависимость пола** (TZ r6).

   (1 ≤ n_found_sho < 4, n_found ≥ 1) после SCRATCHPAD_CANDIDATE и до

   gaps_to_labels — как в AT2d). Для r3 (frozen): метка по новому дереву —
   SUB_THRESHOLD_FOUND (2 FOUND, 3 found+SHO, 2 дока).
3. **Power-лимит**: 10/16 `ascent_not_converged=True` — декларируется в TZ:
