# Project rules (эксперименты prism)

## Обязательный само-аудит нового/изменённого эксп. кода — ДО запуска и ДО интерпретации
Порядок: написал → само-аудит (пункты ниже) → смоук/деградационные тесты → запуск → аудит результата → коммит.
Внешнее ревью (docs/E*_review.md) не заменяет само-аудит; на замечания ревьюера проверять, что он смотрел актуальный файл.

Чек-лист (всё это уже стоило прогонов):
1. **Одинаковая статистика на обеих сторонах сравнения** (raw vs Δ-vs-null, V vs Vc, с intercept vs без).
   Разрыв floor ≈0.045 больше сигналов 0.015–0.024 — молча смещает любой фит/сравнение.
2. **Ветки и guard'ы**: где живут вызовы после if/elif/else; guard, чей результат следующая строка
   перезаписывает — мёртвый код или краш; designed-сценарий guard'а обязан быть протестирован (exec точного
   фрагмента, не копия), глазами не считается.
3. **Каскад фиксов**: изменил возвращаемый тип (float→Optional) — найти всех потребителей (None−None,
   None>0.005, abs(None)).
4. **json.dump**: numpy-типы/NaN → sanitize или float()-касты; артефакт ≠ stdout.
5. **Долгие прогоны**: запускать `setsid nohup ... < /dev/null &` — обычный nohup умирает вместе с
   прерванной оболочкой (проверено 3×); после abort проверять `ps`, не перезапускать дважды.
6. **Калибровки/контроли читаются первыми**: если null-контроль даёт не ноль — метка пониженная,
   это результат, а не шум. Effect-size гейт к любому «значимо ⇒ механизм».
7. **Числа артефакта vs код**: правки после старта прогона — только если ветки не взяты (зафиксировать
   это); иначе перепуск.
8. Ревью существует только как ФАЙЛ на диске: перед правками по замечаниям `sha256sum` файла и
   проверить наличие `VERDICT: PASS|REVISE|FAIL` + финального маркера; в чате/уведомлении/памяти
   ревью не бывает (проверено 12.11: два «ревью» на час, оба моя конфабуляция, ноль применённого).
9. Случайные «мелочи» в новом коде (мёртвые параметры, дедупликация констант, assert на ключи) —
   вычищать в том же коммите.

## Субагенты (headless-воркеры: subagent_spawn / pi-subagents)
**Доказательство работы = маркер + файл на диске. НЕ RC, НЕ отчёт.** Headless-воркеры два раза
умирали «тихо с RC=0 и нулевым выводом» на multi-turn tool-задачах (ngenix-llm default thinking,
qwen3.8); extension может уйти в `extension_unresponsive` посреди прогона; отказавший ребёнок
тоже даёт RC=0. Следовательно:
1. **Финальный маркер обязателен** (EXEC_DONE / S*_DONE / REVIEW_R*_DONE) — в конце вывода И в
   конце файла-результата. RC=0 без маркера = задача не выполнена. Проверка: `subagent_status`
   (done_marker ≠ done_rc0/done_rcX/dead) + grep маркера + `sha256sum` файла (п.8 само-аудита
   распространяется на субагентов: ревью/артефакт обязан быть физически на диске).
2. **Промпт — ФАЙЛ** (`prompt_file`), не инлайн-текст: без shell-кавычек и отравленных cmdline.
   Внутри: указатели на канон-файлы (paper.md, 0_итоги_раунда.md, артефакты с sha), список
   разрешённых действий, критерии STOP («сомнение → STOP + запись в NOTES»), подробная
   спека каждого шага. У субагента НЕТ памяти сессии — чего нет в промте, того нет.
3. **`:low` thinking + короткий scope**: один воркер = один шаг (ревью / exec / само-аудит);
   длинные стадии неживучи (выживание ~14 мин — потолок). Тяжёлые прогоны — СКРИПТОМ через
   ./run_one.sh, а не внутри агента.
4. **Нет дублей**: перед re-spawn — `subagent_status` + `pgrep`. Инцидент 11.11: runner лончан
   exp91 дважды, оба умерли от голода памяти при LA 52. Лонч долгих прогонов — ТОЛЬКО
   ./run_one.sh (flock = BUSY; BUSY = читать лог, не перезапускать; после abort — `ps`).
5. **Память до лонча**: avail ≥ 10G (гейт run_one.sh) + watchdog /tmp/prism_watch.log;
   одна CPU-экспериментальная задача за раз.
6. **run_one.sh — только путь к скрипту**, не инлайн: он ре-джойнит `$*` в свой `bash -c`,
   инлайн `bash -c '<цитата>'` теряет кавычки/расширения; память-вэйт у него foreground —
   запускать `setsid nohup ./run_one.sh <имя> <cmd> &`.
7. **Файлы, написанные воркером, гонять через CJK-гейт** до коммита:
   `grep -nP "[\x{3000}-\x{9fff}\x{3040}-\x{30ff}]" <файлы>` — воркер уже протёк иероглифами в
   промт-файл; чек только по файлам текущей правки (в истории CJK есть —
   репо-wide grep никогда не будет чист).

## Git-гигиена (после инцидента 10.11: git-filter-repo с --prune-before удалил Nov6–10 историю)
- Никаких filter-repo/BFG/переписываний без: (1) полного зеркала `git bundle` ВНЕ репозитория,
  (2) копии `.git`, (3) явного «да» пользователя на КОНКРЕТНЫЙ набор флагов.
- `--prune-before` НЕ использовать без явного согласования: он сносит ВСЁ ранее даты.
- Кеш/артефакты >10MB в git не класть; артефакты, которых нет в git, дублировать в
  /tmp/recovered или внешний бэкап до любых опасных операций.
