# E-45. Цена правки против ущерба листу: что значит «κ изменился»

Статус: таблица закрыта (все 12 правок), вердикты `exp45_verdicts.py` прогнаны и выписаны в
§4 внизу. Не хватает только iid-полосы `seednull_s*` (отдельный `--resume`-проход, критерий 7).
Критерии ниже зафиксированы до чисел
(они же в `PLAN.md`, «Пререгистрация чтения результатов», пункты 0–6); `exp45_verdicts.py`
применяет их к артефакту механически, чтобы вывод не сгибался под историю после того, как числа
увидены.

## 1. Вопрос

Лист `V_r` (главные `r` правых сингулярных направлений якобиана считывания) — объект про
производную. Любая правка весов меняет и лист, и поведение. Нетривиальный вопрос не «меняется ли
лист» (меняется всегда), а **несёт ли величина его изменения информацию о цене правки сверх
величины самого возмущения**. Если `‖ΔJ‖/‖J‖` объясняет и `Δκ`, и `KL`, то `κ` — пересказ той же
числа, и называть его «аномалией структуры» нельзя. Если при согласованном ущербе `κ` различается
в разы — `κ` измеряет что-то другое (способ правки), и это надо проговорить словами, а не
умолчать.

## 2. Протокол

* Слой L23 (`J = W_lm` — тривиальный слой, зато ровно воспроизводимый), `r = 16`, кэш exp27b
  = множество A (4 домена × 8 документов × S=128 = 4096 позиций).
* Срезы разные у разных линеек, и это надо помнить при любом сопоставлении: геометрия
  (`drift`, `κ`, спектр) считается по подыборке **8 документов = 1024 позиций** (`SPEC_DOCS`, база
  `κ = 0.015921` против корпусного якоря `0.015923`, rel 1.3e-04), ущерб — по подыборке с шагом 2
  (`METRIC_STRIDE = 2`, 2048 позиций A и 2032 B), одинаковой для всех правок.
* Множество B — C4-holdout (32 документа × 128), скрытые состояния сняты один раз: правка
  считается только в `lm_head`, значит `h` от правки не зависит и одна съёмка честна для всех.
* Две линейки на каждой правке: геометрическая (`drift = ‖ΔJ‖/‖J‖`, `κ(r=16)` на A) и
  поведенческая (`KL`, `TV`, смена top-1, `PPL` на B; `KL` на A тоже).
* Правки: `base`; GPTQ-4bit и int8-RTN — по **всей** матрице (тип `dense`); iid-шум в 128 строках
  `U128` и по всей матрице при трёх согласованных `drift` (0.06/0.12/0.25); уплощение листа
  обучением (λ из сетки E-39d, 0.01 и 0.1; отдельный прогон без KL-повода) — тоже 128 строк.
* Величина iid-возмущения: `ΔJ` линеен по `σ`, поэтому медианный дрейф линеен по `σ` **точно**,
  и `σ` берётся одной оценкой при `σ=1` (бисекция из шести итераций ничего не добавила:
  `σ_K(0.12)` = 0.1174 против 0.1188 у бисекции, 1 %).
* Разреженные правки (128 строк) считаются замкнутыми формулами через `logsumexp`; сверка с
  плотным путём (`max|Δ| = 1.8e-06` по KL и TV, top-1 расходится 0 позиций из 64) и с
  `kl_leash` (`abs = 3.2e-08`, `rel = 5.7e-06` — это точность fp32-эталона), плюс независимый
  нулевой контроль `exp45c_gauge_null.py` (правка, у которой ответ известен аналитически
  и равен нулю).

## 3. Критерии (зафиксированы до чисел)

| № | Условие | Что объявляем |
|---|---|---|
| 0 | `gap16 < 0.01` или >5 % позиций без зазора | разрез неустойчив, `Δκ` на этой правке невалиден |
| 1 | есть пара правок с `KL_B` в пределах 10 % и `κ/κ₀` различающимся ≥ 1.5× | `κ` — метрика **способа** правки, не качества |
| 1′ | таких пар нет | `κ` идёт за ущербом; вывод про «аномалию» не опираем на `Δκ` |
| 2 | правка с `κ/κ₀ < 0.5`, `KL_B < 1e-3`, сменой top-1 < 1 % | лист разрушается незаметно для поведения |
| 3 | плотная и разреженная правки при равном дрейфе различаются по ущербу ≥ 2× | `drift` — плохой предиктор ущерба, и сопоставлять надо по ущербу |
| 4 | `flat_*`: `KL_B/KL_A` вне (0.5, 2) | уплощение переобучено под корпус A; `KL_B < KL_A` = баг в масках |
| 5 | `|Δκ/κ| < 1e-4` | «изменений нет» — не называть изменением |
| 6 | любая интерпретация `ρ(энергия, поведение)` | только после операторного null и content-matched null (paper §6 п. 22–23) |
| 7 *(добавлено после первых 7 строк, до остальных чисел)* | любое различие двух правок **одного** семейства (знак `Δκ`, `gap16`, величина KL) | значимо только вне полосы `N` iid-правок того же дрейфа (`seednull_s*`); внутри полосы — «не различили» |

**Пункт 0 — и он сработал на всём, включая базу (E-45e, `exp45_gap_scan.py`, wall 1008 с).**
Пререгистрация: «`gap16 < 0.01` или >5 % позиций без зазора ⇒ разрез неустойчив, `Δκ` на этой
правке невалиден». Скан `r` от 1 до 40 на базовом `J` (тот же срез 8 документов; `σ` взяты из
`eigh` грамма `JJᵗ` — быстрый путь сверен с таблицей по `σ16/σ1` с rel 5e-16):

| `r` | медианный зазор `σ` | доля позиций с зазором ≥ 1 % | ≥ 0.1 % | энерг. зазор ≥ 1 % | `σ_r/σ_1` |
|---|---|---|---|---|---|
| 4 | 0.0264 | 100 % | 100 % | 100 % | 0.372 |
| 8 | 0.0093 | 8.7 % | 100 % | 0 % | 0.298 |
| **11** | **0.0109** | **95.7 %** | 100 % | 0 % | 0.280 |
| 16 | 0.00875 | **1.1 %** | 100 % | 0 % | 0.255 |
| 17 | 0.00196 | 0 % | 97.8 % | 0 % | 0.246 |
| 32 | 0.00078 | 0 % | 10.1 % | 0 % | 0.208 |

Читается так. На L23 разрез с зазором ≥ 1 % держится только при `r ≤ 5` (и то по энергии — `r ≤ 5`
же) и островком при `r = 11` (95.7 % позиций). `r = 16` — взятый по наследству от E-28 — зазора
≥ 1 % не имеет почти нигде (1.1 % позиций), а сразу за ним (`r = 17`) зазор падает ещё в 4.5×.
При этом до 0.1 % спектр не вырожден нигде до `r ≈ 24`, то есть речь не о численной неустойчивости
(пол `fp64`-диагонализации грамма ~1e-15, на ~13 порядков ниже), а о реальном отсутствии разрыва.
Следствия по пререгистрации: **`Δκ` при `r = 16` не интерпретируется ни на одной правке, включая
базовую**, и вывод раунда должен стоять на поведенческих метриках и на уровне `κ`, а не на его
приращении. **Это следствие было сформулировано слишком сильно и уточнено в §8 (E-45g):** отсутствие
зазора ≥ 1 % не означает невоспроизводимости — при шуме `ε‖J‖ ≤ 1e-6` направление `V₁₆` и `κ` не
двигаются вовсе, а порядок `σ₁₆ > σ₁₇` держится до `ε = 0.25`. Правильная формулировка: `κ` при
`r = 16` воспроизводим и сравним между правками, но **не является непрерывной функцией правки** —
малое возмущение вне образа `W_U → J` (`ε = 1e-3`) меняет его на порядок, поэтому сравнивать можно
только правки одного семейства, а не утверждать, что «лист устойчив». Отдельно: `J` на L23 отличается от позиции к позиции ранговой поправкой и масштабом,
поэтому спектр по сути один на весь корпус — «подбирать `r` по документу» здесь нечего, выбирать
надо одно `r` (11 — единственный кандидат выше 5 с зазором ≥ 1 %).

**Что уже видно (до вердиктов).**

1. **`κ` не идёт за ущербом — но по пункту 0 это нельзя назвать слепотой.** По двенадцати правкам
   `κ/κ₀ ∈ [0.129, 1.051]`, KL B меняется в 52000× (9.2e-05 у RTN-8bit против 4.78 у
   `flat_noleash`), смена top-1 — с 1 % до 56 %. При этом `κ` падает втрое–всеммеро только на
   *намеренном* уплощении, а на случайном шуме с KL того же порядка, что у `flat_l0.01`
   (`rand_full_d0.25`: KL B 0.170 против 0.147), `κ` стоит на 1.007. Формулировка «`κ` слеп» была
   бы сильнее данных: по пункту 0 разрез `r = 16` неустойчив на 7 правках из 12, поэтому рост `κ`
   на 5 % нельзя приписать ни листу, ни его сохранности. Корректное утверждение: **на этом разрезе
   `Δκ` не метрика вреда**, и сопоставлять надо уровень `κ` (он воспроизводим) с поведением.
2. **Направление сдвига поправимо только с iid-семейством — и изначально было неверным.**
   Формально `rand full` даёт `κ/κ₀` 1.0037 и 1.0016, `rand K` — 0.9973 и 0.9932, и соблазн
   сказать «правка всех строк поднимает `κ`, правка 128 строк опускает» велик. Он неверен по
   построению: якобиан L23 есть функция **только 128 строк** `W_lm[U128]`, поэтому по закону `J`
   у `rand_K` и `rand_full` одинаковый (оба — iid гаусс на те же 128 строк, величина подогнана
   под один и тот же дрейф), а в таблице на каждое семейство по ОДНОЙ выборке. Противоположные
   знаки ⇒ это разброс одной выборки, а не свойство семейства. Разброс меряется строками
   `seednull_s*` (тот же прогон, `E45_SEEDNULL=8`). Что остаётся без оговорок: раз `κ/κ₀` у самой
   вредной правки выше, чем у безвредной RTN (1.0016 против 0.9999), `Δκ` не является монотонной
   функцией вреда.
3. **Равный дрейф ≠ равный вред** (критерий 3 сработал на паре «плотная против разреженной»):
   при `‖ΔJ‖/‖J‖` 0.127 у GPTQ против 0.120 у rand K ущерб по KL A отличается в 3.7×
   (0.00499 против 0.01843), по KL B — в 2.0×. Структурированная ошибка квантизации *менее* вредна,
   чем случайная того же геометрического размера: величина дрейфа J — плохой предиктор. Случайная
   сторона здесь тоже одна выборка: насколько 3.7× превышает разброс семейства, скажут
   `seednull_s*` (их KL B — готовая полоса).
4. **Сколько строк шевелится, при фиксированном дрейфе** — пара `rand full` против `rand K` при
   одном и том же `d`: ×1.82 по KL A и ×1.51 по KL B (0.06) и ×1.82/×1.50 (0.12). Ниже планки 2×
   критерия 3, но стабильно по обоим дрейфам и обоим корпусам: правка всех строк вреднее правки
   одного считывающего базиса.
5. **Спектральный зазор на 16 — артефакт одной выборки, и пара `d = 0.25` показывает это прямо.**
   Две правки ОДНОГО семейства при одном и том же дрейфе 0.25 дают `gap16` = 0.0014 (`rand K`,
   разрез по критерию 0 неустойчив) и 0.0109 (`rand full`, 1.5 % позиций без зазора): восьмикратная
   разница при том, что по закону возмущения идентичны (пункт 2). Плюс база сама имеет `gap16` =
   0.00875, а скан `r` (выше) показывает, что зазора ≥ 1 % на 16-м месте нет почти нигде. Поэтому
   «случайный шум по всей матрице делает разрез каноническим» не утверждается вовсе; утверждается
   только «разрез `r = 16` на L23 неустойчив, и величина `gap16` на одной выборке ничего не стоит».

**Разрешающая способность `κ` (E-45d, без новых прогонов — док-бутстрап по per-doc `κ` из
`results/exp28_leaf_structure.json`).** Относительный разброс `κ` между документами (L23) —
14.2 %, отсюда несогласованный 95 % CI уровня `κ`: **±4.8 % при 32 документах и ±9.5 % при 8**.
По слоям глубина только портит: rel SD 2.7 % (L6), 4.7 % (L12), 5.7 % (L18), 9.3 % (L22),
14.2 % (L23). Следствия: (а) расхождения между протоколами уровня 0.0162 / 0.0175 / 0.018
(разные наборы документов и маски позиций) лежат на границе одного CI и не обязаны означать
разные объекты; (б) сравнивать правку с базой можно только **попарно** (те же позиции, тот же
срез) — и то не выше собственного попарного CI, который измеряется в `exp45_kappa_seed_null.py`.

## 4.1 Вердикты по пререгистрации (`exp45_verdicts.py`, лог `results/exp45_verdicts.log`)

* **п.0 — сработал на 7 правках из 12**, включая базу, GPTQ, RTN и все `rand_K`: разрез `r = 16`
  на них неустойчив, `Δκ` на них не читается. Валидный разрез — только у `flat_*` (зазор 0.029–0.082,
  т. е. 3–9× выше порога) и у `rand_full` при d ≥ 0.12.
* **п.1 — не сработал, и это надо писать как «не сработал».** Пары с `KL_B` в пределах 10 % и
  различием `κ` ≥ 1.5× в наборе нет. Ближайшая — `flat_l0.01` (KL B 0.147, `κ/κ₀` 0.325) против
  `rand_full_d0.25` (KL B 0.170, `κ/κ₀` 1.007): различие `κ` в **3.1×**, а KL расходятся на 15 %,
  то есть на 5 п.п. шве пререгистрированного допуска. Порог поднимать задним числом нельзя;
  заявляется ровно то, что механический тест не подтверждён, а качественная картинка — ниже.
* **п.1′ формально даёт «`κ` идёт за ущербом», но внутри набора это не так:** маргинальный
  Spearman(`κ/κ₀`, KL B) = −0.364 собран из двух разных внутри-семейственных трендов (внутри `flat_*`
  `κ` падает с ростом KL, внутри `rand_*` стоит на месте или растёт) — классическая симпсонова
  свёртка. Предсказывает ущерб величина возмущения: Spearman(дрейф, KL B) = **+0.936**.
* **п.2 — невидимого разрушения нет.** Среди правок, уронивших `κ` больше чем вдвое, минимальный
  KL B = 0.147 (`flat_l0.01`), смена top-1 9.5 %, PPL +12 %. То есть сплющить лист на L23 так, чтобы
  `κ` упал в 3 раза и распределение не заметило, не вышло: цена обнаружима по поведению всегда.
  Это ослабляет линию «аномалия листа как сигнал подмены модели».
* **п.3 — не сработал, но отношение стабильно:** `rand_full`/`rand_K` при равном дрейфе дают ×1.51,
  ×1.50, ×1.49 на трёх дрейфах — ниже планки 2×, то есть «дрейф J» работает предиктором с точностью
  до полуторного множителя. Одна выборка на семейство (критерий 7) эту стабильность не проверяла.
  После прогона `seednull_*` (см. п.7) к этому добавляется ухудшение: сама правка `rand_K_d0.12`
  (KL B 0.0262) лежит вне полосы восьми draw'ей того же семейства при том же σ и том же дрейфе
  (KL B ∈ [0.0136, 0.0180]), то есть дисперсия семейства шире, чем показали 8 draw'ей, и ×1.5
  плотный/разреженный внутри этой дисперсии — значит «различили» про п.3 сказать нельзя.
* **п.4 — уплощение функционально, не переобучено:** KL B/KL A = 0.92, 1.13, 0.87 для трёх
  уплощённых носителей (диапазон пререгистрации (0.5, 2)), случая KL B < KL A нет.
* **п.5 — «изменения нет» только у RTN-8bit** (|Δκ/κ| = 8e-05 < 1e-04); шесть правок лежат в полосе
  < 2 % от базы — при полосе док-бутстрапа ±9.5 % это «не различили», а не «изменилось на 1 %».
* **п.7 — полоса «разброс одного draw'а» измерена** (8 iid draw'ей семейства `U128` при фактическом
  дрейфе 0.120, σ 0.1177 — тот же, что у `rand_K_d0.12`; `E45_SEEDNULL=8 --resume`):
  `κ/κ₀` ∈ [0.9920, 1.0024] ⇒ ±0.52 %, `gap16` ∈ [0.0079, 0.0108] ⇒ ±0.0015, KL A ∈ [0.0112, 0.0148],
  KL B ∈ [0.0136, 0.0180], смена top-1 ∈ [0.075, 0.101]. Отсюда три рабочих утверждения:
  (1) сдвиг `κ` внутри полосы у `rtn8` (0.01 %), `rand_K_d0.06` (0.27 %), `rand_full_d0.06` (0.37 %),
  `rand_full_d0.12` (0.16 %) и `gptq4` (0.46 %) — это «не различили», а не «изменилось на десятые
  долей процента»; (2) ущерб по всем 11 правкам вне полосы, и у `gptq4` KL B 0.0130 лежит **ниже**
  полосы iid-шума той же величины ⇒ структурированная ошибка квантизации мягче случайной при равном
  дрейфе `J` — это теперь заявляемо, а не «на глаз»; (3) доля позиций с зазором < 1 % внутри
  семейства прыгает от 0.016 до 1.00 — бинаризованный зазор не метрика (тот же урок, что и с
  sentinel-порогом 0.5 в `docs/E39_supplement.md` §6 п.10).
  Отдельно: уровень `κ` несогласован из-за док-бутстрапа на ±4.8 % (32 дока) / ±9.5 % (8 доков),
  rel SD между документами 14.2 % — потому сравнимы *отношения* на одних и тех же документах,
  а не уровни.

## 5. Чего этот эксперимент НЕ доказывает

* Не доказывает причинность: `n` правок ~13, режимов правки несколько, маргинальные корреляции
  читаются только вместе с пунктами 1–3.
* Не про глубину: L23 тривиален (`J = W_lm`), вывод про «как устроены промежуточные слои» отсюда не
  следует — там тот же вопрос решается на E-45b/E-46.
* Геометрическая линейка (дрейф, `κ`, спектр) считает по **ограниченному** якобиану: `J` на L23
  строится из 128 строк `W_lm[U128]` (`make_j_fn`), то есть это якобиан на корпусно-частотный
  базис, а не на словарь (та же оговорка, что и врезка `docs/paper.md` §2.5). Следствие для пары
  `rand_full`/`rand_K`: совпадающий «дрейф J» совпадает только по этим 128 строкам, остальные
  151 808 строк плотной правки для геометрии невидимы ⇒ читать пункт 3 надо как «вред растёт
  с числом задетых логиков при фиксированном дрейфе наблюдаемого блока», а не как «при равном
  полном возмущении». Для GPTQ это работает в консервативную сторону: его off-block часть в
  геометрию не входит, а в ущерб — входит.
* Не про «лист = память»: носительство проверяется отдельно (E-46), с null'ами той же
  размерности, включая нецентрированный PCA тех же `h`.

## 6. Калибровочная область применимости `κ` (E-45c, найдено нуль-контролем)

Свобода считывания `W → W + 1·cᵗ` (один и тот же вектор `c` ко всем строкам словаря) точна:
логиты получают одну и ту же добавку `c·ĥ_t` на позиции, softmax по словарю инвариантен ⇒ KL,
TV, top-1, PPL не меняются **ровно**. Проверка этим нулём и вскрыла границу:

* поведение инвариантно с точностью до float32-округления логитов: `max|Δz − c·ĥ|` = 1.3e-05 в
  fp32 против 1.3e-14 в fp64 (при масштабе добавки 2.4), отсюда остаток KL ~2e-06 при нуле TV-долей
  и нулевой смене top-1;
* **`J` в репозитории от калибровки двигается**. `make_j_fn` — якобиан *логитов* по направлению
  RMSNorm: спроецировано радиальное направление `ĥ`, по оси словаря не спроецировано ничего.
  Добавка равна `ΔJ_t = cs_t · 1_K ⊗ (d − (d·ḣ_t) ḣ_t)`, `d = g ∘ c`, и она не обнуляется;
  это ранг-1 член, предсказываемый наперёд — остаток факта против предсказания 2.5e-16…2.2e-15.
  Замер на модели (`results/exp45c_gauge_null.json`, `κ(J)` база 0.0147496):

  | калибровка `c` | `‖c‖` | дрейф `J` (медиана) | сдвиг `κ(J)` | сдвиг `κ(QJ)` | KL_max |
  |---|---|---|---|---|---|
  | случайный, `α=0.05` | 0.032 | 0.045 | **0.67 %** | 3.9e-06 | 1.9e-06 |
  | случайный, `α=0.15` | 0.095 | 0.138 | **3.9 %** | 1.7e-05 | 2.1e-06 |
  | случайный, `α=0.50` | 0.315 | 0.461 | **9.6 %** | 6.4e-06 | 1.9e-06 |
  | вдоль среднего `h`, `α=0.15` | 0.095 | 0.128 | **23.3 %** | 1.7e-05 | 2.0e-06 |
  | вдоль строки `W_0`, `α=0.15` | 0.095 | 0.136 | **1.5 %** | 2.7e-05 | 1.8e-06 |

  (`α` — доля от `σ_W√D`; дрейф — медиана попозиционных `‖ΔJ_t‖/‖J_t‖`.)
* левая проекция `Q = I − 1pᵗ` (p = `P128`, renormalized, `|Σp − 1| ≤ 2.8e-07`) калибровку убивает:
  дрейф `QJ` 1.6e-09…1.6e-08 (подавление относительно сырого `J` в 3e7 раз), `κ(QJ)` движется на
  4e-06…2.7e-05 — это уже не машинный нуль, а float32-под `document_profile` (внутри него `J`
  кастуется в fp32). То есть калибровочно-инвариантна `κ` ровно gauge-free проекции; порядок
  величины: `κ(QJ) = 0.3196` против `κ(J) = 0.0147` на той же L23.

Следствие для таблицы (важное): амплитуда калибровочной неоднозначности `κ(J)` — от 0.67 % до 23 %
на возмущениях, в поведении не видимых **никак**. Если в реальной правке есть калибровочная
компонента порядка `0.05–0.15·σ_W√D`, её вклад в `κ` перекрывает все межправочные различия таблицы,
кроме `flat_*` (сдвиги: `rtn8` 0.01 %, `gptq4` 0.46 %, `rand_*` 0.16–0.68 % при полосе разброса
одного draw'а ±0.52 %). **Оценка была завышена, E-45f (§7) её опроверг:** измеренное `‖c‖` у
случайных и квантизационных правок `0.0006–0.024·σ_W√D` (в 3–80 раз меньше априорного диапазона), а
сдвиг `κ` от одной калибровочной половины `≤ 0.29 %` — то есть для них калибровка межправочные
различия **не** перекрывает, и вывод «плотные и разреженные правки не двигают лист» остаётся в силе
как утверждение про `κ(J)`. Перекос настоящий, но сидит он не там: `‖c‖ = 0.17–0.30·σ_W√D` и
`s = 0.34–0.47` у обученных `flat_*` — единственных правок, где колонка `κ(gf)` обязательна (добавлена
в таблицу §4). Уточнение про сторону:
`document_profile` берёт **правые** подпространства (сторона скрытого состояния), а правило
`docs/ref-math.md` про «на сыром `J` измеряется калибровочный дрейф» говорит о **левой** (токенной)
связности; здесь видно, что правой тоже хватает (23 % на естественном направлении `c` — среднем `h`).

### Пререгистрация E-45f (выполнена, числа — §7)

Для каждой правки таблицы разложить `ΔW` по строкам `U128`: `c := (1/K) Σ_k ΔW_k`,
`ΔW_gauge = 1_K cᵗ`, `ΔW_gf = ΔW − ΔW_gauge`. Считать: долю `s = ‖ΔJ_gauge‖/‖ΔJ‖` (аналитически,
через ранг-1 член выше) и `κ` от правой и левой половин раскладжки. Критерии до чисел:

* F1: если `s ≥ 0.2` хотя бы у одной правки — все `κ`-сравнения в таблице требуют колонки
  `κ(gauge-free правка)`, иначе сравнение неатрибутируемо;
* F2: если `|Δκ|` от gauge-only правки ≥ половины `|Δκ|` полной — вывод об «уплощении листа» для
  этой правки снимается;
* F3 (предсказание, обязательное к опровержению): у плотных правок (`gptq4`, `rtn8`, `rand_full`)
  `s` заметно больше, чем у разреженных (`rand_K`, `flat_*`), потому что первые трогают весь
  словарь, то есть априори содержат компоненту вдоль `1_K`.
* самопроверки: `s = 0` у `base`; `s = 1` и `ΔJ` = ранг-1 у чистой калибровки из E-45c.

Стоимость: фаза `κ` — узкое горло (10 с/док пакетным SVD), поэтому вариант «только L23,
два дополнительных `κ` на правку» ≈ 15–20 минут CPU.

## 7. E-45f: сколько калибровки в каждой правке (`exp45f_gauge_decomp.py`, 2373 с CPU)

Раскладка `ΔW = 1_K cᵗ + ΔW_gf` по строкам `U128`, `s = ‖ΔJ_gauge‖_F/‖ΔJ‖_F` на позициях
геометрии (8 документов, те же, что у колонки `κ`), `κ` от целой правки, от gauge-половины и от
gauge-free половины. `κ` базы 0.01592091. Плотные правки таблицы не сохранялись — восстановлены
теми же детерминированными вызовами и сверены с таблицей: максимальное расхождение `κ`
**4.2e-05**, дрейфа **3.1e-08** (то есть восстановлено ровно то же самое, а не «похожее»).

Алгебра, на которой держится прогон (все три — assert'ы, не рассуждения): `J` линеен по `W_U`
при фиксированном `h` (остаток **1.09e-16**, поэтому `ΔJ = J(ΔW)` и базовый якобиан не нужен);
половины раскладки ортогональны **точно** (у `ΔW_gf` строки в сумме дают ноль ⇒ `Σ_k ΔJ_k = 0`, а
gauge-половина есть `1_K ⊗ v`), отсюда Пифагор по Фробениусу с остатком **2.2e-16** — то есть `s`
есть доля, а не отношение несопоставимых норм; раскладка узнаёт чистую калибровку (её gf-остаток
в `J` **2.3e-15**, ранг-1 остаток **1.1e-15**).

**F1 сработал, но не там, где ожидалось.** Порог `s ≥ 0.2` прошли только обученные уплощающие
носители: `flat_l0.01` 0.340, `flat_l0.1` 0.422, `flat_noleash` 0.469. У всех случайных и
квантизационных правок `s = 0.082–0.090` — это ровно `1/√128 = 0.0884`, то есть уровень iid-шума:
в правках, которые никто не оптимизировал по `κ`, калибровочной компоненты нет сверх того, что
обязано быть в любом случайном возмущении. Чтение: **обучение уплощению само находит
невидимое поведению направление** и кладёт в него 34–47 % движения `J` — KL-поводок его не
штрафует, потому что по этому направлению поведение не двигается вовсе.

**F2 сработал формально и бесполезно.** Список «gauge-only даёт ≥ половины сдвига κ» —
`rand_full_d0.12`, `seednull_s2`, `seednull_s3`, `seednull_s4`, `seednull_s7`. У всех них
полный сдвиг `κ` равен 0.08–0.24 %, то есть **внутри полосы разброса одного draw'а (±0.52 %)**:
отношение двух чисел, каждое из которых — шум. Критерий нужно дополнять условием
`|Δκ_полный| > полосы`, иначе он ловит не артефакт, а дележ шума. По единственными правкам,
где сдвиг `κ` вообще вне полосы (`flat_*`, −67…−87 %), gauge-половина даёт 8–17 % сдвига —
**вывод об уплощении листа остаётся в силе** и после вычитания калибровки: `κ(gf)` = −6.8 %,
−64.4 %, −76.7 % против полных −67.5 %, −78.9 %, −87.1 %.

**F3 опровергнут направление на противоположное.** Предсказание было «у плотных правок `s`
больше, потому что они трогают весь словарь». Измерено: плотные `gptq4`/`rtn8`/`rand_full` —
0.0845–0.0903, разреженные случайные — 0.0819–0.0903 (то же самое), а рекордные 0.34–0.47 у
**разреженных** обученных. «Трогает весь словарь ⇒ содержит `1_K`» неверно: содержимое
калибровочного направления определяется не охватом строк, а тем, оптимизировали ли правку по
величине, которая по этому направлению чувствительна.

Побочное, важное для чтения таблицы: половины складываются **неаддитивно**. У `flat_l0.1`
gauge-only даёт −8.95 %, gf −64.4 %, а вместе −78.9 % (сумма частей −73.4 %); у `flat_noleash`
−7.39 % и −76.7 % против −87.1 %. `κ` нелинеен по правке, поэтому «доля калибровки в Δκ» —
величина условная, и единственная корректная колонка — `κ(gf)` как отдельное измерение, а не
вычитание.

## 8. E-45g: что значит «зазор на r мал» (`exp45g_cut_stability.py`, 779 с CPU)

Повод: E-45b по пререгистрационному порогу `gap_r16 ≥ 0.01` объявил невалидными 99.7 % позиций,
и весь анализ листа стал пустым (`n = 0`). Между тем зазор на разрезе — не «у части позиций
плохой», а весь распределён вокруг одного числа: медиана 0.00875, процентиля 1/99 =
0.00792/0.01001 (свежий текст E-45b — 0.0087). Порог 0.01 стоял ровно на границе этого
распределения, то есть был догадкой, а не измерением.

Что вместо него: плаву́честь разреза, то есть как далеко уезжает `V₁₆` при шуме `ε‖J‖`.

| ε | доля позиций, где порядок σ₁₆>σ₁₇ ломается | max угол `V₁₆` | `Δκ` |
|---|---|---|---|
| 0 (повторный SVD) | 0 % | 0.00° | +0.00 % |
| 1e-07 (fp32) | 0 % | 0.00° | +0.00 % |
| 1e-06 | 0 % | 0.00° | −0.02 % |
| 1e-05 | 0 % | 0.05° | −0.14 % |
| 1e-04 | 0 % | 0.47° | +2.14 % |
| 1e-03 | 0 % | 4.69° | **+1054 %** |
| 1e-02 | 0 % | 41.44° | +31719 % |
| 0.06 / 0.12 / 0.25 | 0 % | 79.1° / 79.0° / 79.4° | ≈ ×342 (насыщение κ ≈ 5.44) |

Три вывода.

1. **Порог по абсолютному зазору — не критерий.** Порядок на разрезе не ломается **ни при каком**
   `ε ≤ 0.25`, а при машинном поле (1.2e-07) не двигается ни угол, ни `κ`: позиции, которые
   пререгистрация объявляла невалидными, численно воспроизводимы до последнего знака. Валидность
   в `exp45b_analysis.py` заменена на `gap ≥ 1e-4` (медианный зазор выше этого пола в ×8722), о
   чём в логе печатается обе доли.
2. **«Зазор мал» ≠ «разрез переставляется»:** эти два факта независимы, и путаница между ними
   стоила пустого анализа.
3. **Про «κ не двигается» — самое неприятное.** Изотропный шум **в пространстве `J`** при
   `ε = 1e-3` (в восемь раз меньше зазора) поднимает `κ` в 11.5 раз. Но этот шум лежит **вне
   образа** отображения `W_U → J`, а все правки таблицы — внутри него (`ΔJ = J(ΔW)` структурирован:
   та же проекция на `ḣ_t`, тот же `g`). Для правки из образа тот же дрейф стоит `κ` в 300 раз
   меньше: `rand_K_d0.25` — ×1.05 против ×342 у изотропного шума при `ε = 0.25`. Значит
   «`κ` не двигается» — утверждение **о направлении движения правок**, а не о жёсткости листа:
   лист можно двигать так, что `κ` сойдёт с ума, и таблицы показывают лишь, что исследованные
   правки идут по направлению, вдоль которого `κ` плоский.

### 9.2. Регистр «что с этим делать»

1. **`κ` нельзя продавать как метрику качества квантизации или правки весов.** Модель может терять
   PPL в процентах и в разах, а `κ` за это время не меняется вообще. Метрика, у которой диапазон
   отклика меньше шума повторного замера, не метрика качества.
2. **`κ` годится как детектор одного конкретного изменения** — систематического уплощения листа,
   которого сама обученная правка добивается намеренно. Использовать его как «измеритель здоровья
   структуры» нельзя, и после вычитания калибровочной компоненты он остаётся валидным ровно для
   этого одного случая.
3. **Часть «уплощения» дешёвая не в смысле пользы, а в смысле невидимости:** треть-половина движения
   `J` у обученных носителей лежит вдоль направления, которое вообще не влияет на вывод модели.
   Если интерпретировать такое уплощение как «перестройка внутреннего представления», интерпретация
   куплена за вычетом того, что ничего не меняет.
4. **Не сравнивать между собой базисы листа покомпонентно** (ни две правки, ни лист и PCA): разрез
   `r=16` стоит в месте, где соседние сингулярные числа разделены на 0.9 % от максимального, и
   направление `V₁₆` начинает вращаться при возмущении в сто раз меньшем, чем сами правки. Сравнимы
   только инварианты (`σ`, `PR`, `g_uni`, величина голономии), не векторы.
5. **Из «листа» не следует строить носитель состояния.** На равной размерности обычный PCA того же
   текста предсказывает следующий токен лучше, а единственное преимущество листа над случайным
   подпространством исчезает, как только сравнить их при равной норме. Практические методы —
   сжатие активаций, steering, выбор размеров — должны начинаться с этого нуля, иначе результат будет
   пересказом главных направлений.
6. **Что при этом остаётся живым:** сам лист (правые подпространства readout-якобиана) воспроизводится
   на двух разных носителях текста с расхождением 0.4 % — как объект он устойчив, бесполезен он
   в конкретном качестве «предиктора следующего токена» и «линейки качества правок».
