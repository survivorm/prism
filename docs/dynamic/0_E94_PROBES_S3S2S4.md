# E94 flip-lane: карта проб S3 / S2 / S4 / arm-B (черновик для ревью, 2026-11-12 05:00)

Родительский документ: `docs/dynamic/0_E94_Q2_supervisor_analysis.md` §17–§20 (факты,
которые пробы обязаны удержать). Сервер: форк llama.cpp, SYCL/iGPU, `/completion`.

## 0. Общая каноника запроса (как в Q1/Q2, чтобы адрес не уплыл)

`temperature 0.0, top_k 400, top_p 1.0, min_p 0.0, typical_p 1.0, xtc_probability 0.0,
repeat_penalty 1.0, repeat_last_n 0, dry_multiplier 1.0, mirostat 0, seed 8181,
n_probs 20, top_logprobs 20, logprobs true, cache_prompt true, n_predict 1`.
Адрес-воспроизводитель: prompt = `ids448(w4)[:70]` (детерминированный флип `w4 j=6/k=70`,
эмиссент `310` = `' to'`, вершина отчёта `318` = `' ('`, разрыв 0.638 логита).
Фон: `backend_sampling` в 432/432 закоммиченных ответов = false (наш канон с `n_probs 20`
сам его выключил), черновика нет (`speculative.types "none"`), вся цепочка нейтральна.

## S3 — свип `top_k` (главный, 8–10 запросов, без пересборки)

`top_k ∈ {1, 2, 3, 4, 8, 400}` на адресе `k=70`.

**Правило выбора контроли (добавлено по §22, до этого контроль был невалиден).** Флипа не
бывает там, где модель уверена: 0 из 11068 позиций с `p1 > 0.90`. Значит контроль обязан
лежать в той же зоне неопределённости, что и проверяемая позиция:
* основной контроль: **`w0` позиция 28** (`lp1 = -0.593`, `g12 = 0.494`) — та же зона, флипа нет;
* контроль внутри документа: ничейная позиция `w4` (`lp1 = -0.98`), флипа нет;
* `k=69` того же дока — оставляем как «сосед», но не как единственный контроль;
* «документ без флипов» (`w9`) годится только как отрицательный контроль на воспроизводимость
  адреса, но не на механизм.
Readout: эмиссент `id`, полный `top_logprobs`, ранг эмиссента в отчёте, `tokens_evaluated`,
эхо `generation_settings.top_k` (манипуляционная проверка, обязательна).
Пререгистрированные чтения:
- флип только при малом `k` -> дефект ветки усечения/привязки keep-массива, и канонические
  32 флипа требуют второго фактора;
- `top_k=1` даёт ранг 2 и на нефлипающих адресах -> безусловный дефект ветки `k=1`,
  к нашей аномалии не относится (полосу закрыть как incidental bug);
- при росте `k` эмиссент возвращается к 318 -> зависимость от размера кандидатов как функция.

## S2 — пара `backend_sampling` (2 запроса, без пересборки)

Единственная работающая комбинация: `backend_sampling: true` требует
`post_sampling_probs: true` (иначе `need_pre_sample_logits = n_probs>0 && !post_sampling_probs`
его глушит; форк так и считает). S2a: канон + `post_sampling_probs true` +
`backend_sampling true`; S2b: то же с `backend_sampling false`.
Readout: эмиссент `id` (318 = бэкенд прав, дефектна выборка на CPU; 310 = дефект не в
выборе между двумя сэмплерами) + `p` на равных `id` + длина списка кандидатов.
Инвариант апстрима: `tools/server/tests/unit/test_completion.py:529`
(`test_n_probs_post_backend_sampling`) утверждает одинаковые `id`/вероятности при
`backend_sampling` true vs false; расхождение пары = баг против защищённого инварианта.
Манипуляционная проверка: эхо `backend_sampling` = true в S2a, false в S2b.

## S4 — причинная проверка ничьей через `logit_bias` (2 запроса, без пересборки)

Основа: §20 — все 4 случая с `g12 < 0.03` имеют ранг 3, Фишер p = 4.17e-4; `w8 j=23`
исключает необходимость. Ручка запросовая: `field_json("logit_bias")`,
`tools/server/server-schema.cpp:430`, формат парой строки-токена
(`[[" (", -0.638]]`, см. `test_completion.py:598`).
S4a: на адресе `k=70` подать `logit_bias [[" (", -0.638]]` (вершины сравниваются).
S4b: контроль `-0.588` (ничьей нет, `top1` впереди на 0.05).
Readout: эмиссент и его ранг; уход глубже ранга 2 = ничья причинно углубляет пропуск;
оставаться в паре сравниваемой = ассоциация §20 не причинна.
Манипуляционная проверка: пара в эхо `generation_settings.logit_bias`.

## arm B — `-ngl 0` (перезапуск сервера, CPU-прогон)

Статус: **дискриминативная сила подорвана** (замечание ревьюера, родитель подтвердил):
отчётные логиты и так совпадают с fp32-эталоном 2304/2304, а `-ngl 0` возмущает прямой
проход, а не сэмплер. Перезапуск стоит весь сервер и блокирует S3/S2/S4 на то же окно.
Решение о нём принимать только после S3/S2/S4, и только если останется вопрос о
доставке логитов из SYCL-прогона в CPU-копию.

## Запрет на невалидные контроли (вместе с §21)

Нельзя называть контролем позицию с `p1 > 0.99` (их 90 % корпуса): пустое отрицание. Нельзя
также опираться на «порог уверенности» — по §22 порога нет, флипающие ничейные позиции лежат
внутренним окном, и никакой `p1 < c` их не отделяет.

## Порядок и инфраструктура

`S3 -> S2 -> S4` внутри **одного** запуска `llama-server`: постоянного сервера нет, прошлые
прогоны поднимали его сами (`LlamaServer, pick_port` в `exp94_sycl_common`), порт 8080 занят
чужим веб-приложением и не пригоден. Экономия раунда — один запуск на все три пробы; arm B —
второй запуск с `-ngl 0`.
