## Ревью `AT0_2_shape.py`: найденные баги

### Критические (меняют вердикт)

**1. `aggregate` — гейт домена считает клетки, не документы (нарушение ТЗ §0.3)**

```python
rows = [v for dlist in ddocs.values() for v in dlist]
nd_nondeg = sum(1 for (dg, _) in rows if not dg)
if nd_nondeg >= 12:
```

`nd_nondeg` — это число **клеток** (док × L), а не документов. ТЗ §0.3: «доменное утверждение только при **n≥12 невырожденных**» — по контексту («после фильтра wiki = 1») это документы.

В текущих данных wiki после фильтра = 1 док × 5 слоёв = 5 клеток — гейт провалится и по клеткам, и по докам. Но домен с 5 доками × 5 слоёв = 25 клеток **пройдёт гейт по клеткам** (25 ≥ 12), хотя доков только 5 (< 12). Это даст ложное доменное утверждение.

**Фикс**: `n_docs_nondeg = sum(1 for dlist in ddocs.values() if any(not dg for (dg,_) in dlist))` и `if n_docs_nondeg >= 12:`.

**2. AR-null: знак `sum_rho` ломает сравнение**

В `run_cell`:
```python
sgn = (rnull - 1.0) / 2.0   # sum_rho_AR
Pn, _ = band_shares_vec(bandsums[ok], c0n[ok], sgn[ok])
```

Для реальных данных `sum_rho_real ≈ +5.4` (dip −0.167 + plateau +5.3). Для AR(1) с φ ≈ −0.167 (из ρ̂(1) реальных данных): `sum_rho_AR = φ/(1−φ) ≈ −0.14` — **отрицательный**.

Тогда AR-«доли» = `bandsums / c0 / (−0.14)` — отрицательные. `C = mean(Pn)` отрицательный, `D_center = L1(p_real(+), C(−))` огромен, `p_doc ≈ 0` → verdict **refuted**. Но причина — не различие формы, а различие знака нормировки. Вердикт «refuted» направленно верен (AR не объясняет real), но получен по ложной причине.

**Фикс** (минимальный): в `run_cell` добавить проверку знака:
```python
same_sign = (np.sign(sgn[ok]) == np.sign(real["sum_rho"])).all()
if not same_sign:
    nulls[f"ar{p}"]["status"] = "not_testable_sign_mismatch"
    continue
```
Либо, если нужен сигнал: отчитывать `sum_rho_AR` рядом с `sum_rho_real` и не интерпретировать refuted при разных знаках.

### Существенные (могут влиять на интерпретацию)

**3. `h_raw` реконструкция из `hn` — потенциально битый источник (TPU-npz)**

```python
u, hn = d["layers"][L]
U = u / np.maximum(np.linalg.norm(u, axis=1, keepdims=True), 1e-12)
h = U * hn[:, None]
xs = {"h_raw": h[1:] - h[:-1], ...}
```

ТЗ v1.2 (G16) прямо предупреждает: **`_hn` в TPU-npz — нормы первых 384 *столбцов*, а не строк** (`hn_vs_column_norms_max_rel = 1.19e-4`). «Строки — сырые fp16-состояния, ‖row‖ — истинная норма».

Если источник — TPU-npz, `h = U * hn` даёт **не** `u`. `h_raw = h[1:] - h[:-1]` ≠ `u[1:] - u[:-1]`. Все `h_raw`-числа для TPU-доков недостоверны.

ТЗ (волна 0, п.3): «любой `h_raw` из TPU-npz пересчитывает ‖row‖». В скрипте этого нет.

**Проверить**: `a1.load_source` уже пересчитывает `‖row‖` для TPU? Если да — OK, если нет — `h_raw` для `own_*`/`cor_*` (TPU-sourced) сломан. `du_unit` и `v_tangent` не затронуты (`vpath` инвариантен к `hn`, TZ: «в curve_u hn сокращается 1.4e-16»).

**Минимальный фикс в скрипте** (если `a1` не чинит):
```python
hn_true = np.linalg.norm(u, axis=1)   # пересчёт истинных row-norms
h = U * hn_true[:, None]
```

**6. `gram_resid`-проверка в `main` избыточна**

В `cell_real`:

В `main`:

`gram_resid = |r_id − r_sum| / max(1, r_sum)`, и assert гарантирует `gram ≤ 1e-12 < 1e-10`. Значит `gram_bad` всегда пуст. Не баг, но бессмысленная проверка — либо убрать assert (оставить G8), либо убрать G8-проверку (assert строже).

**7. `null_blk_seam_excl` при b=2 даёт тривиальный профиль**

`kmax = min(b-1, 96) = 1`. Внутриблочные пары есть только для k=1. Профиль `[1, 0, 0, 0, 0]`. Это ожидаемо, но неинформативно. Не баг.

**8. `dists_to` игнорирует хвост (k≥97)**

По дизайну («хвост — отдельный скаляр tail_share»). Но два профиля, различающиеся только хвостом, имеют L1 = 0. Это ослабляет различение. Стоит либо включить `tail` в вектор (сделать 6-мерный), либо отчитывать `|tail_real − tail_null|` отдельно и включать в `p_doc` как второй критерий.

**9. `null_ar_batch` — один фит на все сиды**

`a, sig, m, info = null_ar_fit(x, p)` — фит один раз, используется для B сидов. Это нормально (мы варьируем ε, не параметры), но дисперсия параметров фита не отражена. Для `B=20` это означает, что оценка `D_null` не учитывает неопределённость в AR-коэффициентах. Стоит либо отчитывать, либо добавить bootstrap по параметрам.

**10. `band_sums_direct` для `hi > N-1`**

`hi = min(hi, N-1)` — OK, но тогда `hi` может стать меньше `lo`. Проверка `if lo > N - 1: continue` есть, но нет проверки `if lo > hi`. Для N=384, `BANDS[4] = (33, 96)`, `hi=96 ≤ 383` — OK. Но для коротких доков (если N < 34) `hi` усечётся ниже `lo`, и тогда `S1`/`S2` дадут мусор. Добавить:
```python
if lo > hi: continue
```

### Что проверено и корректно

- **Off-by-one в `band_sums_direct`**: правильный. `C[m] = Σ_{j<m} Y_j` (prefix sum), `S1 = C[t+hi+1] - C[t+lo]` = `Σ_{j=t+lo}^{t+hi} Y_j`. Проверено аналитически.
- **Перестановочная инвариантность `r`** (G7): правильная. `rnull = ‖Σy‖²/c0`; permutation сохраняет `Σy` и `c0`.
- **Fourier positive control**: правильный. DC и Nyquist фиксированы, круговой ACF совпадает точно.
- **AR фит (Yule-Walker)**: правильный. Toeplitz-матрица из biased autocovariance, `phi = T⁻¹ r`.
- **`acf_full` (FFT zero-padded до 2N-1)**: правильный. Отсутствие wrap-around для k ≤ N-1.
- **`boot_ci` (percentile)**: правильный.
- **`null_fourier`**: правильный — DC и Nyquist не рандомизируются, `irfft` даёт real.

## #2 (знак sum_rho в AR-null) — ЧАСТИЧНО: отклонено «неверная причина» и «p_doc ≈ 0», принято отчёт

- **«p_doc ≈ 0» невозможно конструктивно:** `p_doc = (#{s: D_s ≥ D_center} + 1)/(m + 1) ≥ 1/(B+1)
  = 1/21 ≈ 0.048` (ранг в числителе). В полном прогоне `p_docs_median = 0.0476` = ровно 1/21 —
  т.е. типичная клетка имеет минимально возможный p_doc, а не ≈0.
- **«refuted по ложной причине» — отклонено:** смена знака — не артефакт нормировки, а
  собственное свойство формы суррогата. AR(1), подогнанный Yule-Walker на ρ̂(1) ≈ −0.167,
  даёт ρ(k) = φ^k — знако-меняющееся затухание с суммой φ/(1−φ) ≈ −0.14; реальный профиль —
  положительное плато (сумма ≈ +5.4). Форма суррогата НАСТОЯЩЕ отличается от real, и знак
  суммы — часть формы, а не побочный эффект деления на (r−1)/2. Статус
  `not_testable_sign_mismatch` стёр бы истинный отрицательный результат (AR не объясняет real —
  это и есть вывод).
- **Принято (отчёт):** предложенный отчёт `sum_rho_AR` уже существует в записях null'а
  (`sum_rho_null_mean`, per-seed `sum_rho`, `r_null_mean`, `rho1_real` — строки 388–399).
  Добавлена строка в note AR-записи: знак sum_rho может быть отрицательным (AR(1), φ<0) —
  свойство суррогата, не баг нормировки; p_doc ≥ 1/(B+1) конструктивно.

## #3 (h_raw из TPU-npz) — ОТКЛОНЕНО (проверено), добавлен превентивный fail-loud пин

- **TPU-источники (P1_own/P2_corpus):** `a1.load_source` (AT0_1_accounting.py:183–188) ВООБЩЕ
  не использует битое поле `_hn`: `hn = np.linalg.norm(h, axis=1)` — пересчёт истинных
  row-norm'ов из сырых fp16-строк. Это ровно ТЗ-гейт «любой `h_raw` из TPU-npz пересчитывает
  ‖row‖» (волна 0, п.3). Поэтому `h = U·hn ≡` исходные строки и `h_raw = Δh` точен.
  Утверждение «все h_raw-числа для TPU-доков недостоверны» ложно для текущего кода.
- **Gen-источник (gen_layers_qwen.npz, продюсер exp62 — НЕ TPU-продюсер с багом):** u —
  unit-строки (‖u‖row ≈ 1.000), масштаб hn совпадает с row-norm'ами: замерено

  AT0_1 воспроизвёл ТЗ-янкоры (dip_raw,mean = −0.3708 и др.) по этим же gen-строкам —

## #8 (dists_to игнорирует хвост) — ОТКЛОНЕНО с доказательством

Хвост — не отдельная степень свободы: `tail_share = 1 − Σ₅band` (тождество G1: 5 полос + хвост

по неравенству треугольника `L1₅(p_r, p_n) ≥ |Σ₅p_r − Σ₅p_n| = |tail_r − tail_n|`:
разница хвостов НЕ ВЕРХНЕ, а НИЖНЕ ограничена band-L1. Различение не ослаблено.
Хвост остаётся отдельным скаляром (дизайн ТЗ: объявленная K=96-обрезка).
