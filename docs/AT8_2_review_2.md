# Ответы на ревью r1: AT8_2-R2 (docs/AT8_2_review.md)

Ревью: статическое чтение `AT8_2_R2.py` до main-прогона (F1–F7 флипперы,
M1–M7 несоответствия). Полный прогон r1-машиной к моменту ревью уже завершился
(verdict `LOOP_RESPONSE_DECAYS`, wall 2596 s). Фиксы ревью — статистический
дизайн машины, не реакция на числа; поэтому прогон не переделывался, а
пересчитывался disk-only (store → машина r2). Оба вердикта публикуются.

## Флипперы

### F1. Проверка `PHRASE_IDS` против токенизатора — **подтверждено**
В r1-машине чек не было (в `AT8_2_recovery.py` был). Проверено постфактум:
`tk(PHRASE)["input_ids"] == [561, 523, 668, 381, 5467, 506, 279, 5926, 13]`
— стимул прогона корректен. Фикс: `assert` в начале `run_main` +
`phrase_token_check: true` и `tokenizer` в манифесте.

### F2. `n*` без поправки на множественность — **подтверждено**
Фикс: первичная доза пре-регистрована `n=16` (константа `PRIMARY_DOSE`),
сканирование `n*` упразднено; дозовая кривая — диагностика. Скан по дозам
в r1-машине выбрал тот же n=16 (максимальная значимая доза), так что выбор
первичной дозы не был произвольным постфактум — но правило теперь честное.

### F3. `PERSISTS/NO_LOOP/GENERIC` по точечным оценкам — **подтверждено**
Фикс: CI-правила по всем веткам (doc-bootstrap, B=2000, seed 0):
- `PERSISTS` = CI_low(far) > δ_far;
- `DECAYS` = CI_low(near−far) > 0 И CI_high(far) ≤ δ_far;
- `GENERIC` = max CI_low(near_generic) > δ_near;
- `NO_LOOP` = все CI_low(near) ≤ δ_near И CI_low(near_generic) ≤ δ_near.

### F4. `δ_min` из другой статистики — **подтверждено, главный флиппер**
r1-машина: δ = 95th pct **позиционных** |e_null| (L23: 0.0823) сравнивался
с **док-агрегированными** near (90th pct 16 точек) / far (mean 16 точек).
Это ровно класс ошибки из AGENTS-чк-листа п.1 («одинаковая статистика на
обеих сторонах сравнения»).

Пересчёт по тому же пайплайну (null → per-doc near/far → 95th pct):
δ_near = **0.1480**, δ_far = **0.0332** (vs старые 0.0823 / —).

Последствие (число из store, machine r2):
- near(n=16) = 0.1020, CI95 = [0.0844, 0.1197] → CI_low 0.0844 ≤ δ_near
  0.1480 → **не значимо**; по всем дозам: CI_low = 0.0676/0.0606/0.0780/0.0844.
- far(n=16) = 0.0225, CI95 = [0.0204, 0.0247] ≤ δ_far → не PERSISTS.
- near_generic max = 0.1386, CI_low = 0.1160 ≤ δ_near → не GENERIC.

**Вердикт машины r1 `LOOP_RESPONSE_DECAYS` — артефакт мискалиброванного
порога; вердикт машины r2 — `NO_LOOP_SPECIFIC_EFFECT`.** Именно это
превращение («DECAYS → NO_LOOP без изменения физики») ревью и предсказало.

### F5. `G_inside` с абсолютными порогами — **подтверждено (дизайн), в прогоне не сработало**
Измерено на store (n=16): парный гейт (loop < fillerA И loop < fillerB)
— **14/14**; абсолютный (loop < 1.0, fillerA ≥ 2.0) — **13/14**
(единственный miss: chat_2 fillerA = 1.982). Все loop_blocks = 0.38–0.51
— абс-порог по лупу дал бы ложных провалов ноль, риск ревью был только в
стороне филлера (и он едва не сработал: 1.982 < 2.0).
Фикс: парный гейт — основной, порог ≥75% доков (ceil(0.75×n)); абсолютные
пороги — вторичная диагностика (`inside_abs_pass`).

### F6. Слой-тег `LAYER_INCONSISTENT` — **подтверждено**
Фикс: ветка убрана; ≥1 внутреннего слоя без L23 → `INTERNAL_ONLY`.
`LAYER_INCONSISTENT` вводится только с пре-заданным критерием (разные знаки/
формы затухания) — не сделано, тега нет. В этом прогоне ни один слой
значим (см. F4) → тег `layer: null`. (FIELD_RESPONSE в r1-машине — тоже
артефакт мискалиброванного δ.)

### F7. Пул: ≥2 дока во всех доменах vs `DOMAINS_MIN=3` — **подтверждено**
`DOMAINS_MIN=3` была мёртвой логикой (код всё равно требовал 4 домена).
Фикс: честно `DOMAINS_MIN=4` — все 4 домена обязательны, по ≥2 дока;
при k=2 филлеры берутся из следующего домена (реализовано). Пул прогона:
wiki 4 / math 2 / code 4 / chat 4 = 14 доков — валиден по новому правилу.

## Менее опасные

### M1. Граничный (шовный) инкремент — **подтверждено, вариант A**
Зафиксировано: option A — post-ряд начинается с `cut + L_n`, шов
(`cos_raw[cut+L_n−1]`) вне окна; near[0] = первая внутренняя пара суффикса.
Диагностика шва (из store, L23, e_spec): n=2/4/8/16 → **−0.063 / −0.081 /
−0.055 / −0.080** — знак противоположен near[0] (+0.049…+0.061): на самом
шве луп против филлера даёт отрицательный сдвиг, т.е. исключение шва не
«подсаживает» near в положительную сторону — если бы шов включать, эффект
был бы ещё меньше. Значение шва в JSON (`seam`).

### M2. `e_generic` смешивает вставку и сдвиг — **подтверждено (ограничение)**
Зафиксировано в отчёте: e_generic = «вставка текста данной длины» +
сдвиг абсолютных позиций; разделению нужен доп. контроль (вставка в
другом месте), который не делался — для основного вопроса (e_spec = loop −
fillerA, позиции идентичны) некритично.

### M3. Филлеры из того же пула — **подтверждено**
`filler_source: "same_pool_cross_doc"` в манифесте. Ограничение: единица
бутстрапа — док, а филлеры перекрещены; учтено в отчёте как caveat.
Отдельный filler-пул не делался (дороже на 100% форвардов, для данного
вопроса не требуется).

### M4. `docs_sha256` от текста — **подтверждено**
Фикс: fingerprint от токенов (`sha256(np.array(ids).tobytes())`); `doc_lens`
в манифесте (был и до фикса).

### M5. Finite-гейт в анализе — **подтверждено**
Фикс: fail-loud гейт до вердикта (ce + cos_raw/cos_state/norm_delta по всем
условиям/слоям + e_spec/e_generic/e_null). В этом прогоне: PASS.

### M6. JSON-store > 10 MB — **подтверждено, обработано по AGENTS**
store 12.2 MB, npz 10.8 MB — оба > 10 MB: **не в git** (.gitignore),
бэкап `/data/prism_backups/at8_2_r2/`, sha256 обоих в манифесте. Полные
ряды живут в store (источник для reanalysis) и npz (копия); slimming
store — смена формата, не делался (правило AGENTS — о git, не выполнению).

### M7. NPZ при resume — **подтверждено (дефект r1-машины)**
Фикс: npz строится **из store** (`_series_from_store`) — полный набор при
любом resume. В завершённом прогоне resume не было, артефакт полон
(14 доков × 7 условий).
