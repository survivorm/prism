### 0.1 Серая зона 60–95 (пояснение пользователя — обязательный режим аудита)

Там агент «ушёл с головой в задачу и мог начепушить». Значит для номеров **60–95**:

1. **`paper.md`/`ref-exp` для этого диапазона — не ориентир, а подозреваемый.** Число оттуда
   считается неподтверждённым, пока не пересчитано; «совпадает с кодом» тоже не аргумент — код мог
   быть подогнан под вывод. Снятие подозрения — только независимым пересчётом (аналитика / другой
   скрипт / другая реализация того же нуля).
2. **Аудит по коду идёт первым и независимо** от доков: сначала восстанавливаем, что скрипт реально
   считает, потом смотрим, что об этом написано.
3. **Класс дополняется уровнем доверия** `trust: verified | unverified | suspect`; для 60–95 по
   умолчанию `suspect`.

## 1. Фазы (жёсткий порядок, каждая — с артефактом на диске)

### Фаза A0 — инвентарь диска и внешних хранилищ (read-only, ПЕРВОЙ)

Найти уже существующие артефакты, чтобы не перезапускать найденное. Обходятся: `results/**`
(включая `results/eNN/`, `results/AT0/`, `results/archive/`), `/data/prism_kernels`, `/data/exp19chk`,
`/data/stage`, `/data/kout`, `/tmp/recovered`, `logs/`, `/tmp/*.log`. Матчинг: (а) каталог `eNN`/`expNN`,
(б) имена выходных файлов из кода, (в) манифесты (`*_manifest.json`, `ARTIFACTS_MANIFEST.json`).
Выход: таблица `номер | артефакт | путь | размер | mtime | git-tracked? | годится как ответ?`.
Артефакт без лога/провенанса — **не засчитывается как ответ**, только «след, требует перепроверки».
Файл: `docs/dynamic/RERUN_DISK_INVENTORY.md`, маркер `RERUN_DISK_DONE`.

### Фаза A0-V — научная ценность «потерянных экспов» (отдельный вопрос пользователя)

Для каждого номера/темы 60–95 и 20 «мёртвых» — оценка **ценности**, а не статуса артефакта:

1. **Вопрос:** какую гипотезу проверяет тема и не закрыта ли она уже (другим `E-NN`, аналитикой,
   `paper.md`)?
2. **Новизна:** есть ли ответ что-то сверх известного (новая величина / новый нуль / независимое
   подтверждение)?
3. **Проверяемость:** достижим ли ответ на текущих данных и железе (`runnable-now`)?
4. **Цена:** оценка wall/памяти по константам скрипта.
5. **Вердикт:** `high` (меняет вывод) / `medium` (уточняет число) / `low` (перепроверка без нового
   вывода) / `не нужно` (вопрос закрыт или ни на что не влияет).

Выход: `docs/dynamic/RERUN_VALUE.md`, маркер `RERUN_VALUE_DONE`. **Перезапуски без этой таблицы не
начинаются**: иначе поток превращается в «прогнать 41 скрипт, потому что он есть».

### Фаза A — карта ожиданий (read-only)

Для каждой темы 20 «мёртвых» номеров найти, **отвечен ли уже тот же вопрос под другим `E-NN`**
(пример: `exp79_jlens` ↔ `E-38g_jlens`, `exp80_ring` ↔ ?). Источники: `docs/ref-exp.md`,
`docs/paper.md`, `results/` (по ключевым словам скрипта), `docs/*.md`.
Результат: таблица `тема | номер скрипта | уже отвечено в (E-NN / раздел paper) | вывод: дубль /
новый вопрос / неясно`.
Выход: `docs/dynamic/RERUN_MAP.md`, маркер `RERUN_MAP_DONE`.

### Фаза B — аудит по коду (без запусков, главный шаг)

Для каждого скрипта из 41 (по группам) — чек-лист, всё **исполнением/чтением кода**, не «глазами»:

1. **Самодостаточность:** какие входы читает (пути `results/…`, модели, датасеты); существуют ли они
   сейчас; есть ли `argparse`-дефолты; пишет ли артефакт и куда.
2. **Соответствие вопросу:** считается ли в коде именно та величина, которую обещает docstring/имя
   (`Q1` из `strayed_experiments_TZ.md`).
3. **Математика/статистика (Q2):** нуль-контроль, число перемешиваний, размер эффекта — есть или нет.
4. **Детерминизм:** seed фиксирован? воспроизводим ли результат при повторном прогоне?
5. **Стоимость:** оценка wall/памяти по константам скрипта (объёмы, число итераций, размер модели).
6. **Класс:** `runnable-now` / `needs-input` (нет входа) / `needs-fix` (баг, тогда — находка Q5) /
   `dead` (дубль E-NN, вопрос закрыт).

Выход: `docs/dynamic/RERUN_CODE_AUDIT.md` (+ таблица по 41 скрипту), маркер `RERUN_AUDIT_DONE`.
**Перезапуск запрещён до появления этого файла и внешнего ревью по нему.**

### Фаза C — перезапуск (только `runnable-now`)

- Только через `./run_one.sh <name> <script+args>`; запуск `setsid nohup … &`; **одна CPU-задача за раз**;
  BUSY = читать лог, не перезапускать.
- trackio обязателен (run name `expNN_<имя>_r1`, `step` = wall-секунды, границы этапов, `script_sha`,
  `seed`, `status: ok|crash|interrupted`).
- Артефакт пишется в `results/` c провенансом: `machine`, `seed`, `script_sha`, `git_commit`,
  `started_at/finished_at`, `model` (если модель), `wall_s`.
- Пакетирование по стоимости: сначала чисто-numpy (`55, 56, 63, 67, 80, 81a, 90, 24`), потом
  модельные (`65, 66, 68, 69, 70, 72, 73, 75, 77, 78, 79, 81b/c, 91`) — отдельными пачками,
  каждая пачка фиксируется в отчёте.

### Фаза D — сверка с опубликованным (paper = ориентир, НЕ оракул)

- Для тем, у которых числа в `paper.md`/`ref-exp` есть: сравнить **знак и порядок величины**;
  допуск — «более-менее» (§ задание), численно: совпадение знака + относительное расхождение <50 %
  или явное объяснение.
- Любое расхождение — **находка** (`docs/dynamic/RERUN_FINDINGS.md`), `paper.md` в этом потоке
  **не правится**. Правка канона — отдельная волна с публикацией обоих вердиктов (AGENTS.md п.10).
- Отдельная строка отчёта: «код не воспроизводит опубликованное число» — это результат, а не баг,
  который надо «исправить подгонкой».

## 2. Запреты (нарушение = откат)

1. **Запрещено подгонять код/параметры под числа `paper.md`/`ref-exp`.** Код правится только при
   доказанном баге (Фаза B, `needs-fix`), баг фиксируется до правки, правка мотивируется математикой,
   а не «чтобы совпало».
2. Запрещено править `paper.md` в этом потоке.
3. Запрещено запускать больше одной CPU-экспериментальной задачи одновременно; `avail < 10G` — ждать.
4. Запрещено объявлять прогон успешным без маркера в логе (`RUN_RC=0` + артефакт + `scripts_sha`).
5. Запрещено «додумывать» отсутствующие артефакты: если вход потерян и не восстанавливается из
   git-истории — так и пишется (`needs-input`), без реконструкции «по памяти».
6. Запрещено считать `paper.md`/`ref-exp` ориентиром для диапазона 60–95 (серая зона): там
   любое число — подозреваемое до независимого пересчёта (§0.1).

## 3. Критерии приёмки потока

1. `docs/dynamic/RERUN_DISK_INVENTORY.md` (Фаза A0) и `docs/dynamic/RERUN_VALUE.md` (ценность) +
   `docs/dynamic/RERUN_MAP.md` + `docs/dynamic/RERUN_CODE_AUDIT.md` существуют, по 41 скрипту есть
   строка с классом и `trust`; классы обоснованы ссылкой на строку кода / `ls` входа.
2. Для каждого `runnable-now` — либо артефакт в `results/` с провенансом, либо запись «не дошло до
   запуска» с причиной (STOP).
3. Внешнее ревью кода аудита и артефактов: `docs/dynamic/RERUN_AUDIT_REVIEW.md`, `VERDICT:`,
   маркер `REVIEW_RERUN_DONE`.
4. Коммит — явными путями; артефакты >10 MB в git не кладутся (кроме `.json.gz`, если иначе никак —
   решение отдельно).

## 4. STOP-условия

- Скрипт требует вход, которого нет и который не восстанавливается из git → `needs-input`, дальше не идти.
- Скрипт падает на импорте/несовместимости API (torch/transformers версии) → классифицировать
  `needs-fix`, **не чинить молча**: сначала запись находки + минимум-патч с ревью.
- Аудит показывает, что скрипт считает не то, что заявлено → класс `needs-fix` + находка Q1/Q5;
  перезапуск такого скрипта бессмысленен до исправления.
- Любая попытка «догнать» число paper параметрами → STOP, откат.
