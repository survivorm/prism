### m2 — комбинированный объём памяти — ЗАКРЫТО
(a) Формулы `need` соответствуют реальным буферам (сверка с кодом):
- gemm: `4*(M*K + K*N + 2*M*N)` = dA(M*K) + dB(K*N) + dC(M*N) + хост-копия C(M*N) ✓
- eigjac: `5*4*batch*n²` = device dA + dVT (2) + host vt32, vecs32, out_vecs (3) ✓
- eigbot: `4*batch*n²*8 + 2*4*batch*n²` = 4 f64-копии host-Cholesky (a_f64, μI, сумма,
  L) + L32 + device-копия L ✓ (малые dOff/dDiag/μ-векторы не учтены — незначимы на
  GiB-масштабе).
(b) Ложных срабатываний на реальных размерах НЕТ (устройство: global_mem =
   58.25 GiB → бюджет 0.5·global = 29.15 GiB; исполнено/арифметика): gemm 128×1024@1024×128
   и 1024×128@128×1024 ≈ 0.001–0.002 GiB; eigjac batch=16384 n=128 = 5.00 GiB;
   eigjac batch=1024 n=256 = 1.25 GiB; eigbot batch=16384 n=128 = 10.00 GiB — все в
   бюджете. (Примечание: бюджет зависит от машины; на iGPU с меньшей долей RAM
   (бюджет < 10 GiB) guard отклонил бы eigbot 16384×128 — на целевой машине это
   не так.) (в) reference-режим: бюджет = 1<<62, guard не срабатывает (код +
   исполнение — reference-eigjac работает). (г) Порядок: в gemm — _contig32 (dtype) →
   формы → PS_ERR_ARG по размерам → _check_mem; в eigbot — _eig_check_args (PS_ERR_ARG/
   PS_ERR_LOCAL) → _check_mem → Cholesky; в eigjac — PS_ERR_ARG → curve-проверки →
   _check_mem — все аргс/dtype-проверки ПРЕДШЕСТВУЮТ mem-guard'у (код). Срабатывание:
   `_check_mem(budget+1)` → RuntimeError «PS_ERR_MEM — … требует … GiB > бюджета … GiB
   (0.5·global_mem: iGPU делит RAM с хостом)»; в бюджете — молча (исполнено). C++
   сообщения `malloc_device failed` теперь с GiB и размерностями: gemm_impl (M,K,N),
   eig_impl (batch,n,r), eigjac_impl (batch,n) (код).
