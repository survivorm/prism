## 1. Блокер 1 (алгебра e_phr) — СПОР: «раскрытие» не является раскрытием
заданного определения; остаток (масштаб нуля) — принят и решён структурно

- Ревью цитирует TZ §7 дословно: `e_phr = loop1 − loop2`. Затем «раскрывает»:
  `e_phr = (L1−L2) − e_null`. Это равенство не имеет места:
  `(L1−L2) = (L1−L2) − (F_A−F_B)` только при `F_A = F_B`. Правая часть ревью —
  на самом деле разность **`e_spec1 − e_spec2`** = `(L1−F_A) − (L2−F_B) =
  (L1−L2) − (F_A−F_B)` — то есть **другой контраст**, не тот, что в TZ.
- Механизм ложного срабатывания «если `L1 ≈ L2`, то `e_phr ≈ −e_null`» также
  про `e_spec1 − e_spec2`, а не про `e_phr`: при `L1 ≈ L2` у `e_phr = L1 − L2`
  имеем `≈ 0` по определению, не `−e_null`.
- Тестовая статистика не нуль-вычитается: тест TZ —
  `CI_low(near_phr) > δ`, где δ = 95th pct per-doc p90|e_null|. Это сравнение
  e_phr (L1−L2) с порогом, калиброванным на e_null, а не сравнение
  `(e_phr − e_null)` с e_null («|X − N| против порога по |N|» — не о нашем
  тесте).
- **Остаток (принят).** При H0 `e_phr` = разность двух **луповых** условий,
  `e_null` = разность двух **филлерных** — тождество масштабов этих двух
  типов разностей не верифицировано (row-type mismatch). Реальный, но слабый
  вопрос, не алгебраический. В v1.1 решён структурно: у каждого контраста —
  собственный нуль того же семейства (REP ← `N_perm = S1−S1'`, PHR ←
  `N_content = S1−S2`), а INT прямо мониторит row-type mismatch (если
  контентное различие в луповой строке ≠ в непериодической, INT
  значим → тег `INTERACT_SIGNIFICANT`, вердикт читается с оговоркой).
- Эмпирика (R2-store, L23, n16, 14 доков): near-отношение
  e_spec/e_null в cos_raw = 0.1020/0.1328 = 0.77 — старый дизайн не был
  катастрофически мискалиброван, но структурный фикс лучше (см. п. 3).

## 2. Блокер 2 (e_rep) — ПРИНЯТО

- `e_rep = (L1+L2)/2 − (F_A+F_B)/2` — действительно «луп против филлера», где
  луп-сторона — две конкретные фразы, а филлер-сторона — **чужой контент**:
  периодичность конфаундится с идентичностью контента. Усреднение гасит
  контент-зависимый эффект повторения; при «обе дают эффект» не разделяет
  «повторяемость как таковую» от «средней реакции на эти два текста» (филлерный
  контент тоже входит в среднее).
- Чистый тест «повторения как свойства» = контраст, где при том же лексическом
  составе сломана только периодичность → shuffled-условия S1/S2 (п. 3).
- Старый `e_rep` сохранён в v1.1 как **диагностика** (R2-сравниваемость:
  `e_rep_legacy`), не как вердиктный.

## 3. Факторизация 2×2 — ПРИНЯТО, плюс `S1'`

- Ортогональность проверена: клетки (L1, L2, S1, S2);
  REP=(1,1,−1,−1)/2, PHR=(1,−1,1,−1)/2, INT=(1,−1,−1,1)/2 — попарные
  скалярные произведения = 0 ✓.
- **Дополнение: `S1'` — вторая выборка шифра S1.** В дизайне и смете ревью —
  S1, S2, но объявленный ревью нуль REP — «`S1 − S1'` (два независимых shuffle
  одного текста)» — требует третьей выборки. Без `S1'` у REP **нет чистого
  нуля**: `N_content = S1−S2` несёт контентный эффект, который тестируется
  (PHR), — нуль REP был бы заражён сигналом другого контраста. Цена `S1'`:
  +28 форвардов (14 доков × 2 дозы) → **112** новых форвардов (84 в «урезанном»
  расчёте ревью), ≈ 27 мин — тот же порядок.
- Назначение нулей (зафиксировано в TZ v1.1 §7–8):
  - REP ← `N_perm = S1 − S1'` — тот же мультисет, та же структура, другой
    draw — чистый шум перестановки;
  - PHR ← `N_content = S1 − S2` — контентное различие без периодичности;
  - INT — report-only, нуля нет (и диагностика допущения о нулях, §1 п. 1).

## 4. Наблюдаемая — СПОР, с замером

Ревью: «cos_raw — то, что в R2 не увидело эффекта (δ_near 0.148 против 0.102);
CE — сигнал огромный». Измерено по R2-store (14 доков, 5 слоёв, n16 и n2;
post-позиции; near d∈[0,15]; отношение = mean_i p90|e_spec| /
95pct_i p90|e_null| — та же статистика, что в R2-вердикте):

| наблюдаемая | L23 near n16 | L23 near n2 | замечание |
|---|---|---|---|
| cos_raw | 0.1020/0.1328 = **0.77** | 0.0809/0.1526 = 0.53 | вердиктная R2 |
| CE (pos) | 2.2165/3.3844 = **0.65** | 1.4989/3.2296 = 0.46 | **не зависит от слоя** (одинаково на L6–L23) |
| norm_delta | 1.2251/1.5668 = **0.78** | 0.8681/1.1590 = 0.75 | лучший слой L12: 0.92 |

- «Огромный сигнал» (0.38–0.51 vs ~4 nat) — это **CE внутри блока** —
  обучение, а не пост-эффект (ревью само: «вопрос только в пост-эффекте»).
  **Пост-эффектный** CE-контраст (post-позиции) — 0.65 при n16 и 0.46 при n2 —
  **хуже** cos_raw (0.77/0.53), и CE слеп по слоям (нет субструктуры).
- Вывод: смена primary на CE не даёт выигрыша мощности — это замер, не
  предположение. TZ v1.1: **cos_raw остаётся primary** (сравниваемость с R2);
  CE и norm_delta — report-only вторичные (уже пишутся в store, нулевая цена).

## 5. (a) Доза — ПРИНЯТО (с примечанием о провенансе чисел)

- n=16: `DOSE_FLAT` (I_loop 59.2→64.6, +9%) и кривая обучения из store
  (r1 CE 4.66 → r2 0.38 → r3 0.13 — фраза выучена ко 2–3 повтору) → на n=16
  контентное различие L1/L2 минимально. n=2: контент максимально жив.
  **v1.1: PHR primary — n=2, REP primary — n=16** (содержательное решение по
  механике насыщения, пререгистрировано до прогона, не подгонка).
- Провенанс (урок 0.0294/0.0204): «первая реплика 2.06, вторая 0.38» — в
  R2-store: r2 (первые 8 токенов второй реплики, доз-инвариантно) =
  **0.39** (среднее по 14 докам; по докам 0.24–0.57) ✓ подтверждено;
  r1 = 4.66 (среднее по 14 докам; по докам 3.58–6.10) —
  **2.06 в store нет** (ни среднее, ни медиана, ни док). Качественная кривая
  подтверждена (r3 = 0.13).
- Дозы n=4/n=8 не гоняются: R2-плато по дозам; две точки честнее четырёх,
  три из которых — плато (принято).

## 6. (b) LEARN_ASYMM → INT — ПРИНЯТО

- `INT = ((L1−S1) − (L2−S2))/2` — это и есть «разная обучаемость ×
  повторяемость» (различие контентного эффекта по строкам периодичности).
  v1.1: INT — отдельный исход (значение + CI, обе дозы, L23); тег
  `INTERACT_SIGNIFICANT` при `CI_low(near_INT(n=16)) > δ_REP` — вердикт
  читается с оговоркой «эффект повторения контент-зависим». Старый тег
  LEARN_ASYMM (block-CE ratio > 3×) остаётся дополнительным тегом — это другой
  замер (CE внутри блока), не замена INT.

## 7. (c) Перекалибровка δ — ПРИНЯТО

- v1.1: `δ_REP = 95th pct {per-doc p90|N_perm|}` (28 значений: 14 док × 2
  дозы), `δ_PHR = 95th pct {per-doc p90|N_content|}` — нули из того же
  семейства контрастов, из тех же новых форвардов (урок F4). Старый R2 δ
  (e_null: 0.1480/0.0332) — остаётся **fail-loud integrity-якорем** пайплайна
  R2-store (диагностика), не порогом вердикта.

## 8. (d) Множественность — ЧАСТИЧНЫЙ СПОР

- В TZ уже была декларация primary: дерево v1.0, шаг 3 — «Первичная доза
  n=16, L23», остальное — диагностика без вердиктной роли. Вердиктная
  поверхность — не «30 проверок»: в v1.1 она **ровно 2 проверки** (S_phr на
  n=2, S_rep на n=16; каждая на L23; у каждой — doc-bootstrap CI). Поверхность
  зафиксирована пре-регом → поправлять нечего (Bonferroni не требуется:
  проверяется ровно то, что пререгистрировано). INT/другие дозы/слои —
  диагностика без вердиктной роли (явно в дереве, v1.1 §11).

## 9. Слияние с AT8_3 — направление ПРИНЯТО, но прецеденты не выполнены;
и арифметика 208 фд — не про текущий дизайн 8_3

- **Ревью верно: у 8_3 открыты вердикт-критические пункты.** Ревью AT8_3 r3
  на диске (`docs/AT8_3_review.md`, «Ревью ответа исполнителя по AT8_3
  (6 фиксов)», F1–F5 + патч-лист 1–8, «ТЗ к коду не готово») — все 5
  вердикт-значимых пунктов **открыты в TZ v1.2** (проверено построчно):
  1. **H_eval = 97 (varying-горизонт):** TZ v1.2, строка 56 — «горизонт
     `D = T − cut − 1` на док (97…127)» — D по-прежнему варьированный,
     H_eval не введён;
  2. **Знаменатель (16 vs #resolved) + `n_resolved`/`n_no_response` +
     `LOW_POWER`:** в TZ нет (grep: ни LOW_POWER, ни n_resolved);
  3. **Таблица k → CI_lower + CI-гейт либо честная декларация точечного
     критерия:** v1.2 оставил точечный критерий (frac ≥ 0.5 по дозе, строка
     186), но таблицы методов нет — арифметика 14/16, на которую опиралось
     снятие CI, не воспроизводится ни одним стандартным методом (F3 ревью:
     Clopper–Pearson 13, Wilson 12);
  4. **Строгое `frac > 0.5` либо блокирующий WIDE_CI:** v1.2 строка 186 —
     «`frac ≥ 0.5` ⇔ **≥8 из 16**» — монетная точка 8/16 теперь явно
     проходит, WIDE_CI — тег (строка 201), не гейт;
  5. **Доз-зависимый гейт филлеров:** v1.2 строка 104 — S4 измерен только на
     «144-токеновых блоках»; при n=2 окно = 2×9-граммы (count=2 < 3 → луп
     проходит как «не-луп») — ни per-dose таблицы, ни процедуры замены.
  Четыре пункта, названные 2b-ревью (H_eval, знаменатель, CI-гейт, слепой
  гейт), ⊂ этих пяти (плюс пункт 4 — монетка, который 2b-ревью не называет,
  но тоже открыт).
- **Арифметика 208 фд — не про текущий дизайн 8_3.** Таблица слияния ревью
  считает условия 8_3 на 2 дозах (n=2, n=16) → 16×(1+2×6) = 208. Но дозовый
  дизайн 8_3 — **n16/n18/n36/n72** (TZ v1.2, 4 дозы — дозовая ось часть
  A_spec/ξ). При сохранении 4 доз 8_3 слияние = 16×(1 + 4×4 + 2×4) = **400** (с S1')
  > 224 + 112 = 336 (отдельные прогоны) — **слияне дороже**. Экономия ~26%
  держится только на сокращении 8_3 с 4 доз до 2 — это решение лупа 8_3, не
  слияния.
- **Решение:** (1) сначала закрыть патч-пункты 1–5 по 8_3 (следующий шаг
  8_3-лупа); (2) потом — объединённый пре-рег (архитектор предложил его
  расписать: условия, контрасты с нулями, дерево REP/PHR/INT + локализация
  8_3, гейты, store с h-векторами, смета); (3) до того — **2b TZ v1.1 как
  standalone факторный эксперимент на R2-пуле** (112 форвардов ≈ 30 мин CPU):
  готов к запуску, не наследует дыры 8_3, сохраняет сравниваемость с R2 (пул,
  геометрия, наблюдаемая — те же). Если объединённый пре-рег утвердят до
  запуска 2b, standalone-прогон можно пропустить — явное решение в PLAN, не
  молчаливое.
