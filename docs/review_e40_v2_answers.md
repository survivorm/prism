## 2. С чем спорю

### 2.1 N4: «strict-вариантов в `results/` нет» — неверно для рабочего дерева

```
$ ls results/ | grep exp33r
exp33r_gauge_anatomy.json
exp33r_gauge_anatomy_e33r2_0830.json
exp33r_gauge_anatomy_rerun.json
exp33r_gauge_anatomy_strict.json          <-- есть
exp33r_gauge_anatomy_strict_diag.json     <-- есть, именно его читает E-40.7
```

Ревьюер не увидел их по той же причине, по которой не увидел `exp31_correlation_function.json`,
`exp39_supp_three_objects.json` и весь exp27b-кэш: `results/*.json` в `.gitignore` (строка 47).
Это политика репозитория до E-40: в git трекаются `.log`-и единицы JSON-ов. Логика «вывод не
подкреплён артефактом» тогда равным образом убивает E-31, E-32tail, E-33r — т.е. полстатьи.
Провенанс закрыт другим механизмом: `header()` пишет `sha256_16` каждого входа, а `sha16()`
падает, если файла нет. В (d) это записано явно. Что принято: **операторы** `fixP` в (d) и в S07
разные (`pair_mean` против `P(p̄)`), это настоящая коллизия имён — устранена маркировкой.

### 2.2 N7: «артефакты не закоммичены ⇒ утверждения непроверяемы»

Требование «закоммитить хотя бы метаданные» выполнено внутри артефакта: шапка каждого
`E40_x_*.json` = `core_version`, `timestamp`, `observational`, `new_forwards`,
`inputs{path, sha256_16}`, `channel_tags`. Менять политику трекинга JSON — решение про все
39 экспериментов, а не дефект фазы 1. Отдельно принимаю: в сообщении коммита «`g_uni`
бит-в-бит» при коде с допуском `1e-6` — формулировка сильнее проверки; по факту dev 5.55e-17
по всем пяти слоям (пересчёт по `E40_1_T4a.json` против `exp39_supp_three_objects.json`).

### 2.3 N2: «стоп-правило §14.3 мертво» — да, но содержательных проверок не осталось не все

Тавтология mean/`ratio_of_means`-ячеек при `frac_K` из тождества — признаю, код исправлен.
Но «единственная ячейка с содержанием — median» неверно: содержательны и (а) per-chunk assert
`‖J−PJ‖²` против `e−2⟨J,PJ⟩+a` (он ловит битый кэш и неверную нормировку `p`: на fp32-кэше без
fp64-ренормировки строк он падал прямо в этом раунде), (б) g_uni-чекпоинт по пяти слоям,
(в) T4b-диагноз `s²_implied < 0`. А median-ячейка — контроль, она и не должна замыкаться.
После перехода на прямой `frac_K` §14.3 снова становится работающим стоп-условием.

### 2.4 B5: «захардкоженные константы»

`p_slice = "p_t"`, `p_position = 0`, `T5_p_position = 32` — заключение по коду продюсера
(`exp27.5_pair_matrix.py:28`, `exp27_6_isolation.py:38,58`), которое сам ТЗ §2.3.1 назначил
решающим («гейт решает пункт 1, он детерминирован»). Оно кладётся в артефакт вместе с
подтверждёнными строками (`code_audit[].found/line`) и падает, если строка исчезла. Требовать
«выводить» их из исходника синтаксически — значит просить AST-парсер продюсера. Из литералов
убрано то, что действительно должно было выводиться: `gate_pass`, `E40_2_can_start`.

### 2.5 N6: пустой `channel_tags` в 0.0 и 0.1 — сознательно

§12.1 требует тег для каждого **результата измерения канала**. В гейте их нет: там факт
код-аудита, хеши кэшей и скаляр диагностики сверки `p`. Проставить тег = выдумать значения
`slice`/`side`/`rank` для утверждения «в файле есть строка X», т.е. сфабриковать идентичность
там, где её не было — ровно то, против чего стоит §1.1. Оставил `[]` + `channel_tags_note`.
Для манифеста то же: он регистрирует реестр инвариантов (синтетика) и аудит-ответы.
В T4a претензия справедлива — исправлено.

### 2.6 A14: бутстрап

Текст §1.4 («paired по документам … не блочный») и §4 («Не блочный bootstrap по Δ») изменил
архитектор в ревизиях ТЗ, исполнитель им следует ⇒ отклонения от спецификации нет, D-запись не
требуется. Если считать сменой спецификации сами правки архитектора — тогда D-записи нужны на
каждую строку ТЗ, что превращает D-список в дифф.

### 2.7 Арифметика N5

`(1+√(6/160))² = 1.42480`, а не 1.4259. Для `p=8, n=160` — `1.4972`. (`n=32 → 2.0535`,
`n=192 → 1.3848` подтверждаются; `n=192` из ТЗ удалён как несуществующий носитель.)

## 3. Что реально изменилось в содержании

1. **N3 — единственная находка, меняющая утверждение, а не формулировку.** Ответ на «`r_eff`
   на raw или canonical?» был дан неверно; верно — **canonical**. Следствие жёстче написанного:
   спектр 32×32 при `n = 32` документах, поэтому «24.4–31.6» означает «почти все 32 вектора
   равноценны», т.е. это мера разреженности матрицы сходства документов, а не «плоский спектр
   ESG». Строка §3.4 «`r_eff` на raw, 98–99 % на canonical ⇒ умирает плоский спектр ESG»
   теперь просто не о чём: объект не ESG.
2. **N1** меняет критерий приёмки, не числа: E-40.5 и так проверял `Σ G = ‖ΔJ‖²` — иначе §14.6
   остановил бы фазу ложно на первом же слое.
3. **N2** понижает статус уже закоммиченного «T4a: 8 ячеек замкнуты»: после перехода на прямой
   `frac_K` замыкание становится измерением, его величина — в `identity_gap_rel` + внешней сверке.
4. Прочее — терминология, обвязка гейта, поля покрытия.
