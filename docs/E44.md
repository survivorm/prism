## 0. Что E-44 тестирует — и что нет

### 0.1. Исходный вопрос (сохраняется)

`∂z_{t+k}/∂h_t` (`k ≥ 1`) — кросс-позиционный Якобиан. Отвечает на: «влияет ли `h_t` на логиты через `k` шагов, и **есть ли в этом влиянии структура, которую можно предсказать из геометрии `J_{t→t}`?»

### 0.2. Что E-44 **не** тестирует (framing после E-39)

E-39 показал **4 непустых квадранта** `κ × behavior`:
| κ | behavior | Эксперимент |
|---|---|---|
| ↓ −42% | ↔ +0.99% | E-39d honest floor (L23) |
| ↔ | ↓ +9.6% | E-39f b3g128 |
| ↓ −73% | ↓ +12% | E-39d rank permutation |
| ↔ | ↔ | E-39b/f g≥32, bits≥4 |

**Следствие:** любая гипотеза вида «геометрия `J` предсказывает поведение» **априори суспектна** — E-39 дал контрпримеры в обе стороны (κ↓ при behavior↔, и κ↔ при behavior↓). E-44 — это **проверка, нарушает ли cross-position эта ортогональность**, а не «ещё одна корреляция».

### 0.3. Три возможных вердикта (pre-registered, все publishable)

| Паттерн | Вердикт | Что значит |
|---|---|---|
| `ρ(g, b_res) ≈ 0` везде при разрешении floor | `universal_orthogonality` | E-39-ортогональность — общий закон, не same-position special case. Cross-position **не headline**, но закрывает вопрос |
| `ρ(g, b_res) > 0.5` для некоторых (k, layer) с `b_qual > 0.95` | `sequential_reasoning_mechanism` | Геометрия предсказывает поведение на длинных дистанциях. **Headline** |
| `ρ(g, b_res) ≈ 0` для k ≤ 4, `> 0.5` для k ≥ 8 | `scale_dependent_alignment` | Локально ортогонально, глобально нет. **Самый интересный исход** |
| `b_mag ≈ b_lin` до `k*`, потом noise; `b_qual ≈ 1` до `k*` | `first_order_coupling` (ожидаемый-дефолт) | Линейное тождество работает до `k*`; **информация — в границе `k*`**, а не в ρ(g, b) |

**Правило:** без 4-го исхода наиболее вероятный результат **без ярлыка** — повтор E-39l («исход вне таблицы»).

## 1. Объект: разведение `b` на magnitude и quality

### 1.1. Причина разведения

E-44 v1 (в `E40.md`) определял `b(t,k) = KL(base, perturbed)`. E-39 §16 D2 требовал `b = corr_f`. Это **два разных вопроса**:

- **`b_mag(t,k)`**: «насколько сильно `h_t + εv` сдвигает `z_{t+k}`?» — величина отклика;
- **`b_qual(t,k)`**: «сохраняет ли возмущение ранговую структуру K-логитов в `t+k`?» — качество отклика.

Оба считаются из **одних и тех же двух форвардов** (base и perturbed). Цена разведения — нулевая.

### 1.2. Primary endpoint

```
b_mag(t,k)  = ||Δz_{t+k}||_2                (primary; L2-норма изменения логитов)
b_mag_kl(t,k) = KL(p_base_{t+k} || p_pert_{t+k})  (secondary; KL-версия)
b_qual(t,k) = Pearson_rank(e_k, b_k) в t+k   (corr_f-аналог; K-логиты)
```

`b_mag` — primary, `b_mag_kl` — cross-check (софтмакс-якобиан тривиален, но пересчёт даёт проверку). `b_qual` — **сопровождающая классификация режима**, не исключение из выборки.

### 1.3. Что E-39-квадранты означают для `b_qual`

В E-39d `corr_f = 0.9992` — честный floor. `corr_f = 0.594` — cheat. Порог 0.95 — разделитель режимов. **Но в E-44 контекст другой:** возмущение активации **не обязано** сохранять поведение (мы его измеряем). Поэтому:

- `b_qual > 0.95` → `structured` отклик (изменение в направлении базовой структуры);
- `b_qual ∈ [0.7, 0.95]` → `partially_structured`;
- `b_qual < 0.7` → `scrambling` (изменение вне структуры);
- **Ни одна из категорий не исключается из выборки**; каждая отчитывается отдельно.

## 2. Геометрия: `g` и `b_lin`

### 2.1. Primary geometry

```
g_F(t,k) = ||J_{t→t+k}||_F              (Frobenius; primary)
g_top(t,k) = σ_1(J_{t→t+k})             (top-SV; secondary)
g_align(t,k) = Procrustes-угол между J_{t→t+k} и J_{t→t}   (secondary; см. §2.4)
```

### 2.2. Линейный предиктор `b_lin` — **обязателен**

При возмущении `v = top-r right SV` в первом порядке:
```
Δz_{t+k} ≈ ε · J_{t→t+k} · v = ε · σ_1 · u_1
b_mag ≈ ε · σ_1
g_F = ||J||_F = (Σ σ_j²)^{1/2}
```

Тогда `ρ(g_F, b_mag)` — это **корреляция `||J||_F` с `σ_1`**, то есть мера спектральной концентрации. В плоском спектре `ρ ≈ 1` **по построению**, а не потому что «геометрия предсказывает поведение».

**Fix (Спикер 3 §3.2):**
```
b_lin(t,k) = ε² · σ_1²(t,k)                  (аналитический линейный предиктор)
b_res(t,k) = b_mag(t,k) − b_lin(t,k)          (residual: что сверх первого порядка)
```

**Primary statistic — `ρ(g_F, b_res)`, не `ρ(g_F, b_mag)`.**

**Порядок остатка (патч v2 §1.1): `b_res = O(ε³)`, не `O(ε⁴)`.** Из `Δz = εJv + (ε²/2)H[v,v] + O(ε³)`: `‖Δz‖² = ε²‖Jv‖² + ε³⟨Jv, H[v,v]⟩ + (ε⁴/4)‖H[v,v]‖² + O(ε⁵)`, откуда `b_res = ε³⟨Jv, H[v,v]⟩ + O(ε⁴)`. Порядок `O(ε⁴)` верен только при `⟨Jv, H[v,v]⟩ = 0` — проверяемое условие, не тождество. Отсюда: (1) **пререгистрированное ожидание scaling: `b_res ~ O(ε³)`**; (2) редукционный контроль — `b_res/(ε²σ₁²) → 0` (`o(ε²)`), проверка как `O(ε⁴)` прочитала бы честный ε³-член как баг редукции; (3) **обязательное поле артефакта: `lq_coupling := ⟨Jv, H[v,v]⟩`** (signed) — самостоятельный измеримый объект (линейно-квадратичная связка), не шум; в коде — `prism/behavior.py::lq_coupling`.

**Заметка (ревью раунд 6, `docs/E39+_answers.md`, свёрнут в git history).** Измеренный `cos(J, PJ) = 0.064–0.137` по слоям при операторном базисе `0.154–0.158` (изотропный J): перпендикулярность возмущения даёт оператор, данные углубляют её в 1.5–2 раза (`docs/E39_supplement.md` §2.2.5, свёрнут в git history). Опасение ревьюера по `b_lin`: если амплитуда возмущения держится высшими порядками, `b_lin = ε²σ_1²` переоценивает линейную часть — проверить на пилоте отношение `b_res/b_lin` и устойчивость знака `b_res` (систематически отрицательный ⇒ аддитивная разбивка теряет смысл). Бинарную sentinel-маску в E-44 **не использовать** (supplement §6 правило 10: масса почти равномерна на (0,1), любой порог 0.2–0.8 режет по среднему) — масса `U128` как ковариата или кривая.

### 2.3. Random-v control — **обязателен** (доп. к ревью)

`b_res` может нести остаточную корреляцию с `g_F` через софтмакс-якобиан `P(p)`, если тот выровнен с крупными сингулярными направлениями. Дешёвый контроль:

```
b_mag_random(t,k) = ||Δz_{t+k}|| при v = random Haar direction в R^D
```

Тогда:
- `ρ(g_F, b_mag_random) ≈ ρ(g_F, b_mag_top)` → вся корреляция от `||J||_F`, направление не важно;
- `ρ(g_F, b_mag_random) < ρ(g_F, b_mag_top)` → есть структурный сигнал сверх нормы.

**Контроль входит в primary (не в secondary), потому что отделяет тавтологию через спектр от тавтологии через все направления.**

### 2.4. `g_align` — secondary

`Procrustes-угол между J_{t→t+k} и J_{t→t}` — отвечает на «похожа ли структура отклика через k шагов на same-position структуру». Реализуется через polar-разложение топ-r правых SV:

```
V_a = polar(top-r right SV J_{t→t+k})
V_b = polar(top-r right SV J_{t→t})
R = polar(V_a^T V_b)
g_align = arccos((tr R − 1)/2)   (максимальный главный угол)
```

Это `secondary`, потому что:
- не определяет `σ_1`, поэтому тавтологией не страдает;
- вырождается при постоянном alignment (например, если все `J_{t→t+k} ∝ J_{t→t}`);
- но даёт **механистическую** интерпретацию, если primary дал positive.

## 3. Статистика

### 3.1. Primary test

```
H0: ρ(g_F, b_res) = 0  для всех (t, k) при k ≥ 1
```

**Per-cell (t, k)**: `ρ(g_F, b_res)` по документам (N=32). Bootstrap CI95 (B=2000) **paired** по документам.

### 3.2. Per-cell floor (D4 в редакции Спикера 2 §2.3)

Для каждой ячейки `(t, k)`:
```
floor(k, l) = half-width CI на b_mag при k, l
testable_at_N32(k, l) = (b_mag median at (k, l) > floor)
```

**Правило:** `ρ(g, b_res)` интерпретируется **только выше floor**. Ячейки ниже floor → `not testable`, не «ρ = 0».

### 3.3. Aggregate verdicts

Из per-cell значений:
```
fraction_significant = |{(t, k): CI_lo(ρ) > 0.5 AND b_qual > 0.95}|
fraction_orthogonal  = |{(t, k): CI_hi(ρ) < 0.3 AND b_qual > 0.95}|
fraction_testable    = |{(t, k): testable_at_N32}|
```

Вердикт по §0.3.

### 3.4. Paired differences (D1)

Если сравниваются два слоя или два `k`, разность `ρ(t, k_A) − ρ(t, k_B)` — paired bootstrap по документам. **Marginal CI overlap не считается significance test** (урок E-39f).

## 4. Дизайн возмущений

### 4.1. Возмущение

```
h'_t = h_t + ε · v
v ∈ {v_top (top-r SV J_{t→t+k}), v_random (Haar)}
ε ∈ {0.05, 0.1, 0.2} · ||h_t||   (3 значения; проверка линейности)
```

**Линейность обязательна (E-39d урок):** `b_mag ∝ ε²` при малых ε. Если на всех ε линейный режим пуст — `regime_not_testable`, не `universal_orthogonality`.

### 4.2. Что считается на каждом форварде

```
forward_base   : logits_base[t+k] для всех t ∈ [0, S−k−1], k ∈ {1,2,4,8}
forward_pert   : logits_pert[t+k] для тех же (t, k), с v = v_top
forward_pert_r : logits_pert_r[t+k], с v = v_random
```

**Три форварда на пару (t, k)**, не два. Дополнительный — для random-v control.

### 4.3. `b_qual` вычисление

```
e_k(t+k) = logits_pert[t+k, U128]    (K-логиты в perturbed forward)
b_k(t+k) = logits_base[t+k, U128]    (K-логиты в base forward)
b_qual = Pearson_rank(e_k, b_k)
```

Параметр `U128` — из E-39b/E-39f (тот же token set, для консистентности).

## 5. Null models

### 5.1. Null для `ρ(g, b_res)`

- **перестановка (t, k)** — перемешать ячейки, сохраняя маргиналы;
- **конвейерный суррогат** (семья E-34): `J_rand = Q^T diag(√ESG_ii)`, `Q` — случайный ортогональный;
- **изотропный референс** (новое, по развязке Спикера 3): `g` и `b_res` на случайных `J` из того же распределения.
- **dir-matched null** (по E-39-дополнению §2.2): случайные направления при **сохранённых нормах
  строк/позиций** `J_{t→t+k}` — на нём проверяется, не является ли эффект распределением норм.

**Принцип (перенесён из E-39-дополнения, `paper.md` §6 п. 22):** любая корреляция с энергией `J`
проверяется против **обоих** null'ов. Изотропный — механический (показывает норму оператора; в
E-39-дополнении он сам даёт `conc = 0.101` вместо ожидаемого «нет структуры» и `O1/iso = 1.006`,
то есть калибрует machinery). Dir-matched — содержательный: читается `real / dir-null`, и именно
он равнялось 0.623–0.692 без зависимости ни от слоя, ни от домена, тогда как весь глубинный тренд (0.51 → 0.25)
ушёл в нормы строк. Практический запрет: если `ρ(g_F, b_res)` на реальных `J` неотличим от того же `ρ` на
dir-matched null'е, структура приписана не данным, а распределению норм, — такой результат в
вердикт не входит (он и есть ожидаемый null-результат).

**Primary null: двусторонний** `max(real/null, null/real) ≥ 2` для `g`, `b_res`; **разностный** `|ρ_real − ρ_null|` с CI для `ρ`.

### 5.1.1. `ρ(g, b_mag)` — тоже операторная величина (следствие правила 23)

`b_mag := ‖Δz‖²` — это норма `J_{t→t+k}·v`, где `v` выбран **нами** (топ-правый СВ или случайный
вектор), то есть объект вида `f(O, X)` с оператором, который подставляем мы сами. Значит
`ρ(g_F, b_mag)` — корреляция **двух** операторных величин, и подпадает под `paper.md` §6 п. 23, а
не только под п. 22:

* **operator-null:** `J` изотропен при той же размерности **и** `v` случайный (Haar) — сколько
  корреляции даёт одна схема «норма якобиана против нормы образа»;
* **content-matched null:** реальные `J`, случайные `v`; отдельно — `J` с сохранёнными сингулярными
  числами и случайными направлениями (ловит чисто спектральную компоненту).

Pre-registered признак «signal»: `ρ_real` значимо выше **обоих** null'ов. Без этого возможен
повтор истории «98–99 %»: корреляции энергетических величин с направлениями выглядят сигналом,
потому что операторная компонента не вычтена.

### 5.2. Null для `b_lin`

Не нужен — `b_lin` аналитический (детерминированный из `σ_1`).

## 6. Design constraints (D-фильтр)

E-44 — **интервенционный** тест (возмущение активации, 2-forward). Применимы:

| D | Применим? | Как |
|---|---|---|
| **D1** paired bootstrap | ✅ | §3.4 |
| **D2** corr_f для behavior | ⚠️ **в режиме `b_qual`**, не в исключении | §1.3 |
| **D3** 2-forward | ✅ | §4.2 (3 форварда) |
| **D4** resolution floor | ✅ | §3.2, **per-cell** |
| **D5** двусторонний нуль | ✅ | §5.1 |
| **D6** honest vs cheat | ❌ **не применим** — активация не обязана сохранять поведение | §1.3 |
| **D7** deviations tracking | ✅ | §9 |

**D2**: `corr_f` — сопровождающая классификация режима (`b_qual`), **не исключение** из выборки (в отличие от E-39d). Разница: в E-39d редактируется модель, поведение **обязано** сохраняться; в E-44 измеряется отклик активации — поведение может меняться, это и есть сигнал.

**D6**: `honest vs cheat` — в E-39d различало `κ↓ с поведением целым` vs `κ↓ через rank permutation`. В E-44 нет «плоского листа» и «ранговой перестановки» — есть отклик на возмущение. Классификация режима — через `b_qual` (§1.3).

## 7. Abort criteria (условить на floor и линейный режим — Спикер 3 §3.4)

| Условие | Действие |
|---|---|
| `forward_base` logits не воспроизводятся из кэша (`max_rel > 1e-5`) | **abort**: pipeline broken |
| `b_mag ≈ 0` для всех (t, k) на всех ε | **abort**: model trivially local cross-position, structureless |
| Линейный режим пуст на всех достижимых ε | **abort**: `regime_not_testable`, не `universal_orthogonality` |
| **После** верификации floor: `fraction_testable < 0.3` | **abort**: недостаточное разрешение, N=32 мало |
| `ρ(g, b_res)` CI полностью внутри ±0.15 на всех testable cells | **verdict**: `universal_orthogonality` (не abort — это исход) |
| `ρ(g, b_mag_top) ≈ ρ(g, b_mag_random)` и `ρ(g, b_res) ≈ 0` | **verdict**: `first_order_coupling`, `b_mag` полностью объяснён спектром |
| `|ρ(g, b_qual)| > 0.5` для `b_qual > 0.95` на некоторых (k, l) | **verdict**: `sequential_reasoning_mechanism` или `scale_dependent_alignment` |

## 8. Фазы, cost

### 8.1. Pilot (2–3 ч CPU)

- `N = 8` docs, `S = 32`, `k ∈ {1, 2, 4, 8}`, `layers {6, 18, 23}`.
- 3 форварда на пару (`v_top`, `v_random`, base) × `N × S × |k| = 8 × 32 × 4 = 1024` пар × 3 слоя = ~9K форвардов по 32 позиции.
- **Цель:** per-cell floor, testable_at_N32, `ρ(g, b_res)`, `b_qual`, `b_mag` vs `b_lin`.
- **Решение:** если pilot показывает `fraction_testable < 0.3` — abort; если `ρ(g, b_res) ≈ 0` и `b_mag ≈ b_lin` — `first_order_coupling`, **scale-up не запускать**, публиковать как negative; иначе — scale-up.

### 8.2. Scale-up (4–6 ч GPU, только если pilot contentful)

- `N = 32` docs, `S = 128`, `k ∈ {1, 2, 4, 8, 16}`, `layers {6, 12, 18, 22, 23}`.
- 3 форварда на пару × 32 × 128 × 5 × 5 = ~600K форвардов... это много. **Оптимизация:** батчинг по документам (`N=32` в один forward), per-k пакетно. Оценка: 5 batch × 5 k × 5 layers × 3 v = 375 forward-батчей, ~30 мин GPU.

### 8.3. Abort early

Если на пилоте `b_mag ≈ b_lin` на всех (k, l) — **scale-up не запускать**, писать `first_order_coupling`, economics = 2–3 часа CPU вместо 4–6 часов GPU.
