# E-39f — Полный tied-weight PTQ: сдвигает ли квантование эмбеддингов лист L23?

**Версия:** draft для ревью
**Дата:** 2026-11-02
**Зависит от:** E-39b (readout-only PTQ), E-39c_pre (tied-weight KL-декомпозиция), E-39a (κ baseline), E-28 (κ=0.018), E-38d (κ=0.0162), E-38e (β/σ₁=0.882)
**Связано с:** E-39d/e (training — не блокирует, но интерпретация зависит)
**Заменяет:** старое определение E-39f в `docs/E39.md §6` (было «PTQ robustness of flat model» — теперь это другой эксперимент)

## 0. Overview

### 0.1. Что решаем

E-39b показал: **readout-only** GPTQ-4bit не двигает κ(L23) — ratio 0.988, PPL +0.9%. Однако E-39b **не покрывает** канал, который в реальном tied-PTQ доминирует:

- Qwen3.5-0.8B **tied**: `lm_head.weight == embed_tokens.weight`.
- Реальный GPTQ-4bit квантует **одну** матрицу, которая является **и** readout, **и** эмбеддингом.
- Квантование эмбеддинга → сдвиг `h_t` на всех 24 слоях → `û_t` = `h_t/||h_t||` меняется → `J_t = c_t · M_K · (I − û_t û_tᵀ)` меняется **дважды**: через `M_K` и через `û_t`.
- E-39c_pre дал масштаб: `embed_only KL = 5.23` vs `head_only = 1.36` — upstream-канал доминирует в KL в **~4×**.

**Ключевой вопрос E-39f:** доминирует ли upstream-канал (сдвиг `û_t`) также и в **κ**, или κ устойчива к сдвигу `û_t` так же, как к сдвигу `M_K`? Ответ определяет, «PTQ не ломает лист» (E-39b) — **фундаментальное** свойство, или **артефакт** readout-only протокола.

### 0.2. Гипотеза (pre-registered, фальсифицируемая)

**H-39f:** upstream-канал (сдвиг `û_t` под квантованием эмбеддингов) вносит **≥ 50%** в изменение κ(L23) при full tied-PTQ.

**Нуль:** upstream-канал вносит **< 25%** — κ определяется `M_K`-каналом (readout), а не `û_t`-каналом.

**Промежуточное:** 25% ≤ доля < 50% — оба канала значимы.

### 0.3. Что нового относительно E-39b

| | E-39b | E-39f |
|---|---|---|
| Что квантуется | только `lm_head.weight` | `lm_head.weight` = `embed_tokens.weight` (tied) |
| `h` для κ | из **базовой** модели (кэш exp27b) | из **квантованной** модели (fresh forward) |
| `û_t` | fp16 | квантованный |
| PPL | readout-only | full tied (реальный PTQ) |
| Канал изменения κ | только `M_K` | `M_K` + `û_t` (декомпозиция) |

## 1. Название

**E-39f: Полный tied-weight GPTQ-4bit — сдвиг û_t как источник изменений κ(L23), декомпозиция readout vs upstream.**

## 2. Определения

### 2.1. Full tied PTQ

Квантование GPTQ-4bit матрицы `W = lm_head.weight = embed_tokens.weight` (одна матрица — веса связаны). После квантования:

- `W_lm_q = GPTQ(W, X_cal)` — где `X_cal` — калибровочные `h` из **fp16** модели (стандартная GPTQ-практика, калибровка не зависит от квантованной модели);
- `embed_tokens_q.weight = W_lm_q` — tied автоматически;
- forward квантованной модели даёт `h_q = forward_q(token_ids)` — сдвинутые hidden states.

### 2.2. Три κ для декомпозиции

Для каждого (doc, t):

- **κ_fp16:** `J_t` из `M_K_fp16 = W_lm_fp16[token_set] · diag(g)` и `û_t^{fp16}` из базового кэша exp27b. **Baseline, должен воспроизвести 0.0162** (E-38d/E-39a).
- **κ_readout:** `J_t` из `M_K_q = W_lm_q[token_set] · diag(g)` и **того же** `û_t^{fp16}`. **Это то, что мерил E-39b** (0.01604).
- **κ_full:** `J_t` из `M_K_q` и `û_t^q = h_q_t / ||h_q_t||` из **квантованной** модели. **Новое.**

### 2.3. Декомпозиция

$$\Delta_{total} = \kappa_{full} - \kappa_{fp16}$$
$$\Delta_{readout} = \kappa_{readout} - \kappa_{fp16} \quad \text{(E-39b: } \approx -0.0002\text{)}$$
$$\Delta_{upstream} = \kappa_{full} - \kappa_{readout}$$

$$\Delta_{total} = \Delta_{readout} + \Delta_{upstream} \quad \text{(точно)}$$

**Доли:**

$$\text{share}_{readout} = \frac{|\Delta_{readout}|}{|\Delta_{readout}| + |\Delta_{upstream}|}$$
$$\text{share}_{upstream} = 1 - \text{share}_{readout}$$

(При `share` определены только при `|Δ_total| > 0.001` — иначе «оба канала малы».)

### 2.4. Механистический диагностик: `h_drift` и `û_cos`

Помимо κ, измеряются:

- **`h_drift`(doc,t) = ||h_q_t − h_fp16_t||_2 / ||h_fp16_t||_2** — величина сдвига hidden state.
- **`û_cos`(doc,t) = ⟨û_t^q, û_t^{fp16}⟩** — косинус между направлениями. **Это то, что напрямую входит в κ через `(I − ûûᵀ)`.**

**Механизм, который проверяем:**
- если `û_cos ≈ 1` и `h_drift` велик → `û_t` **не** вращается, κ не должна меняться через upstream (нуль H-39f);
- если `û_cos` заметно < 1 → `û_t` вращается, κ **должна** меняться (подтверждение H-39f).

## 3. Математика

### 3.1. Точное выражение для J_t (E-35, точно на L23)

$$J_t^{(q)} = \frac{\sqrt{D}}{||h_t^q||} \cdot M_K^q \cdot \left(I - \hat u_t^q (\hat u_t^q)^T\right), \quad \hat u_t^q = \frac{h_t^q}{||h_t^q||}$$

где `M_K^q = W_lm^q[token_set] · diag(g)` — readout-множитель, `g = 1 + w` (RMSNorm final weight, не квантуется — RMSNorm параметры не PTQ-каналы в стандартном GPTQ).

### 3.2. κ и инвариантность

κ(L23) = `median_t || H_012(t) − I ||_F` (Procrustes, top-16 правых СВ `J_t`).

κ **инвариантна** к:
- скалярному масштабу `c_t = √D/||h_t||` (только направление правых СВ входит);
- унитарному преобразованию `V_t → V_t O` в каждом `J_t` (сопряжение).

κ **зависит** от:
- `M_K` (входит в `J_t` линейно);
- `û_t` (входит через `(I − ûûᵀ)` — проектор ранга `D−1`).

**Следствие:** изменение `||h_t||` (масштаб) на κ **не влияет**; изменение `û_t` (направление) — **влияет**.

Это значит, что декомпозиция E-39f разделяет два физически разных эффекта:
- `M_K`-канал: «что квантование сделало с readout-матрицей» — E-39b;
- `û_t`-канал: «повернуло ли квантование residual stream» — **новое**.

### 3.3. Ожидание по величине `û_cos`

Квантование эмбеддинга даёт шум `δE[t, :] ~ uniform([−q/2, q/2])` по каждой координате (для RTN) или bias-corrected шум (для GPTQ). Этот шум проходит через 24 слоя. По E-32r.3.1 — `cos(JR, J_tail) = 0.105` на L6 → 1.0 на L23, т.е. residual stream к L23 «синхронизирован» с tail: возмущение на входе претерпевает **много** искажений, но на L23 доминирует последний слой `W_lm` + final norm.

**Ожидание (не pre-registered, качественное):**
- `h_drift` на L23 может быть заметным (10–50%);
- `û_cos` может быть ближе к 1, чем `h_drift` предполагает (направление стабильнее масштаба);
- `|Δ_upstream|` — от < 0.001 (если `û_cos ≈ 1`) до ~0.01 (если `û_cos ≈ 0.99`).

**Но это не predict — именно это E-39f и измеряет.**

## 4. Протокол

### 4.1. Пре-регистрация (7 обязательных полей — ТЗ §3.2)

| Поле | Значение |
|---|---|
| **(1) Гипотеза** | `share_upstream ≥ 0.5` в изменении κ(L23) при full tied GPTQ-4bit (g=128). |
| **(2) Объект и канал** | `[ΔW] × [raw/fixP] × [top-16] × [right]`, κ на L23. Канал `[ΔW]` — квантование весов. |
| **(3) Статистика** | Per-doc медианы (32 doc) + bootstrap CI (B=1000). Compare медиан κ и `Δ_readout`, `Δ_upstream`. |
| **(4) Нуль-модель** | κ на подменённом (shuffled) `û_t` (random directions в R^D) — sanity: κ должна вырасти до ~5 (уровень E-28 random). Это проверка, что κ **вообще** видит `û_t`-канал. |
| **(5) Порог решения** | `share_upstream ≥ 0.5` → **H-39f подтверждена**; `share_upstream < 0.25` → **H-39f опровергнута**; иначе **inconclusive**. |
| **(6) Что остаётся при успехе** | κ — чувствительна к upstream PTQ-каналу; «PTQ не ломает лист» (E-39b) — **артефакт readout-only**. Flatness-мотивация для PTQ — **реальна**. |
| **(7) Что умирает при провале** | Гипотеза «PTQ upstream ломает лист» — **опровергнута**; flatness не нужна для PTQ-защиты. E-39c/d/e теряют одну из главных мотиваций (E-39b + E-39f дают согласованный результат «лист robust к PTQ»). |

### 4.2. Шаги

**Шаг 0 — загрузка и self-check fp16 (5 мин CPU + 1 мин GPU):**

1. Загрузить Qwen3.5-0.8B fp16 на GPU.
2. Assert tied: `lm_head.weight.data_ptr() == embed_tokens.weight.data_ptr()` — если нет, эксперимент **невалиден** (нужен `tie_word_embeddings=True` или явное присвоение).
3. Прогнать forward на **32 doc × 128 pos** (тот же split, что exp27b — `wiki/math/code/chat × 8`), снять `h_fp16`.
4. Self-check: `h_fp16` должен совпадать с кэшем `exp27b_jcache_L23.pt[H]` до ~1e-7 (rel). Если > 1e-5 — pipeline сломан (attention mask? MRoPE? S=128 boundary?) — **abort**.
5. Compute `κ_fp16` из `M_K_fp16` и `û_t^fp16`. Assert: `|κ_fp16 − 0.0162| < 0.005` (E-38d/E-39a reference).

**Шаг 1 — GPTQ-калибровка (5 мин):**

1. C4 train skip 8192, 128 doc × 128 tok (тот же split, что E-39b).
2. Калибровка через lm_head-forward-pre-hook, filtered по `attention_mask` (E-39b фикс P0.2).
3. Выполнить GPTQ-4bit (group=128, damp=0.01, desc_act=True). Получить `W_lm_q`.
4. **Sanity:** `j_rel_drift` на L23 в readout-only режиме должен совпасть с E-39b: `median ≈ 0.1204` (E-39b: 0.12047). Если разошёлся — GPTQ-пайплайн сломан.
5. **Контрольное квантование harsher (для второй половины E-39f):** повторить GPTQ-4bit с `group=32` (в 4× агрессивнее). Получить `W_lm_q_harsh`. Это — probe «действительно ли лист robust, или просто под порогом».

**Шаг 2 — forward квантованной модели (2 мин):**

1. Заменить `W_lm` и `embed_tokens` в модели на `W_lm_q` (одна операция, т.к. tied). Убедиться: `data_ptr` всё ещё совпадает.
2. Прогнать forward на тех же 32 doc × 128 pos → `h_q`.
3. Сохранить: `h_drift(t) = ||h_q − h_fp16|| / ||h_fp16||`, `û_cos(t) = ⟨û_t^q, û_t^fp16⟩`.

**Шаг 3 — κ в трёх режимах (30 сек GPU):**

1. `κ_readout`: `M_K_q`, `û_t^{fp16}` — должен совпасть с E-39b `0.01604` до 1e-4.
2. `κ_full`: `M_K_q`, `û_t^q` — **новое**.
3. `κ_fp16`: уже есть.
4. Декомпозиция: `Δ_readout`, `Δ_upstream`, `share_upstream`.

**Шаг 4 — PPL full tied (5 мин GPU):**

1. C4 val (32 doc × 128 tok, тот же split, что E-39b).
2. Forward полностью **квантованной** модели: embeddings = `W_lm_q`, forward стандартный.
3. `PPL_full_tied = exp(NLL)`. Сравнить с `PPL_fp16 = 30.475` (E-39b) и `PPL_readout_only = 30.749` (E-39b).

**Шаг 5 — harsh режим (g=32) (25 мин):**

Повторить шаги 1–4 с `W_lm_q_harsh`. Это probe: если κ_full ≈ κ_fp16 при g=128, но κ_full >> κ_fp16 при g=32 — «лист действительно robust в интересующем режиме», не «лист слеп к PTQ».

**Шаг 6 — нуль-модель (2 мин):**

Заменить `û_t` на случайные единичные векторы в R^1024 (Haar, 16 seeds), compute κ. Ожидание: κ ≈ 5 (уровень E-28 random). Это **sanity для всей E-39f**: если κ не видит даже random `û_t`, декомпозиция бессмысленна — abort.

**Шаг 7 — запись (1 мин):**

JSON `results/exp39f_full_tied_ptq.json` со структурой ниже.

### 4.3. Критические предусловия и abort-условия

| Условие | Действие |
|---|---|
| `lm_head.data_ptr() != embed_tokens.data_ptr()` | **abort**: модель не tied — эксперимент не имеет смысла |
| `h_fp16` не совпадает с кэшем exp27b (`max_rel > 1e-5`) | **abort**: pipeline forward сломан (проверить attention_mask, MRoPE position_ids) |
| `|κ_fp16 − 0.0162| > 0.005` | **abort**: baseline не воспроизводится (SVD-driver drift) |
| `j_rel_drift(readout)` ≠ E-39b median (tol 5%) | **abort**: GPTQ-пайплайн расходится с E-39b |
| нуль-модель даёт κ < 1.0 | **abort**: κ не видит `û`-канал, декомпозиция невалидна |
| `h_drift > 5.0` (в 5× сдвиг) | **warn, продолжить**: очень жёсткий сдвиг, но κ может быть устойчива — результат информативен |

## 5. Gates (pre-registered)

### 5.1. Основной gate (H-39f)

| Условие | Вердикт | Интерпретация |
|---|---|---|
| `share_upstream ≥ 0.5` | **`upstream_dominates`** | H-39f подтверждена. PTQ ломает лист через сдвиг `û_t`. E-39b — артефакт readout-only. Flatness-мотивация реальна. |
| `0.25 ≤ share_upstream < 0.5` | **`both_channels`** | Оба канала значимы. E-39b частично прав; нужна полная модель для полного ответа. |
| `share_upstream < 0.25` | **`readout_dominates`** | H-39f опровергнута. κ определяется `M_K`, не `û_t`. E-39b фундаментально корректен. Flatness не нужна для PTQ. |

(При `|Δ_total| < 0.001` — вердикт `both_channels_small`: оба канала пренебрежимы, «лист robust к PTQ в целом», более сильный результат, чем E-39b.)

### 5.2. Gate harsher режима (g=32)

| κ_full (g=32) | Интерпретация |
|---|---|
| `< 0.02` (ratio ≤ 1.25) | **`leaf_robust_even_harsh`**: κ устойчива к PTQ даже при агрессивном квантовании. Сильный результат. |
| `0.02–0.10` | **`moderate_harsh`**: агрессивный PTQ умеренно ломает лист. g=128 — «безопасен», g=32 — нет. |
| `> 0.10` | **`catastrophic_harsh`**: агрессивный PTQ катастрофически ломает лист. g=128 — реджим ниже порога. |

### 5.3. Gate PPL full tied

| PPL full tied vs fp16 | Интерпретация |
|---|---|
| `< +5%` | `ppl_robust`: реальный tied-PTQ не ломает поведение. Согласуется с E-39b (но теперь на полной модели). |
| `+5–20%` | `ppl_moderate`: реальный tied-PTQ деградирует, как ожидается от GPTQ-4bit на 0.8B. |
| `> +20%` | `ppl_catastrophic`: что-то сломано (возможно, GPTQ-пайплайн). Проверить декомпозицию по E-39c_pre (`embed_only KL ≈ 5.23` → ожидание `ΔPPL ≈ exp(5.23)/exp(base_NLL)` — очень большое). |

**Примечание по ожиданиям PPL:** E-39c_pre мерил KL не на C4-PPL, а на per-token; полный PPL tied GPTQ-4bit должен дать **значительно больше** +0.9% readout-only. Ориентир: 4-bit GPTQ на 0.8B обычно +10–30% PPL на C4. Если получится +0.9%, это подозрительно — проверить, что `embed_tokens` действительно квантован (assert `data_ptr` и `torch.equal(embed_tokens.weight, W_lm_q)`).

## 6. Исходы (таблица)

| Основной gate | Harsh gate | PPL gate | Сводный вывод |
|---|---|---|---|
| `upstream_dominates` | `moderate_harsh` или `catastrophic_harsh` | `ppl_moderate` | **Полный успех E-39f**: PTQ ломает лист через upstream-канал, E-39b был артефактом. Flatness-мотивация реальна; E-39f — publishable. |
| `upstream_dominates` | `leaf_robust_even_harsh` | `ppl_robust` | **Парадокс**: κ меняется через upstream, но остаётся в `pass`-регионе. Возможно, upstream сдвиг согласован (направление то же, только magnitude) — пересмотреть H-39f. |
| `readout_dominates` | `leaf_robust_even_harsh` | `ppl_robust` | **E-39b фундаментально корректен**: PTQ не ломает лист. Flatness не приоритет для PTQ. E-39c/d/e теряют PTQ-мотивацию. Negative result с чётким механизмом. |
| `readout_dominates` | `moderate_harsh` | `ppl_moderate` | **g=128 — «безопасный реджим»**: readout доминирует и не ломает; harsh — ломает через `M_K`. «Лист robust в интересующем реджиме». |
| `both_channels` / `both_channels_small` | любой | любой | **Промежуточно**: обе компоненты важны, полный ответ требует декомпозиции по каналам. Опубликовать с явными числами, без сильного вердикта. |

**Правило:** при `abort`-условии (см. §4.3) вердикт `inconclusive_pipeline` — не научный результат, а баг.

## 7. Ограничения

1. **Один split для κ и PPL.** κ считается на exp27b (32 doc × 128 pos), PPL — на C4 val (32 doc × 128 tok, disjoint). Это разные splits, но это **правильно**: κ на том же split, что E-38d/E-39a (сравнимость), PPL — на holdout (независимость).
2. **GPTQ-калибровка на fp16 h.** Стандартная практика, но при tied-weights калибровка на fp16 h может быть не оптимальной для `embed_tokens_q` (калибровка не видит последующего forward через квантованные embeddings). **Не меняем** — это стандартный GPTQ, менять значит отклоняться от E-39b/E-39c_pre.
3. **`g = 1 + w` (RMSNorm) не квантуется.** Стандартно для GPTQ. Если реализация проекта включает RMSNorm в PTQ-канал, числа разойдутся; для Qwen3.5 RMSNorm веса **не** квантуются в стандартных pipelines.
4. **PPL — readout vs full — разные объекты.** `ppl["gptq4"]` в E-39b = readout-only; `ppl_full_tied` в E-39f = full. **Не сравнивать** напрямую между экспериментами; только между E-39f-режимами.
5. **`cos_ug_1k` — proxy (как в E-39b).** В E-39f не используем для вердикта; только для отчётности, с оговоркой «proxy, не exact u_g» (E-38f exact = 0.862, proxy ≈ 0.917, расхождение 6% — известное, E-39b).
6. **Sentinel не фильтруется** (консистентность с E-39a/E-39b). Sentinel-позиции ~50%; на них `û_t` может быть шумом. В E-39f это может **занизить** `û_cos` (шумовые позиции дают более случайные направления) — механизм, который E-39f и измеряет, поэтому не фильтруем.
7. **Harsher режим (g=32) — не стандартный GPTQ.** Используется как probe «есть ли порог?», а не как «рекомендуемый PTQ». В отчёте — явно.
8. **`share_upstream` определён при `|Δ_total| > 0.001`.** Иначе «оба канала малы» — более сильный результат, чем «upstream доминирует».
9. **T4 memory.** Forward квантованной модели на 32 doc × 128 pos × D=1024 — ~2 GB fp16; вместе с `W_lm_q` fp64 (~2 GB) — в пределах 16 GB T4. `g=32` даёт тот же memory profile.

## 10. Реализация (черновик `experiments/exp39f_full_tied.py`)

**Структура:** копия `exp39b_ptq_perturbation.py` + три добавления:

1. **`_forward_full_model(model, ids, attn, hook=None)`** — forward всей модели на квантованных весах. Отличие от E-39b: не `model.model(...)`, а полный `model(...)`, потому что квантуем **embeddings** — forward претерпевает изменения с L0.

2. **`_replace_tied_weights(model, W_lm_q)`**:
   ```python
   def _replace_tied_weights(model, W_lm_q):
       lm = model.lm_head
       emb = model.model.embed_tokens
       assert lm.weight.data_ptr() == emb.weight.data_ptr(), \
           "tied assertion failed"
       with torch.no_grad():
           lm.weight.copy_(W_lm_q.to(lm.weight.dtype))
       # Data pointer remains identical (in-place copy) — tied preserved
       assert lm.weight.data_ptr() == emb.weight.data_ptr()
   ```

3. **`_decompose_kappa`** — реализация §2.2–2.3.

**Self-check чек-лист** (assert, не warn):
- `lm_head.data_ptr() == embed_tokens.data_ptr()` до и после replace;
- `h_fp16` vs exp27b кэш: `max_rel < 1e-5`;
- `κ_fp16 ∈ [0.012, 0.021]` (0.0162 ± 0.005);
- `j_rel_drift(readout) ∈ [0.11, 0.13]` (0.1204 ± 5%);
- `κ_null ≥ 1.0` (random `û` реально ломает κ).

## 11. Что Е-39f **не** делает

- Не тестирует E-39c/d/e-модели (flat leaf). Это **отдельный** эксперимент после того, как flat leaf будет достигнут (или не достигнут).
- Не тестирует L6–L22. Только L23 (единственный слой с точной факторизацией E-35).
- Не тестирует KV-cache quantization. Только weight quantization.
- Не тестирует AWQ/GPTQ-вариации. Только GPTQ-4bit (стандарт, совместимо с E-39b/E-39c_pre) + harsher-проверка g=32.
- Не утверждает ничего про downstream (задача, QA, CoT). Только PPL + κ.

## 12. Ожидаемый результат (одна строка)

**Если H-39f подтвердится** (`share_upstream ≥ 0.5`): «readout-PTQ — не тот канал, который важен; upstream-канал через `û_t` ломает лист; E-39b был артефактом; flatness — реальная мотивация для PTQ».

**Если H-39f опровергнута** (`share_upstream < 0.25`): «PTQ не ломает лист ни через `M_K`, ни через `û_t`; κ — фундаментально устойчивая метрика к weight-PTQ; E-39b корректен; flatness не нужна для PTQ, только для downstream (distillation, long-context)».

**Оба исхода — publishable.** Первый валидирует мотивацию E-39-серии; второй закрывает PTQ как направление и фокусирует на downstream.

## 13. Итог (прогнано; числа и границы — `docs/E39.md` §6.7, карточка `docs/ref-exp.md`)

Вердикт: **H-39f не подтверждена** — третья ветка, которой в §12 не было прописано.

- При стандартном GPTQ-4bit (g128) полный tied-PTQ даёт |Δ_total| = 3.03e-04 < DELTA_MIN = 1e-03,
  а парный bootstrap по 32 документам даёт [−0.0014, +0.0009] для Δ_total и [−0.0012, +0.0010]
  для Δ_upstream: **при bits ≥ 3 не различим ни один канал**. Разрешающая способность κ на этом
  корпусе ±0.0012 (7% от κ), то есть пререгистрированный DELTA_MIN лежит на границе различимости.
  Доля upstream разрешается только в 2-битном режиме и равна 0.470 — средняя полоса 0.25–0.5,
  но этот режим есть коллапс модели (PPL +102%, u_cos 0.927).
- Механизм: PTQ — амплитудное возмущение (h_drift 0.046 при u_cos 0.999), κ — угловая метрика.
  В PPL upstream-канал есть (+0.85% при g128, +56% при 2 битах), в κ его след под разрешающей
  способностью. Это разные объекты, не противоречие.
- Граница E-39b «квантован только readout» закрыта: устойчивость κ не была артефактом постановки.
- Инверсии ТЗ: D6 (g32 мягче g128 — жёсткость задают биты), D7 (κ_null(Haar) = 0.00086, в 19 раз
  меньше реальной — гейт переписан в двусторонний, исходный порог 1.0 сохранён в JSON).
- `gate.harsh = leaf_robust_even_harsh` читать с оговоркой `gate.harsh_caveat`: гейт измеряет
  геометрию листа, а не сохранность модели.

Не делать: повторных прогонов, дополнительных λ/seed, scatter (все κ в полосе 0.011–0.016).
Вердикт v2 и парные CI пересобираются из JSON без прогона:
`python experiments/exp39f_full_tied.py --recheck results/exp39f_full_tied.json`.
