## 12. Данные, U, layer mapping, загрузка

**Данные.** Все эксперименты — на данных **OpenWebMath** (математический корпус: формулы, доказательство, теоремы). `N` сэмплов в зависимости от задачи (калибровка ESG: `N ≈ 8–32`; диагностика: `N = 1` — фиксация позиции, §1).

**`𝒮` (набор токенов).** Глобальный набор токенов для всех слоёв:

- `K_max = 512` — максимальный размер (ограничение памяти CPU);
- состав: **top-K по `p_L`** (распределение старшей модели на последнем токене) — гарантирует, что `p_L(i) > 0` для всех `i ∈ 𝒮` (важно для весов `w_i`, §7);
- для Exp 0.1 и Exp 27.6: `K = 64`.

**Layer mapping.** Для моделей разной глубины (`n_S < n_L`) слой младшей модели `l_S` сопоставляется со слоем старшей `l_L = round(l_S · (n_L − 1) / (n_S − 1))`. Выравнивание стро́к `J_L` и `J_S_target` — по токенам `𝒮` (§10, шаг 4); выравнивание слоёв — по mapping'у выше. Эксперименты, где используется только модель `M_S` (ESG, ablation) — без mapping'а.

## 13. Статистический каркас

**Выборка.** `N` сэмплов из OpenWebMath; метрики усредняются по сэмплам, `std` — в отчётах.

**Bootstrapping.** Для всех «важных» сравнений:

- `N_boot = 1000` итераций;
- 95% CI — перцентильный (`[2.5, 97.5]`);
- значимость: CI не пересекает нуль (для разности) или единицу (для cos/bridge).

**Перекрёстная валидация.** Данные разбиваются на `3` фолда (66/33): обучение (калибровка ESG) / тест (оценка bridge) — **не пересечаются**. Это защита от переобучения карты чувствительности.

**Multiple-comparison (Bonferroni).** При тесте `m` гипотез: порог `α/m`. В E-13b `m = 16` (15 слоёв + 1 глобальный тест), `α = 0.05/16 ≈ 0.0031`. Без поправки — ложноположительные findings на ~3% слоёв.

**Метрики для таблиц.** Среднее и `std` по сэмплам; для направленных сравнений — `Δ = mean_A − mean_B` с CI bootstrap.

## 14. Как читать эксперименты (гид)

**Конвенция.** Каждый эксперимент — это `(название, цель, результат, валидирует)`. Идентификатор `E-*` стабилен; нумерация по порядку в Приложении B.

**Типы:**

| Тип | Что проверяет | Примеры |
| --- | --- | --- |
| **Identity** | корректность цепочки | E-1 (identity J), E-14a (identity gauge) |
| **Kill-switch** | «не работает, если X» | E-2 (ESG-kill), E-4 (defrag-kill) |
| **Карта** | тепловая карта по слоям | E-5 (bridge-карта), E-12 (ESG-карта) |
| **Ablation** | влияние одного фактора | E-7 (gramian-коррекция), E-11c (K-зависимость) |
| **Cross-model** | сравнение M_L vs M_S | E-8 (gap-карта), E-9 (ESG-расхождение) |
| **Causal** | причинно-следственная связь | E-13 (surgery) |

**Статус валидации (отдельно от математики).** В Части II леммы `[L-*]` — математические утверждения, **не** требующие экспериментов. В Приложении B — статус валидации каждой леммы: `✅` (прямая), `⚠️` (косвенная), `❌` (открытая).

**Чтение чисел.** Все метрики — в диапазоне `[0, 1]`, кроме `s(l)` (масштаб) и `T_domain` (междоменная разность). `gap ≈ 1.00` — уровень нуля (ортогональность), не «конфликт». `gap < 1.00` — выравнивание лучше случайного; `gap > 1.00` — хуже.
