# 2. БЛОКЕРЫ — то, что меняет выводы

## B1. Лестница P3 = разбавление швами, а не масштаб явления ⚠️ самое важное

`exp64_P3_ladder.py`, `blk_path`: блоки перемешиваются, **швы между блоками не исключаются из подсчёта пар**. При блоке `b` доля испорченных соседних пар = `1/b`. Значит null-дип обязан стремиться к real по закону `(1−1/b)` — независимо от того, на каком масштабе живёт феномен.

Проверяю на вашей же таблице (§14.1):

| blk | измерено | measured/real | предсказание (1−1/b) |
|---|---|---|---|
| 2 | −0.032 | 0.444 | 0.500 |
| 4 | −0.051 | 0.708 | 0.750 |
| 8 | −0.058 | 0.806 | 0.875 |
| 16 | −0.066 | 0.917 | 0.9375 |
| 32 | −0.071 | 0.986 | 0.969 |
| 64 | −0.071 | 0.986 | 0.984 |

Совпадение в пределах 0.005 на всех ступенях (остаток — медиана вместо среднего). **Лестница не измерила масштаб; она измерила долю уцелевших пар.** Вывод «дип сходится к blk16 ⇒ масштаб ≤16» и производный «истинный носитель — шаг и 2–4 токена» из этих чисел не следуют.

Отягчающее: для горба/плато вы швы **зафлагали** («патчворк-границ лестника их раздувает», blk2 плато 0.074 > real 0.043), а для дипа тот же артефакт (только с обратным знаком) прочитали как сигнал. Асимметричная трактовка одного механизма.

**Фикс, 5 строк:** считать `dcurve` только по парам внутри блоков (маска `t//b == (t+k)//b`). Тогда при любом `b` сохраняется 100% локальных пар, и лестница становится информативной. Предсказание: если носитель ≤2 — seam-excluded blk2 даст real сразу; если нет — упадёт. Пока этого нет, «≤32 → ≤16 → 2–4» — не установленный факт.

## B2. E-71 A: порог солитона не отделён от патологии

`exp71_soliton.py`:

```python
ds = [measure(base, d)[1] for d in docs]   # measure возвращает (nll, dip)
```

**nll вычисляется и выбрасывается.** В артефакте порога нет ни nll, ни rep16, ни loopy — при том что ваш собственный §30/§31 установил: *«углубление dip = красный флаг, не зелёный»* (svd8 −4σ, harness −0.72, SVD-крах −0.23…−0.35).

А теперь ключевое число: **на λ=0.7 dip = −0.207, глубже финального −0.174 на 19%.** Рождение объекта должно насыщаться на значении обученной модели, а не перелетать его. Перелёт — ровно подпись промежуточного вырожденного режима. Без nll/rep16 по λ эти две интерпретации неразличимы, и «солитон родился» — не вывод, а выбор.

Ещё три вещи там же:
- `sd_r = {... if v.ndim>=2 else v.clone()}` — **все 1-D тензоры остаются обученными** (RMSNorm gain, bias). λ=0 — это «обученные нормировки + случайные матрицы», а не `from_config`. Концы интерполяции не совпадают с R-null из §17, сравнивать их нельзя.
- Один сид (`manual_seed(11)`). Положение порога может быть сид-зависимым; полоса по инициализации не измерена вообще. IQR в артефакте — по 8 докам, не по сидам.
- `if not res["A"]:` — при падении на 3-й λ следующий запуск **пропустит весь блок A** и посчитает вердикт по трём точкам. Resume по truthiness вместо проверки полноты.

**Фальсификатор, который дешевле самого теста:** вернуть nll и добавить 2–3 наблюдаемые (eff-rank h, cos соседних h, rep16). Если все они включаются на **той же** λ≈0.6 — это генерическое появление компетентности при интерполяции весов, а не локализованный объект. Солитонная заявка требует, чтобы у dip порог был **отдельным** от остальных.

## B3. E-71 B: «упругое столкновение» измеряет не то

```python
ctrl = ids[:cut] + ids[cut:]        # == ids
inj  = ids[:cut] + phrase*8 + ids[cut:]
n0,d0 = measure(m,ctrl); n1,d1 = measure(m,inj)
# комментарий в коде: «сегмент после вставки: переиспользуем общий dip; узкий — по хвосту»
```

Сравниваются **медианы по всей последовательности** двух текстов разной длины и разного состава. Вставка ~64 токенов повтора в 256-токенный док = ~20% массы. Мера «dip сдвинулся ≤0.03–0.07» здесь означает «глобальная медиана разбавилась», а не «среда восстановила ритм после прохождения».

Упругость в смысле солитона — это восстановление формы **после** прохождения, с фазовым сдвигом. Нужен профиль `dip(окно [cut+8L, cut+8L+W])` для W=8/16/32/64 против того же окна в контроле, плюс лестница по числу повторов. Комментарий в коде признаёт, что так и планировалось, — но реализовано не так. **В текущем виде B не отличает упругость от нечувствительности метрики.**

## B4. Матрица чтения: вердикт скрипта противоречит выводу в своде

`exp64_readmatrix.py`:
```python
verdict = ("текстодостаточная линза" if abs(o["dip"]-c["dip"])<0.02
           else "петлевая/политическая добавка")
```
own −0.111, corpus −0.167 → diff 0.056 > 0.02 → скрипт выдаёт **«петлевая/политическая добавка»**. В §22–23 написано обратное: «победитель матрицы — читатель».

Хуже: наблюдённый порядок corpus(−0.167) > crossdom(−0.141) > own(−0.111) **не совпадает ни с одной из трёх пре-регистрированных сигнатур** (§18.2: читатель-однородный ⇒ все равны; текстодостаточность ⇒ свои≈чужие≈corpus; петля ⇒ свои>чужие). Честный вердикт — «ни одна сигнатура не подошла; порядок совпадает с градиентом естественности текста». Это самостоятельная гипотеза, но она не была пре-регистрирована, и подменять ею победу одной из трёх — нарушение протокола, который вы сами вводили.

Конфаунд очевиден и не закрыт: own-greedy = 63% лупов, corpus = живой текст. «Читатель > писатель» и «естественный текст > вырожденный» дают одинаковый порядок. Разделяет их только own **с шаблоном** (E-72, в работе). До неё тезиса нет.

## B5. λ₁: под одним именем два разных оператора, и внутренний конфликт

- `exp64_lambda1.py`: lift по **состоянию** (`Vc = V − mean`, SVD, `lstsq`), **без ridge**, r=48.
- `exp67_quantolike.py`: lift по **приращениям** (`V = H[1:]−H[:-1]`), **с ridge 1e-3**, r=64.

Это разные объекты с разными спектрами. В своде (§24, §27, E-76, E-79) они называются одинаково — «lift-оператор». Плюс §24 описывает «PCA-64 + ridge 1e-3», чего в закоммиченном `exp64_lambda1.py` нет: **описание метода не соответствует коду, который лежит в репо**. Каким скриптом получен LAMBDA1.json — из репо не восстанавливается.

Это ровно та болезнь, которую paper уже запретила для `r_eff` (§2.3: «`r_eff` без субскрипта запрещён», три объекта под именем). В динамической линии она рецидивировала: `lift`, `dcurve`, `plateau`, `нить`.

И главное — **внутреннее противоречие**: §24 объявляет И-2 подтверждённой на λ₁≈−0.92 (L23), а §41.4 (E-76 v4) даёт для L23 `stab_half = 0.49` и вердикт «не разрешено». Флагманский операторный результат стоит ровно там, где собственный вектор неустойчив по половинкам. Одно из двух утверждений должно быть снято.

Отдельно: `arg_near_pi = float(max(|angle(ev)| > 2.6))` — для вещественной матрицы отрицательное собственное значение имеет угол ровно π, то есть этот критерий детектирует то же самое, что `min_re < 0`. **Два из трёх критериев И-2 — один критерий**, а он, в свою очередь, есть переформулировка Δ(1)<0. Новой информации в «И-2 подтверждена» пока ноль; nueva была бы в паре θ≈1.0 и λ₃≈0.97 — они не отчитаны.

## B6. E-69: обещанный канал не измеряется, якоря — из другой агрегации

`exp69_therapy.py`:
- Докстринг: «trajectory по эпохам (nll, dip L23, **loopy-прокси rep16**)». В коде rep16 **не считается нигде**. То есть терапия не может отличить «ритм вылечился» от «лупы убрали» — а это единственная альтернатива, которую ваш §30 обязал исключать.
- `healthy_anchor=[3.19, −0.174]`, при этом `NDOC=8` и nll агрегируется `np.mean`. 3.19 — медиана по 12 докам (вы это нашли в §33, но в коде осталось). `p_recovered = |nll − 3.19| < 0.4` — предикат вердикта сравнивает среднее по 8 с медианой по 12. Это ваш же Б8, нарушенный в коде.
- `evalm` считает nll **на тех же 8 доках, на которых идёт обучение**. Это train-loss; в артефакте он называется `nll` и участвует в `p_recovered`. Holdout есть только в E-69c — отдельно.

И по дизайну: поражение в MLP, терапия в attention. Это не диссоциация, это одна клетка не-2×2. Для заявки «каналы независимы» нужна матрица lesion{MLP, attn} × therapy{MLP, attn} × measure{R, P}. Пока сильнейший результат программы (§35) стоит на одной клетке с неучтённой альтернативой «возврат в полосу».

# 4. MEDIUM — смысловые сдвиги

1. **«Поле, не траектория»** — отчасти тавтология дизайна. blk32 сохраняет ~97% соседних пар и всю структуру до 32 токенов; статистика, чувствительная к 2–4 токенам, обязана совпасть. Информативен контраст blk2/blk4 — а он, как показано в B1, объясняется швами. Плюс семантика: *локальный динамический процесс — всё равно динамический процесс*. «Локально» ≠ «не динамика».

2. **Sum-rule против двухстадийных медиан.** §23 использует «ACF-constraint sum≈0», чтобы объявить дип учётной вершиной. Но опубликованный corpus-ряд (k=1 −0.167, k=3 +0.113, k=4 +0.140, k=8..32 ≈ +0.06) даёт Σρ ≈ +1.8, не 0. Причина: `Δ(k)` — медиана косинусов по докам, затем медиана по домену; **нелинейная агрегация ломает линейные тождества**. Это ровно урок `[L-triple]` из вашей же paper («медиана отношения ≠ отношение сумм», E6 закрыт через сетку 8 ячеек). Две линии одного проекта противоречат друг другу. Надо решить: правило суммы применяется к per-doc ACF (тогда пересчитать на нём) или не применяется вовсе (тогда снять аргумент про «учётную вершину»).

3. **«Выучено»** смешивает «требует обученных весов» и «есть выученное представление». См. H2.

4. **Двухканальность**: «ритм — лабильный канал читающего субстрата» пока не отделён от «ритм вернулся в узкую полосу, потому что убрали лупы». E-69b показывает, что ритм различает *свои лупы vs чистые чужие* — но это снова ось лупов. Нужна дискриминация **между чистыми чужими текстами разных типов** после терапии vs fp32.

5. **Солитон, строгие критерии**: квази-интеграл Σc² плоский **по глубине** — глубина не время, сохранение вдоль эволюции не показано; period-2 flip ≠ бризер (нет ни локализации, ни внутренней частоты); упругость — см. B3; порог — см. B2. По строгим критериям пакет 0/5, по метафорическим ~3/5. Рекомендую понизить до «пороговая нелинейность + робастность локальной статистики» и убрать слово «солитон» из заголовков до B2/B3.

6. **Коллизии имён**: `lift` (состояние/приращение), `dcurve` (две реализации), `plateau` (три окна), `нить_Г/нить_T` (разведено — хорошо), `канал` (подразумевает независимость, а в репарации связаны). Нужен реестр объектов с субскриптами, как в paper §2.3.

7. **Квантовые пробы**: T2 константа (доказано), T1 = дип. T3 (доля мнимой мощности) — легитимный, но обыденный спектральный дескриптор. Оставлять T1/T2 в программе — прямой репутационный риск: рецензент увидит CHSH на ко-измеренных бинаризациях и обесценит остальное.

# 5. Что стоит твёрдо (и что недооценено)

- **P1 «глубина ячейки»** (§14.2) — на мой взгляд, **лучший результат всей программы**: agreement / 1−cos(state) / cos(direction) как функция длины общего суффикса, с внутренним контролем k=0 (0.04). Даёт k50=2, k90=12–16 и остаток 0.13 («состояние несёт контекст сверх того, что входит в направление»). Не зависит ни от одной хрупкой статистики, не требует нулей-костылей, имеет прямой механистический смысл. Сейчас лежит в «S5-личном» разделе. Это заголовок, а не приложение.
- **Цепочка V-оценщик → iid 0.000 → AR +0.414 → blk** — корректная измерительная конструкция с правильными контрастами. Знак лаг-1 переживает всё.
- **P4: контроль фильтруется тем же фильтром, что и основной массив** — учебникового уровня поимка (loopy в контроле тянул медиану 0.4 вместо 0.80). Это надо вынести в протокол как отдельное правило, оно уже спасло одну заявку.
- **AT: детерминированный по роли провал** (BASE теряет «лицензию» в 3/3 наборах, G1/C1 держат её во всех) — сильнее агрегата; и **nudge вредит повсюду** (0.92→0.71 на 36 парах) — реплицировано, контринтуитивно, операционально. Это два настоящих поведенческих факта. Оговорки: filler = повторы своего текста (иголка на однородном фоне), нет C2/C3/C4 на 32k, формальная значимость только при пост-хок пулинге G1+C1.
- **Квантование: схема важнее нормы ошибки** (per-group W4 цел, per-tensor W8 трогает, fqres4 убивает) — практично и честно исправлено после аудита коллеги.
- **`ast.get_source_segment` для переиспользования оценщика** (E-69/E-71 тянут `curves_series` из одного файла) — по-настоящему хороший паттерн провенанса. Доведите до конца: писать в артефакт sha256 исходного файла + sha извлечённых функций. Сейчас оценщик переиспользуется, но не пинуется.
- **Отзыв LFM3 и доктрина provenance входа** — самый ценный методологический выход программы. «Правдоподобный мусор» как отдельный класс отказов — это то, что стоит написать отдельной заметкой.

# 8. Сквозной пробел

Во всей программе — **ни одной генеративной проверки**. Все фиты делали к кривой Δ(k); ни разу не подгоняли модель **пути** с последующим пересчётом статистики. Стандартный шаг surrogate-анализа: подогнать VAR(p)/DMD на половине доков → симулировать → пересчитать Δ(k) → сравнить с held-out доками и слоями. Если VAR(2) воспроизводит дип+горб+плато с правильными величинами — «три моды» есть «линейный процесс второго порядка», и ничего сверх этого искать не надо. Если не воспроизводит — вот тогда есть объект.

Это и есть честный «тест 6», и он же — единственный мост от Кеплера к Ньютону, который вы четыре раунда подряд откладываете.
