## VERDICT

**ПОДТВЕРЖДЕНО.** Конвенция CPU-руки E94 (маржа берётся из строки логитов OFF-1+j,
т.е. из распределения, породившего сгенерированный токен, а не из строки OFF+j)
выдержала независимую перепроверку по обоим докам (w0, w2_r1), j=0..7:

1. Row-тест: top1(row[63+j]) == emitted id_j на 16/16 позиций (w0 8/8, w2 8/8);
   конкурентная row[64+j] — 0/16. В raw-данных аналогично 8/8 против 0/8 по докам.
2. Margin-тест: max|Δmargin| HF-vs-raw = 7.27e-04 < 1e-3 (наихудшая точка w0 j=7);
   на сдвинутой строке расхождение 7.67e-01 — конвенция не «случайно близка»,
   именно prev-row совпадает.
3. Дополнительно (мой пересчёт): p1 из row[63+j] совпадает со замороженным
   REPLAY.gen_p1[j] с max|Δ| = 4.80e-05 — встроенный repro-гейт q3cpu подтверждён
   на взятых позициях.

Без биаса: 7.3e-4 — это меж-движковая точность (llama/SYCL-сырьё против HF CPU fp32),
не бит-равенство; допуск 1e-3 закрыт с запасом ~37 %. Если бы конвенция была сдвинута
на строку, расхождение было бы ~0.77 — на три порядка больше, так что «не нашли
сдвига» здесь не переодевание: конкурентная гипотеза (row[OFF+j]) опровергнута
жёстко (0/16 id и margin ~0.77).

Ограничения (честно):
- покрыты только первые 8 gen-позиций w0 и w2 (по ТЗ); полный трек 384×16 не
  пересчитывался независимо — вердикт по ТЗ-критерию, не по всему треку;
