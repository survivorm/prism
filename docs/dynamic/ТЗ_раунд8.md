Общее: CPU, один тяжёлый процесс за раз; пул — пин E-65/E-71 (12 wiki-доков, pool_fp
144c722df3046f2d-совместимый протокол); оценщик dip/hump/plateau — ast-дубль ядра,
L11/L23; каждая клетка пишет строку в raw-файл ДО следующей (resume). Логи в /tmp/e77.log,

## E-77 LAYERMASS — фальсификатор параметризации порога (Т-В(3)), CPU ~15 мин
**Гипотеза.** Взрыв dip на λ∈[0.5,0.7] (E-71A) — свойство накопленной массы обученных
весов, а не артефакт покомпонентной интерполяции α·W_trained+(1−α)·W_rand.
**Конструкция.** Случайная модель = fresh-init из config той же архитектуры, per-tensor
std-matched к trained (прецедент R-null). Клетка k: случайная модель, у которой СЛОИ
из множества S_k заменены обученными. Три режима S_k: prefix {0..k−1}, suffix {24−k..23},
random-подмноество размера k (сид 0), k=0..24, слои 0..23 трансформера; embed/norm/lm_head
всегда trained (иначе nll взрывается неинтересно; зафиксировать в артефакте).
**Ось X — ИЗМЕРЕННАЯ масса** m(k)=||W_trained(S_k)−W_rand(S_k)||_F / ||W_trained(all)||_F,
не номер k (слои неодинаковы — это главный конфаунд, он же цель теста).
**Метрика.** dip(L11), dip(L23), медиана по 12 документам.
**Контроль.** k=0 обязан попасть в R-null полосу [−4e-5;±1e-4]; k=24 обязан совпасть с
fp32-baseline (−0.174±0.01) — иначе сборка весов сломана, тест останавливается (гейт
оба конца, до анализа кривой!).
**Пре-рег вердикт (заранее).** По оси m: amplitude-разброс между m=0.2·m24 и m=0.8·m24
< 25% полного размаха, а в окне m∈[0.45,0.7]·m24 сосредоточено >50% размаха ⇒ «порог по
массе жив» (Т-В усиливается). Размах размазан ≥50% на широком окне ⇒ «взрыв E-71A —
артефакт параметризации» (Т-В слабеет). prefix/suffix/random расходятся качественнно
(не по шуму) ⇒ порог не про массу, а про КОМПЛЕКТНОСТЬ (какие слои, а не сколько) —
третий вердикт, тоже ценный.
**Ресурс.** Одна загрузка 0.8B trained (3.2 ГБ) + словарь random-тензоров (3.2 ГБ),
25×12 форвардов по ~2 с = минуты. Пик RAM ≈ 8 ГБ — запускать, когда свободен e72.

## E-78 SURPLUS — «излишек чтения» как драйвер амплитуды (3-5 Т-1/С), CPU ~40 мин
**Гипотеза.** |dip| документа растёт с S(doc)=NLL_qwen(doc) − NLL_ngram5w(doc)
(«излишек чтения»: что модель выигрывает у n-gram-машины на том же токенизаторе).
**Часть A (сейчас, без own).** Домены/формы: wiki-12 (dip −0.174), math-32, chat-32,
corpus-32 (−0.167), mix (−0.02), loop-synth (повтор 1 предложения ×N, dip из harness
−0.72 как якорь). S по каждому доку, TF-NLL из существующих forward'ов (часть есть в
meta-файлах; чего нет — досчитать, ~30 форвардов).
**Часть B (после E-72-шаблона).** own-raw и own-tmpl — только тогда сравнение own∈ранжированию легально.
**Машина S.** ngram 5-gram с stupid-backoff, сглаживание +V, per-corpus (C4-wiki учётная
база, та же, что T-23/E-55 — НЕ per-doc!), OOV-ссылка на unigram. S считаем в натах/токен
по токенам ДОКУМЕНТА, оба NLL на одном разбиении.
**Контроли.** (1) loop-synth: n-gram предсказывает почти всё ⇒ S≈0 и dip глубокий
(−0.72) — ЭТО ГЛАВНАЯ УГРОЗА теории: если на лупах dip максимален, а S минимален,
монотонность |dip|~S мёртва ЗАРОДЫШЕМ — теория обязана предсказать знак на петлевом
режиме; пре-рег: ожидаем немонотонность на лупе (петля = другой режим, луч (dip,loopy)),
поэтому гейт по НЕ-петлевым документам, луп — отдельная точка-предсказание «S≈0, dip
глубокий» (попадание = теория описывает оба режима, промах = описывает ничего);
(2) перестановочный контроль текста (shuffle предложений wiki): dip≈−0.11 (E-64), S
растёт (локальная связность пропала для ngram сильнее) — предсказание: S↑ dip↓ ⇒
ОТРИЦАТЕЛЬНАЯ связь?? — НЕТ: S=NLL_qwen−NLL_ngram: у shuffle NLL_qwen растёт меньше,
чем NLL_ngram ⇒ S отрицательный ⇒ «отрицательный излишек = слабый дип» — формализовать
заранее: предсказываем МОНOTOННО ПО S на НЕ-петлевом наборе, ρ≥+0.5 (Spearman по
~90 документам, бут 95% CI) ⇒ S-драйвер жив; ρ∈(0.2,0.5) — не разрешено; ≤0.2 мертво.
**Ресурс.** ngram-счётчики по C4-файлам на диске (память: dict 5-gram — ограничение!
см. аудит ТЗ п.4).

## Само-аудит этого ТЗ (ловим себя ДО кода)
1. **E-77: «random-подмножество размера k» при фиксированном сиде = одна реализация** —
   шум выбора слоioв замаскируется под вердикт. Починка: 3 сида для random-режима,
   показывать разброс dip между сидами как error-bar; вердикт только если расхождение
   режимов > межсидового разброса.
2. **E-77: std-match по всему тензору не спасает rms-norm-слои** — у Qwen3.5 есть
   per-head/per-channel нормы; рандомизировать norm- веса? Починка: layernorm/rmsnorm
   ВЕЗДЕ оставляем trained (они масштабы; их рандомизация убьёт нелинейность неинтересно).
   Фиксировать список патча: только Linear/G-модули слоёв.
3. **E-77 гейт k=24 «совпадёт с baseline» не автоматом:** патч «trained-слои в
   random-модель» ≠ trained-модель, если патчится только часть тензоров слоя (см. п.2 —
   norm trained везде ⇒ k=24 = trained полностью, совпадение гарантировано конструкцией —
   тогда это НЕ гейт, а тавтология!). Починка: настоящий гейт — k=0 против R-null
   (собирается ли «полностью случайный» из тех же кусков с той же полосой) + контроль
   одной клетки k=12 против E-71A α=0.5-клетки (сопоставимая масса) — расхождение
   «кривая массы» против «кривой α» само по себе результат (несовместимость
   параметризаций), записывать обе оси.
4. **E-78: словарь 5-gram по всему C4 в память не влезет** (миллиарды n-грамм).
   Починка: считать NLL_ngram по ХЭШ-таблице с ограничением (count-min ~2 ГБ) ИЛИ
   взять 5-gram по подвыборке 2 ГБ текста, как делал E-55 (там 8g-модель жила в
   pickle 500 МБ — переиспользовать её СОБСТВЕННЫМ кодом exp62, не изобретать:
   import/ast-вытащить из exp62_gen_lfm3-adjacent? нет — из exp55_lookup_coverage.py).
   Зафиксировать: заимствуем ngram-машину из exp55 как есть (проверенная на 8g=0.117).
5. **E-78: TF-NLL моделей уже посчитаны в каких артефактах?** Честно — не помню для
   math/chat; значит план «досчитать» может оказаться «посчитать заново всё» (+20 мин,
   приемлемо), но сначала grep по meta-файлам, потом код.
6. **E-78 mix-файлы:** лежат в /tmp (моёт tmpwatch? чистого /tmp-чистильщика нет, но
   30-дневный systemd — не грозит сегодня). На всякий случай скопировать mix в results/.
7. **Общее: пул E-77 — 12 доков E-71, а матрица −0.167 — 32 дока P2.** Кривые
   несъёмны «с точностью до пула» — в вердикте цитировать СВОЙ baseline (12 доков,
   −0.174), матричные числа не смешивать.
8. **Очередь:** e72(идёт) → eigen(идёт) → E-77 → E-73 → E-75 → E-78A. Цепочку — только
