## §1. «r — статистика двух чисел, не профиля» — ПРИНЯТО

Тождество верное (S5 его гейтит): r = ‖u_N−u_0‖²/c0 = 4(1−cos(u_0,u_N))/c0,
r/r_max = (1−cos(u_0,u_N))/2. Проверено по артефакту в обоих направлениях:
endpoint_cos = 1 − r·c0/2 совпадает с прямым вычислением cos(u_0, u_N) с точностью 1e-12
(дизайн-тест rebuild).

Принято:
- формула записана в `meta.scope` (ранее scope был только в модуле — самокоррекция ниже);
- новый блок `r_decomposition`: per-doc/per-instance r, c0, r_max, endpoint_cos для всех
  14 групп (R0 real/mix, R1/R2 × S × real/mix) + `trained_vs_random`.

СПОРЮ по Следствию 2 («trained и random дают одинаковый endpoint-косинус; вся разница r —
от c0»). Это не тест, а overlap диапазонов при n≤8, и по фактическим числам «совпадения»
нет: endpoint_cos trained (clean) = −0.006 (w6), 0.080 (w3), 0.332 (w1), 0.346 (w2),
0.311 (w5), 0.351 (w7); median по random-инстансам = 0.071 (w7), 0.164 (w1), 0.179 (w6),
0.186 (w2), 0.205 (w3), 0.249 (w5) — random-траектории в медиане СИСТЕМАТИЧЕСКИ
ортогональнее к началу. Утверждение «геометрия endpoint'ов совпадает» НЕ закреплено
(в блоке `r_decomposition.note` так и записано). Чистый сигнал — c0: 8/8 доков и 48/48
paired сравнений (см. §8.3).

Следствие 3 (кинетика) — принято: в P2 `scale_note` записано «bounded path + N=383 ⇒ r
кинематически зажат для trained И random».

## §4. «P1 — бэнд детектор low-motion; rename coherent_drift» — ЧАСТИЧНО; СПОРЮ о rename

Принято: `reachability_note` per-instance («r_max = 4/c0 ≤ 0.0125…0.3019 < 0.75 —
structurally unreachable: c0 median 259…268 ≫ 4») + wording в summary.

СПОРЮ: rename в `coherent_drift` — это неверное имя, и аргумент ревью повторяет уже
отвергнутую (и самим ревьюером в r3 сданную) конфузию из r3 C4:

- **r ≈ 1 — НЕ «когерентный малый дрейф / отсутствие backtracking»**. Для iid-ПРИРАЩЕНИЙ
  (некоррелированных) E[‖ΣΔu‖²] = Σ‖Δu‖² = c0 ⇒ r ≈ 1 — это СЛУЧАЙНЫЙ МАЛЫЙ ШАГ
  (нет ни дрейфа, ни backtracking). Когерентный дрейф — ΣΔu ≈ N·const ⇒ r ≈ N.
  Измеренные null'ы артефакта (`P1.synthetic_null`, seed 117, B=200):
  `iid_lowmotion_c0_2`: r_med = **1.0017**, band_frac = 1.0 (в бэнде);
  `drift_smooth_walk`: r_med = **191.64**, band_frac = 0.0 — дрейф ВНЕ бэнда в ~130×.
- «Для iid-приращений как раз r ≈ 1/N» — неверно: r ≈ 1/N — это iid-ПОЗИЦИИ на сфере
  (телескопирование; в артефакте `iid_sphere`: r_med = 0.0026). Для iid-приращений
  r ≈ 1 (в артефакте 1.0017). Смешение этих двух null-моделей — ровно та конфузия,
  которую закрывала r3 C4 («r ~ 1/N» — iid-позиции; «E[r]=1» — iid-приращения, low-motion).

Поэтому ключ `P1_R2_real_orthogonal_walk` остаётся (пре-рег-имя; «orthogonal walk» =
некоррелированные приращения — корректное имя для режима бэнда), а `band_meaning` записан
в P1-блок с указанными выше измеренными null'ами: бэнд [0.75, 1.5] — сигнатура
НЕКОГЕРЕНТНЫХ малых шагов; дрейф — r≈N; iid-сфера — r≈1/N.

Мелочь «drift_smooth_walk не гейтится» — СПОРЮ (факт): в rebuild-скрипте ассерты
есть: `assert null_rep["drift_smooth_walk"]["band_frac_0.75_1.5"] < 0.01` и
`assert null_rep["drift_smooth_walk"]["r"]["median"] > 100` (в текущем
experiments/AT0_4_rebuild_r5.py — строки 161–162; ранние rebuild-скрипты r1–r4
удалены — не трекались, в репо только актуальный AT0_4_rebuild_r5.py).
