# Часть I. Постановка

## 1. Мотивация, цели, статус

**Суть метода.** Даны две модели одного семейства (Qwen3.5-4B и Qwen3.5-0.8B), общий словарь. Метод сравнивает **чувствительность декодирования** — то, как скрытые состояния каждой модели влияют на финальные логиты. Сравнение происходит через пространство словаря, которое является общей системой координат для обеих моделей.

**Ключевая интуиция.** Для задач с softmax-выводом важны не все компоненты скрытого состояния, а только их проекция на пространство, реально влияющее на выходные вероятности. Математически это выражается через Якобиан `∂p/∂h_l`: он кодирует, какие направления в `h_l` двигают распределение выходов, а какие — нет.

**Цели (по приоритету):**

| Приоритет | Цель | Что получаем | Статус |
| --- | --- | --- | --- |
| **P0** | Диагностика: послойная карта расхождения Якобианов (`𝓖_gap`) | Тепловая карта по слоям | ✅ Подтверждено (E-1 identity, E-2 карта) |
| **P1** | Карта чувствительности для квантования: какие направления защищать | Правые сингулярные векторы `J^T J` (hidden space); ESG = `JJ^T` (token space) | ✅ Частично (E-12b,c: ESG validated) |
| **P2** | Трансформация младшей модели | Лосс для оптимизации | гипотеза, отложено (H4) |
| **P3** | Регуляризатор при дообучении | Дополнительный лосс | гипотеза, отложено |

P0 и P1 — реализованные уровни; P2/P3 отложены до дополнительных исследований. P0 и P1 — разные артефакты: P0 показывает, насколько `J_S` отличается от `J_S_target`, P1 — какие направления hidden state наиболее чувствительны.

> **Фиксация позиции.** Если не указано иное, все карты чувствительности и Якобианы вычисляются для последнего токена последовательности: `t = S-1`.

## 3. Архитектурный контекст: Qwen3.5

Архитектурные факты, влияющие на корректность вычислений. Производные — в §8.

**Гибридная архитектура.** `config.layer_types[layer_idx]` определяет тип слоя: `"full_attention"` → `Qwen3_5Attention` (GQA); `"linear_attention"` → `Qwen3_5GatedDeltaNet` (GDN). Типы чередуются.

**GDN: рекуррентное состояние.** GDN поддерживает рекуррентное состояние `S_t ∈ R^{H × D_k × D_v}`:

```
S_t = g_t * S_{t-1} + k_t * delta_t^T
output_t = S_t * q_t
```

Кэш GDN содержит `conv_state: [1, conv_dim, conv_kernel_size − 1]` и `recurrent_state: [1, num_v_heads, head_k_dim, head_v_dim]`. GDN — не трансформер: обратный проход идёт через рекуррентную цепочку, а не через attention-матрицы.

**Мутация кэша.** `torch_causal_conv1d_update` мутирует `conv_state` in-place (`conv_state.copy_(...)`); GDN обновляет `recurrent_state` через `cache_params.update_recurrent_state(...)`. Поэтому `copy.deepcopy(prefix_cache)` **не работает** для GDN-слоёв — используется `_deep_clone_cache()` (ручной клон всех тензоров), см. §9 и Приложение C.

**Tied weights.** `_tied_weights_keys = {"lm_head.weight": "model.embed_tokens.weight"}` — т.е. `W = E`, и проекция через `E` корректна для логитов.

**MRoPE.** Multi-dimensional RoPE с `position_ids` формы `[4, B, S]` (text, temporal, height, width); для текстового входа все 4 компоненты одинаковы. При вычислении Якобиана для последнего токена с кэшем: `position_ids = S − 1`.

**RMSNorm — не идентичность.** `Qwen3_5RMSNorm`: `output = (x / rms(x)) * (1 + weight)`; вес инициализирован нулями, поэтому на старте `1 + w = 1` и RMSNorm — чистая нормализация `y = x/RMS(x) ≠ x`. Производная — §8 `[L-rms]`.

**Ограничения версии 1:** CPU (Intel Iris Xe / SYCL, 64 GB, `torch.set_num_threads(4)`, float32 — fp16 на CPU на порядок медленнее); текстовый вход (`Qwen3_5ForCausalLM`); `model.model` — `Qwen3_5TextModel` (единый путь доступа ко всем размерам); в экспериментах — Qwen3.5-4B (32 слоя, `D_L = 2560`) и Qwen3.5-0.8B (24 слоя, `D_S = 1024`).

## 4. Якобиан и модели

**Модели.** Старшая модель `M_L`: скрытая размерность `D_L`, `n_L` слоёв, словарь `V`. Младшая `M_S`: `D_S < D_L`, `n_S` слоёв, тот же словарь `V`. Матрица эмбедингов `E ∈ R^{V×D}`; при tied weights `W = E` (§3).

**Якобиан (определение).** Для слоя `l`, позиции `t`:

$$J_l^{(t)} = \frac{\partial z_t}{\partial h^l_t} \in \mathbb{R}^{V \times D}$$

где `z_t ∈ R^V` — логиты, `h^l_t ∈ R^D` — скрытое состояние. На практике вычисляется только для фиксированного набора токенов `𝒮` (§12): `J_l^(t)|_𝒮 ∈ R^{|𝒮|×D}`.

**Слой-переходный Якобиан.** Для скрытого состояния `h^l`:

$$D_l(x) = \frac{\partial h^{l+1}(x)}{\partial h^l(x)} \in \mathbb{R}^{D \times D}$$

**Правило композиции** `[L-comp]`. По цепному правилу:

$$J_l^{(t)} = W_{\mathrm{lm}} \prod_{i=l}^{L-1} D_i(x)$$

Произведение упорядочено справа налево; матрицы `D_i` зависят от `x` и в общем случае не коммутируют — порядок имеет значение.

**Структура pre-norm блока.** Для `h^{l+1} = h^l + MLP(RMSNorm(h^l + Attn(RMSNorm(h^l))))`:

$$D_l = I + \frac{\partial \mathrm{MLP}}{\partial \bar h} \cdot \frac{\partial \mathrm{RMSNorm}}{\partial \hat h} \cdot \left( I + \frac{\partial \mathrm{Attn}}{\partial \tilde h} \cdot \frac{\partial \mathrm{RMSNorm}}{\partial h^l} \right)$$

где `h̃ = RMSNorm(h^l)` (вход Attn), `ĥ = h^l + Attn(h̃)` (вход второго RMSNorm), `h̄ = RMSNorm(ĥ)` (вход MLP); вклад каждого RMSNorm — §8 `[L-rms]`.

**О взвешенных строках.** Величина `Σ_{j∈𝒮} p_{𝒮,j} J_j` (сумма по `𝒮` полная, `Σ p_{𝒮,j} = 1`), где `J_j = ∂z_j/∂h` — строка Якобиана для токена `j`, — это вероятностно-взвешенное среднее строк Якобиана: вектор-строка `1×D`, в общем случае **не равный** самой матрице `J`. Свойства gauge-оператора `M_p` устанавливаются в §8 `[L-gauge]` и из этого среднего не выводятся.

**Gauge-free Якобиан** (определение; свойства оператора — §8 `[L-gauge]`). Для задач, инвариантных к uniform shift логитов (softmax, cross-entropy), важна не `J` целиком, а её gauge-free компонента:

$$J^{(p)} = P(p)\, J, \qquad P(p) = \mathrm{diag}(p) - pp^T$$

где `p = p_𝒮 ∈ R^K` — softmax логитов, урезанный и ренормализованный на `𝒮`. Оператор убивает gauge-направление (uniform shift), сохраняя token-discriminating направления. `J^(p)` используется в defrag (§6, E-11a) и surgery (§18).

## 5. Лемма о размерностях и Gramian-коррекция

**Лемма** `[L-dim]`. Пусть `J_L ∈ R^{|𝒮|×D_L}`, `J_S ∈ R^{|𝒮|×D_S}`, `E_L ∈ R^{V×D_L}`, `E_S ∈ R^{V×D_S}`. Тогда:

- **(а)** Проекция в пространство словаря: `J̃_L = J_L · E_L^T ∈ R^{|𝒮|×V}`;
- **(б)** Целевой Якобиан для младшей модели: `J_S_target = J̃_L · E_S ∈ R^{|𝒮|×D_S}`;
- **(в)** `J_S` и `J_S_target` имеют одинаковую размерность `|𝒮|×D_S` и непосредственно сравнимы.

**Проблема неортогональности.** При кросс-модельной проекции `J_L · E_L^T · E_S` матрица `E_S` неортогональна (`E_S^T E_S ≠ I`). Даже при `J_L = J_S` и `E_L = E_S` (одна и та же модель) лосс не равен нулю — проекция `E_S` «вращает» векторы в пространстве младшей модели.

**Коррекция** `[L-gram]`. После проекции через `E_S` применить правую коррекцию:

$$J_S^{\text{target}} = (J_L \cdot E_L^T) \cdot E_S \cdot G_S^{-1}, \qquad G_S^{-1} = \mathrm{pinv}(E_S^T E_S)$$

`pinv` — через SVD для числовой стабильности. Эквивалентно `E_S · G_S^-1 = (E_S^T)^+` (при `σ_min(E_S) > 0`) — псевдообратная строки `E_S^T`, т.е. замена `E_S` на её ортогональную проекцию в `R^D`. Для identity-случая (`E_L = E_S`):

$$J_S^{\text{target}} = J_L \cdot E^T \cdot E \cdot \mathrm{pinv}(E^T E) = J_L$$

Смысл коррекции: `J_L E_L^T` — координаты в токен-пространстве; умножение на `E_S G_S^-1` — проекция этих координат в пространство младшей модели, корректная при `σ_min(E_L^T E_S) > 0` (матрица пересечения не вырождена — для моделей одного семейства выполнено).

**Оптимизация.** `G_S^-1` вычисляется один раз и кэшируется на диск (`results/.gramians/`) с хешем по форме и содержимому `E_S`.

> Свойства Грамиана (condition number, ранг, достаточность регуляризации) — результаты, см. E-6b, E-8, E-3.
## 6. ESG, спектральные метрики, ранги

**Определение (ESG).** Empirical Sensitivity Gramian для слоя `l` на `N` калибровочных сэмплах:

$$\bar{G}_l = \frac{1}{N} \sum_{i=1}^{N} J_l^{(i)} \left(J_l^{(i)}\right)^T \in \mathbb{R}^{|\mathcal{S}| \times |\mathcal{S}|}$$

Спектральное разложение: `Ḡ_l = U Λ U^T`. Собственные векторы `u_1, …, u_K` — главные направления чувствительности декодирования в **токен-пространстве**.

> **Примечание.** Это НЕ Neural Tangent Kernel в классическом смысле (Jacot et al., 2018): NTK — градиенты по параметрам, ESG — градиенты по активациям. Термин NTK не использовать.

**Спектральные метрики** (для сингулярного разложения `J^(p)`, `σ_1 ≥ σ_2 ≥ …`):

- **uniformity**(`u`) = `⟨u, 1_𝒮/√K⟩² ∈ [0,1]` — доля направления `u` вдоль uniform-режима `𝒮`. Определён только для векторов token-пространства.
- **Эффективные ранги** (спектр `Ḡ_l = U Λ U^T`, `λ_k = σ_k²`, `p_k = λ_k/Σλ`):
  - энтропический: `r_eff = exp(−Σ_k p_k log p_k)`;
  - stable rank: `r_stable = (Σ λ_k)² / Σ λ_k²`;
  - participation ratio: `PR = (Σ λ_k)² / Σ λ_k²` (для спектра `JJ^T`) — в §6 совпадает со stable rank; метрика `F = 1/√(r_eff (K + D − r_eff))` (§15).
- **gauge_share (ESG-версия)** = `σ_1² · uniformity(u_1) / Σ_i σ_i²` — доля энергии `J^(p)`, приходящаяся на gauge-направление.
- **Trace** = `Σ_i σ_i²` — общая чувствительность.
- **SNR** — leave-one-out отношение «сигнал» к «шуму» в спектре (числа — §17, E-14).

Не путать ESG-gauge_share с `g_uni` (§8): `g_uni` — доля энергии **сырого** `J` в uniform-режиме, убиваемая проекцией `P(p)`; ESG-gauge_share — доля энергии уже gauge-free `J^(p)` на направлении `u_1`.

**Разведение рангов.** Символ `r` используется в двух смыслах, которые следует отличать:

1. **Спектральный ранг** `r_eff` — participation ratio / stable rank / энтропический ранг спектра `JJ^T` (определения в §15, метрика `F`).
2. **Функциональный ранг** `r_KL` — минимальное `r`, такое что KL defrag-r аппроксимации `J^(p) ≈ U_r J_r` совпадает с KL полной `J^(p)` (числа — E-11a, §19). Не путать со спектральными рангами: согласие `r_KL` с `r_eff`/`PR` — отдельная проверка, а не допущение.

Оба ранга одного порядка на L6–L18 (E-9, E-14), и их согласие — отдельная проверка, а не допущение.

**Лемма о спектре** `[L-rank]`. `Ḡ_l = JJ^T ≥ 0` симметрична; собственные значения — квадраты сингулярных значений `J`. Для rank-deficient `J` (см. §8 `[L-rms]`: произведение `D_i` вырождено) спектр имеет нулевое собственное значение с кратностью ≥ `K − rank(J)` (`K = |𝒮|`); при `K < D − n_rms` полная матрица может быть полного строчного ранга — нулевых СЗ в `JJ^T` нет вовсе (нуль-пространство `J^T J` в D-пространстве имеет размерность `D − rank(J)` — это другой объект). Top-`m` сингулярные значения определяют всю полезную информацию.

**Тождество** `[L-fisher]`. `P = ∂ softmax/∂ z`, поэтому `J^(p) = P J = ∂p/∂h` — канонический Якобиан выходного распределения, и `J^T P J` — информация Фишера:

$$\mathrm{KL}\left(p \,\|\, p_{h+\delta}\right) = \tfrac{1}{2}\, \delta^T J^T P J\, \delta + O(\|\delta\|^3)$$

## 7. Gap и bridge: определения и направления

**Определение (gap, разрыв).** Для слоя `l`:

$$\mathcal{G}_{\text{gap}}(l) = \sum_{i \in \mathcal{S}} w_i \left(1 - \frac{J_S[i] \cdot J_S^{\text{target}}[i]}{\|J_S[i]\| \cdot \|J_S^{\text{target}}[i]\| + \epsilon}\right)$$

где:

- `w_i = p_L(i) / Σ_{j∈𝒮} p_L(j)` — вероятность токена `i` в распределении старшей модели, **нормированная на 𝒮**. Асимметрия осознанна: используется именно `p_L` (не `p_S` и не среднее) — фиксируется система отсчёта старшей модели.
- `ε = 10^-8`.
- Строки `J_S` и `J_S_target` соответствуют **одним и тем же токенам** из `𝒮` (выравнивание гарантировано §5).

**Определение (bridge, мост).**

$$\mathcal{B}_{\text{bridge}}(l) = \sum_{i \in \mathcal{S}} w_i \frac{J_S[i] \cdot J_S^{\text{target}}[i]}{\|J_S[i]\| \cdot \|J_S^{\text{target}}[i]\| + \epsilon}$$

**Соотношение** `[L-gap]`. При совпадающих весах `w_i`: `𝓖_gap = 1 − 𝓑_bridge` **точно** (при усреднении по строкам без весов — ровно `1 − cos`). Направления противоположны:

| Метрика | Формула | Направление |
| --- | --- | --- |
| **gap** `𝓖_gap` | взвешенная `(1 − cos)` | **меньше = лучше** |
| **bridge** `𝓑_bridge` | взвешенное среднее `cos` | **больше = лучше** |

Исторически именовалось «L_bridge / мост» для обеих величин — вызывало путаницу; теперь имена фиксированы. В JSON: ключи `gap` (E-1…E-15) и `bridge` (E-16a/b) — направление однозначно.

**Диапазон.** `𝓖_gap ∈ [0, 2]` (поскольку `𝓖_gap = 1 − cos`): `0` — полное совпадение направлений, `2` — анти-выравнивание, `≈ 1` — уровень нуля (ортогональность случайных векторов в высокоразмерном пространстве). Меньше = лучшее выравнивание (`gap = 0` ⇔ Якобианы коллинеарны). Наблюдаемые `gap ≈ 1.00–1.03` на ранних слоях интерпретируются как отсутствие выравнивания (стохастическая независимость), а не «структурный конфликт».

**Sentinel-режимы** (определены один раз; все последующие упоминания — «см. §7»):

- **(i) sentinel** — все строки маскированы (gap = 1.00). Это **не реальное значение**: `prism/bridge.py:31` возвращает 1.0, когда маска пуста. В таблицах маркируется «1.000 (sentinel)».
- **(ii) partial mask** — часть строк жива, доля отчитывается полем `masked_fraction`.
- **(iii) baseline ≈ 1.00** — все строки живы, но выравнивание отсутствует (уровень ортогональности, не артефакт маски).

**Относительный порог.** Если `‖J_S[i]‖ < τ_l` **или** `‖J_S^{\text{target}}[i]‖ < τ_l` — строка `i` получает статус sentinel и исключается из суммы (реализация: `_valid_mask`, `prism/bridge.py:84` — маска по обеим нормам); доля sentinel-строк отчитывается отдельно. Порог задаётся **относительным** квантилем слоя, чтобы избежать систематического смещения (масштабы `J` различаются на порядки между слоями):

$$\tau_l = 0.01 \cdot \mathrm{median}_i \left( \|J_S[i]\| \right)$$

(Исторически использовался абсолютный `τ = 10^-6`; при sentinel-доле > 0 результаты маркируются, а не молча маскируются.)

**Масштабная слепота.** Так как Gap — это `(1 − cos)`, он слеп к абсолютному масштабу `J_S` (калибровке уверенности). Для предотвращения геометрической слепоты оптимизации к калибровке Gap отчитывается совместно с метрикой масштаба:

$$s(l) = \log \frac{\|J_S\|_F}{\|J_S^{\text{target}}\|_F}$$

`s(l) ≈ 0` — масштабы совпадают; `s(l) ≫ 0` — младшая модель систематически «громче» старшей по чувствительности (и наоборот).

## 8. Gauge-оператор и производные блоков

**Определение (gauge-оператор).** `P(p) = diag(p) − pp^T`, где `p = p_𝒮` — softmax, урезанный и ренормализованный на `𝒮` (§4). `P` симметричен, полуопределённо положителен (`x^T P x = Var_p[x] ≥ 0`), `ker P = span{1}`, rank = `K−1`.

**Лемма** `[L-gauge]`. `P` **не идемпотентен ни при каком** `p` (даже при `p = uniform`: `P = (1/K) I − (1/K²) 1 1^T` и `P² = (1/K) P ≠ P` при `K > 1`) — это **не проектор**, а якобиан softmax (gauge-оператор). Оператор корректно определён на классах эквивалентности `J ~ J + 1 w^T` и инъективен на них (`P J = 0 ⇒ J = 1 c^T ~ 0`). Gauge-free Якобиан `J^(p) = P J` инвариантен к uniform shift логитов: сдвиг `z → z + c·1` добавляет к `J` строку, пропорциональную `1^T`, а `P 1 = p − p(p^T 1) = 0`.

Утечка на усечённом носителе: `O(p(𝒮)(1 − p(𝒮)))`, где `p(𝒮) = Σ_{j∈𝒮} p_j` — доля массы, приходящаяся на носитель (независимый равномерный сдвиг `1_𝒮` обнуляется точно).

**Тождество** `[L-fisher]` (см. §6): `P = ∂ softmax/∂ z`, `J^(p) = ∂p/∂h`, `J^T P J` — информация Фишера.

**Gauge-направление.** `v_g ∈ R^{D_S}` — правый сингулярный вектор `J_S`, чей левый сингулярный вектор `u_g` максимизирует `|cos(u_g, 1)|` (`1 ∈ R^K` — единичный вектор в токен-пространстве). `v_g` отвечает за mode-shift (сдвиг всех логитов одновременно); направления, ортогональные `v_g`, несут token-discriminating информацию. Gauge-коррекция в `J^(p)` убирает именно `v_g`, оставляя информативные направления для моста.

**`g_uni` (raw gauge-share).** `g_uni = ‖Q J‖_F² / ‖J‖_F²`, где `Q = u u^T`, `u = 1/√K` — доля энергии **сырого** `J`, **убиваемая** проекцией (uniform-компонента). Отличается от ESG-gauge_share (§6): та — доля энергии уже gauge-free `J^(p)` на `u_1`.

**Производная RMSNorm** `[L-rms]`. Для `y = RMSNorm(x)`, `r = √(⟨x,x⟩/D)`, `û = x/‖x‖₂` (`‖û‖ = 1`), `g = 1 + w` (вектор веса):

$$\frac{\partial y}{\partial x} = \frac{1}{r}\, \mathrm{diag}(g)\, \left(I - \hat u \hat u^T\right)$$

(порядок множителей важен: `diag(g)` — слева; при `g = 1` матрица симметрична, при `g ≠ 1` — нет). Свойства: `û` — нулевой собственный вектор (`M û = (1/r) diag(g)(û − û) = 0`), матрица ранга `≤ D−1`, **неортогональна**. Каждый RMSNorm — множитель ранга `D−1`, поэтому произведение `∏ D_i` вырождено (`det = 0`), и **полная** сумма показателей Ляпунова равна `−∞`; FTLE определяется **только для top-m** сингулярных значений. При вычислении FTLE в сумму top-m показателей входит вклад `log(1/r)` на каждом RMSNorm (см. Math.md §3: QR-алгоритм, лог-аккумуляция, оговорки `n = 24–32`): это дрейф масштаба от нормировки, а не хаотичность.

# Часть III. Метод

## 9. Вычисление Якобиана

> **КРИТИЧНО:** Кэш должен содержать состояние **ДО** последнего токена, а не после. Два отдельных прохода.

```python
import copy

def compute_jacobian_for_tokens(
    model,
    layer_idx: int,
    input_ids: torch.Tensor,       # [1, S]
    attention_mask: torch.Tensor,   # [1, S]
    token_set: list[int],           # глобальный набор U
) -> torch.Tensor:
    """
    Вычисляет Якобиан логитов по скрытому состоянию слоя layer_idx
    для последнего токена, только для токенов из token_set.
    
    Возвращает: J [len(token_set), D] — Якобиан (ненормализованный)
    """
    model.eval()
    S = input_ids.shape[1]
    
    # ============================================================
    # ПРОХОД 1: Префикс (все токены кроме последнего) → кэш
    # ============================================================
    with torch.no_grad():
        prefix_outputs = model(
            input_ids=input_ids[:, :-1],
            attention_mask=attention_mask[:, :-1],
            use_cache=True,
            output_hidden_states=False,
        )
    prefix_cache = prefix_outputs.past_key_values
    
    # ============================================================
    # ПРОХОД 2: Полная последовательность → скрытые состояния
    # ============================================================
    with torch.no_grad():
        full_outputs = model(
            input_ids=input_ids,
            attention_mask=attention_mask,
            output_hidden_states=True,
            use_cache=False,
        )
    
    # Извлекаем скрытое состояние последнего токена на слое layer_idx
    # hidden_states[0] = эмбединги, hidden_states[l+1] = выход слоя l
    h = full_outputs.hidden_states[layer_idx + 1][:, -1:, :]  # [1, 1, D]
    h = h.float().detach().requires_grad_(True)
    
    # ============================================================
    # ПРОХОД 3: Прогон h через оставшиеся слои с кэшем ПРЕФИКСА
    # ============================================================
    # Клонируем кэш, чтобы не испортить оригинал
    cache_clone = _deep_clone_cache(prefix_cache)
    
    remaining_layers = model.model.layers[layer_idx + 1:]
    norm_layer = model.model.norm
    lm_head = model.lm_head
    
    # Qwen3.5: MRoPE с 4 компонентами (text, temporal, height, width);
    # для текстового входа все 4 одинаковы. При seq_len=1 с кэшем
    # позиция последнего токена = S - 1 (0-indexed).
    position_ids = torch.full((4, 1, 1), S - 1, dtype=torch.long, device=input_ids.device)  # [4, 1, 1]
    text_position_ids = position_ids[0]  # [1, 1]
    position_embeddings = model.model.rotary_emb(h, position_ids[1:])
    
    x = h  # [1, 1, D]
    for i, layer in enumerate(remaining_layers):
        actual_layer_idx = layer_idx + 1 + i
        # При seq_len=1 с кэшем маска НЕ НУЖНА: один токен attend-ит
        # на все кэшированные KV; GDN-рекуррентное состояние уже
        # содержит контекст.
        layer_output = layer(
            x,
            position_embeddings=position_embeddings,
            attention_mask=None,
            position_ids=text_position_ids,
            past_key_values=cache_clone,
        )
        x = layer_output
    
    x = norm_layer(x)
    logits = lm_head(x[:, -1, :])  # [1, V]
    
    # ============================================================
    # Вычисление градиентов для токенов из token_set
    # ============================================================
    logits_subset = logits[0, token_set]  # [|𝒮|]
    # Цикл по token_set: один backward на токен (надёжно)
    J = torch.zeros(len(token_set), h.shape[-1], device=h.device)
    for i in range(len(token_set)):
        grad = torch.autograd.grad(
            outputs=logits_subset[i],
            inputs=h,
            retain_graph=(i < len(token_set) - 1),
        )[0]  # [1, 1, D]
        J[i] = grad[0, 0, :]  # [D]
    
    return J  # [|𝒮|, D], ненормализованный
```

> **Примечание по производительности.** Цикл по $|𝒮|$ с `autograd.grad` — медленно. Для ускорения использовать `torch.func.jacrev` (PyTorch 2.1+) или `torch.func.vmap`. Валидация корректности завершена (E-1). Оптимизация — future work.

**GDN cache cloning.** `copy.deepcopy(prefix_cache)` не работает для GDN-слоёв — `recurrent_state` и `conv_state` мутируют in-place через `cache_params.update_recurrent_state(...)` и `torch_causal_conv1d_update`. Решение: `_deep_clone_cache()` — ручной клон всех тензоров в кэше (листинг — Приложение C). Внедрено (`prism/jacobian.py`).

> **⚠️ ЗАМЕЧАНИЕ ПО ПАМЯТИ.** Для длинных последовательностей это ~1–2 GB. Если не хватает памяти — уменьшить $S$ до 512.

**Ключевые свойства.** (1) Глубинный доступ к `h_l` через `hidden_states[layer_idx + 1]` (проход 2) без изменения модели. (2) KV cache делает forward $O(S \cdot D)$, а backward — $O(D^2)$ на слой (без re-forward по $S$). (3) В цикле по `token_set` — `retain_graph=(i < len(token_set) − 1)`: граф держится на всех итерациях, кроме последней, и освобождается после. (4) `position_ids = S−1` для последнего токена при использовании KV cache (MRoPE).

## 10. Jacobian bridge

Полный алгоритм (§4, §5, §7, §8) — листинг `jacobian_bridge` (с Грамиан-коррекцией `pinv(E_S^T E_S)` и sentinel-маской) — Приложение C.

**Свойство (identity).** При $M_S = M_L$, $E_S = E_L$: $J_L \cdot E^T \cdot E \cdot \mathrm{pinv}(E^T E) = J_L$ (в пределах pinv-условия, [L-gram]), $J_L \approx J_S$ (детерминизм), $\mathcal{G}_{\text{gap}} \approx 0$ ([L-dim] + [L-gram]). Это — базовая самопроверка корректности всей цепочки (E-1: gap ≈ 10⁻⁸ на всех 24 слоях).

## 11. Диагностика P0 и ESG P1

**P0 (карта расхождения).** Для всех пар слоёв $(l_L, l_S)$: вычислить $\mathcal{G}_{\text{gap}}(l)$, $\mathcal{B}_{\text{bridge}}(l)$. Выход: монотонная карта по глубине (E-2, E-6, E-13, E-15). Направления: `gap` — меньше = лучше, `bridge` — больше = лучше (§7).

**P1 (карта чувствительности для квантования).** Для каждого слоя $l$:

1. $J_S(l)$ — Якобиан, §9.
2. **Защита** (hidden space): правые сингулярные векторы $J_S^T J_S$ — направления в $h$, наиболее чувствительные к изменениям.
3. **Эксплойт** (token space): собственные векторы ESG $\bar{G}_l = JJ^T$.

**ESG-вычисление.** $N$ калибровочных сэмплов, по одному $J^{(i)}$ на сэмпл; **sample-local** (E-0.1: пул по домену невалиден — Якобианы разных сэмплов почти ортогональны):

$$\bar{G}_l = \frac{1}{N} \sum_i J^{(i)} (J^{(i)})^T \quad (\text{усреднение по сэмплам, не пул})$$

Спектральное разложение — стандартное (матрица симметричная, $K \times K$). Метрики: SNR, PR, gauge share — §6.

**Связь с P2/P3 (гипотезы, не валидированы).** Если P2 (трансформация младшей модели) реализовано, лосс: $\mathcal{L}_{p2} = \sum_l \alpha_l \cdot \mathcal{G}_{\text{gap}}(l)$. Если P3 (регуляризатор), лосс: $\mathcal{L}_{p3} = \sum_l \beta_l \, \|J_S(l) - J_S^{\text{target}}(l)\|_F^2$. Коэффициенты $\alpha_l, \beta_l$ подбираются вручную. Статус: H4 (P2) — отложено, не проверяется в v1.

# Часть IV. Инфраструктура

## 12. Данные, 𝒮 (глобальный токен-сет), layer mapping, загрузка

**Калибровочные данные.** C4 (`allenai/c4`, `en`, `train`, streaming): токенизация `max_length=64`, отбор сэмплов ≥64 токенов. В дизайне §2.1 (v1) предполагалось S=2048/512, N=32; в tested-протоколах: **S=64, N=1–4** (ограничения CPU). Для полных экспериментов рекомендуем N ≥ 4, S ≥ 256. Доменные эксперименты (E-0.1, E-13, E-27): 4 домена — wiki (C4), math (GSM8K), code (apex-agents), chat (ultrachat).

**Глобальный набор токенов $\mathcal{S}$ (support).** Токены отбираются **заранее** по частоте: union top-`K_max` токенов по калибровочному набору (старшая модель). Это гарантирует, что строки Якобианов выровнены по одним и тем же токенам на всех сэмплах. Фактический размер `K = |𝒮|` (перекрытия top-`K_max` высоки; типовым случаем является `K = K_max`).

> **Рекомендация (E-10c):** top-K покрытие нестабильно (min coverage 0.86 при K=256, 0.66 при K=32). Для стабильности — top-p саппорт (токены с совокупной вероятностью ≥ p, напр. p=0.99).

**Сопоставление слоёв (v1 — равномерное).**

```python
def uniform_layer_mapping(n_layers_large, n_layers_small):
    mapping = {}
    for i in range(n_layers_large):
        j = round(i * (n_layers_small - 1) / (n_layers_large - 1))
        mapping[i] = j
    return mapping
```

E-15 проверяет фазовую робастность: 4 схемы якорей (full/full±1/full−2) дают идентичные кривые (Spearman 1.0 между парами, max diff 0.12).

**Загрузка моделей.** CPU, float32 обязателен (fp16 на CPU ~10× медленнее), `torch.set_num_threads(4)`, `attn_implementation="eager"` (нужны `hidden_states`). Эмбеддинги: `model.model.embed_tokens.weight` — `E_large [V, 2560]`, `E_small [V, 1024]`.

## 13. Статистический каркас

> **Статистический каркас (единый для всех экспериментов).**
> - **Bootstrap CI**: $B = 1000$ ресэмплингов (по сэмплам, не по парам), percentile-CI.
> - **Permutation tests**: $B = 1000$ перестановок, точный $p = (k+1)/(B+1)$.
> - **Относительное возмущение**: $\varepsilon_{rel} = \varepsilon / \|h_l\|$ (а не абсолютное $\varepsilon$), чтобы амплитуда возмущения была сопоставима между слоями.
> - Fixed seed, детерминированность: один seed на весь эксперимент, кластеризация не пересчитывается при бутстрепах (метки фиксированы).

**Ограничение мощности (честно).** Фактические N: E-1 N=1, E-2 N=3, E-4 N=4, E-6 N=16, E-10b/c N=8, E-0.1/27 N=8/домен (всего 32). Ключевые утверждения валидированы на N=16–32, большинство таблиц — N≤8. Доверительные интервалы не вычислены для всех таблиц, bootstrap — выборочно (E-27.6, T3: $T_{domain} = 0.0024 \pm 0.011$ на L6, CI включает 0 на всех слоях; E-27.6, T4/T7: permutation p-values). Утверждения H1–H5 — предварительные; для валидации требуются N ≥ 16–32 (см. §22).

**Bonferroni (где применялся).** В E-27.6: по слоям, $p_{\text{adj}} = \min(1, p \cdot n_{\text{layers}})$ (T4: α=0.0083). В E-13 коррекции по слоям **не применялось** — пометить при интерпретации 15 слоёв.

## 15. Фундамент поля J: kill-switch и sample-local Gramians

Эксперименты этой секции предшествуют всем остальным: их выводы (поле J когерентно вдоль сэмпла, Грамианы sample-local, доменной кластерной структуры нет) — неявные предпосылки §17–§19.

### E-0.1. Stage-0 kill-switch: длина когерентности поля Якобиана (N=8/домен, всего 32; K=64; 0.8B, слои 6/12/18/22, GPU T4)

> Мотивация — из E-12a: линейный режим (корректность первого порядка, на котором стоит вся конструкция Моста) надёжен только при ε ≤ 0.1; при ε ≥ 0.5 появляется нелинейный разрыв (средний ratio 0.98 → 0.99, max 1.07× при ε = 1.0). Если поле $J(h)$ при этом **фрактальное** — быстро осциллирует на масштабах, сопоставимых с типичным расстоянием между сэмплами домена, — то **доменно-условные Грамианы $G^d$ бессмысленны** (пул Якобианов усредняет несвязанные значения), и Мост как многоточечная метрика не может работать. E-0.1 — kill-switch: измерить длину когерентности поля $J$ и решить, продолжать или останавливаться.

**Задача.** Поле $J: \mathbb{R}^d \to \mathbb{R}^{K \times d}$ (gauge-free $J^{(p)} = (\mathrm{diag}(p) - pp^T) J$, $p$ = softmax логитов, перенормированный по глобальному токен-сету top-K=64 0.8B self-bridge) гладкое, если близкие точки дают близкие Якобианы. Метрика — коэффициент когерентности по парам:

$$C(\delta) = \mathbb{E}_{\|h - h'\| \approx \delta} \left[ \frac{\langle J(h), J(h')\rangle_F}{\|J(h)\|\,\|J(h')\|} \right]$$

(косинус по строкам в порядке ранга токенов, не по id), биннинг по $\log \delta$ (14 бинов, ≥5 пар/бин). Коэффициент когерентности — $\ell = \delta$ при $C(\delta) = 0.5$; гейт — $C(\sigma_d)$, где $\sigma_d = \|\text{std}_{i \in d}\, h_i\|_2$ (норма стандартного отклонения по размерам, по доменам). Три типа пар: **(a)** соседние позиции одного сэмпла $(S{-}2, S{-}1)$, $(S{-}1, S)$ (малые δ, ≤ $\sigma_d$); **(b)** две выборки одного домена (δ ~ $\sigma_d$); **(c)** междоменные (большие δ). Параметры: 4 домена (wiki/math/code/chat) × 8 сэмплов, max_length=64, 384 gauge-free J-вызова, 644 с на T4 (0.18 GPU-h).

| Слой | σ_d | C(σ_d) | приговор | (a) intra-sample C | (b) between-samples C |
| --- | --- | --- | --- | --- | --- |
| 6 | 1.66 | 0.33 | умеренное | 0.14–0.35 (δ 1.7–2.6) | −0.003–0.029 (δ 2.3–2.9) |
| 12 | 1.86 | 0.45 | умеренное | 0.30–0.49 (δ 1.8–2.8) | 0.011–0.023 (δ 2.7–3.0) |
| 18 | 4.78 | 0.64 | гладкое | 0.67–0.71 (δ 5.6–6.6) | 0.04–0.17 (δ 6.9–7.8) |
| 22 | 7.18 | 0.87 | гладкое | 0.85–0.93 (δ 7.5–9.1) | 0.05–0.30 (δ 9.7–11.8) |

**Результат: НЕ ФРАКТАЛЬНО.** Kill-switch не сработал (порог STOP: $C(\sigma_d) < 0.1$) ни на одном из четырёх слоёв. Поле $J$ на масштабах доменной дисперсии $\sigma_d$ когерентно, и когерентность **растёт с глубиной** (0.33 → 0.87). Линейное приближение первого порядка корректно как раз там, где работают Мост и доменные Грамианы.

**Формализм: листы.** Поле $J$ — сечение векторного расслоения $E = \mathcal{H} \times \mathbb{R}^{K \times D} \to \mathcal{H}$ над многообразием скрытых состояний. **Лист** $\mathcal{L}$ — максимальное связное подмногообразие, где когерентность выше порога $C_{\min}$: $\forall h_1, h_2 \in \mathcal{L}:\ C(J(h_1), J(h_2)) \geq C_{\min}$. **Длина когерентности** в направлении $v$: $\ell(h, v) = \sup\{ t > 0 : C(J(h), J(h + tv)) \geq C_{\min}\}$; изотропная — $\ell(h) = \inf_{v \in S^{D-1}} \ell(h, v)$. **Гипотеза анизотропии** (поле анизотропно, экспериментально подтверждена типами пар (a)/(b)): разложив $\delta = \delta_\parallel + \delta_\perp$ относительно локального тангенциального подпространства листа, $C(\delta; h) \approx f(\|\delta_\parallel\|) \cdot g(\|\delta_\perp\|)$, где $f$ убывает медленно (вдоль листа), $g$ — быстро (поперёк). Проверка: для каждой пары вычислить $\delta_\parallel, \delta_\perp$ (PCA по соседним точкам траектории) и убедиться, что $C$ коррелирует со $\|\delta_\parallel\|$ слабо, а с $\|\delta_\perp\|$ сильно.

**Ключевой побочный сигнал.** Разрыв между типами пар: (a) в пределах сэмпла $C \approx 0.14$–$0.93$, а (b) между сэмплами одного домена $C \approx -0.003$–$0.30$ (обычно 0.003–0.05; пик 0.30, L22/code) — в общем случае Якобианы разных сэмплов домена почти ортогональны, хотя их hidden states лежат в пределах $\sigma_d$. Поле $J$ когерентно **вдоль последовательности** (позиции), но не поперёк распределения сэмплов. Следствие для ESG: Грамианы должны строиться **sample-local** (каждый сэмпл — свой Грамиан, как это сделано в E-16/E-19), а не пулом Якобианов по домену: пул усредняет почти ортогональные $J$ и убивает сигнал.

**Оговорки.** (1) Гейт оценен на кривой, сшитой из (a)+(b); (a) даёт покрытие при δ ≤ $\sigma_d$, (b) — диапазон δ ~ $\sigma_d$. $\ell$ (перекрытие $C=0.5$) формально не существует для чистых (b)-кривых ($C \le 0.3$ во всём диапазоне), т.е. поперёк распределения сэмплов когерентность ниже 0.5 уже на масштабе $\sigma_d$ — это не стоп, а количественная граница допустимой пулляции. (2) N=8/домен, доверительные интервалы не вычислялись (см. §21, п. 5). (3) Self-bridge 0.8B: 4B не загружается, токен-сет — из 0.8B (отклонение от параметрической таблицы, зафиксировано в PLAN).

**Практический итог:** Мост как многоточечная метрика допустим; пул Якобианов по доменам — нет (sample-local только).

### E-27.5/27.6. Значимость, кластеры и изоляция доменов поля J (Exp 27, N=8/домен, всего 32; K=128; 0.8B, слои 6/12/18/19/22/23, GPU T4)

E-0.1 показал, что Грамианы sample-local: вдоль сэмпла (соседние позиции) $C \approx 0.14$–$0.93$, а поперёк сэмплов (разные сэмплы домена) $C \approx -0.003$–$0.30$ (обычно 0.003–0.05) — почти ортогонально. Оставались три вопроса: (1) статистически ли значима когерентность $C_a$ относительно null-моделей, (2) существует ли в кросс-сэмпловом спектре кластерная структура (в т.ч. доменная), (3) каков честный шумовой пол $F$ вместо $1/\sqrt{D}$.

**Локальные определения.** $C_a = \mathrm{mean}\ \cos(J^{(p_1)}_{t1}, J^{(p_2)}_{t2})$ по position-парам одного образца; $C_b = \mathrm{mean}\ \cos$ по sample-парам одного домена (pos 0); $T_{domain} = C_{within} - C_{cross}$ ($C_{within}$ = 112 пар в доменах, $C_{cross}$ = 384 междоменных, N=32 = 4×8). $r_{eff}$ — энтропический ранг: $r_{eff} = \exp(-\sum p_k \log p_k)$, $p_k = \sigma_k^2/\sum\sigma^2$. Шумовой пол: $F = 1/\sqrt{r_{eff}\,(K + D - r_{eff})}$; вердикты: $C < F$ — ORTHOGONAL, $F \le C < 3F$ — WEAK, $C \ge 3F$ — COHERENT. Конвенции пар: **pos-pk** (каноническая), **same-pk**, **raw**. T-блоки: T1 (degenerate-J exclusion), T2 (Bock 4×4 на $K^G$), T3 (bootstrap CI), T4 ($T_4(L) = C_a(L) - C_b(L)$, block-permutation по доменам, Bonferroni по слоям $p_{adj} = \min(1, p_4 \cdot n_{layers})$), T5 (Hartigan dip + β-null, moment-match), T6 (eigengap $K^F$, $K^G$), T7 (ρ(layer, $C_a$) + perm-null), T8 (ковариаты: $E, r_{eff}, r_{stable}, H, g_{uni}$).

**Данные и метод.** Exp 27 (v11, 0.8B, T4): 4 домена × 8 сэмплов, $S=64$, $K=128$, pos=0, 6 слоёв {6,12,18,19,22,23} (GDN + full-attention, контроль L23 ≈ lm_head). Gauge-free $J^{(p)}$ кешируются в jcache; post-processing — только CPU. Exp 27.5 (`experiments/exp27_5_postprocess.py`): перестановочный тест доменных меток (B=1000), spectral null (хранящие собственные значения ротации, B=100), half-split, корреляции с осями (entropy quartile), agglomerative clustering на $D^G = 1 - K^G$ (silhouette, gap, $\rho_{NN}$, cophenetic). Exp 27.6 (`experiments/exp27_6_isolation.py`): P0-приложение — T1–T8. Два раунда ревью (коллега + внутренний аудит) выловили 6 P0-багов; все закрыты, финальный прогон — run12.

**Строго установленные факты** (следуют из данных без дополнительных предположений):

1. Внутридоменная когерентность Якобианов статистически неотличима от междоменной (p_perm > 0.05 на всех слоях; все bootstrap CI включают ноль).
2. Спектры матриц сходства $K^F$ и $K^G$ не содержат заметных разрывов (eigengap ratio < 1.5 для всех $i \in \{2,3,4\}$); эффективный ранг $r_{eff} \approx 24.4$–31.6 из 31.

4. Распределение попарной когерентности отвергает гипотезу унимодальности (Hartigan dip, $p < 0.05$ на всех слоях для обоих срезов $S=64$ и $S=128$).

**Интерпретации (с оценкой вероятности).**

*Высокая (>80%):*
- **Глобальная доменная геометрия отсутствует.** Все тесты (permutation, bootstrap CI, ARI-null, eigengap) согласованно показывают отсутствие сигнала. Альтернативы: эффект $N=32$ — маловероятно (CI с ростом $N$ сужаются, но остаются широкими); math-домен маскирует сигнал — отвергнуто (T1: исключение math не улучшает сигнал); **ротационная структура** (одинаковые грамианы $JJ^T$, различие — ортогональные вращения в hidden-пространстве; vec-$C$ в ней нулевой) — отвергнута фактом 5: для неё нужно $K^G_{dd} \approx 1$, наблюдаемо 0.033–0.042. Проверка: $N=64$–128, повтор T3.
- **Кластерная структура в спектральном смысле отсутствует.** Плоский спектр (факт 2) ⇒ silhouette и gap statistic измеряют шум, а не структуру. Альтернативы: структура в нелинейном многообразии (средняя вероятность — проверка UMAP/t-SNE); размытие из-за усреднения по позициям (средняя — per-position кластеризация).
- **Readout-pull имеет фундаментальный потолок** для кросс-сэмплового выравнивания: без кросс-сэмпловой когерентности (факт 1) глобальная правка $W$ не может выровнять разные «листы» траекторий. Наиболее вероятно, что readout-pull работает только внутри траекторий (согласуется с фактом 3). Проверка: ограничить readout-pull парами одной траектории (intra-sample).

*Средняя (40–80%):*
- **Бимодальность связана с внутри-/междокументным разделением.** Факт 4 (бимодальность) при отклонённой доменной оси (факт 1): естественная альтернатива — разделение на пары внутри одного документа (высокая $C$) и между разными (низкая $C$). Альтернативы: позиция в документе (средняя), синтаксические паттерны (низкая — code-домен не выделяется). Проверка: split пар на intra-/inter-document.
- **Отрицательный $\rho(C, \Delta h)$ на поздних позициях — эффект «листов».** Близкие точки в $h$-пространстве могут принадлежать разным листам: траектории расходятся. Альтернативы: масштабный эффект (низкая — косинус масштабно-инвариантен); нелинейность поля $J(h)$ (средняя — анализ вторых производных). Проверка: локальные тангенциальные подпространства, когерентность внутри/между листами.
- **Math-домен имеет специфическую структуру** (символьная запись, формулы). Альтернативы: больше шума (короткие формулы, мало контекста) — средняя; особый набор токенов — средняя. Проверка: распределение токенов, контроль на длину контекста.

*Низкая (<40%):*
- **Латентные оси кроме доменов существуют** — но ARI с доменами не значим (T4), что снижает вероятность сильных латентных осей. Проверка: unsupervised кластеризация + атрибуция (энтропия, длина, позиция).
- **Бимодальность связана с синтаксисом** — code-домен не отличается от wiki/chat, что противоречит этой гипотезе.

**Открытые вопросы (требуют экспериментов).**
1. Механизм отрицательной корреляции с $\Delta h$ (тангенциальные подпространства, вторые производные $\nabla^2 J(h)$).
2. Природа бимодальности (intra-/inter-document split, per-position, кластеризация + атрибуция).
3. Эффект размера выборки ($N=64$–128, повтор T3; если CI не сужаются — эффект реальный, но слабый).

**Итоговая формулировка.**
- *Основной вывод:* глобальная доменная геометрия Якобианов отсутствует — внутри- и междоменная когерентность неотличимы, спектр плоский, кластерная структура в спектральном смысле не обнаружена.
- *Вторичный вывод:* $C_a$ монотонно растёт с глубиной (формирование устойчивой локальной геометрии в поздних слоях); бимодальность, вероятно, отражает внутри-/междокументное разделение.
- *Практический вывод:* readout-pull ограничен для кросс-сэмплового выравнивания; рабочая парадигма — per-sample / leaf-oriented геометрия, а не глобальная доменная.
- *Ограничение:* $N=32$; увеличение выборки может выявить слабые эффекты, но основные выводы (отсутствие доменной оси, плоский спектр) устойчивы.

### E-3. Абляция inverse Gramian (N=1, K=8; 0.8B)

**Цель:** проверить необходимость Gramian-коррекции и отличить learned W от случайной ортогональной.

**Результат.**

| Коррекция | gap (layer 0) ↓ = лучше |
| --- | --- |
| С `pinv(E^T E)` | $1.1 \times 10^{-8}$ |
| Без (raw $E^T$) | 0.82 |
| **Случайная ортогональная R** | **1.02 ± 0.01** |

**Вывод:**
1. Inverse Gramian критичен: без него loss 0.82 vs $10^{-8}$ — разница в 10⁷×.
2. Learned bridge matrix ≠ случайная ортогональная матрица: random orthogonal R даёт loss ≈ 1.02 (уровень ортогональности, т.е. выравнивание отсутствует; максимум диапазона gap $[0,2]$ равен 2 — анти-выравнивание), тогда как learned W даёт loss ≈ 0. Это strong evidence, что W выполняет конкретную работу по выравниванию подпространств, а не просто вращает.
3. Три режима: corrected (≈0) < raw (0.82) < random R (1.02). Порядок подтверждает, что Gramian correction убирает bias, а learned W убирает rotation.

### E-5. Перестановка эмбеддингов (N=2, K=8; 0.8B)

где $U_1, U_2 \in \mathbb{R}^{V \times r}$ — ортонормированные базисы подпространств ESG (по собственным векторам $JJ^T$ с наибольшими eigenvalues), $r = 8$. Значение в $[0, 1]$: 0 — ортогональны, 1 — совпадают.

- Cross-overlap L0: 0.30–0.42 — в ранних слоях чувствительные подпространства **доменно-специфичны**.

### E-11a. Fidelity реконструкции через defrag (N=4; 0.8B, слои 6/12/18, K=32)

**Цель:** проверить, мал ли эффективный ранг $J^{(p)}$ (гипотеза дефрагментации, §11).

Метод: возмущаем $h_l$ на $\pm\varepsilon \cdot v$ (gauge / semantic / random направления, $\varepsilon \in \{0.5, 1.0, 2.0\}$), мерим KL($p_{\text{true}} \| p_{\text{pred}}$) для трёх предикторов:

- **Raw:** $z_{\text{pert}} = z_0 + J \cdot \delta$ (только по token_set)
- **Gauge-free:** $p_{\text{pert}} = \text{softmax}(\log p_0 + J^{(p)} \cdot \delta)$ на token_set
- **Defrag-r:** $p_{\text{pert}} = \text{softmax}(\log p_0 + U_r J_r \cdot \delta)$, $r \in \{4, 8, 16, 32\}$

| Perturbation | Scale | KL(raw) | KL(gf) | KL(dr4) | KL(dr8) | KL(dr32) |
| --- | --- | --- | --- | --- | --- | --- |
| gauge (L6) | 1.0 | 13.43 | 10.47 | 10.47 | 10.47 | 10.47 |
| sem_0 (L6) | 1.0 | ~13.5 | ~10.6 | ~10.6 | ~10.6 | ~10.6 |

**Выводы:**

1. **Gauge-free значительно лучше raw** (10.5 vs 13.4) — softmax-weighting убирает gauge-артефакты из линейной аппроксимации.
2. **Defrag сходится при $r=4$** — KL(dr4) = KL(dr8) = KL(dr32) = KL(gf). Эффективный ранг $J^{(p)}$ действительно мал.
3. **Но KL(gf) всё ещё ~10.5** — линейная аппроксимация ломается при $\varepsilon=1.0$. Нелинейности оставшихся слоёв доминируют. Это не баг реконструкции, это предел первого порядка.

### E-12a. Пертурбационный тест: gauge vs differential (N=8, K=64; 0.8B, слои 6/12/18)

> **Params:** текущий прогон: N=8, K=64 (`results/exp12a_perturbation_test.json` → `params`). Дефолт скрипта `experiments/exp12a_perturbation_test.py` (N=4, K=64) не синхронизирован с прогоном — следующий GPU-ран перезапишет значения.

Для каждого слоя находим:

- $v_g$ = правый сингулярный вектор $J$, чей левый вектор ≈ равномерен (gauge direction)
- $v_d$ = топ-правый сингулярный вектор $J^{(p)}$ (дифференциальное направление)

Возмущаем $h_l \leftarrow h_l \pm \varepsilon \cdot v$ при одинаковой норме $\|v\|=1$, $\varepsilon=1.0$. Мерим KL($p_{\text{orig}} \| p_{\text{pert}}$).

| Слой | uniformity($u_g$) | KL$_g$ (avg ± std) | KL$_d$ (avg ± std) | ratio KL$_d$/KL$_g$ |
| --- | --- | --- | --- | --- |
| 6 | 0.92 | 7.04 ± 0.37 | 7.55 ± 0.58 | 1.07× |
| 12 | 0.94 | 7.46 ± 0.47 | 7.80 ± 0.51 | 1.05× |
| 18 | 0.97 | 6.42 ± 0.97 | 6.69 ± 0.94 | 1.04× |

($u_g$ — левый сингулярный вектор в token-пространстве; $v_g$ живёт в hidden-пространстве, uniformity определён только для $u_g$.)

**Результат ε-sweep:**
1. **Линейный режим (ε ≤ 0.1):** KL_g = KL_d (ratio = 1.00×). Gauge и differential направления неразличимы — в первом порядке оба дают одинаковый KL.
2. **Нелинейный переход (ε = 0.5–1.0):** Появляется слабый разрыв (max ratio = 1.07×, L6, ε=1.0): KL_g(L6) 7.34 → 7.04, KL_d(L6) 7.52 → 7.55; на L18 gap остаётся малым (1.01× → 1.04×).
3. **Интерпретация:** Модель не игнорирует gauge-направление (KL_g не меньше KL_d). Gauge «просачивается» через нелинейности decoder. Разрыв при ε=1.0 — не gauge-инвариантность, а нелинейное затухание gauge-сигнала.

**Что подтверждено:** uniformity левого сингулярного вектора $u_g$ = 0.92–0.97 на слоях 6–18 — gauge direction существует и имеет равномерную структуру. **Структурное разделение** работает; **функциональная разделимость** при полном forward — нет. (Последующий E-0.1, §15, исключил альтернативное объяснение нелинейного перехода — фрактальности поля $J$: на масштабах $\sigma_d$ поле когерентно, первый порядок корректен.)

> **Рефрейм:** map — **направление минимальной чувствительности**. При равном destruktive budget (KL≈15) map-квантование даёт меньшее возмущение hidden space (Δh 0.24–0.84 vs 0.95–3.34), чем uniform — но **оба варианта разрушают модель полностью** (PPL 10⁶–10⁸). Это не «map сохраняет модель», а «map направляет разрушение эффективнее» (см. E-12b).

### E-12b. Квантование по карте (N=4, K=32; 0.8B, слои 6/12/18)

> **Params:** таблица — из сохранённого JSON (N=4, K=32). Скрипт уже обновлён до K=64; следующий run перезапишет значения.

Симуляция направленного квантования $h_l$:

- **Map-based:** gauge (2 бита) + 5 дифференциальных направлений (8 бит) + остальные (6 бит). Число 5 согласовано с E-11a: эффективный ранг $J^{(p)}$ мал (defrag сходится уже при $r=4$), PR(L6) ≈ 5.9 — то есть «5 направлений» — это спектральный ранг, а не фиксированная конвентация.
- **Uniform:** 4 бита на всё

| Слой | KL(map) | KL(uniform) | $\Delta h_{\text{map}}$ | $\Delta h_{\text{uniform}}$ | PPL(map) | PPL(uniform) |
| --- | --- | --- | --- | --- | --- | --- |
| 6 | 14.91 | 15.00 | 0.24 | 0.95 | 1.25M | 2.47M |
| 12 | 15.09 | 15.09 | 0.26 | 1.00 | 14.8M | 50.8M |
| 18 | 15.02 | 15.01 | 0.84 | 3.34 | 1.69M | 2.14M |

> **PPL note:** Значения PPL ~1.25M-50.8M соответствуют exp(15) ~ 3.3e6. Это ожидаемо: KL ~15 означает полное разрушение распределения (random perturbation), а не реальное квантование. Симуляция проверяет *направление* dH, не абсолютный PPL.

**Вывод:** KL одинаков (оба ~15), но map-based достигает этого при $\Delta h \approx 0.24$ vs uniform $\Delta h \approx 0.95$. Map-based квантование создаёт в 4× меньшее возмущение в hidden space при том же KL.

> **Оговорка:** оба варианта непригодны (PPL 10⁶–10⁸, полное разрушение распределения). Меньший Δh не означает «лучше сохраняет модель» — карта лишь эффективнее направляет разрушение в чувствительные направления. Это предельный тест, не практическое применение.

### E-12c. Мост оригинал ↔ квантованная (N=4, K=32; 0.8B, слои 6/12/18)

> **Params:** таблица — из сохранённого JSON (N=4, K=32); скрипт `experiments/exp12c_bridge_quantized.py` на K=64.

Softmax-мост между оригиналом и каждой схемой квантования (cosine similarity градиентов):

| Слой | $\mathcal{L}$(orig ↔ map) | $\mathcal{L}$(orig ↔ uniform) | $\mathcal{L}$(map ↔ uniform) |
| --- | --- | --- | --- |
| 6 | 0.001 | 0.020 | 0.021 |
| 12 | 0.001 | 0.015 | 0.016 |
| 18 | 0.001 | 0.014 | 0.015 |

**Вывод:**

1. **Map-based ≈ идентичен оригиналу по НАПРАВЛЕНИЮ ЯКОБИАНА** — мост 0.001 (почти ноль). *Оговорка: это направление градиента, не функция — по E-12b обе схемы полностью разрушают PPL (10⁶–10⁸); map лишь 15–20× меньше искажает Jacobian-направление.*
2. **Uniform далеко** — мост 0.014–0.020, в 15–20× больше.
3. **Мост map↔uniform ≈ мост orig↔uniform** — равномерное квантование повреждает те же направления, что отличают map от оригинала.

**Механистическая интерпретация:** Uniform квантование шумит в gauge-направлении (где нужно 8 бит защиты) и в дифференциальных направлениях (где 4 бита достаточно). Map-based ставит 8 бит туда, где они нужны, и экономит на gauge. Результат: тот же KL, но в 4× меньше возмущение и мост ≈ 0.

## 19. Causal lever и поведение

**Главный вывод (наверх секции).** Геометрический bridge и поведенческая top-p retention **антикоррелированы**: readout-редакция монотонно «улучшает» мост (0.60→0.921), одновременно разрушая поведение. Точечных якобианов недостаточно — оптимизация по одной точке = Goodhart на геометрическом прокси.

### E-16a. Readout-pull как доза-ответ (0.8B → target, пара 31_23; Exp 16 v2)

> **Params:** lm_head-only edit (readout), loss = (1−cos(J_S_p, J_tgt_p)) + 0.1·KL(leash), Adam lr=1e-3, 100 steps, eval every 10, K=256, N=4 (paired by input_ids), device=cuda. GPU T4, 126s.

Доза = ‖ΔW‖_F (Frobenius norm readout-редакции); bridge = cosine readout (exp16-метрика, ≠ exp19 per-token), KL = leash-метрика (full-vocab, base vs edited). База при ΔW=0: **bridge=0.599965** (= exp19 baseline — совпадает), KL=0.

| step | dose ‖ΔW‖ | bridge (cos) | KL (leash) |
|---|---|---|---|
| 0 | 0.0 | 0.599965 | 0.0 |
| 10 | 61.8 | 0.6173 | 0.4808 |
| 20 | 77.4 | 0.6460 | 0.5970 |
| 40 | 91.6 | 0.6843 | 0.3627 |
| 60 | 98.6 | 0.7137 | 0.2836 |
| 80 | 100.2 | 0.7359 | 0.2608 |
| 100 | 100.7 | **0.7543** | 0.2403 |

**Вывод:** readout-редакция (lm_head-only) — **causal lever**: bridge монотонно растёт 0.60→0.754 (т.е. мост к target-подпространству **улучшается**), при этом KL leash держит (0→0.24, damage bounded). **α\* = 0.3207 при step 100** — к моменту 100 шагов колено (knee, перестановка bridge gain ниже knee_tol=0.001) **не достигнуто**: bridge продолжает расти. Т.е. readout-редакция — самое дешёвое управление (1 матрица ‖W‖≈314, не вся сеть), и она движет мост в сторону target с ограниченным collateral (KL). **V4 (1000 шагов)** — continuation этого прогона, bridge достигает **0.921** (‖ΔW‖=128.8); см. E-16b (поведенческая проверка). V1 (alpha sweep как trust-region caps) **VOID** — caps ≥0.1 не bind, α не был дозой (его 'α*=0.01' = артефакт первого slope); v2 чинит определение дозы. **Оговорка:** exp16 (analytical last-layer readout, bridge 0.60→0.754) и exp19 (per-token full-path, baseline 0.600) — **разные величины bridge**, напрямую несравнимы (structural, не bug).

### E-16b. Поведенческая проверка LORA: top-p retention (Exp 16 v4)

> **Params:** финальный ΔW из exp16 v4 (‖ΔW‖_F=128.8, ‖W‖≈314, bridge@end=0.921) накладывается на lm_head 0.8B; поведение измеряется на **held-out** запросах (≠ training queries) тремя путями — base 0.8B / 0.8B+LORA / 4B-учитель. Метрика — **top-p retention** (p=0.9): доля массы вероятностей модели, попадающая в top-p регион учителя (top-p set = минимальный префикс, покрывающий 0.9 массы). Т.к. топ-k (top-10) — хрупкий индикатор (малейший шов двигает конкретный член), оценка построена на top-p retention как на робастной массовой метрике.

**Single-edit (s=1, чистые held-out вопросы, n=6):**

| Метрика (vs 4B-учитель) | base 0.8B | 0.8B + LORA |
| --- | --- | --- |
| Масса модели в top-p(0.9) регионе учителя | **0.841** | **0.016** |
| Масса учителя в top-p(0.9) регионе модели | **0.888** | **0.173** |

**Доза-ответ top-p retention (s ∈ {0.1, 0.25, 0.5, 0.75, 1.0}, C4-heldout, n=6):**

| s (доля ΔW) | top-p retention | bridge (exp16-metric) |
| --- | --- | --- |
| 0 (base) | **0.837** | 0.603 |
| 0.10 | 0.809 | (растёт) |
| 0.25 | 0.746 | ↑ |
| 0.50 | 0.666 | ↑ |
| 0.75 | 0.523 | ↑ |
| 1.00 | **0.416** | **0.921** |

(Метрики top-k: agreement k=10: 0.733→0.067; garbage k=10 (вне top-200 учителя): 0→0.450 — оба монотонны.)

**Вывод.** LORA exp16 **не улучшает** поведение, а **ломает** его. Уже при **s=0.1** (10% финального edit) top-p retention падает 0.837→0.809; при полном edit — до 0.016 (чистые вопросы) / 0.416 (C4), т.е. модель выводится **с manifold** (масса уходит в нереалистичные для учителя токены). Критично: это происходит **одновременно** с **монотонным ростом bridge** (0.603→0.921) вдоль той же траектории. Т.е. **геометрический bridge и поведенческая top-p retention антикоррелированы**: мост «улучшается», поведение деградирует.

**Почему (механизм Goodharta).** Эксперимент 16 тянет **одну точку** (один last-layer hidden state → одно направление ΔJ, одна метрика bridge по одной паре слоёв). Оказалось, что такую точку можно «подогнать» (bridge 0.60→0.92) **без улучшения — а с разрушением** реального поведения. Точечный якобиан не несёт ограничения на **остальные** точки/домены, поэтому оптимизация по нему = **Goodhart на геометрическом прокси**: метрика растёт, качество гниёт. Чтобы это исправить, метрика/ограничение должны быть **многоточечными**: не точка, а **гиперповерхность из якобианов по доменам** (и по глубине), т.е. нельзя подогнать одну точку, не сломав другие. Это направление — следующая работа (после exp16/exp19).

### Практические следствия

1. **Карта $J^{(p)}$ работает для направленного квантования** (E-12b,c): map-based при 4× меньшем Δh даёт тот же KL, мост ≈ 0. Оба варианта непригодны как реальные схемы (PPL 10⁶–10⁸).
2. **Defrag экономит backward** (E-11b), но для bridge-моста нужен полный ранг (E-11c) — defrag и мост решают разные задачи.
3. **Gauge-direction реален и поведенчески активен** (E-12a): нелинейности decoder пропускают gauge-сигнал; он «невидим» только в линейном приближении.
4. **Мост не заменяет KL, но дополняет его:** KL — один номер, мост — послойная карта расхождения.
5. **Рабочая парадигма — per-sample / leaf-oriented геометрия** (E-0.1, E-27.5/27.6), а не глобальная доменная: Грамианы sample-local, доменная ось — шум.

### Что это значит для читателя

Мост — рабочая послойная метрика выравнивания: она монотонна, доменно-робастна, не артефакт фазы архитектуры, и её можно двигать readout-редакцией. Но (1) метрика чувствительна к полным Якобианам — defrag её ломает; (2) «улучшение» моста в одной точке не улучшает поведение — E-16b показывает Goodhart на геометрическом прокси; (3) все количественные оценки предварительны (N ≤ 32, без CI) — см. §21.

## 21. Ограничения

Свод всех ограничений v3.3 (§6 «Известные ограничения», оговорки §11, оговорки §13.1). Сгруппированы: (a) методологические, (b) статистические, (c) инфраструктурные. Дубли убраны.

### (a) Методологические

1. **Локальность Якобиана.** Якобиан — касательная в конкретной точке. Агрегация по $N$ сэмплам частично решает проблему, но не полностью. **E-0.1 уточняет границу:** поле $J$ когерентно вдоль последовательности ($C(\sigma_d) = 0.33$–$0.87$ по глубине) и не когерентно поперёк распределения сэмплов ($C \approx -0.003$–$0.30$, обычно 0.003–0.05) — Грамианы строятся sample-local, без пулляции по домену.
2. **Неортогональность $E$.** Матрица эмбедингов не ортогональна. Проекция $J \cdot E^T$ не изометрична. Проверяется E-8.
3. **Ранние слои.** Для $l < n/4$ градиент может затухнуть: строки с $J_S[i] = 0$ маскируются (относительный порог, §9, E-1), что порождает sentinel 1.000 (см. §17, E-6).
4. **Линейный предиктор.** При $\varepsilon \leq 0.1$ gauge и differential направления неразличимы (KL_g = KL_d, ratio = 1.00×). При $\varepsilon = 1.0$ появляется слабый разрыв (ratio = 1.07×). При $\varepsilon \geq 1$ нелинейности оставшихся слоёв доминируют (E-12a, E-11a: линейный предиктор ненадёжен в глубоких слоях). Якобиан корректен в первом порядке; для больших возмущений нужны higher-order методы.
5. **Сравнимость моста.** Абсолютная величина моста между доменами несравнима (разные распределения вероятностей); монотонность — сравнима (E-13). Trace значения при разных K не сравнимы.
6. **Goodhart на геометрическом прокси.** Точечный bridge оптимизируем без улучшения поведения (E-16b); многоточечная метрика — следующая работа.
7. **E-6 L18 SNR (вынесен из секций).** Эксперимент «Spektrum vs depth r» (N=8, K=256, слой 18: SNR = 2.803 r-инвариантен, PR 2.15→16.91, gauge share 0.602→0.199) сознательно не перенесён в секции v4.0 — его вывод (спектр L18 не low-rank) дублируется E-14 (§17) на K=64. Данные и вывод — в Приложении B.1.

### (b) Статистические

8. **Малая статистическая мощность.** N = 1–32 в зависимости от эксперимента (E-6 — N=16, E-0.1 — N=8/домен, E-27 — всего 32 = 8/домен); ключевые утверждения валидированы на N=16–32, большинство таблиц — N≤8. Доверительные интервалы не вычислены, bootstrap не применяется (кроме E-27.5/27.6). Утверждения H1–H5 — предварительные; для валидации требуются N ≥ 16–32 (см. §22).
9. **E-0.1:** N=8/домен, CI не вычислялись; гейт оценен на кривой, сшитой из (a)+(b); поперёк распределения сэмплов когерентность ниже 0.5 уже на масштабе $\sigma_d$ — количественная граница допустимой пулляции, не стоп.
10. **E-27.5/27.6:** N=32: разрешение T3 — CI ±0.011, эффекты меньше неотличимы от нуля; T5 dip на грани критического значения (маржа 1.1–1.5×) — би-модальность слабее, чем заявлено selfcheck-бимодальностью.

### (c) Инфраструктурные

13. **Точность.** Модели на CPU — float32 обязателен (fp16 на CPU в 10× медленнее; применение fp16 требует отдельной валидации); матрица $J$: $|\mathcal{S}| \times D$ (256×2560 = 655 360 float32 = 2.5 MB) — приемлемо. GPU-прогоны (E-0.1, E-10b, E-11b, E-16, E-27) — T4.
14. **Память.** `_deep_clone_cache` для $S = 2048$ может требовать 1–2 GB; при нехватке — уменьшить $S$ до 512 (в экспериментах использовано $S \le 64$).
15. **Скрипты не синхронизированы с прогонами.** В нескольких местах дефолт скрипта расходится с параметрами сохранённого JSON (E-12a: скрипт N=4/K=64, прогон N=8/K=64; E-12b: скрипт K=64, таблица K=32; E-12c: скрипт K=64, таблица K=32; E-9: скрипт K=128, прогон K=64). Полный список — Приложение B, колонка «примечания».
16. **E-16: две версии bridge-метрики.** E-16a (v2) — analytical last-layer readout, bridge = mean(1 − cos) по U, cos 0.60→0.754; E-16b (v4) — per-token full path, baseline bridge 0.600. Это две разные величины, напрямую несравнимы (structural, не bug).

# Приложение A. Глоссарий

Расширенные определения понятий с прозой. Однозначные символы — в §2 (индекс символов); здесь — понятия, у которых есть семантическая нагрузка, два смысла или которые легко спутать.

| Термин | Определение | Каноническая секция |
| --- | --- | --- |
| **gap (разрыв)** | $\mathcal{G}_{\text{gap}}(l) = \sum_{i \in \mathcal{S}} w_i\,(1 - \cos(J_S[i], J_S^{\text{target}}[i]))$ — вероятностно-взвешенное среднее $(1-\cos)$ по токенам $\mathcal{S}$, $w_i = p_L(i)/\sum_j p_L(j)$ (нормирована на $\mathcal{S}$; асимметрия осознанна — система отсчёта старшей модели). $\in [0,2]$: 0 — коллинеарны, ≈1 — уровень ортогональности. **Меньше = лучше**. Эксперименты 1–15 отчётуют gap. | §5, §7 |
| **bridge (мост)** | $\mathcal{B}_{\text{bridge}}(l) = \sum_{i \in \mathcal{S}} w_i\,\cos(J_S[i], J_S^{\text{target}}[i])$ — то же, что gap, но среднее $\cos$: $\mathcal{G}_{\text{gap}} = 1 - \mathcal{B}_{\text{bridge}}$ (при совпадающих весах). **Больше = лучше**. Эксперименты 16–19 отчётуют bridge (higher-is-better). Исторически именовалось «Л_bridge» — вызывало путаницу, в v3.3 разведены. | §5, §7 |
| **gauge-оператор** | $P(p) = \mathrm{diag}(p) - pp^T$ — якобиан softmax. **НЕ проектор**: $P^2 \ne P$ ни при каком $p$. Симметричен, полуопределённо положителен, $\ker P = \mathrm{span}\{\mathbf{1}\}$, rank $K-1$. | §8 |
| **gauge mode / uniform mode** | Направление $\mathbf{1}/\sqrt{K}$ в token-пространстве (common-mode, uniform shift). Softmax инвариантен к нему, но он несёт сигнал уверенности (E-10a, E-10d). | §8 |
| **gauge direction** | Правый сингулярный вектор $J$, чей левый вектор $u_g$ ≈ равномерен (в hidden-пространстве). Uniformity 0.92–0.97 (E-12a). | §18 |
| **gauge_share — два смысла** | (1) `gauge_share_softmax` (в v3.3 §1.5): $\sigma_1^2 \cdot \mathrm{uniformity}(u_1) / \sum_i \sigma_i^2$ — доля энергии $J^{(p)}$, приходящаяся на gauge-направление. (2) `gauge_share_raw` (v3.3 §12–13): $\|P(p)J\|_F^2/\|J\|_F^2$ — доля энергии **сырого** $J$, **оставшейся** после убийства gauge-направления; убиваемая uniform-компонента — $\|QJ\|_F^2/\|J\|_F^2$, $Q = uu^T$, $u = \mathbf{1}/\sqrt{K}$. В v3.3 одно имя для разных величин; в v4.0 имена разведены. | §8, §15 |
| **uniformity** | Степень равномерности левого сингулярного вектора $u_g$ в token-пространстве: $\|u_g - \mathbf{1}/\sqrt{K}\|$ близок к 0 ⇒ uniformity ≈ 1. Определяется только для $u_g$ (левый вектор), не для $v_g$ (hidden-пространство). | §18 (E-12a) |
| **$g_{uni}$** | Доля энергии uniform-режима: $\|Q J\|_F^2 / E$, $E = \|J\|_F^2$. После gauge-free проекции $g_{uni} \le 3\times10^{-12}$ (машинный ноль, E-27). | §15 |
| **$r_{eff}$** | Эффективный ранг Якобиана (энтропический): $r_{eff} = \exp(-\sum p_k \log p_k)$, $p_k = \sigma_k^2/\sum\sigma^2$. Вторичные: stable rank, participation ratio (PR). | §15 (локальные определения) |
| **$r_{KL}$** | **Функциональный ранг**: минимальное $r$ такое, что KL defrag-$r$ аппроксимации $J^{(p)} \approx U_r J_r$ совпадает с KL полной $J^{(p)}$ (E-11a: r ≈ 4). | **$C_a$** | Внутридокументная (intra-sample) когерентность: mean cos gauge-free Якобианов по position-парам одного образца. 0.061→0.229 по глубине (E-27.6). | §15 |

| **$T_{domain}$** | $C_{within} - C_{cross}$ — доменная когерентность (внутри- минус междоменная). В шумовом поле (E-27.6 T1/T3). | §15 |

| H3 | E-проекция $E_L^T E_S$ — нетривиальное выравнивание (≠ случайное; опирается на семантику эмбеддингов, а не только на размерности) | ✅ Подтверждена | E-3 (режим random R), E-5 | Loss 1.02 vs 0.0 (random R); перестановка эмбеддингов ломает мост |

## C.1. Вычисление Якобиана (из §9)

```python
import copy

def compute_jacobian_for_tokens(
    model,
    layer_idx: int,
    input_ids: torch.Tensor,       # [1, S]
    attention_mask: torch.Tensor,   # [1, S]
    token_set: list[int],           # глобальный набор U
) -> torch.Tensor:
    """
    Вычисляет Якобиан логитов по скрытому состоянию слоя layer_idx
    для последнего токена, только для токенов из token_set.
    
    Возвращает: J [len(token_set), D] — Якобиан (ненормализованный)
    """
    model.eval()
    S = input_ids.shape[1]
    
    # ============================================================
    # ПРОХОД 1: Префикс (все токены кроме последнего) → кэш
    # ============================================================
    with torch.no_grad():
        prefix_outputs = model(
            input_ids=input_ids[:, :-1],
            attention_mask=attention_mask[:, :-1],
            use_cache=True,
            output_hidden_states=False,
        )
    prefix_cache = prefix_outputs.past_key_values
    
    # ============================================================
    # ПРОХОД 2: Полная последовательность → скрытые состояния
    # ============================================================
    with torch.no_grad():
        full_outputs = model(
            input_ids=input_ids,
            attention_mask=attention_mask,
            output_hidden_states=True,
            use_cache=False,
        )
    
    # Извлекаем скрытое состояние последнего токена на слое layer_idx
    # hidden_states[0] = эмбединги, hidden_states[l+1] = выход слоя l
    h = full_outputs.hidden_states[layer_idx + 1][:, -1:, :]  # [1, 1, D]
    h = h.float().detach().requires_grad_(True)
    
    # ============================================================
    # ПРОХОД 3: Прогон h через оставшиеся слои с кэшем ПРЕФИКСА
    # ============================================================
    # Клонируем кэш, чтобы не испортить оригинал
    # (deepcopy не работает для GDN-слоёв — in-place мутации кэша, см. §9)
    cache_clone = _deep_clone_cache(prefix_cache)
    
    # Получаем оставшиеся слои
    # model.model.layers содержит все декодерные слои
    remaining_layers = model.model.layers[layer_idx + 1:]
    norm_layer = model.model.norm
    lm_head = model.lm_head
    
    # Позиционные данные для последнего токена
    # Qwen3.5 использует MRoPE с 4 компонентами: text, temporal, height, width.
    # Для текстового входа все 4 одинаковы.
    # При seq_len=1 с кэшем позиция последнего токена = S - 1 (0-indexed).
    position_ids = torch.full((4, 1, 1), S - 1, dtype=torch.long, device=input_ids.device)  # [4, 1, 1]
    text_position_ids = position_ids[0]  # [1, 1]
    
    # Позиционные эмбединги (RoPE)
    # Для последнего токена с кэшем нужны cos/sin для позиции S-1
    position_embeddings = model.model.rotary_emb(h, position_ids[1:])
    
    x = h  # [1, 1, D]
    
    for i, layer in enumerate(remaining_layers):
        actual_layer_idx = layer_idx + 1 + i
        layer_type = model.config.layer_types[actual_layer_idx]
        
        # При seq_len=1 с кэшем маска НЕ НУЖНА.
        # Attention: один токен attend-ит на все кэшированные KV.
        # GDN: рекуррентное состояние уже содержит контекст.
        mask = None
        
        # Сигнатура layer.forward() не принимает use_cache —
        # слой решает сам по past_key_values is not None.
        layer_output = layer(
            x,
            position_embeddings=position_embeddings,
            attention_mask=mask,
            position_ids=text_position_ids,
            past_key_values=cache_clone,
        )
        x = layer_output
    
    # ============================================================
    # Нормализация и логиты
    # ============================================================
    x = norm_layer(x)
    logits = lm_head(x[:, -1, :])  # [1, V]
    
    # ============================================================
    # Вычисление градиентов для токенов из token_set
    # ============================================================
    logits_subset = logits[0, token_set]  # [|U|]
    # Цикл по token_set: один backward на токен (надёжно)
    J = torch.zeros(len(token_set), h.shape[-1], device=h.device)
    for i in range(len(token_set)):
        grad = torch.autograd.grad(
            outputs=logits_subset[i],
            inputs=h,
            retain_graph=(i < len(token_set) - 1),
        )[0]  # [1, 1, D]
        J[i] = grad[0, 0, :]  # [D]
    
    return J  # [|U|, D], ненормализованный
```

## C.2. _deep_clone_cache (GDN in-place мутации; из §9)

```python
def _deep_clone_cache(cache):
    """Клонирует DynamicCache, учитывая GDN in-place мутации."""
    new_cache = DynamicCache()
    for layer in cache:
        if hasattr(layer, 'keys'):  # DynamicLayer
            new_cache.append(DynamicLayer(
                keys=[k.clone() for k in layer.keys],
                values=[v.clone() for v in layer.values],
            ))
        elif hasattr(layer, 'recurrent_states'):  # LinearAttentionLayer
            new_conv = {k: v.clone() for k, v in layer.conv_states.items()}
            new_recur = {k: v.clone() for k, v in layer.recurrent_states.items()}
            new_cache.append(LinearAttentionLayer(
                conv_states=new_conv,
                recurrent_states=new_recur,
            ))
    return new_cache
```

## C.3. jacobian_bridge (из §9)

```python
def jacobian_bridge(
    J_L: torch.Tensor,       # [|U|, D_L] — Якобиан старшей модели
    J_S: torch.Tensor,       # [|U|, D_S] — Якобиан младшей модели
    E_L: torch.Tensor,       # [V, D_L] — эмбеддинги старшей
    E_S: torch.Tensor,       # [V, D_S] — эмбеддинги младшей
    probs_L: torch.Tensor,   # [|U|] — вероятности токенов в старшей модели
    threshold_rel: float = 0.01,  # относительный порог: τ = 0.01 · median(‖J_S[i]‖) (см. §17, E-6)
) -> float:
    """
    Вычисляет Якобианов лосс между старшей и младшей моделями.
    
    Возвращает: scalar — значение лосса
    """
    # Проекция в пространство словаря
    # J_L: [|U|, D_L], E_L^T: [D_L, V] → J_L @ E_L^T: [|U|, V]
    J_L_projected = J_L.float() @ E_L.float().T  # [|U|, V]
    
    # Обратная проекция в пространство младшей модели
    # J_L_projected: [|U|, V], E_S: [V, D_S] → J_L_projected @ E_S: [|U|, D_S]
    # Коррекция неортогональности E_S через pinv(E_S^T E_S)
    G_inv = torch.linalg.pinv(E_S.float().T @ E_S.float())  # [D_S, D_S]
    J_S_target = J_L_projected @ E_S.float() @ G_inv  # [|U|, D_S]
    
    # Маска затухших градиентов (относительный порог: τ_l = 0.01 · median_i ‖J_S[i]‖; см. §17, E-6;
    # исторически использовался абсолютный порог τ = 1e-6)
    J_S_norms = J_S.float().norm(dim=1)       # [|U|]
    J_target_norms = J_S_target.norm(dim=1)    # [|U|]
    tau = threshold_rel * J_S_norms.median()
    valid_mask = (J_S_norms > tau) & (J_target_norms > tau)  # [|U|]
    
    if valid_mask.sum() == 0:
        return 1.0  # максимальный лосс, если всё затухло
    
    # Косинусное сходство по валидным строкам
    cos_sim = torch.nn.functional.cosine_similarity(
        J_S.float()[valid_mask],
        J_S_target[valid_mask],
        dim=1,
    )  # [n_valid]
    
    # Взвешивание по вероятностям старшей модели
    weights = probs_L[valid_mask]
    weights = weights / (weights.sum() + 1e-8)  # нормализация весов
    
    loss = (weights * (1.0 - cos_sim)).sum().item()
    
    return loss
```

## C.4. run_diagnostics (из §10)

```python
def run_diagnostics(
    model_large, model_small,
    calibration_samples,
    token_set,
    layer_mapping,
):
    """
    Вычисляет gap (разрыв Якобиана, lower=better) для всех пар слоёв.
    Возвращает: dict {(l_L, l_S): loss}
    """
    E_L = model_large.model.embed_tokens.weight.detach()
    E_S = model_small.model.embed_tokens.weight.detach()
    
    results = {}
    
    for l_L, l_S in layer_mapping.items():
        losses = []
        
        for sample in calibration_samples:
            input_ids = sample["input_ids"].to(model_large.device)
            attention_mask = sample["attention_mask"].to(model_large.device)
            
            # Якобиан старшей модели
            J_L = compute_jacobian_for_tokens(
                model_large, l_L, input_ids, attention_mask, token_set
            )
            
            # Якобиан младшей модели
            J_S = compute_jacobian_for_tokens(
                model_small, l_S, input_ids, attention_mask, token_set
            )
            
            # Вероятности токенов из token_set в старшей модели
            with torch.no_grad():
                logits_L = model_large(input_ids=input_ids).logits[:, -1, :]
                probs_L = torch.softmax(logits_L[0, token_set], dim=-1)
            
            loss = jacobian_bridge(J_L, J_S, E_L, E_S, probs_L)
            losses.append(loss)
        
        results[(l_L, l_S)] = sum(losses) / len(losses)
    
    return results
```

## C.5. ESG (из §11)

```python
def compute_esg(
    model,
    layer_idx: int,
    calibration_samples,
    token_set,
    n_components: int = 32,
):
    """
    Вычисляет Empirical Sensitivity Gramian для слоя layer_idx.
    
    Возвращает:
        eigenvalues: [n_components] — собственные значения
        eigenvectors: [n_components, |U|] — собственные векторы
    """
    all_J = []
    
    for sample in calibration_samples:
        input_ids = sample["input_ids"].to(model.device)
        attention_mask = sample["attention_mask"].to(model.device)
        
        J = compute_jacobian_for_tokens(
            model, layer_idx, input_ids, attention_mask, token_set
        )
        all_J.append(J)  # [|U|, D]
    
    # ESG: (1/N) * sum_i (J_i @ J_i^T)
    # J_i: [|U|, D] → J_i @ J_i^T: [|U|, |U|]
    U_size = len(token_set)
    G = torch.zeros(U_size, U_size, device=all_J[0].device)
    
    for J in all_J:
        G += J.float() @ J.float().T
    G /= len(all_J)
    
    # Спектральное разложение
    eigenvalues, eigenvectors = torch.linalg.eigh(G)
    
    # Сортировка по убыванию
    idx = eigenvalues.argsort(descending=True)
    eigenvalues = eigenvalues[idx][:n_components]
    eigenvectors = eigenvectors[:, idx][:, :n_components].T  # [n_components, |U|]
    
    return eigenvalues, eigenvectors
```

```python
import torch
from collections import Counter

def build_global_token_set(model, calibration_samples, K=64):
    """Собирает глобальный набор токенов из top-K логитов на всех сэмплах."""
    token_counter = Counter()
    model.eval()

    with torch.no_grad():
        for sample in calibration_samples:
            outputs = model(
                input_ids=sample["input_ids"].to(model.device),
                attention_mask=sample["attention_mask"].to(model.device),
            )
            # Берём логиты последнего токена
            logits = outputs.logits[:, -1, :]  # [1, V]
            top_indices = logits.topk(K, dim=-1).indices[0]  # [K]
            token_counter.update(top_indices.tolist())

    # Берём топ-|U| самых частых токенов
    U_size = min(K, len(token_counter))
    U = [token_id for token_id, _ in token_counter.most_common(U_size)]
    return sorted(U)
```
