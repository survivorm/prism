## Оспорено

### 1. §9: «переиспользовать форвард-слой AT8_2-r2, не дублировать» — НЕВОЗМОЖНО

Store R2 (`results/AT8/AT8_2_R2_store.json`) хранит на условие/слой только
`cos_raw / cos_state / norm_delta / ce` — **никаких h-векторов** (проверено по
ключам: `per-L keys: ['cos_raw','cos_state','norm_delta']`). Основной наблюдаемый
AT8_3, A(d) = ‖h_inj(d) − h_ctrl(d)‖/‖h_ctrl(d)‖, требует сырых h из ДВУХ
разных форвардов (inj и ctrl) на выровненных позициях — из store R2 его
невосстановимо. Кроме того: R2 — 5 слоёв {6,12,18,19,23} против {6,11,18,23} здесь,
и 14 доков против 16. **Форвард-слой не переиспользуется; смет — как в §9-б.**

### 2. §9: цена 144 форварда (9/док) — недоучтены собственные же контроли

У 5.3 (положительный контроль) нужен случайный блок — +1 условие (n=16).
У 5.4 (нуль-контроль) нужен второй филлер — и для позиционного floor по КАЖДОЙ
дозе (вердикт агрегирует по 4 дозам) fillerB нужен на всех 4 дозах, а не один.
Реально: ctrl(1) + 4×{loop, fillerA, fillerB}(12) + rand(1) = **14 условий/док,
16×14 = 224 форварда**.

База сметы тоже скорректирована: R2 фактически прогнал **182 форварда за
2596 s = 14.3 с/фд** под нагрузкой (не «98 фд / 26 с» — 98 было начальной сметой,
реальный дизайн R2 — 3 условия на дозу). Итог: 224 фд × 6.2 с (без нагрузки) ≈ 23 мин;
× 14.3 с (замеренная нагрузка) ≈ 53 мин; с PCA/анализом **бюджет 60–90 мин**.

### 3. §5.2: δ_min «из дальних позиций, где эффект ожидается нулевым» — циклично

«Заведомо вне влияния вставки» нельзя определить до ответа на вопрос о
локализации — это и есть то, что тестируем. Чистый источник floor — **null-контраст
двух филлеров**: A_null(d) = ‖δh_fillerA(d) − δh_fillerB(d)‖/‖h_ctrl(d)‖ — два
не-луповых блока одной длины, сдвиги идентичны; специфического отклика там быть
не может по построению. Фикс: **δ_min(n, L, d) = 95th pct A_null(n, L, d) по 16 докам —
позиционный floor**, и сравнения идут против δ_min(d) на той же позиции d.
Плюс F4-урок AT8_2: floor и сравниваемый профиль — одна статистика (per-doc,
per-position). «Дальные позиции» остаются вторичной диагностикой, не в вердикт.

### 4. §6.2 п.3 + §6.3 — прямое противоречие

LOCALIZED включает «ξ слабо зависит от дозы», а 6.3: «не входит в основной
вердикт как гейт». Фикс: dose-зависимость ξ — **только диагностика**
(ξ(n), ξ(I(n)) в отчёте — I(n) — информационная доза, тег DOSE_TREND при монотонном росте). В вердикт —
только «существует конечное ξ < D на ≥2 из 4 доз» (точнее — через doc-агрегацию, см. 6).

### 5. Определение ξ слепо к «дальному бампу»

ξ = «наименьшее d, начиная с которого A ≤ floor на окне m=8» — одиночный дальний
пик (d=100) НЕ сдвигает ξ (окно [d, d+m] при малых d пик не покрывает). Документ
может быть «локализован» при артефакте вдали от вставки. Фикс (без изменения
вердикта): тег **FAR_BUMP** — доля d ∈ [ξ+m, D] с A_spec(d) > δ_min(d) > 10%.
Групповой тег FAR_BUMP, если >25% локализованных доков его несут. Диагноз, не гейт.

### 6. Агрегация вердикта не определена (ξ — величина per-doc)

«Для ≥половины доз существует конечное ξ» — не сказано, по какой популяции.
Фикс (полная пре-рег цепочка):
1. **per (док, n, слой)**: статус ∈ {NO_RESPONSE (A_spec(d) ≤ δ_global(n,L) для всех d),
   LOCALIZED (ξ < D), PERSISTENT (нет окна m=8 ≤ floor до D)}.
2. **per (док, n)**: ≥3 из 4 слоёв одного статуса, среди них ≥1 GDN и ≥1 full →
   статус дока; ξ_док(n) = медиана ξ по согласованным слоям. Иначе LAYER_INCONSISTENT.
3. **per доза**: frac_persistent(n) = #PERSISTENT/16, frac_localized(n) = #LOCALIZED/16.
4. **Дерево**: INSENSITIVE_CELL → NOT_LOCALIZED (≥2/4 доз: frac_persistent ≥ 0.5) →
   LOCALIZED (≥2/4 доз: frac_localized ≥ 0.5) → NOT_RESOLVED (+теги
   BELOW_RESOLUTION / WIDE_CI / FAR_BUMP).

### 7. §6.4: порог Q-насыщения не пре-регистрован

«ΔQ на последних 25% ≤ порога» — порог пуст. Фикс: **Q_sat = (Q(D) − Q(⌊0.75D⌋))/
max(Q(D), 1e-9) ≤ 0.10** → «насыщен». Только диагностика (как и в черновике).

### 8. §1: `attn_implementation="eager"` — против локального референса серии

Локальный референс серии (AT8_2-R2, замеры R1) — **sdpa** (лог R2: «fp32, sdpa,
OMP=6»); eager на CPU ~2× медленнее → 224 фд: ~1.5 ч против ~53 мин. Фикс: **sdpa**
+ смоук-кроссчек (1 док: ctrl + loop n=16 в eager и sdpa; max относ. разницы A_spec
< 1e-5 → идём в sdpa; иначе — стоп и обсуждение). Это отклонение от черновика
зафиксировано здесь, не молча.

### 9. §8 S6: «пин механики поля (curves_series)» — артефакт из другого дизайна

В AT8_3 curves_series не используется. Фикс: S6 = sha256 (а) четырёх пул-пинов,
(б) filler-таблицы (источник/диапазон/sha филлера на каждый док), (в) случайного
блока (см. §12 TZ).

### 10. §4.1: A(d) как отношение норм — нельзя контрастировать «луп против филлера»

Разность A_loop(d) − A_fillerA(d) — разность нелинейных величин, без чистого
интерпретируемого объекта. Фикс: луп-специфичный профиль — **векторная** разница
на уровне состояний:
`A_spec(d) = ‖(h_loop(t_inj) − h_ctrl(t_ctrl)) − (h_fillerA(t_inj) − h_ctrl(t_ctrl))‖ / ‖h_ctrl‖
= ‖δh_loop(d) − δh_fillerA(d)‖ / ‖h_ctrl(d)‖`.
Тогда A_spec / A_null / A_ins — одна линейная схема (векторные разности δh),
сравнимые между собой и с floor. A_ins(d) = ‖δh_loop(d)‖/‖h_ctrl‖ остаётся
«реакция есть вообще» (включая эффект вставки).

### 11. §4.3: q(d) отбрасывает ортогональное дополнение

q(d) — проекция на топ-32 моды контроля; возмущение, живущее вне подпространства,
в q не попадает. Фикс: диагностика **capture(d) = q(d)/‖δh_loop(d)‖²** в store и
отчёте; если медиана capture < 0.5 — квази-интеграл помечен «readout вне
подпространства», в вердикт не идёт (как и всё §6.4).

### 12. §11: store «<10 МБ» — оценка нужна, не декларация

Оценка по дизайну: 16 доков × 4 дозы × 4 слоя × 7 рядов × 128 позиций ≈ 14.3k
float/док + CE (14 условий × ≤400) + PCA-базис (4×32×1024) ≈ **~2–3 МБ JSON** —
в git (AGENTS: >10 МБ — запрещено). Фикс: правило — если store > 10 МБ,
gitignore + бэкап /data + sha в манифесте (как R2), а не «гигиена» без числа.

## Самокоррекции черновика, заложенные в TZ

- δ_min — позиционный из null-контраста (п.3), не «дальные позиции».
- Случайный блок 5.3 **заморожен в пре-реге**: 144 токена, uniform(0, 248320),
  seed 0, список и sha в TZ §12 (генерирован ДО дизайна финализации).
- S_base: точное правило (9-грамма со счётчиком ≥4 → отсев ИЛИ rep_rate(≥3) > 0.02),
  выбор — первые 4 прошедших в порядке пина; math — ровно 10 прошедших, запас есть.
- S9: детерминизм = повторный ctrl-форвард; bit-identical ИЛИ max rel diff < 1e-6,

  пре-регистрован, а не предполагается).
- Вердикт-машина проверяется синтетикой 6/6 (LOCALIZED / PERSISTENT / BELOW /
  INSENSITIVE / LAYER_INCONSISTENT / NOT_RESOLVED) до прогона.

### 2.1 T ≠ 256 у 5 из 16 доков (самокоррекция TZ v1.0)

TZ v1.0 писал «T = 256 у всех» — **ошибка**: у пина `min_length=192`,
truncation срабатывает только у длинных. Измерено (18.11): d1 T=254,
d2 T=205, d6 T=238, d8 T=200, d9 T=196 (остальные 11 — T=256). Фикс:
`cut = T//2` и `D = T − cut − 1` **на док** (cut 98…128, D 97…127 — оба
≥ 64, так что окно d=0…64 для смоука и позитивного контроля существует
у всех). δ_min(n,L,d) — 95th pct по докам с `D_doc ≥ d` (при d=127 —
11 доков). 16 доков заморожены в таблице TZ §4 с полными sha по токенам.

### 2.2 S_base (правило v2) — 16 доков стабильны

Измерено на пинах по точному правилу v2 (9g-счётчик ≥ 4 ИЛИ
rep_rate(≥3) > 0.02): проходят wiki 12/12, math 11/12, code 11/12,
chat 12/12 (в TZ v1.0 было «math 10/12» — это счёт для правила черновика
v1 ≥3; единственная разница — math doc11: max9g=3, rep_rate 0.0043,
проходит по v2). **Первые 4 в порядке пина идентичны во всех вариантах
правила** (v1 ≥3 / v2a ≥4|rep-по-различным / v2b ≥4|rep-по-вхождениям):
wiki 0-3, math 0-3, code 0,1,3,4, chat 0-3. Формула rep_rate зафиксирована
в TZ: по **различным** 9-граммам; обе трактовки проверены — множество
проходящих совпадает.

### 2.3 S4: гейт филлеров ≥ 2 убивал бы 4 из 16 доков

Измерено: у d4 (math0), d6 (math2), d8 (code0), d10 (code3) в первых
144 токенах есть 9-грамма со счётчиком ровно 2 (нигде ≥ 3; на дозах
18/36/72 — везде счётчик 1). Строгий гейт v2 («нет период-9 повторов»,
т.е. ≥ 2) → артефакт не соберётся (эти доки — источники филлеров).
Фикс: S4 = «нет 9-грамм со счётчиком ≥ 3 в филлерном блоке»: единичный
повтор 9-граммы — текстовый шум, период-9 структура лупа имеет счётчик
n ≥ 2 и при n ≥ 3 строго больше порога; содержание филлера и лупа
различается и так (cross-doc). Измеренный максимум по всем 16 докам — 2,
гейт ≥ 3 проходит всем.

### 2.4 NO_RESPONSE — по позиционному floor (формула v2)

v2: `NO_RESPONSE` = `A_spec ≤ δ_min` всюду. TZ v1.0 сравнивал со
скалярным δ_global (95th pct по всем (док, d) — выше позиционных значений).
Фикс: статус — по позиционному floor (как в v2), δ_global остаётся
диагностикой (тег BELOW_RESOLUTION). На вердикт не влияет: в денотаторы
fracs идут только PERSISTENT/LOCALIZED.

### 2.5 «Точечные оценки без CI в вердикт не идут» (v2 §7) — как операционализировано

При n=16 доков CI95 доли не исключает 0.5, пока доля < 12/16≈0.75
(двоичная арифметика: 11/16 → CI ≈ [0.45, 0.93], 14/16 → ≈ [0.62, 1.0]).
Жёсткий CI-гейт сделал бы вердикт практически недостижимым (нужны
14–16/16 доков), а не более честным. Операционализация (как в R2):
**правило решения зафиксировано пре-регом по точным оценкам**
(frac_persistent/frac_localized ≥ 0.5 на ≥2 дозах), CI95 (doc-bootstrap
B=2000, seed 0) **обязательно в отчёте**, а если CI95 доли квалификационных
доз содержит 0.5 — на вердикте висит тег **WIDE_CI**, т.е. «вердикт при
разрешении n=16» читается с явной пометкой. Альтернатива (больше доков)
дорожает прогон и не меняет дизайн — не пре-рег-материал.

### 2.6 sha случайного блока (самокоррекция TZ v1.0)

`bfa37b242d2e7812…` из TZ v1.0 не соответствует ни одной сериализации
замороженного списка (json.dumps/repr/sep/space/newline — проверено).
Список (144 токена, default_rng(0).integers(0, 248320, 144)) **не менялся**
и остаётся source of truth в TZ §12; зафиксирован точный fingerprint:
sha256(`json.dumps(списка)`) = `0dae5659e99518de2d5b94b9ac320202d41a887577910eecc121b336d47b19cc`.
