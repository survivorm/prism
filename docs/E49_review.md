Посмотрел обновлённые файлы. Часть замечаний действительно исправлена, но **один существенный баг остался**, и есть несколько ограничений, которые всё ещё влияют на интерпретацию.

## 1. Что исправлено в новой версии

- `synth_coh` теперь действительно геодезический: `w` ортогонализуется к `u` при инициализации и после каждого шага. Это закрывает старую проблему, из-за которой на LFM3 coherent-контроль был невалиден (`CB > CA`).
- `frames_of` больше не даункастит в `float32` — кадры считаются в `float64`.
- Tied-weights проверка стала универсальной: для LFM3, где `lm_head` отсутствует и `tie_word_embeddings=True`, `A` действительно строится по эмбеддингам. Это подтверждено комментарием.
- В `exp49_leaf_info` helper `frame_in_metric` исправлен: теперь для `G = L Lᵀ` используется `L.T @ V`, а не `L @ V`.
- Добавлен `--controls-only`, чтобы перепроверить только CA/CB после фикса.
- В docstring `exp49_leaf_info` честно написано, что M3 holonomy не запускалась в production-сетке. Заявка снята.

## 2. Что всё ещё не так

### 2.1. Главный оставшийся баг: M-метрика в основной сетке `exp49_leaf_info` всё ещё считается неверно

В `main()`:

```python
Lch = torch.linalg.cholesky(G + jitter)
...
if metric == "M":
    V = torch.linalg.qr(Lch @ V)[0]
```

`torch.linalg.cholesky(G)` даёт `G = L Lᵀ`. Значит, G-ортонормированный базис — это `qr(Lᵀ V)`, а не `qr(L V)`.  
Helper `frame_in_metric` уже исправлен на `L.T @ V`, но **основная сетка `W×r×metric` в `main()` этот helper не использует** — там по-прежнему `Lch @ V`.

**Следствие:** все M-ячейки в `exp49_leaf_info_*.json`, если они были посчитаны этой версией, всё ещё неинтерпретируемы. H2 в `exp49b2` не затронута, потому что там `L=None`, то есть чистая евклидова метрика.

### 2.2. `other_doc` по-прежнему не входит в вердикт

В JSON:

- Qwen W4: `real = 0.4437`, `other_doc = 0.4509`;
- LFM3 W4: `real = 0.4818`, `other_doc = 0.4786` — real даже чуть **хуже**.

Если лист нёс бы информацию именно о траектории **этого** документа, `other_doc` должен быть заметно хуже. Он не хуже. Значит, измеренная когерентность, скорее всего, **не документ-специфична**, а является свойством модели/головы/локальной динамики поля `J`. Вердикт этого не ловит, потому что `other_doc` не включён в `verdict_rule`.

### 2.3. Для LFM3 набор токенов `U` остаётся произвольным

В `load_model` для LFM3:

```python
U = list(range(0, 384, 3))[:128]
```

Для Qwen берётся частотный `U128` из кэша. Это разные наборы. Абсолютные `τ` между Qwen и LFM3 сравнивать рискованно: различие может отражать не архитектуру, а разный выбор токенов. Это не ошибка вердикта внутри модели, но ограничение кросс-модельного вывода.

### 2.4. `blockmix` / `interleave_check` не проверяют длину чужого документа

```python
ok_ = fr[others[...]]
obl = [ok_[i * W:(i + 1) * W] for i in range(T // W)]
mixed = [Vs[t] if t % 2 == 0 else ok_[t] for t in range(T)]
```

Если у `ok_` длина меньше `T`, последние блоки будут короче, а `mixed` упадёт по индексу. Сейчас в данных, видимо, длины совпадают, но код хрупкий. Нужен `assert len(ok_) >= T` или выравнивание.

### 2.5. Старый JSON LFM3 содержит невалидный CB

В старом `exp49b2_floor_lfm3.json`:

- W4: `CB_smooth = 0.6164` — выше порога `<0.5`;
- W16: `CB_smooth = 0.6339`, а `CA_smooth = 0.6038` — «когерентный» контроль менее когерентен, чем «белый».

Это как раз следствие старого `synth_coh`. Новый код должен это исправить, но **новых чисел после фикса в присланных файлах нет**. Нужно прогнать `--controls-only` и проверить, что `CB < CA` и `CB < 0.5`.  
Вердикт H2 при этом **не включает CB**, поэтому старый `H2_survives=true` для LFM3 W4 формально не опровергается, но качество контроля было плохим.

### 2.6. `N_REP = 2` — мало

Для block/shuffle/blockmix используется среднее по 2 реализациям. CI может быть оптимистичным. Не ошибка, но ограничение.

## 3. Что означают результаты простыми словами

`τ` — мера неаддитивности движения кадров:

- `τ ≈ 0` — шаги складываются как по гладкой траектории, движение когерентное;
- `τ ≈ 1` — шаги независимы, как белый шум.

### W = 4: умеренное сглаживание открывает медленный канал

Для обеих моделей:

- Qwen: `real τ = 0.4437`, `block τ = 0.4879`, `blockmix τ = 0.4875`;
- LFM3: `real τ = 0.4818`, `block τ = 0.5108`, `blockmix τ = 0.5079`.

Real заметно ниже block и blockmix, CI разности не включает 0.  
Это значит: если порезать траекторию на блоки длины 4 и перемешать блоки — или взять блоки из другого документа — движение становится менее когерентным. То есть у реальной траектории есть когерентность **длиннее 4 позиций**, которую перестановка блоков разрушает.

### W = 16: сильное сглаживание стирает различие

- Qwen: `real 0.3914`, `block 0.3950`, `blockmix 0.3930`;
- LFM3: `real 0.4417`, `block 0.4430`, `blockmix 0.4437`.

Разности почти нулевые, CI включает 0. При окне 16 реальная траектория уже не отличается от перестановки блоков длины 16. Простая интерпретация: характерная длина когерентного медленного канала — **между 4 и 16 позициями**. При W=16 блочный контроль сам сохраняет достаточно локальной непрерывности, и разница исчезает.

### Но две оговорки

1. **`other_doc` почти не отличается от `real`**, а для LFM3 W4 даже чуть хуже. Значит, эффект, вероятно, **не документ-специфичен**; это может быть общее свойство поля `J` для данной модели.
2. **Coherent-контроль на LFM3 в старом JSON был сломан**. Новый код должен его исправить, но это надо перепроверить прогоном `--controls-only`.

## 4. Итог

- **Код и JSON согласованы по вердикту**; ошибок в арифметике вердикта я не вижу.
- **H2 при W=4** формально подтверждается: real когерентнее block и blockmix на обеих моделях.
- **H2 при W=16** не подтверждается: сильное сглаживание стирает различие.
- **Главный оставшийся баг:** M-метрика в основной сетке `exp49_leaf_info` всё ещё использует `Lch @ V` вместо `Lch.T @ V`. M-числа неинтерпретируемы; H2 (евклидова) не затронута.
- **Главное ограничение интерпретации:** `other_doc` не хуже `real`, поэтому нельзя утверждать, что лист несёт информацию именно о траектории документа. Скорее — о локальной динамике модели.
- **Для LFM3** нужно перепрогнать controls-only после фикса `synth_coh` и проверить, что `CB < CA` и `CB < 0.5`.

Если коротко: **«при умеренном сглаживании виден когерентный медленный канал; при сильном он исчезает» — да. «Это канал именно траектории документа» — пока нет, `other_doc` против. «LFM3 подтверждает» — формально да по W4, но старый coherent-контроль был невалиден; после фикса надо перепроверить.**
