# ТЗ: E-37 (финальный). Анатомия P(p_t)-чувствительной компоненты Якобиана

**Статус:** финал, готов к запуску. Не новый эксперимент, а переименование и углубление E-33/E-33r. Термин «gauge» снимается.

---

## 0. Признание ошибки и контекст

**Ошибка:** `cos_depth_gauge_v ≈ 0.999 по всем парам слоёв` в моём разборе — неверно. Реальные значения `med_cos` из `exp33r_gauge_anatomy.json`: 6–12 = 0.557, 12–18 = 0.429, 18–22 = 0.615, 22–23 = 0.209 (raw). Ни одно не близко к 0.999. Было спутано с `align_ug` (внутри слоя: top-1 SVD vs cheap-proxy, 0.85–0.99). «Жёстко зафиксированная ось сквозь сеть» не следует из данных.

**Что выживает из критики:** терминология «gauge» перегружена; `rank_K = 67–94` не интерпретирован; L22-аномалия реальна; проекция `u_g` на токены и профиль `rank_K` — дешёвые тесты.

**Что критик пропустил:** структура J существует (E-28: Δ_SVD = 0.27 на L23); факторизация `J = M_K·(√D/r)·P_u` точна (E-35); fixed-P сохраняет структуру (0.25), per-P убивает (1.57). Эти факты не пересматриваются.

**Установлено ранее (не пересматривается):**
- `survive_frac ≈ 0.02` — следствие пиковости `p` (`‖P‖_op ≈ p_max(1−p_max)`), не «большого gauge».
- Fixed-P сохраняет структуру, per-position P убивает — разрушитель есть вариация `p_t`.
- `Δ_SVD_gf = π/2` — максимальный главный угол, не шум.
- `Ω = 0.205` при random baseline 0.016: gf- и raw-подпространства частично пересекаются.
- `rank_K = 67–94` из 128: не автоматически rank-1 событие.
- L22-аномалия: `uniformity_0` 0.80→0.49, `align_u_top_ug` 0.99→0.85.

## 1. Цель

Охарактеризовать **P(p_t)-чувствительную компоненту** `K_t = J_t − P(p_t)·J_t` и ось `u_g(t) = J_t J_tᵀ 𝟙 / ‖·‖`, ответив на три вопроса:

1. **Что убивает P?** `rank_loss = 128 − rank_K = 34–61`. Это сигнал или артефакт порога? Если структура есть — какая?
2. **Что такое `u_g`?** На что нагружена в словаре: синтаксис (пунктуация, whitespace) или содержание?
3. **Что делает L22?** Аномалия — тип слоя (GDN vs full-attn) или фазовый переход внутри GDN?

Все ответы — на существующем кэше `exp27b` (слои {6, 12, 18, 19, 22, 23}, 32 документа). Никаких новых форвардов.

## 2. Диагностика A: SVD убитой компоненты

### 2.1. A.0 — калибровка порога (первая фаза, обязательна)

**Обоснование.** `RANK_EPS = 1e-6` на границе fp32-шума. `K = J − P·J` теряет точность: `σ_noise(K) / σ_1(J) ~ 5e-8`. Порог 1e-6 может частично определять наблюдаемый `rank_K`, не структуру.

**Метод.**
- Подмножество позиций: **первые 8 позиций каждого документа** (32 × 8 = 256). Это же подмножество входит в полный прогон A.1 — не независимая выборка.
- Для каждой позиции: SVD `K_t` в fp32 и в fp64.
- `σ_noise` = хвост `σ_i(K_fp64)` за пределами топ-32: среднее или 95-й процентиль `σ_i` для i ≥ 96.
- `RANK_EPS = 3·σ_noise` — калиброванный порог.

**Выход:** `RANK_EPS_calibrated`, таблица `σ_i(K_fp32) / σ_i(K_fp64)` для топ-32 и хвоста. Если fp32/fp64 различаются значимо в топ-32 → fp32-числа ненадёжны, использовать fp64.

### 2.2. A.1 — полный прогон

Для каждой позиции `t`, слоя `l`:

```
K_t_perP = J_t − P(p_t)·J_t         # per-position P
K_t_fixP = J_t − P(p̄_med)·J_t       # fixed P, p̄_med = median по позициям
```

`p̄_med` — **median**, не mean (устойчивость к выбросам, консистентность с E-33r.2 A). Не смешивать `p̄_med` и `p̄_mean` в одном прогоне.

SVD каждой версии. Собираем:

- **Спектр `σ_i(K)` — топ-32 целиком**, не только participation ratio. Искать колено.
- **`energy_K_topk = Σ_{i≤k} σ_i²(K) / ‖K‖²_F`** — доля **внутри** `K`. Отдельно: **`frac_K_from_J = ‖K‖²_F / ‖J‖²_F`** — сколько энергии от J перешло в K. Не смешивать.
- **`rank_loss Δ = 128 − rank_K`** — основной объект, не «много». Каким порогом считать rank: калиброванным из A.0.
- **`rank_K` для `RANK_EPS ∈ {1e-4, 1e-5, 1e-6}`** — контрольная таблица стабильности. Плюс калиброванный порог.
- **Эффективный `dim ker`** = `#{σ_i(K) < ε_calibrated}`. Связь с Ω: если `dim ker ≈ 3`, то gf- и raw-подпространства пересекаются в `m ≈ 3` направлениях, что согласует Ω. Если `dim ker ≫ 3` — дополнительная структура.
- **`align_K_1 = |⟨u_K_1, 𝟙/√K⟩|`** — выравнивание топ-левого вектора `K` с uniform.
- **`align_K_p = |⟨u_K_1, p_t/‖p_t‖⟩|`** — выравнивание с текущим выходом.

**Две null-модели.**
1. **Shuffled J**: переставить токенные строки `J` (i ↔ i' случайно), пересчитать `K`, baseline для `align_K_1`, `rank_loss`.
2. **Random p**: заменить `p_t` на случайное Дирихле с теми же параметрами (или на `p̄_med`). Baseline для `align_K_p`.

**Агрегация:** per-sample медиана по позициям внутри `(dom, si)`, затем медиана/IQR по блокам (протокол E-30/E-34).

**Решающее правило.**
- `align_K_1 > 0.8` и `energy_K_top1 > 0.5` при baseline ≈ 0.09 → убитая компонента = uniform-подобный блок. Термин был неудачен, наблюдения верны, тема закрывается.
- `align_K_1 < 0.5` и `energy_K` распределена по топ-8 → `K_t` структурирована сложнее. Новая декомпозиция.
- `K_perP ≠ K_fixP` по `rank`, `align_K_1`, спектру → комплексность подтверждается напрямую (position-dependence в убитой компоненте).
- `dim ker ≫ 3` (калиброванный) → дополнительная структура сверх Ω.
- `rank_K` нестабилен по порогам {1e-4, 1e-5, 1e-6} → результат — артефакт порога, обнулить `rank_loss`.

## 3. Диагностика B: атрибуция оси `u_g`

**Шаг 1 — вычитание uniform.**
`u_g(t) = J_t J_tᵀ 𝟙 / ‖·‖`. Разложение: `u_g⊥ = u_g − ⟨u_g, 𝟙/√K⟩·𝟙/√K`. Зафиксировать `‖u_g⊥‖² / ‖u_g‖²` (доля остатка). Если **< 0.1** — атрибуция неинформативна, честно записать, не приписывать ось к категориям.

**Шаг 2 — атрибуция по `u_g⊥`** (не по `u_g`). Разложить по 128 токенам `U128`: `u_g⊥ = Σ_i α_i e_i`.

Метрики:
- `top8_tokens`: топ-8 токенов по `|α_i|` с весами.
- `category_share`: доля энергии в категориях {whitespace, punctuation, newline, content}. Категории — по `exp28_semantic.json` (220=space, 198=newline, 11=comma и т.д.).
- `entropy_ug⊥ = −Σ |α_i|²·log|α_i|² / ‖u_g⊥‖²` — размазана ли ось.

**Пер-позиционный baseline.**
`category_share` сравнить с частотой категорий **в топ-128 токенах по `p_t`** для той же позиции — не с глобальной частотой `U128`. Если whitespace доминирует в `p_t` для данной позиции, «share = 0.8» не сигнал.

**Краевой случай: пиковый `p_t`.**
Если `p_max(t) > 0.9`, «топ-128 по `p_t`» вырождается в один-два токена, baseline вырожден. Такие позиции исключать из атрибуции или объединять с соседними. Фиксировать долю исключённых.

**Пер-позиционный шумовой порог.**
Не использовать глобальный `σ_noise` из A.0 для B. Для каждой позиции — свой `σ_noise_t` (например, из хвоста `σ_i(J_t)`). Иначе сравниваем глобальный шум с локальным сигналом.

**Опционально (только L22).** Точный `u_1` через SVD `J_t J_tᵀ` на позицию. На L22 `align_ug = 0.85` (cheap-proxy хуже), вычитание из `u_g` может быть недостаточно. На L6–L18 `align_ug ≈ 0.99` — вычитания достаточно.

**Решающее правило.**
- `category_share(whitespace + punctuation + newline) > 0.8` **над per-position baseline** → ось синтаксическая. Согласуется с E-28-semantic.
- `category_share(content) > 0.3` над baseline → ось содержательная. Неожиданно, интересно.
- `entropy_ug⊥ > 3.0` или `‖u_g⊥‖² / ‖u_g‖² < 0.1` → ось не несёт информации. Закрываем.

## 4. Диагностика C: L22

**Шаг 1 — тип слоя из config (30 сек).**
Читать `model.config.layer_types` или аналог. Ожидание по `[L-qwen]`: 3×GDN + 1×full-attn, full на {3, 7, 11, 15, 19, 23}. В кэше: {6, 12, 18, 22} = GDN, {19, 23} = full. Подтвердить или опровергнуть.

**Шаг 2 — сравнение 18 / 19 / 22 / 23.**
По всем метрикам E-33r: `uniformity_0`, `align_u_top_ug`, `survive_frac`, `rank_K` (из A.1), `depth_gain` (из E-33r). L19 уже в кэше, форвард не нужен.

**Шаг 3 — интерпретация.**
- Если L22 — локальный скачок внутри GDN-слоёв (18→22 падение, 12→18 плоское), это не тип слоя, а фазовый переход.
- Если L22 — часть монотонного тренда (18→22→23 продолжают тренд), то 22 не «особенный», а следующий шаг к выходному режиму.
- Тип слоя объясняет переход 22→23 (GDN→full), но не объясняет падение 22 относительно 18.

**Решающее правило.**
- L22 = GDN, L23 = full подтверждено + монотонный тренд 18→19→22→23 → аномалия — часть выхода из GDN-режима, закрываем.
- L22 = GDN, L23 = full подтверждено + локальный скачок на 22 → фазовый переход внутри GDN, записываем как наблюдение без интерпретации (не придумываем историю).
- L22 = full → пересматриваем всё, потому что это несовместимо с паттерном.

## 5. Подводные камни

1. **`K_t = J_t − P·J_t` не ортогонально `P·J_t`.** P не проектор. Энергии не складываются: `‖J‖² ≠ ‖PJ‖² + ‖K‖²`. `energy_K_topk` — доля внутри `K`, не от `J`. Отдельно `frac_K_from_J`.

2. **`u_g` — cheap-proxy.** На L22 `align_ug = 0.85`; вычитание uniform может быть недостаточно, нужен точный `u_1`. На L6–L18 — достаточно.

3. **U128 — глобальный top-128.** Содержательные токены могут быть вне. Фиксируем ограничение.

4. **Пер-сэмпл агрегация.** Не усреднять `K_t` по сэмплам до SVD (SVD нелинеен).

5. **Не смешивать `p̄_med` и `p̄_mean`.** Обе версии — если нужны, отчитывать отдельно.

6. **Категориальная база per-position.** Не глобальная частота в U128, а per-position частота в топ-128 по `p_t`.

7. **Пиковый `p_t`** (p_max > 0.9) — baseline вырожден. Исключать или объединять позиции, фиксировать долю.

8. **Калиброванный порог — единый** для A.1 и B. Пер-позиционный шумовой порог для B — отдельная величина.

9. **`torch.linalg.svd` в этом env (torch 2.13.0+cu130) возвращает U с НЕДЕТЕРМИНИРОВАННЫМ layout** (3D `(T,K,K)` vs 2D «folded» `(T,K)`) — зависит от процесса/кэша; `svdvals` (σ) от layout не зависят. ЛЕВЫЕ сингулярные векторы считаем через **`eigh(K·Kᵀ)`** (детерминированно, проверено selfcheck-тестом против `linalg.svd` на 2D-матрице). Это не баг-фикс метрик, а страховка от layout-хаза.

## 6. Порядок запуска

**A.0** (калибровка, ~15 мин):
- fp64 SVD на 256 позициях, хвост `σ_noise`, `RANK_EPS_calibrated`.
- Если fp32/fp64 различаются значимо в топ-32 → перейти на fp64 в A.1.

**A.1** (полный, ~30 мин):
- SVD `K_perP`, `K_fixP` на всех позициях, все собранные метрики.
- Две null-модели, таблица `rank_K` по 3 порогам.

**B** (атрибуция, ~30 мин):
- Вычитание uniform, per-position baseline, категориальный share.
- Краевые случаи (peaked p_t) — отдельно.

**C** (L22, ~15 мин):
- Config check, сравнение 18/19/22/23 по всем метрикам.

C независим от A.0, может идти параллельно. B зависит от A.0 (калиброванный шумовой порог).

**Итого:** ~1.5–2 часа CPU.

## 8. Итог

E-37 не ищет новую структуру. Он характеризует **P(p_t)-чувствительную компоненту J** — объект, который раньше назывался «gauge», но не является gauge в математическом смысле. Три вопроса: что убивает P (A), что такое ось `u_g` (B), что делает L22 (C).

**Возможные исходы и их следствия.**

| A | B | C | Следствие |
|---|---|---|---|
| uniform-block | синтаксис | тип слоя | Закрыто: gauge = uniform mode, L22 — архитектурный артефакт. E-36 D1/D2 избыточны. |
| uniform-block | размазано | фазовый переход | Гибрид: P убивает uniform, но ось не информативна; L22 — реальный переход. |
| сложная структура | содержание | локальный скачок | Открытие: `K_t` структурирована сложнее uniform. E-36 D3/D4/D5 становятся содержательными. |
| артефакт порога | — | — | Обнуляем `rank_K`, тема закрывается. |

Все четыре исхода информативны. Эксперимент не таргетирован на конкретный результат.
