## 1. B1 — формула R²: `‖pred‖²` вместо `‖yc − pred‖²` ⛔ (может обнулить главный вывод AT2b)

Видимый фрагмент:

```python
pred_cd = np.hstack([X, np.ones((X.shape[0], 1))]) @ W_cd
pc_cd = pred_cd                      # шкала centered-цели (DC = 0)
cosv_cd = (pc_cd * yc).sum(1) / (norm(pc_cd) * norm(yc) + 1e-12)
rows_cd.append(cosv_cd)
r2rows_cd.append(1.0 - float((pc_cd ** 2).sum()) / float((yc ** 2).sum()))
```

`cos` считает `pc·yc` ⇒ `pc` — **предсказание**. Тогда следующая строка считает

$$\text{«}R^2\text{»} = 1-\frac{\|\hat y\|^2}{\|y_c\|^2}\quad\text{вместо}\quad R^2 = 1-\frac{\|y_c-\hat y\|^2}{\|y_c\|^2}$$

Это **не R²**, а отношение норм. Малое предсказание даёт «R²»→1 независимо от направления.

**Это точно объясняет парадокс, который я отмечал в ревью прогона:** `R²_c` 0.6656–0.7750 при `cos_median` −0.040…−0.007. Корректный R² не может быть положительным при отрицательной агрегированной корреляции:

$$R^2 = 2\rho\frac{\sigma_{\hat y}}{\sigma_y}-\Big(\frac{\sigma_{\hat y}}{\sigma_y}\Big)^2$$

Ручной счёт из чисел прогона (если формула как показана):

| «R²» | ‖ŷ‖²/‖y_c‖² | ‖ŷ‖/‖y_c‖ | R² при ρ=0 |
|---:|---:|---:|---:|
| 0.7750 | 0.2250 | 0.474 | **−0.225** |
| 0.7152 | 0.2848 | 0.534 | **−0.285** |
| 0.6656 | 0.3344 | 0.578 | **−0.334** |

Чтобы корректный R² был > 0, нужно ρ > ratio/2 ≈ **0.24–0.29** — при медианном cos ≈ −0.02 это возможно только при сильной скошенности, и это не показано.

Следствие: заголовок прогона «метрика перестала вырождаться (r1: R² < 0 везде)» **может быть артефактом формулы**. Не исключено, что R² по-прежнему отрицателен везде, и центрирование не спасло метрику.

**Контр-улика, которую надо объяснить:** S6b прошёл `|R²_c| < 1e-12` для P-zero. По показанной формуле P-zero даёт `ŷ ≈ 0` ⇒ «R²» = 1 ⇒ гейт бы **упал**. Значит гейт написан по **правильной** формуле, а основной цикл — по другой. Это ровно болезнь «две реализации одной статистики» (как `sign_test` в AT3).

**Что сделать:**
1. Прислать точные строки R² в `AT2b.py` (RAW-ветка) и в диагностике (RAW/CD).
2. Добавить третью колонку `r2_correct = 1 − ((yc − pred)**2).sum()/(yc**2).sum()` рядом с текущей, для RAW и CD.
3. Если расхождение подтвердится — **все выводы про валидность метрики отзываются**, и C2-диагностика должна сравнивать не только cos, но и корректный R².

Пока это не закрыто, `SUBSPACE_CONTROL_FAIL` стоит на фоне метрики, валидность которой не установлена.

## 2. B2 — C1a проверяет тавтологию, а не то, что может сломаться ⛔

C1a как реализовано: `sum(lam_top)` vs `sum(lam_weak)`. Докстринг честно gọi это tautology-check — и это верно: `lam` отсортирован по возрастанию, top = последние R, weak = первые R ⇒ top ≥ weak **по построению**. Баг в split/eigh поймает, больше ничего.

**Реальный риск в другом месте — `_lift_arr`:**

```python
for j, i in enumerate(idxs):
    if lam[i] > 1e-12:
        V[:, j] = jrt @ (sp * w[:, i]) / np.sqrt(lam[i])
return _qr(V)
```

Порог **абсолютный**. `G = √P·(J Jᵀ)·√P`, где `P` — softmax-вероятности (малые), значит нижние собственные значения легко уходят ниже 1e-12. Тогда:

- колонка остаётся **нулевой**;
- `QR` матрицы с нулевыми колонками даёт **произвольное ортонормальное дополнение**;
- эти направления **не обязаны лежать в ker(J)**.

То есть weak-арм может оказаться **случайным подпространством**, а не «слабо наблюдаемым». Это одним механизмом объясняет и инверсию на L6, и Haar-аномалию (тоже случайные направления).

**Решающая проверка, почти бесплатная — всё уже в `ew_cache`:**

```python
# для каждого (L,d,t) и каждого арма:
E_real = || sp[:,None] * (jr @ V) ||_F²      # реализованная энергия
E_spec = lam[idxs].sum()                      # заявленная энергия
rel_dev = |E_real − E_spec| / max(E_spec, eps)
n_dead  = #{i ∈ idxs : lam[i] <= 1e-12}
```

- **top:** `rel_dev ≈ 0` обязано быть. Если нет — lift сломан и для top.
- **weak:** если `n_dead > 0` и `E_real ≫ E_spec` — **weak-арм не weak**, это случайные направления с ненулевой J-энергией.

Плюс прямой контроль: `||jr @ V_weak||_F / ||jr||_F` — доля J-энергии, которую «слабый» базис всё-таки несёт.

Это и есть функциональный гейт, которого не хватало в AT2b. C1a в нынешнем виде его не заменяет.

## 3. B3 — C1c: три ошибки в определении стационарного контроля ⛔

```python
Jagg = JRt.mean(axis=(0, 1))            # mean_{d,t} J
Gagg = Jagg.T @ Jagg                    # без P
order = argsort(lam, descending=True)
Vtop_a  = w[:, order[:r_final]]         # top-7
Vweak_a = w[:, order[r_final:2*r_final]]  # ранги 8–14
```

**(а) «weak» — это второй эшелон top, а не низ спектра.** Per-t weak = `range(0, R)` = наименьшие из 128. Здесь weak = 8-е–14-е **по убыванию** из 1024, причём у `Gagg` rank ≤ 128 ⇒ внизу ~896 нулевых собственных значений, до которых дело не доходит. Контраст top-7 vs next-7 **намного слабее**, чем top-7 vs bottom-7. Если C1c покажет top ≈ weak, это нельзя читать как «разбиение невалидно» — weak просто не weak.

**(б) Потеряна P-метрика.** Per-t: `G = √P (J Jᵀ) √P`. Здесь: `JᵀJ` без веса. Разные метрики ⇒ разные «top»-направления. Сравнение с per-t арм becomes apples-to-oranges.

**(в) `mean J` вместо `mean JᵀPJ`.** Якобианы разных позиций/доков могут иметь противоположные знаки — среднее **сокращается**. `mean J` — якобиан усреднённого отображения, а не «среднее подпространство». Корректный стационарный агрегат — **усреднённая грам-матрица**:

$$\bar G=\frac{1}{|D||T|}\sum_{d,t}J_{d,t}^\top P_{d,t} J_{d,t}\succeq 0$$

Она PSD, не сокращается, и её top-собственные векторы — направления, несущие максимум усреднённой наблюдаемости. Это стандартная average observability Gramian, и именно она нужна для T2.1c.

Все три ошибки в клетке, помеченной «кандидат контроля T2.1c» — то есть в том, на чём будет стоять следующая постановка.

## 4. B4 — C1b не устраняет нестационарность, а переносит её ⚠️

Базис — `VJ[(L,d,t)]`, **per (l,d,t)**. C1b фиксирует t и фитит ridge по 32 докам. Но при фиксированном t у **разных доков разные базисы** ⇒ семантика координаты j по-прежнему плавает, теперь по оси d вместо t.

Значит C1b — не чистый тест C1, а замена одного конфаунда на другой. Он информативен только если вращение по d существенно меньше, чем по t. Это надо **измерить напрямую**, а не предполагать:

```python
# главные углы между базисами
angles_t = principal_angles(V[d,t], V[d,t+1])   # вдоль t
angles_d = principal_angles(V[d1,t], V[d2,t])   # вдоль d
```

Медианы/квантили двух распределений — это **прямое измерение гипотезы C1**. Если углы вдоль t ≈ 90°, а вдоль d малы — C1 подтверждён и C1b осмыслен. Если оба велики — оба контроля конфаундированы, и нужен либо стационарный базис (исправленный C1c), либо локальная реконструкция без ridge вообще.

Это дешевле и решающее, чем ещё один ridge-вариант.

## 1. Критические замечания (влияют на вердикты)

### 1.1. Смешение медианы и среднего при проверке DC+MA(1)

Это главное.

- Плато измеряется на `dip_V,med` — **медиана косинусов** (канон T1a.1).
- `f_DC` считается из `r_v` — **момент** (среднее): `r_v = 21.846`, `N = 383`, `f_DC = r_v/N = 0.0570`.
- Утверждение «DC+MA(1) объясняет ≈93% уровня плато» сравнивает **медианное** плато с **средним** `f_DC`. Это не apples-to-apples.

Что известно из документа:
- Медианная строка: `Σ_{k≥2} ≈ +5.6` — но это **не моментная сумма** (Запрет 1).
- Моментная сумма: `r_v = 1 + 2Σρ̄ ⇒ Σρ̄ = 10.423`.
- Средняя и медианная кривые расходятся существенно: медиана даёт +5.6/2 ≈ 2.8, момент — 10.4.

Кроме того, под DC+MA(1) ожидаемое `ρ̂(k)` для `k≥2` не равно `f_DC`, а равно `f_DC·(1−k/N)` из-за конечной выборки. Среднее по полосе `k=9..96` от `(1−k/N)` ≈ **0.863**. То есть корректное предсказание модели для среднего плато ≈ `0.057·0.863 ≈ 0.049`, а не `0.057`. Если наблюдаемое среднее плато ≈ `0.05–0.06`, то «избыток» и «93%» могут измениться в разы.

**Что делать:** пересчитать плато на **среднем** `ρ̄(k)` (том же объекте, на котором определён `f_DC`), сравнить с `f_DC·(1−k/N)`, и только тогда фиксировать «объяснено 93% / необъяснено 6–7%». Медиану оставить как робастную описательную статистику, но не как основу для проверки линейной модели. Сейчас вердикт «DC+MA(1) refuted» скорее всего выживет (пермутационный тест на медиане валиден), но **величина остатка и интерпретация «93%» — под вопросом**.

### 1.2. T0-арбитр и несовпадение объекта

`r_max ≤ 0.208` — это **только для `du_unit`** (`Δu`). Дип измеряется на `v_tangent`, у которого `r_v = 21.846`. Граница `r_max` к `v_tangent` **не применяется**.

- Для `Δu` ограничение `r_max < 1` действительно невакуумно: оно запрещает `r ≥ 1`, т.е. DC-долю ≥ `1/N`.
- Для `v_tangent` никакого `r_max` нет; `r_v` измерен и может быть большим. T0 для `v_tangent` — это **тождество** `r = 1 + 2Σρ̂`, а не ограничение. Оно фиксирует сумму, но не форму.

Поэтому фраза «T0 — арбитр» в аддентуме звучит сильнее, чем есть: T0 арбитрирует **учёт шага `Δu`**, но не дип на `v_tangent`. Дип на `v_tangent` не ограничен `r_max`; его сумма фиксирована `r_v`, но форма — нет.

**Что делать:** явно разделить:
- T0 для `Δu`: невакуумное ограничение `r_max < 1` (арбитр шага).
- T0 для `v_tangent`: тождество учёта, фиксирующее сумму, но не форму (арбитр только на уровне «сумма должна сходиться»).
- Не переносить «T0 — арбитр» на дип без этой оговорки.

### 1.3. Фактический `r` для `Δu` не отчитан

Пре-рег T0.1: «`r ≤ r_max` на `du_unit` — теорема, sanity». В результатах отчитан только `r_max ≤ 0.208`, но **не фактический `r_du`**. Это важно:

- Если `r_du` близко к `r_max` (например, 0.15), то ограничение почти насыщено, и DC-доля шага ≈ `0.15/383 ≈ 4e-4`.
- Если `r_du` много меньше (например, 0.01), то DC-доля ещё на порядок меньше, и утверждение «шаг почти без дрейфа» сильнее.

Без фактического `r_du` нельзя сказать, насколько силён арбитраж T0. Это не меняет вердикт «r_max < 1», но меняет интерпретацию.

**Что делать:** отчитать `r_du` per-doc (и, желательно, `r_h` для `h_raw`) вместе с `r_max`. Это ~10 минут из лежащих полей.

### 1.4. T2: `ε` и метрика `P` не зафиксированы

Обобщённая задача `O_H^fut v = λ (C + εI) v` зависит от:
- `ε` (регуляризация),
- `P_{t+k}` (softmax/Fisher/иная метрика в логитовом пространстве).

В документе сказано «`ε` обязателен», «отчёт по `ε` обязателен», но **значение `ε` не задано**, и метрика `P` не выбрана канонически. Спектр `λ` может быть чувствителен к обоим. Без пина `ε` и `P` утверждение «устойчивый спектр» невоспроизводимо.

**Что делать:** пре-регистрировать `ε` (например, `ε = 1e-3 · trace(C)/D`) и одну метрику `P` (например, Fisher). Отчитать свип по `ε` (хотя бы 3 значения) как robustness check. Иначе T2.1/T2.2 не будут иметь однозначного вердикта.

### 1.5. T1a: аналогия с дизером сильнее, чем доказательство

T-сэмплинг действительно убивает лупы (rep16 0.43→0.001, hit 0.61→0.10) и не трогает поле (T-инвариантность). Это красиво. Но называть это «подписью дизера в чистом виде» — перебор.

- Дизер — это добавление шума **до** квантования с последующим вычитанием; его подпись — статистическая независимость ошибки от сигнала.
- T-сэмплинг — это **стохастическое квантование** (замена argmax на сэмплирование). Он ломает детерминированные циклы, но это может быть просто эффект стохастичности, а не именно dither-механизм.
- Фальсификатор T1a («после matching по subspace SNR и структуре ошибки ущерб всё равно объясняется только полной нормой») **не прогнан**.

**Что делать:** смягчить формулировку до «consistent with a dither-like mechanism» и оставить T1a гипотезой до прямого теста (дизер h-канала под квантованием весов, как предложено в самом ТЗ). Сейчас это инженерная аналогия, а не подтверждённый механизм.

### 1.6. T3: полиэдральные конусы только при отсутствии bias

Утверждение «ячейки argmax — точные полиэдральные конусы в h-пространстве» верно **только если в голове нет bias** и RMSNorm — чистая нормировка. В документе сказано «голова без bias», но это нужно **проверить по чекпоинту**, а не предполагать. Если bias есть, ячейки — полиэдры, но не конусы через начало координат; условия `(w_i − w_j)^T h ≥ 0` заменяются на аффинные.

**Что делать:** добавить в T3.1 проверку `bias is None` (или учесть bias в определении ячеек). Это влияет на символический граф и margin/flip-версию.

## 2. Сущности и знаки

### 2.1. Raw / projection / tangent — в целом корректно, но есть нюанс

Документы чётко разводят:
- `h_raw` — сырое состояние,
- `du_unit` — `Δu` (приращение единичного вектора),
- `v_tangent` — ортогонализованный тангенс направления.

Запрет 2 и G14 требуют координат (`field_object`, `field_stat`, `tangent_frame`) — это правильно и важно, потому что знак «горба» объектно-зависим: `+0.0121 v_tangent` vs `−0.0134 h_raw` / `−0.0137 du_unit`.

**Нюанс:** `r_v = 21.846` для `v_tangent` и `r_max ≤ 0.208` для `du_unit` — это не противоречие, а разные объекты. `v_tangent` когерентен (направление имеет сильное предпочтение), `Δu` мал и компенсируется. Это и есть «ритм». Но в тексте это стоит проговорить явно, иначе читатель может решить, что `r_v` и `r_du` должны быть согласованы.

### 2.2. Знак «dip» и «hump»

- «dip» — отрицательная корреляция на лаге 1 (`−0.167` для `dip_V,med`).
- «hump» — положительный excess на лагах 3–4 (`+0.0121` для `v_tangent`, но `−0.0134` для `h_raw`).
- Сумма по лагам положительна (`Σρ̄ = 10.4` для `v_tangent`), т.е. общий вклад — положительный, а «dip» — локальная отрицательная ямка.

Это корректно, но терминология «dip» может путать: это не «отрицательная площадь вообще», а локальный отрицательный лаг-1. В T0.3 знак периода-2 исправлен правильно (отрицательная площадь на нечётных k). Хорошо.

### 2.3. T0.1: «refuted на всех трёх» — уточнить направление

Модель DC+MA(1) отвергается на всех трёх объектах, но **знак отклонения разный**:
- `v_tangent`: excess `+0.00194` (плато выше модели),
- `h_raw` / `du_unit`: ≈ `−9e−5` (в нуле, чуть ниже).

Это не «одно и то же отклонение». В вердикте стоит писать: «модель отвергнута на всех трёх, но остаток положителен только на `v_tangent`; на `h_raw`/`du_unit` он в нуле». Иначе создаётся впечатление единого эффекта.

## B1. R² считается как отношение норм, а не R² ⛔ подтверждено

```python
pc = pred - ym
yc = y_all[d] - ym
cosv = (pc * yc).sum(1) / (...)
r2rows.append(1.0 - float((pc ** 2).sum()) / float((yc ** 2).sum()))
```

`pc` — предсказание (это видно по `cosv`). Значит

$$\text{«}R^2_c\text{»}=1-\frac{\|\hat y_c\|^2}{\|y_c\|^2}\quad\ne\quad R^2_c=1-\frac{\|y_c-\hat y_c\|^2}{\|y_c\|^2}$$

Артефакт при этом декларирует `"R2_c = 1 - SSE_c/TSS_c"` — **формула в мете и формула в коде разные**.

Численное следствие: «R²» 0.6656–0.7750 ⇒ ‖ŷ_c‖/‖y_c‖ = 0.474–0.578. Корректный R² при агрегированной корреляции ρ:

$$R^2_{\text{corr}}=2\rho\frac{\|\hat y_c\|}{\|y_c\|}-\frac{\|\hat y_c\|^2}{\|y_c\|^2}$$

При ρ=0 это **−0.225…−0.334**. Чтобы получилось >0, нужно ρ ≳ 0.24–0.29 — при медианном cos ≈ −0.02 это не показано.

**Заголовок прогона «центрированная метрика работает (R²_c > 0)» не обоснован.** Не исключено, что R² по-прежнему отрицателен везде, как в r1.

### B1b. Гейт S6b — тавтология ⛔

```python
tss = float(((y_all[d] - ym) ** 2).sum())
r2c = 1.0 - tss / tss
if not (tss > 0.0 and abs(r2c) < 1e-12): ...
```

`1 − tss/tss ≡ 0` по построению. Гейт проверяет только `tss > 0` и **никогда не запускает предиктор**. Комментарий обещает «константный предиктор in-sample ⇒ R²_c = 0», но предиктор не вычисляется.

Значит «floor в нуле» — не измерение, а определение. Именно поэтому S6b прошёл, несмотря на B1: он написан по правильной формуле аналитически, а основной цикл — по неправильной. Две реализации одной статистики, ровно как `sign_test` в AT3.

## B2. Обучающая цель LOO не центрирована ⛔ подтверждено

```python
y_all = z_U128[:, :n, :]                     # сырые логиты
yf = np.vstack([y_all[d2] for d2 != d])      # БЕЗ вычитания ȳ(d2)
...
ym = y_all[d].mean(0)
pc = pred - ym
```

`Xf` центрирован per doc, `yf` — нет. Intercept впитывает `ȳ_f` (глобальное среднее), и

$$pc_t = W X_t + \underbrace{(\bar y_f - \bar y(d))}_{c(d)}$$

**S6 это документирует, а не ловит:** гейт проверяет `intercept ≈ mean(y_f)` — то есть прямо подтверждает, что цель сырая.

Для k=0 (`X` центрирован точно, `Σ_t X_t = 0`) алгебра замыкается:

$$\|pc\|^2=\|WX\|^2+T\|c\|^2,\qquad \sum_t yc_t=0$$

$$R^2_{\text{corr}}=\frac{2\langle yc,WX\rangle-\|WX\|^2-T\|c\|^2}{\|yc\|^2}$$

Смещение **штрафует** корректный R² на `T‖c‖²/‖yc‖²` и **искажает cos**.

Критично для контроля: `c(d)` **одинаков для всех армов** при данном (L,k,d) — `yf` и `ym` от арма не зависят. Но cos нелинеен, и общий аддитивный вектор **не сокращается** в разности `cos_top − cos_weak`:

- при ‖c‖ ≫ ‖WX‖ оба cos → cos(c, yc), разность → 0 ⇒ **L12 CI содержит 0**;
- при разном выравнивании сигналов с c один арм выигрывает случайно ⇒ **L6 инверсия**.

То есть B2 сам по себе объясняет обе провальные клетки. Диагностика C2 через `cos` это поймает; через `R²` — нет, потому что diag повторяет ту же формулу (`r2rows_cd` тоже `pc_cd**2`).

## B3. `weak_i` выбирает собственные значения **ниже** порога ⇒ weak-базис может быть координатными осями ⛔

```python
n_nz = int((lam > 1e-12).sum())
top_i  = np.argsort(lam)[::-1][:r_final]
weak_i = np.argsort(lam)[:min(r_final, n_nz)]
```

`min(r_final, n_nz)` ограничивает **количество**, но не запрещает брать значения ≤ 1e-12. Если `n_nz < 128` (а `G = √P·JJᵀ·√P` с softmax-весами почти наверняка имеет огромный динамический диапазон), то наименьшие 7 лежат **среди отброшенных**.

Дальше в `_lift_arr`:

```python
V = np.zeros((D, len(idxs)), dtype=np.float32)
for j, i in enumerate(idxs):
    if lam[i] > 1e-12:
        V[:, j] = ...
return _qr(V)
```

Все колонки остаются нулевыми → `np.linalg.qr(zeros((1024,7)))`. LAPACK `dgeqrf` на нулевой матрице даёт `tau=0`, `dorgqr` возвращает **`Q = I[:, :7]`** — первые семь координатных осей.

Следствия, если это так:

1. **weak-базис фиксирован** (одинаков для всех d и t), а top — вращается. Контроль сравнивает вращающийся базис с фиксированным ⇒ это ровно C1, но с конкретной причиной, а не с «конфаундом вообще».
2. weak ведёт себя как случайный фиксированный базис ⇒ **Haar-аномалия перестаёт быть аномалией**.
3. `d_eff_of(Vweak0, Hdoc)` при R=32 берёт `range(0,32)` — те же ниже-пороговые ⇒ d_eff считается для первых 32 координатных осей. Rematching `r_final = round(min(deff))` ⇒ **выбор r=7 тоже загрязнён**.

Правильный отбор — наименьшие **среди ненулевых**:

```python
nz = np.where(lam > 1e-12)[0]          # lam отсортирован по возрастанию
weak_i = nz[:r_final]
```

**Решающая проверка, почти бесплатная:**

```python
n_nz_per_cell = (lam > 1e-12).sum()
n_dead_weak   = (lam[weak_i] <= 1e-12).sum()
is_axes       = np.allclose(V_weak, np.eye(1024, r_final), atol=1e-6)
E_real        = ||sp[:,None] * (jr @ V_weak)||_F²   vs   lam[weak_i].sum()
```

Если `n_dead_weak > 0` и `is_axes` — weak-арм не «слабо наблюдаемый», а фиксированные оси. Тогда `SUBSPACE_CONTROL_FAIL` — артефакт построения базиса.
