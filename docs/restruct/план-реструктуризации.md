# Реструктуризация «Моста Якобиана»: план (предложение)

**К чему применимо:** `paper.md` v4.0 (2 343 строки, ~344 КБ).
**Принцип:** основной файл отвечает на вопросы «что исследовано, как, зачем, с каким результатом, что дальше» и достаточен для обсуждения и оценки развития; всё остальное — в справочные документы, доступные по стабильным ID (`E-*`, `L-*`, `H-*`).

---

## 1. Диагноз: почему разрослось

Замер по секциям (тыс. знаков):

| Блок | Объём | Доля |
| --- | --- | --- |
| Часть V. Эмпирика (карточки E-*) | 111 | 47% |
| Часть VI. Синтез (§20–§22) | 27 | 11% |
| Часть II. Математика (§4–§8) | 24 | 10% |
| Приложения A–E (глоссарий, индекс, листинги, доказательства) | ~47 | 20% |
| Части I, III, IV (постановка, метод, инфраструктура) | 22 | 9% |
| Шапка + статус + оглавление | 3 | 1% |

Корневые причины (не «много контента», а **смешение жанров**):

1. **Четыре жанра в одном файле.** (а) научная записка «что мы узнали»; (б) формальная спецификация (леммы, определения, конвенции); (в) инженерный журнал (версионные исправления: «v6.0», «это исправляет неверные формулы», P0-баги, история v3.3→v4.0); (г) реестр экспериментов (протоколы, JSON-артефакты). Жанр (а) — то, что нужно для чтения; (б)–(г) — справочные.
2. **Дублирование фактов.** `g_uni`, `r_eff`, `sentinel` определены по 3–4 раза каждая (две таблицы §2, §6, §8, Приложение A); семантика пулляции ESG — в §6 и §11; вердикты экспериментов — в карточках Части V, в §20 и в примечаниях B.1. Каждое дублирование — будущая эволюция в противоречие.
3. **Версионная археология в тексте.** §22 «Future work» = 16 КБ, из которых большая часть — зачёркнутые выполненные пункты с историями («выполнен как E-32r.2 → завершён профилем E-32r.3 → …»). Это changelog, а не план.
4. **Навигационный дрейф.** Оглавление обещает приложения A–C, реально их пять (D «Формулы E-34», E «Доказательства [M-1]–[M-5]» не заявлены).
5. **Раздутые секции-аккумуляторы.** §18 (56 КБ, 24% файла) — свалка «карты чувствительности»: туда попали и спектр E-9, и gauge-анатомия E-33r/E-36/E-37, и Гессианы E-32r*, и defrag E-11*. Секция выросла вокруг заголовка, а не вокруг вопроса.

## 2. Целевая архитектура: 4 файла

```
paper/
├── paper.md            ← основной файл (цель: ~35–40 КБ, 12–15% текущего объёма)
├── math.md             ← формальный аппарат + все определения символов (~35 КБ)
├── experiments.md      ← полный реестр экспериментов (~135 КБ, архивный)
└── implementation.md   ← инженерия, воспроизводимость, код (~30 КБ)
```

| Файл | Жанр | Вопрос читателя | Состав (источник в v4.0) |
| --- | --- | --- | --- |
| **paper.md** | записка | «Что исследовано, что вышло, что дальше?» | Новый текст + §1, §20, §21, §22 (без истории) |
| **math.md** | спецификация | «Как именно определено X? Докажи» | §4–§8 + §2 (единая таблица символов) + Прил. A, D, E |
| **experiments.md** | реестр | «Как проверяли, где артефакты?» | §14 (гид) + Часть V (карточки дословно) + Прил. B + changelog |
| **implementation.md** | журнал | «Как воспроизвести, какие подводные камни?» | §3 + §9 + §12 + §13 + Прил. C (листинги) |

Правило принадлежности: **каждый новый абзац имеет ровно один дом** — по жанру, а не по теме. Тема не определяет файл; жанр определяет.

## 3. Состав основного файла paper.md

Восемь секций, все существующие ID сохраняются:

1. **Статус** (существующая шапка, без изменений) — P0–P3 тремя строками.
2. **Цели и результаты по приоритетам** — текущая §1 дословно (она уже делает ровно то, что нужно) + новая компактная таблица «Утверждение → статус → ID» (слив §20 «Подтверждено» + реестра H1–H8, одна строка на гипотезу).
3. **Как устроен метод** (новая, ~5–6 КБ) — цепочка из 6 шагов: `J → проекция в словарь → Gramian-коррекция → gap/bridge → ESG / gauge-free E_K → bridge-лосс (P2)`. Каждому шагу — 2–3 предложения без формул-доказательств; ссылки `[L-*] → math.md`. Плюс **мини-глоссарий** (15–18 строк): только символы, реально встречающиеся в paper.md, с пометкой «полный индекс — math.md §Символы». Плюс фиксация позиции `t = S−1`.
4. **Программа экспериментов: что исследовано и что найдено** (новая, ~12–15 КБ) — 7 тематических блоков вместо текущих §15–§19:

   | Блок | Вопрос | Эксперименты |
   | --- | --- | --- |
   | 4.1 Корректность цепочки | Считаем ли мы то, что думаем | E-1, E-3, E-5, E-8 |
   | 4.2 Карта bridge | Как выравнивание устроено по глубине | E-2, E-4, E-6, E-6b, E-7, E-13, E-15 |
   | 4.3 Фундамент поля J | Когерентность, sample-local, домены | E-0.1, E-27.5/27.6, E-31 |
   | 4.4 Листы и кривизна | Настоящая ли локальная геометрия | E-28, E-35 |
   | 4.5 Спектр, ранги, gauge | Что несёт ESG, где живёт gauge | E-9, E-10a–d, E-14, E-33r, E-36, E-37 |
   | 4.6 Первый порядок и cross-talk | Диагональность ESG, Гессиан | E-34, E-30, E-30b, E-32r.2–r.3.1, E-32-tail |
   | 4.7 Прикладной контур | Квантование, causal lever | E-11a–c, E-12a–c, E-16a, E-16b |

   Формат блока (жёсткий, ~12–18 строк каждый):
   - **Вопрос** — одна строка.
   - **Как проверяли** — 1–2 строки (протокол в карточке).
   - **Вердикт** — 2–4 предложения, самая осторожная формулировка (правило уже есть в §20).
   - **Ключевые числа** — 2–4, не больше.
   - **Валидирует** — ссылки на леммы/гипотезы; **Карточки** — `E-* → experiments.md`.

5. **Итоговая картина** — из §20: таблицы «Подтверждено» и «Не подтвердилось» дословно (это уже готовый синтез), «Практические следствия» — сжато до 5 строк.
6. **Ограничения** — §21 сжать до ~2.5 КБ: по 2–3 пункта на группу (a/b/c), каждая строка = ограничение + чем смягчено (ID). Детали остаются в карточках.
7. **Открытые вопросы и roadmap** — §22 **без зачёркнутой истории**: только живые пункты (Exp 17 full, Exp 18 downstream, Exp 19 calibration, N≥32 для H1–H5, GPU-режим, P3) с оценкой стоимости и зависимостями («что блокирует что»). История выполненного — одна строка «см. experiments.md §Changelog».
8. **Карта документов** (новая, полстраницы) — какой файл за что отвечает, конвенция ссылок, правила обновления (см. §5 ниже). Гарантирует, что читатель одного файла знает, где лежит остальное.

## 5. Правила против повторного разрастания

1. **Жанровая граница.** В paper.md запрещены: код, протоколы, полные таблицы метрик, истории исправлений, новые определения символов. Разрешено: вердикт + 2–4 числа + ID-ссылки.
2. **Один факт — одно место.** Канонические определения — только в math.md. experiments.md и implementation.md ссылаются, не переопределяют. (Сейчас «дублирование определений намеренно исключено» заявлено в §2, но нарушено самой §2.)
3. **Протокол обновления.** Новый эксперимент → (1) карточка в experiments.md → (2) одна строка-вердикт в тематический блок paper.md → (3) строка в таблицу «Подтверждено» → (4) при необходимости H-* в реестр. Обратный порядок запрещён.
4. **Changelog, а не археология.** Всё «это исправляет», «раньше было», «v3.3→v4.0», зачёркнутые пункты — в §Changelog experiments.md. В рабочих секциях — только текущее состояние.
5. **Бюджет размера.** paper.md ≤ 40 КБ (контроль при каждом релизе; превышение — повод для нового справочника, а не для «ещё чуть-чуть»).
6. **Ссылки только по стабильным ID.** Между файлами: `experiments.md#E-28`, `math.md#L-gram`, якоря вида `#e-28` в заголовках карточек. Внутри одного файла — якоря. Нумерация секций paper.md не используется в ссылках (правило уже сформулировано в v4.0 — расширить на межфайловые ссылки).
7. **Версия.** Предлагаю v4.1 (реструктуризация без изменения утверждений) с одной строкой в changelog. Содержательные правки, неизбежно всплывшие при дедупе, фиксировать отдельно — они не должны маскироваться под «переезд».

## 6. Риски и как закрыты

- **«Один файл недостаточен без справочников».** Мини-глоссарий + вердикты с числами + карта документов закрывают чтение и обсуждение; справочники нужны только для проверки доказательств и воспроизведения.
- **Потеря контекста при разрезе.** Карточки переезжают дословно — ничего не перефразируется. Единственный авторский текст — блоки 4.1–4.7 и §3 метода, и они пишутся только из существующих вердиктов.
- **Битые ссылки.** Финальный шаг — скрипт проверки: извлечь все `E-*`, `L-*`, `H-*` из paper.md и убедиться, что каждый существует в справочниках; отчёт о несогласованных ID и дублирующихся определениях.
- **Дедуп как источник ошибок.** При слиянии таблиц символов правка фиксируется в changelog построчно (какая строка куда канонизирована).

## 7. Порядок исполнения

1. **Механический разрез** (без правок): карточки → experiments.md; листинги + §3/§9/§12/§13 → implementation.md; §4–§8 + Прил. A/D/E → math.md. Самый безопасный шаг, результат уже снимает 60% нагрузки с основного файла.
2. **Дедуп math.md**: слияние таблиц §2, глоссария; вынос версионных вставок в changelog.
3. **Написание paper.md заново** (не подстриганием!): резюме, метод, блоки 4.1–4.7, синтез, ограничения, roadmap, карта документов.
4. **Проверка целостности**: скрипт сверки ID + бюджет размеров + оглавления всех четырёх файлов.
5. **Версионный коммит**: v4.0 → v4.1, changelog-строка.

Пункты 1–2 механические; пункт 3 — редакторская работа, которую стоит обсудить после просмотра разреза.
