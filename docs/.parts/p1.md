# Часть I. Постановка

## 1. Мотивация, цели, статус

**Суть метода.** Даны две модели одного семейства (Qwen3.5-4B и Qwen3.5-0.8B), общий словарь. Метод сравнивает **чувствительность декодирования** — то, как скрытые состояния каждой модели влияют на финальные логиты. Сравнение происходит через пространство словаря, которое является общей системой координат для обеих моделей.

**Ключевая интуиция.** Для задач с softmax-выводом важны не все компоненты скрытого состояния, а только их проекция на пространство, реально влияющее на выходные вероятности. Математически это выражается через Якобиан `∂p/∂h_l`: он кодирует, какие направления в `h_l` двигают распределение выходов, а какие — нет.

**Цели (по приоритету):**

| Приоритет | Цель | Что получаем | Статус |
| --- | --- | --- | --- |
| **P0** | Диагностика: послойная карта расхождения Якобианов (`𝓛_bridge`) | Тепловая карта по слоям | см. E-1 (identity), E-2 (карта), E-5 (ESG-валидация) |
| **P1** | Карта чувствительности для квантования: какие направления защищать | Правые сингулярные векторы `J^T J` (hidden space); ESG = `JJ^T` (token space) | см. E-12b,c (ESG validated) |
| **P2** | Трансформация младшей модели | Лосс для оптимизации | гипотеза, отложено (H4) |
| **P3** | Регуляризатор при дообучении | Дополнительный лосс | гипотеза, отложено (H4) |

P0 и P1 — реализованные уровни; P2/P3 отложены до дополнительных исследований. P0 и P1 — разные артефакты: P0 показывает, насколько `J_S` отличается от `J_S_target`, P1 — какие направления hidden state наиболее чувствительны.

> **Фиксация позиции.** Если не указано иное, все карты чувствительности и Якобианы вычисляются для последнего токена последовательности: `t = S-1`.

## 2. Соглашения и обозначения

Индекс символов: пространство (token vs hidden), тип, каноническое определение (ссылка). Дублирование определений намеренно исключено.

| Символ | Пространство/тип | Значение | Определение |
| --- | --- | --- | --- |
| `M_L`, `M_S` | — | старшая/младшая модель | §4 |
| `D_L`, `D_S` | скаляр | hidden size (`D_S < D_L`) | §4 |
| `n_L`, `n_S` | скаляр | число слоёв | §4 |
| `V` | скаляр | размер словаря | §4 |
| `E` | матрица `V×D` | матрица эмбедингов; строка `E[i]` — эмбединг токена `i` | §4 |
| `W` | матрица `V×D` | матрица анэмбединга; при tied weights `W = E` | §3, §4 |
| `J_l^(t)` | матрица `V×D` | Якобиан логитов по скрытому состоянию слоя `l`, позиция `t` | §4 |
| `J` | матрица `K×D` | Якобиан, урезанный на набор токенов `𝒰` | §4 |
| `J^(p)` | матрица `K×D` | gauge-free Якобиан (оператор `P(p)` на `J`) | §8 |
| `D_l(x)` | матрица `D×D` | слой-переходный Якобиан `∂h^(l+1)/∂h^l` | §4 |
| `G_S^-1` | матрица `D×D` | `pinv(E_S^T E_S)`, Gramian-коррекция | §5 |
| `𝒮` | множество | глобальный набор токенов, `K = |𝒮| ≤ K_max` | §12 |
| `p_L` | вектор `K` | вероятности токенов в распределении старшей модели, нормированные на `𝒮` | §7 |
| `p_U` | вектор `K` | softmax логитов, урезанный и ренормализованный на `𝒮` | §8 |
| `w_i` | скаляр | вес строки: `p_L(i) / Σ_{j∈𝒮} p_L(j)` | §7 |
| `τ_l` | скаляр | относительный порог sentinel: `0.01 · median_i ‖J_S[i]‖` | §7 |
| `𝓖_gap(l)` | скаляр | разрыв Якобиана (lower = better), `∈ [0,2]` | §7 |
| `𝓑_bridge(l)` | скаляр | мост (weighted cos, higher = better) | §7 |
| `s(l)` | скаляр | метрика масштаба `log(‖J_S‖_F / ‖J_S_target‖_F)` | §7 |
| `Ḡ_l` | матрица `K×K` | Empirical Sensitivity Gramian (ESG), `K` = token space | §6 |
| `σ_1 ≥ σ_2 ≥ …` | скаляры | сингулярные значения `J^(p)` | §6 |
| `uniformity(u)` | скаляр `∈ [0,1]` | доля направления `u` вдоль uniform-режима `𝒮`; определён только для векторов token-пространства | §6 |
| `g_uni` | скаляр | `‖Q J‖_F² / ‖J‖_F²`, `Q = uu^T`, `u = 1/√K` — доля энергии **сырого** `J` в uniform-режиме (убиваемая gauge-часть) | §8 |
| `gauge_share` (ESG) | скаляр | `σ_1² · uniformity(u_1) / Σ_i σ_i²` — доля энергии `J^(p)` на gauge-направлении | §6 |
| `r_eff` | скаляр | эффективный ранг: энтропический `exp(−Σ p_k log p_k)`; вторичные — stable rank, participation ratio | §6, §15 |
| `r_KL` | скаляр | функциональный ранг: минимальное `r`, при котором KL defrag-r аппроксимации совпадает с KL полной `J^(p)` | §6 |
| `u_g`, `v_g` | векторы | левый (token) / правый (hidden) сингулярный вектор `J`, максимизирующий `|cos(u_g, 1)|` | §8 |
| `P(p)` | матрица `K×K` | gauge-оператор `diag(p) − pp^T` (якобиан softmax; **не проектор**) | §8 |
| `F` | скаляр | шумовой пол `1/√(r_eff (K + D − r_eff))` | §15 |
| `C_a`, `C_b` | скаляры | когерентность position-пар / sample-пар | §15 |
| `T_domain` | скаляр | `C_within − C_cross` (междоменная разность) | §15 |

**Пространства.** Token-пространство — векторы длины `K` (направление `u`, ESG-собственные векторы `JJ^T`). Hidden-пространство — векторы длины `D` (`v`, правые сингулярные векторы `J^T J`). Uniformity определён только для векторов token-пространства; применять его к `v_g` (hidden) — ошибка.

**Обозначение «𝒮» против «𝒰».** В v3.3 набор токенов обозначался `𝒰`; в v4.0 мы используем `𝒮` (support), чтобы не путать с `U` из спектрального разложения ESG (§6) и `U_r` из defrag (§6). В JSON-артефактах ключи не переименованы.

## 3. Архитектурный контекст: Qwen3.5

Архитектурные факты, влияющие на корректность вычислений. Производные — в §8.

**Гибридная архитектура.** `config.layer_types[layer_idx]` определяет тип слоя: `"full_attention"` → `Qwen3_5Attention` (GQA); `"linear_attention"` → `Qwen3_5GatedDeltaNet` (GDN). Типы чередуются.

**GDN: рекуррентное состояние.** GDN поддерживает рекуррентное состояние `S_t ∈ R^{H × D_k × D_v}`:

```
S_t = g_t * S_{t-1} + k_t * delta_t^T
output_t = S_t * q_t
```

Кэш GDN содержит `conv_state: [1, conv_dim, conv_kernel_size − 1]` и `recurrent_state: [1, num_v_heads, head_k_dim, head_v_dim]`. GDN — не трансформер: обратный проход идёт через рекуррентную цепочку, а не через attention-матрицы.

**Мутация кэша.** `torch_causal_conv1d_update` мутирует `conv_state` in-place (`conv_state.copy_(...)`); GDN обновляет `recurrent_state` через `cache_params.update_recurrent_state(...)`. Поэтому `copy.deepcopy(prefix_cache)` **не работает** для GDN-слоёв — используется `_deep_clone_cache()` (ручной клон всех тензоров), см. §9 и Приложение C.

**Tied weights.** `_tied_weights_keys = {"lm_head.weight": "model.embed_tokens.weight"}` — т.е. `W = E`, и проекция через `E` корректна для логитов.

**MRoPE.** Multi-dimensional RoPE с `position_ids` формы `[4, B, S]` (text, temporal, height, width); для текстового входа все 4 компоненты одинаковы. При вычислении Якобиана для последнего токена с кэшем: `position_ids = S − 1`.

**RMSNorm — не идентичность.** `Qwen3_5RMSNorm`: `output = (x / rms(x)) * (1 + weight)`; вес инициализирован нулями, поэтому на старте `1 + w = 1` и RMSNorm — чистая нормализация `y = x/RMS(x) ≠ x`. Производная — §8 `[L-rms]`.

**Ограничения версии 1:** CPU (Intel Iris Xe / SYCL, 64 GB, `torch.set_num_threads(4)`, float32 — fp16 на CPU на порядок медленнее); текстовый вход (`Qwen3_5ForCausalLM`); `model.model` — `Qwen3_5TextModel` (единый путь доступа ко всем размерам); в экспериментах — Qwen3.5-4B (32 слоя, `D_L = 2560`) и Qwen3.5-0.8B (24 слоя, `D_S = 1024`).
