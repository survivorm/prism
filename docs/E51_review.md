## P0-1: контроль I2 несоответствует данным (тихая ошибка, ломающая валидацию)

### Контроль

```python
rngp = torch.Generator().manual_seed(9)
pl = []
for x in vv:
    zz = nz(torch.randn(D, dtype=torch.float64, generator=rngp))   # ← случайный
    zz = nz(zz - x * (x @ zz))
    pl.append(torch.stack([x, zz], 1))
```

`zz_t` — **независимый случайный** ортогональный вектор на каждом `t`. Тогда `pl[t]ᵀ · pl[t+1]`:

```text
[[<vv[t], vv[t+1]>, <vv[t], zz_{t+1}>],
 [<zz_t, vv[t+1]>, <zz_t, zz_{t+1}>]]
```

Для geo: диагональ (1, ~0), off-диагональ (случайные ~0). `det ≈ ε3` — случайный знак. Product of 3 dets — случайный знак. `I2_mean ≈ 0`.

### Данные

```python
def leaf_bases(x, A, eps):
    ...
    v2 = nzr(J.T @ Ue[:, -2])          # ← детерминирован
    v2 = nzr(v2 - v1 * (v1 @ v2))
```

`v2` — **детерминированная** вторая главная мода J, ортогонализованная к v1. Если J гладко зависит от x, `v2(t)` гладко зависит от t. Тогда `pl[t]ᵀ · pl[t+1]` — гладкая 2×2 матрица, `det` имеет **устойчивый знак**, `I2_mean` может быть ±1.

### Итог

Контроль валидирует I2 на **несогласованных** `pl`, поэтому «I2_mean ≈ 0 для white» проходит **не потому что** I2 детектирует white, а потому что **обе** выборки дают случайный знак. Контроль не отличает «I2 ≈ 0 = нет сигнала» от «I2 ≈ 0 = плохой контроль».

Для данных I2_mean может быть **±0.8–1.0** (детерминированная хиральность) — и вы не знаете, валиден ли этот сигнал, потому что контроль не подтверждает поведение I2 на coherent case.

### Fix

Контроль должен использовать **coherent** `pl` — детерминированную функцию от `t`, как в данных. Для geo:

```python
# Ортонормированный 2-фрейм, вращающийся вместе с геодезической
u0, w0 = ...  # базисные направления геодезической
theta = 0.012
pl = [torch.stack([u0*math.cos(theta*t) + w0*math.sin(theta*t),
                   -u0*math.sin(theta*t) + w0*math.cos(theta*t)], 1)
      for t in range(T)]
```

Тогда `pl[t]ᵀ · pl[t+1]` — матрица поворота на θ, `det = 1` на каждом шаге. `I2_mean = +1` ровно.

Для white — `pl` из QR случайных матриц `[D, 2]`, но **без** принудительной ортогональности `zz_t` к `vv[t]` через случайный zz. Или лучше — white с **coherent** `pl` (например, `v2 = parallel transport v2_0 along white v1`), чтобы I2 ловил только «нет гладкости v1», а не «zz случайный».

**Гейт после фикса:**
```python
and abs(res["geo"]["I2_mean"] - 1.0) < 0.1   # coherent -> +1
and abs(res["white"]["I2_mean"]) < 0.15       # incoherent -> 0
```

Без этого гейта на geo `I2_mean` не валидирован, и I2 в данных интерпретировать нельзя.

## P0-2: Вердикт не pre-registered

Docstring говорит:

> ВЕРДИКТ (предрегистрирован): инвариант выживает, если |real − swap| вне bootstrap-CI swap И знак стабилен минимум в 3/4 доменов.

Код:

```python
verdict[f] = ("directional+ordering" if sig["sur"] and sig["sw"] else
              "directional(order-free)" if sig["sur"] else
              "local-ordering" if sig["sw"] else
              "long-range-only" if sig["sh"] else "null-compatible")
```

Это **другая** классификация, с другими категориями. Она не описана в docstring и не была pre-registered.

**Проблема:** если данные покажут `directional+ordering` для I1, вы не сможете утверждать, что это «предсказано» — категория не была определена заранее. Это подрывает научную валидность, а не только стиль.

**Fix:** либо вернуть старый бинарный вердикт (`survives` / `null-compatible`) как основной, а multi-category — как **вторичную диагностику**; либо **обновить docstring** с явным определением каждой категории:

```text
- "directional+ordering": sur-нуль значим (не step-random) И sw-нуль значим
                          (локальный порядок важен) — сильнейшая структура;
- "directional(order-free)": sur значим, sw не значим — траектория не step-random,
                             но локальные перестановки не ломают — гладкая структура;
- "local-ordering": sw значим, sur не значим — сигнал в локальном порядке,
                    но по масштабу шага не отличим от random;
- "long-range-only": sh значим, sur/sw не значимы — только дальний порядок;
- "null-compatible": ничего не значимо — случайная динамика.
```

И делать это **до** первого запуска на данных.

## P0-3: «3/4 доменов» из docstring не реализовано

Docstring: «знак стабилен минимум в 3/4 доменов». Код:

```python
for f in FIELDS:
    sig = {}
    for n in NULLS:
        d = [x for rows in rep.values() for x in paired(rows, f, n)]
        ...
        sig[n] = lo is not None and lo * hi > 0
```

`paired()` собирает `d` **по всем доменам вместе** и проверяет CI по объединённой выборке. `summ[dom]` есть для каждого домена — но вердикт по домену **не выносится**. Критерий из docstring отсутствует.

**Fix:** либо добавить проверку по доменам:
```python
dom_sig = {n: sum(1 for dom, rows in rep.items()
                  if ci_for(paired(rows, f, n)) не содержит 0) for n in NULLS}
# "survives" только если dom_sig[n] >= 3 для n=sur (и опционально sw)
```

либо убрать «3/4 доменов» из docstring (не реализовано — не обещать).

Без этого читатель может подумать, что эффект подтверждён, хотя он может быть в одном домене и отсутствовать в остальных (как E-13 в paper.md — домены сильно расходятся).

## P1-1: `leaf_bases` — `v2` шумит при rank-deficient J

```python
v1 = nzr(J.T @ Ue[:, -1])
v2 = nzr(J.T @ Ue[:, -2])
```

Если `J` в позиции `t` имеет **rank 1** (например, из-за RMSNorm или вырожденной структуры), `Ue[:, -2]` соответствует **нулевому** singular value — это произвольный вектор в нуль-пространстве, шум. Тогда `v2(t)` шумит, `pl[t]ᵀ · pl[t+1]` становится случайным, и **I2 в этой позиции случайно ±1** — шум в I2_mean.

В paper.md `[L-rms]` явно сказано: «произведение `∏D_i` вырождено». То есть **J может быть низкоранговым** для некоторых позиций.

**Fix:** фильтровать позиции по `σ2`:
```python
sig_full = torch.sqrt(torch.linalg.eigvalsh(Gm).flip(0).clamp(min=0))
if sig_full[1] < 0.01 * sig_full[0]:  # σ2/σ1 < 1%
    # rank-deficient, v2 = noise
    v2 = None  # или пропустить позицию
```

Или в `bundle` отчитываться `frac_rankdef` = доля позиций с `σ2/σ1 < 0.01`. Если `frac > 0.2`, I2 интерпретировать нельзя.

Также стоит логировать `eigengap(σ1/σ2, σ2/σ3)` в summary — если `σ2 ≈ σ3`, вторая мода не стабильна, I2 шумит.

## P1-2: `surrogate_lines` — seed зависит от порядка вызовов

```python
vs = E50.synth_white_matched(Vs, D, 1, len(v1s), int(rng.integers(1 << 30)))
...
rg = torch.Generator().manual_seed(int(rng.integers(1 << 30)))
```

`rng` — глобальный, состояние накапливается. Порядок вызовов `swap_idx`, `rng.permutation`, `surrogate_lines` определяет, какой seed получит surrogate для документа `k`. Если кто-то изменит порядок (например, поставит `sh` перед `sw`), числа **изменятся**, хотя данные те же.

**Fix:** детерминированный seed от ключа:
```python
def surrogate_lines(v1s, key, j):
    seed_step = int.from_bytes(hashlib.sha256(f"{key}_sur{j}_step".encode()).digest()[:8], 'little')
    seed_orth = int.from_bytes(hashlib.sha256(f"{key}_sur{j}_orth".encode()).digest()[:8], 'little')
    vs = E50.synth_white_matched(Vs, D, 1, len(v1s), seed_step)
    rg = torch.Generator().manual_seed(seed_orth)
    ...
```

Тогда вызовы `sur0`, `sur1` для разных документов независимы и воспроизводимы без зависимости от порядка.

## P2 — мелкие

- **`np.abs` для 0-мерного тензора:**
  ```python
  dev = float(np.abs(T.T @ T - torch.eye(D)).max())
  ```
  работает, но `np.abs` на 0-мерном тензоре делает копию в numpy. Чище:
  ```python
  dev = float((T.T @ T - torch.eye(D)).abs().max())
  ```

- **`gauge_dev` — только в конце, не max по циклу:** если дрейф накапливается монотонно, финальное значение = max. Но если есть «возврат» (например, ошибка компенсируется), финальное значение может быть маленьким при больших промежуточных. Для r=1 и D=1024 маловероятно, но для `r ≥ 2` в будущем — стоит проверить. Оставить как есть — ОК для r=1.

- **`I4 drift` не используется:** `inv_I4` возвращает `drift` (уход главной оси), но в `bundle` только `e` сохраняется. Потенциально полезный сигнал — либо использовать, либо убрать из возврата.

- **`I2_signfrac` — уже убран** (заменён на `I5_tau_s1` в `summ[dom]`), хорошо.

- **`surrogate_lines` — `zz` per `t` случайный, не coherent**: но это **правильно** для surrogate — surrogate должен давать «случайную динамику», поэтому incoherent `pl` — цель. Мой P0-1 про **контроль** geo/white, а не про surrogate.
