## 1. Правило канона (то, что вводится этим ТЗ)

1. **Каждый номер эксперимента, присутствующий в `experiments/`, обязан иметь след в
   `docs/ref-exp.md`**: либо карточку `E-NN`, либо явную строку в разделе
   «Код без следа запуска» (см. §3, класс B). Номер без следа = дефект, который ловит чек (§5).
2. **В карточке числа берутся только из артефакта/лога** (`results/…`, `logs/…`, `paper.md`-строка,
   указывающая на артефакт). Если артефакта нет — карточка пишет «числа не сохранены», а не оценки.
3. **Никаких новых выводов.** Задача — восстановить провенанс и адреса, а не пересчитать науку.
   Если артефакт противоречит `paper.md` — это фиксируется находкой (класс C) и уходит в отдельную
   волну, `paper.md` в этом ТЗ **не правится**.
4. Обратное направление (карточка без кода) — допустимо только с явной пометкой «не выполнено» /
   «в работе» / «Stage-0».

## 2. Класс A — 6 номеров с артефактами, канон молчит

Цель: карточки `E-17`, `E-18`, `E-47`, `E-52`, `E-57`, `E-61` в `docs/ref-exp.md`, собранные
**по артефактам**, с указанием файлов, размеров и дат.

Требования к каждой карточке:
- строка «Артефакт:» со списком `results/*` (имя + размер), лог — если есть (`exp47*` есть);
- «Постановка:» — из скрипта (`experiments/**/expNN*.py`, указать файл и ключевые константы);
- «Числа:» — только то, что физически лежит в артефакте; каждая цифра с именем файла;
- «Где опубликовано:» — `paper.md:строка` если упоминается (у 47, 52, 61 упоминания есть);
- «Статус канона:» — «карточка восстановлена по артефакту (инвентаризация <дата>)».

Если по номеру артефактов несколько версий (`exp52a_*` 16 файлов) — карточка перечисляет их
таблицей (файл → что внутри по ключам JSON), без агрегирования «средних по файлам».

## 3. Класс B — 20 номеров, 41 скрипт, нет ни артефактов, ни логов

Цель: раздел «Код без следа запуска» в `docs/strayed_experiments.md` — одна таблица:

`номер | каталог | скриптов | что делает (по docstring/аргументам, 1 строка) | следы в доках (ref/paper/иные) | рекомендация`

Рекомендации — ровно три допустимые формулировки:
- `перезапуск возможен` — если скрипт самодостаточен и данные на месте (проверить `argparse`/
  входные пути и наличие входов);
- `перезапуск под вопросом` — входные данные/модели недоступны (Kaggle-выгрузки, LFM3 и т.п.);
- `код мёртв` — нет входов, дубль другого номера, или заменён более поздним экспериментом.

Для `63` (9 скриптов) и `55` (5) — отдельные подтаблицы: это самые крупные «мертвецы».

Никаких удалений файлов в этом ТЗ. Удаление/архивация — отдельное решение пользователя.

## 5. Критерии приёмки (проверяемые, не «на глаз»)

Скрипт-чек `experiments/canon_inventory_check.py` (новый, ~40 строк, без сети/GPU) печатает:

- `numbers_without_trace` = **0** (для 20 «мёртвых» — засчитывается строка в разделе «Код без
  следа запуска», для 6 — карточка `E-NN`);
- `cards_without_code` ⊆ {`E-0.1`, `E-62`, `E-63`, `E-64`, `E-83`, `E-85`};
- числа в новых карточках **есть в артефактах**: для каждой цифры, помеченной `[art]`, чек ищет её
  форменное вхождение в указанном `results/`-файле (строковое сравнение значения в JSON).

Чек печатает итог двумя строками (`numbers_without_trace=0`, `cards_ok=1`) — эти строки идут в
отчёт как доказательство (маркер `INVENTORY_DONE` в конце отчёта и в конце вывода).

4. Внешнее ревью КОДА/артефакта (не только ТЗ): `docs/dynamic/CANON_INVENTORY_REVIEW.md`,

5. Коммит: `git add` тремя явными путями + чек-файл. `paper.md` не трогать.

## 7. STOP-условия

- Артефакт есть, но JSON битый/пустой → STOP по этому номеру, запись в NOTES, карточка не пишется
  «по памяти».
- Число в артефакте не совпадает с `paper.md` → STOP, фиксируется как находка класса C;
  `paper.md` не правится в этой волне.
- Для «мёртвого» номера находится след запуска (лог/артефакт вне `results/`) → номер
  переклассифицируется в класс A.
