# ТЗ на серию экспериментов E-38 (День 1)

**Обозначения.** Базовый номер — 38. Буквы — по финальному протоколу «Дня 1» (14-1/14-3). Порядок букв соответствует логическому порядку зависимостей, а не исходной нумерации `1a/1b/...`.

**Волны запуска:**
- **Wave 1** (параллельно, чистый post-process exp27b, 0 cost): E-38a, E-38b, E-38c, E-38e
- **Wave 2** (после Wave 1): E-38d (после c), E-38f (после e, gate)
- **Wave 3** (независимо от Wave 1/2, нужны внешние данные / E-16): E-38g, E-38h, E-38i

**Общие конвенции:**
- Все артефакты — `results/exp38X_<short_name>.json`; схема: `{params, metrics, outcomes, meta}`; `outcomes` — pre-registered labels (см. ниже).
- Все seeding — `seed=0` для детерминизма; при bootstrap — `B=1000`.
- Все результаты — медиана по docs (32) + IQR; bootstrap CI где применимо.
- `exp27b` dense cache: N=32, K=128, S=128, layers 6/12/18/19/22/23.

## E-38a — û_t trajectory and local curvature through positions

**Мотивация.** L22-аномалия и вся позиционная структура поля J зависят от того, как нормализованный hidden state `û_t` движется по позициям. Если края (`t < 16`, `t > S−2`) демонстрируют аномальную динамику — все наши метрики (`C_b`, `τ`, `PR_modes`) могут быть edge-contaminated. Это первая проверка валидности всего протокола.

**Зависимости.** Нет.

**Setup.** exp27b. Для каждого `(layer, doc, t)`:
1. `û_t = h_t / h_t.norm().clamp_min(1e-12)` — inline (функции `unit_direction` в репозитории **нет**); `clamp_min` защищает attention-sink `pos 0` с `‖h_0‖ ≈ 0`. `h_t` — поле `H` кэша exp27b (`H[(dom, si, t)]` — `torch.Tensor [1024]`, проверено по `kaggle_kernel/results/exp27b_jcache_L*.pt`).
2. Скорость: `s(t) = ‖û_{t+1} − û_t‖₂`.
3. Локальная кривизна: `κ_g(t) = geodesic_curvature(û_{t−1}, û_t, û_{t+1})`.
4. Сегменты: `head = [0, 16)`, `body = [16, S−2)`, `tail = {S−2, S−1}`.

**Math.** `geodesic_curvature` из **`prism.holonomy`** (не `jstruct.py` — там только `build_M_K`, `decompose_w_vs_uhat`, `v_pred_from_JT`): `from prism.holonomy import geodesic_curvature`. Дискретная геодезическая кривизна, не дефект неравенства.

**Pitfalls.**
- L22 — GDN-слой: рекуррентность может дать численно другую траекторию, чем full-attention. Сравнивать профили L18 (full) vs L19 (GDN) отдельно.
- Первые позиции — attention sink; `û_0` может быть вырожден (малая норма h → шум в нормировке). Исключать из медиан или записывать как отдельный сегмент.
- `S = 128` — эффект границы чанка GDN при `S = 128` (E-27.6) может контаминировать tail. Записать `S` в meta.

**Procedure.**
1. Построить `S(t) = median_{doc} s(t)`, `K(t) = median_{doc} κ_g(t)` для каждого слоя.
2. Отчёт по сегментам: `median(segment)`, IQR.
3. Найти аномальные сегменты: `|median(seg) − median(body)| / IQR(body) > 2`.

**Pre-registered interpretation.**
- `median(head) >> median(body)` И `median(tail) >> median(body)` → **края special** (attention sinks + last-token): сценарий (c). RSB требует позиционно-зависимых реплик.
- `median(head) ≈ median(body) ≈ median(tail)` → **края typical**: сценарий (b). Наши метрики на `pos 0` валидны (с оговоркой про sentinel).
- `median(head) << median(body)` → **края atypical**: сценарий (a). Наши `pos 0` измерения — артефакт. Все position-sensitive выводы надо пересчитать.

**Cost.** 0 (post-process exp27b, ~2 минуты CPU).

**Artifact.** `results/exp38a_uhat_dynamics.json`.

## E-38b — Classical position audit (C_b, PR_modes, align_K1 on [16, S−2])

**Мотивация.** E-27.6 измерил `C_b` на `pos 0`, `PR_modes`/`align_K1` — на последних позициях. Если середина последовательности даёт значимо другие значения, все интерпретации сдвигаются. Это прямой тест «наши findings — edge effects или нет».

**Зависимости.** Нет (независим от E-38a, но интерпретируется вместе).

**Setup.** exp27b. Пересчитать на `t ∈ [16, S−2]`:
1. `C_b(t)`: cross-sample cosine gauge-free J на позиции `t`, медиана по парам docs.
2. `PR_modes(t)`: participation_ratio спектра `J^(p)` на позиции `t`.
3. `align_K1(t)`: `|cos(top-left-singular, 1/√K)|` для J на позиции `t`.

**Math.** `participation_ratio` (spectral.py); `align_K1` как в E-37.

**Pitfalls.**
- `C_b` на `pos 0` уже известно (`0.003–0.05`, E-0.1). Если на середине то же — finding устойчив; если `C_b × 2+` — артефакт.
- `PR_modes` на L22 = 4.6 на `pos 0`; если на середине другое — интерпретация L22 как «критической точки» требует пересчёта.
- N=32: bootstrap CI обязателен; без него нельзя отличить «рост в 1.5×» от шума.
- Сегмент `body` включает `t = S−2`; не путать с tail.

**Procedure.**
1. Per-(layer, t, doc): вычислить три метрики.
2. Медианы по docs, bootstrap CI: `from prism.cache import bootstrap_ci` (`bootstrap_ci(values, B=1000, alpha=0.05, seed=0, statistic=np.median)`); для парного сравнения body vs pos 0 — `bootstrap_ci_paired`.
3. Сравнение `pos 0` (E-27.6 baseline) vs `median over body`.
4. Профиль по `t` (для визуализации L22-аномалии).

**Pre-registered interpretation.**
- Все три метрики на body ≈ pos 0 (в пределах CI): **артефакта нет**, выводы статьи валидны.
- `C_b` на body > 1.5× pos 0: **edge contamination**: RSB, критическая точка, L22 требуют переформулировки.
- `PR_modes` на L22 body ≠ 4.6: **L22-аномалия position-sensitive**, нужен пересчёт через весь S.
- `align_K1` на body > 0.9: **L22-провал align — edge effect**, критические выводы E-37 откладываются.

**Cost.** 0 (~5 минут CPU).

**Artifact.** `results/exp38b_position_audit.json`.

## E-38c — Degeneracy pre-flight for holonomy (eigengap_min in top-16)

**Мотивация.** Неабелев формализм (`H_012`, `{θ_j}`) требует (почти-)вырожденных собственных подпространств. Если зазоры в топ-16 разрешены, каждый singular vector транспортируется независимо, и голономия редуцируется к набору Abelian фаз. Это pre-flight: без него E-38d даст мусор (интерпретация спектра `{θ_j}` некорректна).

**Зависимости.** Нет. **Gate для E-38d.**

**Setup.** exp27b. Для каждого `(layer, doc, t)`:
1. SVD `J → σ_1 ≥ σ_2 ≥ ... ≥ σ_16`.
2. `gap_min(t) = min_{i=1..15}(σ_i² − σ_{i+1}²)`.
3. `threshold = eps_frac · σ_1²`, `eps_frac = 0.01`.
4. `applicable(t) = gap_min(t) >= threshold` (`>=` — не `>`: граничный случай «допустим», согласовано с docstring `eigengap_min`).

**Math.** `eigengap_min` из `spectral.py` (новая функция из ядра).

**Pitfalls.**
- L23 тривиален (lm_head): σ разрешены по построению — preflight только для L18/L22 (внутренние слои) информативен.
- `eps_frac=0.01` — конвенция. Записать в meta; sensitivity sweep `eps_frac ∈ {0.005, 0.01, 0.02}`.
- Разные layers могут дать разные `applicable` — не усреднять.

**Procedure.**
1. Per-(layer, t, doc): `(gap_min, applicable)`.
2. Per-layer: `fraction_applicable = median_t applicable`.
3. Per-layer: `min_t gap_min` (самый вырожденный случай).

**Pre-registered interpretation.**
- `min_t gap_min >= threshold` на всех слоях: **неабелев формализм неприменим**, только Abelian (`Ω`, trace). E-38d интерпретируется как Abelian-проверка, `{θ_j}` — набор отдельных фаз.
- `min_t gap_min < threshold` на L18 или L22: **почти-вырождение**, формализм допустим. E-38d даст содержательный спектр.
- L23 применим, L18/L22 нет: **архитектурная особенность** выходного слоя — записать как structural finding.

**Cost.** 0 (~10 минут CPU, SVD на 32×128×6 = 24576 матрицах).

**Artifact.** `results/exp38c_degeneracy_preflight.json`.

## E-38d — Full holonomy matrix H_012 and spectrum {θ_j}

**Мотивация.** `κ = 0.018` (E-28) — скалярная свёртка `‖H − I‖_F`. Полная матрица `H_012` и спектр `{θ_j}` различают Abelian (все `θ_j` малы/равны) и неабелев (разброс `θ_j`) случаи. Без этого «три компоненты» — декларация. Также прямая проверка `tr(H)` vs локальный `Ω(û_t)`.

**Зависимости.** E-38c (interpretation gated).

**Setup.** exp27b. Для каждой тройки `(t, t+1, t+2)`, каждого doc, каждого layer:
1. `V_t = top_r_svd(J_t, 16)[2].T` → `[D, 16]`: `top_r_svd` возвращает `V_r` формы `[r, D]` (**строки** = правые сингулярные векторы), но `procrustes_align`/`_validate_orthonormal` требуют `[K, r]` с **ортонормальными столбцами** — поэтому транспозиция обязательна (без неё `‖V^T V − I‖_F ≈ √(D−r) ≈ 31.7` → ValueError).
2. `theta, H_012 = holonomy_spectrum([V_0, V_1, V_2], closed_loop=True)` — сигнатура принимает **список подпространств** (не матрицу); внутри сама вызывает `holonomy_accumulate(..., return_total=True)`, отдельный вызов не нужен. Возврат: `theta` — np.ndarray `[r//2]` (8 углов для r=16), `H_012` — `torch [16, 16]` float64 (`R_total`). `κ = ‖H_012 − I‖_F` считается из `H_012` напрямую.
3. `tr(H) = 2 Σ cos(θ_j)`, `‖H−I‖_F² = 4 Σ (1 − cos θ_j)` — точные тождества.
4. `Ω(t) = geodesic_curvature(û_t, û_{t+1}, û_{t+2})` (из `prism.holonomy`).

(Если нужны отдельные шаги: `R_ij, residual_sq = procrustes_align(V_i, V_j)` — возврат **tuple** `(R, residual_sq)`, не одна матрица; но для `H_012` шаг 2 достаточен.)

**Math.** `holonomy_accumulate(return_total=True)`, `holonomy_spectrum`, `geodesic_curvature`.

**Pitfalls.**
- Procrustes rotation не уникальна при degenerate главных углах → `{θ_j}` может быть неоднозначно. `procrustes_align` возвращает одну из валидных ротаций; при `σ_min(V_i^T V_j) ≈ 0` — детектировать и исключать тройку (крупный `residual_sq` из tuple-возврата).
- `tr(H)` — свёртка (сумма), `{θ_j}` — полный инвариант. Записывать оба.
- Сравнение `tr(H)` vs `Ω` — по позициям (корреляция), не равенство. Формула `κ ≈ Ω + κ_MK` — эвристика.
- E-28 даёт `κ = 0.018` на L23. Значения `{θ_j}` должны давать `‖H−I‖_F` в этом порядке.
- На тривиальных позициях (`R_total ≈ I`) `holonomy_spectrum` возвращает `theta = [0, …, 0]` с `RuntimeWarning` — это **валидный** Abelian-результат, не баг; фиксировать в outcomes.

**Procedure.**
1. Per-(layer, t, doc): `H_012`, `{θ_j}`, `tr(H)`, `‖H−I‖_F`, `Ω(t)`.
2. Per-layer: распределение `{θ_j}` по docs (гистограмма 8 углов).
3. Per-layer: `ρ(tr(H), Ω)` по позициям (Spearman).
4. Consistency: `‖H−I‖_F` per-layer vs E-28 (`κ(L23) = 0.018`).

**Pre-registered interpretation.**
- `‖H−I‖_F` совпадает с E-28 (tol 1e-3): **consistency check пройден**.
- `{θ_j}` узко распределены (все `θ_j ≈ 0`, `max(θ) − min(θ) < 0.1`): **effectively Abelian**, `Ω(û_t)` определяет `κ`.
- `{θ_j}` широко (один `θ_1 >> θ_2..θ_8`): **неабелев кандидат** — но только если E-38c подтвердил почти-вырождение. Иначе — артефакт численной неустойчивости Procrustes.
- `ρ(tr(H), Ω) > 0.7`: **κ определяется сферической геометрией** `û_t`.
- `ρ(tr(H), Ω) < 0.3`: **κ измеряет что-то третье** (не û_t-геометрию), интерпретация требует пересмотра.

**Cost.** 0 (~30 минут CPU, SVD на 126×6×32 = 24192 тройках).

**Artifact.** `results/exp38d_holonomy_spectrum.json`.

## E-38e — M_K diagnostic: `w = α û_t + β v_⊥`

**Мотивация.** Проверить, лежит ли uniform-направление `1/√K` (в token space) на blind direction `û_t` (тест «сильной унификации» по лемме M-1) или ортогонально. Если `|α|/|β| > 10` везде — сигнал отсутствует, E-38f неинформативен. Это **gate** для E-38f. Также — consistency check числа `σ_g` из E-12a.

**Зависимости.** Нет. **Gate для E-38f.**

**Setup.** На L23 (индекс 23 для 0.8B):
1. `W_lm = _resolve_lm_head_weight(model)` (из `prism.interventions`, wrapper-safe; прямой `model.lm_head.weight` ломается на multimodal wrapper) → `W_lm[token_set]` → [128, 1024].
2. `g = _lm_module(model).norm.weight + 1` (из `prism.jacobian`, wrapper-safe — flat `model.model.norm` не работает на `Qwen3_5ForConditionalGeneration`; RMSNorm weight `1 + w`, проверить по `[L-rms]`).
3. `M_K = build_M_K(W_lm, token_set, g)` → [128, 1024].
4. `w = M_K^T · 1/√K` → [1024].
5. Для каждой позиции `t`: `(α_t, β_t, v_⊥_t) = decompose_w_vs_uhat(w, û_t)`.

**Math.** `build_M_K`, `decompose_w_vs_uhat`.

**Pitfalls.**
- `g` в RMSNorm — это `1 + w_rmsnorm` (не сырой `w`). Проверить по `model.model.norm.weight` + `1`; при `w = 0` на старте, `g = 1`.
- `W_lm` tied с `embed_tokens` (tied weights). `build_M_K` не зависит от того, tied или нет — просто использует матрицу.
- `token_set` — из exp27b (128 токенов), не из E-10c (другой протокол).
- `α_t, β_t` меняются с позицией `t` через `û_t`. Медиана по `t` + записать распределение.
- `|β|` сравнивается с `σ_g · cos(u_g, 1/√K) · r_t/√D` из E-12a/E-33r, tolerance 15%. Не забыть alignment factor.

**Procedure.**
1. `M_K`, `w` — один раз на модель.
2. Per-(doc, t): `α_t, β_t, v_⊥_t`.
3. Per-doc: `median_t |α_t|/|β_t|`.
4. Consistency: `(√D/r_t)|β_t|` vs `σ_g` из E-28 per-layer (записать `r_t = ‖h_t‖₂`).

**Pre-registered interpretation.**
- `|α|/|β| > 10` (медиана) на всех docs: **gate провален**, blind direction ортогонален uniform. E-38f пропускается. Унификация не подтверждается, но и не опровергается — тест неинформативен.
- `|α|/|β| ≈ 1`: **смешанный случай**, `w` имеет значимые компоненты по обоим направлениям. E-38f запускается.
- `|α|/|β| << 1` (медиана < 0.1): uniform почти ⊥ `û_t`, gauge-мода ортогональна blind direction. Интересный режим, требует отдельной интерпретации (gauge и blind — разные объекты).
- Consistency `(√D/r_t)|β|` vs `σ_g`: если в пределах 15% — лемма M-1 (3) подтверждена, E-12a воспроизведено. Если нет — **red flag**, проверить `M_K`, `g`, `token_set`.

**Cost.** 0 (~1 минута, одна SVD M_K + 32×128 inner products).

**Artifact.** `results/exp38e_MK_diagnostic.json`.

## E-38f — Structural consistency: `cos(v_g, v_pred)` with alignment normalization

**Мотивация.** Проверить, совпадает ли gauge-направление `v_g` (из SVD J) с предсказанием `v_pred = J^T·1/√K / ‖·‖` (лемма M-1). Это **прямой** тест того, что gauge определяется `M_K + û_t` структурой. Consistency (не открытие): ожидаем `cos(v_g, v_pred) ≈ cos(u_g, 1/√K)`, не `≈ 1`.

**Зависимости.** E-38e (gate: если `|α|/|β| > 10`, пропуск).

**Setup.** На L23, тех же docs:
1. SVD `J = U Σ V^T` (top singular для gauge mode — тот, чей левый вектор `u_g` максимизирует `|cos(u_g, 1/√K)|`).
2. `v_pred = v_pred_from_JT(J, uniform=1/√K)`.
3. `cos(v_g, v_pred)`, `cos(u_g, 1/√K)`.

**Math.** `v_pred_from_JT`, `top_r_svd`.

**Pitfalls.**
- `sign(v_g)` не уникален (LAPACK). Использовать `|cos|`.
- `cos(v_g, v_pred) ≈ cos(u_g, 1/√K)` — это полное согласие. `cos ≈ 1` — НЕ полное согласие, а избыточное.
- `cos >> cos(u_g, 1/√K)` — методологическая аномалия (теоретически невозможно при правильной нормировке). Если возникает — проверить `token_set`, `M_K`, `J^T · 1/√K`.
- `J` — cached gauge-free или raw? Для теста нужен raw `J` (формула M-1 выведена для raw). Проверить по кэшу.

**Procedure.**
1. Per-(doc, t): `cos(v_g, v_pred)`, `cos(u_g, 1/√K)`.
2. `Δcos = cos(v_g, v_pred) − cos(u_g, 1/√K)`.
3. Bootstrap CI Δcos по docs.

**Pre-registered interpretation.**
- `|Δcos| < 0.05` (в пределах CI): **лемма M-1 подтверждена**, gauge = M_K-проекция.
- `Δcos < −0.1`: **лемма нарушена**, gauge происходит из другого механизма. Structural unification провалена.
- `Δcos > +0.1`: **методологическая аномалия**, требуется проверка alignment factor / `M_K` / `g`.

**Cost.** 0 (~5 минут CPU, SVD J per (doc, t)).

**Artifact.** `results/exp38f_structural_consistency.json`.

## E-38g — J↔h dual: projection of activations on tail modes

**Мотивация.** Сравнить хвостовые моды `J` (наши) с J-Space Anthropic (их представление). Тест — не «лежат ли J-lens векторы в хвосте» (провалится по построению: J-lens доминируется топ-модами), а «у каких активаций спарс-представление на хвостовых `v_k`». Это единственный тест симметрии с Anthropic.

**Зависимости.** Внешние данные (J-Lens checkpoints). **Условно**: если checkpoints для 0.8B недоступны — отложить.

**Setup.**
1. Скачать J-Lens checkpoints: `bcywinski/jacobian-lens-qwen3.5-9b` (для 9B). Для 0.8B — проверить наличие; при отсутствии — отложить или адаптировать (другая архитектура — другая методология).
2. Для нужных слоёв (L22 приоритет): `J_ℓ = E[∂h_final/∂h_ℓ]` (из checkpoints).
3. Для активаций `h_t` на L22 (из exp27b):
    - `c_k(t) = ⟨h_t, v_k⟩` для k = 1..K (D=1024 → K=128 в token space? Нет: `v_k` — правые сингулярные векторы, D-мерные; `h_t ∈ R^D`; K = число мод = D).
    - Спарс-ность: `S(t) = −Σ p_k log p_k`, `p_k = c_k(t)²/Σ c_k²`.
    - Доля энергии в хвосте: `frac_tail(t) = Σ_{k ∈ tail} c_k(t)² / Σ_k c_k(t)²`, где `tail` — modes с `σ_k` в нижних 10% спектра.
4. Корреляция: `ρ(S(t), frac_tail(t))`.

**Math.** `top_r_svd`, энтропия по `c_k(t)`.

**Pitfalls.**
- Checkpoints для 9B, не 0.8B: число D разное (2560 vs 1024), J-lens векторы в разных пространствах. **Нельзя** сравнивать напрямую.
- Токен-пространство (K=128) vs hidden-space (D=1024): `c_k(t) = ⟨h_t, v_k⟩` — проекция D-мерного вектора на D-мерные `v_k`. Не путать с `⟨h_t, uniform⟩`.
- «Спарс-ность» — энтропия, порог должен быть pre-registered: например, top-10 modes carry > 80% energy.
- Если Anthropic выложил результаты на 0.8B (проверить), использовать их напрямую.

**Procedure.**
1. Скачать checkpoints, распаковать `J_ℓ`.
2. SVD `J_ℓ` (или `J_ℓ^T J_ℓ`), получить `{v_k}`.
3. Для 32 docs из exp27b: `c_k(t)`, `S(t)`, `frac_tail(t)`.
4. `ρ(S, frac_tail)` per-doc, median + bootstrap CI.

**Pre-registered interpretation.**
- `ρ > 0.7`: **J-Space = tail modes**, симметрия установлена. Anthropic независимо нашли то же, что мы.
- `ρ < 0.3`: **J-Space ≠ tail modes**, наши результаты — про другое. J-Lens — sidebar, не внешняя валидация.
- Промежуточное: частичное пересечение, требует дальнейшего анализа (по каким модам пересекается).

**Cost.** Малая (скачивание ~100–500 MB, post-process ~15 минут).

**Artifact.** `results/exp38g_jlens_link.json`.

**Условность.** Если для 0.8B checkpoints нет, эксперимент откладывается. **Не** подменять 9B-результатами (разная архитектура — другая методология).

## E-38h — Two-channel Goodhart decomposition

**Мотивация.** Проверить двухканальную модель Goodhart: bridge растёт за счёт gauge-компоненты (top-16 differential), поведение ломается через tail differential. Это операционализация разведочной гипотезы 13-1/13-2/13-3 — «если топ-16 неабелев, хвост Abelian, то `ΔW` в каждом канале даёт разный вклад в bridge/behavior».

**Зависимости.** E-16 checkpoints (существуют), E-38d (для сравнения — но можно запускать параллельно).

**Setup.**
- Чекпоинты E-16a/b: `ΔW(s)`, `s ∈ {0.1, 0.25, 0.5, 0.75, 1.0}`; top-p retention(s); bridge(s).
- На L23: проектор на топ-16. **Правильная нотация** с учётом форм из `top_r_svd`: `U_t ∈ R^{K×16}` (левые, столбцы), `V_t ∈ R^{16×D}` (правые, **строки**). Двухсторонний: `ΔW_top = U_t @ U_t.T @ ΔW @ V_t.T @ V_t` (`[K,D]`); **не** `ΔW @ V_t @ V_t.T` — это `[K,16]`, shape-mismatch. Альтернативно (зафиксировать один вариант в meta): односторонний `ΔW_top = U_t @ U_t.T @ ΔW` (только token-side), `ΔW_tail = ΔW − ΔW_top`.
- Bridge per-channel: `bridge = 1.0 − jacobian_gap(J_L, J_S, E_L, E_S, probs)` (из `prism.bridge`; `jacobian_gap` — lower=better, «bridge» — higher=better, инверсия по докстрингу).

**Math.** `apply_edit`, `top_r_svd`, `procrustes_align` на `ΔW(s_i)` для некоммутативности.

**Pitfalls.**
- `ΔW ∈ R^{K×D}`: проекция на топ-16 может быть в любом из пространств. Определиться и записать в meta.
- Bridge per-channel: `bridge(ΔW_top)` vs `bridge(ΔW)` — не одно и то же. Определить: bridge берётся по `J · ΔW` или по `cos` в проекции.
- Behavior response: `top-p retention(s)` — скаляр; некоммутативность ротаций на поведение не влияет напрямую.
- Nonlinearity G-matrix: bridge × behavior — 2 признака; "G-matrix" тут метафора (одна регрессия).

**Procedure.**
1. Для каждого `s`: `ΔW(s)` (из E-16).
2. `ΔW_top(s)`, `ΔW_tail(s)` через проектор.
3. Bridge per channel: `bridge(ΔW_top(s))`, `bridge(ΔW_tail(s))` — новый bridge, вычисленный под edit `apply_edit(model, ΔW_top(s))` и `ΔW_tail(s)` отдельно. Требует forward → moderate cost.
4. Behavior per channel: то же для `s` = 0.5 (одно значение), не для всех `s` (дорого).
5. Некоммутативность: `R(s1, s2) = procrustes_align(ΔW_top(s1), ΔW_top(s2))`; `‖R(s1, s2) · R(s2, s3) − R(s1, s3)‖_F` vs 0.
6. Nonlinear: линейная vs квадратичная регрессия bridge(s) vs behavior(s).

**Pre-registered interpretation.**
- Bridge растёт в top-16 канале, behavior ломается в tail: **двухканальная модель подтверждена**, операционализация Goodhart.
- Оба канала коррелируют одинаково: **одноканальная модель**, top/tail не разделены в механизме.
- Некоммутативность в top-16 >> tail: **неабелев в топ-16**, согласуется с E-38d-сценарием 2.
- Некоммутативность одинакова в обоих: оба канала Abelian.

**Cost.** Средняя (forward passes под edit: 5 s × 5 steps × 32 docs ≈ 15 минут GPU; но если E-16 forward есть, то post-process).

**Artifact.** `results/exp38h_two_channel_goodhart.json` (ручная JSON-запись; `run_spec` не используется — `"E38"` не в `_VALID_EXPERIMENTS` pipeline.py, для разовых экспериментов список не расширять).

## E-38i — Factorization `J = M_K(I − û_t û_t^T)` under readout-pull

**Мотивация.** L23-факторизация точна на невозмущённой модели (E-35). На L23 всё тавтологично — **но под edit факторизация может ломаться**, и это делает тест не-тавтологичным. Если факторизация сохраняется при edit — лист защищён; если ломается — Goodhart через нарушение факторизации.

**Зависимости.** E-16 checkpoints (существуют). E-38f (полезно, но не блокирует).

**Setup.**
- Чекпоинты E-16: `ΔW(s)`, `s ∈ {0, 0.1, 0.25, 0.5, 0.75, 1.0}`.
- Для каждого `s`:
    1. `apply_edit(model, ΔW(s))`.
    2. Вычислить `J(s)` на L23 для набора docs.
    3. Вычислить `M_K(s) = _resolve_lm_head_weight(model)[token_set] · diag(g)` (из `prism.interventions`, wrapper-safe; вес **перерезолвится** после `apply_edit` — `W_lm` изменён).
    4. Вычислить `û_t(s) = h_t(s) / ‖h_t(s)‖` (h_t меняется под edit).
    5. `residual(s) = ‖J(s) − M_K(s)(I − û_t(s) û_t(s)^T)‖_F / ‖J(s)‖_F`.

**Math.** `build_M_K`, SVD.

**Pitfalls.**
- `M_K(s)` — нужно строить заново для каждого `s`, `W_lm` изменён.
- `û_t(s)` — пересчитывается под edit (h_t меняется).
- `residual(0)` может быть большим из-за float noise — записать как baseline.
- `s = 1` — сильный edit, `W_lm` сильно изменён. Может дать residual >> baseline по тривиальной причине (не factor).
- Baseline residual на невозмущённой модели уже ≈ 0 (E-35 точна). Если baseline > 1e-3 — проверить пайплайн.

**Procedure.**
1. `s = 0` (baseline): residual.
2. Для каждого `s > 0`: `apply_edit`, вычислить `J(s)`, `M_K(s)`, `û_t(s)`, residual(s).
3. Профиль `residual(s)` vs `s`.

**Pre-registered interpretation.**
- `residual(s) ≈ baseline` для всех `s`: **факторизация сохраняется**, лист L23 защищён под edit. Прямое подтверждение унификации на возмущении.
- `residual(s)` растёт с `s`: **Goodhart через нарушение факторизации**, механизм — разрыв листа.
- `residual(s)` скачкообразно растёт при `s* < 1`: **критическая доза Goodhart** (порог скручивания).
- `residual(s)` растёт, но `bridge(s)` тоже растёт: **Goodhart через две разных причины**, не только факторизация.

**Cost.** Средняя (forward passes под edit: 6 s × 32 docs × 6 layers ≈ 30 минут GPU, но можно ограничить s ∈ {0, 0.5, 1} = 15 минут).

**Artifact.** `results/exp38i_factorization_under_edit.json` (ручная JSON-запись; см. решение по `run_spec` в E-38h).
