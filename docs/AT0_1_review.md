## 1. C1 — MA(1)-центрирование всё ещё неверно (r6 его не тронул)

`script_sha256` не менялся (`de305869`), значит код `p4_plateau` тот же:

```python
s_doc = mean(rt[8:K_MAX]) - c["f_dc"]
z_docs[nm] = {"z": (s_doc + c["f_dc"]) / se, ...}
```

то есть `z = mean_band / se`, а не `s_doc / se`.

Докстринг и артефактное поле утверждают:

```text
"E_doc": "−f_dc (matched MA(1): ρ_true(k≥2)=0 ⇒ E[mean_band]=0)"
```

Но в **безцентровом** согласии, которое гейтят S4/S7 (`r_odd = 1/N ≠ 0`), для процесса с ненулевым средним:

$$\mathbb E[\rho_{T-k}(k\ge2)]\approx\frac{\|m\|^2}{\|m\|^2+\mathrm{var}}=f_{DC}\neq0$$

Следовательно `E[s_doc] ≈ 0`, и правильный z — это `s_doc/se`. Текущий z тестирует `mean_band = 0`, то есть «DC отсутствует», а не «плато сверх MA(1)».

Для `h_raw`/`du_unit` (`f_dc ~ 1e-5`) это пренебрежимо. Для `v_tangent` (`f_dc ≈ 0.0797`) — доминирует.

Ручной счёт (N=383, D=1024, K=96):

```
Σ_{k=9..96} 1/(383−k) ≈ ln(374.5/286.5) = 0.2679
/1024 = 2.616e-4 ; sqrt = 0.016175 ; /(K_MAX−8)=/88 → se ≈ 1.84e-4
```

| канал | z |
|---|---:|
| как в коде: `mean_band/se` | ≈ 444 (артефакт: median 381) |
| правильно: `s_doc/se`, ambient D | **≈ 10.5** |
| то же, d_eff=178 | ≈ 4.4 |
| то же, d_eff=50 | ≈ 2.3 |

**381 — это на 30–150× завышенный plateau-сигнал.** Столбец помечен «описательно», но он единственный, где `v_tangent` выглядит экстремально, и его будут цитировать.

Фикс: `z_excess = s_doc/se_eff`, `z_raw_band` оставить отдельной диагностикой; `E_doc` переписать на `E[s_doc] ≈ 0`.

## 2. C2 — `tpu_dev` тождественно равен roundoff, это не гейт G0a

Определение из скрипта:

```text
hn = ‖h_raw‖ ; u = h_raw/max(hn,1e-12) ; U = u/max(‖u‖,1e-12)
dev = ‖U·hn − h_raw‖ / ‖h_raw‖
```

Разбор по веткам:

- `hn > 1e-12`: `u = h/hn`, `‖u‖=1`, `U=u` ⇒ `U·hn = (h/hn)·hn = h`
- `hn ≤ 1e-12`: `u ∝ h`, `U = h/‖h‖` ⇒ `U·hn = (h/‖h‖)·‖h‖ = h`

**В обеих ветках `U·hn ≡ h`.** `max_rel_dev` измеряет только ошибку round-trip divide→multiply, ~2e-16, и не может провалиться ни на каких данных, кроме NaN/inf.

Это ровно та тавтология, которую AT0_3 r3 удалил из `G0a_tpu_curves` («U*hn==h»). Здесь она возвращается под именем `tpu_dev` и подписью «гейт G0a, review #5».

Что действительно верифицирует TPU-ряды — уже есть и это не тавтология:

| проверка | значение | смысл |
|---|---|---|
| `hn_vs_column_norms_max_rel` | 1.19e-4 | `_hn` **есть** нормы столбцов ⇒ баг продюсера подтверждён |
| `row_norm_vs_hn_corr` | 0.0429 | `_hn` **не** нормы строк |
| `l23_meta_vs_recomputed` | max dev 2.08e-4 ≤ 1e-3 | ряды согласованы с продюсерским meta |

Фикс: `tpu_dev` → `reconstruction_roundoff_identity`, статус «тождество, не provenance»; в note явно «годность рядов установлена `l23_meta_vs_recomputed`, не `tpu_dev`».

## 6. C6 — `T_none_full` остаётся в `excess_median`, `r` не поднят в headline

Note добавлен и он честный:

```text
T_none_full — полная сумма по всем лагам (точно, тождество G1/Gram: sum_rho_full=(r−1)/2)
```

Но арифметика остаётся:

$$T\_none\_full=\frac{r-1}{2}-(N-1)\frac rN=-\frac{1+(N-2)f_{dc}}2$$

— функция только `(N, f_dc)`. `gram_identity_check` в новом скрипте **подтверждает тождество**, но подтверждение тождества не делает его измерением. Оно лежит в одном dict с настоящими excess-колонками (`Tk_none_K96` и др.), что приглашает к сравнению.

Ответ на заголовочный вопрос T0 — это `r`:

```text
r_du ≈ 0.0048  ⇒ DC-suppressed
r_v  ≈ 24.9    ⇒ not DC-free
```

Фикс: `T_none_full` → отдельный блок `identity_check_G1`; headline = `r`/`f_dc` per object.
