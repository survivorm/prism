# E94 / Q3 — независимый пересчёт надзирателя (Q3.json, rc=0)

Вопрос: связаны ли низкие отрывы первого кандидата от второго с повторами **внутри одного движка**
(междвижкового смешения позиций нет: и `margin`, и флаг повтора считаются по собственному потоку llama).

## 1. Согласие с артефактом

Сводка артефакта: `ρ(margin_t, rep8_flag_t) = 0.341` на 6144 позициях, `p_perm = 0.0`,
null ±0.025 (2000 перестановок, seed 8181). Лаги: L1 0.3568 / L4 0.3901 / L8 0.3180 / L16 0.3121.

## 2. Единица анализа (то, что пул из 6144 позиций скрывает)

В артефакте пер-доковые ρ лежат (`per_doc[].spear_a`), поэтому честная статистика считается без
нового прогона — я её посчитал сам, единица ресемплинга = документ (n = 16):

- **медиана пер-доковых ρ = 0.345, bootstrap-CI (10 000, seed 8181) = [0.298, 0.472]** — ноль вне интервала;
- разброс: от `w13 = −0.121` до `w14 = 0.653`; медиана совпадает с пуловым числом (0.341 против 0.345),
  то есть пул не «наддул» эффект, но и его доверительный интервал по документам — то, что надо
  цитировать вместо `p_perm = 0.0`;
- три документа около нуля объясняются устройством, а не опровержением: `w4` имеет `n_flag1 = 1`
  (повторов почти нет — корреляция неопределима), `w13` — 90, `w2` — 168; у остальных 13 документов
  `n_flag1` от 312 до 374 и ρ от 0.269 до 0.653.

## 3. Что законно утверждать (моя формулировка до внешнего ревью)

1. Внутри движка llama/SYCL на 16 документах отрыв первого кандидата от второго **положительно связан**
   с флагом восьмикратного повтора в той же позиции: медиана по документам 0.345, CI [0.298, 0.472].
2. Связь не исчезает при сдвиге флага на 1-16 позиций вперёд (ρ 0.31-0.39 по лагам), то есть низкие
   отрывы скорее **предшествуют** участившимся повторам, чем сопровождают их; но лаги — пять чисел
   по одному и тому же массиву без поправки на множественные сравнения, поэтому максимум утверждения:
   «ρ(L) положителен во всех проверенных лагах, наибольшее значение при L = 4».
3. Метрика повтора насыщена (91% значений p-значений > 0.9 по раунду), поэтому величина ρ — не
   «сила механизма», а мера совместимости рангов; механизм (почему отрыв падает вместе с повтором)
   не проверялся вовсе.
4. CPU-аналог не измерен: в `results/e81/REPLAY.json` нет вторых кандидатов, поэтому обещанное ТЗ
   сравнение «корреляция против корреляции» сегодня **N/A**, и перенос метода на другой движок —
   отдельная работа.

## 4. Что проверит внешнее ревью (и что я сам считаю слабым)

- пересчёт пер-доковых ρ своими формулами (моя проверка — только по массивам артефакта, не из сырья);
- корректность `p_perm = 0.0`: при 0 из 2000 корректно писать `p < 1/2001`, а не `p = 0`;
- смещение исключений: `n_excluded_short_toplogprobs` по докам (в артефакте есть поле — проверить,
  что оно не концентрируется в одном классе документов);
- мёртвые ветки и `sys.exit`-карта.
