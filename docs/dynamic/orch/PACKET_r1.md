## 1. Контекст (чтобы войти с нуля)
- Объект: Qwen3.5-0.8B fp32. Движки: локальный CPU/torch (оценщик, градиенты, middle-layer),
  TPU (съёмка фич), llama.cpp iGPU Vulkan/CPU — greedy ПОБИТОВО == torch (32/32), законен
  для массовых генераций. GPU-Kaggle 0/30ч до 14.11; TPU 20ч.
- Данные: 64 дока (wiki/math/code/chat × 16), T=256, фичи L{1,5,11,17,23} в
  /data/prism_kernels/exp62/gen_layers_qwen.npz; пул n16 пин pool_fp=144c722d (sha256 текстов).
  Мета-JSON TPU-батареи и часть артефактов E-52+ потеряны в git-инциденте 09.11 — статус
  по файлам: results/ARTIFACTS_MANIFEST.json (9 запишей sha16) + §C2 ответов на аудит4.
- Главный измеритель: V-оценщик (u=h/‖h‖; V_t = орт.компонента u_{t+1} от u_t;
  dip = median cos(V_t,V_{t+1})); исходники восстановлены из pyc, пин ESTIMATOR_PIN.json.
  Конвенции null: пермутационный mean-2 для ядер; iid-sign floor≈0.07 для R-рядов;
  cluster/moving-block bootstrap (iid-позиционный bootstrap — запрещён на автокорр. рядах).
- Вопрос программы: есть ли в текстовой динамике модельная структура ЗА/token-статистиками,
  каковы её носитель и масштаб.

## 2. Проверено (числа; ≡ ссылка на артефакт/paper)
1. **Dip-камень**: корпус dip = −0.072 (L23, pooled nonwiki, лестница-2b real); знак
   переживает движки/нулли/окна. Контрасты: iid-вход 0.000, AR(1) +0.414, blk-швы §6.
2. **Вырожденный режим own**: p1-медиана 0.999–1.000; REPLAY **16/16 r=1.000**; rep8=1.0
   у 14/16; onset8 медиана ≈17. «Своя генерация» = петли; все «own»-эксперименты без
   вмешательства измеряют петли (E-88 в очереди это лечит).
3. **Раннее own≠cor**: Δ 0.12±0.05 @ t≈30, гаснет к lag≈72; связь метки «own» с e-кривой
   только на lag0 (±0.05) — метка в e80c была null.
4. **L4 анти-эхо (канон)**: k=1..3 = −0.0078/−0.0077/−0.0049 (rng99, null mean-2).
   Nov10-числа (−0.0101…) — unreproducible, эрратта. 32k: excess плоский до 32k —
   «мгновенного ядра» нет (артефакт потерян, пере-вывод R9-12).
5. **MDL-линейка (E-85a закрыта)**: корпус 9.85/9.25 B/токен (ratio 0.94); own-генерация
   8.09/7.93 (ratio 0.98, на 13% дешевле корпуса); **novelty≡1.0 обе стороны** → L0 —
   не носитель dip.
6. **Квантование**: схема важнее нормы: fqres4 убивает dip, per-group W4 цел, per-tensor W8
   задевает.
7. **AT-факты**: детерминированный провал по роли (BASE теряет «лицензию» 3/3 наборов,
   G1/C1 держат); nudge вредит: 0.92→0.71 (36 пар).
8. **Воспроизводимость движков**: torch CPU fp32 == TPU bf16 24/24; llama f32 (VK и CPU)
   == torch 32/32; бенч f16/q8 снят (разбор — очередь).
9. **HEAT, n=4 (первый срез)**: нагрев подавляет петли 3/4 (rep8 1.0→0.31/0.65/0.52,
   один sign-flip w3); μ гетерогенно (медиана −0.36→−0.16). Направление, не величина.
10. **Лестница v2b (11.11, results/e90/LADDER_V2.json)** — см. §5: B1 закрыт.

## 3. Мертво / снято (причина; дата)
- «Масштаб ≤16 → носитель 2–4 токена» — лестница = разбавление швами (1−1/b), и masked-
  вариант тоже не мера (шовное искажение оценщика). 11.11, ladder v2b.
- Солитонный пакет → понижен до «пороговая нелинейность + робастность»: перелёт dip на
  λ=0.7 (−0.207 > финального −0.174) без nll/rep16; «упругость» = глобальные медианы
  разной длины; 1-D параметры были обучены при λ=0 (не R-null). (audit2 B2/B3)
- «Читатель > писатель» — не отделён от естественности текста; ни одна из 3 пре-рег
  сигнатур не подошла; авто-вердикт скрипта снят. (B4)
- И-2 на L23 — снята (stab_half 0.49, §41.4); λ₁≈−0.92 остаётся на L1/L11 (0.72/0.70);
  arg_near_pi ≈ min_re на вещ. оси — независимых критерия ~2, не 3.
- «Power-law послесвечение, μ∈Hunt» — битый roll-null; форма НЕ разрешена: n_eff=5,
  ΔBIC(exp−power)=2.01/1.59<6 (k=8 запас +0.0003 — хрупко); «интенсивность/e-модуль»
  n_eff=0 — снято. (E-82b)
- T1 (= переименованный dip), T2 CHSH (тождественно |S|≤2 на ко-измеренных), g₂=1+Cov₁
  (не оптический g₂). (audit2 H3)
- R3 (Δp1) — p1 на потолке; LFM3-ветка — GPU-квота; «анти-эхо Nov10», B4-T, Gemini-анатрия
  — статус unreproducible (не путать с exploratory).
- sum-rule «учётной вершины» на медианных рядах — медиана ломает линейные тождества
  (Σρ≈+1.8); жить может только на per-doc ACF (пересчёт R9-14).

## ЧАСТЬ 2. Ревьюемый объект: P0-задачи ТЗ (дизайны и вердикт-правила)
## 2. P0 — убийства конфаундов (дёшево, CPU, запускать по готовности очереди)
- **R9-1 Seam-ladder V2b** (B1+H1+H6) — **сделан 11.11, exp90_ladder_v2.py** (артефакт
  results/e90/LADDER_V2.json). Само-аудит поправил и ревьюера, и первичный «фикс»:
  (а) unmasked-лестница = разбавление (1−1/b) — B1 верно; (б) НО и masked-лестница НЕ
  равно real тождественно — маска это детерминированный ПОЗИЦИОННЫЙ подотбор пар (при
  blk=2 — чётные позиции), поэтому добавлен control: случайный подотбор того же размера
  из нешаффленной последовательности; (в) masked при blk≥9 не измерит горб (нет пар
  k≥blk) — лестница про горб/плато молчит честно; (г) информативна только seam_delta =
  unmasked−(1−1/b)·masked с кластерным по докам бутстрапом (axis=1 — в v2 был CI-баг).
  Честный масштаб сверх локальности решает R9-6 (surrogate), не лестница.
- **R9-2 Клетка random-веса × corpus teacher-forced** (H2). Модель из config, случайная
  инициализация, TF на 16 корпусных доках, тот же dcurve. Если dip≈0 → «выучено»
  выдерживает; если dip<0 → метрика измеряет вход, не веса. ~20 мин.
- **R9-3 Random→random null интерполяции** (RV-3). λ-путь R1→R2 (тот же sd_r-рецепт,
  теперь полные sd). Даёт нуль-полосу для «рождения» E-71. ~20 мин.
- **R9-4 E-71 перепуск по фиксированному протоколу** (B2/B3/D2: nll+dip по λ, 3 сида,
  окно после вставки, гейт ступенька/линейная, resume по полноте). Наблюдаемые по λ:
  dip, nll_med, rep16-прокси (K_gen-ядро top-16 продолжения — дешёвая замена rep16),
  eff-rank h. Солитон остаётся гипотезой, только если порог dip **отделён** от порогов
  остальных наблюдаемых. 1–2 ч CPU.
- **R9-5 Клетка читатель/писатель на gen_ids** (RV-1, новые данные). Read-матрица
  (own/crossdom/corpus) с TF на 16 REPLAY-генерациях вместо own-TF-петель. Если
  gen_ids-«писатель» ≈ corpus → читатель снова не отличим (естественность побеждает);
  если ниже обоих → оживает петлевая сигнатура. ~1 ч CPU, скрипт почти готов.
- **R9-6 СУРРОГАТ: генеративная проверка VAR(2)/DMD** (audit2 §8, «тест 6»). Фит линейной
  модели 2-го порядка на приращениях h (lift^incr, ridge 1e-3) по ПОЛОВИНЕ доков →
  симуляция траекторий → пересчёт Δ(k)/горба/плато на held-out-доках и held-out-слое
  (L11→L17). Если VAR(2) воспроизводит дип+горб+плато с величинами → «три моды» =
  линейный процесс второго порядка, искать «сверх» нечего; если нет — носитель существует.
  Пред-регировать метрику сравнивания до фитa (например, L2-расстояние нормированных
  Δ-кривых + знак на lag-1). 2–3 ч CPU. **Главная задача раунда.**
- **R9-7 loopy-гейт в загрузчике пула** (RV-4). Фильтр uniq-доков (Δ(k)≈1 при k≥2) ДО
  образования пула; новый пул = новая эпоха пина (sha256 текстов меняется — все прежние
  числа эпохи 144c722d помечаются epoch=1). Реализовать + перепин + прогнать L4-канон на
  новом пуле как мост эпох. ~1 ч.
- **R9-8 Реестр метрик** (RV-9/B5/H4). `docs/MARKERS.md`: lift^state (V−mean, SVD, lstsq,
  r=48) vs lift^incr (H[1:]−H[:-1], ridge 1e-3, r=64); plateau×3 окна; dcurve×2;
  null-конвенции (mean-2 perm для ядер, iid-sign floor 0.07 для R-рядов, moving-block
  bootstrap для рядов с автокорреляцией); агрегации (median по докам ≠ mean; sum-rule
  только на per-doc ACF). Гейт: имя метрики без ссылки на реестр в доке невалидно. Полдня,
  без прогонов.

## 3. P1 — живая линия режима (после P0-очереди)
- **R9-9 E-86 HEAT полный**: 16 доков × T∈{0,0.7,1.0} × 72 шага, реестр реперов на каждом
  шаге + K_gen-ядро по 16-окну + rep8. Движок: llama-iGPU для генераций (пин побитовой

  LFM3 если появится датаквота); заодно re-cite 0.846 (RV-8b).
- **R9-12 E-79 32k re-scan** — в прогоне (torch); артефакт-долг §32k закрывается здесь же
  (якорная тройка эпохи по RV-5).
- **R9-13 E-69c holdout + healthy-LoRA контроль** (RV-2, D4): math/code/chat holdout,
  здоровая модель × тот же LoRA-бюджет. Без него «диссоциация» = «любая дотренировка
  сглаживает ритм». ~2 ч CPU.
- **R9-14 Sum-rule на per-doc ACF** (audit2 §4.2): Σρ≈+1.8 на медианных рядах — пересчитать

  возвращается, иначе снимается. 30 мин.
- **R9-15 Null-калибровка «win»** (D8): как часто osc выигрывает на rnull-шуме. 15 мин.
- **R9-16 Бюджет дисперсии** (H8): фиксированный мини-набор (4 дока × L{1,11,23} ×

  горба, plateau. Порог интерпретабельности: любое «различие на 0.02» вне бюджета — молчит.
