## 3. Осталось

### U1 ⚠️ Содержательно: в normal-режиме линейность **K2-окна не гейтится нигде**

```python
if mode == "normal":
    linear_ok = bool(L1 <= 0.10 and 1.9 <= L2 <= 2.1)   # L1 — λ^K1 (k=1,2), L2 — q_t (k=0)
else:  # denom_below_floor
    linear_ok = bool(L1n <= 0.10 and 1.9 <= L2n <= 2.1 and not kfail)  # kfail по k=0..8
```

`kappa_flags_hi` считается для **всех** k=0..8, но в normal-режиме — только отчёт. Итог: клетка может получить **FOUND** (т.е. пройти K2-rank ≥2/3 τ) при нелинейном отклике на k=4,8 — том самом окне, которое объявлено out-of-sample-валидацией.

Это не механический флиппер (rank — сравнение v* и refs при одной a_hi, нелинейность общая), но это **дыра в интерпретации**: FOUND заявляет фишеровскую величину на окне, где линейный режим не проверен. В below_floor-режиме она закрыта κ-флагами, в normal — нет. Асимметрия не объявлена.

**Два выхода (оба дешёвые):**
- (а) декларация в TZ §3.5: «в normal-режиме линейность гейтится на k=0 (L2) и k∈K1 (L1); k=4,8 — κ-флаги отчёт, не гейт; FOUND возможен при нелинейном K2-отклике»;
- (б) `linear_ok = ... and not any(kflags_hi.values())` — **0 форвардов**, κ уже посчитаны; делает normal-режим симметричным below_floor. Требует строки в TZ.

Рекомендую (б): инвариант 4 уже требует считать κ для всех k, гейт по ним — естественное продолжение, а не новая сущность.

### U2 ⚠️ Отчёт: `nonlin_probe_1c` не покрывает `v*` — расхождение со схемой TZ

TZ §13: `nonlin_probe: per (4 кл., 2 доп. амплитуды): q(a) curve [3e-4, 1e-3, 3e-3, 1e-2] **per v\*** + B0-subset`.

Код: `nonlin_probe_1c(fwd, cell, b0)` — цикл `for j in range(32)` по B₀, **v\* не передаётся и не меряется**. То есть q(a)-кривая за пределами a_hi есть для 32 стартовых направлений и отсутствует для того единственного направления, которое входит в вердикт. Это ровно тот класс, что V6 (объявленное поле отсутствует), только в отчётном блоке.

**Фикс:** добавить `vstar` в сигнатуру и в цикл (+2 амплитуды × 2 fwd = 4 ф.-э. на клетку × 4 = **16 ф.-э. ≈ 70 с**). Заодно даёт прямой ответ «v* линеен до 3e-3?» — то, чего сейчас нет ни в одном гейте.

dirs = []

## 4. Нитки (по строке каждая)

- **`np.median([])`** в `pos_spec` при `n_ref=0` (мёртвый sibling): возвращает `nan` + RuntimeWarning; downstream-guard `med_ref > 0` спасает, но предупреждение в логе смока/1b будет. `med_ref = float(np.median(ref_lams_t16)) if ref_lams_t16 else 0.0`.

- **TZ §5 ↔ §3.11.5**: в §5 всё ещё parenthetical «клетка **сохраняет стадию-1-метку**, без FOUND-промоушена», а §3.11.5 (r5-гигиена) — «вердикт клетки **NOT_TESTABLE**, не считается в ≥8». Код делает NOT_TESTABLE и исключает из `n_ok8` — т.е. следует §3.11.5. Синхронизировать §5 (я это отмечал в ревью TZ r5, поправлена только одна из двух секций).
- **`stage1b_verdict`** использует полный per-cell вердикт, TZ §5 говорит «НЕ по полному per-cell вердикту». После V4 пайплайны идентичны ⇒ смещения нет (обе стороны под одними гейтами), но формулировку стоит привести: «по FOUND/SHO идентичного пайплайна» — это то, что код делает.
