## 3. Требования к артефакту работы

Три самостоятельных скрипта + агрегатор, без новых зависимостей (stdlib), без GPU/сети/весов:

1. `tools/gate_collect.py` (G1) — область: `experiments/` + `tools/`; **`tests/` не входит**
   (363 теста = 26 с, гейт не должен этим заниматься).
2. `tools/gate_paths.py` (G2) — перенос `paths_resolve.py` **с расширением**: после разбора
   AST строится среда имён (`X = <любое выражение от __file__>`: `dirname`/`abspath`/`join`/
   `Path(...).parent`/`/`-оператор) и пути разрешаются **символически**, а не по `args[0]`.
   Требование: `exp45b_analysis.py:29` обязан попадать в отчёт. Глубина `dirname` считается по
   фактическому вычислению, а не подсчётом подстрок.
3. `tools/gate_artifacts.py` (G6) — канон выборки: `results/**/*.json` + `results/**/*.json.gz`,
   **минус `results/**/store/**`** (см. §2: 425.8 МБ адресных блобов, у которых нет ни
   `meta.n_rows`, ни смысла в `isfinite`; их учёт — G7 итерации 3, а не G6). `.gz` читать через
   `gzip`; `.jsonl` и `*.json.tar.gz` — вне scope (записать это в docstring, иначе вернут через
   волну). Канон печатается числом: `canon_files=<N> canon_mb=<M>`.
4. `tools/gate_all.sh` — последовательно, суммарно **≤ 120 с**; бюджет: G1 ≤ 60 с (pytest по 7
   файлам с импортами: замер 14–22 с, из них 23.9 с — один torch-файл), G2 ≤ 30 с (AST без
   импортов, замер 16.7 с на 352 файлах), G6 ≤ 20 с (замер 11.0 с на каноне 435 файлов / 172.7 МБ);
   печатать фактическое время каждого гейта. Если store попадёт в канон по ошибке — G6 станет 40 с
   и упадёт в свой бюджет: это и есть защита от «тихо втянули 425.8 МБ».
5. `tools/gate_allowlist.txt` — формат `gate_id<TAB>path<TAB>links=<K><TAB>причина`. **Ключ =
   относительный путь файла** (не `file:line`), но запись обязана объявить **число закрываемых
   ссылок** `links=K`: гейт падает (RC=1), если фактическое число битых ссылок файла ≠ K. Без
   этого одна запись легализует все будущие поломки того же файла («широкая маска» — замечание 6
   ревью r2); с `links=K` — нет. Сводка печатает `entries=<N> links_covered=<K>`. Для G6 ключ —
   путь артефакта, `links=` не нужен (одна запись = один файл).
6. В `AGENTS.md` — 3 строки (перед коммитом `tools/gate_all.sh`; новые записи allowlist только
   с причиной; чистка записи в том же коммите, где исправлен дефект).

`trackio` для этих скриптов не требуется (инфраструктура, ≤ 180 с, нет прогонов модели) —
исключение объявлено здесь явно.

## 4. Критерии приёмки

**G1.** Для каждого файла под `experiments/` и `tools/`, чьё имя матчит `test_*.py` или
`*_tests.py`:
- `pytest <file> --collect-only -q` собирает ≥ 1 тест → OK;
- **RC=2 (`collection error`) или RC=5 (`no tests collected`) → `DEAD_TEST <path>`**;
- либо файл в allowlist с причиной.
Файлы из allowlist **исключаются** из проверки «нет ERROR» — иначе baseline противоречив
(ровно ошибка r1). Baseline печатается гейтом в форме `collected=<N> errors=<N> dead_allowlisted=<N>`;
ожидание на сегодня — `11/0/2`, но в тексте гейта эти числа **не зашиты** (замечание 2 ревью r2b:
`collected=11` устареет в день внедрения).
Требование «без torch» формулируется честно: **гейт сам не импортирует torch/numpy**; импорт
возможен внутри pytest при сборе (≤ 60 с, разрешено). Гейт не качает веса и не трогает сеть.

**G2.** Отчёт по каждой ссылке: `DIR_MISSING <file>:<line> → <path>` / `FILE_MISSING …`.
**RC=1 только на `dir_missing`** — отсутствующий каталог-родитель объективен и означает
последствие реорга. `file_missing` (родитель есть, файла нет) печатается как `INFO` и на RC
**не влияет**: скрипт вправе писать артефакт, которого ещё нет в git, и гейт, падающий на этом,
запретит нормальную работу (ревью r2, замечание 5). Сводка печатает **сырые** числа
(`dir_missing=<N> files=<M>`, `file_missing=<N> files=<M>`, `allowlisted_links=<K>`).

**G6.** RC=1, если в каноне хотя бы один файл:
- не парсится;
- содержит в разобранной структуре `float`, для которого `math.isfinite` ложно;
- имеет `meta.n_rows` и `len(rows)`/`len(positions)` ≠ `meta.n_rows`.
Сводка печатает **фактические** числа (`files=… invalid=… nonfinite_files=… nrows_mismatch=…`),
без вписанных эталонов в строку. На введении гейт проходит с allowlist §5 (6 записей) и падает,
если файл allowlist удалить.

**Дизайн-тесты** (`tools/test_gates.py`, pytest; сам файл подпадает под G1 — так задумано):
- **G1:** tmp-каталог с `good_test.py` (1 тест), `broken_test.py` (импорт несуществующего
  модуля → RC=2), `script_tests.py` (`def main()` без тестов → RC=5) → гейт обязан назвать оба и
  выйти RC=1; после добавления обоих в allowlist — RC=0. Запуск гейта из дизайн-теста — с
  `-p no:cacheprovider` и явным `rootdir` tmp-каталога (защита от рекурсии и порчи кэша).
- **G2 (r2c: ярлыки классов приведены в соответствие §4 + каждый кейс в СВОЁМ tmp-корне —
  замечания 3/5 ревью r2 и r2b).** Файл всегда `<tmp_k>/a/b/gate_probe.py` (глубина фиксирована),
  `tmp_k = tmp_path / <имя кейса>`; варьируется **число `dirname`**:
  1 → `<tmp_k>/a/b/results` (родитель есть) → `FILE_MISSING`, RC=0;
  2 → `<tmp_k>/a/results` (создан заранее) → OK, RC=0;
  3 → `<tmp_k>/results` (родитель `<tmp_k>` есть) → `FILE_MISSING`, RC=0.
  Три цели **различны** и не совпадают между кейсами (регрессия на подсчёт `dirname`: цель
  смещается вверх ровно на уровень на каждое `dirname`).
  Класс `DIR_MISSING` проверяется отдельным кейсом, где отсутствует именно родитель:
  `join(H, "nope", "results")` → `<tmp_k>/a/nope/results`, RC=1.
  Алиас-регрессия (слепота r1): `H = dirname(dirname(abspath(__file__)))`,
  `join(H, "results")` при том же файле → `<tmp_k>/a/results`... но это же было OK-кейсом 2 —
  поэтому берётся **второй tmp-корень**: `<tmp_alias>/a/b/gate_probe.py` с двухуровневым алиасом
  → `<tmp_alias>/results`, не создан → ссылка **обязана быть видна в отчёте** (это и есть регрессия),
  класс `FILE_MISSING`. Ни один кейс не пишет и не читает `/tmp/results` (замечание 3 r2b).
- **G6:** три tmp-json — `{"a": NaN}`, `{"meta": {"n_rows": 2}, "rows": [1]}`, обрывок `{"a": 1`
  → по одному RC=1 на каждую причину; четвёртый — `{"a": NaN}` внутри `.json.gz` (проверка, что
  `.gz` распаковывается, а не считается битым).

   больше — норма (гейт обязан быть сильнее пробера), меньше — баг (замечание 4 ревью r2).
   Числа из ТЗ в коммит-сообщения не переписывать вручную — только печать гейта.
   Границы, которые `gate_paths.py` обязан перечислить в docstring: вложенный `dirname` любой
   глубины, алиасы второго уровня (`A = dirname(abspath(__file__)); B = join(A, ".."); C = join(B, …)`),
   `Path(...).parent` и `/`-оператор — поддерживаются; `getattr`, f-строки, пути из JSON/env и
   значения, приходящие из аргументов CLI, — **вне** возможностей AST-прохода.
4. В приёмочный лог `results/_audit_checks/gate_all_<date>.log` additionally: `sha256sum` самого
   гейта, `sha256sum results/_audit_checks/paths_sym_scan.json` и `sha256sum
   experiments/_audit_checks/paths_sym_probe.py`, плюс счётчик `allowlist_unused=<N>` (замечания
   5/6 ревью r2b: без пина «воспроизведи вывод» превращается в движущуюся цель — артефакт уже
   перезаписывался во время ревью).
5. Ревью итерации — файлом `docs/dynamic/GATES_R2_REVIEW.md` с `VERDICT: PASS|REVISE|FAIL`.

## 7. Риски (переписаны по ревью)

- **G1 тянет импорты.** `pytest` при сборе импортирует модуль: `test_exp39f_math.py` — torch
  (8.8 с). Это принято как цена (бюджет G1 ≤ 60 с), но запрещено тянуть веса/сеть. Если
  импорт станет дороже — лёгкое AST-плечо (`есть ли def test_`) до вызова pytest.
- **G2 видит не всё, и я это уже дважды недооценил.** Первая версия ТЗ говорила «15 файлов» —
  держалось на слепоте к алиасам; вторая говорила «51 файл / 77 ссылок» — держалось на **баге
  самого пробера**: `os.path.dirname("\x00FILE") == ""`, поэтому `_ROOT = dirname(dirname(abspath(__file__))
  )` отсекался строкой `startswith(FILE)` и файлы вида `AT0_4_rebuild_r6.py`, `at8/AT8_1_r2_reanalysis.py`,
  `sycl/exp94_s6_dry0.py` в скан не попадали (нашёл ревьюер r2, воспроизведя импортом). После
  перевода на абсолютный символический корень `/\x00REPO/<путь файла от корня репо>`: **352 файла /
  566 ссылок / 226 битых в 86 файлах**, из них `dir_missing` — **184 ссылки в 69 файлах**. Мораль:
  «сколько дефектов в классе» — это свойство инструмента, а не репозитория; поэтому §6.3 требует
  печать фактического числа гейтом и запрещает цитировать счётчик из ТЗ.
  Остаются слепыми `getattr`, f-строки, пути из JSON/env/CLI. G2 фиксирует класс, но не лечит
  (лечение — единый аксессор путей).
- **G6, глоб и store.** `json*` даёт 18 не-JSON файлов; канон — `*.json`+`*.json.gz` c `gzip`
  и **без `results/**/store/**`** (425.8 МБ адресных блобов, один 233.6 МБ; без их исключения
  G6 тратит 39.9 с на данные без `meta.n_rows` и без смысла в `isfinite` — заметил ревьюер r2).
  С исключением канон = 435 файлов / 172.7 МБ, проход 11.0 с.
  Объём канона — **598.5 МБ** (r1 ТЗ врало «107 МБ»), проход — **39.9 с** ⇒ по времени риск не
  «снят», а ограничен бюджетом G6 ≤ 20 с (замер 11.0 с) и агрегатора ≤ 120 с. Широкий glob
  добавляет 18 файлов, 17 из которых дают ложный `INVALID`.
- **Вложенный pytest в дизайн-тестах.** `tools/test_gates.py` сам под G1 и запускает gейт,
  который запускает pytest ⇒ обязательны `-p no:cacheprovider` и tmp-`rootdir`.
