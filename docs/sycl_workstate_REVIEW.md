## Пункт 3. `sycl_env.sh` (set -u, append, идемпотентность, warning, fail-fast)

Все свойства проверены **выполнением** в чистом шелле (`env -i`), не только чтением:

1. **set -u безопасность:** все переменные с гвардом — `ONEAPI_BIN/UMF_LIB/SYS_STDCXX` через
   `${VAR:-…}`; `LD_LIBRARY_PATH` — `${LD_LIBRARY_PATH:-}` в case и `${LD_LIBRARY_PATH:+…:}` в
   export; `LD_PRELOAD` — `${LD_PRELOAD:-}` в case; `n_gpu` — `${n_gpu:-0}`. Запуск в `env -i`
   (ни одной переменной не задано) — без ошибок, rc=0.
2. **Append-семантика (не перезапись):** PATH — `case`-гвард против дубля + prefix; LD_LIBRARY_PATH —
   `case`-гвард + append; LD_PRELOAD — системная libstdc++ ставится **в начало** существующего
   значения (`$SYS_STDCXX${LD_PRELOAD:+:$LD_PRELOAD}`). Тест с чужим `LD_PRELOAD=/some/other/lib.so`:
   результат `/usr/lib/libstdc++.so.6:/some/other/lib.so` — фикс ENV-B не пропущен, чужое не
   потеряно. ✓
3. **Идемпотентность:** двойной source в чистом шелле — rc=0/rc=0, `ONEAPI_BIN` ровно 1 раз в PATH,
   UMF ровно 1 раз в LD_LIBRARY_PATH, LD_PRELOAD однозначен. ✓ (смоук из ТЗ §3.1 воспроизведён)
4. **Warning-ветка:** при непустом чужом LD_PRELOAD печатает `ВНИМАНИЕ: LD_PRELOAD уже задан: …`
   с текущим значением. ✓
5. **Fail-fast при отсутствующем icpx:** `ONEAPI_BIN=/nonexistent` → сообщение в stderr + rc=1
   (`return 1 2>/dev/null || exit 1` — работает и при source, и при direct-exec); никакого тихого
   фолбэка. ✓
6. Быстрый чек `sycl-ls`: в чистом шелле напечата `OK: GPU устройств видно: 2` — совпадает с
   строками sycl-ls в артефакте (L0 + OpenCL).

NIT (не блокирует): в `run_local.sh` (строка `source "$ROOT/sycl_env.sh"`) сбой source НЕ
фатален — скрипт без `set -e` продолжит; но все icpx-шаги далее проверяют `command -v icpx` и
печатают «icpx не найден — шаг пропущен», т.е. деградация видимая, не тихая. Для G1-формы
запуска (`source … && ./probe`) цепочка `&&` обрывается корректно.

**Находки: NIT (run_local.sh: сбой source не фатален, но видимый).**

## Пункт 4. `probe_kernel_name.cpp` (D2H до check, хост-буфер, rc-логика, компиляция)

1. **check() получает ХОСТ-буфер:** `check(tag, ran, out, n)` — вызовы `check(…, out.data(), n)`,
   где `out` — `std::vector<float>` хоста; USM-указатель `dout` в check больше не передаётся.
   Фикс CODE-C (SEGV при дерефе USM на хосте) выполнен.
2. **D2H + wait() ПЕРЕД check:** после каждого из трёх запусков (A, B, C) —
   `q.memcpy(out.data(), dout, …).wait();` и только потом `check`. ✓
3. **rc-логика сохранена:** `return (a_ok2 && (b_ok2 || c_ok2)) ? 0 : 1;` — дословно как в
   требовании (A обязателен, B или C достаточны). ✓
4. **Компиляция:** проверено на этой машине icpx 2026.0 (`icpx -fsycl -std=c++20
   probe/probe_kernel_name.cpp -o /tmp/_probe_kn_test`) — rc=0, 8.4 c, предупреждений нет.
   По логике ТЗ (варианты A/B/C) и лог G1 §1c-3: «A: обычная / B: шаблон / C: имя ядра —
   ОТРАБОТАЛ, макс. ошибка = 0 (OK)», `код возврата: 0` — зонд работает на карте после фикса.
5. Поведение вывода: «A и B оба работают ⇒ … дело в СБОРКЕ» — совпадает с установленной причиной
   (AOT-путь, `-DPRISM_SYCL_TARGETS=`) и с шагами 1c/2 run_local.sh, где флаг задан явно.

NIT (предсуществующие, не введённые этим фиксом): (а) шапка файла описывает 4 варианта
(A/B/C/D), main запускает только A/B/C — вариант D не реализован; (б) `template <typename T>`
у `run_templated`/`run_named` — T не используется (намеренно: H1 требует шаблонный контекст,
инстанциация всегда `<float>`). Оба — косметика диагностического зонда.

**Находки: NIT ×2 (комментарная/предсуществующая косметика).**
