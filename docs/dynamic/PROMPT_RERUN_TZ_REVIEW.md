## Что искать как дефекты (по опыту проекта)

1. **Классификация**: не должен ли номер с найденным на диске артефактом (75, 81, 90, 63, 69) остаться
   в «мёртвых» без переклассификации; согласовано ли это с §0 и Фазой A0.
2. **Порядок фаз**: можно ли, читая ТЗ буквально, начать запуск раньше аудита/оценки ценности.
3. **Критерии приёмки проверяемы?** Для каждого пункта §3 — можно ли машинно сказать «выполнено/нет».
4. **Дыры протокола**: `./run_one.sh` только, `setsid nohup`, BUSY = читать лог, `avail ≥ 10G`,
   trackio (обязателен для новых локальных CPU-экспериментов), sha-фиксация скриптов, правки `paper.md`
   запрещены, docs-hygiene (разовые файлы >48ч удаляются), маркеры `*_DONE` у артефактов субагентов.
5. **Ложные обещания**: оценка «цена/wall» без констант; «runnable-now» без проверки входов;
   обещание перезапустить модель без указания, какая модель и где она лежит.
6. **Серая зона 60–95**: достаточно ли жёстко записано, что опубликованное число — подозреваемое,
   и что «совпало с кодом» не снимает подозрение (нужен независимый пересчёт).
7. **Не попадает ли в поток то, что уже закрыто** (дубли `E-NN`) — есть ли механизм отсева.
8. **Мёртвые/недостижимые шаги**: фазы, у которых нет выхода-файла или маркера.
