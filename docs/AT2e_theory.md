# AT2e — каноническая клетка T2

Формулирую от принципов. Порядок: **что спрашиваем → какой объект отвечает → как его измерить одним движением → что нельзя «оптимизировать» в коде, не изменив вопрос**.

---

## I. Логический разрыв, который надо закрыть

Аддентум T2:

$$O_H^{fut}(l,t)\,v=\lambda\big(C_l^t+\varepsilon I\big)v,\qquad
O_H^{fut}=\sum_{k=1}^{H}J_{t+k}^\top P_{t+k}J_{t+k},\quad C=J_t^\top P_t J_t$$

> «Большие λ = направления, слабо видимые текущему ответу, но сильно видимые будущему.»

Что делали предыдущие клетки:

| клетка | что мерила | чего не мерила |
|---|---|---|
| AT2c | предсказуемость будущего **регрессией** из bottom-C | причинную чувствительность; O |
| AT2d | причинный эффект **bottom-C** при matched dose | отношение; O; текущий эффект (знаменатель) |

**Ключевой факт, который делает обе клетки неинформативными для T2:** при ε-регуляризации знаменатель для всего хвоста C почти константен:

$$\lambda_i(C)\ll\varepsilon\ \Rightarrow\ \lambda_i(C)+\varepsilon\approx\varepsilon
\ \Rightarrow\ \lambda_i\approx\frac{\lambda_i(O)}{\varepsilon}$$

Внутри хвоста ранжирование идёт **по O**, а не по C. Выбор «4 самых слабых по C» — с точки зрения O произвольная выборка. Числа из AT2c §11.8: `λ_min_nz/λ_max = 3.2e-4 … 3.0e-3`, т.е. weak-4 лежит на 2–3 порядка ниже любого разумного ε. Отсюда `excess ≈ random` был **предсказуем из конструкции**, а не из физики.

Формально: `∀v ∈ bottom-C: O(v) мало` **не опровергает** `∃v: O(v)/(C(v)+ε) велико`.

⇒ AT2d REFUTED остаётся валидным утверждением о bottom-C. Статус T2 возвращается в **«не тестирована канонически»**. AT2e — та клетка, которая её тестирует.

## II. Объект: три величины, а не одна

Не одно λ, а **пара условий + их свёртка**, потому что «слабо видимое текущему» и «сильно видимое будущему» — независимые требования, и λ их прячет за ε.

Для направления `v` (‖v‖=1) в точке (l,t):

$$
\underbrace{q_t(v)}_{\text{текущая видимость}},\qquad
\underbrace{\bar q_{fut}(v)=\tfrac1H\sum_{k=1}^{H}q_{t+k}(v)}_{\text{средняя будущая}},\qquad
\rho(v)=\frac{\bar q_{fut}}{q_t},\qquad
\lambda_\varepsilon(v)=\frac{H\,\bar q_{fut}}{q_t+\varepsilon}
$$

где `q_s(v) = v^⊤ J_s^⊤ P_s J_s v`.

**Почему mean, а не sum, в ρ.** O в аддентуме — сумма по k. Но тогда «естественный» уровень λ для направления с `C ≫ ε` равен ≈ H, а не 1. Порог «λ ≫ 1» был бы вакуумным. Отчитываем **обе** нормировки и явно объявляем референс: `ρ ≈ 1` = будущее выглядит как текущее; `ρ ≫ 1` = future-only.

**Три альтернативы аддентума читаются прямо:**

| исход | q_t | ρ | что это |
|---|---|---|---|
| **скретчпад** | ниже пола | ≫ 1 | невидимое текущему, видимое будущему |
| **редундантная запись** | выше пола | ≈ 1 | видно обоим одинаково |
| **мёртвый груз** | ниже пола | ≈ 0 (обе ниже пола) | не видно никому |
| **не разрешено** | — | CI через пороги | — |

ε-регуляризация обязательна и **свипуется**: `ε = τ·λ_max(C)`, `τ ∈ {1e-3, 1e-2, 5e-2}`. Отчёт — кривая λ(τ), не одно число. Причина: именно ε определяет, что вообще значит «слабо видимое», и выбор одного τ post-hoc = подбор вердикта.

## III. Принцип измерения: один патч → все считывания

Это центральное решение, из которого дальше всё следует.

**Патчуем ОДНО состояние в ОДНОЙ позиции:** `h_l^t ← h_l^t + a·v`. Один forward. Читаем логиты **на всех позициях** s = t…t+H. Из одного forward получаем:

- `Δz_s` для всех s → числитель **и** знаменатель;
- `q_s = Δz_s^⊤ P_s Δz_s` — **точная полная Fisher**, `P_s Δz = p_s⊙Δz − p_s(p_s·Δz)`, полный вокабуляр;
- `κ_s = KL(p_s^{patched} ‖ p_s^{base})` — фактический функциональный отклик;
- argmax-флипы по позициям.

Пять следствий, каждое снимает конкретный дефект прошлых клеток:

1. **Числитель и знаменатель из одного forward** → нет рассогласования базиса, среза, агрегации, кэш/прогон. Знаменатель не «теряется при оптимизации бюджета» (моя ошибка M7 в AT2d).
2. **Полный вокабуляр, точная P** → нет оговорки «U128-pooled ≠ полный вокабуляр, диагональ ≠ Fisher». Метка базиса не нужна: считывание — всё распределение.
3. **Одна позиция** → это частная производная `∂z_{t+k}/∂h_l^t`, а не отклик системы на возмущение 64 позиций. Объект T2, а не его замена.
4. **Teacher forcing = TF-замок по построению.** Входные токены фиксированы, патч не меняет эмиссию → будущее меняется **только** через внутреннее состояние. Это ровно требование §7.3 ТЗ_4-8, полученное бесплатно. Открытая генерация — другая клетка (T7), не эта.
5. **`q` и `κ` из одних логитов** → встроенная проверка первого порядка: `κ_s ≈ ½ q_s` в линейном режиме. Расхождение = нелинейность, флаг.

**Калибровка амплитуды.** `a = ε_a·‖h_l^t‖`, `ε_a ∈ {1e-3, 3e-3, 1e-2}` (относительная, не абсолютная — нормы h различаются по слоям/докам на порядки). Отклик квадратичен: `q_s(a) ∝ a²`. Отношение ρ **безмасштабно в первом порядке** — обе части ∝ a². Это снимает необходимость dose-матчинга как первичного механизма: контроль нужен по **направлению**, не по амплитуде. Dose-matching остаётся только для функционального теста на большей амплитуде.

## IV. Выбор кандидатов: почему нельзя сэмплировать хвост

Искомые направления редки в 1024-мерном пространстве. Случайный поиск их не найдёт; bottom-C — не ранжирует по O (см. §I). Нужен **подъём по отношению**.

Два способа, и они дают **разные по силе утверждения**:

**(а) Подъём в полном пространстве** (градиент обобщённого Рэлея):
$$\nabla_v\lambda \propto Ov-\lambda(C+\varepsilon I)v,\qquad
Ov=\sum_k J_k^\top P_k (J_k v)$$
`J_k v` — из FD-forward, `J_k^⊤ w` — VJP (backward). Итерация = 2 forward + (H+1) backward. На CPU backward ≈ 2× forward ⇒ дорого.

**(б) Ограничение на подпространство** (probe-батч): берём ортонормированный `B ∈ R^{D×r}`, для каждого столбца — один FD-forward, получаем `Δz_s^{(j)}`. Тогда
$$\big[O|_B\big]_{jj'}=\sum_{k\ge1}\frac{\Delta z_{t+k}^{(j)\top}P_{t+k}\Delta z_{t+k}^{(j')}}{a^2},\qquad
\big[C|_B\big]_{jj'}=\frac{\Delta z_t^{(j)\top}P_t\Delta z_t^{(j')}}{a^2}$$
— точные ограничения операторов на span(B) с точностью O(a²) при центральных разностях. Решаем малую обобщённую задачу `r×r`. **Только forward, ни одного backward.**

**Асимметрия, которую надо использовать:**

> `λ_max|_B ≤ λ_max` — ограничение даёт **нижнюю границу**.
> Для утверждения существования нижней границы **достаточно**.
> Для утверждения отсутствия нужен полный prostor.

⇒ **Дешёвая стадия может дать только «найдено» или «не найдено в B»**. Дорогая нужна только если дешёвая negative. Это правильная асимметрия затрат под фальсификационную логику.

Бонусы probe-батча (всё бесплатно, из тех же forward):
- весь спектр в span(B), не только λ_max;
- **ε-свип без новых forward** (ε входит только в знаменатель малой задачи);
- per-k профиль (эффект живёт на k=1 или k=8?);
- **split-half против selection bias** — делим k на две половины, ищем v* на одной, меряем ρ на другой. Ноль дополнительных forward.

**Состав B (пре-рег, r=64):** 16 top-C + 16 bottom-nonzero-C + 16 top-PCA состояний дока + 16 Haar. Кэш `JR` используется **только для выбора направлений проб**, не для вычисления эстимандов — все эстиманды из свежих forward с полной P. Это снимает конфликт «кэш U128 vs прогон full-vocab».

Честная формулировка результата: `λ_max` **в объявленном подпространстве**, с указанием состава B. Если найдено — существование установлено. Если нет — «не найдено», не «нет».

## V. Вердиктное дерево

Первичная единица — **(l, t)**, не (L, k)-клетка. T2 сформулирована per-(l,t); усреднение по 64 позициям её убивает (позиционная зависимость J сильна на ранних слоях — AT2c C1b: frac 0.49/0.34 на L6/L12).

```
0. Гейты: линейный режим (q ∝ a²), G-zero(L23), детерминизм,
   пол численного шума, split-half-валидность
   провал → NOT_TESTABLE (не refuted)

1. SCRATCHPAD_CANDIDATE:
   ∃ (l,t): q_t(v*) < floor  И  ρ_splitB(v*) > ρ_min
            И  λ_ε(v*) > λ_min на ≥2 из 3 τ
            И  ρ(v*) > ρ(random matched) по парному CI
   → существование направления-кандидата установлено

2. REDUNDANT_DOMINANT:
   на всех (l,t): ρ(v*) ≈ 1 (CI накрывает 1) при q_t выше пола
   → будущее видно не лучше текущего

3. DEAD_WEIGHT:
   на всех (l,t): и q_t, и q_fut ниже пола для всех v ∈ B
   → в этом подпространстве нечего нести

4. NOT_FOUND_IN_SUBSPACE:
   λ_max|_B не превышает референс, но пол/мощность достаточны
   → требуется стадия 2 (полный подъём), T2 НЕ закрывается

5. NOT_RESOLVED: иначе
```

`ρ_min`, `λ_min`, `floor` — **пре-регистрируются из pilot-замера шума и референса ρ≈1**, не из желаемого исхода. Референс ρ для «generic» направления объявляется: ρ ≈ 1 при C ≫ ε.

**Ни один исход не повышает статус до «солитон»/«скретчпад доказан»** — для этого нужны адресуемость (функциональный тест), устойчивость и null. Клетка даёт **кандидата**, не теорию.

## VI. Контроли и нули

| контроль | зачем | цена |
|---|---|---|
| **ε_a-свип, slope≈1** | отличить оператор от нелинейного отклика | те же пробы на 2–3 амплитудах |
| **split-half по k** | v* подобран на тех же данных → ρ оптимистично смещён | 0 (из тех же проб) |
| **split-half по readout-координатам** | то же, независимая ось | 0 |
| **random direction, matched ‖δn‖** | контроль по направлению (ρ безмасштабно ⇒ амплитуда вторична) | +2 forward/клетка |
| **random weights × real text** | обязательный null аддентума: спектр — свойство обучения или архитектуры? | ×2 на подвыборке |
| **позиционная специфичность** | тот же v* в другой позиции t' → ρ должен упасть, иначе это свойство модели, не точки | +2 forward |
| **тип слоя** | GDN (рекуррентная память) vs full attention — разные механизмы переноса | 2 слоя в дизайне |
| **G-zero: L23** | архитектурный нуль `O_H^fut(L_max) ≡ 0`; детектор ошибки окна/пропагации | 2 forward |
| **температурный sham** | для функционального теста: отделить калибровку от информации | 0 (из baseline-логитов) |
| **множественные рестарты** | локальные максимумы подъёма | ×2–3 на стадии 2 |

Пропагация проверена по архитектуре: патч выхода слоя l в позиции t идёт вверх по слоям в t, затем вперёд через attention/GDN на слоях > l. Для l=23 путей вперёд нет ⇒ тождественный нуль. Это не эвристика, а свойство графа — и потому годится как гейт.

## VII. Инварианты: что нельзя «оптимизировать» в коде

Это прямой ответ на твоё опасение. Каждый пункт выглядит как деталь реализации, но **меняет эстиманд**:

1. **Одна позиция, не окно.** Окно = отклик системы, не частная производная. Усреднение по 64 позициям убивает per-(l,t).
2. **Числитель и знаменатель — из одного forward.** Разные forward / разные базисы / кэш vs прогон → отношение не определено.
3. **Полный вокабуляр, точная `P = diag(p) − pp^⊤`.** U128-pooled или диагональная Fisher — другой объект с другими числами.
4. **`q` (оператор) и `κ` (отклик) отчитываются оба.** Только q — не проверен первый порядок; только κ — не оператор T2.
5. **ε относительно `λ_max(C)`, свип, не одно значение.** Иначе порог «слабо видимое» подобран под вердикт.
6. **ρ нормировано на H, референс объявлен.** Sum-версия даёт вакуумный порог «λ≫1».
7. **Подбор и проверка v* разделены** (split-half). Иначе ρ при выбранном направлении смещён вверх, и это не отличимо от сигнала.
8. **Teacher forcing, не свободная генерация.** Open-loop меняет X → это T7, не T2.
9. **`l ≤ 22`; L23 только как нуль-гейт.**
10. **Кэш — только для выбора проб.** Ни одно вердиктное число не берётся из кэша.
11. **Ограничение на span(B) отчитывается как нижняя граница**, состав B — в артефакте. «Не найдено» ≠ «нет».
12. **Амплитуда относительная к ‖h_t‖**, не абсолютная. Нормы h различаются на порядки между слоями/доками.

Если при написании кода захочется «сэкономить» на любом из 12 — это не оптимизация, это другая клетка.

## VIII. Стадии и цена

Оценка требует одного замера (forward 128 tok на этой машине ≈ 3.5–4 s по AT2d pre-study; backward не замерен).

**Стадия 1 — existence pilot (только forward).**
- 2 слоя: L11 (full attention) + L12 (GDN) — контроль типа, оба в кэше, оба ≤22.
- 4 дока (по одному на домен) × 2 позиции (t=32, t=96; t+H_max ≤ 127).
- 16 клеток × r=64 пробы × 2 (центральные разности) = 2048 forward + верификация ≈ 100.
- ≈ 2.2–2.5 ч при 4 s/forward. Плюс null на 4 клетках ≈ +0.6 ч.
- **Отдаёт:** λ_max|_B, спектр в B, ε-кривую, per-k профиль, split-half ρ, сравнение с random. Всё, кроме полного подъёма.

**Стадия 2 — только если стадия 1 дала NOT_FOUND.** Градиентный подъём в полном пространстве на подвыборке клеток; требует замера backward. Дороже в ~3–5× на клетку; ставится адресно, не на всю сетку.

**Стадия 3 — функциональная адресуемость** (только если стадия 1 дала кандидата): патч v* на амплитуде в линейном режиме, current vs future, argmax-флипы, matched random, температурный sham, устойчивость по докам/позициям, полный null random×real.

Разделение стадий — не экономия, а логика: **дешёвая стадия даёт нижнюю границу (достаточную для существования), дорогая нужна только для отрицательного вывода.**

## IX. Что клетка не утверждает

- Найденный кандидат — **не скретчпад**: нужны адресуемость, устойчивость, null (стадия 3).
- `λ_max|_B ≈ референс` — **не опровержение T2**: только «не найдено в объявленном подпространстве».
- Ничего про CoT-достаточность (T7): TF-замок фиксирует X, open-loop не делается.
- Ничего про солитон (T8): другая программа, другой объект.
- Один носитель, один пул: переносимость не заявляется (Запрет 8, урок E-61 — переносится структура, не числа).

```

```

## Резюме в одну фразу

Меряем **отношение будущей видимости к текущей у одного направления в одной точке**, получая числитель и знаменатель **из одного патча** с точной полной Fisher; кандидатов ищем **подъёмом отношения** (а не сэмплированием хвоста знаменателя, который при ε-регуляризации не ранжирует), дешёвой стадией дающей **нижнюю границу** — достаточную для существования и недостаточную для опровержения; и заранее выписываем 12 инвариантов, «оптимизация» любого из которых молча превращает клетку обратно в AT2c/AT2d.

Если согласен с постановкой — дальше могу: (а) выписать точные формулы проб/матриц и процедуру split-half, (б) прикинуть смету после замера одного forward+backward, (в) сформулировать пре-рег-документ в формате проекта (§0–§14) с гейтами и схемой артефакта.
