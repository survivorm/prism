## B. Совпадение конвенций CPU и GPU (чтение `exp94_q3.py` + `exp94_q3cpu.py` + `exp94_sycl_common`)

| Элемент | GPU (llama/SYCL) | CPU (HF fp32) | Совпало |
|---|---|---|---|
| Индекс позиции | `pos = OFF + j` метит сгенерированный `g_j` (OFF=64) | `t = OFF + j` метит `g_j` | да |
| Строка логитов маржи | `completion_probabilities[j]` — распределение, ЭМИТИРОВАВШЕЕ `tokens[j]` (schema: `cp[j].id == tokens[j]`) | `logits[OFF-1+j]` — строка, предсказавшая токен на позиции `OFF+j` | да (одно распределение) |
| Маржа | `exp(lp_top1) − exp(lp_top2)` | `p_max − p_top2` из той же строки | да\* |
| Флаг повтора | `rep_flags(ids448,8)[OFF+j]` (общий common, дословно exp81b) | то же | да |
| Лаги | `(margin_p, flag_{p+L})`, отброс `p+L ≥ 448` | `(margin_j, flag_{j+L})`, отброс `j+L ≥ 384` | да |
| Исключения | `len(top_logprobs)<2` (набл. 0/16) | `p2≤0 или p1≤p2` (набл. 0/16) | да (счётчики 0 на обеих руках) |

\* Латентная (неактивная здесь) асимметрия: GPU-маржа привязана к ЭМИТИРОВАННОМУ
токену, CPU-маржа — к истинному аргмаксу. Совпадают при аргмаксе=эмитированному;
гейт воспроизведения это проверяет: `n_argmax_ne_gen_total=0`. В данном артефакте
асимметрия не реализовалась; при другом прогоне могла бы — фиксирую, BLOCKER'ом не
считаю. Конвенции совпадают → сравнение корреляций между движками валидно.

  `0_итоги_раунд9.md:183` есть «интервалы **совпадают**» — MINOR-2.

## E. Атака на самый слабый вывод

Кандидаты брифа, отработанные:
1. `docs_none` при лаге 16 — НЕ уязвим, проверено числом (таблица ниже —
   вырождение валидно, объяснение надзирателя верено).
2. «15/16 положительных ρ» — НЕ уязвим: при n=16 двухсторонний знаковый тест даёт
   p = 2·(17/2^16) ≈ 0.00052, т.е. «15/16 > 0» — это значимый сигнал, а не слабый
   описательный; вместе с CI, не покрывающим 0, кандидат отпадает.
3. **Выбран: `repro_gate.meaning` в Q3cpu.json**: «свежие HF fp32 p_max совпадают с
   замороженным REPLAY.gen_p1, аргмакс совпадает с gen_ids => **трек построен на том
   же conditioning**». Это самый уязвимый вывод, потому что стрелка шире, чем гейт.

Что гейт реально устанавливает: замороженные `gen_p1[j]` воспроизводятся текущей
моделью на тех же ids448 с |Δ| ≤ 1.67e-4 (16/16, допуск 1e-3) и argmax = `gen_ids`
(0/16). Из этого следует: те же ВЕСА (другой чекпоинт дал бы O(0.1)+ расхождение
вероятностей) и тот же ВВОД (другие ids дали бы O(0.01)+). Т.е. «conditioning» в
смысле (модель+вход) подтверждён в пределах допуска — и в этом смысле стрелка
обоснована. Чего гейт НЕ устанавливает: КАКОЙ ДВИЖОК породил замороженный трек.
Измеренный разброс f16/SYCL vs fp32 (Q1/Q2: 3e-6..1.7e-4) НАМНОГО меньше допуска
1e-3 — замороженный трек, сгенерированный iGPU-f16, прошёл бы этот же гейт. Гейт
движко-независим. limitations-5 («провенанс ... не перепроверялся») честен, но
`meaning`, читаемый в отрыве, шире своего основания; «доказывает» (формулировка
брифа) — тем более: это подтверждение в пределах допуска, не доказательство.

Законная формулировка: «замороженный gen_p1 воспроизводится текущей моделью на тех же
ids с точностью ≤1.7e-4 (16/16, argmax 0/16): трек согласован с теми же весами и тем же
вводом; какой движок породил замороженный трек, гейт не устанавливает (f16/fp32-разброс
≪ допуска)».

Л16-таблица (flag-массивы артефакта = мой перепуск, совпадение побайтовое):

| док | sum(flag[16:]) из 368 | нули флага (позиции) |
|---|---|---|
| w9 | **368** | 0..12 (все ≤15) |
| w11 | **368** | 0..9 (все ≤15) |
| w12 | **368** | 0..15 (все ≤15) |
| w8 | **365** | 0..4, 14, 15, 16, 17, 18 |

`docs_none L16 = [w9, w11, w12]` — точно совпадает с вычисленным вырождением (за
первой 16-кой все флаги = 1 ⇒ `std(b)==0` ⇒ `spear=None`). Слепое пятно метрики
(не пропуск данных) — подтверждено. Контроль: w13 — 285 нулей, не вырожден, L16
определён; L1/L4/L8 — `docs_none` пустые.
