## 3. Математика (что вынести в §18, часть 1)

### 3.1 Setup

At layer `l`, position `t`:
- `h_l(t) ∈ R^D` — hidden state
- `z(t) = decoder_tail(h_l(t))` ∈ R^V, `decoder_tail = RMSNorm → ·g → ·W_U^T`
- `U128` — vocab slice, K = 128

### 3.2 Два Якобиана

**(i) Full-chain `J_R(t) ∈ R^{K×D}`** — кэшируется в E-27b, считается через body-слои:
$$J_R(t) = \frac{\partial z_U}{\partial h_l(t)}\Big|_{\text{full chain }h_l \to \text{layers } l+1..23 \to \text{norm} \to \text{lm\_head}}$$

**(ii) Decoder-tail `J_tail(t) ∈ R^{K×D}`** — аналитически из кода `analytic_J(W_U, g, h)`:
$$J_{\text{tail}}(t) = \frac{\sqrt{D}}{\|h\|}\,\Big(M - (Mu)u^\top\Big), \quad M = W_U\odot g,\; u = h/\|h\|$$

**Ключевое тождество:** `J_R ≡ J_tail` **только на L23** (слоёв l+1..23 нет, единственный путь — norm + lm_head). На L < 23 они различны, и это различие монотонно убывает с глубиной.

### 3.3 Инъекция и форвард

Направление инъекции — `Ĵn(t,i) = J_R(t,i)/‖J_R(t,i)‖` (полный путь, из кэша). Форвард — **только tail**:
$$h'(t, i, \varepsilon) = h_l(t) + \varepsilon\cdot Ĵn(t,i), \qquad z'(t,i,\varepsilon) = decoder\_tail(h'(t,i,\varepsilon))$$

**Важно:** инъекция в направлении `J_R`, форвард через `J_tail`. Это осознанный выбор (desync-эксперимент), не баг.

### 3.4 Тейлоровское разложение

$$\Delta z(t,i,\varepsilon) = z'(t,i,\varepsilon) - z(t) = a_1(t,i)\,\varepsilon + a_2(t,i)\,\varepsilon^2 + a_3(t,i)\,\varepsilon^3 + O(\varepsilon^4)$$

`a_1, a_2, a_3 ∈ R^{K×K}` (индексы: `j` — выходной токен, `i` — строка инъекции).

### 3.5 Chain rule для `a_1` — точное тождество

По цепному правилу для **tail-форварда**:
$$a_1(t,j,i) = \big(J_{\text{tail}}(t)\,\hat Jn(t,i)\big)_j$$

Это **точно** при любом фите (если `resid_frac` мал). В матричной форме:
$$a_1(t) = J_{\text{tail}}(t)\,\hat Jn(t)^\top$$

**Следствия:**
- `cos(a1, ESG_R)` не равен 1 на ранних слоях — **не** нарушение chain rule, а следствие `J_R ≠ J_tail`.
- `cos(a1, ESG_tail)` — тоже не равен 1 механически (это row-нормализованная проекция `ESG_tail` на `a1`, а не то, что даёт chain rule).
- **Истинный fit-контроль** — `cos(a1(t), J_tail(t)·Ĵn(t)^T)` per-position. На L6 single-point дал +1.5% (E-32r.3). На всех слоях должен быть ≈ 1. Это — предлагаемая новая метрика `cos_a1_Jtail_Jn_median`.

### 3.6 Метрики — финальные определения

| Метрика | Определение | Роль в статье |
|---|---|---|
| **`s_l_tail`** | `ε_canon · ‖off(a2)‖_F / ‖off(ESG_tail)‖_F` | **канонический `s_l`**, глубинная метрика |
| `s_l_full` | `ε_canon · ‖off(a2)‖_F / ‖off(ESG_R)‖_F` | артефакт (смешение tail-фита и full-chain знаменателя) |
| **`d3_raw_tail(1)`** | top-1 right singular angle между `J_tail(t)`, `J_tail(t+1)` | **канонический `d3_raw`**, глубинная метрика |
| `d3_raw_full(1)` | то же для `J_R` | артефакт полного пути |
| `d3_gf_tail(1)` | то же, gauge-free (`P(p)·J`) | глубинная метрика |
| `d3_fixP_tail(1)` | то же, fixed-P(`p_0`) | диагностика (только mid-слои) |
| **`cos_JR_Jtail`** | `⟨J_R, J_tail⟩_F / (‖J_R‖_F·‖J_tail‖_F)` per position, median over docs | **desync-guard**, ключевая новая метрика |

| **`cos_a1_Jtail_Jn`** | `median_t cos(a1[t], J_tail[t]·Ĵn[t]^T)` | **истинный fit-контроль** на всех слоях (новая) |
| `quad_frac` | `(‖a1‖ − ‖a1 + 2·ε₀·‖h‖·a2‖) / \|‖a1 + 2·ε₀·‖h‖·a2‖\|` | диагностика |
| `slope_ratio` | `median(|Δz(ε₀)|/ε₀ ÷ |Δz(ε₁)|/ε₁)` | диагностика линейности |

### 3.7 Почему `d3_raw_full ≈ 1.4`, а `d3_raw_tail ≈ 0.03` на L6–L22

`J_tail(t)` — это `√D/‖h‖·(M − (Mu(t))u(t)^T)`. Top-1 right-направление `J_tail` зависит от `u(t)` и спектра `M`. Если `u(t)` почти ортогонален top-1 левому сингулярному направлению `M`, то `(Mu(t))u(t)^T` почти не двигает top-1 правое направление при изменении `u(t)`. Это подтверждается независимо в **E-35**: `|cos(û, v₁(J))| ≈ 0` на всех слоях (0.018–0.033, L23 = 0.000). Отсюда — позиционная стабильность `J_tail` на L6–L22. Полный `J_R` накапливает вращение от body-слоёв l+1..23 — это и есть `d3_raw_full ≈ 1.4`.

**На L23** (где `J_R = J_tail`) `d3_raw` = 0.162 — реальное движение; вероятная причина — более плоский спектр `M` на L23 (E-14: `PR = 33.4` vs `6–16` на L6–L21), top-1 направление чувствительнее к `u`. Проверить: `λ₂/λ₁` спектра `M` (новая метрика `eigengap_M_rel`).

## 4. Структура E-32r в §18

**Один entry**, четыре подсекции (старые E-32r.2/.3/.3.1 остаются как sub-artifacts):

### E-32r.0 — Motivation and pipeline
- Цель: разрешить A/B/C по второму порядку; измерить глубинный профиль кривизны.
- Pipeline: 16-точечный ε-sweep, кубический фит, `a_vs_ESG_cos`, `s_l`, `d3`, `quad_frac`, OLS+HC3.
- Конфигурация: N=32, T=128, слои {6,12,18,19,22,23}, GPU T4, eps 5–70%.
- Три эпизода: .2 (CPU, 5 слоёв, T=128/64) → .3 (GPU, 6 слоёв, T=128) → .3.1 (resume, tail-J).

### E-32r.1 — Linear regime (fit quality)
- `s_l_tail` = 0.00028–0.07255 ≪ 0.3 на всех слоях (таблица).
- `slope_ratio` ≈ 1.0, `resid_frac` < 0.2% (при 14% ‖h‖).
- `quad_frac` = 0.8–3.1%, растёт к L23.
- Вердикт: `s_l_tail < 0.3`, `resid_frac < 1%`, `linear_verdict = True`. **ТЗ-правило выполнено с запасом.**
- New: `cos_a1_Jtail_Jn` ≈ 1 на всех слоях (истинный fit-контроль; на L23 = `a_vs_ESG_cos` = 0.992).

### E-32r.2 — Curvature structure (A/B/C)
- **(A) подтверждён:** на слоях с gauge-структурой (L22, L23) второй порядок наследует её: `d3_gf_tail(1) ≈ 1.49` (gauge-free разрушен), `d3_raw_tail/d3_fixP_tail` малы.
- **(B) отклонён:** OLS `nb ~ α·|Δp|` не значим (`alpha_p = 0.78–0.98`); Q1/Q4 вырожден (`n_docs_with_strata = 1`), но это ограничение E-34, не E-32r.
- **(C) для амплитуды:** `nb` не коррелирует с `d3_full` (|ρ| ≤ 0.13) — исход (C) для **full-chain** `d3`. Слабая положительная `ρ(nb, d3_raw_tail)` = 0.13–0.35 на L6–L22 (IQR не пересекает 0) — **вероятно генерическая** (near-degeneracy спектра M), **не** gauge и **не** position-dependence. Пометить как вторичный эффект, ~5–10% дисперсии.
- **Глубинный профиль:** `d3_raw_tail` флэт ≈ 0.03 на L6–L22, `d3_raw_tail` = 0.162 на L23; `d3_gf_tail` флэт ≈ 1.49 на всех слоях — gauge-free неструктурирован на всей глубине.

### E-32r.3 — The desync story (why early d3_raw looked like noise)
- **Desync profile:** `cos(JR, J_tail)` монотонно 0.105 → 0.237 → 0.598 → 0.642 → 0.789 → 1.0000 (L6 → L23).
- **Артефакт:** ранний `d3_raw_full ≈ 1.4` — вращение **полного** пути, не локального readout. С истинным `J_tail` top-1 right направление стабильно уже на L6.
- **Механизм:** `J_tail = √D/‖h‖·(M − (Mu)u^T)`; если `u ⊥ v₁(M)` (E-35), top-1 правое направление стабильно по `t`.
- **L23 самосогласованность:** все метрики full ≡ tail до 4+ знаков (контроль корректности нового кода).
- **Согласование с E-31:** вращение top-16 подпространства на L6–L22 — свойство полного пути, не локального readout. Локальный `J_tail` когерентен в обоих срезах E-31.
- **Согласование с E-33r.2:** «position-dependence через `p_t`» — свойство траектории `h_t`, а не оператора `P`. `J_tail` стабилен по `t`, всё разнообразие приходит из upstream.

## 7. §22 (Future work) — обновить

**Существующий пункт «E-32-tail (не запущен)»** — обновить с учётом правильного `J_tail`:

> **E-32-tail (не запущен).** E-30b локализовал **первый порядок** в tail-модах ESG ($r \geq 118$ на L22); E-32r работал в **hidden-space** (right singular `J_tail`) и не отвечает, наследует ли **token-space** локализацию второй порядок. Три исхода: (T1) наследование, (T2) независимость, (T3) размазанность. **Важно:** базис должен быть от `ESG_tail`, не `ESG_R` (иначе — смешение desync и локализации).
