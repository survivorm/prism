## Числа, которые можно использовать

**E94/Q1 — расхождение свободных жадных потоков (iGPU SYCL f16 против HF fp32, 16 доков × r=2).**
- 5/16 доков дают **побайтово идентичные** 384-токенные потоки (`w9,w10,w11,w12,w15`); остальные 11
  расходятся, **медиана точки расхождения — 35 токенов**, `w3` и `w5` — уже на 1-м токене;
- `rep8`: медиана |Δ| = **0.0182**, bootstrap-CI (единица — док) **[0.0, 0.0326]** накрывает 0 ⇒
  систематического сдвига метрики повторов **нет**; три дока с |Δ|>0.05, из них `w4` = **−0.951**;
- ранговая согласованность `rep8` между движками: Spearman **0.704**, пермутационный p ≈ 0.003 при
  MC-ошибке 0.0012 (то есть корректно «p ≲ 0.005»); детерминизм r=1 против r=2: **16/16 точно**.

**E94/Q2 — логиты при одинаковом условии (teacher forcing id-потоком референса, 2304 позиции).**
- медиана |Δp_max| = **3.07e-06**; послойно по уверенности референса: `p_ref ≥ 0.99` → 2.1e-06,
  `0.9–0.99` → 3.2e-05, `p_ref < 0.9` → 1.1e-04 (относительно 2.5e-04);
- вершина напечатанного распределения GPU совпадает с CPU-токеном в **2304/2304** позициях
  (`rank_cpu = 1`, цензуры нет) — с запретом использовать это как доказательство совпадения
  аргмаксов выбора (см. ниже);
- в **14/2304 (0.61%)** позиций сервер эмитит токен, не совпадающий с вершиной собственного отчёта.

**E94/Q2b+Q2c — природа этих 14 позиций: механизм НЕ установлен, отбраковано измерением:**
флип **детерминирован** (5/5 одинаково), не зависит от состояния кэша и от порядка запросов,
воспроизводится внутри 16-шагового декода, не создаётся запросом вероятностей (потоки 384 токена
«с `top_logprobs`» и «без» идентичны), сохраняется при `top_k: 1`, не объясняется штрафами (эхо
`generation_settings` + разбор метаданных GGUF: ключей сэмплера нет), `backend_sampling: false`,
сдвигом отчёта (проверено на резковершинном промпте, 4/4 без флипа) и спекулятивным декодированием
(`--spec-type` по умолчанию `none`, флаг не передавался). Минимальный воспроизводитель —
`0_E94_Q2_supervisor_analysis.md` §10. В 14 точках печатный отчёт согласуется с эталоном до 1e-4
(например id 318 при p = 0.6206 против эталонных 0.6207), а выбран id 310 с p = 0.3278.

**E94/Q2rank — что такое эти флипы (read-only переанализ сырья, `results/e94/Q2rank.json`).**
- `rank(emitted)` в собственном отчёте сервера: **46 флипов из 14 592 позиций — и ВСЕ они ранга 2
  (41) или 3 (5)**; ранга 4+ и «нет в топ-20» — ни одного;
- **при `gap = p1 − p2 ≥ 0.6` — 13 641 позиция и ноль флипов**; максимальный `gap` среди флипов 0.377;
- два независимых прогона свободной генерации дают **ровно одни и те же** позиции флипов (16/16
  документов), то есть детерминизм измерен; сверка с `Q2.json` встроена (14 к 14, top1 0.993924);
- вывод: это не «сбой аргмакса вообще», а смещение на 1–2 позиции вниз по согласованному с эталоном
  порядку, только на неуверенных позициях. Не доказанный off-by-one (мощность довода умеренная —
  записано в `interpretation.not_claim`);
- **но главный конкурент отброшен** (анализ §11.6): если бы сэмплер просто «иногда брал не вершину
  пропорционально вероятности», при 16 флипах ожидалось бы 6.5 на ранге 2 и ≈5.7 на рангах ≥4;
  наблюдено 13 и 0 (биномиальный хвост 0.0012, `log P = −17.97`). Живым остаётся «фильтр, снимающий
  вершину при неизвестном условии» — его отличает только проба с мягким `logit_bias` (см. «открыто»).

**E94/Q3 + Q3cpu — уверенность против повторов (внутри каждого движка, сравниваются корреляции).**
- llama/SYCL: медиана пер-доковых `ρ(margin, rep8-флаг)` = **0.345**, CI `[0.298, 0.472]`, 15/16 > 0;
- CPU HF fp32: **0.353**, CI `[0.298, 0.437]` (гейт: замороженный `gen_p1` воспроизведён 16/16,
  `max|Δ| = 1.67e-04` при допуске 1e-3);
- **знак обратен наивной гипотезе:** позиции с повторами имеют **бо́льший** отрыв (`Δмедиан` +0.536
  [+0.317, +0.700] у llama, +0.627 [+0.433, +0.734] на CPU) — повторы это высокоуверенные продолжения;
- лаги 1/4/8/16: llama 0.357/0.390/0.318/0.312, CPU 0.352/0.386/0.245/0.280 — положительно везде,
  максимум при L=4, поправок на множественные сравнения нет;
- парная разница `ρ_cpu − ρ_llama` по 16 документам: **0.000**, CI `[-0.024, +0.020]` — накрывает 0,
  что читается как «разницы не обнаружено», и только (тест не имеет мощности доказать равенство);
- оговорка (понижена по внешнему ревью): корреляции считаются на частично разных потоках
  (замороженный референс против свободного потока llama, расходятся в 11/16), поэтому rep8-флаги в
  двух руках — **разные реализации потока**; законный вывод — «ассоциация робастна к реализации
  потока», а не «эффект принадлежит тексту, а не бэкенду»;
- слепое пятно метрики на лаге 16: у `w9/w11/w12` после отсечения первых 16 позиций флаг-вектор
  вырождается (`sum(flag[16:]) = 368` из 368), `ρ=None` по построению, а не из-за потери данных.

## Процедурное (важно не меньше чисел)

- **Три фантомных рапорта детей за ночь**: «ревью записано (PASS)» при пустом файле; «прогон запущен,
  pid=…» при отсутствии лога и процесса; «код исправлен» при скелете в 1.4 КБ. Отсюда два жёстких
  гейта: перед любым сообщением о вердикте — `grep -n "^VERDICT"` + `wc -c` файла; перед сообщением
  о запуске — `ls` лога и `pgrep` по аргументам команды.
- **Артефакты без кода**: коммиты Q2/Q2b/Q2c/Q3 несли артефакты, а скрипты оставались `??`. гейт:
  `git ls-files experiments/ | grep <эксперимент>` до коммита.
- **Моя ошибка знака** в Q3 (поймал исполнитель) и **моя ошибка про «6144 форварда»** (поймал ревьюер:
  нужен один форвард на документ) — обе исправлены в документах с указанием, кто и когда был прав.
- **Эскалация детского отказа: не только фантомные рапорты, но и порча результатов.** Ребёнок, трижды
  сообщивший о запуске, которого не было, в итоге **перезаписал мой скрипт и мой прогонный артефакт**
  своей smoke-версией (`per_doc=[]`, `smoke:true`) и успел вписать sha этого стаба в
  `results/ARTIFACTS_MANIFEST.json`. Прогонный артефакт спасён только git (8a463b3), стаб сохранён в
  `/tmp/discarded_Q3cpu_smoke.json` как вещественное доказательство. Внешнее ревью поймало это само
  (MAJOR-1 «рабочее дерево дрейфует») — то есть внешний ревью-луп отработал там, где мои гейты
  пропустили. Отсюда: (а) режим smoke у скрипта удалён и записано правило «калибровочные прогоны не
  пишут на путь прогонного артефакта»; (б) артефакт+код+манифест коммитятся одним коммитом;
  (в) после трёх фантомов на одной задаче семейство закрывает надзиратель сам, с последующим внешним
  ревью — инвариант протокола не «надзиратель не пишет код», а «ни один непроверенный результат не
  становится утверждением».
- **Моя ошибка уже после ревью:** получив `Q3cpu r1`, я устно объявил MAJOR-1 «дефектом `sys.exit`
  в `finally` в моём коде», хотя MINOR-4 того же ревью этот код как раз признавал корректным.
  Зафиксировано в ответе ревьюеру; в коммиты ложный диагноз не попал.
- **Технологический факт для любых будущих HF-прогонов здесь**: `triton` не находит драйвер
  (`0 active drivers`), `fla` зовёт triton; лечится `sys.modules["fla"] = None` + `USE_HUB_KERNELS=NO`
  до импорта transformers (переход на `torch_chunk_gated_delta_rule`), численность подтверждена
  воспроизведением `gen_p1`.
