## 1. M1 (критично). `R_can` измеряет не тот объект

**Определение (ТЗ §8.1, paper §4):** `R_can(l) = λ_max(E_K)/tr(E_K)`, `E_K = J^(p)(J^(p))ᵀ` — **канонический (gauge-free) грамиан**.
**Код (`prism/profiles.py:48-56`):**

```python
def R_can(J, p):
    Kmat = J - apply_P(J, p)          # ← (I − P)J, а НЕ P(p)J
    return _lam_share(Kmat @ Kmat.T)
```

То есть код берёт **дополнение** gauge-оператора, а не сам gauge-free срез. Докстринг кода это фиксирует как «canonical slice `K = (I−P)J`» — то есть неверное определение записано как намерение.

**Численно (исполнено):**

| | код `R_can` | по ТЗ `E_K = J^(p)J^(p)ᵀ` | `R_raw` |
|---|---|---|---|
| случайный `J` | 0.084603 | 0.515363 | 0.084913 |
| `J` с сильным uniform-компонентом | 0.919618 | 0.520092 | 0.915051 |

**Последствие.** `P(p)J` — это ~1–2 % энергии `J` (оператор убивает 98–99 % нормы), а `(I−P)J` — практически всё `J`. Поэтому λ-share кода **почти совпадает с `R_raw`** (0.9196 против 0.9151): «canonical»-кривая в коде есть «raw»-кривая с другим названием. Ровно та различка, ради которой E-40.6 существует (критерии (a′)(a)(b)(c) и сравнение «с/без удаления топ-gauge-моды»), в коде **не различима** ⇒ профиль `R_can` не может ни подтвердить, ни опровергнуть «радиальный нуль как фазу». При этом тест `test_profiles` проверяет лишь `0 < R_can(J,p) <= 1.0` — неверное определение этому удовлетворяет ⇒ тест баг не ловит.

**Фикс.** `Kmat = apply_P(J, p)` (и зафиксировать в докстринге, что `E_K` — gauge-free грамиан); добавить в реестр тождество `R_can(J,p) == λ_max((PJ)(PJ)ᵀ)/tr(...)`; в тесте — сравнение с эталонной величиной, а не с диапазоном.

**Плюс расхождение по срезу.** Paper §4 определяет `E_K` «на срезе `p = p_0`, fixP», а код берёт произвольный `p` ⇒ даже после починки оператора нужен явный дефолт p-среза (`p_t` или `p_0`) и его фиксация в теге.

## 2. M2 (критично). `kinetic`: σ не переставляется вместе с кадрами

**Код (`prism/kinetic.py:72-86, 124-129`):** кадры выравниваются венгерским сопоставлением по `|U0ᵀU1|` и **переставляются** (`U1a = U1[:, perm] * signs`), но σ остаются в исходном (ранговом) порядке:

```python
U0a, U1a, fU = align_signs_and_columns(U0a, U1a)     # перестановка применяется
Sig_t   = np.diag(S0[:r])
Sig_t1 = np.diag(S1[:r])                             # ← НЕ переставлен под perm
dSig   = Sig_t1 - Sig_t
```

При `order_cross = True` (этот флаг код сам выставляет) `E_radial` сравнивает **σ в ранговом порядке**, а кадры — в согласованном ⇒ величина «радиальное изменение» перестаёт быть радиальным изменением в том фрейме, в котором считаются остальные каналы.

**Воспроизведено** (r=2, поворот левого фрейма на 80°, спектр как мультимножество не изменился):

| | ‖ΔΣ‖² |
|---|---|
| код (σ в ранговом порядке) | **0.0018** |
| согласованный фрейм (σ переставлена по сопоставлению) | **0.5589** |

Разница ≈ в 300 раз; реальное радиальное изменение **молча уходит в `E_resid`**.

**Дополнительно:**
1. `align_signs_and_columns` **не возвращает саму перестановку** — в флагах только `order_cross: bool` и `sign_flips: list` ⇒ потребитель не может поправить сопоставление, даже если захочет.
2. `channels_reportable` (`kinetic.py:149-156`) не демотирует `E_radial` при `order_cross` — а именно этот канал объявлен «всегда интерпретируемым» (`["E_radial", "E_off_manifold"]` в невалидном режиме).
3. Та же несогласованность в `channel_energy_matrix` (`kinetic.py:186-203`): `S1r` не переставляется ⇒ `A1 = embed(ΔΣ)` соответствует другому сопоставлению. Само тождество `Σ_ij G_ij = ‖ΔJ‖²` при этом не страдает (оно алгебраическое), страдает **атрибуция по каналам**.
4. Тест `test_align_signs_and_columns_recovers_flips_and_perm` проверяет восстановление кадров, но **не проверяет, что σ едут вместе с ними** ⇒ дыра не покрыта.

**Фикс.** Возвращать `perm` из `align_signs_and_columns`; в `kinetic_decomposition`/`channel_energy_matrix` переставлять `S1` согласованно (`S1a = S1[perm]` с учётом знаков — σ положительны, знаки не влияют); при `order_cross=True` помечать `E_radial` как `ambiguous` либо пересчитывать в согласованном фрейме.

## 3. M3 (высокий). `s()` при агрегации `mean` ломает тождество

**Исполнено** (n=8, K=32, D=16):

| aggregation | `frac_K` | `1 − 2c + s²` | остаток | `O1 − s²` |
|---|---|---|---|---|
| `ratio_of_means` | 0.941068376932 | 0.941068376932 | **0.0** | −2.2e-19 |
| `mean` | 0.941029947810 | 0.941028236814 | **+1.7e-6** | +1.7e-6 |
| `median` | 0.940234157351 | 0.940234157171 | +1.8e-10 | +1.8e-10 |

Причина: `s()` при `mean` возвращает `mean_t(√r_t)`, и `s² = (mean √r)² ≠ mean(r)` (Йенсен) — **ровно та величина, о которой ТЗ §3.2 предупреждает** («`s = mean_t(√O1_t)` в квадрате — другая величина (≤ по Йенсену) … это ошибка реализации, а не свойство данных»).

**Почему это тихий баг ядра:** `operator_checks.s()` не предупреждает и не различает случаи; реестровый guard `O1_eq_s2` проверяет только дефолт (`ratio_of_means`) ⇒ не ловит. `exp40_1_t4a.py` считает mean-ячейку **вручную и правильно** (`s2_m = mean_t(s2_t)`) ✓, но любой следующий потребитель API (E-40.2/0.6/0.7) возьмёт `s()` и получит неверное `s²` без единого предупреждения.

**Фикс.** Либо `s(..., aggregation="mean")` возвращает `sqrt(mean(r))` (тогда `s² = mean(O1)` и тождество замыкается), либо в докстринге — явное предупреждение + тест `frac_K == 1−2c+s²` **для каждой** агрегации, которая заявлена как закрывающаяся.

## 4. M4. `cos_J_PJ` при `mean`/`median` — не косинус

**Исполнено:** pooled-косинус = 0.848520; среднее по позициям = 0.848763; `cos_J_PJ` при `ratio_of_means` = 0.848520 ✓ (совпадает), при `mean` = **0.849195**, при `median` = **0.854060** — т.е. ни pooled, ни среднее по позициям. Это `mean(c_t)/mean(s_t)` — гибрид, смысл которого молча меняется с агрегацией; докстринг «cos(J, PJ) = c/s» об этом молчит, а в тексте проекта цитируется «0.064–0.108» (это corpus-значение).

**Фикс.** Либо ограничить `cos_J_PJ` агрегацией `ratio_of_means`, либо переименовать в `c_over_s` и запретить его использование как косинуса.

## 5. M5. `resolution_floor`: `floor_full` структурно ≈ 0

**Исполнено:** `floor_by_size = {8: 0.384, 16: 0.229, 32: 0.0}`, `floor_full = 2.4e-17`.

Причина: при `m = n` код берёт `rng.choice(n, n, replace=False)` — **перестановку** всех документов; для перестановочно-инвариантной статистики (а это почти все) все `reps` значений одинаковы ⇒ `std = 0`. Докстринг при этом предписывает: «Compare an effect against `floor_full` BEFORE interpreting absence: effect below the floor ⇒ status `not_testable`» ⇒ **гард структурно вакуумен: любой эффект «проходит»**.

**Фикс.** Считать `floor_full` бутстрапом с возвращением (ресемпл документов с заменой), а не перестановкой; и/или брать флор на максимальном размере `m < n`.

## 6. M6–M10. Валидация identity-relevant полей

**M6 `operator_fraction`** (`operator_checks.py:36-48`): `norm_type` не валидируется — всё, что не `"energy"`, трактуется как `"norm"`. Исполнено: `"energy"` → 0.013316, `"norm"`/`"angle"`/`"ENERGY"`/`"nrom"` → 0.115395. Для поля, которое сам проект называет identity-relevant (paper §6 item 19: норма vs энергия отличаются квадратом), опечатка даёт молчаливое изменение величины на √.

**M7 `permutation_test`** (`nulls_and_stats.py:112-122`): `alternative` не валидируется — всё, что не `"greater"`, трактуется как `"less"`. Исполнено: `"gt"` → p = 0.667 (зеркало правильных 0.334) ⇒ вердикт инвертируется без ошибки.

**M8 `mp_upper_edge`** (`nulls_and_stats.py:47-57`): докстринг утверждает «p=8 gives **1.4425**, NOT the quoted 1.45». Функция даёт **1.449915** — как ТЗ §1.4 («`n=192 → 1.4499` (не `1.4425` — отозванное число патча v2)»). То есть **докстринг ядра противоречит и функции, и ТЗ**; отозванное число задокументировано как правильное. Исполнено: (6,32)=2.053525, (6,192)=1.384803, (8,32)=2.250000, **(8,192)=1.449915**.

**M9 два «флага стабильности»**: `svd_bundle["stable"]` — в σ (`min|σᵢ−σⱼ|/σ₁ > 1e-2`), `kinetic.rotation_unique` — в σ² (`min|σᵢ²−σⱼ²|/σ₁² > 1e-2`). Исполнено на σ=[1.0, 0.991]: `stable = False`, `rotation_unique = True` ⇒ **на одном спектре флаги противоречат друг другу**. Обе формы присутствуют в артефактах, и нигде не сказано, что это разные конвенции (E-38c `gap_min` — «в единицах σ», патч v2 §1.4 — σ²).

**M10 `principal_angles`** (`svd_bundle.py:29-40`): нет проверки ортонормированности (в `transport._check_frame` — есть), а `np.clip(s, 0, 1)` **маскирует** нарушение. Исполнено на неортонормированных фреймах: «косинусы» = [1.0, 1.0, 0.3878] — значения >1 тихо срезаны до 1 ⇒ неверный объект проходит как валидный.

## 10. Приложение: что исполнено, что прочитано

**Исполнено (numpy-часть ядра):** `p_algebra` (closed forms, λ_max ≤ p_max, secular roots, g_uni ≡ gauge_share), `operator_checks` (тождество по 4 агрегациям, cos_J_PJ, apply_P, operator_fraction), `nulls_and_stats` (mp_upper_edge × 4 пары, operator_null × 2 вида, reduction_control, resolution_floor), `svd_bundle` (stable σ vs σ², principal_angles на неортонормированных фреймах), `profiles` (R_can vs определение ТЗ, R_raw, G_l, r_cross).
