# AT0_4 — T0.4 «Разводящая клетка 3×2: кто несёт профиль» (CPU-форварды)

**Премег v2 (2026-11-13, правки по смоку/разработке — см. §10).** Серия AT (ТЗ v1.1, T0.4): disk-only эксперименты AT0_1–AT0_3
закрыты; AT0_4 — **волна 2**, единственный эксперимент серии, требующий **новых CPU-
форвардов** (вход не вычисляется из TPU-npz — P10 ТЗ).

## 0. Цель

Разделить носителей лаговой структуры (r, f_DC, форма профиля) по факторам
**{модель (обучение) × текст (корпусная избыточность)}** факторизацией 3×2:

| | real (токены в исходном порядке, TF) | mix (full-permutation тех же токенов) |
|---|---|---|
| **R0** trained (Qwen3.5-0.8B) | есть | есть |
| **R1** random trunk, trained tied embed+head | есть | есть |
| **R2** random всё (т.ч. tied embed+head), real token ids | есть | есть |

Измерять **различающие** переменные (не тождества): `r`, `f_DC`, `r_max`, `d_eff`,
форма профиля ρ̄(k). Тождество G1 (r = N·f_DC) — sanity, не гейт (П4 ТЗ).
Сумма Σ — НЕ тестовая статистика (G7: инвариантна к перестановкам).

## 1. Вход (v1.1, P10: новых CPU-форвардов)

- **Модель:** `/data/Qwen/Qwen3.5-0.8B` (Qwen3.5-0.8B: 24 слоя, hidden=1024, hybrid
  18×linear-attn + 6×full-attn (interval 4), `tie_word_embeddings=True`, vocab=248320,
  RMSNorm). fp32, CPU, torch 2.14.1, 4 треда (политика серии).
- **Доки:** **8 из P1_own** (`results/e64/tpu_v8/P1_own.npz`): `own_w0..own_w7`
  (первые 8 в лексикографическом порядке — детерминировано, без sampling-шума).
  **Обоснование выбора:** P1_own — единственный источник с токенами (P2_corpus: 0/16
  доков с токенами, G16; gen_layers — свои токены есть, но gen-доки — модельные
  генерации на калибровочных промптах, а не «real corpus»; T0.4 требует TF на
  реальной последовательности + mix-вариант той же последовательности).
  T=384 на каждый, N=383 приращений, K=96 (канон серии).
- **real** = 384-токенная последовательность дока из `P1_own.npz` как **самодостаточная**
  teacher-forced последовательность (без prompt-префикса). **Почему без prompt:** P1_own
  — авторегрессионные генерации (e64_tpu.py: prompt 64 wiki-токена → 384 greedy-токенов,
  hidden на позициях 64..447); воспроизведение точных TPU-hidden требует prompt-токенов
  И точного TPU-bf16-пайплайна — локальный pin-пул совпадает по fp, но TPU-bf16 vs
  CPU-fp32 расхождение в linear-attention state (greedy-каскад: w0 93%, w1 5% токенов)
  делает косинус-пин недостижимым без TPU-аудита. AT0_4 — относительное сравнение
  R0 vs R1/R2 на ОДНОМ CPU-пайплайне, абсолютное совпадение с TPU не требуется.
- **mix** = full-permutation ТОХ ЖЕ 384 токенов дока (многожество сохранено, порядок
  уничтожен). Одна общая перестановка на документ для ВСЕХ клеток (парный дизайн —
  аналог M2 exp91): `np.random.default_rng(7).permutation(toks)` по докам в
  лексикографическом порядке; seed_shuffle=7 зафиксирован.
- **Слой:** L=23 (0-based) → `hidden_states[24]` (hook-семантика серии: выход слоя L
  = hidden_states[L+1]; off-by-one уже стоил пина, exp91 11.11).

## 2. Рандомизация (фикс бага ndim≥2, T0.4 v1.1)

Правило: **std-matched по каждому тензору** — каждый параметр заменяется на
`N(0, σ_t)` независимых значений, где `σ_t = std(trained-тензор t)` (вычисляется
по тензору, таблица σ_t — в артефакт с формами и sha). **RMSNorm gain-ы (1D,
ndim=1) рандомизируются** — предыдущий код серии рандомизировал только `ndim>=2`
(`exp66_lesion_health.py:40`, `exp7177c_pairladders.py:37`), пропуская 115 1D-
параметров (input/post-attention layernorm ×24, linear_attn.norm ×18, model.norm,
A_log ×18, dt_bias ×18) — это и есть исправляемый баг.

- **R0** = trained (без рандомизации).
- **R1** = ВСЁ, кроме `model.embed_tokens.weight` и `lm_head.weight` (tied-пара,
  один и тот же тензор) → random. «trunk» = все 24 блока + `model.norm` + все
  layer-norm'ы. (НЕ exp91 half-random: там сохранялись layer-norm'ы — здесь нет.)
- **R2** = ВСЁ random, **вкл. tied embed+head как ОДИН общий random-тензор** (tied-
  семантика: после рандомизации lm_head и embed_tokens делят одно storage — S2 проверяет
  torch.equal). **Единственное различие R1 и R2 — embed** (trained в R1, random в R2);
  стволы побайто идентичны для одного S, поэтому R1 ≠ R2 и P2-контраст определён. (Не
  «trained-тied сохраняется»: тогда R2≡R1 и P2≡0 — неоднозначность устранена в v3 по
  внешнему ревью.)
- **Сиды:** `torch.manual_seed(S)` ПЕРЕД `from_config`, S ∈ {11, 12, 13} (G17:
  только default_rng/manual_seed, hash() запрещён). Для одного S стволы R1_S и R2_S
  побайто идентичны (один init-поток, trained-пара накладывается поверх — analog
  M9 exp91). R0 — детерминирован, «сид» для него не существует (1 инстанс).
- **Таблица σ_t:** 115 1D-тензоров имеют mean 0.08…3.31, std 0.08…2.8 — N(0,σ)
  не обнуляет их (σ>0), но снижает амплитуду gain-ов; A_log (mean −1.2, std 0.78)
  → случайные значения включают положительные (медленный decay) — потенциальная
  нестабильность linear-attn покрывается гейтами finiteness + невырожденности.
- **Tied-проверка (S2):** после каждой рандомизации `torch.equal(lm_head.weight,
  embed_tokens.weight)` — иначе STOP.

**Клетки и инстансы:** R0×real, R0×mix (1×1), R1×{real,mix}×{11,12,13},
R2×{real,mix}×{11,12,13} = 14 инстансов × 8 доков = **112 forward**.

## 3. Метрики (du_unit L23, per-doc)

`u_t = h_t/‖h_t‖` (fp64-пересчёт из fp32 hidden); `Δu_t = u_t − u_{t−1}`, t=1..383.

```
r     = ‖ΣΔu‖² / Σ‖Δu‖²              # (G1) = N·f_DC — тождество, sanity
f_DC  = ‖mean(Δu)‖² / mean(‖Δu‖²)
r_max = 4 / Σ‖Δu‖²                   # (G4, только du_unit) — замераТЬ ДО оценки пре-рега
d_eff = exp(−Σ λ̂_i ln λ̂_i)          # PCA облака u (383×1024), λ̂ — норм. собственные
ρ̄(k)  = moments-ACF (field.acf_moments, кано́н серии) на Δu, k=1..96 — описательно
          (НЕ перестановочно-инвариантен: G7 покрывает только r и Σ; mix меняет профиль —
          это и есть P3/P4)
```

- `d_eff` — **по данным** (собственные значения Cov(u)), не по проектору (реестр §0.2).
- `r_max` вычисляется и записывается в артефакт **до** применения пре-рег-правил
  (D7/G10 ТЗ) — порядок в коде: метрики → r_max-отчёт → оценка гипотез.

## 4. Гейты

### 4.1 Sanity (ПЕРВЫМИ, до доверия random-клеткам; печать в лог)

- **S1 (R0 liveness, главный):** per-doc **head-accuracy R0×real ≥ 0.90** на собственных
  генерациях (#{t: argmax(logits_t)=tok[t+1]}/(T−1)). Проверка, что trained-модель «жива»
  на этом тексте (валидный baseline). Измерено на смоуке: 0.945–0.977. Провал ЛЮБОГО дока
  → STOP (RC=2). (Исходный S1 — косинус-пин vs TPU npz — **заменён**: TPU-bf16 vs CPU-fp32
  расхождение в linear-attention state делает его недостижимым без TPU-аудита; AT0_4 —
  относительное сравнение R0 vs R1/R2 на одном CPU-пайплайне, абсолютное совпадение с TPU
  не требуется. См. §1 «почему без prompt».)
- **S2:** tied-проверка R1/R2 (torch.equal embed/lm_head).
- **S3 (finiteness, перед полным прогоном):** 1 док × 32 токена, **ВСЕ 3 сида**
  (R1_S/R2_S, S∈{11,12,13}) — hidden конечны (аналог sanity(a) exp91). Провал → STOP
  (RC=3). (v3.1, р1-ревью: был только seed 11 — расхождение S12/S13 убивало ~1ч
  посреди прогона.)
- **S4:** G1-тождество r = N·f_DC — max |r − N·f_DC| / (N·f_DC) ≤ 1e-9 (fp64).
- **S5:** Telescope ‖ΣΔu‖ = ‖u_383 − u_0‖ — max отклонение ≤ 1e-9 (fp64, точно).

(S6 head-accuracy убран как отдельный гейт — его функция у S1 liveness.)

### 4.2 Невырожденность random-клетки (T0.4; иначе `not_testable`)

На каждый (инстанс, док) R1/R2 (3 условия, И), на real-режиме:
- **G_nd1:** `cv(‖Δu‖) = sd/mean > 0.05` по N позициям — распределение шагов не
  коллапсировало (не все шаги одной длины/ноля).
- **G_nd2:** `d_eff ≥ 3` — облако u не сжато в точку/линию (d_eff: точка→1, линия→2).
  **(v3: порог 8 убивал ключевые клетки — miscalibration, поймана смоуком):** на
  random×real d_eff≈5 — облако ограничено словарём дока (nuniq 16..66), это свойство
  входа, а не коллапс. Измерено: R0 real 11..21, random×real ~5, random×mix 15..18.
  Порог 3 ловит истинный коллапс (точка/линия), не отсекая low-vocab доки.
- **G_nd3:** `mean_t H(softmax(logits_t)) / log(V) > 0.5` (V=248320) — выходное
  распределение модели не вырождено (не дельта на одном токене). [Операционализация
  «энтропия p не вырождена» ТЗ; на trained (R0) заменяется S1 liveness.]
- **G_nd4 (отчёт + жёсткий порог, v3.1 по р1-ревью):** нормы random vs trained —
  per-instance (real-режим, 8 доков) median/IQR ‖h‖ против R0×real. **Порог:
  median ‖h‖ > 100×R0×real ⇒ инстанс «divergent» ⇒ P1–P4 `not_testable`** (р1-ревью:
  только отчёт — finite-but-huge state дивергировавшей модели давал бы «валидные»
  метрики; S3 ловит только inf). При A_log→N(0,σ): exp(A_log)≈1 (weak decay) —
  потенциальный рост state-вектора linear-attn.
- **Degenerate-док (v3.1, р1-ревью):** точечный коллапс (Δu≡0, c0=0) — метрики r/f_DC
  не определены; док помечается `degenerate` (ok=False в G_nd), инстанс `not_testable`
  по существующему правилу «все доки вырождены»; P1–P5 считают медиану по оставшимся
  докам. (Было: неловленный ValueError → краш ДО метки not_testable — главный случай
  G_nd2.)

**Правило (v2, исправлено):** инстанс = `not_testable` только если **ВСЕ** доки
вырождены (n_ok==0). Исходное правило «любой док» убивало инстанс на одном
вырожденном доке (смоук: 1 док, real d_eff=5.0 → весь инстанс not_testable). Per-doc
таблица гейтов отчитывается всегда; r считается по всем докам (r определён при любом
d_eff, c0>0), вырожденность — диагностический сигнал, а не условие определённости r.

## 5. Пре-рег (различающие переменные, НЕ тождества)

Оценка — per-doc, агрегация — **медиана по докам** (per-seed отчёт отдельно),
α = 0.05.

- **P1 (R2×real): «ортогональный марш».** r ≈ 1 — **ТОЛЬКО если r_max ≥ 1 в этой
  клетке** (измерено до оценки). `r ≈ 1` := r ∈ [0.75, 1.5]. При r_max < 1
  предсказание запрещено геометрией (G4) ⇒ исход клетки **`vacuous(r_max<1)`** —
  объявленный исход (условно достижима), НЕ провал. При коллапсе — гейт
  невырожденности ⇒ `not_testable`. **Семантика (v3, по ревью):** метрики — на
  приращениях Δu, НЕ на u_t: для некоррелированных приращений E[r]=1 при любом размере
  шага, поэтому «ортогональный марш» и r_max≥1 не противоречат; r_max<1 — «длинные»
  шаги, режим, где чтение «марш» неприменимо (G4). **A priori-ожидание (v3.1,
  р1-ревью):** для истинно случайных unit-векторов E[Σ‖Δu‖²]≈2N=766 ⇒ r_max≈2/N≈0.005
  <1 — т.е. **`vacuous(r_max<1)` — наиболее вероятный исход для случайной модели**;
  подтверждение P1 возможно только если случайный ствол на реальном тексте даёт
  «короткие» шаги (r_max≥1) — объявлено заранее, не подгонка.
- **P2 (R1 vs R2, real): «ствол vs эмбеддинг».** `|median_doc r(R1) − r(R2)| ≥ 0.1`
  (per-seed) ⇒ trained tied-пара (embed+head) меняет структуру шага; `< 0.1`
  (все 3 сида) ⇒ структура несётся стволом, trained-эмбеддинг на r не влияет.
  Направление не пре-регится (a priori не объявляем знак). **Исходы (v3.1):**
  «different» все 3 сида ⇒ embed_head_contributes; «same» все 3 ⇒ trunk_carries;
  смешанное (1–2 сида) ⇒ `mixed` (неоднозначность — объявленный исход, не фазл).
- **P3 (R0×real vs R0×mix): «текст».** Направленная гипотеза (ТЗ): `median_doc
  r(mix) − r(real) > 0` — корпусная избыточность даёт когерентный дрейф (real
  «сплошнее», mix — ближе к маршу). Нулевой исход (≤0) допустим и публикуем:
  mix не убивает/не создаёт структуру ⇒ носитель — модель.
- **P4 (random × real vs random × mix): «случайная модель не читает текст».**
  `median_doc |r(R?×real) − r(R?×mix)| < 0.1` (R1 и R2, per-seed) — ноль-проверка:
  random-модель нечувствительна к порядку токенов. Провал (≥0.1) = **token-statistics
  флаг** (аналог full-random-флага M9 exp91): даже случайные веса «видят» локальную
  структуру текста — сильный результат, отдельный вердикт.
- **P5 (f_DC, зеркало P3):** `f_DC(mix) − f_DC(real) > 0` для R0 — DC-доля как
  независимая координата (f_DC = r/N тождественно по G3, но пересчитана независимо
  в fp64 — расхождение > 1e-9 = S4-сбой, не «отдельный сигнал»).

**Отрицательные результаты публикуемы.** «Дип/форма профиля» в клетки —
описательно (G7: сумма и dip поодиночке гипотезы не различают — ТЗ v1.1).

## 6. Слово о цене и порядке

- Forward 384 ток. fp32/4tr: замер **51.7 с** (median, warm; ТЗ оценивало 87 с —
  консервативно). 112 forward ≈ 99 мин + 15 загрузок моделей ≈ **~2 ч**.
- Порядок: sanity S1–S3 (до доверия) → полный прогон → S4/S5 → метрики →
  r_max-отчёт → оценка P1–P5 → артефакт.
- Память: модель 752M fp32 ≈ 3 ГБ + hidden (384×1024×4B×24 слои ≈ 37 МБ/док) —
  в пределах (watchdog: used 36/62 ГБ на момент запуска).

## 10. Изменения v2 (право по смоку/разработке, до прогона)

1. **Вход: [tok] без prompt-префикса** (было: «real = исходная последовательность»). P1_own
   — авторегрессионные генерации (prompt 64 + 384 gen); точные TPU-hidden требуют prompt
   И TPU-bf16-пайплайна. Локальный pin-пул совпадает по fp, но TPU-bf16 vs CPU-fp32
   расхождение в linear-attention state (greedy-каскад: w0 93%, w1/w2 5% совпадения
   токенов) делает косинус-пин недостижимым. AT0_4 — относительное сравнение на одном
   CPU-пайплайне → самодостаточный вход [tok] (384), reproducible по sha npz.
2. **S1: R0 liveness (head-acc ≥ 0.90)** вместо TPU-косинус-пина. S6 убран (функция у S1).
3. **G_nd: not_testable только если ВСЕ доки вырождены** (было: «любой док»). Смоук:
   real-клетки random d_eff≈5 (<8), mix≈17 — «any» убивал инстанс на 1 доке. Per-doc
   отчёт сохраняется; r считается по всем докам.
4. **d_eff-порог 8** обоснован: d_eff у всех LLM на тексте 5..21 (low-dim manifold);
   8 = «не тривиально коллапсировано». Измерено: R0 11..21, R1/R2 real ~5, mix ~17.

## 11. Изменения v3 (по внешнему ревью TZ, 2026-11-13)

1. **R2-однозначность (MAJOR ревью):** «tied сохранён» читалось как «trained-тied
   сохраняется» ⇒ R2≡R1 ⇒ P2≡0. Явное: R2 рандомизирует tied embed+head как ОДИН
   общий random-тензор; единственное различие R1/R2 — embed.
2. **G_nd2 порог 8→3 (MAJOR, мискалибровка):** d_eff≈5 на random×real — vocab-limited
   (nuniq 16..66), не коллапс; порок 8 делал P1/P2 не testable. ≥3 = точка/линия.
