## 3. Мажорные

### M1. PHR — не эстиманд H_phr (содержательно, не косметика)

Обозначу `D_L = (L1−L2)/2`, `D_S = (S1−S2)/2`. Тогда `PHR = D_L + D_S`, `INT = D_L − D_S`.

H_phr в §1: «специфическое содержание **повторяемой** фразы (**запоминание именно этой фразы**)». Это про **периодическую строку**, т.е. про `D_L`. Главный эффект `PHR` усредняет по строкам и включает `D_S` — контентное различие **перемешанных** блоков.

Три режима:

| режим | D_L | D_S | PHR fires? | это H_phr? |
|---|---|---|---|---|
| контент не важен | ≈0 | ≈0 | нет | нет ✓ |
| **bag-of-words**: какие токены были — важно, порядок нет | ≈D_S | ≠0 | **да** | **нет** ✗ |
| запоминание повторённой фразы | ≫D_S | ≈0 | да | да ✓ |

Средний режим вполне вероятен (пост-суффикс идентичен, различается только мешок токенов префикса) — и он даёт `PHRASE_SPECIFIC`, который §17 читает как «канал: содержание конкретной фразы… запоминание». Это overclaim.

**Фикс бесплатный и он же делает INT несущим:** вердиктное количество для H_phr — **простой эффект** `L1 − L2 = PHR + INT` (все четыре условия уже прогоняются), против `δ_PHR` из `N_PHR = S1' − S2'`. Тогда тест буквально спрашивает: «контентное различие больше, когда контент **повторён**, чем когда он перемешан?» — и средний режим正确地 не срабатывает (D_L ≈ D_S ≈ масштаб нуля). Терм-непересекаемость сохраняется.

Альтернатива (если оставляете PHR): переписать §17 — `PHRASE_SPECIFIC` = «контент-канал в среднем по строкам», и требовать `INT`-квалификацию для формулировки про запоминание. Но первой вариант строго лучше отвечает заявленному вопросу.

### M2. Путь провала `G_inside_rep`: «neither → NO_2B» при нерешённом контрасте

§11 шаг 3: `neither → NO_2B_SPECIFIC_EFFECT`, сноска «нерешённый контраст → вердикт по решённому + тег GATE_*».

Если гейт провален на n=2 (PHR не тестировался), а REP решён и нулевой — «вердикт по решённому» ведёт в `NO_2B_SPECIFIC_EFFECT`, который §17 читает как «**ни содержимое, ни периодичность** не создают пост-эффекта». Это отсутствие измерения как свидетельство отсутствия — тот самый A3 из AT8_2.

**Патч:** явно развести
```
оба протестированы, оба нулевые → NO_2B_SPECIFIC_EFFECT
один нулевой + второй нерешён   → NOT_RESOLVED + GATE_N2/N16
```

### M3. Слойный тег считается на n=16 для обоих контрастов

§11 шаг 6: «слойный тег (на n=16 … объединение {REP, PHR})». Но PHR primary — **n=2**, и весь смысл этого выбора в том, что на n=16 контент стёрт (ваш же §9: r1 4.66 → r2 0.39 → r3 0.13). Значит слойная поддержка PHR читается ровно на той дозе, где эффекта быть не должно → тег систематически пустой/ложный.

**Патч:** тег per-contrast на **его** первичной дозе (PHR@n2, REP@n16); объединение — только если оба значимы на своих дозах. И явно пометить, что тег — по точечной оценке (в отличие от CI-правила вердикта), как наследие R2.

### M4. Проверка пулинга δ сделана на наблюдаемой, которая PHR больше не использует

Ответка §6: «per-doc p90|e_null| **(L23, cos_raw)**: n2 0.1526, n16 0.1328, ratio 1.149 → пул; для PHR консервативен на 0.5%».

Но PHR теперь на norm_delta, где числа другие (ваша же таблица r1-ответки): n2 δ = **1.1590**, n16 δ = **1.5668**. Отношение n16/n2 = **1.35** — и направление **обратное** (на cos_raw больше n2, на norm_delta больше n16). Пул/per-dose@n2 ≈ **+36%**, а не +0.5%.

Направление всё ещё консервативное (пул больше), так что вердикт не флиппит — но **проверенное допущение проверено не на той величине**. Переделать disk-only из R2-store (минуты), записать оба ratio в §8.

## 4. Минорные

**m1. Коллизия сид-формулы между доками.** `10000·i + 1000·doc_idx + n`: при `Δi=1, Δdoc=−10` сумма совпадает. Пример: `S1(doc 10)` и `S2(doc 0)` при n=2 → оба 20002. Внутри дока все четыре i различны (шаг 10000) ⇒ `N_perm`, `N_PHR` независимы ✓, но кросс-доковая независимость draw'ов нарушена для doc 10–13. Фикс: шаг `100000·i` или канонический идиом проекта `zlib.crc32(f"S{i}|{doc}|{n}".encode())` (аддентум G17).

**m2. `doc_idx` не запинен.** «Замороженный порядок R2-доков (0..13)» — это `sorted(store.keys())` (chat→code→math→wiki) или порядок `DOMAIN_ORDER` (wiki→math→code→chat)? Разные присвоения → разные перестановки. Не флиппер, но воспроизводимость. Зафиксировать список 14 имён с индексами таблицей (как AT8_3 §4).

**m3. Двухрежимная оговорка — остаток от `N_content`.** С `N_PHR = S1'−S2'` порог **не схлопывается к нулю** (draw-шум всегда положителен). Реальный остаточный риск другой: **σ_L ≫ σ_S** (периодическая строка шумнее по докам, чем перемешанная) — тогда порог, построенный только на S-строке, анти-консервативен. Переформулировать так; и это проверяемо disk-only из R2-store: сравнить across-doc SD `e_spec` и `e_null` на обеих наблюдаемых.

**m4. G14-координаты per contrast.** В claim теперь два разных `stat` в одном вердикте (`norm_delta` для PHR, `lag1_pair_cos` для REP). §13 не требует метки на каждом числе. Добавить явно — иначе ровно та ошибка «число без координат», из-за которой началась вся линия.

**m5. `N_perm` структурно не сматчен по дисперсии.** `Var(N_perm) = 2σ_S²` против `Var(REP) = (σ_L²+σ_S²)/2`. При σ_L≈σ_S порог шире в ~1.41× (переконсервативно). Теперь, с `S2'`, доступен сматчен-нуль `(S1+S2−S1'−S2')/2` с `Var = σ_S²` — **бесплатно**. Не требую менять (текущий объявлен и консервативен в правдоподобном режиме), но выбор стоит сделать явно, а не по умолчанию.

**m6. Смета слияния.** «384 > 336 (224+112)» — 112 это до `S2'`. Раздельно теперь 224+140 = **364**, слитно 384. Вывод не меняется, число устарело.

**m7.** «S_shuffle — диагностика» + «fail-loud assert» в §10 — семантически это bug-guard-гейт, не диагностика. Слово выбрать одно.
