## 2. ⛔ Мажорные — все три на новом главном гейте

### F1. `S_cross_store` не может пройти: стор округлён до 6 знаков, а толеранс — относительный 1e-6

R2 `cond_series` пишет **`round(float(x), 6)`** для `cos_raw`/`cos_state`/`norm_delta` (проверено по коду). Свежий форвард даёт полную точность. Гейт: «bit-identical **или** max rel diff < 1e-6».

- **bit-identical** между raw-float и 6-знаковым store-значением — недостижимо по построению;
- **rel diff < 1e-6** — тоже: округление само даёт до 5e-7 абсолюта. При `|cos_raw| = 1e-3` это **5e-4 относительных**, в 500× выше порога. А `cos_raw` — лаг-1 косинус приращений, он проходит через нуль: на 272 позициях (wiki_0, n=2: T+18−2) значения ~1e-3 и меньше гарантированно есть.

⇒ **гейт падает всегда, даже при идентичном численном пути**, и запускает задекларированный fallback (+112 фд, 60 мин) — то есть удваивает цену по построению. Либо кодер начнёт ослаблять порог ad hoc.

Разрешимость зависит от **незаявленной** детали: переиспользует ли 2b `cond_series` verbatim (с тем же `round(...,6)`).

**Фикс (запинить, цена 0):**
> Свежий ряд считается **тем же `cond_series`, что R2 (round до 6 знаков)**; гейт — **bit-identity округлённых значений**. Относительный 1e-6 — только как диагностика, с абсолютным полом 5e-7 (полпоследнего разряда).

Это не ослабление, а правильный масштаб: округление до 6 знаков даёт естественный допуск ~5e-7 абсолюта, а реальные расхождения пути (другой кернел/версия) в cos-единицах — 1e-6…1e-5, т.е. **ловятся**. Плюс сравнение становится достижимым. Заодно запинить **домен сравнения** (весь ряд vs post-окно) — сейчас не сказано.

**Туда же: `use_cache` не запинен.** R2 явно использовал `use_cache=False` — и его докстринг называет это детерминантом пути: *«use_cache=False — GDN-путь р1 (якорь CE wiki_0 = 3.2320)»*. L6/L12/L18 — GDN; cached/uncached путь там разный. В §10.1 пины attn/dtype/torch/py/threads есть, `use_cache` — нет. Добавить (и `torch.set_grad_enabled(False)` для полноты).

### F2. Гейт покрывает только n=2 — а `REP@n16` тоже вычитает сохранённый L1

Вердиктная поверхность:
```
E_phr@n2  = L1(n=2)  − L2(n=2)                ← L1 из стора,covered гейтом
REP@n16   = (L1(n=16) + L2 − S1 − S2)/2       ← L1 из стора, НЕ covered
```
Гейт: «wiki_0, **n=2**, loop». Второй вердиктный тест остаётся без защиты. И путь **dose-зависим**: длина последовательности 274 vs 400 токенов → другие формы тензоров, другие тайлы SDPA/GDN-сканов. Расхождение может появиться на n=16 и не появиться на n=2.

Плюс слойный тег REP считается на n=16 по δ_REP(L) — тоже наследует непокрытый L1.

**Фикс:** +1 форвард (wiki_0, **n=16**, `loop`) → гейт покрывает обе первичные дозы. **+14 с**, смок 20+2 = 22 фд.

### F3. §10.2 и §11 противоречат друг другу о судьбе провала гейта

- §10.2: «Провал → **fallback** (задекларирован заранее): перегон всех 4 R2-условий свежими… факт fallback'а — в манифест».

## 3. Умеренные

### F4. `CALIBRATION_WARN` конфаундится с наличием эффекта — рецидив класса «нуль содержит свои термы»

Пост-прогоновый чек: `SD_docs(near_E_phr)/SD_docs(near_N_PHR) > 1.5 → CALIBRATION_WARN`.

Но `near_E_phr` под H1 несёт **реальный эффект**, варьирующий по докам ⇒ его SD включает вариацию сигнала, не только шума. Отношение >1.5 может сработать **из-за настоящего гетерогенного эффекта**, а не из-за несовпадения шумовых шкал. То есть диагностика, валидирующая калибровку порога, загрязнена тем самым сигналом, который порог тестирует — ровно класс `N_content = PHR − INT` из r2.

**Фикс (декларация, цена 0):** «при fires отношение включает вариацию эффекта; `CALIBRATION_WARN` в этой ветке не читается как анти-консервативность порога. Чистая интерпретация — только при нулевом вердикте». Опционально: считать σ-отношение и на `N_perm`-паре (обе стороны — нули) как незагрязнённый якорь.

### F5. Число `10⁻¹²` приписано не тому объекту и не той версии δ

§11: «P(firing | **эффект масштаба e_spec**) ≈ 10⁻¹²». Но 10⁻¹² — это **type-I под H₀** (mean = μ_null = 0.7538) при **per-dose** δ. Пересчёт всех четырёх величин (SE = 0.0802):

| объект | pooled δ=1.4897 | per-dose δ=1.1590 |
|---|---|---|
| type-I (mean = 0.7538) | z=11.1 → ~4·10⁻²⁹ | z=7.01 → **1.2·10⁻¹²** |
| power при mean = 0.8681 | z=9.71 → ~1·10⁻²² | z=5.59 → ~1·10⁻⁸ |

Ни одна клетка с меткой «эффект масштаба e_spec» + pooled не даёт 10⁻¹². Это ровно ваше же правило m4/G14 («координаты на каждое число»), применённое к числу из моего ревью — я его дал без явной метки, вы перенесли с другой меткой.

**Фикс:** либо `type-I ≈ 10⁻¹² (per-dose δ) / ≪10⁻²⁰ (pooled)`, либо `power(e_spec-масштаб) ≈ 10⁻⁸ (per-dose)`. **И честно про хвост:** при z ≈ 7–11 и n=14 доков с bootstrap-перцентильным CI нормальное приближение в таком хвосте не идентифицируемо. Правильная формулировка: «рабочий уровень type-I **много ниже** 0.025; точное значение по 14-доковому бутстрапу не оценивается». Заявленный α — верхняя граница (это уже написано ✓).

### F6. Правило пересмотра маржи — решение по 2 докам о медиане 14; остаточный риск не задекларирован

`median(min(m₁,m₂))` на 2 доках = среднее двух значений. Это очень шумная оценка 14-доковой медианы. Два исхода:
- смок <0.3, main ≥0.3 → гейт снят зря (потеряли контроль);
- **смок ≥0.3, main <0.3 → `GATE_N2` срабатывает → E_phr нерешён → при нулевом REP `NOT_RESOLVED`.**

Второй — ровно риск, который правило вводилось снимать, и оно снимает его лишь частично. **Фикс:** (а) задекларировать этот исход как пре-рег-исход, не пост-хок пересмотр; (б) обязать манифест писать **и смок-значение, и реализованную 14-доковую медиану**, чтобы читатель видел, какая ветка была взята и была ли она права.
