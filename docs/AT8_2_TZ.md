окно W=64, один замер. Здесь: доза n∈{2,4,8,16}, окна W∈{8,16,32,64}, 8 доков, + новая

что в E-71B (FIX audit2 B3: окно ПОСЛЕ вставки vs то же окно контроля).

## 0. Вердикт-вопрос

Вставляется луп-блок (доза n). Восстанавливается ли поле (dip) в окне после вставки
до уровня контроля (упруго), и как длина восстановления ℓ_rec масштабируется с дозой?
- `ℓ_rec` конечна и **слабо** зависит от n + окно возвращается к **контролю** ⇒ **упругость (ELASTIC)**.
- dip возвращается **только за счёт разбавления** (окно ≈ глобальная медиана, а не контроль) ⇒ **нет упругости (DILUTION)**.
- `ℓ_rec` **растёт линейно** с n ⇒ **диффузия (DIFFUSION)**, не упругое столкновение.

## 3. Фраза, доза, вставка, окна (определения)

- **Фраза** (как E-71B): `PHRASE = " The class will be held at the park."`
  → **9 токенов** `[561,523,668,381,5467,506,279,5926,13]` (add_special_tokens=False).
  `L_n = 9·n`.
- **Доза:** `n ∈ {2,4,8,16}` → `L_n ∈ {18,36,72,144}`.
- **Вставленный документ:** `inj = ids[:cut] + phrase·n + ids[cut:]`, длина `T + L_n`
  (T = len(ids), до 400 ток. при n=16).
- **Контроль:** оригинальный документ `ids` (без вставки), h23 считается **один раз** на
  документ (не зависит от дозы — одна статистика на обеих сторонах).
- **h23:** `caps[23][0,:len]` (forward hook на слой 23, fp32, numpy) — на весь документ
  (и вставленный, и контроль).
- **Окно** длины `W ∈ {8,16,32,64}`:
  - вставленный, смещение `d`: `h1[cut + L_n + d : cut + L_n + d + W]`;
  - контроль, смещение `d`: `h0[cut + d : cut + d + W]`.
  - (E-71B: d=0, W=64 — частный случай.)
- **Окноное dip:** `curves_series(окно)["dip"]` (lag-1 ACF, функция **пин**
  `experiments/kaggle_e64gpu/e64_gpu.py` sha256
  `8c517e18f801fa877dfde9265ed5ce18df1e7d3af705194fc01ff6b150cf7633`, вычитается из
  исходника, exec; гейт S7). Dip определён для W≥3; все W∈{8,16,32,64} — OK.
- **Доступность смещения:** оба окна (вставленный и контроль) влезают при
  `d ≤ D_max = T − cut − W = (T − T//2) − W` (второй минус окна). При `D_max < 0` окно
  не влезает даже при d=0 ⇒ пара (doc, W) — `not_measurable` (не считается, в отчёте).

## 4. Наблюдаемые и ℓ_rec (определения, фиксированы)

Для каждой измеримой пары (doc, n, W) (D_max ≥ 0):
- `dip_inj(n,W,d) = curves_series(h1[cut+L_n+d : cut+L_n+d+W])["dip"]`
- `dip_ctrl(W,d)  = curves_series(h0[cut+d : cut+d+W])["dip"]`
- **Возмущение:** `pert(n,W,d) = |dip_inj(n,W,d) − dip_ctrl(W,d)|`; `pert0 = pert(n,W,0)`.
- **Длина восстановления ℓ_rec(n,W):**
  - если `pert0 < ε_min` (ε_min = 0.01) ⇒ `ℓ_rec = 0` (возмущение пренебрежимо — нет эффекта);
  - иначе `ℓ_rec = min{ d ≥ 0 : max_{d'∈[d, D_max]} pert(n,W,d') ≤ 0.25·pert0 }`
    (возмущение падает **и остаётся** ≤ 25% начального до конца горизонта);
  - если такого d нет (возмущение > 25% до D_max) ⇒ `ℓ_rec = D_max`, флаг `not_recovered`.
  - при `0 ≤ D_max < 8` — восстановление `not_measurable` (мало места), отчитывается только pert0.
  - **r1 (MINOR-2, ограничение мощности, зафиксировано):** при малом возмущении
    (0.01 ≤ pert0 ≲ 0.04) порог 0.25·pert0 (≈0.0025–0.01) может оказаться ниже шумового пола
    dip ⇒ ℓ_rec вырождается в D_max (not_recovered) даже при реальном восстановлении; ось A
    неинформативна в маловозмущённом (ожидаемом ELASTIC) режиме — вердикт сходится через ось B.
- **Глобальный dip вставленного:** `dip_global(n) = curves_series(h1)["dip"]` (целый inj-документ).
- **r1 (MAJOR-1): dip целого контроля:** `dip_control_whole = curves_series(h0)["dip"]`
  (один раз на док, вместе с контролем) — та же шкала, что у `dip_global` (документ, не окно).
- **Разбавление (dilution) — проверка цели восстановления** (при D_max ≥ 8):
  - `residual_ctrl   = |dip_inj(n,W,D_max) − dip_ctrl(W,D_max)|` (дистанция до **контроля** на дальнем крае);
  - `residual_global = |dip_inj(n,W,D_max) − dip_global(n)|` (дистанция до **глобального** вставленного);
  - **r1 (MAJOR-1): то_global-гейт на одной шкале:** `to_global = 1` если `residual_global <
    residual_ctrl` И `|dip_global(n) − dip_control_whole| > 0.25·pert0` (глобальное вставленного
    существенно отличается от глобального **контроля** — одна документная шкала; v1.0 сравнивал
    `dip_global` с dip **окна** контроля — смешение шкал, отклонено ревьюем).

## 5. Агрегация и вердикты (пре-рег, фиксированы ДО прогона)

По докам — **медиана** (дип-конвенция E-71/AT8_1). Ключевая таблица: `ℓ_rec(n)` по
медиане доков (**по измеримым (doc,W)** — v1.2 уточнение, MAJOR-1: ВСЕ измеримые (doc,W)
с ℓ_rec; not_recovered имеют ℓ_rec=D_max — цензурированное значение, **входит** в медиану;
вариант с исключением цензурированных (только recovered/no_effect) — вторичный, в артефакте
с явной меткой `censored_excluded`), для n∈{2,4,8,16}, по каждому W (основное — W=64)
i по объединённо (справочно).

**Ось A — масштабирование ℓ_rec по дозе** (r1, MINOR-1: **основная — по W=64** (референс
E-71B), по медиане доков измеримых; объединённый по W — вторичный, в артефакте для справки:
W=8 (D_max до ~120) и W=64 (D_max от ~18) — разные горизонты/капы, смешение искажает
ratio/регрессию). **v1.2 (MAJOR-1): популяция медиан — полная:** все измеримые (doc,W)
с ℓ_rec (not_recovered — ℓ_rec=D_max, цензурированное значение, входит); вариант с
исключением цензурированных (recovered/no_effect) — вторичный, с явной меткой
`censored_excluded`. **v1.2: конвенция «медиана доков» для объединённого:** сначала
медиана по W внутри дока, потом медиана по докам (та же редукция к уровню дока, что
и у оси W=64; прямой median по всем (doc,W) — не конвенция). `ratio` и линейная регрессия
— **по W=64-медианам** (если для дозы нет ни одного измеримого ℓ_rec при W=64 ⇒ ось A
`not_resolved`):
- `ratio = ℓ_rec(16) / ℓ_rec(2)` (если ℓ_rec(2)=0 ⇒ ratio=∞ при ℓ_rec(16)>0, else 0).
- линейная регрессия `ℓ_rec = a + b·n` по 4 дозам (R², b). (r1, MINOR: R² по 4 точкам (3 ст.
  св.) — хрупкий гейт, одна выброс-точка рушит; порог 0.6 — консервативный, оставлен.)

**Ось B — цель восстановления** (доля пар (doc,n,W) с `to_global=1` среди измеримых
с D_max≥8).

**Вердикт (приоритет DIFFUSION > ELASTIC > DILUTION > NOT_RESOLVED):**
- **DIFFUSION:** `ratio ≥ 4` И b>0 И R²(linear) ≥ 0.6 ⇒ «ℓ_rec растёт с дозой — диффузия,
  не упругое столкновение».
- **ELASTIC:** `ratio ≤ 2` (ℓ_rec слабо зависит от n) И доля `to_global` ≤ 0.4
  (окно в целом к контролю, не к глобальному) ⇒ **упругость подтверждена**.
- **DILUTION:** доля `to_global` > 0.6 (окно ≈ глобальное разбавленное, не к контролю)
  ⇒ «нет упругости: dip возвращается только за счёт разбавления».
- **NOT_RESOLVED:** иначе / мало измеримых пар (меньше 6 пар (doc,n) с ℓ_rec>0 —
  v1.2 уточнение: счёт по **основной оси (W=64)**) / большинство `not_recovered`
  (v1.2 уточнение, MINOR-1: по **полной измеримой популяции** — все W, D_max≥8, та же
  популяция, что у оси B; чтение по W64-оси — diagnostic `axis_W64_notrecovered_share`
  в артефакте, не гейт: в маловозмущённом режиме (р1 MINOR-2) not_recovered — вырождение
  ℓ_rec в D_max под шумовым полом, не свидетельство «нет восстановления», и пре-рег
  (§4-ноут) фиксирует сходимость вердикта через ось B). Доп. консервативный гейт
  ELASTIC: `n_pos≥2` (число доз с медианой ℓ_rec>0 на W=64) — зафиксирован в r1-прогоне,
  сохранён (косметика: не меняет вердикт на этом пуле, n_pos=4).

**Ожидаемый исход (pre-reg):** по E-71B (упругое столкновение, луп поглощается фоном,
сдвиг ≤0.03–0.07) — **ELASTIC** (ℓ_rec конечна, слабо зависит от n; окно к контролю).
¬ожидание (DIFFUSION или DILUTION) — содержательный результат (солитон не подтверждён
по критерию упругости), разбор, не «исправление».

## 7. Цена (измерено 16.11, torch-fallback, OMP=6)

- 8 docs × [1 контроль (T≤256) + 4 дозы (T+L_n ≤ 400)] = **40 форвардов**.
- **fwd256 ≈ 3.9 с, fwd400 ≈ 5.7 с** (замер 16.11, 0.8B fp32 CPU, 6 нитей) ⇒
  40 форвардов ≈ **3.6 мин** + загрузка модели ~1 с + dip-окна (O(W·H·k), мс).
  **Итого ~5–8 мин** (v1.0-оценка «65–80 мин» — неверная, ~87 с/fwd256 не подтверждена замером).
- **Двухпроходная запись (r1, self-audit):** forward → в том же процессе считать dip-кривые
  по смещениям d (скаляры) → анализ. Store хранит **скалярные dip-кривые + nll**,
  не полные h23-векторы (v1.0-дизайн хранил 40×(T+L_n)×1024 float — ~160–300 МБ в JSON;
  нарушало бы git-гигиену «артефакты >10MB не класть»). Resume — по ключам (doc, n).
- Запись: `results/AT8/AT8_2_RECOVERY.json` (claim) + `results/AT8/AT8_2_RECOVERY_store.json`
  (dip-кривые/nll, компактный) + manifest + `logs/AT8/AT8_2_run.log`. **Store не трогается**
  (read-only входы).
