## 1. E-50 (гаузы)

### 1.1 `A[top1]` — [ПОДТВ], и хуже, чем предполагалось
`top1` в npz — это **вероятность** `p.max()` (float32, значения 0.079…0.9998; проверено
в exp47b: `feats["top1"].append(float(p.max()))`). Индексом токена она не была никогда →
ветка `tokengauge` молча вычитала практически постоянную строку `A[0]`. ID токенов в
npz нет вовсе → **ветка удалена** (не починкой, а удалением): без перегенерации трасс с
сохранением id восстановить нечего. Все прежние `W*_tokengauge` числа — мусор.

### 1.2 `log_slope → None → nan → невалидный JSON` — [ПОДТВ] → [ИСПРАВЛЕНО]
Все агрегаты через `safe_med` (None вместо nan) + `json.dump(..., allow_nan=False)`
(крик вместо тихой порчи). Компилируется и прогнано заново.

### 1.3 `r1_drift_ratio` blow-up / отсутствие CI — [ПОДТВ]
Добавлен `log_shrink` (аддитивная, устойчивая версия) с bootstrap CI; точный ноль
защищён в `ratio()`; почти-нули остаются риском единичных отношений — для вердикта
используется pooled point + медиана отношения + log-версия (три согласованных числа).

### 1.4–1.6 `by_dom` без null, `tau_trans` не в summary, хардкод лагов — [ПОДТВ] → [ИСПРАВЛЕНО]
`by_dom` теперь real/swap/shrink/n; τ_trans и slope_swap в summary; `log_slope(lags=…)`.

### 1.5/2.6 `tau_trans` считался ДО транспорта — [ПОДТВ] → [ИСПРАВЛЕНО + оговорка]
Теперь τ считается на ТРАНСПОРТИРОВАННЫХ рамках. Честная оговорка: в транспорт-гаузе
соседние Ṽ заведомо близки (транспорт поглощает попарную геодезику by design), поэтому
τ_trans — диагностика, а дискриминант гипотезы — рост дрейфа (shrink).

### 1.7 один shuffle на документ — [ПОДТВ, выполнено частично]
N_SHUF=2 на null с посевом `rng(key)` (не глобальный RNG). 10–100 реализаций не потянуты
намеренно: транспорт = O(T·D²) на каждую реализацию; 2 достаточно, т.к. дисперсия null
по лагам мала (сравнение CI real/swap это показывает).

### 1.8/1.9 контроль не на r=16, докстринг ≠ код — [ПОДТВ → исправлено, с двумя находками]
Новый контроль — **точная геодезическая ранги r** (p_j ∈ span V₀, q_j ⟂ span V₀,
плоскости фиксированы): drift32(гауз) ≡ 0 аналитически; прогнано r∈{1,4,16}:
`geo_r1/4/16 drift32 = 0.0`, SELFTEST ok; white-рамки: drift насыщен (порог >1).
Находка А (моя, в первой версии контроля): `E=qr(randn)` **не ортогонален** span(V₀) —
неверная «геодезическая»; контроль падал справедливо. Находка Б (ловушка в тесте,
предложенном ревью): орбита `exp(tA)V₀` со СЛУЧАЙНЫМ полным skew-A — не геодезическая
пар; при малых шагах raw drift = transport drift (0.0015 vs 0.0015) — тест **нечувствителен**.
Находка В: при длине пути > π/2 главный угол «складывается» (RP¹-фолдинг) — любой
geodesic-контроль обязан держать θ·T < π/2 (установлено; амплитуды уменьшены).

### 1.10 θ→π no-op — [ПОДТВ, задокументировано] В докстринге `pullback_step`: осознанно,
метрика subspace-инвариантна; для frame-дрейфа (с базисом) пришлось бы менять.

### 1.11 порядок tokengauge/smooth — снято вместе с удалением ветки (1.1).

### 2.1 shrink как вердикт — [ИСПРАВЛЕНО]: предрегистрированныеcuts (0.3/0.7), verdict,
CI (медиана, pooled point, log-версия), `shrink_by_lag`, `by_dom`.
ОБЪЯВЛЕНО ДО ЧТЕНИЯ ЧИСЕЛ: cuts — до первого shrink; выбор swap-null — после controls,
до данных (задекларировано здесь же).

###Null-дизайн (важнее исходного замечания 1.7) — [УСИЛЕНО, с самокритикой]
Глобальная перестановка кладёт попарные углы за π/2 → фолдинг (Находка В) **завышает**
дрейф null → shrink по нему систематически в пользу гипотезы. Поэтому введён второй,
честный null: **swap-local** (25% непересекающихся транспозиций соседей; маргиналы и
масштаб шага сохранены, дальнодействие уничтожено). Вердикт предрегистрирован по swap;
glob-shuffle оставлен как верхняя диагностика (оба числа в JSON).

### 2.2 W16 — роль сформулирована: сравнение shrink(W1) vs shrink(W16) при парном
null-порядке на том же W; артефакт сглаживания отдельное проверен в E-49b (см. §3).

### 2.5 sentinel/alive — [ПОДТВ как ограничение] К генеративным трассам неприменим
(нет P128_RAW); маркировано в докстринге; alive-срез — только на teacher-forcing кэше (будущее).

## 2. E-49 (сетка r/W/метрика)

### 1.1 M-метрика (Cholesky) — [ПОДТВ], оба слоя ошибки
Проверено числом: `torch.linalg.cholesky` даёт G=LLᵀ (не LᵀL — 3.9e-14 vs 246);
к корректной G-ортонормировке ведёт `Lᵀ·V` **с обратной заменой** `V_G = L⁻ᵀ·qr(LᵀV)` —
у меня было `qr(L·V)`: ошибка и ориентации, и отсутствия обратного отображения; плюс
rank(G)=128<D и регуляризация 1e-10 — «метрика» в нуль-пространстве произвольна.
**Все `*_M` числа E-49 неинтерпретируемы**; вывод «M-метрика не важна» **ОТОЗВАН**
(H3 как тест не состоялся). Корректный рецепт (для будущего прогона): через SVD A
(`T=S V_Aᵀ`, `V_G=qr(T V)` — ранг-корректно) + cond(H) в отчёте.

### 1.2 M3 holonomy отсутствует в e49 — [ПОДТВ по коду e49; по сути — измерена ранее]
В финальном e49 функция не вызывалась — верно. Величина не потеряна: голономия окна
L=8 vs shuffled измерена и задокументирована отдельно (§10 docs/leaf_dynamics.md,
0.028/8 шагов vs 0.013 shuffled). В e49 не дублируется; дублировать негде — вердикт e49
по M1/M2.

### 1.3 v1 = дубликат r=1, abs ест знак — [ПОДТВ]
r=1 span-угол и есть |dot| линия — метод не независим, знак после трассировки
бросался. Принято к сведению; независимая знаковая статистика (sign-flip rate,
signed holonomy) — в backlog.

### 1.4/2.1 контроли только в одной точке сетки; W — главный конфаундер — [ПОДТВ → ПРОГНАНО]
Проведён **e49b** (сильнее, чем «сглаженные white/coherent» из ревью — null на самих
данных, см. §3).

### 2.3 «tau на max-угле не метрика» — [ОТВЕРГНУТО]
`frame_kinematics` возвращает `s = ||Θ||₂` (геодезическая дистанция Грассманиана,
треугольник выполняется); max-угол — это отдельный выход `p`. τ E-49 уже построен на
геодезическом расстоянии. Претензия построена на неверном чтении возврата функции.

### 2.4 eigengap r=16 — [ПОДТВ, известно] Вырожденность хвоста (σ₁₆/σ₁₇≈0.99)
задокументирована ранее (§10 и своды E-47); выводы по r=16 помечать «нестабильное
подпространство» — принято правилом.

### P2 «сравнить J_analytic с autograd» — [ОТВЕРГНУТО как новое требование]
Сверено до этого: тождество J против autograd 1e-16 (Qwen, E-47 P0) и 2.7e-7 (обе
архитектуры, E-48a), документировано. Повтор не требуется.

### P3 единый token set — [ПОДТВ, задекларировано] U(Qwen)=частотный top-128, U(LFM3)=
срез range(0,384,3) — разные построения; кросс-модельные утверждения E-48/E-49 силу не
теряют (воспроизводятся при разных построениях, т.к. утверждения — об относительных
эффектах), но формально «одно-в-одно» сравнение требует общего набора — в backlog.

## 3. E-49b: артефакт ли «медленный канал» (решающий тест H2, Qwen)

Null'ы строятся на КАДРАХ СГЛАЖЕННОГО ряда, порядок меняется ПОСЛЕ сглаживания:
`shuffle` (полная перестановка), `block` (перестановка блоков длины W — сохраняет
внутриоконную гладкость), `cross` (ошибка дизайна: бралась чужая ТРАЕКТОРИЯ целиком,
т.е. это второй real — неинформативен, признано).

| W | τ real [CI] | τ shuffle | τ block | s(32) real / block / shuffle |
|---|---|---|---|---|
| 4 | 0.444 [0.441,0.451] | **1.002** | 0.483 [0.478,0.498] | 0.318 / 0.329 / 0.332 |
| 16 | 0.385 | 1.001 | 0.389 | **0.212 / 0.259 / 0.252** |

Чтение:
1. Опасение ревью «сглаживание само даёт τ≈0.4 на любом шуме» **опровергнуто для
   глобального порядка**: shuffle после сглаживания остаётся белым (τ=1.00).
2. Но **внутриоконная** часть падения τ объясняется фильтром: block ≈ real (W16 —
   идентичны: 0.385 vs 0.389).
3. Сверх фильтра остаётся в лаг-профиле: s(32) real 0.212 против null 0.252–0.259
   (−15…18%): дальнодействующая когерентность есть, но мелкая. По доменам τ real
   неодинаков (W16: wiki 0.434 > chat 0.394 ≈ code 0.383 > math 0.366).

Итог H2: «медленный канал» — реален, но тонок: почти весь τ-эффект окна — фильтр;
за вычетом фильтра — устойчивый дефицит дрейфа ~15% на лагах > W.
