## 1. E6 — отвергнут статус `blocked`, закрыт в этом же раунде (с числами)

Тезис ТЗ: «в опубликованной таблице `(c, cos, frac_K)` не удовлетворяют тождеству,
s² < 0 на всех слоях (−0.0007…−0.0015) ⇒ как минимум одно число — не агрегат того
объекта, которым названо». **Вывод верен, диагноз неполон: носитель ошибки — сама
публикация, а не данные.** Таблица `E39_supplement` §2.2.1 смешивала срезы в одной
строке: `c` и `cos` — aggregates alive-среза (1.215e-3 / 0.088 на L6), `frac` —
**медиана** по всем позициям (0.996576). Подстановка даёт `s² = 0.996576 − 1 +
2·1.22e-3 = −9.8e-4` — ровно диапазон ТЗ. На одном срезе и одной агрегации тройка
самосогласована до 5 знаков: L6 all `c = 2.4418e-3`, `s = √O1_corpus = 0.018772`,
`c/s = 0.13008` = хранимый `cos_J_PJ`; тождество `‖K‖² = ‖J‖² − 2⟨J,PJ⟩ + ‖PJ‖²`
ассертится в скрипте попозиционно (невязка < 1e-12). Медиана отношения и отношение
сумм — разные объекты, тождество их не связывает (правило 7 supplement, paper §6
item 23). Сделано: поля `s_agg`/`frac_K_energy_agg` в скрипте и JSON (перепрогон
356.6 с, все прежние якоря побитово), таблица перемаркирована по срезам, полная
тройка по 10 строкам (all/alive × 5 слоёв) в §2.2.1, D14. `frac_K` разстейдживается
(решение пользователя); инвариант `triple_identity` — `passing`, тест
`test_triple_identity_one_aggregation` закрепляет семантику «одна агрегация».

## 2. Граница `λ_max` — утверждение ТЗ неверно, исправлено

§I.1: «`λ_max ≤ p_max(1 − p_max)`» противоречит собственному двухточечному пределу
ТЗ же (`λ_max = 2 p_max(1−p_max)` ровно в 2× больше) и числам: K=2, q=0.9 →
λmax = 0.18 > 0.09; K=128 sharp p (softmax randn·3) → λmax = 0.1366 >
p_max(1−p_max) = 0.1229. Корректная граница: **`λ_max ≤ p_max`** (из `P ⪯ diag p`).
Зафиксирована тестом `test_lambda_max_bound_corrected` (включая точный двухточечный
предел). Формулировка для §2.5.1 статьи — исправленная.

## 3. `P² ≠ P` «ни при каком p» — неверно на границе

При `p = e_i` (делегат) `P = 0` идемпотентен. Инвариант `P_properties` формулируется
для interior p (нарушение проверяется на uniform: `P² = (1/K)P ≠ P`), вершина
проходит отдельным тестом `test_not_projector_interior_and_vertex`. Мелочь, но
ассерт без неё падал бы ложно.

## 4. «MP-скобки» — Монте-Карло истец (решение пользователя), λ+ опознан

`(1+√(p/n))²` при **n = 32** даёт 2.0535 (p=6) и 2.2500 (p=8) — то есть первое число
каждой пары ТЗ = MP верхняя граница дискретизации на 32 документах (воспроизведено с
точностью 0.004). Вторые числа (1.38/1.45) не воспроизводятся ни при одной стандартной
нормировке Wishart (MC: mean λmax(6,32) = 1.736, median 1.726 — между ними, но не они);
записаны как расхождение. `nulls_and_stats.mp_lambda_max_mc` — calibration-тест §IV.6,
значения ТЗ в тесте — ориентиры, не истина.

## 5. Кинетика — ТЗ неполон, принята рецептура `E40_ans.md`

Пять каналов покрывают `‖ΔJ_proj‖²`, не `‖ΔJ‖²`; при r = 16 ≪ D = 1024 доля
`E_off_manifold` велика (на L6–L22 ≈ ‖ΔJ‖²/2, Δ_SVD ≈ π/2 — ожидаемо, не провал).
Ядро реализует **шесть** каналов + `eps3_correction` как диагностику (не седьмой
канал, иначе тавтология), флаги `linearization_valid` (Δ_SVD < π/2 − 0.3) и
`rotation_unique` (min σ-gap > 1e-2·σ₁²). Тесты: замыкание Σ6 < 1e-2 на синтетике,
`channel_energy_matrix` (5×5 Gram) замыкает `‖ΔJ‖²` **точно** (1.9e-16) — это учёт
всех cross-членов, а не проверка линеаризации; r=1 → `E_cross ≡ 0`. Пререгистрация
перенесена из `E40_ans` §9.6: на L6–L22 `linearization_valid=false` — ожидаемый
результат.

## 6. Что принято без спора

Три роли `P(p)` и замкнутые формы (проверены: tr, tr P², seкулярное уравнение против
eigvalsh < 1e-8); правило срез-локальности; тождества O2≡O3 (тест против torch-маршрута
`spectral.gauge_share`, ≤ 1e-10) и `g_uni(J^gf) ≡ 0`; разложение `O1/iso = conc×V×sharpness`
(уже измерялось, здесь — как инвариант реестра); правило двух null'ов (оба null'а в
`operator_null`); sentinel как разрез (бинарной маски в ядре нет); `align_signs_and_columns`
как предусловие (венгерский алгоритм на `|U₀ᵀU₁|`, не по σ; отказ при ~нулевом overlap);
ChannelTag с identity-relevant полями (отсутствие любого из трёх — ValueError);
gate `behavior.py` (pytest-скан источников, CI у нас только pytest); `profiles.py` —
recipes вне ядра.

## 7. Отклонения реализации (не содержание, а имена/механика)

- `softmax_jacobian(p) → P` живёт как `p_algebra.P_matrix`: в пакете уже есть
  `prism.jacobian.softmax_jacobian(J, p)` с ДРУГИМ смыслом (применяет P к J); два
  имени на один пакет — ночная ловушка.
- `svd_bundle(..., slice=...)` → `slice_name` (builtin).
- `p_algebra.gauge_share(G)` принимает **грамиан** (numpy, `1ᵀG1/(K tr G)`), не
  spectrum+vectors (`spectral.gauge_share` не дублируется, маршрут перекрёстно
  сверен тестом).
- `invariants.py` — dataclass-реестр с вызываемыми check'ами вместо dict с лямбдами:
  лямбды ТЗ не сходились сигнатурами; статус по-прежнему объявлен в записи,
  driver-тест требует прохождения всех.
- `principal_angles` из `svd_bundle` поглощает три копии (`exp28`, `exp31`, `exp39a`);
  миграцию экспериментальных скриптов не делал — они закоммиченные артефакты прогонов.
- `secular_roots` требует различных `p_i` (при совпадений — явный raise к `eigvalsh`).
- Правки статьи (§2.5.1–2.5.6, §2.7, §2.9, §2.11, §3.2, §4.5, §5, §6) — **не сделаны
  по решению пользователя** («код+тесты, потом статья»); список готовности — разделы I
  ТЗ с пометками этого файла (E6 закрыт, λ_max исправлен, кинетика 6-канальная).
