# План экспериментов: что действительно стоит вынести в ядро как переиспользуемую математику

Я бы сейчас сделал шаг назад от очередного спора о моделях и сформулировал **ядро проекта** не как набор гипотез H1–H5, а как маленькую библиотеку математических операций над полем \(J\), которая будет использоваться во всех E-40/E-41/E-42.

Главный принцип:

> В ядро выносим не «полимер», не «мобильный край», не «L22-фазу», а только те операции, которые переиспользуются разными тестами и имеют ясный математический контракт.

То есть ядро должно быть **модельно-лёгким**, а гипотезы — поверх него.

---

# 1. Что должно быть в ядре

Я бы выделил 8 переиспользуемых блоков.

---

## 1.1. Канальный паспорт результата

Это не совсем математика, но без этого математика постоянно ломается из-за смешения объектов.

Каждый результат должен иметь обязательную метку:

\[
[\text{natural}/\Delta W]
\times
[\text{raw}/\text{gf}/\text{fixP}]
\times
[\text{top}/\text{tail}/\text{full}]
\times
[\text{left}/\text{right}/\text{mixed}]
\]

Плюс:

- слой \(l\);
- ранг \(r\);
- тип нормы: norm / energy / angle;
- источник: cache / recomputed / audit-only;
- статус: measured / inferred / not-testable.

**Почему в ядро:** мы уже несколько раз ловили ошибки именно из-за отсутствия такой метки: left IPR, \(T_{ij}\), E-39 \(corr_f\), \(\Delta_{gf}\), «98–99% нормы».

**Переиспользование:** все E-40, E-41, E-42, E-43.

**Минимальный API:**

```python
ChannelTag(
    protocol="natural" | "deltaW",
    slice="raw" | "gf" | "fixP",
    window="top" | "tail" | "full",
    side="left" | "right" | "mixed",
    layer=int,
    rank=int | None,
    norm_type="norm" | "energy" | "angle",
)
```

## 1.2. SVD-связка поля

Базовый объект:

\[
J = U\Sigma V^\top.
\]

Но в ядро надо вынести не просто SVD, а **три проекции**:

1. радиальная:
   \[
   \Sigma,\quad \lambda_k=\sigma_k^2;
   \]

2. правая угловая:
   \[
   V\in \mathrm{Gr}(r,D);
   \]

3. левая угловая:
   \[
   U\in \mathrm{Gr}(r,K).
   \]

**Важно:** SVD имеет знаковую и внутриблочную gauge-свободу. Поэтому ядро должно возвращать не «векторы как абсолютные сущности», а:

- подпространства;
- проекторы;
- главные углы;
- полярные транспорты;
- инварианты.

**Переиспользование:**

- E-40.5 — кинетическая декомпозиция;
- E-41.1/1.2 — token/neuron IPR;
- E-41.3 — \(\kappa_{raw/gf/fixP}\);
- E-41.4 — locking;
- E-42.2 — \(F_{lt}\);
- E-43 — защита хвоста / balanced coordinates.

**Минимальный API:**

```python
svd_bundle(J, rank, side, slice, energy_threshold)
```

Возвращает:

```python
{
  "U": ...,
  "Sigma": ...,
  "V": ...,
  "energy": ...,
  "rank_effective": ...,
  "stable": bool,
  "tag": ChannelTag
}
```

## 1.3. Procrustes-транспорт и голономия

Это уже почти готовое ядро.

Для двух подпространств \(V_i,V_j\):

\[
V_i^\top V_j = W\Sigma Z^\top,
\]

\[
R_{ij}=WZ^\top.
\]

Голономия тройки:

\[
H_{012}=R_{01}R_{12}R_{02}^{-1}.
\]

Инварианты:

\[
\kappa=\|H-I\|_F,
\]

\[
\theta_j=\arg\lambda_j(H).
\]

**Почему в ядро:** это самый устойчивый математический объект всей программы. Он не зависит спора о полимере, mobility edge, H5 или L22.

**Переиспользование:**

- E-40.5 — транспортный фрейм;
- E-41.3 — \(\kappa\)-срезы;
- E-41.4 — left/right locking;
- E-41.5 — \(\log\kappa\) vs \(\log\Delta\);
- E-42.2 — mixed plaquette;
- E-43.3 — голономический лосс.

**Минимальный API:**

```python
procrustes_transport(V0, V1)
holonomy(V0, V1, V2)
holonomy_spectrum(H)
```

**Обязательные проверки:**

- gauge covariance;
- \(H\mapsto O^\top H O\) при смене базиса;
- \(\kappa\) и \(\theta_j\) invariant;
- \(r=1\) limits;
- random Haar null.

## 1.4. Кинетическая SVD-декомпозиция

Это один из лучших кандидатов в reusable core, потому что объединяет радиальное, правое, левое и лево-правое взаимодействие.

Для соседних \(J_t,J_{t+1}\) в транспортном фрейме:

\[
dJ \approx dU\,\Sigma + U\,d\Sigma + U\Sigma\,dV^\top.
\]

В согласованной конвенции:

\[
M=\log Q_U,\quad N=\log Q_V,
\]

\[
\bar\Sigma=\frac{\Sigma_t+\Sigma_{t+1}}2.
\]

Разложение энергии:

\[
\|\Delta J\|_F^2
=
E_{\text{radial}}
+
E_{\text{right}}
+
E_{\text{left}}
+
E_{\text{cross}}
+
E_{\text{residual}}.
\]

Где:

\[
E_{\text{cross}}
=
2\operatorname{tr}(\bar\Sigma M\bar\Sigma N)
\]

с точностью до выбранной знаковой конвенции.

**Важно:** в ядре хранить **энергии каналов**, а не только доли. Доли композиционны:

\[
\sum_i s_i=1,
\]

и могут искусственно создавать отрицательные корреляции.

**Переиспользование:**

- E-40.5;
- E-41.4 locking;
- E-42.2 \(F_{lt}\);
- E-42.5 metric-connection compatibility;
- E-43 диагностика редактирования.

**Минимальный API:**

```python
kinetic_svd_decomposition(J0, J1, rank, frame="transport")
```

Возвращает:

```python
{
  "E_right": ...,
  "E_radial": ...,
  "E_left": ...,
  "E_cross": ...,
  "E_residual": ...,
  "shares": ...,
  "rank_channel_matrix": ...,
  "selfcheck_sum": ...
}
```

**Обязательные selfchecks:**

- сумма пяти каналов близка к \(\|\Delta J\|_F^2\);
- при \(r=1\) cross-term = 0;
- при искусственном чисто радиальном изменении угловые каналы = 0;
- при искусственном чисто правом повороте radial = 0.

## 1.5. Редукционный контроль

Это, на мой взгляд, главный методологический результат последних раундов. Его точно надо вынести в ядро.

Формулировка:

> Любая производная метрика должна иметь тривиальный прототип-кандидат и контроль, который отделяет новый сигнал от тривиального.

Примеры:

| Метрика | Тривиальный прототип | Контроль |
|---|---|---|
| \(R_{raw}-R_{can}\) | частота / масса токена | rank-partial / matched-null |
| \(G(l)\) | изменение \(p_t\), энтропия | permutation \(p_t\), partial |
| \(\rho_{LR}\) | монотонность спектров углов | permutation of mode pairs |
| \(r_{cross}\) | форма двух cumulative curves | permutation within curves |
| operator-kill | норма оператора | isotropic reference |
| \(b_{mag}\) в E-44 | первый порядок \(\epsilon^2\sigma_1^2\) | subtract \(b_{lin}\) |

**Почему в ядро:** это предотвращает повторение ошибок E-39k / E-39d / E39_supplement.

**Минимальный API:**

```python
reduction_control(
    statistic,
    trivial_predictor,
    null_model,
    partial_vars=None
)
```

Возвращает:

```python
{
  "raw_effect": ...,
  "residual_effect": ...,
  "trivial_explained_fraction": ...,
  "passes_control": bool
}
```

Это не новая модель. Это стандартный способ не обмануться.

## 1.6. Операторные нормы, изотропный референс и калибровочные дроби

После `E39_supplement` это обязательно должно быть в ядре.

Для оператора \(O\) и поля \(X\):

\[
\mathrm{kill}_{energy}
=
1-\frac{\|OX\|_F^2}{\|X\|_F^2}.
\]

Но этого недостаточно. Надо всегда считать:

\[
\mathrm{iso}(O)=\frac{\|O\|_F^2}{K},
\]

и отношение:

\[
\frac{\|OX\|_F^2/\|X\|_F^2}{\mathrm{iso}(O)}.
\]

Для \(P(p)\):

\[
P=\operatorname{diag}(p)-pp^\top.
\]

Uniform-направление:

\[
Q=\frac{1}{K}\mathbf1\mathbf1^\top.
\]

Настоящая uniform-доля:

\[
g_{uni}(J)=\frac{\|QJ\|_F^2}{\|J\|_F^2}.
\]

**Важно:**

\[
g_{uni}(P J)\equiv0
\]

по построению, потому что \(P\mathbf1=0\). Это не эмпирический результат.

**Переиспользование:**

- E-40.1 audit;
- E-40.6 \(R_{raw}/R_{can}\);
- E-40.7 \(G(l)\);
- E-41 gauge diagnostics;
- E-42/E-43 любые gauge-aware потери.

**Минимальный API:**

```python
operator_fraction(O, X, norm_type="energy")
isotropic_reference(O)
uniform_gauge_fraction(J)
softmax_jacobian(p)
```

**Selfchecks:**

- \(P\mathbf1=0\);
- \(P^2\neq P\);
- \(g_{uni}(PJ)\approx0\);
- `norm` и `energy` не путаются;
- `cos(J,PJ)` считается отдельно.

## 1.7. Статистическое ядро: floors, paired bootstrap, permutations

Этот блок нужен всем.

Обязательные элементы:

1. percentile bootstrap по документам, \(B=1000\);
2. paired bootstrap для разностей;
3. permutation tests, \(B=1000\);
4. resolution floor для каждой метрики;
5. флаг `not_testable_at_N32`, а не `refuted`, если эффект ниже floor;
6. per-doc medians, не per-position как независимые samples;
7. block structure / domain controls.

**Минимальный API:**

```python
paired_bootstrap(docs, stat_fn, B=1000)
permutation_test(objects, stat_fn, permute_fn, B=1000)
resolution_floor(metric_fn, docs, subsamples=[8,16,32])
```

**Важно:** floor не в аудите, а внутри каждого теста. Это поправка Спикера 3, которую я принимаю.

## 1.8. Поведенческий блок для интервенций

Этот блок **не нужен** наблюдательному E-40, но нужен E-44/E-42/E-43.

Основной endpoint:

\[
b_{mag}:=\|\Delta z\|^2.
\]

Линейный предиктор:

\[
b_{lin}:=\epsilon^2\sigma_1^2.
\]

Остаток:

\[
b_{res}:=b_{mag}-b_{lin}.
\]

KL-сопровождение:

\[
KL_{lin}
=
\frac12\epsilon^2(Jv)^\top P(p)(Jv).
\]

Качественный endpoint:

\[
b_{qual}:=corr_f
\]

используется как **классификатор режима**, а не как фильтр исключения.

**Переиспользование:**

- E-44 cross-position;
- E-42.4 intervention;
- E-43.3 holonomy loss;
- E-43 recipes.

**Минимальный API:**

```python
behavior_magnitude(delta_logits)
linear_predictor(J, eps, direction)
behavior_residual(b_mag, b_lin)
kl_linear_predictor(J, p, eps, v)
corr_f(logits_base, logits_perturbed)
```

# 2. Что НЕ надо вносить в ядро

Вот это важно. Я бы явно запретил тащить в core следующие вещи:

| Объект | Почему не в ядро |
|---|---|
| \(T_{ij}\) | PSD вакуумен; грамиан производных не объединяет SVD, связность и спектр |
| WLC / полимер | модель поверх данных, не reusable операция |
| mobility edge / Anderson | интерпретация, не базовая математика |
| \(U(2)\) | гипотеза о конкретном окне, не общий объект |
| CFT / лог-периодика | частная гипотеза |
| p-адика / экономика | внешние метафоры, не операционное ядро |
| \(F_{lt}\) как готовую истину | вычислительный модуль можно сделать, но его интерпретация — E-42 |
| \(R_{can}\) как «параметр порядка» | в ядре это скаляр профиля; статус — результат теста |

Ядро должно быть библиотекой **операций**, а не музеем гипотез.

# 5. Что считать «переиспользуемой математикой» в статье

Я бы в методологическую часть статьи вынес не все модели, а 5 reusable contributions.

## 5.1. Gauge-aware operator diagnostics

Формулы:

\[
\frac{\|OX\|^2}{\|X\|^2},
\quad
\frac{\|OX\|^2/\|X\|^2}{\|O\|_F^2/K},
\quad
g_{uni}(X)=\frac{\|QX\|^2}{\|X\|^2}.
\]

Это главный урок E39_supplement.

---

## 5.2. SVD-bundle kinetics

Формулы:

\[
J=U\Sigma V^\top,
\]

\[
\|\Delta J\|^2
=
E_{radial}+E_{right}+E_{left}+E_{cross}+E_{resid}.
\]

Это reusable для любого поля якобианов.

---

## 5.3. Procrustes holonomy

Формулы:

\[
R_{ij}=\operatorname{polar}(V_i^\top V_j),
\]

\[
H_{012}=R_{01}R_{12}R_{02}^{-1}.
\]

Это уже зрелый кусок.

---

## 5.4. Reduction control

Формула в общем виде:

\[
Y_{res}=Y-\hat Y_{\text{trivial}}.
\]

И правило:

> производная метрика не принимается, пока не отделена от тривиального прототипа.

Это очень сильная методологическая вещь.

---

## 5.5. Channel-tagged inference

Формально:

\[
\text{result}=
(\text{protocol},\text{slice},\text{window},\text{side},\text{metric},\text{null},\text{contract}).
\]

Это не glamorous, но именно оно спасает от ложных противоречий.

# 7. Мой итоговый ответ на вопрос

Что имеет смысл внести в ядро проекта как переиспользуемую математику?

Мой список:

1. **ChannelTag / provenance** — обязательная паспортизация результата.
2. **Gauge/operator diagnostics** — norm vs energy, isotropic reference, \(g_{uni}\), \(P(p)\)-selfchecks.
3. **SVD-bundle representation** — \((U,\Sigma,V)\) как три проекции поля.
4. **Procrustes transport / holonomy** — \(R_{ij}\), \(H\), \(\kappa\), \(\theta_j\).
5. **Kinetic SVD decomposition** — пять каналов, cross-term, energy not shares.
6. **Reduction control** — тривиальный прототип + residual/null.
7. **Statistical contract machinery** — paired bootstrap, permutation, resolution floor, `not_testable`.
8. **Behavior endpoints** — только для интервенционных треков: \(b_{mag}=\|\Delta z\|^2\), \(b_{lin}\), \(b_{res}\), \(b_{qual}\), KL-linear predictor.

Если это оформить как ядро, то E-40 становится не набором разрозненных скриптов, а первой проверкой библиотеки. E-41–E-43 тогда будут не «ещё экспериментами», а потребителями тех же операций.

**Коротко:**

\[
\boxed{
\text{Ядро проекта = SVD-связка + калибровочные операторные диагностики + Procrustes-связность + редукционный контроль + статистический контракт.}
}
\]

Модели остаются снаружи. Ядро должно уметь убивать модели, а не верить им.
