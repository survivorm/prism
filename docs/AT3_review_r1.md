## 2. B1 — баг: two-sided sign p в `min_n_sens` занижен в 7 раз, когда негативов меньшинство ⛔

Код:

```python
p_one = sum(comb(n_dd, i) for i in range(k_neg, n_dd + 1)) / 2**n_dd
p_two = 2 * min(p_one, 1 - p_one)
```

`p_one = P(X ≥ k)`, значит `1 − p_one = P(X ≤ k−1)`. Корректный двусторонний — `2·P(X ≤ min(k, n−k))`.

- **k > n/2:** `P(X≥k) = P(X≤n−k)` по симметрии ⇒ **верно**;
- **k < n/2:** нужно `P(X≤k)`, код даёт `P(X≤k−1)` ⇒ **off-by-one, анти-консервативно**.

Затронутые числа (ручной счёт):

| блок | k_neg/n | в артефакте | корректно | отношение |
|---|---|---:|---:|---:|
| **L17_gen** min-n 3 | 2/14 | **0.00183105** | 2·106/16384 = **0.01293945** | **7.1×** |
| **L17_gen** min-n 20/50 | 2/13 | **0.00341797** | 2·92/8192 = **0.02246094** | **6.6×** |
| L23_gen min-n 50 | 11/13 | 0.02246094 | 0.02246094 | ✓ |
| L23_tf min-n 3 | 8/14 | 0.79052734 | 0.79052734 | ✓ |
| L17_tf min-n 3 | 13/14 | 0.00183105 | 0.00183105 | ✓ |

Проверка: `0.0018310546875 = 2·15/16384 = 2·P(X≤1)`, а нужно `2·P(X≤2) = 2·106/16384`.

**Первичный `sign_test_gen_L23` использует `sign_test_twosided` — там формула правильная** (`2·Σ_{i≤min(k,n−k)}`), p=0.012939 для 12/14 верно. Баг только в `min_n_sens` и только на minority-negative ветке — то есть **ровно на L17 reverse-trend**, который выносился как самостоятельный результат.

Направление при корректных p выживает (0.0129 и 0.0225 < 0.05), но заявленная сила завышена на порядок. Фикс — одна строка:

```python
k_min = min(k_neg, n_dd - k_neg)
p_two = 2 * sum(comb(n_dd, i) for i in range(k_min + 1)) / 2**n_dd
```

и переиспользовать `sign_test_twosided` вместо локальной формулы, чтобы не было двух реализаций одного теста.

## 3. B2 — `resolvable` сравнивает не с той величиной; gen-p1 на самом деле разрешён ⛔

Код: `resolvable = bool(dp1 < min(widths))`, где `widths` — ширины **средних** бинов.

Но статистика блока — **Δ(Q1−Q4)**, то есть крайние квартили. Релевантный масштаб — **IQR**, а не самая узкая середина.

| сторона | δp1 | IQR | min mid-width | флаг | по IQR |
|---|---:|---:|---:|---|---|
| **gen** | **0.000921** | **0.003893** | 0.000246 | `false` | **0.00092 < 0.00389 ⇒ разрешён** (24% IQR) |
| TF | 0.405712 | 0.238707 | 0.082388 | `false` | 0.406 > 0.239 ⇒ не разрешён ✓ |

И артефакт это подтверждает: **gen p1 Δ = −0.02170, CI95 [−0.06497, −0.00788] — целиком ниже нуля.** Эффект на p1-оси есть, и он того же знака, что на margin-оси. Флаг `resolvable=false` его ложно отбрасывает.

Содержательно это **усиление**: gen-эффект виден на двух разных ось-переменных (margin и p1), а не только на одной. TF не разрешён ни по одному критерию.

Фикс: `resolvable_extremes = dp1 < iqr` отдельно от `resolvable_all_bins = dp1 < min(widths)`; в вердикт по Δ(Q1−Q4) идёт первый.

## 4. B3 — атрибуция «fp16-шум» не проходит арифметику ⛔

Артефакт: `margin_diff_w_saved_gen` median **1.920**, p95 **2.838**, при margin median **6.94** ⇒ 28% медианно.

Оценка квантования (ручной счёт): fp16 eps = 2⁻¹¹ = 4.88e−4; ‖h‖ = 10.03, D = 1024 ⇒ компонента ≈ 0.313; ошибка компоненты ≤ 2.44e−4·0.313 = 7.6e−5; после деления на rms (0.313) → 2.44e−4; логит = Σ₁₀₂₄ (h/rms)·w·E, при |E| ~ 0.025 и случайных знаках →

$$\delta z \sim \sqrt{1024}\cdot 2.44\!\times\!10^{-4}\cdot 0.025 \approx 2\!\times\!10^{-4}$$

Маржа — разность двух логитов ⇒ δ ≲ 4e−4. Наблюдаемое 1.92 — **на 3–4 порядка больше**. bf16 (eps 2⁻⁸) даёт ×8, то есть ~3e−3 — всё равно на 3 порядка ниже.

Значит расхождение `recomputed vs saved` **не объясняется dtype состояний**. Кандидаты: масштаб/конвенция saved mg, другой путь вычисления головы на TPU, E в другой точности, или saved mg ≠ та же величина.

Это load-bearing: на оценке 2.838 держится вся оговорка «TF низкорешиционный».

**Решающая проверка, одна строка на уже лежащих массивах:**

```python
# |Δmg| против mg_saved: мультипликативно или аддитивно?
slope, intercept = np.polyfit(mg_saved, np.abs(mgw - mg_saved), 1)
# slope≈0.28, intercept≈0  ⇒ масштаб/конвенция, НЕ шум
# slope≈0,   intercept≈1.9 ⇒ аддитивный шум (тогда искать источник)
```

Плюс корреляция |Δ| с ‖h‖ по позициям. Это разводит объяснения до всякой интерпретации TF.

## 5. B4 — оговорка о разрешении применена непоследовательно: L17-local ещё мельче TF ⛔

```
TF L23 margin quartiles:      0.269 / 0.662 / 1.366   IQR 1.097
L17-local margin quartiles:   0.146 / 0.351 / 0.677   IQR 0.531
```

**L17-local IQR вдвое меньше TF-ного.** Тот же dtype состояний, та же голова, тот же перенос оценки шума 2.838. Если TF объявлен низкорешиционным, L17-local — тем более.

Но N3-вывод («эффект про уверенность финальной политики, не локальную») опирается именно на **flat** L17-local: Δ = +0.000126, CI [−0.0266, +0.0136]. Под шумом 2.838 flat — ожидаемый исход, а не свидетельство.

Логически нельзя держать оба:

- шум ≈ 2.84 ⇒ **и TF, и L17-local** неинформативны, N3-вывод не установлен;
- шум ≪ 1 ⇒ TF разрешён (и его flat — содержательный), L17-local разрешён, N3-вывод стоит.

Сейчас выбран промежуточный вариант, который даёт максимум выводов при минимуме оговорок. B3 решает, какой из двух的世界 верен.

Отдельно: `corr_local_final` медиана около нуля (per-doc от −0.266 до +0.218) — локальная и финальная уверенность почти не связаны. Это интересно само по себе, но опять же зависит от того, шум это или сигнал.
