## 5. Что физически измеряется (подмена эстиманда)

Контрольное и вставленное окна **токен-идентичны** (`ids[cut+d : cut+d+W]`), различаются абсолютной позицией и префиксом. По вашему же результату E-62/E-64: *«кривая = локальное поле», dip воспроизводится blk32-нулём, избыток сверх локальности ≈ 0*. Значит близость оконных dip **ожидается заранее** и не свидетельствует об упругости среды — она свидетельствует о локальной детерминированности статистики токенами окна.

Плюс: A4 (релаксация ≠ упругость) уже принято, но проблема глубже — **на этих данных не установлено даже наличие возмущения**. Статья, §6 п.25: *«сдвиг ниже разрешения получает статус not_testable, а не refuted»*. AT8_2 присваивает ELASTIC там, где собственный канон проекта требует `not_testable`. В enum вердиктов **нет ветки NO_EFFECT / below_resolution** — машина не умеет выразить фактическое состояние дел.

И ещё: **доза в токенах ≠ доза в натах**. Фраза предсказуема после 2-го повтора; surprisal повторов 3…16 ≈ 0. «Не масштабируется с дозой» может быть свойством входной статистики, а не среды. У вас **есть nll в каждой записи** (S4) → это проверяется disk-only: `D(n) = CE(inj)·(T+L_n−1) − CE(ctrl)·(T−1)`. Если D(n) насыщается — ось дозы построена не в той переменной.

### A1. Инверсия гейта `n_meas_doc_n`: цензурированные клетки засчитываются как «восстановление»

`at8_2_analysis.compute_verdict`:

```python

                    if c["W"] == w_axis and c.get("l_rec", 0) > 0})
...
if n_meas_doc_n < 6: verdict = "NOT_RESOLVED"
```

TZ §5: «меньше 6 пар (doc,n) с `ℓ_rec>0`» — по смыслу это гейт **достаточности наблюдённых восстановлений**. Но `not_recovered` имеет `l_rec = D_max > 0` ⇒ **провал восстановления удовлетворяет гейт наличия восстановления.** Чем больше клеток не восстановилось, тем надёжнее гейт «данных хватает».

**Доказательство на ваших числах.** Популяция W64 с `l_rec` = 20 клеток (5 доков × 4 дозы; wiki_4/5/6 отваливаются: `D_max = 2, −1, −1`). Диагностик v2: `axis_W64_notrecovered_share = 0.75` ⇒ **15 not_recovered**, остаётся 5 = `no_effect` + `recovered`.

⇒ число (doc,n) на W64 с `rec_status == "recovered"` и `l_rec > 0` **≤ 5 < 6**.

| чтение гейта | n_meas_doc_n | исход |
|---|---|---|
| как реализовано (`l_rec>0`) | ≥ 15 | гейт проходит → ELASTIC |
| как задумано (`recovered` и `l_rec>0`) | ≤ 5 | **гейт срабатывает → NOT_RESOLVED** |

⇒ **DIFFUSION**, все три условия выполнены. R² проходит порог с зазором 0.021 — ровно та хрупкость 4-точечной регрессии, которую TZ сам помечает как MINOR.

Это не гипотетика: в вашем артефакте **нулевая медиана реально есть** — `censored_excluded = {61.5, 0, 49, 62}`, ноль на `n=4`. Попал бы он на `n=2` — машина выдала бы «диффузия, солитон опровергнут». Один шумовой отсчёт решает между ELASTIC и DIFFUSION.

Корень: `no_effect`-нули входят в **основную** медиану наравне с длинами, а потом на них делят.

### A3. Отсутствующая доза 16 превращается в `ratio = 0.0` → ELASTIC

```python
elif l2 == 0 and (l16 in (None, 0)): r = 0.0
```

`l16 = None` (нет ни одного измеримого `ℓ_rec` на W64 для n=16) → `r = 0.0` → `r ≤ 2` истинно → ELASTIC при `frac ≤ 0.4` и `n_pos ≥ 2` (набирается с n=4,8). **Отсутствие измерения становится положительным свидетельством упругости.**

Честно: на *этом* пуле не активно — все четыре дозы делят один набор доков, так что либо все None, либо ни одного. Но это живая мина для любого resume с частичным store / фильтром по длине. Класс G10: недостижимость ветки не должна маскироваться под её подтверждение.

### A4. Знаменатель majority-гейта: точный критерий переворота

```python
with_status = [c for c in cells.values() if "rec_status" in c]   # 116
if n_notrec > len(with_status)/2: NOT_RESOLVED
```

В знаменателе — `no_effect`-клетки, которые **не могут** быть `not_recovered` по построению. Гейт разбавлен структурно-неподходящими элементами.

Точная арифметика на ваших числах (`116` клеток, `55` not_recovered):

```
возмущённые = 55 + R,  R = #recovered(все W);   no_effect = 61 − R
гейт на возмущённых:  55/(55+R) > 0.5  ⟺  R < 55  ⟺  no_effect ≥ 7
```

**Критерий: если в артефакте ≥ 7 клеток `no_effect` — гейт срабатывает на корректной популяции ⇒ NOT_RESOLVED.**

Не утверждаю, что их ≥7: на W64 всего 5 нецензурированных клеток, а на W=8/16/32 `pert0` больше (шумнее окна) ⇒ `no_effect` там меньше. Но отсюда более важный вывод — **хрупкость**:

| правило | текущее | нужно для NOT_RESOLVED | запас |
|---|---|---|---|
| как в коде (все 116) | 55/116 = 0.474 | ≥ 59 | **4 клетки** |
| по возмущённым | 55/(55+R) | `no_effect ≥ 7` | **единицы клеток** |

Вердикт ELASTIC находится в нескольких клетках от NOT_RESOLVED при *любом* из двух чтений. Это не «подтверждено», это «не разрешено с зазором в 3%».

## B. Мажорные — методология (вердикт не обязательно меняется, но он не о том)

### B1. Оси A и B не независимы: `recovered ⇒ to_global = 0` структурно

Для восстановившейся клетки по определению суффикс-макса `pert[D_max] ≤ 0.25·pert0`, а `residual_ctrl = pert[D_max]`. Значит

```
to_global = 1  ⟹  |ik[D_max] − dip_global| < 0.25·pert0 ≈ 0.0035
```

т.е. оконная медиана дальнего края должна совпасть с медианой **всего документа** точнее, чем четверть исходного (и без того крошечного) возмущения. При типичном расхождении окно↔документ 0.05–0.2 это не бывает.

⇒ **все восстановившиеся клетки дают структурный ноль в ось B.** Числитель `frac_to_global` набирается **исключительно из клеток, которые не восстановились** (`not_recovered`: `res_ctrl > 0.25·pert0` → сравнение выигрывается легко; `no_effect`: ограничения нет вообще).

Это убивает главную логическую опору ТЗ: «ось A неинформативна в маловозмущённом режиме — вердикт сходится через ось B». Ось B посчитана **из тех же 116 массивов `pert`** и устроена так, что восстановление в неё вносит нули. Она не может подтвердить восстановление — только не опровергнуть. «Упругость подтверждена» считывается с невосстановившейся субпопуляции.

### B2. Гейт нетривиальности `to_global` смешивает масштабы (остаток MAJOR-1)

```python
to_global = res_glob < res_ctrl and abs(dip_global - dip_control_whole) > thr * pert0
```

MAJOR-1 починил *сравнение* (взяли `dip_control_whole`, не окно) — но **допуск остался оконный**: `0.25 × pert0 ≈ 0.0035` против документного расхождения ~0.01–0.15 (разбавление = массовая доля лупа × разность dip). Гейт истинен почти всегда ⇒ вакуумный. Он начинает связывать только при большом `pert0` — т.е. **перестаёт охранять ровно в том режиме, который решает вердикт**. Анти-консервативно.

### B3. `W8_noisy_flag` — декоративный

Ставится в каждой клетке, **не читается нигде**. Исключение W=8 из оси A достигнуто `W_AXIS=64`, а не флагом. При этом W=8 даёт 32/116 = 27.6% популяции оси B и majority-гейта. Аргумент MINOR-4 («медиана ~6 косинус-пар, самый шумный») для `residual_global` работает **сильнее**: там 6-парная медиана сравнивается с ~400-парной. Самые шумные клетки сидят в оси, которая несёт вердикт.

Направленная проверка: `frac_to_global` по W. Если растёт с W — pooled 0.233 набран смесью масштабов, а не физикой.

### B4. Асимметрия требований к данным между ветками

* DIFFUSION: `_fit` требует `mask.sum() ≥ 3`, иначе `b=None` → ветка недостижима.
* ELASTIC: достаточно `l2` и `l16` (**2 дозы**) + `n_pos ≥ 2`.

При 2 измеримых дозах из 4 опровергающая ветка выключена, подтверждающая включена. Плюс `n_pos ≥ 2` может набираться с n=4/8, которые **в ratio не участвуют** — гейт и статистика говорят о разных дозах.

### B5. `pert0` — один шумный отсчёт, задающий и статус, и линейку

`pert0 < 0.01` (абсолютная шкала) решает статус; `0.25·pert0` (относительная к тому же отсчёту) решает допуск. Следствие: **`ℓ_rec` механически убывает по `pert0`** — больше начальное возмущение → шире допуск → раньше выполняется суффикс-макс. Это верно без всякой физики. А «медиана по докам» смешивает клетки, измеренные **разными линейками** (у каждого дока свой `pert0`).

### B6. `no_effect`-клетка голосует за DILUTION

Для `no_effect` нет никакого ограничения на `pert[D_max]` — оно может быть **больше** `pert0`. Клетка, объявленная «эффекта нет» для оси A, одновременно даёт `to_global=1` для оси B на основании дальнего отклонения, превышающего начальное. Внутренне несогласованно; такие клетки надо либо исключать из оси B, либо обрабатывать явно.

## D. Проверено — чисто (охота на off-by-one)

Специально прошёл всю индексную арифметику. **Здесь ошибок нет:**

* `D_max = T − T//2 − W`: из `start + W ≤ T`, `start = T//2 + d` ⇒ `d ≤ T − T//2 − W` — точно, без ±1.
* Кривые строятся `range(D_max+1)`, `pert` — `range(D_max+1)`, `ik[D_max]` — последний валидный отсчёт. Длины согласованы.
* `win_dips`: guard `start+W > len(h23)` → None ⇔ `D_max < 0` → None. Согласовано.
* **Выравнивание окон:** inj `h1[cut+L_n+d]` и ctrl `h0[cut+d]` — это скрытые состояния **одного и того же исходного токена** `ids[cut+d]`. Токен-идентичность выполнена по построению (ассерта A1/A6 нет, но факт верен). Шовного сдвига нет.
* `cut = T//2`, вставка `ids[:cut] + phrase*n + ids[cut:]` — ни токен не потерян, ни задвоен. Баг E-71B (`ctrl = ids[:cut]+ids[cut:]` — no-op) **не воспроизведён**: контроль = `ids` целиком. ✓
* `W ≥ 3` ⇔ `W−2` lag-1 пар ⇔ «~6 косинус-пар при W=8» — согласовано, окно считается в **состояниях**.
* Популяционные фильтры: `lrec_medians` (по n,W + наличие `l_rec`), `axis_B` (наличие `to_global`) = 116, `lrec_medians_allw` (сначала медиана по W внутри дока, потом по докам) — соответствуют TZ v1.2.

## F. Что делать

**Диск-only, из committed store, до любого перепрогона:**

1. `#recovered(W64)` — если ≤5, гейт `n_meas_doc_n` в задуманном чтении срабатывает ⇒ **NOT_RESOLVED**.
2. `#no_effect(все W)` — если ≥7, majority-гейт на возмущённой популяции срабатывает ⇒ **NOT_RESOLVED**.
3. `frac_to_global` по W и по доку + доковый bootstrap; проверить рост по W (подпись B2/B3).
4. Прогнать машину через синтетические store с известным ответом (нуль / истинная упругость / вечный сдвиг / диффузия) и опубликовать confusion matrix — A2 показывает, что машина путает «нет эффекта» с «диффузия».

**Патчи в код (минимальные, до следующего прогона):**

* `n_meas_doc_n` и `n_pos` — считать по `rec_status == "recovered"`, не по `l_rec > 0`.
* `no_effect`-нули **исключить из основной медианы и из ratio**; ввести отдельный исход `NO_EFFECT / below_resolution` (сейчас машина не умеет выразить фактическое состояние).
* `l16 is None` → `ratio = None` → `not_resolved`, не 0.0.
* majority-гейт — знаменатель `{pert0 ≥ ε_min, D_max ≥ 8}`; старое чтение оставить как diagnostic.
* допуск `to_global` — из документного разброса, не из оконного `pert0`.
* `W8_noisy_flag` — сделать рабочим (исключить W=8 из оси B и гейтов) или снять флаг и признать, что шумные клетки в вердикте.
* решения и публикация на одной точности; `assert` длин кривых; `config_fp` в store + проверка при resume.
* S8 — сплайс из `exp71_soliton.py` вместо `f(x)==f(x)`.
* в клетки — `object/stat/frame` (G14); хуки на 4 слоя обоих типов (ноль дополнительных форвардов); per-position ряды cos и CE вместо скалярных медиан.

**Итог по вопросу «не тот объект / не так взяли / off-by-one»:** индексы и выравнивание окон — чистые, off-by-one нет. «Не так взяли» — да, и в самом неприятном месте: **гейт достаточности данных считает провалы восстановления успехами**, а fallback-ось устроена так, что настоящие восстановления вносят в неё структурные нули. Плюс машина способна выдать DIFFUSION из нулевого возмущения на малой дозе. На этих числах честный статус — `NOT_RESOLVED / below_resolution`, и он достигается disk-only, в две строки подсчёта.
