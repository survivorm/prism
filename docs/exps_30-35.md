## Инфраструктура — глобальные факты (из ревью, применимо ко всем)
- **E-30, E-31, E-33, E-35 — postprocessing на локальном CPU** (GPU/Kaggle не нужны).
  **E-34 — кластеризация** (тоже CPU, кэш). **E-32 — единственный новый GPU-прогон** (инъекции).
- **Слои в кэше `LAYERS_DEFAULT = (6,12,18,19,22,23)`, L0 в кэше нет.** E-30 и E-33 берут
  `{6,12,18,22,23}` (L19 исключён для консистентности с E-14; на L0 нечего считать).
- **Позиционная конвенция — cache-t:** `p128[S-1-t]`, `ids[:, :S-t]`, `H[...]=hs[S-1-t]`.
  **t=0 — последняя позиция, t=127 — первая** (инвертировано к наивной). `seq_pos = S-1-t`.
- **Состав кэша exp27b_dense.pt:** `JR` = **полный (raw) J** (НЕ gauge-free — gauge-free
  = softmax-проекция, применяется downstream); `P128` = **нормализованный p** (сумма 1 по U128);
  `H` = hidden states позиции по слоям; `RANKS` = (entropic, stable, PR) **уже посчитаны**.
- **g = RMSNorm.weight не в кэше** — достаётся из модели (один forward на 0.8B), нужен E-33 (M_K).

## E-30. ESG rank-лестница: где «тысяча измерений» листа (5.md высший-1)

**Цель.** Отделить «лист ~1000 мер» от gauge-артефакта: сравнить effective rank
gauge-free J против raw J. Если `r_gf ≈ r_raw` — лист реально высокоразмерный; если
`r_gf ≪ r_raw` — «тысяча измерений» = gauge/общий режим (см. exp01 v6 / exp27: gauge mode
держит ~99.75% энергии raw J). E-33 интерпретировать через r.

**Протокол.** Для каждого из слоёв `{6,12,18,22,23}` (без L0, без L19) и K-свипа 32..128:
`r_raw` — из кэша (J raw есть), `r_gf` — уже в `RANKS`. Три rank-метрики: entropic,
stable, participation. Вывод: где лестница raw и gf расходятся.

**Off-diagonal coupling — исправленный по ревью.** Наивное `‖offdiag‖/‖diag‖` зависит от K:
`= √(K−1)·(RMS_off/RMS_diag)`, при K=128 порог «0.3» = per-element ≈ 0.026 — пороги повисают.
**Основная метрика (K-инвариантная):** `ρ = RMS(offdiag)/RMS(diag) = ‖offdiag‖_F/‖diag‖_F / √(K−1)`.
Пороги **абсолютные**: `ρ ≪ 0.1` (диагональ доминирует), `ρ ~ 0.3` (сравнимо),
`ρ ≫ 0.3` (offdiag доминирует). **Калибровка по нуль-модели:** `J_rand = diag(√ESG_ii)·Q`
(случайное ортогональное Q с той же диагональю), `ρ_null` — фон; решающее правило `ρ_actual/ρ_null`.

**Нотация:** проектор — `P(p^{(t)})` (p — функция t и сэмпла, не слоя).

**Контроль (ревью):** корреляция `ρ_offdiag` (per-layer) с `|Δp|` на том же слое. Если
coupling сидит там, где p прыгает — это структура выходного распределения, не ESG.

**Считаем:** `r_raw(K)` и `r_gf(K)` на 5 слоях × K-свип; `ρ` + `ρ_null`; контроль `ρ`↔`|Δp|`.
**Артефакт:** `results/exp30_esg_ranks.json`.

## E-31. C(Δpos) полного J: границы предложений (5.md высший-1)

**Цель.** Найти, где поле полного J «ломается» — на границах предложений. Полный J,
**не** топ-r подпространство (E-28 мерил подпространство; здесь — весь объект).

**Δpos — фиксируем в cache-t** (конвенция §Инфраструктура). При маппинге на границы
предложений: `seq_pos = S-1-t`.

**Двойной срез (ревью — критично, полный J vs подпространство).** Ревью подчёркивает:
`C_Frobenius(Δpos)` (полный J) и `C_top-r(Δpos)` (подпространство) — **разные объекты**;
их расхождение — самостоятельный сигнал:

| C_Frobenius | C_top-16 | Значение |
|---|---|---|
| высок | высок | нить/лист в обоих смыслах |
| низок | высок | подпространство когерентно, синг.числа «дышат» |
| высок | низок | энергия когерентна, подпространство вращается |
| низок | низок | ни листа, ни нити |

Добавляем **вторую кривую `C_top-16(Δpos)`** через главные углы (дёшево: те же SVD на `JR`).

**Chunk-гипотеза закрыта** (Test 5: нет периодичности κ на t≈31/63/95) — отдельную проверку
на периодичность чанков **НЕ запускаем**.

**Сегментация (ревью — подводный камень):** code даёт мусор на `nltk.sent_tokenize`.
- wiki/chat: `nltk.sent_tokenize`.
- code: границы `\n\n` или структурный парсер (ast для Python, regex для других).
- math: формулы как единицы (`\(...\)`, `\[...\]`).
- Если парсер не готов — **огранич E-31 до wiki/chat** и зафиксируй в протоколе.

**Pre-flight (ревью — согласование двух сигналов, не гипотеза):** перед запуском проверить,
что пики `dP` (E-28-semantic, границы листа) совпадают с границами предложений. Если совпадают —
сегментно-усреднённый `C(Δpos | intra/inter)` даст контраст.

**Три среза:** (1) усреднённый `C(Δpos)`, (2) позиционно-разрешённый `C(Δpos | t)`,
(3) сегментно-усреднённый `C(Δpos | intra/inter)`.

**Считаем:** `C_Frobenius(Δpos)` + `C_top-16(Δpos)` на 3 срезах; pre-flight dP↔границы;
контроль |Δp|. **Артефакт:** `results/exp31_cpos_full.json`.

## E-32. Инъекции в mid-layers: видит ли Hessian-направление b (5.md высший-2) — **GPU**

**Цель.** Инжектить направление `b_l` (Hessian-направление) в mid-слои и мерить сдвиг.

**Нормировка инъекции (ревью A):** `δ_i ← ε·J^T e_i / ‖J^T e_i‖` → `‖δ_i‖ = ε` для всех
токенов, `s_l` — не смесь доз (соответствует `ε = ‖δ‖` в E-12a).

**Рабочая точка ε (ревью B):** `ε_canon = 0.15·‖h‖` (середина диапазона E-12a 14–53%, где
нелинейности видны, Тейлор ещё адекватен). `s_l` отчитывается на `ε_canon`; sweep
`ε ∈ {5%,15%,30%,50%,70%}` — для диагностики режима (остатки, `Δz/ε` vs ε), не для `s_l`.

**Только в h (ревью C):** модифицируем `h` перед `_run_decoder_pass` (последний токен),
`prefix_cache` остаётся чистым. Зафиксировано в коде E-32.

**Стратегия:** α ∈ {1, 3}, слои {6, 12, 18}.

**Контроль (ревью):** корреляция `‖b(t)‖` (Hessian, per-position) с `|Δp(t)|`. Если ~1 —
Hessian тоже прокси для |Δp|, структура 2-го порядка не несёт независимой информации.

**Стоимость (ревью D):** `64·5·5·32 ≈ 51k` форвардов-от-слоя; K=64 инъекций на позицию =
64 отдельных `_run_decoder_pass` (не батчатся). ~2–3 ч на T4.

**Артефакт:** `results/exp32_injection.json` (kernel, push_all.py — только для E-32).

## E-33. Кривизна L23-листа: геодезика vs линейная интерполяция (5.md высший-8, ставка №2)

**Цель.** Проверить «искривлённый readout»: сравнивает ли геодезическая интерполяция
между логитами вдоль L23-листа линейную интерполяцию, и где кривизна вспыхивает.

**E-33-preflight — регрессионный контроль (ревью, блокирует E-33-full).** Третий кандидат
на объяснение `Δ_SVD`: (i) `d_S(û,û')` — геодезическое расстояние на сфере, (ii) спектр
`M_K` (M-pinning), (iii) `|Δp|` — скачок выходного распределения. Если `Δ_SVD` сильно
коррелирует с `|Δp|`, «геометрия L23» — проекция выходного распределения через RMSNorm, не
геометрический объект. Различить — только этой регрессией. Идёт **до** r-sweep.

```
Δ_SVD(t) = α·d_S(û_t,û_{t+1}) + β·|Δp_t| + residual(t)
```
- `Δ_SVD(t)` — макс. главный угол топ-r (r=16) правых подпространств `J_t, J_{t+1}` (из E-28).
- `d_S = arccos(⟨û_t,û_{t+1}⟩)`, `û = h_final/‖h_final‖` (L23 из кэша).
- `|Δp_t| = ‖p_{t+1}−p_t‖₂` (уже посчитано в E-28-semantic как `dP`).
- OLS + HC3 (robust SE); VIF-контроль (VIF>5 → частичная корреляция Δ_SVD↔d_S).
- 32 док., L23; исключить sentinel-позиции (rank<r, сумма p<0.5 на U128).
- Устойчивость r ∈ {8,32}; остатки: runs test + Breusch-Pagan.

**Вердикт preflight:** α значим, β≈0 → геометрия есть (E-33-full). β значим, α≈0 →
Δ_SVD — прокси |Δp| (E-33 переопределяется). Оба значимы → mixed, добавить |Δp| как
ковариату в sweep и кросс-чек с Hessian. R²<0.3 → искать другие предикторы.

**E-33-full** (только если α значим): geo vs linear интерполяция на L23, M-pinning, r-sweep.
Нужен `M_K = W_lm[𝒮]·diag(g)`, `g = RMSNorm.weight` (из модели, один forward).

**Считаем:** per-doc α,β, p-values, VIF, partial corr, R²; устойчивость r; Δû граница/вне
(permutation B=2000); атрибуция оси 2 (топ-10 токенов U128 по нагрузке).
**Артефакт:** `results/exp33_preflight_regression.json`,
`results/exp33_preflight_axis2_attribution.json`, `results/exp33_l23_curvature.json`.

## E-35. Gauge-голономия (5.md высший-1) — review-E-33, был без места в перенумерации

**Цель.** Накопить голономию по последовательности и проверить нетривиальность gauge-связности.

**Недоопределённость (ревью — оба подводных камня реальны):**
- **«Петля в глубине» не петля.** Одномерная ось; нужен замкнутый контур в плоскости
  (глубина×позиция): плакетка `(l,t)→(l+1,t)→(l+1,t+1)→(l,t+1)→(l,t)`.
- **Пространства несовместимы.** `v_g` из E-12a в R^D (hidden), `P(p)` в R^K (token);
  транспорт `v_{l+1}=P(p)·v_l` некорректен.

**Вариант 2 (упрощение, рекомендован как preflight, один вечер):** отличим ли транспортированный
вектор от случайного той же нормы? Если нет — gauge-связность тривиальна, вопрос закрыт.

**Вариант 1 (полный, только если preflight нетривиален):** связность на расслоении
(глубина×позиция) с двумя полями — вдоль глубины `T_l^(h):R^D→R^D` (`D_l=∂h^{l+1}/∂h^l`),
вдоль позиции `T_t^(p):R^K→R^K` (`P(p_t)`); голономия = некоммутативность `T^(h)`,`T^(p)`.

**Ставка — на тривиальность.**

**Артефакт:** `results/exp35_holonomy_preflight.json`.
