## Зачем (один вопрос, не про M1/M2)

Условие 2 гейта руки B требует «эмиссент зависит от ширины набора / на контроле нет».
Прогон S4pp дал `probe_dependence=false`, но свип **не демонстрировал применения ширины**:
при `top_k=1` и `top_k=400` отчёт одинаков (`n_tl=20`, один порядок id), а по исходнику
(`server-context.cpp:1790`) отчёт при `post_sampling_probs=false` строится из логов ДО
сэмплера — путь отчёта **в принципе** не может показать действие `top_k`.

Вопрос руки S3b один: **применяется ли `top_k` к пост-сэмплированному набору кандидатов на
этом форке.** Ответ НЕ меняет чтение `gate2_met=false` в основном (T=0) прогоне — жадная
эмиссия при T=0 структурно инвариантна к ширине усечения (argmax не зависит от размера
набора, из которого он выбран), поэтому `probe_dependence=false` при T=0 не может быть ни
«отрицательным результатом», ни «положительным». S3b устанавливает только механику: есть ли
вообще механизм, который делал бы условие 2 осмысленным при T>0. Про M1/M2 здесь не
говорится ничего.

## Что уже известно из исходника (догадки не тестируем)

  (`server-context.cpp:1967-1992`). При `temperature=0` вероятности не вычисляются →
  отчёт пуст при любом `top_k`. **Значит контроль при T=0 мёртв; мерим при T=1.0.**
* **Факт-основание (против «флаг проигнорирован»):** `S2a/S2b` основного прогона ходили с
  `post_sampling_probs=true, T=0` и дали `n_tl=0`. Если бы сервер игнорировал флаг, отчёт
  строился бы из пре-сэмплерных логов и был бы не пуст даже при T=0. Пустой отчёт
  достижим только через пост-сэмплерный путь (B3) ⇒ флаг читается. Это исключает
  альтернативное чтение «плоский N» = «post_sampling_probs проигнорирован». Вторичная
  проверка внутри S3b: сумма вероятностей item[0] (Σp) записывается в каждую строку —
  пост-сэмплированный отчёт нормирован (Σp ≈ 1), пре-сэмплированный (logprob без
  перенормировки) — нет.
* `top_k` в цепи сэмплеров есть, и порядок (эхо живого запроса, поле `echo.samplers`):
  `[penalties, dry, top_n_sigma, top_k, typ_p, top_p, min_p, xtc, temperature]`.
  `top_k` идёт ДО `temperature`; `typ_p/top_p/min_p/xtc` после `top_k` при эхо-дефолтах

  интерпретируется как «режет ещё B4», а не как «top_k не применяется».
* `speculative.types=none`.

## Ассерты ДО вычисления N (на каждый ответ)

1. `HTTP == 200`, иначе строка невалидна (`halt_reason="http_<code>"`), N не считается.
2. Поле `completion_probabilities` ЕСТЬ в ответе, иначе `halt_reason="no_field"` —
   отсутствие поля НЕ считается `N=0` (иначе молча попадало бы в правило 3).
3. Для строки `S3b-off-probe`: в её эхе ЕСТЬ поле `top_k` и его значение ≥ `n_probs=20`,
   иначе `halt_reason="off_default_low"`, рука невалидна (потолок B4 не измерен: если
   дефолт < 20 или поле не заэханено, `N_off` — минимум потолка B4 и серверного
   дефолта, неразличимы).
Только после ассертов 1–2: `N(x) = len(completion_probabilities[0])`, если item[0] есть,
иначе `N(x) = 0` (пустой item[0] — это НОРМАЛЬНЫЙ ответ, он попадает в правило 3).

## Правило решения (записано ДО запуска; иного чтения не будет)

Пусть `N_probe = (N(k1),N(k2),N(k4))` и `N_ctrl = (N(k1),N(k2),N(k4))` по адресам;
`N_off` — по строке `S3b-off-probe`.

1. **Положительное (top_k применяется):** на ОБОИХ адресах: `N(1) ∈ {1,2}` И
   `N(k) ∈ {k, k+1}` для всех `k ∈ {1,2,4}` с ОДНОЙ конвенцией (+0 или +1) на адрес И
   `N(1) < N(2) < N(4)` И `N(4) ≤ N_off` (согласие с порядком цепи B4→top_k→отчёт:
   режевый набор не шире безрежевого). Чтение: «top_k применяется к пост-сэмплированному
   набору на этом форке (механика установлена)». Ветка потолка: если при этом
   `N(4) == N_off < 20`, дополнительно фиксируется «B4 держит потолок = N_off, top_k
   виден ниже него» — **только при пройденном ассерте 3** (echo.top_k(off) ≥ n_probs);
   иначе потолок не атрибутируется B4 (он может быть дефолтным top_k) и рука
   невалидна по ассерту 3. Состояние `gate2_met=false` T=0 не меняется (инвариантность
   жадности); осмысленным становится повтор условия 2 при T>0.
2. **Не применяется:** `N_probe` ПЛОСКое `c_p ≥ 2` (все три равны) И `N_ctrl` ПЛОСКое
   `c_c ≥ 2` (все три равны); **`c_p` и `c_c` МОГУТ РАЗЛИЧАТЬСЯ** (у адресов разные
   потолки B4 — ТЗ это прямо допускает), важно только плоское на каждом. Чтение: «top_k
   не применяется к набору (механика отсутствует)»; повтор условия 2 при T>0
   бессмысленен (нет механизма, от которого эмиссия могла бы зависеть); рука B не
   запускается по этой причине. Альтернатива «post_sampling_probs проигнорирован»
   исключена фактом-основанием (n_tl=0 у S2a/S2b) + вторичной проверкой: в строках
   правила 2 Σp0 ≈ 1 (нормированный пост-сэмплированный отчёт), `echo.post_sampling_probs
   = true` — оба поля записаны в артефакт.
3. `N(k1-probe) == 0` (пустой item[0]: пост-сэмплерный цикл оборвался на первом
   `p == 0.0` — при T=1.0 это аномалия: либо вероятности не вычисляются вообще,
   либо `post_sampling_probs` сломан иначе) → рука **невалидна**, выводов нет,
   разбирательство по исходнику.
4. **Любой halt_reason ассертов 1–3 (`http_*`, `no_field`, `off_default_low`) ИЛИ
   смерть сервера** → рука невалидна: `kind="mech"`, `verdict="mech_invalid"`,
   артефакт пишется с `halt_reason`. (Строки без N не попадают в правила 1/2/3/5.)
5. **Catch-all:** ЛЮБОЕ иное сочетание N — в том числе явно: плоское `c_p == 1`
   (с любым `c_c`: «top_k применяет и держит 1» на пробе неотличимо от чужого
   потолка B4=1); плоское `c_p ≥ 2` при неплоском `c_c` (или наоборот: одна
   лестница, другое плато); не-k-лестница (например (2,4,8) или (1,3,5): строгий
   рост, но не {k,k+1}); `N_off < max(N(1),N(4))` (противоречие механике: безрежевый
   набор уже режевого); `N(1) > 2`; частичный рост —
   → `kind="mech"`, `verdict="mech_void"`,
   `halt_reason="no_preregistered_reading"` — рука заканчивается без вывода, чтение не
   выдумывается постфактум.

## Чего здесь заранее НЕ утверждается

* Эмиссия этих 7 запросов **не читается** как довод о механизме: при `temperature=1.0`
  ридаут «эмиссент = аргмакс» не определён, и жадная инвариантность к ширине усечения
  делает эмиссию неинформативной при любом T для вопроса «зависит ли эмиссент от
  ширины». Строкам присваивается `kind="mech"`, вердикт только механический
  (`mech_ok` / `mech_flat` / `mech_void` / `mech_invalid`).
* Ни один вывод S3b не цитируется как про M1/M2 и не правит `gate2` в `S4pp.json`
  (ни предикат, ни числа). S3b даёт оговорку к чтению статуса `gate2_met=false`.
* Если выяснится (2), рука B не запускается; это предрегистрированное следствие, а не
  решение, принятое по факту.

  требует N(k) ∈ {k, k+1} для всех трёх k с ОДНОЙ конвенцией на адрес.
- MINOR-6 «правило 2 при c==20 опирается на внешний факт; payload не включает

  первичным; (б) payload в артефакт — ПОЛНЫЙ (messages, адрес-промпт и все поля

- F5 «эхо записан, но ни в одном правиле не читается» — закрыто: эхо читается
