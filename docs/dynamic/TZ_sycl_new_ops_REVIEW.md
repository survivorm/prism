## Пункт 2. eigtop/eigbot (§2.2)

По v1 найдено и проверено расчётом (power iteration + MGS по ТЗ v1 на 96 реальных
(d,t) jcache L6): shift-подход S=‖A‖_F+margin для bottom-r не сходится (95/96
упираются в max_iter, выход ≈ случайное подпространство, subdist 2.53–2.59) —
причина: нижние 7 λ G — почти нулевой почти вырожденный кластер (λ₇≈8.1e-8,
λ₈≈9.9e-8), S−λ_i ≈ S для всего кластера, относительный gap ~1e-10. Ожидаемая
сходимость v1 «gap ≥ 1.05 ⇒ 15–40 итераций» занижена в ~10× (замер top-7:
17…511 итер., 7/96 > max_iter=512; при gap 1.027 нужно ~440).
**Закрыто версией 07:59**: redesign (eigbot = inverse iteration + host-Cholesky,
прототип на реальных данных), сходимость приведена из замеров, стоп только по
max_iter (resid — отчёт), бюджет local пересчитан, добавлен тест Gagg.
Проверил redesign:
- inverse iteration на M=A+μI для bottom-r — корректный метод (скорость =
  gap λ_r/λ_{r+1} нижнего кластера, ~1.23 ⇒ 2–150 итер. — согласуется с
  прототипом ТЗ);
- Cholesky на реальных данных: **96/96 (d,t) jcache L6 — матрица fp32-входа SPD
  (мин λmin(f32) = 0.0), Cholesky(A_f32 + 1e-12·‖A‖_F·I) сходится 96/96** —
  заявка §5 «jcache-Граимиан SPD, вырожденный вход упадёт громко на хосте»
  подтверждается по данным;
- тест «jcache: subdist ≤ 5e-2, Ritz-max(bot) ≤ λ₇(1+1e-3)» на реальных данных:
  сверка bottom-7 подпространств G_f64 vs G_f32 (то, что видит ядро) —
  **subdist < 5e-4 (worst), Ritz-проверка проходит 96/96** — допуски
  достижимы на этом датасете.

Открытые находки по текущей версии:
- **m-13 (MINOR, §2.2, V₀/LCG) — не закрыто версией 07:59.** Параметры LCG
  (a, c, m) не заданы; сид = batch_idx·7919+col ⇒ batch=0, col=0 → сид 0 (при
  c=0-типе LCG — все-нулевой старт), а «перезапуск колонки w_j = V₀[j]» —
  перезапуск в тот же вырожденный вектор (no-op). Укажите параметры (c≠0),
  перезапуск с другим сидом, либо гарантированно недегенерированный детерм.
  старт (chirp/синусоидальный v[i]=sin(2π(i+1)/(n+1)+φ_j)).
- **m-12b (MINOR, §2.3, деградация).** Пункт «n*r > 32768 → PS_ERR_LOCAL»
  устарел вместе с новым бюджетом: теперь PS_ERR_LOCAL при
  2·n·r·4 + r·r·4 + 64·4 > 65536. Тестовый случай должен быть
  соответствующим (например, n=1024, r=8 ⇒ 66048 > 65536), а не «n*r > 32768»
  (n=1024, r=8 даёт n*r*4 = 32768 — по старой формуле не сработает).
- **n-23 (NIT, §2.2, μ).** μ = 1e-12·‖A‖_F (~1e-10) много ниже fp32-noise
  входа (~1e-7 в абсолютном, ‖rounding‖₂ замеры: 2e-7…3e-6); SPD-свойство
  fp32-матриц и сходимость Cholesky на серии-данных — «по факту», не «по
  построению». Альтернатива μ ~ 1e-6·‖A‖_F даёт робастный SPD, но замедляет
  inverse iteration (ratio (μ+λ₂)/(μ+λ₁) → ~1.005 ⇒ >512 итер. на тесных
  кластерах). Текущий выбор (малый μ + громкий хост-фолл) допустим — зафиксируйте
  в §5, что μ выбран осознанно вместе с этим trade-off.
- **n-24 (NIT, §2.2, FLOP-оценка).** «Итерация ≈ 2·n³/3 FLOP (n=128:
  0.7 MFLOP ×2)» — 2·n³/3 = 14 MFLOP при n=128 (это стоимость Cholesky, не
  итерации); два triangular-solve ≈ 2·n²·r (n=128, r=7: 0.23 MFLOP; r=32:
  1.05 MFLOP). Число в примечании поправьте, чтобы не вводить в заблуждение.
- **n-25 (NIT, §2.2/§5).** H2D-трансфер L [batch,n,n] (1 ГБ для 16384×128×128)
  на каждый вызов — не упомянут как стоимость; для batch=16384 это заметная
  часть wall (порядка 0.5–2 с на iGPU). Отметьте в §5.
- **n-26 (NIT, §2.2).** «16384 матриц 128×128 Cholesky ≈ 0.4с» —
  (1/3)·128³·16384 ≈ 1.2e10 FLOP; 0.4 с требует ~30 GFLOP/s в numpy —
  реалистичнее 1–4 с. Оценка в примечании, поправьте.
- **n-14 (NIT, §2.3, ортогональность).** ‖VᵀV−I‖_F ≤ 1e-5 на грани для одного
  прохода MGS в fp32 (попарные ~√n·eps ≈ 1e-5 при n=128); если смоук провалит —
  двойной MGS или вывод из n·r·eps.
