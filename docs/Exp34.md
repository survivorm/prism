## Цель и идеология

Локализовать источник off-diagonal структуры ESG — равномерный сдвиг (gauge), доминирующий токен, или распределённый cross-talk между токенами. Результат определяет, спасаема ли per-token защита (P1) в первом порядке, и, следовательно, статус E-32 (центральный vs уточняющий). Идеология: не запускать дорогое измерение второго порядка (E-32), пока не известно, что первый порядок нетривиален.

## Математика (сверх paper.md)

**ESG и её диагональ.** `ESG_l = (1/N) Σ_i J_l^{(i)} (J_l^{(i)})^T ∈ R^{K×K}`. Диагональ `ESG_ii = ||J_i||²` — self-response токена `i`; off-diagonal `ESG_ji = ⟨J_j, J_i⟩` — cross-talk.

**Три уровня снятия cross-talk.** Последовательно применяем три проектора к `ESG_l`:

- **Raw:** `ESG_l` как есть.
- **Gauge-free:** `ESG_l^{(p)} = P(p^{(t)}) · ESG_l · P(p^{(t)})` (P симметричен, поэтому `P·ESG·P^T = P·ESG·P`). `p` — функция позиции `t` и сэмпла, не слоя — отсюда нотация `P(p^{(t)})`, не `P(p_l)`.
- **Top-1 removed:** `ESG_l^{(-1)} = ESG_l − λ₁ · u₁ u₁ᵀ`, где `(λ₁, u₁)` — топ-собственная пара `ESG_l`.

**Основная метрика `ρ` (K-инвариантная).** Frobenius ratio `r = ‖offdiag(ESG)‖_F / ‖diag(ESG)‖_F` зависит от K: `r = √(K−1) · (RMS_off/RMS_diag)`, и пороги в шкале `r` «повисают» при смене K (при K=128 порог 0.3 — это per-element ratio ≈ 0.026). Поэтому основная метрика — per-element:

`ρ = RMS(offdiag) / RMS(diag) = r / √(K−1)`.

Абсолютные пороги, не зависящие от K: `ρ ≪ 0.1` — диагональ доминирует, `ρ ~ 0.3` — сравнимо, `ρ ≫ 0.3` — offdiag доминирует.

**Калибровка по нуль-модели.** Случайное `J_rand` с той же диагональю: `J_rand = Qᵀ·diag(√ESG_ii)`, случайный ортогональный `Q` (первоначальная запись `diag(√ESG_ii)·Q` — опечатка: тогда `ESG_rand = diag(ESG_ii)`, offdiag ≡ 0 и калибровка вырождается; `E_Q[off²(Q D Qᵀ)]` в этом же пункте подтверждает порядок `Q D Qᵀ`). `ρ_null = E_Q[ρ]` — среднее по Q; решающее правило: `ρ_actual / ρ_null`.

**Sentinel-исключение.** Sentinel = позиция, где сырая (sub-stochastic) сумма `p128` по `U128` < 0.5 — top-128 токенов несут < 50% вероятностной массы. Критерий проверяем по полю `P128_RAW` в кэше (сырые суммы; нормированная `P128` всегда суммирует в 1, порог на ней не триггерится). Без `P128_RAW` в кэше доля 0 означает «нет данных для проверки», а не «сентинелов нет». Исключённые позиции выбрасываются из per-sample медианы и пар корреляции; доля фиксируется в отчёте (`sentinel_fraction`, `sentinel_source`).

**Сокращение по слоям.** L0 в dense-кэше нет (`LAYERS_DEFAULT = (6, 12, 18, 19, 22, 23)`, L19 исключаем для консистентности с E-14) → считаем на `{6, 12, 18, 22, 23}`. По E-10a `uniformity_0 = ⟨u₁, 𝟙/√K⟩²`:

- L23 = 0.503 → `u₁` не совпадает с `𝟙`, третий уровень информативен. Три числа.
- L6–L18 ∈ [0.85, 0.97] → `u₁ ≈ 𝟙`. При **дополнительном допущении `p ≈ uniform`** (тогда `P(p) ∝ proj_{1⊥}`) `P(p^{(t)})·ESG·P(p^{(t)}) ≈ ESG − λ₁u₁u₁ᵀ` и второй/третий уровни совпадают — два числа. Без `p ≈ uniform` (фокусированный `p`, типично для уверенных сэмплов L6–L18) `P(p)` — не ортогональная проекция на `1⊥`, и совпадение уровней 2 и 3 — **гипотеза для проверки**, а не факт: считаем оба числа, расхождение `|ρ_gf − ρ_top1|` — само по себе сигнал (фокусировка `p`).

**Пер-сэмпл агрегация.** Ratio считается **на каждом сэмпле отдельно** (на его собственном `ESG_l^{(i)} = J_l^{(i)}(J_l^{(i)})^T`), затем агрегируется медианой по сэмплам. Пул `ESG` по сэмплам до вычисления отношения некорректен: смешивает сэмплы с разными масштабами перед нелинейной функцией `offdiag/diag`.

**Инвариантность к нормировке.** Ratio инвариантен к умножению `ESG` на скаляр: `offdiag(c·ESG)/diag(c·ESG) = offdiag(ESG)/diag(ESG)`. Дополнительная нормировка на trace избыточна, но не вредит.

## Подводные камни

1. **Per-sample vs pooled.** Главный риск. Если пулить `ESG` по сэмплам до отношения, получим артефакт: смешение разных масштабов `||J||` искажает `r_raw` в сторону от истинной структуры.
2. **Sentinel-строки.** Если при взятии `ESG` часть строк замаскирована (норма ниже порога), диагональ содержит нули, и `diag → 0` даёт `r → ∞`. Решение: считать отношение только на сэмплах с полным набором ненулевых строк; фиксировать долю исключённых.
3. **K=128 vs D=1024.** Off-diagonal — `K×K`, не `D×D`. Это cross-talk по токенам, не по hidden-направлениям. Для P1 (защита) — правильно, потому что P1 защищает токены через их представление в hidden.
4. **P(p^{(t)}) — не проектор.** `P² ≠ P` (лемма `[L-gauge]`). `P·ESG·P` — не ортогональная проекция, а квадратичная форма. `ρ_gf` нормирован, но интерпретация «сколько энергии в off-diagonal после снятия gauge» — приблизительна. Это фиксируем явно.
5. **Диагональ ≠ self-response в строгом смысле.** `ESG_ii = ||J_i||²`, но `J_i` — градиент логита `i` по `h`. Это не «токен i защищает себя», а «насколько логит i чувствителен к h». Терминология важна для интерпретации P1.
6. **Малые N (N=32).** Bootstrap-CI широкие, точка может быть неустойчивой. Обязательно отчитываться разбросом, а не только медианой.

## Что собираем

Per-layer (L6, L12, L18, L22, L23):
- `ρ_raw`, `ρ_gf`, `ρ_top1` — медиана по сэмплам.
- `ρ_null` (нуль-модель) и `ρ_actual / ρ_null` на каждом уровне.
- IQR или std по сэмплам для каждой.
- Доля сэмплов, исключённых из-за sentinel.
- `uniformity_0` каждого слоя (подтверждение по E-10a).
- Контроль: корреляция `ρ_offdiag` (per-layer) с `|Δp|` на том же слое. Если coupling сидит там, где `p` прыгает, — это структура выходного распределения, не ESG; без этого контроля интерпретация неоднозначна.

## Как

1. Загрузить exp27b dense-кэш: `JR` — полный raw `J` (не гейдж-фри, `r_raw` не теряется), `P128` — нормализованный `p` (сумма 1 по `U128`, готов к использованию), `RANKS` — уже посчитаны. Все три уровня вычислимы на существующем кэше.
2. Для каждого сэмпла, позиции и слоя: посчитать `ESG_l^{(i)}`, `P(p^{(t)})^{(i)}`, `ρ_raw^{(i)}`, `ρ_gf^{(i)}`, `ρ_top1^{(i)}` (последний — только на L23).
3. Нуль-модель: `J_rand` с той же диагональю, `ρ_null`.
4. Агрегировать медианой и IQR по сэмплам.
5. Контроль: корреляция `ρ_offdiag` с `|Δp|` per-layer.
6. Сохранить `exp34_p1_coupling.json`.

## Интерпретация

| Паттерн | Что означает | Следствие для P1 |
|---|---|---|
| `ρ_raw ≫ 0.3` на L6–L18; `ρ_gf ≪ 0.1` | coupling сидит в uniform mode | P1 спасаема: убить gauge, защищать дифференциальные направления |
| `ρ_gf ~ 0.3` на L6–L18; `ρ_top1 ≪ 0.1` | coupling в доминирующем токене | P1 частично спасаема: защищать несколько токенов, не все |
| `ρ_gf ~ 0.3` и `ρ_top1 ~ 0.3` | распределённый cross-talk | **P1 фундаментально сломана в первом порядке** — публикуемый факт |
| `ρ_gf ≪ 0.1` везде | первый порядок диагонален | E-32 остаётся центральным (уточняет второй порядок) |
| `ρ_gf ≪ 0.1` на L6–L18, но `~ 0.3` на L23 | coupling растёт у выхода | P1 валидна в середине, ломается на выходе |

Медианы по per-sample медианам (IQR в отчёте). Читаем:

1. **ρ_gf ≈ 0.064–0.069 < 0.1 на всех слоях** — по таблице интерпретации это строка «первый порядок диагонален» → **E-32 остаётся центральным** (уточняет второй порядок).
2. **ρ_raw 0.16–0.22 — «comparable» зона**: сырой offdiag значителен, но gauge-free снимает его в 3–4 раза. Coupling в основном в gauge + доминирующем токене, не распределённый cross-talk. **P1 спасаема**.
3. **ρ_gf/ρ_null растёт с глубиной**: 0.98 (L6 — остаток на уровне нуль-модели) → 3.61 (L23). Остаток cross-talk усиливается к выходу — совпадает с паттерном E-13 (сходство подпространств L18→L23).
4. **Sentinel: 50.7% позиций** (2077/4096, одинаково по слоям — как и положено, raw sum не зависит от слоя). Крупный побочный факт: top-128 токенов несут < 50% массы на половине позиций; порог 0.5 для raw-sums, видимо, слишком строгий. Все ρ-медианы отчитаны по оставшимся 49.3% («уверенным» позициям); при переосмыслении порога пересчёт дешёвый (только маски).
5. Контроль `ρ_raw` vs `|Δp|`: слабый в ранних слоях (0.09–0.15), заметный на L22–L23 (0.29–0.36) — часть coupling в поздних слоях сидит там, где `p` прыгает; интерпретация ρ на L22–L23 с оговоркой.

**Решение по гейту:** `ρ_gf ≪ 0.1` на L6–L18 → **E-32 центральный**. `ρ_gf/ρ_null` = 0.98–3.61, не «≪ 1» → **E-30 (mode decomposition) запускается** (postscript ниже). E-31/E-35 — параллельно, как в «Порядке запуска».

## Критерии остановки

- E-34 запускается первым, до всего остального.
- Если `ρ_gf ≪ 0.1` на L6–L18 (и `ρ_gf/ρ_null` мало) → **E-32 центральный**.
- Если `ρ_gf ~ 0.3` на L6–L18 → **E-32 уточняющий**, приоритет уходит к E-31 и E-35.
- Если результат неоднозначен (например, `ρ_gf` между 0.1 и 0.3) → разложить `ρ_gf` по модам `ESG` (какие собственные направления дают вклад в off-diagonal) — это дополнительный шаг внутри E-34.

**Postscript (гейт E-30).** Вывод «первый порядок диагонален → E-32 центральный уточняющий» — **предварительный**: E-34 меряет `ρ_gf`, агрегированный по всем K=128 модам ESG, и не показывает, *где* сидит остаток (`ρ_gf ≈ 0.056–0.064`). E-30 (mode decomposition, `docs/E-30.md`) его разбирает: если сигнал несёт хвостовые моды (r > 32, `PR_modes > 15`), картина смещается в «диагонален в топ-модах, но не в хвосте», и статус E-32 меняется с «центральный уточняющий» на «объясняет только хвостовую часть» (рамка переопределяется: «почему хвост несёт cross-talk, если топ диагонален»). E-30 запускается до E-32 (`docs/run_sequence.md`).

## Порядок запуска

1. **E-34** (pre-flight 1) — минуты, существующие кэши. Включает контроль `ρ_offdiag` vs `|Δp|`.
2. **E-35-preflight** (регрессия `|Δp|`-контроля + Δû-чек + атрибуция оси 2 + контроли E-34/E-32) — **блокирует E-35-full**.
3. **E-35-full** (M-pinning, r-sweep) — только если preflight показывает, что геометрия есть (`α` значим).
4. **E-31** (B9, корреляционная функция) — параллельно; требует правки `calibration.py` для `return_offsets_mapping=True`.
5. **E-30** (mode decomposition) — по гейту E-34: если `ρ_gf/ρ_null` не «≪ 1» (наблюдено 0.98–3.61 → **да, запустить**). Определяет, несёт ли остаток `ρ_gf` хвостовые моды (r > 32, `PR_modes > 15`).
6. **E-32** (Гессиан) — только после E-30; статус по его результату (`ρ_gf ≪ 0.1` на L6–L18 → центральный; `ρ_gf ~ 0.3` → уточняющий, после E-31/E-35; хвостовая структура → объясняет хвост). Включает контроль `‖b‖` vs `|Δp|`.
7. **E-33** (gauge-голономия) — preflight «транспорт vs случайный», один вечер; полный вариант 1 — только если preflight нетривиален.
