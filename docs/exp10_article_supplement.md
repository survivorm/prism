# §10: Дополнение статьи — Jacobian Bridge как инструмент интервенции

## Методология

Эксперименты Exp16–19 исследуют гипотезу: **правки весов малой модели, направленные на приближение её якобиана $J_S$ к транспортированному якобиану старшей $J_L$, улучшают качество чтения без разрушения модели**. Ключевая архитектура — целевые якобианы считаются один раз (Stage 0) и кэшируются; все последующие эксперименты работают только с малой моделью, что делает CPU-fallback тривиальным.

### Транспорт якобианов

$$J_{\text{tgt}} = (J_L @ E_L^\top) @ E_S @ G_S^{-1}, \quad G_S = (E_S^\top E_S)$$

где $G_S^{-1}$ — псевдообратная Грамиановой матрицы малой модели (вычисляется в float64 для числовой стабильности). Gauge-free проекция:

$$J^{(p)} = \text{diag}(p) \cdot (J - p^\top J)$$

удаляет common-mode shift (gauge component), оставляя дифференциальную чувствительность.

### Архитектура запуска

1. **Stage 0** (`exp16_stage0_targets.py`): вычисление и кэширование целевых якобианов для ~7 пар слоёв × n_samples.
2. **Exp16** (`exp16_readout_pull.py`): пилот без обучения — правка только `lm_head`, свип по α.
3. **Exp19** (`exp19_destruction.py`): калибровка детектора разрушения — 4 сценария правок при α*.
4. **Exp17** (`exp17_lora_distill.py`): послойная LoRA-дистилляция с bridge-loss.
5. **Exp18** (`exp18_logit_kd.py`): контроль — logit-KD при том же бюджете.

Порядок 16 → 19 → 17 → 18: калибровка детектора до доверия к метрикам.

### Батарея метрик (`prism/metrics.py`)

| Метрика | Назначение | Интерпретация |
|---|---|---|
| `bridge_per_pair` | Косинусное сходство J_tgt_p и J_S_ed_p | ↑ = pull работает |
| `KL_ed_L` = KL(p_ed ‖ p_L) | Расхождение с senior | ↓ = лучше согласование |
| `P_ed(A_L)` | Масса вероятности на top-15 senior | ↑ = лучше покрытие |
| `rank_top10_L_in_ed` | Средний ранг top-10 senior в p_ed | ↓ = senior токены выше |
| `hit5_in_U` | Доля top-5 p_ed в union top-15 | ↑ = когерентность |
| `KL_ed_orig` | Поводок: расхождение с оригиналом | ↓ < 0.5 = безопасно |
| `PPL_ed_orig` | Перплексность на 2 последовательностях | ≈ original = не сломано |
| `gsm8k_accuracy` | Поведенческий контроль (GPU) | ≈ original или ↑ |

### Device-конфигурация

| Параметр | GPU (T4/P100) | CPU |
|---|---|---|
| dtype малой | fp32 | fp32 |
| n_samples | 4 | 2 |
| K (token set) | 256 | 128 |
| α-свип Exp16 | {0.01,0.03,0.1,0.3,1.0} | {0.03,0.1,0.3} |
| GD steps | 100 | 40 |
| Exp17 порядки | late→early и early→late | только late→early |
| Exp18 GSM8K | 20 задач few-shot | пропуск |

Runtime-guard: замер первого якобиана; если >60 с — уменьшение K и n_samples вдвое.

### Интерпретация результатов

Три сценария, все публикуемы:

1. **Pull улучшает bridge и поведение** → sensitivity distillation как новая форма KD.
2. **Bridge падает, поведение стоит** → проблема малой в репрезентациях, не в readout.
3. **Разрушение при малых α** → readout жёстко связан с репрезентациями; мост — диагностик, не скальпель.
