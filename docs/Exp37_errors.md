Да, в коде есть и фактические ошибки, и отрицательные отклонения от ТЗ `Exp37.md`. Ниже — по убыванию критичности.

## 1. Критическая ошибка: используется gauge-free J вместо сырого

В `exp37_p_sensitivity.py` (`load_doc`) загружается `ck["JR"]` и трактуется как сырой Якобиан `J_t`.  
Но в E-29 явно зафиксировано: **кэш `exp27b` хранит gauge-free `J_FR`**, а не сырой `∂z/∂h`:

> «исправлен … проверкой “JR сырой” (кэш хранит gauge-free $J_{FR}$, $\sum_j p_j J_{ij} \approx 0$, а не сырой $\partial z/\partial h$)».

ТЗ E-37 (§2.2) определяет:
```
K_t = J_t − P(p_t)·J_t
```
где `J_t` — сырой Якобиан. Код же считает:
```
K_t = J_gf − P(p_t)·J_gf
```
Это **не тот объект**. Все метрики A.1 (`energy_top*`, `rank*`, `align_K*`, `frac_K_from_J`) и B (`ug_attribution`) посчитаны на gauge-free J.  
Косвенное подтверждение — `frac_K_from_J_perP ≈ 0.998` во всех слоях: `P(p_t)·J_gf` очень мал, потому что `J_gf` уже почти ортогонален `p_t`-направлению. Это ожидаемо для gauge-free, но не для сырого J.

**Следствие:** результаты JSON не отвечают на вопрос ТЗ «что убивает P(p_t) в сыром Якобиане». Интерпретация `align_K1`, `rank_loss` и т.д. некорректна.

## 3. Менее критичные, но стоит поправить

- **`peaked_only_frac` считается несогласованно**: `excluded_frac` — по всем позициям всех документов, а `entry["sent_frac"]` — медиана по документам. Если доля sentinel варьируется, `peaked_only_frac` может быть смещён.
- **B исключает не только пиковые, но и sentinel-позиции**: `alive_b = (~sent_t) & (~peaked)`. TZ §3 говорит только о пиковых (`p_max > 0.9`). Sentinels (raw sum < 0.5) — дополнительное исключение, не оговорённое в E-37 (хотя E-34 его использует).
- **`pbar` в A.1 считается по non-sentinel позициям** (`Pdoc[alive].median`). TZ §2.2 не оговаривает исключение sentinel для `p̄_med`.
- **`calibrate` использует `K32_t` (gauge-free K) для калибровки** — усугубляет проблему п.1.
- **В `k_metrics` `rank_*_cal` сравнивает `Sx/s1(t)` с `eps_cal`, где `eps_cal = 3σ_noise/s1_med`**. Это даёт порог `3σ_noise · s1(t)/s1_med`, а не абсолютный `3σ_noise`. Формально TZ допускает «relative to σ1», но при использовании `s1_med` из другого слоя это может искажать ранг.

## 4. Что не является ошибкой, но заслуживает фиксации

- Отсутствие точного `u_1` через SVD `J_t J_tᵀ` для L22 — опционально по ТЗ (§3).
- `null_shuffled`, `null_random_vector`, `null_random_p` игнорируют sentinel-маску — TZ не требует явно, но для чистоты сравнения лучше считать на тех же позициях.
- `top8_tokens` сохраняются, но в агрегаты не попадают — TZ не требует агрегировать, но можно вынести в B-артефакт.

## 5. Итог

**Главная проблема** — использование gauge-free J из `exp27b` в качестве сырого J. Это делает A.1 и B невалидными относительно ТЗ E-37. Если цель — анализировать именно gauge-free J, ТЗ нужно переформулировать. Если цель — сырой J, нужен другой кэш или восстановление `J_raw = P(p)^+ J_gf` (что нетривиально, т.к. `P` не проектор).

**Остальные отклонения** — неполная реализация требуемых диагностик (null для rank_loss, per-position noise, категории из exp28, C-метрики, отдельный B-артефакт, fp64-переключение). Они не ломают код, но делают результаты неполными и частично несопоставимыми с ТЗ.
