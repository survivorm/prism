# Дополнение 2 к ТЗ ARM-B — новый первичный зонд, найденный в исходниках (ноль пересборки)

Всё ниже проверено командами по `~/work/llama.cpp` (read-only) и по закоммиченным артефактам.
ТЗ-файл по-прежнему не правим (на нём идёт ревью); это приложение.

## 1. Где в этом билде расходятся «выбор» и «отчёт» — два разных источника

`tools/server/server-common.cpp:1502-1519` (`get_token_probabilities`, путь `post_sampling_probs=false`):

```
const auto * logits      = llama_get_logits_ith(ctx, idx);
const llama_token * sampled_ids = llama_get_sampled_candidates_ith(ctx, idx);
const int n_logits = llama_get_sampled_logits_count_ith(ctx, idx);
...  cur[i] = {sampled_ids[i], logits[i], 0.0f};
```

а выбор (`src/llama-sampler.cpp:893-950`, `llama_sampler_sample`) устроен иначе:

```
if (sampled_probs)        cur[i] = {sampled_ids[i], sampled_logits[i], sampled_probs[i]};
else if (sampled_logits)  cur[i] = {sampled_ids[i], sampled_logits[i], 0.0f};
else                      cur[token_id] = {token_id, logits[token_id], 0.0f};   // полный словарь
```

То есть отчёт всегда берёт `llama_get_logits_ith(...)`, а сэмплер, если контекст отдал
`sampled_logits`/`sampled_probs` (буферы `sampling.*`, `src/llama-context.cpp:1046-1095`), берёт ИХ.
Это два разных набора чисел при одном и том же `idx` — единственный найденный механизм, который
согасуется со всеми измеренными фактами сразу:

* цепочка сэмплеров в наших запросах нейтральна и при `temperature=0` обязана выдавать аргмакс
  (`Q2b.json`, `E.generation_settings.samplers = [penalties, dry, top_n_sigma, top_k, typ_p, top_p,
  min_p, xtc, temperature]`, все параметры нейтральные; `grammar: ""`, `speculative.types: "none"`,
  `backend_sampling: false`) — и всё равно выбор ≠ вершина отчёта;
* **`top_k: 1` не меняет выбора** (`Q2b.json`, `E`: `emitted=310`, `top1=318`, `generation_settings.top_k=1`)
  — при нейтральной цепочке и общем наборе логитов это невозможно;
* вершина отчёта согласуется с HF fp32 (`Q2.json`: `rank_cpu == 1` во всех 2304 позициях, сверено
  независимым пересчётом внешнего ревью), значит «виноват» именно выбор, а не печать отчёта.

Что это ОБЯЗАНО менять в интерпретации: формулировка «сервер противоречит сам себе» законна, но
«сбой в сэмплере» — уже нет без проверки, чьи логиты увидел сэмплер.

## 2. Новый первичный зонд S1 (дешевле руки B, делать ПЕРВЫМ, iGPU занят на секунды)

`post_sampling_probs` — поле уровня запроса (`tools/server/server-schema.cpp:190`, `field_bool`),
пересборки не требуется. При `post_sampling_probs: true` отчёт строится из `cur_p` самого сэмплера
(`server-context.cpp:1965-1993`), то есть из того же набора чисел, из которого выбран токен.

Запрос: то же `base_body(..., **CANON)` + `"post_sampling_probs": true` на w4, k=70 (известная точка
флипа: отчёт 318/0.6206, выбор 310) плюс 5 повторений и, для калибровки, 3 любых нефлипных позиции.

Предсказания, которые РАЗЛИЧАЮТ гипотезы (переписать в ТЗ дословно):
* **H-двух-буферов** (сэмплер ест `sampled_logits`, отчёт ест `logits`): при
  `post_sampling_probs=true` вершина отчёта ОБЯЗАНА совпасть с выбором (310) и перестать совпадать
  с HF fp32 (318) — флип «переезжает» из выбора в отчёт;
* **H-сбоя-выбора** (сэмплер видел те же полные логиты и всё равно выбрал 310): при
  `post_sampling_probs=true` вершина отчёта остаётся 310 (по построению), НО `top_logprobs`
  схлопывается до одного кандидата при `top_k=1` и вообще перестаёт быть полным словарём —
  сравнивать длину списка;
* **H-шума** (случайное возмущение): флип не воспроизводится 5/5 — а он воспроизводится
  (`Q2b.json`, `A`: 5/5 `emitted=310`, `distinct=1`).

Второй, бесплатный срез того же: длина `top_logprobs` и сумма `p` при `post_sampling_probs=true`
показывают, какой буфер реально использовался (полный словарь или компактный список кандидатов).

## 3. Что отсюда следует для руки B

Рука B (`-ngl 0`) остаётся нужной, но её первичный конецпоинт уточняется: интерес не «число флипов»,
а **исчезает ли расхождение двух буферов на CPU** — то есть S1 на руке B (там, где `sampling.*`
-буферы с большой вероятностью не заполняются) обязан давать вершину отчёта, совпадающую и с
выбором, и с HF fp32. Если на CPU расхождение остаётся — гипотеза двух буферов мертва и остаётся
чистый сбой выбора.

## 4. Мелочи, которые обязан учесть исполнитель

* `--log-disable` в `Q2b.json.server_cmd` подавляет `SLT_DBG`/`SRV_DBG`: для отладочного прогона
  его НЕ передавать, иначе нельзя будет увидеть `sampler chain:` (server-context.cpp:1804).
* гейт устройства: `offloaded %d/%d layers to GPU` печатает `src/llama-model.cpp:1800`; список
  устройств — `src/llama.cpp:172`.
* `-fa` — не bool (`common/arg.cpp:1758-1765`), `on` валиден; менять его в руке B не нужно.
