## Оставшиеся вопросы

### ⚠️ 1. pair_mean использует n = T − 2·dt вместо T − dt

```python
p0a = pair_p0(Pdoc, dt)         # [T-dt, K] — доступны T-dt пар
n = T - 2 * dt                   # ← используется T-2dt
PJa = p_apply(Jdoc[:n], p0a[:n])
PJb = p_apply(Jdoc[dt:dt + n], p0a[:n])
```

Для каждой пары `(t, t+dt)` берётся `p0_t = mean(p_t, p_{t+dt})` и применяется к обоим `J_t`, `J_{t+dt}`. Валидные пары: `t = 0 .. T-dt-1`, то есть **T−dt** штук. В коде используется только **T−2·dt** (≈ 86% для dt=16, 99% для dt=1).

Это рудимент **прежней** версии (different-p0), где `p0b` имел длину T−2dt и нужно было выровнять по нему. В текущей same-p0 семантике ограничение излишне.

**Fix:** `n = T - dt`.

Не блокирует, но сокращает выборку (для L23 dt=16: 96 vs 112).

### ⚠️ 2. Stale docstring про `kill_frac = uniformity_0`

```
Самодиагностика: --selfcheck (синтетика rank-1: uniformity_0 = <u, 1/√K>²,
kill_frac = uniformity_0 при p = uniform; ...)
```

Selfcheck (3) проверяет `survive = √(1−uf)/K`, откуда `kill = 1 − √(1−uf)/K`. Это **не** равно `uf`, кроме тривиальных случаев uf=0 (kill ≈ 1) и uf=1 (kill ≈ 1). Равенство `kill_frac = uniformity_0` не проверяется и не верно.

Стоит либо поправить docstring, либо добавить реальный тест на `kill = uniformity_0` — но он не пройдёт. Рекомендую привести docstring к текущим тестам:
```
синтетика rank-1: uniformity_0 = <u, 1/√K>², survive_frac = √(1-uf)/K;
Δ_SVD_gf = Δ_SVD_raw при p = uniform (Jᵀ1 = 0)
```

### ⚠️ 4. `E_fixed_p_r` внешний guard только по `dgp_1_r{rt}`

```python
for rt in (1, 2, 8, 16)
if all(f'dgp_1_r{rt}' in r_ for r_ in rows)
```

Внутренний `for dt` уже проверяет `all(f'dgp_{dt}_r{rt}' in r_ for r_ in rows)`, так что внешний — избыточен и потенциально неверен (если бы `dgp_1_r{rt}` отсутствовал для какого-то dt, но присутствовал для dt=1 — редкий случай). Для текущего batch_metrics (все dt пишутся одновременно) — ок. Косметика.

### ⚠️ 6. depth_keep ~1.3 GB

Единственный крупный накопитель после one-layer-at-a-time оптимизации. При 5 слоях × 32 документов × 128 позиций × 18×1024 float32 ≈ 1.3 ГБ. ## Проверка логики pair_mean end-to-end

Тест на игрушечном примере:
- `Pdoc` = T×K, T=5, dt=1 → `p0a` = [4, K], `p0a[t] = (Pdoc[t] + Pdoc[t+1])/2`
- `n = T - 2·1 = 3`
- `PJa = p_apply(Jdoc[:3], p0a[:3])` → использует J_0, J_1, J_2, все с p0 = pair(0,1), pair(1,2), pair(2,3)
- `PJb = p_apply(Jdoc[1:4], p0a[:3])` → использует J_1, J_2, J_3, те же p0

Пары: (P(pair(0,1))·J_0, P(pair(0,1))·J_1), (P(pair(1,2))·J_1, P(pair(1,2))·J_2), (P(pair(2,3))·J_2, P(pair(2,3))·J_3). Всё корректно — same p0 на обоих концах.

Потеря: пара (P(pair(3,4))·J_3, P(pair(3,4))·J_4) не используется, хотя `p0a[3]` вычислимо. Это и есть эффект n = T−2dt. Не баг, но потеря данных.

Sentinel mask `mask[:n]` = `~(sent[:n] | sent[dt:dt+n])` — корректна для используемых пар.
