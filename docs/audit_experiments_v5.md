# ...

**Почему это критично:**
| Эксперимент | Sentinel-фильтр | Доля позиций |

**Вердикт:** Требует проверки в `paper.md`. Если сравнения есть — добавить сноску или пересчитать E-28 на alive-only подмножестве.

## ✅ Подтверждено независимо: ключевые математические ядра ЧИСТЫ

Я переписал и численно сверил критические формулы «вручную», не доверяя selfcheck'ам:

### 1. `P·ESG·P` в E-34 — **корректно**
Моя первоначальная гипотеза о баге в `outer(p2e, p)` оказалась ложной. Для симметричного `ESG = J Jᵀ` разложение:
```
(P E P)_ij = E_ij p_i p_j − p_i p_j (E p)_i − p_i p_j (E p)_j + (pᵀE p) p_i p_j
```
**Точно совпадает** с кодом:
```python
ESG * pp - np.outer(p2e, p) - np.outer(p, p2e) + pEp * pp
```
Selfcheck против плотной реализации проходит не потому, что оба варианта ошибочны, а потому, что оба верны. ✓

### 2. Голономия в E-28/E-38d — **корректный порядок**
`H = R01 @ R12 @ R20`, где `R20 = procrustes(V2→V0) ≡ R02⁻¹`.  
Для ортогональных полярных множителей `R⁻¹ = Rᵀ`, поэтому `.transpose(-1,-2)` эквивалентен обратному. Цикл `0→1→2→0` замкнут правильно. ✓

### 3. Спектр углов в E-38d — **баг LAPACK-шума исправлен**
`np.abs(np.angle(...))` действительно предотвращает потерю eigenvalue `-1` (угол `-π` → отфильтровывался старым `>1e-6`). Без этого отражения маскировались под `H ≈ I`. Сейчас каждый 2D-блок даёт два угла `{θ, θ}`, одиночное `-1` попадает в бин `π`. ✓

### 4. Некоммутативность в E-38h — **порядок матриц верен**
`prod = R23 @ R12` соответствует композиции `V_c → V_b → V_a`. Старый `R12 @ R23` давал ложный неабелев сигнал для базисов, отличающихся внутренней ротацией. Исправление подтверждено алгебраически. ✓

### 5. Einsum-проекция в E-39a — **баг v1-v3 устранён**
`'kd,td->tk'` вместо `'kd,td->tkd'` даёт правильное матричное умножение `M_kp · û_t`, а не поэлементное. Докстринг честно фиксирует историю ошибки. ✓

## ⚠️ Потенциальные мины (не баги, но требуют внимания)

### 1. Fallback `P128_RAW` → `P128` в E-35/E-30/E-33r
```python
raw = ck.get('P128_RAW', ck['P128'])  # E-35, E-30
sent = raw.sum(-1) < SENTINEL_SUM
```
- Если кэш создан без `P128_RAW`, fallback на нормализованный `P128` (sum=1) **молча отключает sentinel**.
- В E-30 это уже проявилось как баг. В E-35/E-33r не проявилось только потому, что кэш содержал `P128_RAW`.
- **Рекомендация:** Заменить fallback на явный `raise KeyError("P128_RAW required for sentinel filtering")` во всех скриптах, кроме тех, где sentinel не нужен по дизайну.

### 2. Конвенция порядка позиций `t` в кэше
- Все скрипты используют `t=0..S-1` из кэша, который соответствует **обратному** порядку истинных позиций (`JR[t] = closed_form(h_post[S-1-t])`).
- Это не баг, если все эксперименты согласованы между собой. Но E-38e ранее смешивал свежий форвард (прямой порядок) с кэшем (обратный) — баг был найден и исправлен.
- **Рекомендация:** Добавить глобальный assert в `_e38_cache.load_layer()`, проверяющий конвенцию через контрольный документ, чтобы предотвратить регрессию.

### 3. `kill_frac` vs `kill_frac_check` в E-33r (подтверждено)
- `1 − ‖PJ‖/‖J‖` ≠ `‖J−PJ‖/‖J‖`. Разрыв 2% (0.977 vs 0.997).
- В `paper.md` §2.11 фраза «оператор P(p) снимает 97.8–99.0 % нормы» ссылается на первое, но читатель может восстановить второе как `1 − survive`.
- **Требуется явная пометка в статье**, какое из двух чисел цитируется. Подтверждаю находку исполнителя.

## Ответ исполнителя (верификация находок v5, 2026-11-05)

Проверено независимо от формулировок аудита. По пунктам:

1. **E-28 без sentinel-фильтра — ПОДТВЕРЖДЕНО (механика), но численно не критично.**
   В `exp28_leaf_structure.py` действительно нет ни `P128*`, ни sentinel-маски
   (`deg` — только rank-degeneracy). Квантифицировано на том кэше, что читает E-28
   (`/data/prism_kernels/exp27b/results`, L23, P128_RAW есть): доля sentinel
   **50.7%** (2077/4096 — бит-в-бит с E-34); per-doc медианы all→alive:
   **κ 0.0159→0.0172 (×1.065), Δ_SVD 0.266→0.299 rad (×1.117)** (eigh по Gram JJᵀ
   вместо SVD, self-check против `document_profile` max|Δk2| = 2e-7). Лист L23
   живёт: κ остаётся ~3 порядка ниже rand-базлайна. Снято оговоркой в карточке
   E-28 (ref-exp) и в «Границе вывода» (paper §); в `exp28` добавлены params-поля
   `sentinel_position_set='all'` + `sentinel_fraction_first_layer` (самодокументация
   артефакта, протокол не менялся — опубликованные числа остаются «all»).
   Чужой замеченный нюанс: реестр аудита приписывает E-28 «метрикs чисты, НО...» —
   согласен; сравнения L23↔E-34 в paper уже закрыты глобальной заметкой
   §«Слои и позиции» (строка про all vs alive ≈49%).
2. **Fallback `P128_RAW→P128` — ЧАСТИЧНО.** В E-35 был тихий fallback — заменён на
   `raise KeyError`. В E-37 тихий `sent=0` в else — заменён на raise с env-выходом
   `PRISM_ALLOW_NO_RAW=1`. **E-33r упомянут ошибочно**: там прямой `ck["P128_RAW"]`
   (KeyError по умолчанию), фолбэка нет. E-30 уже fail-loud (fix 2026-11-04),
   в реестре аудита описано состояние артефакта, не кода.
3. **Конвенция порядка `t` — ПОДТВЕРЖДЕНО как конвенция** (билдер `exp27b_dense.py`:
   `p128[S-1-t]`, префикс `:S-t` — внутренне согласован). Регрессионная защита уже
   есть: selfcheck-assert `.flip(0)` в E-38e после бага. Отдельный assert в
   `load_layer` не делал (требует форварда в лоадере) — закрыто на уровне E-38e.
4. **kill_frac vs kill_frac_check — УЖЕ ИСПРАВЛЕНО до аудита**: paper §2.11/§«Объекты»
   публикуют оба числа вместе (прокси `survive_frac` 97.8–99.0% и прямой срез
   0.9974/0.9975). Претензия актуальна только к ранним ревизиям.
5. **E-10a подпись колонки — НАЙДЕН ЖИВОЙ ОСТАТОК**: §2.5 paper.md всё ещё называла
   `gauge_share_0` топ-1 прокси, хотя E-10a/`§2.10` аудита — это `1−λ₁ᶜ/λ₁⁰` (×1.3–2.6).
   Исправлено в этом коммите.
6. **E-35 «эффект softmax»** — докстринг исправлен ранее (commit 37b9045:
   «ПРОВЕРКА ТОЧНОСТИ редукции, НЕ эффект softmax»); в paper/ref-exp такого
   ярлыка нет.
7. Выборочная сверка «подтверждено независимо»: P·ESG·P (разложение совпадает),

   `np.abs(np.angle(...))` (exp38d:145), `prod = R23 @ R12` (exp38h:121 с комментарием),
   einsum `'kd,td->tk'` (exp39a:250 с историей) — все пять верны.
