## Findings

- **F1 — MAJOR** — §2.3 стр. 228–229 (+ история стр. 43): «watchdog ~20с не срабатывает: 1 sweep ≈ 3с (n=128, iGPU)» — замер БЕЗ привязки к batch (6 одиночных 128×128 jcache), а лимит `1 ≤ batch ≤ 65536` и AT2c прогоняет 16384 матриц (§1, §2.8 L390). 1 sweep = 1 запуск ядра на ВЕСЬ батч ⇒ время sweep при batch=16384/65536 ТЗ не ограничивает; при 3с/матрицу и ~10^2 параллельных work-item'ов iGPU — минуты на sweep ≫ hang-check ~20с (§2.1). У gemm в §2.1 чанкинг под hang-check — жёсткое требование; у eigjac правила НЕТ. Чинить: указать batch замера «3с/sweep»; добавить чанкинг batch внутри eigjac (аналог §2.1) или явную оценку времени sweep для worst-case batch=65536.
- **F2 — MINOR** — §2.3 стр. 200–204: в формуле «t = (d−a)/(2b)» буква d (элемент A_jj) конфликтует с циклическим d (смещение в sweep). Математически верно (стандарт XLA), но читатель/исполнитель спутает. Чинить: переименовать элементы (A_ii, A_jj или p/q).
- **F3 — MINOR** — §2.3 стр. 243–244, §2.5 стр. 277–278, §2.7 стр. 322: «offdiag_curve[…] — offdiag_rel матрицы 0 ПОСЛЕ каждого sweep (до остановки; после — финальное значение)» — двусмысленно: при остановке финальное значение = последний per-sweep ⇒ дубликат записи, счёт k vs k+1 не определён; тесту (§2.7, sweeps_to(1e-5) ≤ 16 при max_sweeps=16) нужна точная контрактная длина. Чинить: curve[0..k-1], k = число реально выполненных sweep'ов, дубля не писать; финальное значение = offdiag[0].
- **F4 — MINOR** — §2.3 стр. ~231–235 (Постобработка): MGS — указано, ЧТО (V, все n векторов, 1 проход, host, f64, фикс. порядок ⇒ детерминизм ОК), но НЕ указано, что результат записывается обратно в vecs f32; цифра «ortho ~5e-15» — точность f64, для f32 vecs ожидаемо ‖VᵀV−I‖ ~ n·eps ≈ 1e-5 (всё равно ≤ допуска теста 1e-4). Чинить: явно указать write-back в vecs f32 и к какой точности относятся 5e-15 / 8.4e-5 (f64-расчёт vs f32-вывод).
- **F5 — NIT** — §2.3 стр. 204: «fudge-guard XLA (|b| ≤ 0.1·eps·min(|a|,|d|))» — eps не определён. Чинить: eps рабочей точности (f32 для ядра); иначе реализатор возьмёт f64-eps ≈ 0 и guard никогда не сработает.
- **F6 — NIT** — §0 таблица стр. 66: `ps.eigjac(A)` → (vals, vecs, offdiag) без max_sweeps/tol/curve (полная сигнатура в §2.5). Опционально выровнять; как сводка допустимо.
- **F7 — NIT** — §2.3 C-ABI стр. 242: типы скаляров не явны (ожидаются max_sweeps int64_t, tol double). Нужна сверка с C-ABI-конвенцией §2.1/§2.2 (строки не читались в дельте).
- **F8 — NIT** — закрытие MINOR прошлых ревью: m-28 подтверждён закрытым из самого ТЗ (замер fp32/f64 сходимости в истории+§2.3, тест §2.7: curve-артефакт + assert sweeps_to(1e-5) ≤ 16); полный перекрёстный чек остальных eigjac-MINOR из TZ_sycl_new_ops_REVIEW.md НЕ выполнен — в контексте были только стр. 1–40 файла ревью (заголовок).
