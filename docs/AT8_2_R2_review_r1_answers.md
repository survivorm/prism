### 3.1 Манифест неконсистентен — **принято, исправлено (с уточнением причины)**

Подтверждено на диске: манифест на диске (generated_by «--reanalysis» +
mode «full») записан **пре-финальной** версией скрипта; текущий код уже
писал `mode="reanalysis"`. Корень глубже: **манифест полного прогона в git
не попадал** — реанализ перезаписал его до коммита 478ccbd, и коммит зафиксировал
именно неконсистентный файл. Провенанс полного прогона восстановлен из лога
(source of truth, AGENTS): 182 `CE=` строки, `wall 2596s`. Исправление:
reanalysis-манифест несёт `full_run`-блок (`log` + `log_sha256` + `n_fwd` +
`wall_s`, распарсенные из лога) — артефакт самодостаточен без утратившегося
манифеста полного прогона.

### 3.2 Число форвардов 98 ≠ сетка — **принято, исправлено**

Подтверждено: фактический прогон = **182 форварда** = 14 доков × (1 ctrl +
3 условия × 4 дозы) — лог (182 `CE=`), store (14 доков × 5 ячеек {ctrl, n2,
n4, n8, n16}, в каждой дозе 3 условия), trackio (`n_fwd=182` в финальной
точке). «98» — устаревшая смета TZ v1.0 (до решения о fillerB на всех дозах),
протухшая в докстринге и results. Исправлено: докстринг, results,
`n_fwd=182` в claim и в `full_run`-блоке манифеста. `L_n` в store — длина
блока (int), не форвард; i_loop/ce_block выводятся из loop-форварда — сетка
13/док подтверждена кодом.

### 3.3 Текст причины сильнее логики кода — **принято, исправлено**

Подтверждено по коду: ветки NO_LOOP/GENERIC писали «≤ δ на всех дозах», хотя
решение — по первичной дозе (это **пре-рег F2**, а не недосмотр — скан n*
упразднён именно ради этого), и «≤ δ» читалось как «весь CI ниже δ», тогда
как код проверял CI_low. Для e_generic(16) CI_high = 0.1627 > δ — «≤ δ» было
фактически ложно. Исправлено в `compute_verdict`:
- NO_LOOP: «primary dose n=16: CI95(near)=[0.0844, 0.1197] — CI_low ≤
  δ_near=0.1480, не значимо выше филлер-нуля (здесь весь CI первичной дозы
  ниже δ) (по всем дозам max CI_low=0.0844); e_generic не значим по нижней
  границе (max CI_low=0.1160 ≤ δ_near; верхние границы отдельных доз могут
  превышать δ — см. delta_calibration)…»
- GENERIC: аналогично, без «на всех дозах».

Против «явно проверять all(ci_high ≤ δ на всех дозах)» — **спор**:
усиление правила решения после прогона — post-hoc тюнинг пре-рега; текущая
формулировка текста честна и вердикт при усиленном правиле на этих данных
не меняется (даже CI_high первичной дозы 0.1197 < 0.1480).

### 3.4 Уровень агрегации δ_min — **принято как диагностика; вердикт не трогаем**

Подтверждено и согласен с разбором. Исправление — по рекомендации: в claim
добавлен блок `delta_calibration` (per доза): `near/far_null_mean` +
`null_mean_ci95` (doc-bootstrap, B=2000, seed 0) + `near/far_per_doc_p95`.
Числа: null-mean near(16) = 0.0840, CI [0.0669, **0.1024**]. Честный нюанс,
который эта диагностика открывает: near(16)=0.1020 лежит **на границе**
null-среднего CI — при популяционной калибровке эффект «на разрешении», а не
«ясно ниже». Поэтому:
- вердикт по пре-рег-правилу (per-doc p95 = 0.1480) остаётся
  `NO_LOOP_SPECIFIC_EFFECT` — правило не меняется задним числом;
- чтение результата — именно как в §4 ревью: «нет значимого специфического
  эффекта **относительно выбранного консервативного филлер-нуля и
  фиксированного разрешения δ**», а не «доказано отсутствие эффекта».
  Эта формулировка перенесена в results/ref-exp.

### 3.5 e_generic с другим нулём — **принято (пометка); отдельный нуль — не нужен для вердикта**

Согласен с диагнозом. Исправление: в claim `e_generic_note` — «exploratory/
диагностика: сравниваемый нуль (fillerA−fillerB) не тождествен собственному
нулю e_generic — эффект вставки не компенсируется». Против «строить отдельный
нуль fillerB−ctrl» — **спор-уточнение**: fillerB−ctrl измеряет тот же эффект
вставки (другим филлером) и служил бы нулём только для разделения
«вставка» vs «контент именно fillerA» — т.е. бы это новый (третий) контраст,
не калибровка текущего. Ветка GENERIC не сработала (max CI_low 0.1160 <
0.1480), отдельный нуль вердикт не меняет; оставляем пометку, не добавляем
объект (YAGNI, границы §10 TZ).

### 3.6 Ссылка на ответки не по адресу — **принято, исправлено**

Подтверждено: `docs/AT8_2_review_r1_answers.md` — ответки на оригинальный

### 3.7 Гейты в claim/manifest — **принято, исправлено**

### 2.1 (пул 16 vs 14, гейт 12/16 vs 11/14) — ПРИНЯТО с одной оспоренной формулировкой

Расхождение подтверждено: TZ §6 «16 доков (4×4)» vs фактический пул 14
(wiki 4 / math 2 / code 4 / chat 4 — из стора); гейт §8 «≥12 из 16» vs
`ceil(0.75·n_docs)` = 11/14 в коде; `DOMAINS_MIN=4`, `DOCS_MIN=12`, STOP
только при `<2`/домен; `inside_pass = 14/14` — оба гейта срабатывают.

**СПОР (по существу, не по форме):** тезис «**финальный вердикт стоит на
пуле, который финальное правило пула запрещает**» — неверен и не переносится
в документы. Финальное правило (машина r2): все 4 домена обязательны +
`len(passed) < 2 → SystemExit`. Фактический пул 4/2/4/4: math = 2 →
`2 < 2` — ложь, SystemExit не срабатывает; 4 домена ≥ 4 ✓; 14 ≥ 12 ✓.
Пулу **не запрещено** — он удовлетворяет финальному правилу. Демонстрация:
r1-прогон (182 форварда, 2596 s) выполнен ровно на этом пуле. Сам ревьюер
снимает часть тезиса в том же абзаце («k=2 допускается (<2 — стоп), fallback
работает»), но сильная фраза и цепочка-схема остаются в тексте — при
цитировании §2.1 их надо опускать. Реальные (и применённые) последствия:
(a) в документе были два пре-рега пула — синхронизированы (TZ §6/§8/§13/§15,
пометки superseded); (b) claim теперь самообъясняющий: `pool_rule` +
`pool_per_domain`.

### 2.2 (e_generic: статус + скан по дозам) — ПРИНЯТО

Подтверждено кодом: `mg = max(ci_low по всем дозам)` (F2 применён наполовину:
для e_spec первичная доза, для e_generic — скан) и e_generic управляет веткой
GENERIC (note «в вердикте используется e_spec» ложен — e_generic решает
GENERIC vs NO_LOOP при незначимом e_spec).

Выбран минимальный вариант: **`mg = gci[pn]["ci_low"]`** (первичная доза,
симметрично e_spec/F2) — а не вывод GENERIC из дерева (это изменение дерева,
а не его калибровка; оба варианта ревьюер допускал, выбрать до прогона —
выбрано, зафиксировано в TZ §22). `e_generic_note` переписан честно
(вторичный вердиктный контраст, нуль не калиброван, индикативно).
На текущем store max CI_low по дозам = primary = 0.116008 < δ 0.1480 —
ветка GENERIC не срабатывает ни в каком чтении, вердикт не меняется.

### 2.3 (n_fwd выводится, wall_s молчаливый None) — ПРИНЯТО
