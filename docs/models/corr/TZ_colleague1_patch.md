## А. Блокеры — нужен арбитраж архитекторов, до этого не имплементить

**А1. [III.9, II.10] `b_mag`: противоречие с зафиксированным определением.**
В протоколе архитекторов `b_mag = ‖Δz‖` (первая степень) зафиксирован как определение «не дискутировать». ТЗ коллеги 1: `b_mag = ‖Δz‖²`, первая степень запрещена. Одно из двух ложно.
Размерный аргумент — в пользу ТЗ коллеги 1: `b_res = b_mag − b_lin` требует одинаковых единиц, а `b_lin = ε²‖Jv‖²` — энергия; вычитать норму из энергии нельзя.
Действие: однострочный арбитраж (какая запись протокола каноническая). Блокировка локальная: `behavior.py` не нужен tier-0 (gate), остальные работы не стоят.

**А2. [IV.4, I.5] Тест тождества тройки нельзя объявлять EXPECTED FAIL без разделения.**
Тождество `frac_K = 1 − 2c + s²` — математика, и на прямых измерениях оно подтверждено (E39+, финальный раунд: `c ≈ 0.002`, `cos(J,PJ) ≈ 0.08`, `frac_K ≈ 0.997`, «совпадает с тождеством при правильной подстановке»). Несогласована именно опубликованная таблица `E39_supplement` §2.2.1 (агрегатная семантика; подстановка даёт s² < 0 на −0.0007…−0.0015) — с этим согласен, статус «не цитировать» правилен.
Разделить тест 4 на два:
- **T4a** — тождество на тройке, пересчитанной одной кодовой дорожкой из кэша: обязан быть зелёным. Красный → стоп-условие (числовая/кэш-ошибка), не «ожидаемо».
- **T4b** — кросс-проверка опубликованной таблицы §2.2.1 против тождества: ожидаемо красный, фиксируется как `deviations_from_spec` (D7) и питает текст §2.5.4 «Открытый вопрос».
Следствие: `frac_K(J,p)` как функция — разрешена (иначе E6 не разобрать); staged только цитирование кэш-значений в статье/ядре.

**А3. [I.1, I.10] Коллизия нумерации §2.5.1.**
E39+ §7 (закоммичено, консенсус) резервирует врезку про sentinel в §2.5 (предложение «§2.5.1 или врезка»). ТЗ коллеги 1 отдаёт §2.5.1 спектру P(p), а sentinel ставит в §2.5.6.
Действие: одна перенумерация за один проход: sentinel — первым (врезка или §2.5.1, текст уже согласован дословно в E39+ §7), подразделы P(p)/тождеств/разложения — после со сдвигом. Не оставлять исполнителю два конкурирующих §2.5.1.

## Б. Ошибки — поправить формулировку до входа в ref-math/код

**Б1. [I.1] Граница `λ_max ≤ p_max(1−p_max)` — ложна, противоречит собственному двухточечному пределу.**
Контрпримеры: p = uniform, K=3: λ_max = 1/K = 0.333 > p_max(1−p_max) = 2/9; p = (0.8, 0.1, 0.1): λ_max ≈ 0.24 > 0.16. Двухточечный случай (K=2) даёт λ_max = 2·p_max(1−p_max) — что сам ТЗ и пишет, т.е. общая граница не может быть `p_max(1−p_max)`.
Правдоподобная замена: `λ_max ≤ 2·p_max(1−p_max)` (в примерах выполняется, K=2 — насыщение). Но в ref-math включать только с выводом + численной проверкой по `secular_roots(p)` (сквозное правило: спектральные утверждения — через корни секулярного уравнения, не «по памяти»). Диапазон «≈ 0.09–0.18 при K=128» — тоже прогнать через `secular_roots`, не цитировать как данность.

**Б2. [II.2 `kappa_invariant`] Инвариант на ортогональном H вакуумен.**
`H = R₀₁R₁₂R₀₂⁻¹ ∈ O(r)` ⇒ все сингулярные числа равны 1 ⇒ `κ(H) = 1` тождественно, `κ(OᵀHO) = κ(H) = 1` — тест зелёный всегда и ничего не проверяет.
Заменить на два нетривиальных:
- `κ² = 2r − 2tr H = 4Σⱼ(1−cos θⱼ)` — два пути (ref-math, якорь: r=16, κ=0.018 ⇒ Σcosθⱼ = 7.999919);
- κ-инвариантность на грамианах: `κ(OᵀGO) = κ(G)` для ортогонального O (якорь: κ(EᵀE) = 1684, E-6b).

**Б3. [II.3, II.5, II.7 vs II.8, II.9] Дублирование существующих модулей — нарушает собственный §0 («не дублируют»).**
- `gauge_share` уже есть в `prism/spectral.py` (строки ~326, ~374) — из `p_algebra.py` импортировать, не переопределять. Пара O2/O3 остаётся: `g_uni` через суммы столбцов (p_algebra) vs `gauge_share` спектра (spectral) — это и есть двухпутевая проверка.
- `holonomy()`, `holonomy_spectrum()` в новом `transport.py` дублируют существующий `prism/holonomy.py`. В `transport.py` оставить только `align_signs_and_columns`, `procrustes_transport`, флаги; `holonomy.py` импортирует align.
- `permutation_test` в `nulls_and_stats.py` пересекается с `permutation_max_statistic`/`generate_null` в `prism/permutation.py` — сверить покрытие, не плодить третий пермутационный тест.
- `c, s, cos, frac_K` заявлены одновременно в `operator_checks.py` (II.7) и `cheap_invariants.py` (II.8). Один дом: `operator_checks.py`; `cheap_invariants` только вызывает и кормит реестр.

**Б4. [II.2] Захардкоженные `"status": "passing"` обесценивают реестр.**
Все 14 записей поставляются со статусом passing в исходнике — тогда реестр декоративен, и «смена статуса — событие» нечему отслеживать. Статус при объявлении — `unverified`; выставляется только прогоном; в артефакт пишется фактический статус + timestamp + входы. Также `O1_eq_s2` с комментарием «может failing» — статус не комментарий, а результат прогона на указанных входах.

**Б5. [II.9 `resolution_floor`] Подмена зафиксированного метода флора.**
В репо флор зафиксирован: `1.253·IQR/√n` из сохранённых per-doc IQR (A5, `exp40_1_audit.py::_floor`), и вердикты A5 («testable/not_testable» по слоям) получены им. `resolution_floor` через subsamples=[8,16,32] — другой метод; замена молча делает вердикты несравнимыми с A5. Действие: вердикты — только по зафиксированному флору; subsample-вариант — отдельное доп. поле, не замена.

**Б6. [II.2 `O2_eq_O3`] Допуск ослаблен против протокола.**
ТЗ: rel < 1e-12. Протокол: 7.7e-16 (abs, fp64, ulp-уровень). rel 1e-12 при g_uni ≈ 0.13–0.22 — это ~1e-13 abs, т.е. в ~1000 раз мягче; красное на fp32 пройдёт как зелёное. Фиксировать: fp64, 7.7e-16 abs; в fp32 тест обязан быть красным (это фича, проверяющая точность дорожки).

**Б7. [III.11, IV.6] MP-скобки и MP-калибровка — без вывода и без объекта.**
«p=6 (6×6): λ+ = 2.05/1.38; p=8: 2.25/1.45» — для квадратного аспекта классический край ≈ 4; числа без определения (что за матрица, что за нормировка, какая ветка) в ref-math не включать. Тест «MP-калибровка: Монте-Карло гауссовского нуля» не специфицирует нуль-объект. Действие: либо развернуть до формулы+вывода+MC-проверки, либо вынести из ТЗ в отдельный вопрос. Сквозное правило (Правило 0): новая формула в ref-math — только с выводом или численной проверкой.

**Б8. [II.9] Имена нулей: не плодить третий синоним.**
`content-matched-null` ТЗ = dir-null из E-39+ (перестановка при сохранённых нормах строк, сравнение O1_rel_dir vs O1_rel_real). Третье имя для того же объекта повторяет болезнь r_eff/real-dir. Оставить имя `dir_null`, в скобках при первом упоминании — «content-matched».

## В. Дополнения — в ТЗ отсутствует, но по состоянию репо обязательно

**В1. Эксперименты яруса — ТЗ коллеги останавливается на модулях и тестах.**
- **A4-gate:** определить p-срез спектров E-27.5/27.6 (`S64K64p0` — намёк, не доказательство) до E-40.2 — прямое требование `results/E40_1_audit.json` (`gate_open_items_for_E40_2`). Минуты, ноль форвардов. Без этого E-40.2 не стартует.
- **E-41 + E-40.1(m):** второй кэш J на `Qwen/Qwen3.5-4B` (профильщик exp27b умеет: `resolve_model("Qwen/Qwen3.5-4B")`; ~13 ГБ, отдельный Kaggle-прогон) и затем real/dir по пререгистрации — вердикты (m1)/(m2) дословно из `docs/E40_tier0.md`, интервал 0.62–0.69 и правило «не перекрылся CI → слово „инвариант“ не употребляем» менять нельзя. Это текущий фронт репо, а не опция.
- Статус «прогоняются в E-40.1» (IV) уточнить: E-40.1-аудит уже выполнен (A1–A5); тесты ядра — регрессия для всех E-40.x.

**В2. Статья: пропущены обязательные правки по консенсусу E-39+.**
Помимо новых подразделов ТЗ коллеги: (а) врезка sentinel в §2.5 — текст готов дословно в E39+ §7 (числа 0.5071 = 2077/4096; Σp² 0.415 vs 0.557); (б) коррекционная волна: c ≈ 0.002 (не 0.5), cos(J,PJ) = 0.064–0.108, бимодальности нет (mean 0.996–0.998 ≈ median), направление dir-null на L23 перевёрнуто (1.099 = убивает слабее), две категории ошибок (units ≠ category; правила 19/20 раздельно; 23 = генерализация 19/20/22, не 21), real/dir = 0.623–0.692 — «surprising constant on content axis» (ни инвариант, ни компенсация), модель `(1−g_uni)^α` мертва (α = 1.64–3.13), контроль iid per domain = 1.000 ± 0.002; (в) индексация `r_eff^ESG` vs `r_eff^U(τ)` по всему тексту.

**В3. [II.1] `p_provenance` — две ортогональные оси, и в ТЗ закрыта только одна.**
ТЗ коллеги: {truncated_U128, full_softmax, other} — это ось «режим распределения». Открытый пункт A4 — про другую ось: **какой срез p** использован: `p_slice ∈ {"p_t", "p_0"}` (per-position vs fixP). Нужны обе: `p_slice` (identity-relevant, сравнения только внутри одного значения) и `p_mode`. Значение `other` убрать: неизвестный режим — это стоп-репорт, а не легальный тег (иначе «третье значение» всегда легально и стоп-условие мертво). В tier-0 артефактах `p_mode` обязан быть `truncated_U128` — появление full_softmax = смешение срезов, стоп.

**В4. [II.6] Для ΔJ-каналов зафиксировать срез.**
`ΔJ = J_{t+1} − J_t` имеет смысл только внутри одного среза: raw−raw, gf−gf, fixP−fixP **с одним и тем же p_0** (для среза `p_t` на позициях t и t+1 это разные операторы P — разность бессмысленна). Срез и p_0 — в ChannelTag результата; проверка — дешёвый инвариант перед декомпозицией.

**В5. Дисциплина и стоп-политика (в ТЗ коллеги нет).**
- Отклонение артефакта от карточки/статьи → `deviations_from_spec` (D7), правится карточка по артефакту, не наоборот (урок A2: «Δ_gain = 0.404…» невоспроизводим ни в одном JSON).
- Стоп-условия: тождество реестра красное на реальном кэше (не в тестовой среде) → стоп; доля `unstable_transport` > 5% → стоп; третье значение p_slice/p_mode → стоп. Допуск не ослаблять.
- Вердикты: эффект < флора → `not_testable`, никогда `refuted` (D4).
- Границы PLAN.md: не трогать `docs/paper_add.md`, `docs/E39.md`; кэш exp27b read-only; числа-якоря не пересчитывать без причины.
- Техника: алгебра — fp64 (модель — fp32/eager по ref-impl); сериализация через `json_utils` (κ→inf писать null+флаг — JSON не держит inf); файлы экспериментов — стиль `exp40_1_audit.py` (`main(results_dir) -> dict`, поля `observational`, `new_forwards`).

**В6. [I.10] Sentinel: для tier-0 порог 0.5 сохранить.**
Кривая массы/ковариата — хорошее дополнение, но замена порога меняет операциональное определение sentinel, на котором посчитаны все коммитнутые числа (E-34, E-33r, E-39k: 50.7%, Σp² 0.415/0.557) — это скрытый re-basing всего яруса. В tier-0: порог 0.5 как был; кривая массы — дополнительное поле артефакта. Смена определения — отдельное пререгистрированное решение после яруса.

**В7. [IV] Добавить недостающие тесты.**
- Stiefel для связок: `‖UᵀU−I‖`, `‖VᵀV−I‖` ≤ 1e-9 (инвариант `H·Hᵀ=I` в ТЗ — только для квадратной голономии; для K×r базовых матриц проверять именно `UᵀU`).
- Детерминизм знаков/порядка столбцов SVD: повторный вызов на тех же данных — бит в бит (иначе транспорт сравнивает разные базисы молча).
- Вырожденный p (однозначный, p_max → 1): P → 0, все относительные инварианты делят на ноль — ветка с абсолютным допуском/помеченным пропуском, не исключение.
- Клип аргумента acos в метрике E-28 (`acos(min svdval(VₐᵀV_b))`, домен [-1,1]).
- JSON round-trip артефактов с tag (включая inf→null) и запрет третьего значения p_slice.
