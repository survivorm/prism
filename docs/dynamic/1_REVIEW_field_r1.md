## 1. Замечания (код)

### N1. BUG: `gram_r` в `__all__` не определён — :23
`__all__ = [..., "rho_t", "gram_r", "f_dc", ...]` — функции `gram_r` нигде нет (grep по
репо: только упоминания `gram_resid` в ТЗ). `from prism.field import gram_r` и
`from prism.field import *` падают с ImportError. Мёртвое имя — правило #9 (вычищать в том же
коммите). AT0_1 не использует (импортирует 9 имён без gram_r) — удаляем без последствий.

### N2. BUG: `jclean` — python `bool` сериализуется как 0/1, `np.bool_` — как true/false — :151-153
Ветка `isinstance(o, (np.integer, int))` (**:151**) стоит раньше `isinstance(o, (np.bool_, bool))`
(**:153**); `bool ⊂ int` в Python. Подтверждено прогоном:
`json.dumps(jclean({"a": True, "b": np.bool_(True), "c": False}))` → `{"a": 1, "b": true, "c": 0}`.
Двойная семантика для одного типа + неверный тип в JSON (1 ≠ true). Затрагивает claim-JSON AT0_1:
`gates["G2_ok"]`, `G10.ok`, `degen_tz`, `loopy_ladder`, `anchor_ok`, `consistent` — все python bool.
В Python-читателях `1 == True` маскирует; в JS/прочих инструментах — нет. **Фикс:** перенести
bool-ветку выше int-ветки (одна строка).

### N3. BUG (trap): `rho_t(P, 0)` / `dcurve(k=0)` — краш с неинформативной ошибкой — :53
`Pn[:-0]` → пустой массив → `einsum` падает `ValueError: operands could not be broadcast
together with remapped shapes: (0,4)->(0,4) (10,4)->(10,4)`. Для канонического прибора это
не «fail-loud», а тупик. Потребители охраняют k≥1, но прибор обязан либо вернуть
`ones(T)` (k=0 — косинус с самим собой), либо падать с явным сообщением. **Фикс:** guard
`if k == 0: return np.ones(len(Pn))` (и/или `if k >= len(Pn): raise/empty явно`).

### N4. DOC/SEM: `degen` — порог `>= 0.95` (:139) против LADDER_V2 strict `> 0.95`
LADDER_V2 (exp90_ladder_v2.py:41): `if float(np.max(real[nm][1:])) > 0.95: loopy.add(nm)`.
Код — `m >= 0.95`; docstring :134 пишет «реализация как в LADDER_V2 для якоря» — на границе
это ложь. Подтверждено: `degen(np.array([-0.07, 0.95, 0.5]), [])` → `(True, 0.95, 0.0)`,
LADDER такого дока не считает loopy. Код **соответствует ТЗ §0.3** (там `>= 0.95`), т.е. спор
не «код vs ТЗ», а (а) неточность docstring-претензии на LADDER-эквивалентность и (б) расхождение
AT0_1 `loopy_ladder` (`>=`, AT0_1:157) с LADDER (`>`) — при m = 0.95 ровно набор anchor-доков
отличается. Вероятность точной 0.95 ≈ 0, но для якоря с «поведение обязан совпадать» —
закрепить одну семантику и поправить docstring/комментарий (что ТЗ и LADDER расходятся
на границе, и какая побеждает).

### N5. MINOR: `acf_moments` — тихое усечение при K > N−1 — :74-81
`cfull[:K]` при K=10, N=5 молча возвращает длину 4 (подтверждено). K ≤ 0 → пустые
массивы без ошибки. Потребитель (AT0_1: `Kmax = min(K, n-1)`) охраняет, но канонический
прибор не должен молча менять форму результата. **Фикс:** `if not (0 < K <= N-1): raise
ValueError(...)` (K=0 — явный выбор пустого результата? задокументировать).

### N6. MINOR: `f_dc` — fail-soft 0.0 на нулевом объекте (:90) против fail-loud `acf_moments` (:71-72)
`acf_moments` на c0 ≤ 0 бросает ValueError; `f_dc` на mean_n2 == 0 молча возвращает 0.0 —
а 0.0 для f_DC легитимно значимое число (DC-доля ноль). Несогласованность политик. **Фикс:**
raise, как в acf_moments.

### N7. GAP: T−k-нормировка недоступна из прибора (ТЗ §1.4-1 «Обе отчитывать»)
field.py отдаёт только T-нормированное ρ̂ = c(k)/c(0); знаменатель по лагам
d(k) = Σ_{t=0}^{N−1−k}‖x_t‖² не возвращается, и точный T−k-ρ̂ из вывода прибора не
реконструируется. Последствие уже видно у потребителя: AT0_1 П4 «taper-corrected» plateau
`= rho[k]/(1−k/N)` — это **точное T−k-нормирование только для unit-объектов** (v_tangent);
для h_raw и du_unit (нормы переменные — ровно случай, который ТЗ §1.3 G2/§1.4-1 выделяет:
«знаменатель взвешен нормами») это приближение, а не нормировка. **Фикс (1 строка в
acf_moments):** `e = np.einsum("ij,ij->i", x,x); d = np.cumsum(e)[:-1]; out["rho_Tk"] =
cfull/d` (d[k−1] = Σ_{t<N−k}‖x_t‖²), добавить в docstring. Тогда AT0_1 П4 может брать
точный T−k для всех трёх объектов.

### N8. DOC: контракты входов не записаны — `ra_split` :93, `acf_moments` :61
`vpath` явно говорит «u — unit-состояния»; `ra_split` нормализует u молча (`_unit`) и не
говорит, что ожидает unit + нормы; `acf_moments` — (N,D) без 1-D. Однострочные docstring-правки.

### N9. COVERAGE: selfcheck не ловит N1–N3
В `_selfcheck` нет: round-trip jclean (bool), rho_t(k=0), degen-границы, cross_acf, импорта
через `__all__`. Н1–N3 — ровно тот класс «мелочей», который самопроверка обязана закрывать.
Добавить 4-5 строк assert'ов.
