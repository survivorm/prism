## 1. Одна строка и вопрос

R2-вердикт `NO_LOOP_SPECIFIC_EFFECT` (machine r2d) bounds контраст
`e_spec = loop − fillerA`, который одновременно несёт **«запоминаемое vs
новое»** И **«повторение vs не-повторение»** (TZ R2 §10, r2d-1.1). 2b
разделяет эти гипотезы вторым стимулом — **другой** фразой, повторённой n
раз, и факторным дизайном, где каждый канал меряется контрастом со своим
нулём:

- **H_phr (фраза-канал):** *контент повторяемой фразы* создаёт пост-
  эффект **в повторённой строке** — «запоминание именно этой фразы»,
  т.е. контентное различие L1 vs L2 (простой эффект `E_phr = L1 − L2`
  на периодических строках) превышает шкалу контентного различия
  shuffled-строк (`N_PHR`). **Bag-of-words режим (важен мешок токенов,
  порядок нет) — НЕ H_phr:** в нём `E_phr` и `N_PHR` одной шкалы → тест
  не срабатывает (синтетика 7).
- **H_rep (повторение-канал):** *периодический порядок* при **том же
  лексическом составе** (случайный порядок того же мультисета) создаёт
  пост-эффект.

Вопрос: какой из каналов (ни один / один / оба) несёт специфический
локальный пост-эффект поля при разрешении филлер-вариативности (нули из
shuffled-условий, §8)?

## 2. Главный сдвиг дизайна (от R2 и от 2b v1.0–v1.2)

- **Вердиктные количества (M1):** `E_phr := L1 − L2` (простой эффект на
  периодических строках; = PHR_main + INT) против `δ_PHR`; `REP :=
  (L1+L2−S1−S2)/2` (главный эффект периодичности) против `δ_REP`.
  PHR_main = D_L + D_S (контент в среднем по строкам) — **диагностика**.
- **Нули:** `N_PHR := S1' − S2'` (терм-непересекающийся с {L1,L2});
  `N_perm := (S1+S2−S1'−S2')/2` (сматчен: Var = σ_S² = Var(REP) при
  σ_L=σ_S; отрицательная корреляция со статистикой через общие S1,S2 —
  высокий draw-уровень S-строк снижает и статистику, и порог).
- **Per-doc shuffle-сиды** (F1/r3-m1): `zlib.crc32(f"S{i}|{doc}|{n}")`
  — имя дока в стринге, без коллизий; draw-дисперсия в doc-bootstrap
  (прецедент AT2d-B1).
- **Дозы: n ∈ {2, 16}** (E_phr primary n=2 — контент жив; REP primary
  n=16 — максимальная доза периодичности; n=4/8 не гоняются — R2-плато).
- **R2-store заморожен и переиспользуется**: ctrl, loop1, fillerA,
  fillerB — read-only из `results/AT8/AT8_2_R2_store.json` (sha §10) на
  n=2 и n=16.
- Новые форварды: **5 условий × 14 доков × 2 дозы = 140** (R2: 182).
- Вердикт-машина R2 (per-doc δ, CI-правила, finite-гейт, doc-bootstrap) —
  сохраняется; меняются контрасты, нули, дозы, наблюдаемые, гейты, дерево
  (§11).

## 3. Стимулы

- **loop1 (зафиксирован R2):** `" The class will be held at the park."` —
  `PHRASE1_IDS = [561, 523, 668, 381, 5467, 506, 279, 5926, 13]` (9 токенов;
  13 = «.»).
- **loop2 (новый, зафиксирован пре-регом v1.0, без изменений):**
  `" Three new buses wait near a quiet station."` —
  `PHRASE2_IDS = [14095, 491, 32275, 3655, 3043, 264, 11012, 7803, 13]`
  (9 токенов; верифицировано токенизатором Qwen3.5-0.8B; пересечение
  контент-токенов с phrase1 = ∅, общий только 13 «.»).
- **Shuffled-условия (новые, зафиксированы ЭТИМ пре-регом):**
  - `L_i(n)` = токен-последовательность `PHRASE_i_IDS × n` (длина
    `L_n = 9n`);
  - `S_i(n, doc)` = `L_i(n)[π_{i,doc,n}]`, где
    **`π_{i,doc,n} = default_rng(zlib.crc32(f"S{i}|{doc}|{n}".encode())).
    permutation(L_n)`** — **детерминированная per-doc перестановка** (F1).
    i ∈ {1,2,3,4} = (S1, S2, S1', S2'); `doc` = имя дока из таблицы §4
    (в сид-стринге — m2: индексу не нужна); `n` в стринге — явная
    независимость доз. **Полные 32 бита crc32, БЕЗ `% 99991`** (G17:
    `% 99991` в идиомах репо — для малых пространств; 112 сидов в
    99991 → P(≥1 коллизия) ≈ 6.2%, в 32 битах ≈ 1.5e-6). Старая v1.2-
    формула `10000·i + 1000·doc_idx + n` имела коллизию
    S1(doc10) ≡ S2(doc0) @ n=2 (= 20002; доки 10–13 между смежными i) —
    устранена.
    **Мультисет, длина, позиции — те же; сломан весь порядок (включая
    биграммы), периодичность в первую очередь.**
  - `S1'(n, doc)` — второй независимый draw от `L1(n, doc)` (i=3);
    `S2'(n, doc)` — второй независимый draw от `L2(n, doc)` (i=4).
- **Estimand REP (m3-r2, без изменений):** «**периодический порядок vs
  случайный порядок при том же мультисете**» — НЕ «повторение vs
  отсутствие повторения»: shuffled-блок сам повторяющийся (ожидаемое
  число смежных пар: n=2 → ≈1.0, n=16 → ≈15.0). `REPETITION_SPECIFIC`
  читается как «канал упорядоченности/периодичности». Сужение до
  «именно период-9» требует арма с другим периодом при том же мультисете
  ((p1+p2)×(n/2), +28 фд) — **follow-up, не в этом прогоне**.
- **Алгебра 2×2 (зафиксирована, M1; D_L = (L1−L2)/2, D_S = (S1−S2)/2,
  m_L = (L1+L2)/2, m_S = (S1+S2)/2):** `E_phr = 2D_L`, `REP = m_L − m_S`,
  `INT = D_L − D_S`, `PHR_main = D_L + D_S = E_phr/2 − INT`,
  `N_content := S1 − S2 = PHR_main − INT` (тождество, legacy-диагностика).
  Терм-непересекаемость: `{L1,L2}` (E_phr) vs `{S1',S2'}` (N_PHR) ✓.
- **Критерии phrase2** — как в v1.0 (форма, не CE/эффект; обучаемость —
  диагностика §9).
- **S_stimulus (fail-loud):** `L_n = 9n` для L1/L2/S1/S2/S1'/S2';
  `assert tk(PHRASE_i) == PHRASE_i_IDS`; **multiset-check**:
  `sorted(S_i) == sorted(L_i)` для всех (i, doc, n) (assert в
  `run_main`; `phrase_token_check`/`shuffle_multiset_check` в
  claim/манифесте).
- **S_shuffle — bug-guard** (m7: fail-loud assert, НЕ «диагностика»):
  (а) период-9-чек `¬∀k: S[k] == S[k+9]` (защита от бага
  перестановки; с per-draw перестановками вероятность прохода
  астрономически мала); (б) max count любой 9-граммы в окне `[0, 9n)` —
  **per-(S_i, doc, n) таблица в артефакте** (отчёт).
  - **Филлеры вне вердиктного пути 2b** (явно, m1/F3б): проверка
    специфичности филлеров — только R2's «нет конкретной фразы»,
    унаследована через R2-store integrity (sha-пин, §10); 8_3-проверка
    9-грамм для филлеров к 2b неприменима.

## 7. Условия и контрасты

### 7.1 Условия

На (док, n∈{2,16}): `ctrl`, `L1`, `L2`, `S1`, `S2`, `S1'`, `S2'`,
`fillerA`, `fillerB` — 4 из R2-store (ctrl, L1, fillerA, fillerB), 5 новых
(L2, S1, S2, S1', S2').

### 7.2 Вердиктные контрасты и нули

```
E_phr := L1 − L2                    (H_phr: простой эффект на
                                    повторённых строках; = 2·D_L)
REP   := (L1 + L2 − S1 − S2)/2      (H_rep: главный эффект периодичности)
INT   := (L1 − S1 − L2 + S2)/2      (= D_L − D_S; report-only + тег)

N_PHR  := S1' − S2'                (нуль E_phr; терм-непересекающийся
                                    с {L1,L2}; не схлопывается —
                                    draw-шум > 0)
N_perm := (S1 + S2 − S1' − S2')/2  (нуль REP; Var = σ_S² = Var(REP)
                                    при σ_L=σ_S; отрицательная корреляция
                                    со статистикой через S1,S2 — draw-
                                    робустность)
```

- **σ_L/σ_S (m3-r3, P0 r3 из R2-store, L23):** пороги строится с S-строк;
  если σ_L > σ_S — анти-консервативно для обоих контрастов. Замерено:
  across-doc SD-отношение SD(e_spec)/SD(e_null) = **0.756** (n2 cos_raw) /
  **1.220** (n2 norm_delta) / **1.023** (n16 cos_raw) / **1.470** (n16
  norm_delta) — не «≫»; для E_phr: ×1.22; частично покрывается p95-
  маржином (порог — 95-й перцентиль near нуля, не среднее). Чек — прокси
  (e_spec смешивает вариацию филлера): граница, не доказательство.
- **INT:** нуля нет; report-only + тег `INTERACT_SIGNIFICANT` (значимый
  INT на первичной дозе = контентный эффект row-type-зависим: D_L ≠ D_S;
  направление — по signed near в claim).
- **PHR_main = D_L + D_S → диагностика** (M1: включает bag-of-words
  режим — «контент в среднем по строкам», не H_phr).
- **N_content = S1 − S2 = PHR_main − INT (тождество) → legacy/
  диагностика** (нуль содержит собственные термы PHR_main).
- **Диагностика (R2-сравниваемость, в вердикт не идут):**

```
e_spec1 = L1 − fillerA               (R2, заморожен — e_spec R2)
e_spec2 = L2 − fillerB               (новый)
e_null  = fillerA − fillerB          (R2, заморожен)
e_rep_legacy = (e_spec1 + e_spec2)/2 (v1.0-определение)
(S1 − S1')  (старый N_perm, 2σ_S² — 1.41× переконсервативен)
PHR_main, N_content
```

- **Шов (M1-R2) — диагностика для L2** (как v1.1): `seam2(n) =
  cos_raw_L2[cut+L_n−1] − cos_raw_fillerB[cut+L_n−1]` (R2: −0.055…−0.081).

## 8. Разрешение δ (C1: привязка к наблюдаемой; M4: проверенный пул)

**Каждый порог — только на наблюдаемой своего контраста:**

```
E_phr: near_phr_i,n  = p90 |N_PHR_i,n(d)| (norm_delta),   d ∈ [0,15]
       far_phr_i,n   = mean |N_PHR_i,n(d)| (norm_delta),  d ∈ [48,63]
       δ_PHR    = 95th pct {near_phr_i,n}   (28 значений: 14 док × 2 дозы)
       δ_far_PHR = 95th pct {far_phr_i,n}

REP:   near_rep_i,n  = p90 |N_perm_i,n(d)| (cos_raw),     d ∈ [0,15]
       far_rep_i,n   = mean |N_perm_i,n(d)| (cos_raw),    d ∈ [48,63]
       δ_REP    = 95th pct {near_rep_i,n}   (28 значений)
       δ_far_REP = 95th pct {far_rep_i,n}

Смешанные наблюдаемые (статистика на norm_delta, δ на cos_raw или
наоборот) = жёсткий флиппер (P0 r2: near 0.8681 vs δ 0.1526, ×5.7;
под H0 S_phr срабатывает всегда) — запрещено.
```

- **Пулинг по дозам — проверенное допущение на ОБЕИХ наблюдаемых**
  (M4, P0 r3 из R2-store, L23):

  | наблюдаемая | p95 n2 | p95 n16 | ratio | pooled(28) | vs per-dose |
  |---|---|---|---|---|---|
  | cos_raw | 0.1526 | 0.1328 | 1.149 (n2 ↑) | 0.1533 | +0.5% / −13.3% |
  | norm_delta | 1.1590 | 1.5668 | **1.352** (n16 ↑) | 1.4897 | **+28.5% / −4.9%** |

  Оба ratio < 1.5 → пул остаётся; направление разное (cos_raw: n2 выше;
  norm_delta: n16 выше); pooled ≥ min(per-dose) всегда.
- Вычисляются 2b-машиной **из новых форвардов** (S1, S1', S2, S2') —
  единый пайплайн. `δ_min` неконечен/нулевой → NOT_RESOLVED (гейт S_null).
- **Integrity-якорь (fail-loud, m2-r2):** пересчёт legacy-δ (e_null,
  cos_raw) из R2-store — **по ВСЕМ 4 дозам, R2-пайплайн verbatim**
  (14 док × 4 = 56 значений), **независимо от дозового списка 2b** [2,16]
  (P0: по 2 дозам = 0.1533/0.0306 — ложный STOP-ловушка). Ожидаемо
  bit-идентично R2: **0.1480 / 0.0332**; отклонение > 1e-6 → стоп
  (store повреждён/подменён). Это проверка пайплайна, **не** порог
  вердикта.

## 10. Гейты (до вердикта)

1. **R2-store integrity (главный):** sha256
   `results/AT8/AT8_2_R2_store.json` == **`78419a69a2edbc767248b3a8f9512e19
   61ea82c154970772c66c35e2a42b16c0`**; `__config__`-fingerprint (model,
   layers, n_dose, phrase_ids, docs_sha256, pool_fps, H) == константы 2b;
   `n_docs=14`, 4 домена, ≥2/домен. Провал → стоп (SystemExit), не
   NOT_RESOLVED.
2. **S_stimulus:** phrase_token_check (оба), shuffle_multiset_check
   (S1/S2/S1'/S2', per doc), L_n = 9n, конечность. Fail-loud.
3. **S_shuffle — bug-guard** (m7): период-9-чек (а) — fail-loud assert
   (защита от бага перестановки); (б) per-(S_i, doc, n) таблица max
   9-gram-count — в артефакт. **Не «диагностика»** — гейт; филлеры вне
   вердиктного пути (§3).
4. **Finite-гейт (M5):** ce + cos_raw/cos_state/norm_delta по всем
   условиям × слоям (новые — полный; R2-условия — spot-проверка) + все
   контрасты (2 вердиктных + 2 нуля + 7 legacy/диагностика). Провал →
   NOT_RESOLVED.
5. **G_inside_rep (F3 — положительный контроль вердиктного пути):**
   per doc: `CE(L1 block) < CE(S1 block)` И `CE(L2 block) < CE(S2 block)`
   (тот же мультисет, та же длина, сломан только порядок — если модель не
   видит порядок **внутри** блока, ждать пост-эффекта неоткуда). На
   **обеих** первичных дозах (n=2, n=16); гейт: ≥ `ceil(0.75 × 14) = 11`
   доков на дозу; margin `(CE_S − CE_L)` per doc в отчёт. Провал на дозе →
   контраст этой дозы **нерешён** (тег `GATE_N2`/`GATE_N16`); провал на
   обеих → `INSENSITIVE_CELL`.
6. **G_inside_legacy (диагностика):** старый v1.1 filler-гейт (n=16,

   e_spec1/e_spec2, гейт-роли не имеет.
7. **S_null:** δ_PHR, δ_REP (и δ_far_*) конечны (> 0), §8.

### Дерево вердикта (порядок жёсткий)

```

   [integrity/S_stimulus → стоп].

3. Вердиктная клетка (L23; ровно 2 теста — поверхность зафиксирована):
   S_phr := CI_low(near_{E_phr}(n=2), norm_delta) > δ_PHR
   S_rep := CI_low(near_REP(n=16), cos_raw)       > δ_REP

     S_phr ∧ S_rep → BOTH_SPECIFIC (+substructure каждого)

   CI_low(C_far) > δ_far(C)                                  → _PERSISTS

5. INT (отчёт, не вердикт; первичная доза n=2, norm_delta):
```

## 17. Пререг-чтения исходов

- `NO_2B_SPECIFIC_EFFECT` — R2-`NO_LOOP` усиливается: **оба канала
  протестированы** (M2): ни контент повторённой фразы (на n=2, где
  контент жив), ни периодичность (на n=16) не создают пост-эффекта сверх
  shuffled-нулей (на пре-рег-разрешении; отсутствие не доказано —
  конвенция r2d-1.5).
- `PHRASE_SPECIFIC` — канал: **контентное различие повторённой фразы
  (L1 vs L2, периодические строки) превышает шкалу контентного различия
  shuffled-строк — запоминание именно этой фразы** (M1: bag-of-words
  режим исключён — там шкалы совпадают, синтетика 7). Тег
  `INTERACT_SIGNIFICANT` (INT на n=2 значим) уточняет: эффект
  repetition-specific (D_L ≫ D_S). Без тега (INT ≈ 0) — чтение «контент
  (bag) эффект, порядок не установлен» (residual type-I, α ≈ 0.025).
  Согласуется с ответом архитектора «после ~2 повторов фраза выучена»
  (block CE 0.38–0.51) — CE внутри блока ≠ пост-эффект; теперь разделены
  (и меряются на дозе, где контент ещё жив).
- `REPETITION_SPECIFIC` — канал: **упорядоченность/периодичность** при
  том же мультисете (m3-r2: не «повторение как таковое»).
- `BOTH_SPECIFIC` — два канала; substructure каждого — в claim.
- `INTERACT_SIGNIFICANT` — контентный эффект row-type-зависим (D_L ≠ D_S;
  направление — по signed near в claim): вердикт читается с этой
  оговоркой.
- `NOT_RESOLVED + GATE_N2/N16` — канал не протестирован (гейт провален);
  отсутствие измерения — не свидетельство отсутствия (M2).
- `LEARN_ASYMM` — phrase2 обучается иначе phrase1 (block-CE ratio > 3×):
  E_phr читается с оговоркой «содержимое + обучаемость».
