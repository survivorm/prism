## Цель и идеология

Измерить второй порядок readout по `h_l` и определить, добавляет ли нелинейность cross-talk сверх первого. E-32 закрывает Ставку №2 в сильной форме (кривизна readout = RMSNorm, подтверждено на L23) и уточняет P1 вторым порядком. Идеология: первый порядок E-32 тавтологичен (воспроизводит ESG), поэтому содержательный сигнал — отклонение от ESG в полном нелинейном форварде.

## Математика (сверх paper.md)

**Разложение Тейлора.** Инъекция `δ_i = ε · J_lᵀ e_i / ‖J_lᵀ e_i‖` — **нормированная**: `‖δ_i‖ = ε` для всех токенов, `s_l` не смесь доз; соответствует `ε = ‖δ‖` в E-12a. Разложение логита `j`:

`z_j(h + δ_i) − z_j(h) = ε · (ESG_l)_{ji} / √((ESG_l)_{ii}) + (ε²/2) · (J_lᵀ e_i)ᵀ H_j (J_lᵀ e_i) / (ESG_l)_{ii} + O(ε³)`

Нормировка делителя: `δ_i = ε·J_lᵀ e_i / ‖J_lᵀ e_i‖` — **нормированная**, `‖J_lᵀ e_i‖² = (ESG_l)_{ii}`; без знаменателей оба члена были бы записаны для ненормированной `δ_i = ε·J_lᵀ e_i` и противоречили бы определению (токены входили бы с разными эффективными дозами `ε·√((ESG_l)_{ii})`).

где `H_j = ∂²z_j/∂h_l² ∈ R^{D×D}` — Гессиан логита `j` по `h_l`.

**Сырой отклик и нормировка.** Определяем `Δz_j(ε)` — эмпирически из полного форварда. Фит:

`Δz_j(ε) = a·ε + b·ε² + c·ε³ + O(ε⁴)`,

где `a_ji = (ESG_l)_{ji} / √((ESG_l)_{ii})` (первый порядок, нормированный), `b_ji = (1/2)·(J_lᵀ e_i)ᵀ H_j (J_lᵀ e_i) / (ESG_l)_{ii}` (второй порядок, нормированный).

**Матрицы.** `a` и `b` — `K × K`, индексированы `(j, i)`. Диагональ `a_ii = ||J_i||²` — self-response; диагональ `b_ii` — вторая производная self-response.

**Безразмерный скаляр.** `s_l = ε · ‖offdiag(b)‖_F / ‖offdiag(ESG_l)‖_F` на рабочей точке `ε_canon = 0.15·‖h‖` (нижняя треть диапазона E-12a, 14–53% — ближе к нижней границе, чем к середине: нелинейности уже видны, Тейлор ещё адекватен). Первый порядок вклада — `ε·‖offdiag(ESG)‖`, второй — `ε²·‖offdiag(b)‖`. Их отношение и есть `s_l`. Sweep `ε ∈ {5%, 15%, 30%, 50%, 70%}` — только для диагностики режима (остатки, `Δz/ε` vs `ε`), не для `s_l`.

**Решающее правило.**
- `s_l ≪ 1` — readout практически линеен в рабочей точке, P1-защита независима.
- `s_l ~ 1` — нелинейность сравнима с линейностью, P1 должна учитывать cross-talk.
- `s_l ≫ 1` — readout существенно нелинеен, линейная защита некорректна.

**Диагностика режима.** График `Δz/ε` против `ε` — линейный, если доминирует второй порядок. Излом = выход из квадратичного режима. Остатки кубического фита: если случайны — второй порядок реален; если систематически растут — упёрлись в радиус сходимости.

**Чёт/нечёт остатков.**

- На L23: `û^T(J^T e_i) = 0` (по построению RMSNorm). Линейный член `2ε⟨û, v⟩/‖h‖` в разложении `1/r` обнуляется, `1/r` — чётная функция `ε`, высшие члены **чётные**. Симметричные остатки — норма.
- На промежуточных слоях: `⟨û_l, J_l^T e_i⟩ ≠ 0` в общем случае. Остатки могут быть антисимметричны без «третьего порядка». Чёт/нечёт — **вторичный** диагностик.

## Подводные камни

1. **Тавтологичность первого порядка.** `a_ji` воспроизводит `ESG_l`. Содержательный сигнал — только `b` и `c`. Не интерпретировать `a` как «новый результат».
2. **Нормировка.** Не смешивать конвенции `R_full = Δz` (вычитать `ε·ESG`) и `R_full = Δz/ε` (вычитать `ESG`). Фит по `ε` снимает путаницу — предпочтительный способ.
3. **Нормировка инъекции (фикс).** С нормировкой `δ_i = ε·J_lᵀ e_i / ‖J_lᵀ e_i‖` — `‖δ_i‖ = ε` для всех токенов; смешения доз нет. Без нормировки `‖δ_i‖ = ε·√((ESG_l)_ii)` зависит от токена — не использовать.
4. **Инъекция только в `h` последнего токена.** По `jacobian.py` `_run_decoder_pass` использует `prefix_cache` для префикса и получает `h` как вход. Модифицируем **только `h` перед `_run_decoder_pass`; `prefix_cache` остаётся чистым** — явно зафиксировать в коде E-32.
5. **Мощность кубического фита.** Минимум 5 точек `ε`. На 4 точках `dof = 1`, `p(c)` тест вырожден.
6. **Потолок диапазона ε.** Мощность растёт с `ε`, но валидность Тейлора падает. Потолок определяется структурой остатков, а не статистикой.
7. **Не-полиномиальность RMSNorm.** `z(h)` гладкая, но не полином. Коэффициент `c` абсорбирует все высшие порядки. Значимый `c` = «квадратичная модель неадекватна», не «третий порядок важен».
8. **Bootstrap по сэмплам.** Не по парам `(j, i)`. Пара — детерминированная функция от `h`, варьируется через `h`.
9. **Пилот на одном сэмпле.** `|T|=16` токенов одного сэмпла — CI нет, только ε-стабильность `b`. Не интерпретировать «b устойчив» как «b значим».
10. **Диагональ b.** `b_ii` — вторая производная self-response; отдельный объект, не часть cross-talk. Не включать в offdiag-норму.
11. **Функциональная зависимость `p_t` и `û_t`.** Оба функции `h_final`. Не путать с независимыми переменными.

## Что собираем

Per-layer (L22, L23 в пилоте; L6, L12, L18, L22, L23 в полном):

- Матрица `a` (первый порядок) — должна совпасть с `ESG_l` (валидация метода).
- Матрица `b` (второй порядок).
- Матрица `c` (остаток).
- `s_l = ε·||offdiag(b)||_F / ||offdiag(ESG_l)||_F` — скаляр.
- Per-pair остатки кубического фита: структура, зависимость от `ε`.
- График `Δz/ε` vs `ε` для диагностики режима.
- Bootstrap CI на `b` по сэмплам.
- Кросс-чек: корреляция `||b||` на L23 с `κ` из E-28 (sweep `r`).
- Опциональный контроль: корреляция `‖b(t)‖` (Гессиан, per-position) с `|Δp(t)|`; если ~1 — Гессиан тоже прокси для `|Δp|`, структура второго порядка не несёт независимой информации (ожидание — положительная, но не единичная).

## Как

**Пилот.**
1. `|T| = 16` токенов, 2 слоя (L22, L23), 5 точек `ε ∈ {5%, 15%, 30%, 50%, 70%}` (в долях `||h||`); `s_l` отчитывается на `ε_canon = 15%`.
2. Для каждого `i ∈ T`: инъекция в `h` последнего токена (`h_l += δ_i`, нормированный `δ_i`), `prefix_cache` чистый; полный форвард через `_run_decoder_pass`, получить `Δz_j` для `j ∈ T`.
3. Фит per-pair `Δz_j(ε) = a_ji·ε + b_ji·ε² + c_ji·ε³`.
4. Проверить: `c` значим? Остатки случайны? `Δz/ε` линейно по `ε`?
5. Критерий разворачивания: `c` незначим и остатки случайны по всему диапазону.

**Полный E-32.**
1. `|T| = 64`, 5 слоёв, 5 значений `ε`, N = 32 сэмпла.
2. Те же шаги.
3. Bootstrap CI по сэмплам для `b`.
4. Значимость: CI не включает 0.

**Кросс-чек.**
1. Для каждого `r ∈ {8, 16, 32}` (пересечение с E-28): `κ_r(t)` из E-28. `r = 1` и `r = 128` в E-28 не измерялись — сверка только на пересечении (расширение до `{1, 128}` — только если пересечение даст явный пик).
2. Корреляция `κ_r` с `||b(t)||` по позициям.
3. Пик корреляции — `r`, при котором κ и Гессиан мерят одно.

## Интерпретация

| Наблюдение | Что означает |
|---|---|
| `a ≈ ESG_l` (валидация) | метод корректен |
| `s_l ≪ 1`, остатки случайны | readout практически линеен, P1 валидна |
| `s_l ~ 1` | нелинейность сравнима с линейностью, P1 требует cross-talk защиты |
| `s_l ≫ 1` | readout существенно нелинеен |
| `c` значим, остатки растут | мы вышли за радиус сходимости, нужен другой диапазон `ε` |
| Кросс-чек: пик на `r = 16` | E-28 и E-32 согласованы |
| Кросс-чек: пик смещён | E-28 и E-32 мерят разные режимы |

## Критерии остановки

- Пилот: `|T| = 16`, 2 слоя, 5 ε, критерий `c` незначим и остатки случайны.
- Если пилот проходит → полный E-32.
- Если пилот не проходит → добавить ε-точки или пересмотреть диапазон (возможно, `ε → 0`).

**Стоимость.** Полный E-32: `64·5·5·32 ≈ 51k` форвардов-от-слоя (в единицах `_run_decoder_pass`). Батчится по `i`, `ε` — но `K=64` инъекций на позицию = 64 отдельных `_run_decoder_pass` (нельзя батчить: инъекция разная). Оценка GPU: ~2–3 часа на T4. Планировать.

## Порядок запуска

1. **E-34** (pre-flight 1) — минуты, существующие кэши. Включает контроль `ρ_offdiag` vs `|Δp|`.
2. **E-35-preflight** (регрессия `|Δp|`-контроля + Δû-чек + атрибуция оси 2 + контроли E-34/E-32) — **блокирует E-35-full**.
3. **E-35-full** (M-pinning, r-sweep) — только если preflight показывает, что геометрия есть (`α` значим).
4. **E-31** (B9, корреляционная функция) — параллельно; требует правки `calibration.py` для `return_offsets_mapping=True`.
5. **E-30** (mode decomposition) — по гейту E-34: если `ρ_gf/ρ_null` не «≪ 1» (наблюдено 0.98–3.61 → **да, запустить**). Определяет, несёт ли остаток `ρ_gf` хвостовые моды (r > 32, `PR_modes > 15`).
6. **E-32** (Гессиан) — только после E-30; статус по его результату (`ρ_gf ≪ 0.1` на L6–L18 → центральный; `ρ_gf ~ 0.3` → уточняющий, после E-31/E-35; хвостовая структура → объясняет хвост). Включает контроль `‖b‖` vs `|Δp|`.
7. **E-33** (gauge-голономия) — preflight «транспорт vs случайный», один вечер; полный вариант 1 — только если preflight нетривиален.
