## 2. F1 — правило монотонности убивает целевой сигнал ⛔

`u_seedavg` для dip (запись с `bisect_interval: null`):

```
λ:      0.50    0.55    0.60    0.65    0.70    0.75    0.85    1.00
u_dip: +1.547  +1.708  +1.341  −0.758  −1.737  −1.339  −1.130  +1.000
```

Это **не шум**. Это двунаправленный выброс: dip на λ≈0.55 уходит **выше** обученного значения на 1.71 нормированной единицы, к λ=0.7 проваливается **ниже** на 1.74, потом возвращается.

Машина делает так:

```python
rho = entry["spearman_seedavg"]
if rho is None or abs(rho) < SP_CRIT:      # SP_CRIT = 0.9
    entry["outcome"] = "non_monotone_excluded"
    out[o] = entry
    continue                                # ← max_u / overshoot НЕ считаются
```

Немонотонная кривая → `|ρ| < 0.9` → **excluded** → `dip_outcome != "resolved"` → ветка `V0_NOT_RESOLVED`.

Но немонотонность с выбросом — это **и есть** заявленная сигнатура порогового рождения локализованного объекта. Гладкая сигмоида — сигнатура генерической компетентности. Гейт `|ρ|≥0.9` был поставлен, чтобы отсекать шумные наблюдаемые, а отсекает он **ровно альтернативу V2**.

Сравните с гладкими наблюдаемыми того же прогона:

| наблюдаемая | u-профиль | ρ (seed-avg) | outcome |
|---|---|---|---|
| nll_holdout | −0.007 → 0.036 → 0.190 → 0.365 → 0.610 → 1.0 | **−0.9909** | resolved, λ_c≈0.85 |
| margin | монотонно вверх | ≈ +1 | resolved, bisect [0.75, 0.85] |
| dip | +1.71 → −1.74 → +1.0 | \|ρ\|<0.9 | **excluded** |

Компетентность растёт гладко к 0.85. Поле перестраивается резко на 0.6–0.65. **Это двухсобытийная картина, то есть V2-подобный исход** — и она невыразима в текущей машине.

## 3. F2 — флаг `overshoot` слеп там, где выброс максимален ⛔

Из-за того же `continue` до вычисления `max_u`:

```python
entry["max_u"] = None
entry["overshoot"] = False        # остаётся значением по умолчанию
```

Артефакт для dip сообщает `overshoot: false`, при том что `max(u_dip) = 1.708 > 1`.

**Флаг патологии выключен именно на наблюдаемой с самым большим выбросом.** Это не интерпретация, это порядок операций в коде: `max_u`/`overshoot` считаются только для прошедших гейт монотонности.

Фикс: считать `max_u`/`overshoot` **до** гейта, для всех наблюдаемых, независимо от outcome.

## 4. F3 — V3 смотрит не на тот λ, и второе условие недостижимо ⛔

Правило V3:

```python
"u_dip(0.7)>1 и rep16(0.7)>rep16(1) (seed-avg) — патология порога"
```

Два независимых провала:

**(а) λ захардкожен под E-71.** Там выброс был на 0.7. Здесь `u_dip(0.7) = −1.737`, а максимум **+1.708 на λ=0.55**. Детектор патологии проверяет точку, где выброса нет.

**(б) `rep16(0.7) > rep16(1)` математически недостижимо.** На λ=1 модель **зациклена**: sample `s12_lam1.00` = `"ame ame ame ame a me ame…"`, `loopy=1`. 16-окна с <12 distinct → все hits → `rep16(1) = 1.0`. Ничто не может быть строго больше 1.

То есть детектор патологии отключён **потому, что обученный конец сам вырожден** — instruct-модель на сыром wiki-тексте. Тот же паттерн, что `NO_DH_DC` в AT0_2b (15/15) и `vacuous` в AT0_4 P1: гейт съедает informative-исходы.

Фикс: V3 через `max(u_dip) > 1` (любой λ) **и** `dip_band_hinge(argmax) > dip_band_hinge(0)` — это уже есть в `health_ray` и не зависит от насыщенного rep16.

## 5. F4 — V1 недостижим: гранулярность бинарной наблюдаемой ⛔

`coin_all` требует, чтобы **все четыре** `DISC_OTHERS = [nll_holdout, eff_rank, loopy, margin]` дали сравнимый λ_c. Два из них не могут:

**eff_rank — исключён по монотонности.** Ручной счёт по `curves_seedavg` (17.56, 12.44, 24.70, 37.90, 38.88, 33.46, 13.16, 6.39, 5.66, 4.59, 13.20):

```
ранги в λ-порядке: 7,4,8,10,11,9,5,3,2,1,6
Σd² = 330 ;  ρ = 1 − 6·330/(11·120) = −0.500
```

`|ρ| = 0.50 < 0.9` → excluded. Аналогично pr_sigma: `Σd² = 310`, **ρ = −0.409**. Оба пикуют на λ≈0.55 — это реальная структура, а не шум.

**loopy — гранулярность.** Это `int(max ACF > 0.95)` на **одной** генерации, seed-avg по 3 сидам ⇒ возможные уровни только `{0, 1/3, 2/3, 1}`. Наблюдается:

```
λ ≤ 0.75: 0.0    λ=0.85: 0.3333    λ=1.0: 1.0
```

`crossing_of` требует **два соседних** узла с `u ≥ 0.5`. Единственный узел ≥0.5 — последний (1.0), у него нет соседа справа. Пара (0.85, 1.0) не проходит: 0.333 < 0.5. → `no_transition` → `ci=None` → `pair_compare` возвращает None → `coin_all = False` **навсегда**.

Порог 0.5 лежит **точно в зазоре между 1/3 и 2/3**. При n_seeds=3 переход бинарной наблюдаемой через 0.5 — это подбрасывание монетки: хватит одного сида, чтобы 0.85 стало 2/3 и пересечение появилось.

Фикс: либо убрать бинарные наблюдаемые из `DISC_OTHERS`, либо для них использовать не u=0.5-crossing, а первый λ с `seedavg > 0` (у loopy это 0.85 — и тогда он **совпадёт** с nll/margin).

## 6. F5 — бисекция структурно не доходит до заявленной ширины ⚠️

Пре-рег: «бисекция ≤5 ит./**≤0.02**». Артефакт:

```json
"S9_bisect": {"points": [0.8, 0.8], "widths": {"nll_holdout": 0.05, "margin": 0.05}, "ok": true}
```

`bisection_plan` строит план по **статическим** интервалам: `intervals` не обновляется между раундами, а `mid` попадает в `used`, и второй раунд пропускается. Поэтому реальный план — **один раунд**, ширина = половина исходного зазора сетки: [0.75, 0.85] → 0.05.

`refine_interval` затем упирается в `if mid not in u_at: break` — точек 0.775/0.825 нет.

А гейт:

```python
gates["S9_bisect"]["ok"] = S3_complete.ok and all(bis-клетки присутствуют)
```

**ширину не проверяет.** `BIS_WIDTH = 0.02` объявлен, недостижим и не гейтится.

Фикс: либо честно объявить «один раунд, ширина = ½ зазора сетки» и убрать 0.02 из контракта, либо планировать раунд 2 после первого (динамические интервалы). Сейчас — расхождение контракта и реализации, замаскированное `ok: true`.

Мелочь того же ряда: докстринг говорит «union ≤6 точек», константа `BIS_CAP = 12`.

## 7. F6 — медиана по меняющемуся составу ⚠️

`aggregate_cell` берёт медиану по 6 main-докам = **первые 6 wiki**. По AT0_3/wiki-разбору это wiki_0…wiki_5, из которых wiki_0 и wiki_4 — период-1 лупы (rep8 0.928 / 0.994), плюс wiki_1 и wiki_5 в loopy-стратуме. То есть **4 из 6** документов несут стабильную repeat-структуру.

На λ=1 модель их «видит» и залипает; на λ≤0.75 — нет (`loopy=0`). Значит медианный dip на λ=1 частично отражает **repeat-структуру текста**, а на низких λ — случайную геометрию. Состав вклада меняется вдоль λ.

Это прямо смыкается с AT0_7: полевая структура — feedforward-следствие token-repeat. Тогда λ_c^dip измеряет смесь «когда модель начинает видеть повторы» и «когда меняется геометрия», а не одну наблюдаемую.

Фикс без перепрогона: per-doc кривые dip уже в store (`cells[...]["docs"][n]["dip"]`), отчитать медиану по не-луповому подмножеству (wiki_2, wiki_3) как sensitivity.

## 8. Мелкое

- **σ=0 на λ=0 для бинарных.** `u_exit` считается от `sig = std over seeds at λ=0`. Для loopy все сиды дают 0 → `sig=0` → критерий `|Δ| > 2σ` вырождается в «любое ненулевое». Не баг, но чувствительность бесконечна; стоит flooring или отдельная ветка для бинарных.
- **`families_check` вернёт `intra_consistent: False` для всех трёх семейств** (field: dip/hump/plateau исключены; leaf: оба исключены; mode: loopy no_transition). Это **самостоятельный положительный результат**: ни одно семейство не даёт согласованного порога ⇒ нет единого координированного «рождения». Сейчас это записано как технический флаг, а не как вывод.
- `hump` ρ = −0.70 → excluded; `plateau` тоже немонотонен (0.122 → 0.155 на 0.5 → 0.047 на 0.85 → 0.081 на 1.0). Итого **все три полевые наблюдаемые исключены** — то есть поле целиком выпало из вердикта.
