## 1. Главное: V0 → V2 (кандидат), но V2 ≠ подтверждение

**Было** (мой предыдущий ответ, по первому ревью и артефакту):
> V0_NOT_RESOLVED корректен: dip немонотонен по λ, λ_c для него не определён, солитонная гипотеза не подтверждена.

**Стало** (по r2-exec и коду): V0 — это **артефакт машины**, а не свойство данных. Данные содержат **два разделённых события**:
- поле (dip) перестраивается резко на λ ≈ 0.55–0.65 (u: +1.708 → −1.737);
- компетентность (nll_holdout, margin) растёт гладко к λ_c = 0.85;
- режим (loopy) включается на 0.85–1.0.

Скорректированная машина v2 (disk-only из store, без перепрогона) даёт **V2_SOLITON_CANDIDATE**: поле отделено от компетентности на ≥1 шаг сетки (0.65 → 0.85 = 2 шага по 0.1).

**Но V2 — это кандидат, не подтверждение.** В коде прямо: «порядок на прямой интерполяции весов, НЕ на обучении — кандидат идёт в T8.2». То есть T8.1 из «программы фальсификации» переходит в «кандидат с T8.2 впереди» — слот T8 в аддентуме сдвигается: было «0/5 по строгим критериям», стало «есть кандидат на λ-прямой, проверка на траектории — T8.2».

## 2. Один пункт ревью опровергнут: F3b

Ревью утверждало: `rep16(1.0) = 1.0` (насыщено), поэтому V3 недостижим.

**r2-exec проверил по store:** raw `rep16(1.0) = 0.0` на всех трёх сидах. Причина: фраза-цикл на λ=1 длиннее 16 токенов, поэтому 16-окна внутри фразы имеют ≥12 distinct → hits=0. Пример `"ame ame ame"` в артефакте **отсутствует** (0 вхождений в run.log) — это, видимо, из E-71, не из AT0_8.

Следствие: V3-условие по rep16 **истинно** (0.8824 > 0.0). V3 мёртв **только** из-за захардкоженного λ=0.7 (F3a), а не из-за насыщения rep16. Это меняет диагноз: машина ломается на одном месте, а не на двух.

## 6. Что НЕ меняется

- **λ-интерполяция ≠ траектория SGD** (Запрет 5). V2 — это кандидат на прямой, не на обучении. T8.2 обязателен.
- **V1 (generic competence) структурно недостижим** на этих данных: eff_rank/pr_sigma исключены по монотонности, loopy/rep16 — бинарные. Это ограничение машины, не физика.
- **Families all-false** — содержательный результат: ни одно семейство (field/leaf/mode) не даёт согласованного порога. Нет единого координированного «рождения». Это поддерживает «два события».
- **V3 (pathology)** не срабатывает: hinge(argmax_u=0.55) = 0.034 < hinge(0) = 0.048. Но есть негативный выброс на 0.7 (hinge=0.134) — это классическая E-71-патология, просто v2-правило её не ловит (использует max(u), а не max(|u|)). Это определение, не данные; на вердикт V2 не влияет.
