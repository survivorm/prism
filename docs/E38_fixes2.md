## 1. «Тихие» баги, которые могут испортить результат

### 1.1. `kapp` инициализирован нулями, индекс `t=0` никогда не заполняется
```python
kapp = np.zeros((N, S - 1), dtype=np.float64)  # t=0..S-2
for t in range(1, S - 1): ...
```
`kapp[:, 0]` остаётся **0.0**, хотя κ_g(0) не определена (нет `u[-1]`). Сейчас сегменты начинаются с `t=1`, поэтому индекс 0 не используется. Но это **тихая ловушка**: любой будущий срез, включающий `t=0`, прочитает «идеально плоскую кривизну» вместо NaN.

**Фикс:** `np.full((N, S-1), np.nan)`.

### 1.2. NaN-нормы не попадают в `kappa_nan_count`
```python
if float(norms[i, t - 1:t + 2].min()) < 1e-10:
    kapp[i, t] = np.nan; kapp_nan_count += 1; continue
```
Если в `norms` есть NaN, `min()` даёт NaN, а `NaN < 1e-10` — **False**. Код идёт в `geodesic_curvature`, где NaN просто распространяется, возвращается NaN, но **счётчик не увеличивается**. В результате `kappa_measured_fraction` завышается, а `kappa_nan_count` занижается.

**Фикс:** проверять `torch.isfinite(norms[i, t-1:t+2]).all()` (или `np.isnan(...).any()`), а не только `< 1e-10`.

### 1.3. `s` не защищён от вырожденных норм
`u = H / norms.clamp_min(1e-12)`. Если `‖h_t‖ = 0`, то `u = 0`, и `s` считается как расстояние от нулевого вектора до соседнего — например, **1.0 вместо NaN**. Конвенция ТЗ «дегенерации → NaN и исключаются» (E-28) применена только к `κ_g`, но не к `s`. На текущем кэше (min 5.85) не проявляется, но на повреждённом кэше `s` будет тихо искажён.

**Фикс:** для позиций с `‖h_t‖ < 1e-10` (или NaN) ставить `u = NaN`, чтобы `s` тоже становился NaN и исключался nan-робастной статистикой.

### 1.4. `pos0_ratio` при нулевой норме `h0` считает «sink», а не NaN
```python
pos0_ratio = norms[:, 0] / norms[:, 1:].nanmedian(...).clamp_min(1e-12)
```
Если `‖h0‖ = 0`, отношение = 0, и такой документ **попадёт в `frac_norm_h0_below_0.1x_median`** как «sink», хотя это дегенерация, которую надо исключать. Докстринг обещает nan-робастность, но нулевую норму не отлавливает.

**Фикс:** `norms[:, 0]` с `clamp_min` не спасает; нужно явно проверять `norms[:, 0] <= 1e-12` → NaN.

### 1.5. `per_doc_ratio` тихо возвращает нули, если `iqr_b` NaN/≤0
```python
if iqr_b > 0:
    return [...]
return [0.0] * v.shape[0]
```
Если IQR(body) = NaN (например, body весь NaN) или 0, все per-doc ratio становятся **0.0**, что выглядит как «аномалий нет». Это только диагностика (в вердикты не входит), но может ввести в заблуждение.

**Фикс:** возвращать `[float("nan")] * N` в этом случае.

## 2. Несоответствия документации/логики разметки

### 2.1. `meta.direction_from_s_only` не совпадает с кодом
В `meta` написано:

## 1. Семантическая проблема: `align_K1` на gauge-free J

Самое серьёзное. Код берёт максимум `|<U[:,k], 1/√K>|` **по всем модам** `U` (SVD gauge-free `J^(p)`), как в E-37:

```python
al_docs = (sv.U * one[None, :, None]).sum(dim=1).abs().max(dim=-1).values
```

Но для gauge-free J **активные моды имеют ~0 перекрытия с uniform** (по построению `P(p)·1 = 0` ⇒ `1^T J^(p) ≈ 0`, а значит для активных мод `<U[:,k], 1/√K> ≈ 0`). Максимум по всем модам фактически **выбирается из нуль-пространства** `J^(p)`. Поскольку `1/√K` лежит (приближённо) в нуль-пространстве `J^(p)`, то

- `Σ_{k ∈ null} |<U[:,k], 1/√K>|² ≈ 1`,
- `max_k |<U[:,k], 1/√K>|` определяется тем, насколько LAPACK-овский базис нуль-пространства «случайно» выровнен с uniform.

То есть `align_K1` на `J^(p)` **измеряет не «residual gauge»**, а базисно-зависимую алигнацию нуль-пространства. Отчётные значения ~0.9 — это в основном артефакт. Докстринг честно предупреждает: «NOT directly comparable to E-37's 0.895→0.710», — но имя и порог `>0.9 body / <0.7 pos0` сохраняют прямой смысл «gauge high → edge effect», что вводит в заблуждение.

**Почему это не «портит вердикт» сейчас:** `align_edge_effect` не срабатывает ни на одном слое (у всех body 0.90–0.97, а pos0 0.83–0.92 > 0.7). Числа отчётливы, но **интерпретация `align_K1` как метрики gauge ошибочна**.

**Фикс:** либо ограничить max активными модами (`sv.S > threshold`), либо явно задокументировать в `meta`, что метрика на `J^(p)` мерит «насколько хорошо убит uniform» (null-space alignment), а не «сколько gauge осталось».

## 1. Семантическое замечание: `gap_min` включает хвостовые зазоры

`gap_min` = минимум по **всем 15** последовательным зазорам `σ_i² − σ_{i+1}²` (i = 1..15). Это соответствует формальному определению [M-4] в paper.md:

> `gap_min(t) = min_{i=1..15} (σ_i(J_t)² − σ_{i+1}(J_t)²)`

Но семантически: если `σ_15` и `σ_16` почти равны (а оба малы), `gap_min ≈ 0`, и слой классифицируется как **near-degenerate** = «неабелев формализм применим», даже если **топ-моды** (σ_1…σ_10) прекрасно разделены. То есть «применимость неабелева формализма» определяется **хвостом спектра**, а не топ-структурой, где реально живёт геометрия (ср. E-30b: остаточный cross-talk локализован именно в 10–20 **наименьших** модах ESG).

**Следствие:** вердикт `near_degeneracy` на L6/L12/L18/L19/L22 (все имеют tail gaps ≈ 0) не означает, что «неабелева структура в топ-модах» — скорее наоборот, топ-моды разделены, а «near-degeneracy» в хвосте — это **свойство tail спектра**, не топ-структуры. Для paper.md это нормально (вердикт формально следует определению), но при интерпретации «мораторий на WZ-терминологию из-за near_degeneracy» стоит помнить, что это **tail-degeneracy**, а не top-mode degeneracy.

**Фикс**: дополнительно посчитать `gap_min` на **топ-8** или **топ-4** — если там зазоры большие, зафиксировать «tail-degeneracy, not top-mode degeneracy», вердикт M4 считать с учётом него!.

## 5. Float32 SVD: подводный камень с underflow хвостовых σ

Комментарий утверждает:
> «float32 SVD noise in sigma^2 is ~5e-7 relative — 10^4x below the eps_frac=0.005 threshold — so it cannot flip the well_separated predicate».

Для **топ-мод** — верно. Но для **хвоста**: если `σ_i < 1e-19` (близко к float32 subnormal), то `σ_i²` underflow-ится в 0. Тогда `σ_i² − σ_{i+1}² = 0 − 0 = 0` → gap = 0 → near-degeneracy, **даже если реальный gap был 1e-30** (не underflow-нут в float64). То есть при глубоко-подпороговых сингулярных числах вердикт near-degeneracy — **артефакт float32**.

На текущих данных не доминирует (L23 `gap_min = 0.00916` — не underflow), но для чистых нулевых сингулярных чисел (или очень малых) near-degeneracy может быть over-triggered. Комментарий «cannot flip the predicate» верен только для **ненулевых** зазоров; для `σ_i ≈ 0` он неточен.

**Фикс:** проверять `σ_R > 0` для значимости (или считать в float64 для tail-suspect случаев).

## 1. Что говорит определение `[M-4]`

`paper.md` §4.4 (addendum E-28, пункт 3):

> `gap_min(t) = min_{i=1..15}(σ_i(J_t)² − σ_{i+1}(J_t)²)`, порог `ε = 0.01·σ_1²`. `min_t gap_min(t) > ε` → неабелев формализм **неприменим** (все зазоры разрешимы, каждый сингулярный вектор транспортируется независимо); `< ε` → **допустим, не обязателен**.

Это математически корректно: non-Abelian Berry/WZ требует **вырождения** — иначе каждое собственное направление транспортируется независимо (диагональ = Abelian). Значит:

- `gap_min > ε` (well-separated) → **НЕ применим**
- `gap_min < ε` (near-degenerate) → **применим** (допустим)

То же самое в коде:
```python

#  the non-Abelian formalism is applicable where this is False)"
# "INVERSION WARNING: well_separated=True means ... NOT applicable"
```

И вердикты `exp38c` это отражают:
- `non_abelian_not_applicable` ← все слои well-separated
- `near_degeneracy` ← есть near-degenerate (то есть **применим**)
