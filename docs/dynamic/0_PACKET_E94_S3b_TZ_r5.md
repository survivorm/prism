## Зачем (один вопрос, не про M1/M2)

Условие 2 гейта руки B требует «эмиссент зависит от ширины набора / на контроле нет».
Прогон S4pp дал `probe_dependence=false`, но свип **не демонстрировал применения ширины**:
при `top_k=1` и `top_k=400` отчёт одинаков (`n_tl=20`, один порядок id), а по исходнику
(`server-context.cpp:1790`) отчёт при `post_sampling_probs=false` строится из логов ДО
сэмплера — путь отчёта **в принципе** не может показать действие `top_k`.

Вопрос руки S3b один: **применяется ли `top_k` к пост-сэмплированному набору кандидатов на
этом форке.** Ответ НЕ меняет чтение `gate2_met=false` в основном (T=0) прогоне — жадная
эмиссия при T=0 структурно инвариантна к ширине усечения (argmax не зависит от размера
набора, из которого он выбран), поэтому `probe_dependence=false` при T=0 не может быть ни
«отрицательным результатом», ни «положительным». S3b устанавливает только механику: есть ли
вообще механизм, который делал бы условие 2 осмысленным при T>0. Про M1/M2 здесь не
говорится ничего.

## Ассерты ДО вычисления N (на каждый ответ)

1. `HTTP == 200`, иначе строка невалидна (`halt_reason="http_<code>"`), N не считается.
2. Поле `completion_probabilities` ЕСТЬ в ответе, иначе `halt_reason="no_field"` —
   отсутствие поля НЕ считается `N=0` (иначе молча попадало бы в правило 3).
3. Для строки `S3b-off-probe`: в её эхе ЕСТЬ поле `top_k` и его значение **>
   `n_probs` = 20 (строго, без равенства)**, иначе `halt_reason="off_default_low"`,
   рука невалидна (потолок B4 не измерен: при дефолте ≤ 20 — включая ровно 20 —
   `N_off` — минимум потолка B4 и серверного дефолта, неразличимы).
4. **Сверка эха с отправленным (против «поле не доехало» / «сервер перебил»):**
   * 4a: на ВСЕХ 7 строках `echo.post_sampling_probs == true`, иначе
     `halt_reason="echo_mismatch"`;
   * 4b: на лестничных строках (1,2,3,5,6,7) в эхе ЕСТЬ поле `top_k` И

## Правило решения (записано ДО запуска; иного чтения не будет)

Пусть `N_probe = (N(k1),N(k2),N(k4))` и `N_ctrl = (N(k1),N(k2),N(k4))` по адресам;
`N_off` — по строке `S3b-off-probe` (адрес пробы). Порядок: сначала правило 4 (любой
halt_reason/смерть сервера — механический дефект precedence'ом выше любого чтения N;
строки без N в 1a/1b/2/3 не попадают), затем 1a, 1b, 2, 3 по порядку; ни одно не
применилось → 5.

1a. **Положительное (лестница):** на ОБОИХ адресах: `N(1) ∈ {1,2}` И `N(k) ∈ {k, k+1}`
   для всех `k ∈ {1,2,4}` с ОДНОЙ конвенцией (+0 или +1), ОДНОЙ НА ОБА АДРЕСА (смешанная
   A/B → правило 5) И `N(1) < N(2) < N(4)` И `N(4) ≤ N_off` (сравнение только с probe:
   безрежевый набор не шире режевого; на контроле сравнения с `N_off` нет — off там не
   меряется). Чтение: «top_k применяется к пост-сэмплированному набору на этом форке
   (механика установлена)». Состояние `gate2_met=false` T=0 не меняется
   (инвариантность жадности); осмысленным становится повтор условия 2 при T>0.
1b. **Положительное + потолок B4** (лестница обрезана потолком, 1a не прошла): существует
   ЕДИНОЕ `c ∈ {0,1}` (одинаковое на обоих адресах) такое, что на ОБОИХ адресах
   `N(k) == min(k+c, N_off)` для всех `k ∈ {1,2,4}` И `N_off < 20` И лестница не
   плоская (есть хотя бы одно строгое увеличение). Чтение: «top_k применяется и B4
   держит потолок = N_off (лестница обрезана потолком)». Отличие от правила 2: здесь
   есть рост, там плоское. (Формула min(k+c, N_off) исключает механически невозможные
   лестницы: напр. (1,2,5) не проходит ни при c=0 (min(4,5)=4≠5), ни при c=1
   (min(2,5)=2≠1).)
2. **Не применяется:** `N_probe` ПЛОСКое `c_p` (все три равны) И `N_ctrl` ПЛОСКое
   `c_c` (все три равны) И НЕ (`c_p == c_c == 1`) И НЕ (`c_p == c_c == 2`);
   **`c_p` и `c_c` МОГУТ РАЗЛИЧАТЬСЯ** (у адресов разные потолки B4 — ТЗ это прямо
   допускает). Обоснование порога: плоское при «не применяется» возможно при ЛЮБЫХ
   потолках (N = |набор после B4| на каждом адресе); при «применяется» плоское
   возможно только в двух случаях — оба адреса (1,1) (конвенция A, потолок 1) или
   оба (2,2) (конвенция B, потолок 2) — ровно два исключённых случая (неотличимы от
   «не применяется» → правило 5). Чтение: «top_k не применяется к набору (механика
   отсутствует)»; повтор условия 2 при T>0 бессмысленен (нет механизма, от которого
   эмиссия могла бы зависеть); рука B не запускается по этой причине. Альтернатива
   «post_sampling_probs проигнорирован» исключена: первично — факт-основанием (n_tl=0
   у S2a/S2b) и ассертом 4a (`echo.post_sampling_probs == true` на всех строках);
   вторично — `0 < sum_p0 ≤ 1.02` в строках правила 2 (при c < 20 набор ровно c ≤ 19
   кандидатов, обрезки нет, Σp0 = 1.0; при c = 20 набор ≥ 20, Σp0 ∈ (0, 1]; окно
   0 < sum_p0 ≤ 1.02 покрывает оба; пре-сэмплированный при T=1.0 дал бы >> 1, при T=0 —
   0; оба поля записаны в артефакт).
3. `N(x) == 0` на ЛЮБОЙ строке (включая контроль и off: поле есть по ассерту 2,
   item[0] пустое — пост-сэмплерный цикл оборвался на первом `p == 0.0`; при T=1.0 это
   аномалия: либо вероятности не вычисляются вообще, либо `post_sampling_probs` сломан
   иначе) → рука **невалидна**, выводов нет, разбирательство по исходнику.
4. **Любой halt_reason ассертов 1–4 (`http_*`, `no_field`, `off_default_low`,
   `echo_mismatch`) ИЛИ `echo_no_topk` ИЛИ смерть сервера** → рука невалидна:
   `kind="mech"`, `verdict="mech_invalid"` (для `echo_no_topk` — `mech_void`: эхо не
   подтверждает применение `top_k`, но это ограничение сервера, а не баг запроса),
   артефакт пишется с `halt_reason`.
5. **Catch-all:** ЛЮБОЕ иное сочетание N — в том числе явно: плоское `c_p == c_c == 1`
   («top_k применяет и держит 1» на обоих адресах, конвенция A, потолок 1, неотличимо
   от «не применяется» с потолками 1); плоское `c_p == c_c == 2` (неотличимо: конвенция
   B + «применяется» с потолком 2 = «не применяется» с потолком 2); плоское c на одном
   адресе при лестнице/обрезанной лестнице на другом; не-k-лестница (например (2,4,8)
   или (1,3,5): строгий рост, но не {k,k+1}) и не-обрезанная (не min(k+c, N_off));
   `N_off < max(N(1),N(4))` (противоречие механике: безрежевый набор уже режевого);
   `N(1) > 2`; частичный рост; смешанная конвенция A/B на адресах — → `kind="mech"`,
   `verdict="mech_void"`,
   `halt_reason="no_preregistered_reading"` — рука заканчивается без вывода, чтение не
   выдумывается постфактум.

## Чего здесь заранее НЕ утверждается

* Эмиссия этих 7 запросов **не читается** как довод о механизме: при `temperature=1.0`
  ридаут «эмиссент = аргмакс» не определён, и жадная инвариантность к ширине усечения
  делает эмиссию неинформативной при любом T для вопроса «зависит ли эмиссент от
  ширины». Строкам присваивается `kind="mech"`, вердикт только механический
  (`mech_ok` / `mech_flat` / `mech_void` / `mech_invalid`).
* Ни один вывод S3b не цитируется как про M1/M2 и не правит `gate2` в `S4pp.json`
  (ни предикат, ни числа). S3b даёт оговорку к чтению статуса `gate2_met=false`.
* Если выяснится (2), рука B не запускается; это предрегистрированное следствие, а не
  решение, принятое по факту.

## B. Факты из исходника форка (перепечатаны, читать C++ не надо)
