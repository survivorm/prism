## Короткий вердикт

Идея хорошая (искать структуру в старших моментах приращений, а не в первом моменте), но в текущем виде **два из пяти инвариантов (I2, I3) тривиальны по построению**, и вердикт по ним не интерпретируем. I1 и I4 содержательные, но swap-null слаб для I1. I5 без null'а.

Это более серьёзная проблема, чем в exp50v3 — там трихотомический вердикт спасал, а здесь **никакой вердикт не спасёт тривиальный инвариант**.

---

## 1. Критическая ошибка: I2 и I3 тривиальны в этом гаузе

### Геометрический факт

В `gauge_along_lines` накапливается `T_t = R_{t-1} · R_{t-2} · ... · R_0`, где `R_s = 𝓡(vv[s]→vv[s+1])` — геодезическая ротация. Тогда **точно** (в точной арифметике):

```text
T_t · vv[0] = vv[t],   T_t · pl[0] = pl[t]
```

То есть `gvv[t] = T_tᵀ · vv[t] = vv[0]` и `gpl[t] = T_tᵀ · pl[t] = pl[0]` — **тождественно**, для **любой** последовательности.

Это ровно та «тривиальность открытого транспорта», которая в exp50v3 docstring уже зафиксирована («span(Ṽ_t) ≡ span(V_0) ТОЧНО»). В exp51 она вернулась.

### Следствие для I3

```python
def inv_I3(gv):
    ...
    c12, c23, c34, c14 = abs(a @ b), abs(b @ c), abs(c @ d), abs(a @ d)
```

`a, b, c, d = gv[t..t+3] = vv[0]` (все одинаковые) → `c12 = c23 = c34 = c14 = 1` → cross-ratio = `1·1/(1·1) = 1` → `log(1) = 0`.

**I3 = 0 всегда**, независимо от данных. `I3_sd = 0`. Control `geo_I3_sd < 0.02` проходит — но не потому что контроль валидирует смысл I3, а потому что I3 **тривиален по построению**.

### Следствие для I2

```python
def inv_I2(gpl):
    ...
    s = float(det(A2.T @ B2) * det(B2.T @ C2) * det(C2.T @ A2))
```

`A = B = C = pl[0]` → `det(pl[0]ᵀ · pl[0]) = det(I₂) = 1` → `I2 = sign(1·1·1) = +1`.

**I2 ≡ +1**, `I2_mean = +1`, а docstring обещает null `⟨ε⟩ = 0` (для стационарного ряда с симметрией). Для тривиального ряда sign = +1 стабильно, никакой симметрии нет.

### Что это значит для вердикта

`|real − swap|` ≈ 0 (оба тривиальны), CI swap — узкий вокруг 0, → `|real − swap|` внутри CI → **"invariant does not survive"**. Технически верно, но **семантически неверно**: I2/I3 не «не выживают в данных», они **не могут выжить в этом гаузе вообще**, потому что все транспортированные подпространства одинаковые.

### Что делать

Три опции, все валидные:

**(а) I2/I3 на сырых подпространствах** (без gauge-транспорта):

```python
I2_raw = inv_I2(pl)   # pl, не gpl
I3_raw = inv_I3(vv)   # vv, не gvv
```

Тогда I2/I3 измеряют «как меняются 2-плоскости/линии вдоль текста» — нетривиально. Cross-ratio и chirality инвариантны к выбору базиса, так что это осмысленно. «Гауз» был нужен для I1/I4, не для I2/I3.

**(б) I2/I3 на остатках** (deviation from `pl[0]`):

```python
def residuals(gsub, base):
    return [nzr(gsub[t] - base @ (base.T @ gsub[t])) for t in range(len(gsub))]
```

Тогда I2/I3 измеряют «как остатки транспорта ведут себя» — потенциально интереснее, но требует обоснования, что они инвариантны.

**(в) Признать I2/I3 невалидными** и выкинуть из вердикта, оставить как диагностику. В paper.md это будет honest limitation.

Я рекомендую **(а)** — прямое применение без гауза. Cross-ratio и chirality — это проективные инварианты, они не требуют gauge-транспорта.

## 2. I1 — содержательный, но swap-null слаб

`I1_k = <cos(δ_t, δ_{t+k})>` — на `gdg` (транспортированные приращения). Это **не тривиально**, потому что `gdg[t] = T_tᵀ · δ_t`, и δ_t — это **настоящее** приращение в позиции t, не параллельно перенесённое.

Но `swap_order` делает только **25% локальных транспозиций**. Для I1 при **малых лагах** (k=1, 2) соседние приращения остаются «почти как в реальных данных» — swap меняет только 25% пар. Значит:

- `I1_1` на real: `cos(δ_t, δ_{t+1})` для реальных данных;
- `I1_1` на swap: то же самое для 75% пар, но для 25% пар — `cos(δ_t, δ_{t+2})` или `cos(δ_{t-1}, δ_{t+1})`, что всё равно близко к `cos(δ_t, δ_{t+1})` для гладких данных.

Итог: `|I1_real − I1_swap|` будет **маленьким** для I1 при k=1, 2. Вердикт «не выживает» — но это артефакт слабого null'а, не отсутствия структуры.

Для **больших** лагов (k=8, 16) swap эффективнее, потому что перестановки разрушают дальнюю корреляцию. Так что `I1_8`/`I1_16` — более осмысленные тесты, чем `I1_1`/`I1_2`.

### Что делать

- Использовать **surrogate** (step-matched белый) как null для I1 — как в exp50v3. У него та же средняя скорость, но нет никакой динамики. Тогда `I1_real ≠ I1_sur` детектирует «направленность» приращений.
- Или дополнить swap **block-shuffle** (перестановка блоков длины, скажем, 4), чтобы разрушить и локальную, и дальнюю структуру, сохраняя локальную гладкость.

Docstring I1 явно говорит «Белое⇒0, баллистика⇒+1». Значит **null для I1 — это white**, не swap. Swap не разрушает I1 на малых лагах.

## 3. I5 — без null'а, и это явно сказано, но не выведено как limitation

`I5` — автокорреляция сингулярных чисел `σ₁..σ₄`. `bundle` считает `I5 = inv_I5(specs)`, но `row["sw{j}"] = {I1_1, I1_8, I2, I3_sd, I4_e}` — I5 там **нет**. Так что I5 не имеет swap-null в отчёте.

Docstring честно пишет «null для них — только перестановочный, отмечаем честно». Но:
- Перестановочный null для I5 не реализован;
- Вердикт I5 не выносится (нет `|real − swap|`).

В `summ["_all"]` есть `I5_median_tau` и `I5_corr_s1_lag16`, но без CI и без null. Это диагностика, не вердикт.

**Fix:** добавить в `row["sw{j}"]` поле `I5` (вычислять `inv_I5` на перемешанном ряду `specs`) — дешево, 2 строки. Или явно в `summ` пометить `I5_no_null = true`.

## 4. `I2_signfrac` — не то, что выглядит

```python
summ[dom]["I2_signfrac"] = safe_med([abs((r["I2"] or 0)) for r in rows])
```

Это медиана **абсолютных значений** I2, не «sign fraction». Название вводит в заблуждение — читатель подумает «доля triples с sign +1», а это «медиана |I2|». Убрать или переименовать в `I2_abs_median`.

## 5. `I4` — содержательный и с правильным null

`I4_e = λ₂/λ₁` ковариации приращений в окне 8. Для geodesic — `e ≈ 0` (все приращения в одной плоскости); для white — `e ≈ 1` (изотропные). Real данные: зависит от того, есть ли «dominant direction of flow».

Swap-null работает: 25% транспозиций меняет состав окон, ковариация меняется. `|real − swap|` может быть значимым, если структура есть.

Хорошо. Один из пяти инвариантов полностью рабочий.

## 6. `_DEV` для ортогональности — отсутствует

В exp50v3 был `_DEV` с `xl` и `q`, чтобы ловить накопленную численную ошибку. Здесь его нет. Для r=1 и r=2 (используется в exp51) `Xl` = `±1` или матрица 2×2 с малыми отклонениями. Если `pullback_step` накапливает ошибку (например, из-за `live`-маски на θ близких к π), I2/I3 могут «выглядеть нетривиально», хотя это численный шум.

**Fix:** добавить `_DEV` в `gauge_along_lines` или в `loop_curvature` (там его в exp50v3 не было, но для r=1/r=2 понадобится).

## 7. `leaf_bases` — только v1 и v2, не top-16

```python
def leaf_bases(x, A, eps):
    ...
    v1 = nzr(J.T @ Ue[:, -1])
    v2 = nzr(J.T @ Ue[:, -2])
    ...
    return v1, torch.stack([v1, v2], 1), sig.tolist()
```

Используются только **два** top singular vectors, не 16. Для exp50v3 использовалось r=16. Это осознанное упрощение (1-линия и 2-плоскость вместо 16-подпространства), но:
- В docstring сказано «линии v1 и 2-плоскости листа» — согласовано;
- В paper.md «лист» определён как **top-16**, а не top-2. Значит exp51 измеряет не «лист», а «главную моду листа».

Если осознанно — ок, но в `result` надо пометить `rank_used = 2` и в paper.md указать, что это **проекция** листа, не полный лист.

## 8. `mean_step` — правильная формула

`C.frame_kinematics` — та же, что в exp50v3, в которой κ. Матчинг согласован.

Но в exp51 `mean_step` не используется для surrogate — только для диагностики (в `summary`). В exp50v3 `mean_step` был основанием для `synth_white_matched`. Здесь surrogates нет, есть только swap. Значит matching — не проблема, потому что surrogate не строится.

## 9. Контроли — проходят, но не валидируют I2/I3

```python
ok = (... and (res["geo"]["I3_sd"] is not None and res["geo"]["I3_sd"] < 0.02)
      ... and (res["white"]["I2_mean"] is not None and abs(res["white"]["I2_mean"]) < 0.15))
```

- `geo I3_sd < 0.02` — проходит **тривиально** (I3 = 0 для geodesic, потому что gv = vv[0]).
- `white I2_mean < 0.15` — для white `I2_mean` должно быть ≈ 0 по симметрии; но если бы I2 был тривиален, `I2_mean` был бы +1, и этот контроль **упал бы**. Значит `white` в контролях — это **не** то же, что данные; для белого `I2_mean` может быть 0 потому что `gpl` нетривиален (если `pl` не геодезический транспорт белого ряда).

Стоп, для **белого** ряда (случайные 2-плоскости) `pl[t]` — независимые случайные. Тогда `T_t = R_{t-1} · ... · R_0` — композиция случайных ротаций, `gpl[t] = T_tᵀ · pl[t]`. Здесь `T_t` — произведение **несвязанных** ротаций, и `T_tᵀ · pl[t]` **не равно** pl[0] (потому что pl[t] — независимая, не та, к которой ведёт транспорт). Значит для белого `gpl` нетривиален, и I2 работает.

**Ага — значит «тривиальность» I2/I3 не абсолютна, а зависит от того, насколько pl[t] «согласован» с предыдущими pl через транспорт.**

Для **гладкой/геодезической** траектории: pl[t+1] ≈ 𝓡(pl[t]→pl[t+1]) · pl[t] = R_t · pl[t]. Тогда `T_tᵀ · pl[t] = R_0ᵀ · ... · R_{t-1}ᵀ · pl[t] = R_0ᵀ · ... · R_{t-1}ᵀ · R_{t-1} · ... · R_0 · pl[0] = pl[0]` — тривиально.

Для **белого/случайного** ряда: pl[t+1] не связан с R_t · pl[t], поэтому `T_tᵀ · pl[t] ≠ pl[0]` — нетривиально.

Для **реальных данных**: где-то посередине, зависит от того, насколько траектория «геодезическая» в смысле geodesic rotation.

**Ключевой момент:** для **реальных данных** I2/I3 будут отражать «отклонение от геодезичности». Это **правильно** и осмысленно! Моя критика «I2/I3 тривиальны» была бы верна только для строго геодезической траектории. Для реальных данных они измеряют интересную величину.

Так что я был неправ в пункте 1. I2/I3 **не тривиальны для данных** — они тривиальны только для геодезической траектории (и для control — geo). В `white` они нетривиальны, в `real` они нетривиальны.

**Но:** контроль `res["geo"]["I3_sd"] < 0.02` проходит именно потому, что для геодезической траектории `gv = vv[0]` (тривиально). Это правильный контроль: «I3 детектирует геодезичность как const». **Не баг.**

**Значит I2/I3 в порядке**, если их интерпретировать как:
- I3 (cross-ratio) — «отклонение от геодезичности в cross-ratio метрике»;
- I2 (chirality) — «есть ли систематическая асимметрия в триплетах 2-плоскостей после транспорта».

Моя критика была **частично ошибочной**, потому что я не учёл, что для реальных данных `gpl[t] ≠ pl[0]` — именно потому, что реальная траектория не строго геодезическая. Приношу извинения.

Но тогда **проблема с swap-null для I2/I3**: если 25% транспозиций **почти не меняют** траекторию (как я говорил), то `I2_real ≈ I2_swap` — то есть либо оба «нетривиальны одинаково», либо «оба тривиальны одинаково». Вердикт «не выживает» не отличит эти два случая.

**Фикс:** нужен surrogate, не swap. Например, для I2/I3 — permute **сами pl[t]** (полная shuffle, не 25% локально). Тогда для shuffle `gpl[t]` = `T_tᵀ · pl[shuffled]` = некая нетривиальная комбинация, и разность с real может быть значимой.

Или использовать `phase-randomized` null (FFT по t, случайные фазы) — сохраняет спектр, убивает детерминированную динамику.

## 10. Итоговая переоценка после пересмотра

**Уточнение к п.1:** I2/I3 **нетривиальны для реальных данных** (потому что реальная траектория не строго геодезическая — есть «изломы» при смене токена). Моя критика была неверной в части «тривиальны всегда». Снимаю это.

**Но остаётся:**
- I2/I3 с 25% swap — null слишком слаб. Нужен полный shuffle или surrogate.
- I1 с малыми лагами — swap слаб. Нужен surrogate.
- I5 без null.
- `I2_signfrac` — misleading name.
- `_DEV` отсутствует.
- `leaf_bases` использует только top-2, не top-16. Пометка в result нужна.

## 11. Приоритет правок

**P0 (перед запуском):**

1. **Добавить surrogate-null в дополнение к swap** — для I1, I2, I3, I4. Используйте `synth_white_matched` из exp50v3 (с правильным `mean_step`) или `phase-randomized`. Swap оставить как secondary diagnostic.

2. **I2/I3 на полном shuffle** — в дополнение к swap. Полный shuffle разрывает связь `pl[t+1]` с `pl[t]` и делает `gpl[t]` не «отклонением от геодезического», а «случайной матрицей». Это сильнее.

3. **`_DEV` для `gauge_along_lines`** — проверка `T_tᵀ · T_t = I` (ортогональность накопленного T). Иначе численный дрейф может «выглядеть нетривиально».

**P1 (перед интерпретацией):**

4. **`I5` с null** — добавить `inv_I5` на shuffl'ed ряду `specs` в `sw{j}`.

5. **`I2_signfrac`** — переименовать в `I2_abs_median` или убрать.

6. **`leaf_bases`** — пометить `rank_used = 2` в JSON, чтобы читатель знал, что это «проекция листа», не полный top-16.

**P2:**

7. **`boot_mean_ci` seed** — вынести наружу (для power-теста).
8. **`N_SW=2`** — увеличить до 4, если power на грани.
9. **`bootstrap CI` на swap** — сейчас `boot_ci([r[f"sw{j}"][f] for r in allr for j in range(N_SW)])` — это CI по 2×N значениям, а не по N документам. Псевдорепликация, как в exp49b (я критиковал). Здесь: 2 репликации swap на доку × 64 документа = 128 значений, bootstrap по 128. Но уникальных (real − swap) — 64 (потому что real общий). CI **занижен**. Для вердикта нужен paired CI по документам, как в exp50v3. Сейчас вердикта I2/I3 по real−swap **нет** (есть только отдельные real и swap), но если добавлять — нужно paired.

## Главное, что нужно исправить

**Добавить surrogate-null** (`synth_white_matched` или `phase-randomized`). Без него swap-25% — слишком слабый null для I1 (малые лаги), I2 и I3, и вердикт «не выживает» может означать «null слаб», а не «структуры нет».

С surrogate:
- Если `|I_real − I_sur|` значимо и знак стабилен 3/4 доменов → **структура есть** (гипотеза подтверждена).
- Если `|I_real − I_swap|` значимо и стабилен → **локальная структура** (дополнительная информация).
- Иначе → **случайная динамика**.

Два нуля (swap и sur) дают трёхрежимный ответ, как в exp50v3 трихотомический вердикт.

Без sur — эксперимент работает для I4, но не для остальных.
