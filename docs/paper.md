# Часть I. Постановка

## 1. Мотивация, цели, статус

**Суть метода.** Даны две модели одного семейства (Qwen3.5-4B и Qwen3.5-0.8B), общий словарь. Метод сравнивает **чувствительность декодирования** — то, как скрытые состояния каждой модели влияют на финальные логиты. Сравнение происходит через пространство словаря, которое является общей системой координат для обеих моделей.

**Ключевая интуиция.** Для задач с softmax-выводом важны не все компоненты скрытого состояния, а только их проекция на пространство, реально влияющее на выходные вероятности. Математически это выражается через Якобиан `∂p/∂h_l`: он кодирует, какие направления в `h_l` двигают распределение выходов, а какие — нет.

**Цели (по приоритету):**

| Приоритет | Цель | Что получаем | Статус |
| --- | --- | --- | --- |
| **P0** | Диагностика: послойная карта расхождения Якобианов (`𝓖_gap`) | Тепловая карта по слоям | ✅ Подтверждено (E-1 identity, E-2 карта) |
| **P1** | Карта чувствительности для квантования: какие направления защищать | Правые сингулярные векторы `J^T J` (hidden space); ESG = `JJ^T` (token space) | ✅ Частично (E-12b,c: ESG validated) |
| **P2** | Трансформация младшей модели | Лосс для оптимизации | ✅ Валидирован (Exp 17–19: LoRA-дистилляция bridge-лоссом + logit-KD-контроль + детектор разрушения; §22) |
| **P3** | Регуляризатор при дообучении | Дополнительный лосс | гипотеза, отложено |

P0, P1 и P2 — реализованные уровни; P3 отложен до дополнительных исследований. P0 и P1 — разные артефакты: P0 показывает, насколько `J_S` отличается от `J_S_target`, P1 — какие направления hidden state наиболее чувствительны. P2 (Exp 17–19) показывает, что bridge-лосс работает как causal-механизм трансформации (LoRA r=4), при этом logit-KD-контроль подтверждает направленность движения, а детектор разрушения различает направления.

> **Фиксация позиции.** Если не указано иное, все карты чувствительности и Якобианы вычисляются для последнего токена последовательности: `t = S-1`.

## 3. Архитектурный контекст: Qwen3.5

Архитектурные факты, влияющие на корректность вычислений. Производные — в §8.

**Гибридная архитектура.** `config.layer_types[layer_idx]` определяет тип слоя: `"full_attention"` → `Qwen3_5Attention` (GQA); `"linear_attention"` → `Qwen3_5GatedDeltaNet` (GDN). Типы чередуются.

**GDN: рекуррентное состояние.** GDN поддерживает рекуррентное состояние `S_t ∈ R^{H × D_k × D_v}`:

```
S_t = g_t * S_{t-1} + k_t * delta_t^T
output_t = S_t * q_t
```

Кэш GDN содержит `conv_state: [1, conv_dim, conv_kernel_size − 1]` и `recurrent_state: [1, num_v_heads, head_k_dim, head_v_dim]`. GDN — не трансформер: обратный проход идёт через рекуррентную цепочку, а не через attention-матрицы.

**Мутация кэша.** `torch_causal_conv1d_update` мутирует `conv_state` in-place (`conv_state.copy_(...)`); GDN обновляет `recurrent_state` через `cache_params.update_recurrent_state(...)`. Поэтому ни `copy.deepcopy(prefix_cache)`, ни ручной клон не чинят in-place-запись в сохранённый узел графа — это делает только `_clone_gdn_states_on_entry()`. Используется `_deep_clone_cache()` (ручной клон всех тензоров + объектные атрибуты кэша; `deepcopy` на 5.15.1 тоже даёт независимые копии — ручной клон нужен для detach и устойчивости к переименованию полей слоёв), см. §9 и Приложение C.

**Tied weights.** `_tied_weights_keys = {"lm_head.weight": "model.embed_tokens.weight"}` — т.е. `W = E`, и проекция через `E` корректна для логитов. Защита: `extract_embeddings` (§12) при каждом вызове проверяет `data_ptr`-тождество `lm_head.weight` и `embed_tokens.weight` и при их расхождении выдаёт `UserWarning` — молчаливое использование не той матрицы анэмбеддинга для нетянутых чекпоинтов превращается в громкий сигнал (в рамках статьи все модели — с tied weights).

**MRoPE.** Multi-dimensional RoPE с `position_ids` формы `[4, B, S]` (text, temporal, height, width); для текстового входа все 4 компоненты одинаковы. При вычислении Якобиана для последнего токена с кэшем: `position_ids = S − 1`.

**RMSNorm — не идентичность.** `Qwen3_5RMSNorm`: `output = (x / rms(x)) * (1 + weight)`; вес инициализирован нулями, поэтому на старте `1 + w = 1` и RMSNorm — чистая нормализация `y = x/RMS(x) ≠ x`. Производная — §8 `[L-rms]`.

**Ограничения версии 1:** CPU (Intel Iris Xe / SYCL, 64 GB, `torch.set_num_threads(4)`, float32 — fp16 на CPU на порядок медленнее); текстовый вход (`Qwen3_5ForCausalLM`); `model.model` — `Qwen3_5TextModel` (единый путь для flat-моделей всех размеров; для мультимодального wrapper `Qwen3_5ForConditionalGeneration` путь — `model.model.language_model`, обрабатывается `_lm_module()`, `prism/jacobian.py`); dtype Якобиана — dtype модели (`model_dtype`, fp16 на GPU — `h.to(model_dtype)`); в экспериментах — Qwen3.5-4B (32 слоя, `D_L = 2560`) и Qwen3.5-0.8B (24 слоя, `D_S = 1024`).

## 4. Якобиан и модели

**Модели.** Старшая модель `M_L`: скрытая размерность `D_L`, `n_L` слоёв, словарь `V`. Младшая `M_S`: `D_S < D_L`, `n_S` слоёв, тот же словарь `V`. Матрица эмбедингов `E ∈ R^{V×D}`; при tied weights `W = E` (§3).

**Якобиан (определение).** Для слоя `l`, позиции `t`:

$$J_l^{(t)} = \frac{\partial z_t}{\partial h^l_t} \in \mathbb{R}^{V \times D}$$

где `z_t ∈ R^V` — логиты, `h^l_t ∈ R^D` — скрытое состояние. На практике вычисляется только для фиксированного набора токенов `𝒮` (§12): `J_l^(t)|_𝒮 ∈ R^{|𝒮|×D}`.

**Слой-переходный Якобиан.** Для скрытого состояния `h^l`:

$$D_l(x) = \frac{\partial h^{l+1}(x)}{\partial h^l(x)} \in \mathbb{R}^{D \times D}$$

**Правило композиции** `[L-comp]`. По цепному правилу:

$$J_l^{(t)} = W_{\mathrm{lm}} \prod_{i=l}^{L-1} D_i(x)$$

Произведение упорядочено справа налево; матрицы `D_i` зависят от `x` и в общем случае не коммутируют — порядок имеет значение.

**Структура pre-norm блока.** Для `h^{l+1} = h^l + MLP(RMSNorm(h^l + Attn(RMSNorm(h^l))))`:

$$D_l = I + \frac{\partial \mathrm{MLP}}{\partial \bar h} \cdot \frac{\partial \mathrm{RMSNorm}}{\partial \hat h} \cdot \left( I + \frac{\partial \mathrm{Attn}}{\partial \tilde h} \cdot \frac{\partial \mathrm{RMSNorm}}{\partial h^l} \right)$$

где `h̃ = RMSNorm(h^l)` (вход Attn), `ĥ = h^l + Attn(h̃)` (вход второго RMSNorm), `h̄ = RMSNorm(ĥ)` (вход MLP); вклад каждого RMSNorm — §8 `[L-rms]`.

**О взвешенных строках.** Величина `Σ_{j∈𝒮} p_{𝒮,j} J_j` (сумма по `𝒮` полная, `Σ p_{𝒮,j} = 1`), где `J_j = ∂z_j/∂h` — строка Якобиана для токена `j`, — это вероятностно-взвешенное среднее строк Якобиана: вектор-строка `1×D`, в общем случае **не равный** самой матрице `J`. Свойства gauge-оператора `P(p)` устанавливаются в §8 `[L-gauge]` и из этого среднего не выводятся.

**Gauge-free Якобиан** (определение; свойства оператора — §8 `[L-gauge]`). Для задач, инвариантных к uniform shift логитов (softmax, cross-entropy), важна не `J` целиком, а её gauge-free компонента:

$$J^{(p)} = P(p)\, J, \qquad P(p) = \mathrm{diag}(p) - pp^T$$

где `p = p_S ∈ R^K` — softmax, урезанный и ренормализованный на носителе:

$$p_S(k) = \frac{p(k)}{\sum_{j \in \mathcal{S}} p(j)}, \qquad k \in \mathcal{S}$$

Оператор убивает gauge-направление (uniform shift), сохраняя token-discriminating направления. `J^(p)` используется в defrag (§6, E-11a) и surgery (§18).

## 5. Лемма о размерностях и Gramian-коррекция

**Лемма** `[L-dim]`. Пусть `J_L ∈ R^{|𝒮|×D_L}`, `J_S ∈ R^{|𝒮|×D_S}`, `E_L ∈ R^{V×D_L}`, `E_S ∈ R^{V×D_S}`. Тогда:

- **(а)** Проекция в пространство словаря: `J̃_L = J_L · E_L^T ∈ R^{|𝒮|×V}`;
- **(б)** Целевой Якобиан для младшей модели: `J_S_target = J̃_L · E_S ∈ R^{|𝒮|×D_S}`;
- **(в)** `J_S` и `J_S_target` имеют одинаковую размерность `|𝒮|×D_S` и непосредственно сравнимы.

**Проблема неортогональности.** При кросс-модельной проекции `J_L · E_L^T · E_S` матрица `E_S` неортогональна (`E_S^T E_S ≠ I`). Даже при `J_L = J_S` и `E_L = E_S` (одна и та же модель) лосс не равен нулю — проекция `E_S` «вращает» векторы в пространстве младшей модели.

**Коррекция** `[L-gram]`. После проекции через `E_S` применить правую коррекцию:

$$J_S^{\text{target}} = (J_L \cdot E_L^T) \cdot E_S \cdot G_S^{-1}, \qquad G_S^{-1} = \mathrm{pinv}(E_S^T E_S)$$

`pinv` — через SVD для числовой стабильности. Эквивалентно `E_S · G_S^-1 = (E_S^T)^+` (при `σ_min(E_S) > 0`) — псевдообратная строки `E_S^T`, т.е. замена `E_S` на её ортогональную проекцию в `R^D`. Для identity-случая (`E_L = E_S`):

$$J_S^{\text{target}} = J_L \cdot E^T \cdot E \cdot \mathrm{pinv}(E^T E) = J_L$$

Смысл коррекции: `J_L E_L^T` — координаты в токен-пространстве; умножение на `E_S G_S^-1` — проекция этих координат в пространство младшей модели, корректная при `σ_min(E_L^T E_S) > 0` (матрица пересечения не вырождена — для моделей одного семейства выполнено).

**Оптимизация.** `G_S^-1` вычисляется один раз и кэшируется на диск (`results/.gramians/`) + в memory-кэш. Ключ — SHA-256 по форме/device + **представительным строкам** `E_S` (первой, последней и 10 детерминированным mid-строкам, равномерно по глубине: `step = (V−1)//10`, см. `_gramian_key`). Полная матрица 248k×1024 слишком дорога для хеша. Это репрезентативный, а не полный хеш: две разные матрицы эмбедингов с совпадающими образцовыми строками (и формой) столкнутся в кэше. В текущем сценарии (1–2 модели фиксированной провены) риск нулевой; при смене модели с тем же V и D **или при обновлении torch** кэш надо чистить (`results/.gramians/`) — ключ не включает версию torch/`rcond`.

> Свойства Грамиана (condition number, ранг, достаточность регуляризации) — результаты, см. E-6b, E-8, E-3.

**Пространства и представления.** Собственные векторы ESG живут в разных пространствах:

- **ESG eigenvectors** (`JJ^T`): живут в **токенном** пространстве `R^K`. Каждая строка `J_i` — градиент логитов по скрытому состоянию для токена `i`; `JJ^T` = Грамиан токенов.
- **Right singular vectors** (`J^T J`): живут в **hidden** пространстве `R^D` — чувствительность hidden dimensions; собственные векторы `J^T J` = направления в hidden space, по которым модель наиболее чувствительна.
- **Связь через SVD:** `J = UΣV^T`, где `U ∈ R^{K×K}` — левые (token space), `V ∈ R^{D×D}` — правые (hidden space). ESG использует `U`; анализ hidden directions требует `V`.

## 6. ESG, спектральные метрики, ранги

**Определение (ESG).** Empirical Sensitivity Gramian для слоя `l` на `N` Якобианах одной траектории:

$$\bar{G}_l = \frac{1}{N} \sum_{i=1}^{N} J_l^{(i)} \left(J_l^{(i)}\right)^T \in \mathbb{R}^{|\mathcal{S}| \times |\mathcal{S}|}$$

Спектральное разложение: `Ḡ_l = U Λ U^T`. Собственные векторы `u_1, …, u_K` — главные направления чувствительности декодирования в **токен-пространстве**.

> **Семантика пулляции (важно).** Пул допустим **в пределах одной траектории** (позиции одного документа): внутри-сэмпловая когерентность `C_a` в 8–41× выше шумового пола (E-27.6). Меж-сэмпловый пул **невалиден** (E-0.1: `C_b ≈ 0.003–0.05`, почти ортогонально) — он усредняет несвязанные Якобианы. Агрегация по сэмплам — только на уровне скалярных метрик (λ, PR, SNR, `r_eff`), не на уровне матрицы (реализация: `compute_esg` — внутри-траектория, `compute_esg_per_sample` — sample-local, `prism/esg.py`). Практические протоколы E-9/E-13/E-14 пулят по последним позициям N **разных** сэмплов — допустимо приближение в гладких слоях (где `C(σ_d)` велико, E-0.1), с оговоркой.

> **Примечание.** Это НЕ Neural Tangent Kernel в классическом смысле (Jacot et al., 2018): NTK — градиенты по параметрам, ESG — градиенты по активациям. Термин NTK не использовать.

**Спектральные метрики** (для сингулярного разложения `J^(p)`, `σ_1 ≥ σ_2 ≥ …`):

- **uniformity**(`u`) = `⟨u, 1_𝒮/√K⟩² ∈ [0,1]` — доля направления `u` вдоль uniform-режима `𝒮`. Определён только для векторов token-пространства.
- **Эффективные ранги** (спектр `Ḡ_l = U Λ U^T`, `λ_k = σ_k²`, `p_k = λ_k/Σλ`):
  - энтропический: `r_eff = exp(−Σ_k p_k log p_k)`;
  - stable rank: `r_stable = trace(JJ^T) / λ_1` (отношение полной энергии к максимуму — метрика «насколько спектр не сосредоточен в одной моде»);
  - participation ratio: `PR = (Σ λ_k)² / Σ λ_k²` (для спектра `JJ^T`). Stable rank и PR — **разные метрики**, совпадающие только для rank-1 спектра (пример: `λ = (4,1,1,1,1)`: `r_stable = 8/4 = 2`, `PR = 64/18 ≈ 3.6`); не смешивать. Метрика `F = 1/√(r_eff (K + D − r_eff))` (§15).
- **gauge_share (ESG-версия)** — доля энергии `JJ^T`, приходящаяся на uniform-направление в токен-пространстве: `gauge_share = Σ_k (u_k^T 1)² λ_k / Σ_k λ_k`, где `J = UΛV^T` — SVD (эквивалентно: `u^T JJ^T u / trace(JJ^T)`, `u = 1/√K`). В топ-1 приближении: `λ₁ · uniformity(u₁) / trace` — именно его отчётен E-10a (колонка `gauge_share_0`).
- **Trace** = `Σ_i σ_i²` — общая чувствительность.
- **SNR** — leave-one-out отношение «сигнал» к «шуму» в спектре (числа — §17, E-14).

Не путать ESG-`gauge_share` с `g_uni` (§8): `g_uni` — доля энергии **сырого** `J` в uniform-режиме токен-пространства (`‖QJ‖_F²/‖J‖_F²`, `Q = uu^T` — проекция на uniform-направление строк), убиваемая gauge-оператором `P(p)`; ESG-`gauge_share` — доля энергии **в токен-пространстве** `JJ^T`, лежащая на uniform-направлении. Обе малы в дифференциальных слоях (L23), велики при uniform-доминировании (L6–L18).

**Разведение рангов.** Символ `r` используется в двух смыслах, которые следует отличать:

1. **Спектральный ранг** `r_eff` — энтропический / stable rank / participation ratio спектра `JJ^T` (определения выше; метрика `F`).
2. **Функциональный ранг** `r_KL` — минимальное `r`, такое что KL defrag-r аппроксимации `J^(p) ≈ U_r J_r` совпадает с KL полной `J^(p)` (числа — E-11a, §19). Не путать со спектральными рангами: согласие `r_KL` с `r_eff`/`PR` — отдельная проверка, а не допущение.

Оба ранга одного порядка на L6–L18 (E-9, E-14), и их согласие — отдельная проверка, а не допущение.

**Лемма о спектре** `[L-rank]`. `Ḡ_l = JJ^T ≥ 0` симметрична; собственные значения — квадраты сингулярных значений `J`. Для rank-deficient `J` (см. §8 `[L-rms]`: произведение `D_i` вырождено) спектр имеет нулевое собственное значение с кратностью ≥ `K − rank(J)` (`K = |𝒮|`); при `K < D − n_rms` (где `n_rms` — число RMSNorm-блоков на пути `h → logits`, каждый даёт множитель ранга `D−1`, см. `[L-rms]`) полная матрица может быть полного строчного ранга — нулевых СЗ в `JJ^T` нет вовсе (нуль-пространство `J^T J` в D-пространстве имеет размерность `D − rank(J)` — это другой объект). Top-`m` сингулярные значения определяют всю полезную информацию.

**Тождество** `[L-fisher]`. `P = ∂ softmax/∂ z`, поэтому `J^(p) = P J = ∂p/∂h` — канонический Якобиан выходного распределения, и `J^T P J` — информация Фишера:

$$\mathrm{KL}\left(p \,\|\, p_{h+\delta}\right) = \tfrac{1}{2}\, \delta^T J^T P J\, \delta + O(\|\delta\|^3)$$

Первый порядок тождественно нулевой (softmax инвариантен к сдвигу логитов); **ведущий ненулевой член — квадратичный**, и он корректен при `‖δ‖ ≪ ‖h‖`. Для gauge-направления `v_g` (левый сингулярный вектор `u_g`, uniformity `u_g` ≈ 1): `J^(p) v_g ≈ 0`, т.е. gauge-направление имеет почти нулевую информацию Фишера — в линейном (квадратичном) смысле оно **сильно отличается** от differential-направления. Сравнивать KL по полному forward при `‖δ‖ ~ ‖h‖` с этим предсказанием нельзя (см. E-12a).

## 7. Gap и bridge: определения и направления

**Определение (gap, разрыв).** Для слоя `l`:

$$\mathcal{G}_{\text{gap}}(l) = \sum_{i \in \mathcal{S}} w_i \left(1 - \frac{J_S[i] \cdot J_S^{\text{target}}[i]}{\|J_S[i]\| \cdot \|J_S^{\text{target}}[i]\| + \epsilon}\right)$$

где:

- `w_i = p_L(i) / Σ_{j∈𝒮} p_L(j)` — вероятность токена `i` в распределении старшей модели, **нормированная на 𝒮** (в реализации — по **незамаскированным** строкам: после применения маски масса исключённых строк перераспределяется на оставшиеся, режим (ii)). Асимметрия осознанна: используется именно `p_L` (не `p_S` и не среднее) — фиксируется система отсчёта старшей модели.
- `ε = 10^-8`.
- Строки `J_S` и `J_S_target` соответствуют **одним и тем же токенам** из `𝒮` (выравнивание гарантировано §5).

**Определение (bridge, мост).**

$$\mathcal{B}_{\text{bridge}}(l) = \sum_{i \in \mathcal{S}} w_i \frac{J_S[i] \cdot J_S^{\text{target}}[i]}{\|J_S[i]\| \cdot \|J_S^{\text{target}}[i]\| + \epsilon}$$

**Соотношение** `[L-gap]`. При совпадающих весах `w_i`: `𝓖_gap = 1 − 𝓑_bridge` **точно** (при усреднении по строкам без весов — ровно `1 − cos`). Направления противоположны:

| Метрика | Формула | Направление |
| --- | --- | --- |
| **gap** `𝓖_gap` | взвешенная `(1 − cos)` | **меньше = лучше** |
| **bridge** `𝓑_bridge` | взвешенное среднее `cos` | **больше = лучше** |

Исторически именовалось «L_bridge / мост» для обеих величин — вызывало путаницу; теперь имена фиксированы. В JSON: ключи `gap` (E-1…E-15) и `bridge` (E-16a/b) — направление однозначно.

**Диапазон.** `𝓖_gap ∈ [0, 2]` (поскольку `𝓖_gap = 1 − cos`): `0` — полное совпадение направлений, `2` — анти-выравнивание, `≈ 1` — уровень нуля (ортогональность случайных векторов в высокоразмерном пространстве). Меньше = лучшее выравнивание (`gap = 0` ⇔ Якобианы коллинеарны). Наблюдаемые `gap ≈ 1.00–1.03` на ранних слоях интерпретируются как отсутствие выравнивания (стохастическая независимость), а не «структурный конфликт».

**Sentinel-режимы** (определены один раз; все последующие упоминания — «см. §7»):

- **(i) sentinel** — все строки маскированы (gap = 1.00). Это **не реальное значение**: `jacobian_gap, sentinel-ветка (bridge.py)` возвращает 1.0, когда маска пуста. В таблицах маркируется «1.000 (sentinel)».
- **(ii) partial mask** — часть строк жива, доля отчитывается полем `masked_fraction`.
- **(iii) baseline ≈ 1.00** — все строки живы, но выравнивание отсутствует (уровень ортогональности, не артефакт маски).

**Маска и порог.** Если `‖J_S[i]‖ ≤ τ` **или** `‖J_S^{\text{target}}[i]‖ ≤ τ` — строка `i` исключается из суммы (реализация: `_valid_mask (bridge.py)` — маска по обеим нормам, порог **одинаков** для обеих). Дефолт — `τ = 0` (sentinel-only: маскируются только нулевые строки; все численные протоколы статьи работают в этом режиме). Исторически дефолтом был абсолютный `τ = 10^-6`. Для decay-маски (исключение затухших, но ненулевых строк) статья использует **относительный** квантиль слоя, чтобы избежать систематического смещения (масштабы `J` различаются на порядки между слоями):

$$\tau_l = 0.01 \cdot \mathrm{median}_i \left( \|J_S[i]\| \right)$$

(калибровка — E-6: на L18 `τ_l ≈ 10^-4` — на порядок выше абсолютного 10^-6; при sentinel-доле > 0 результаты маркируются, а не молча маскируются).

**Масштабная слепота.** Так как Gap — это `(1 − cos)`, он слеп к абсолютному масштабу `J_S` (калибровке уверенности). Для предотвращения геометрической слепоты оптимизации к калибровке Gap отчитывается совместно с метрикой масштаба:

$$s(l) = \log \frac{\|J_S\|_F}{\|J_S^{\text{target}}\|_F}$$

`s(l) ≈ 0` — масштабы совпадают; `s(l) ≫ 0` — младшая модель систематически «громче» старшей по чувствительности (и наоборот).

## 8. Gauge-оператор и производные блоков

**Определение (gauge-оператор).** `P(p) = diag(p) − pp^T`, где `p = p_S` — softmax, урезанный и ренормализованный на `𝒮` (§4). Свойства — в `[L-gauge]`.

**Лемма** `[L-gauge]` (gauge-оператор). Пусть `P = P(p)`:

1. **Положительная полуопределённость.** `P` симметричен, `x^T P x = Var_p[x] ≥ 0`, `ker P = span{1}`, rank = `K−1`.
2. **Не проектор.** `P` **не идемпотентен ни при каком** `p` (даже при `p = uniform`: `P = (1/K) I − (1/K²) 1 1^T` и `P² = (1/K) P ≠ P` при `K > 1`) — это **не проектор**, а якобиан softmax (gauge-оператор).
3. **Определённость и инъективность на классах.** Оператор корректно определён на классах эквивалентности `J ~ J + 1 w^T` (uniform-сдвиг строк) и инъективен на них: `P J = 0 ⇒ J = 1 c^T ~ 0`.
4. **Каноничность и инвариантность.** `J^(p) = P J = ∂p/∂h` — канонический Якобиан выходного распределения (`P = ∂ softmax/∂ z`, `[L-fisher]`); инвариантен к uniform shift логитов: сдвиг `z → z + c·1` добавляет к `J` строку, пропорциональную `1^T`, а `P 1 = p − p(p^T 1) = 0`.

Утечка на усечённом носителе: `O(p(𝒮)(1 − p(𝒮)))`, где `p(𝒮) = Σ_{j∈𝒮} p_j` — доля массы, приходящаяся на носитель (независимый равномерный сдвиг `1_𝒮` обнуляется точно).

**Тождество** `[L-fisher]` (см. §6): `P = ∂ softmax/∂ z`, `J^(p) = ∂p/∂h`, `J^T P J` — информация Фишера.

**Gauge-направление.** `v_g ∈ R^{D_S}` — правый сингулярный вектор `J_S`, чей левый сингулярный вектор `u_g` максимизирует `|cos(u_g, 1)|` (`1/√K` — нормированное uniform-направление в токен-пространстве, `K = |𝒮|`). `v_g` отвечает за mode-shift (сдвиг всех логитов одновременно); направления, ортогональные `v_g`, несут token-discriminating информацию. Gauge-коррекция в `J^(p)` убирает именно `v_g`, оставляя информативные направления для моста.

**`g_uni` (raw gauge-share).** `g_uni = ‖Q J‖_F² / ‖J‖_F²`, где `Q = u u^T`, `u = 1/√K` — доля энергии **сырого** `J` в uniform-режиме токен-пространства (строки), **убиваемая** gauge-оператором (uniform-компонента; при `p = uniform` точно: `P Q = 0`). Отличается от ESG-gauge_share (§6): та — доля энергии `JJ^T` на uniform-направлении, `Σ_k (u_k^T 1)² λ_k / Σ_k λ_k`.

**Производная RMSNorm** `[L-rms]`. Для `y = RMSNorm(x)`, `r = √(⟨x,x⟩/D)`, `û = x/‖x‖₂` (`‖û‖ = 1`), `g = 1 + w` (вектор веса):

$$\frac{\partial y}{\partial x} = \frac{1}{r}\, \mathrm{diag}(g)\, \left(I - \hat u \hat u^T\right)$$

(порядок множителей важен: `diag(g)` — слева; при `g = 1` матрица симметрична, при `g ≠ 1` — нет). Свойства: `û` — нулевой собственный вектор (`M û = (1/r) diag(g)(û − û) = 0`), матрица ранга `≤ D−1`, **неортогональна**. Каждый RMSNorm — множитель ранга `D−1`, поэтому произведение `∏ D_i` вырождено (`det = 0`), и **полная** сумма показателей Ляпунова равна `−∞`; FTLE определяется **только для top-m** сингулярных значений. При вычислении FTLE в сумму top-m показателей входит вклад `log(1/r)` на каждом RMSNorm (см. Math.md §3: QR-алгоритм, лог-аккумуляция, оговорки `n = 24–32`): это дрейф масштаба от нормировки, а не хаотичность.

> **Производительность.** Строки Якобиана вычисляются **одним батченным backward** (`grad_outputs=torch.eye(K)`, `is_grads_batched=True`) — не циклом по токенам; 3–15× быстрее на T4 (реализовано, `prism/jacobian.py:_compute_jacobian_rows`). Для плотного `[D, D]` Якобиана (`compute_hidden_jacobian`) цикл по `D` строк остаётся — `vmap`/`jacrev` там future work.

**GDN cache cloning.** Ни `copy.deepcopy(prefix_cache)`, ни ручной клон не чинят in-place-запись в сохранённый узел графа (на 5.15.1 `deepcopy` даёт независимые копии — мутации изолированы; проблему в-place решает только `_clone_gdn_states_on_entry`, ниже). `_deep_clone_cache()` — ручной клон всех тензоров в кэше через **прямое присваивание атрибутов** (конструкторные kwargs в обоих типах слоёв молча отбрасываются — листинг C.2) плюс **объектные атрибуты кэша** (`vars(cache)`: на 5.15.1 — флаг `offloading`, в 4.x — `_seen_tokens`) и assert `get_seq_length()` после клона (на 5.15.1 длина выводится из `keys.shape`; на версии с объектным учётом длины assert превращает тихую порчу в громкий сбой). Внедрено (`prism/jacobian.py`).

**In-place мутация сохранённых узлов графа.** Detach не решает проблему: in-place `copy_` (оптимизация статических адресов cudagraph в transformers 5.15) попадает на объект, сохранённый рекуррентным циклом для backward, — version-счётчик узла повышается в **любом** backward через декод (не только при `create_graph`). Решение — `_clone_gdn_states_on_entry()`: monkey-patch ядер `torch_recurrent_gated_delta_rule` / `causal_conv1d_update`, клонирующий входное состояние **на входе ядра** (объект чтения ≠ объект записи), с восстановлением оригиналов после декода. Активен во всех градо-декодах (логит-Якобиан §9, hidden-Jacobian, `bridge_rows_backward`); в `no_grad`-прогонах клон избыточен, но безвреден. **Гарантия действия патча — версионно-зависимая, эмпирическая**: патч подменяет атрибуты модуля `modeling_qwen3_5`, а GDN `forward` на 5.15.1 разрешает ядра как свободные переменные этого модуля (вызовы L457/L506); если ядро вызывается через алиас в другом модуле, патч молча не действует — сигнал обнаружения будет громкий (autograd-ошибка в месте, который патч защищает, вернётся). Патч **реентерабелен** (вложенный контекст — no-op, клон идемпотентен); обёртки фиксируют только `initial_state`/`cs`, хвост сигнатуры ядер прокидывается без изменений (устойчиво к добавлению позиционных параметров; удалённый/переименованный параметр — громкий `TypeError`).

**Аналитический Якобиан последнего слоя** (`_last_layer_jacobian`): `J = ∂h_norm/∂h` без backward (RMSNorm: `[L-rms]`; LayerNorm: аналог с `diag(w)`). Вход `h` может прийти как `[1, S, D]` (полные hidden_states) — схлопывается до последней позиции **до** `reshape(1,-1)`: иначе identity размера `[S·D, S·D]` (например `[65536, 65536]` = 16 GB) → OOM на GPU / XLA-аборт на TPU.

> **⚠️ ЗАМЕЧАНИЕ ПО ПАМЯТИ.** Для длинных последовательностей это ~1–2 GB. Если не хватает памяти — уменьшить $S$ до 512.

**Ограничение на вход.** Только одна последовательность **без паддинга**: replay-фаза строит causal-маски от длины кэша с `attention_mask=None`, поэтому padding-токены в префиксе молча считались бы валидным контекстом. Ограничение зафиксировано в коде (`ValueError` в `compute_jacobian_for_tokens`, v23.2).

**Версионно-зависимое поведение (vmap через GDN-ядра).** Батченный backward проходит через хвост декодера с `linear_attention`-слоями (рекуррентные ядра `torch_recurrent_gated_delta_rule` / `causal_conv1d_update`). Идентичность построчному циклу проверена на синтетических графах; на реальных ядрах — эмпирический факт для transformers 5.15 (прогоны на T4), **фолбэка на построчный цикл нет**: апгрейд transformers, ломающий batched backward через GDN, даст runtime-ошибку, а не тихую деградацию.

**Ключевые свойства.** (1) Глубинный доступ к `h_l` через `hidden_states[layer_idx + 1]` (проход 2) без изменения модели. (2) KV cache делает forward $O(S \cdot D)$, а backward — $O(D^2)$ на слой (без re-forward по $S$). (3) Один батченный backward со всеми $K$ строками (`retain_graph=False`; см. «Производительность») — граф не удерживается между строками. (4) `position_ids = S−1` для последнего токена при использовании KV cache (MRoPE).

## 10. Jacobian bridge

Полный алгоритм (§4, §5, §7, §8) — листинг `jacobian_gap` (с Грамиан-коррекцией `pinv(E_S^T E_S)` и sentinel-маской) — Приложение C.

**Свойство (identity).** При $M_S = M_L$, $E_S = E_L$: $J_L \cdot E^T \cdot E \cdot \mathrm{pinv}(E^T E) = J_L$ (в пределах pinv-условия, [L-gram]), $J_L \approx J_S$ (детерминизм), $\mathcal{G}_{\text{gap}} \approx 0$ ([L-dim] + [L-gram]). Это — базовая самопроверка корректности всей цепочки (E-1: gap ≈ 10⁻⁸ на всех 24 слоях).

## 11. Диагностика P0 и ESG P1

**P0 (карта расхождения).** Для всех пар слоёв $(l_L, l_S)$: вычислить $\mathcal{G}_{\text{gap}}(l)$, $\mathcal{B}_{\text{bridge}}(l)$. Выход: монотонная карта по глубине (E-2, E-6, E-13, E-15). Направления: `gap` — меньше = лучше, `bridge` — больше = лучше (§7).

**P1 (карта чувствительности для квантования).** Для каждого слоя $l$:

1. $J_S(l)$ — Якобиан, §9.
2. **Защита** (hidden space): правые сингулярные векторы $J_S^T J_S$ — направления в $h$, наиболее чувствительные к изменениям.
3. **Эксплойт** (token space): собственные векторы ESG $\bar{G}_l = JJ^T$.

**ESG-вычисление.** `N` Якобианов одной траектории (позиции сэмпла) — внутри-траекторный пул; **sample-local** по сэмплам (E-0.1: меж-сэмпловый пул невалиден — Якобианы разных сэмплов почти ортогональны; агрегация по сэмплам — только скалярные метрики, §6):

$$\bar{G}_l = \frac{1}{N} \sum_i J^{(i)} (J^{(i)})^T \quad (\text{усреднение по сэмплам, не пул})$$

Спектральное разложение — стандартное (матрица симметричная, $K \times K$). Метрики: SNR, PR, gauge share — §6.

**Связь с P2/P3.** P2 реализован (Exp 17–19, §22): лосс $\mathcal{L}_{p2} = \sum_l \alpha_l \cdot \mathcal{G}_{\text{gap}}(l)$ — bridge-лосс на matrix-free per-sample J-rows (chunked backward, HVP), оптимизирует LoRA r=4 на lm_head + o_proj(l_S). P3 (регуляризатор) — гипотеза, отложена: $\mathcal{L}_{p3} = \sum_l \beta_l \, \|J_S(l) - J_S^{\text{target}}(l)\|_F^2$.

## 15. Фундамент поля J: kill-switch и sample-local Gramians

Эксперименты этой секции предшествуют всем остальным: их выводы (поле J когерентно вдоль сэмпла, Грамианы sample-local, доменной кластерной структуры нет) — неявные предпосылки §17–§19.

### E-0.1. Stage-0 kill-switch: длина когерентности поля Якобиана (N=8/домен, всего 32; K=64; 0.8B, слои 6/12/18/22, GPU T4)

> Мотивация — из E-12a: линейный (квадратичный) предиктор [L-fisher] корректен при ε/‖h‖ ≪ 1; в E-12a (ε=1.0, ε/‖h‖ = 14–53%) полный decoder даёт ratio ≈ 1.02–1.04, тогда как линейный предиктор — 7–59×, т.е. на масштабах возмущений, сопоставимых с ‖h‖, поведение поля $J(h)$ становится важным. Если поле $J(h)$ при этом **фрактальное** — быстро осциллирует на масштабах, сопоставимых с типичным расстоянием между сэмплами домена, — то **доменно-условные Грамианы $G^d$ бессмысленны** (пул Якобианов усредняет несвязанные значения), и Мост как многоточечная метрика не может работать. E-0.1 — kill-switch: измерить длину когерентности поля $J$ и решить, продолжать или останавливаться.

**Задача.** Поле $J: \mathbb{R}^d \to \mathbb{R}^{K \times d}$ (gauge-free $J^{(p)} = (\mathrm{diag}(p) - pp^T) J$, $p$ = softmax логитов, перенормированный по глобальному токен-сету top-K=64 0.8B self-bridge) гладкое, если близкие точки дают близкие Якобианы. Метрика — коэффициент когерентности по парам:

$$C(\delta) = \mathbb{E}_{\|h - h'\| \approx \delta} \left[ \frac{\langle J(h), J(h')\rangle_F}{\|J(h)\|\,\|J(h')\|} \right]$$

(косинус по строкам в порядке ранга токенов, не по id), биннинг по $\log \delta$ (14 бинов, ≥5 пар/бин). Коэффициент когерентности — $\ell = \delta$ при $C(\delta) = 0.5$; гейт — $C(\sigma_d)$, где $\sigma_d = \|\text{std}_{i \in d}\, h_i\|_2$ (норма стандартного отклонения по размерам, по доменам). Три типа пар: **(a)** соседние позиции одного сэмпла $(S{-}2, S{-}1)$, $(S{-}1, S)$ (малые δ, ≤ $\sigma_d$); **(b)** две выборки одного домена (δ ~ $\sigma_d$); **(c)** междоменные (большие δ). Параметры: 4 домена (wiki/math/code/chat) × 8 сэмплов, max_length=64, 384 gauge-free J-вызова, 644 с на T4 (0.18 GPU-h).

| Слой | σ_d | C(σ_d) | приговор | (a) intra-sample C | (b) between-samples C |
| --- | --- | --- | --- | --- | --- |
| 6 | 1.66 | 0.33 | умеренное | 0.14–0.35 (δ 1.7–2.6) | −0.003–0.029 (δ 2.3–2.9) |
| 12 | 1.86 | 0.45 | умеренное | 0.30–0.49 (δ 1.8–2.8) | 0.011–0.023 (δ 2.7–3.0) |
| 18 | 4.78 | 0.64 | гладкое | 0.67–0.71 (δ 5.6–6.6) | 0.04–0.17 (δ 6.9–7.8) |
| 22 | 7.18 | 0.87 | гладкое | 0.85–0.93 (δ 7.5–9.1) | 0.05–0.30 (δ 9.7–11.8) |

**Результат: НЕ ФРАКТАЛЬНО.** Kill-switch не сработал (порог STOP: $C(\sigma_d) < 0.1$) ни на одном из четырёх слоёв. Поле $J$ на масштабах доменной дисперсии $\sigma_d$ когерентно, и когерентность **растёт с глубиной** (0.33 → 0.87). Линейное приближение первого порядка корректно как раз там, где работают Мост и доменные Грамианы.

**Формализм: листы.** Поле $J$ — сечение векторного расслоения $E = \mathcal{H} \times \mathbb{R}^{K \times D} \to \mathcal{H}$ над многообразием скрытых состояний. **Лист** $\mathcal{L}$ — максимальное связное подмногообразие, где когерентность выше порога $C_{\min}$: $\forall h_1, h_2 \in \mathcal{L}:\ C(J(h_1), J(h_2)) \geq C_{\min}$. **Длина когерентности** в направлении $v$: $\ell(h, v) = \sup\{ t > 0 : C(J(h), J(h + tv)) \geq C_{\min}\}$; изотропная — $\ell(h) = \inf_{v \in S^{D-1}} \ell(h, v)$. **Гипотеза анизотропии** (поле анизотропно, экспериментально подтверждена типами пар (a)/(b)): разложив $\delta = \delta_\parallel + \delta_\perp$ относительно локального тангенциального подпространства листа, $C(\delta; h) \approx f(\|\delta_\parallel\|) \cdot g(\|\delta_\perp\|)$, где $f$ убывает медленно (вдоль листа), $g$ — быстро (поперёк). Проверка: для каждой пары вычислить $\delta_\parallel, \delta_\perp$ (PCA по соседним точкам траектории) и убедиться, что $C$ коррелирует со $\|\delta_\parallel\|$ слабо, а с $\|\delta_\perp\|$ сильно.

**Ключевой побочный сигнал.** Разрыв между типами пар: (a) в пределах сэмпла $C \approx 0.14$–$0.93$, а (b) между сэмплами одного домена $C \approx -0.003$–$0.30$ (обычно 0.003–0.05; пик 0.30, L22/code) — в общем случае Якобианы разных сэмплов домена почти ортогональны, хотя их hidden states лежат в пределах $\sigma_d$. Поле $J$ когерентно **вдоль последовательности** (позиции), но не поперёк распределения сэмплов. Следствие для ESG: Грамианы должны строиться **sample-local** (каждый сэмпл — свой Грамиан, как это сделано в E-16/E-19), а не пулом Якобианов по домену: пул усредняет почти ортогональные $J$ и убивает сигнал.

**Оговорки.** (1) Гейт оценен на кривой, сшитой из (a)+(b); (a) даёт покрытие при δ ≤ $\sigma_d$, (b) — диапазон δ ~ $\sigma_d$. $\ell$ (перекрытие $C=0.5$) формально не существует для чистых (b)-кривых ($C \le 0.3$ во всём диапазоне), т.е. поперёк распределения сэмплов когерентность ниже 0.5 уже на масштабе $\sigma_d$ — это не стоп, а количественная граница допустимой пулляции. (2) N=8/домен, доверительные интервалы по бинам не вычислялись; эффект-сайз разрыва (a)/(b) по слоям (Cohen's d по парным C из JSON): L6 d=1.91, L12 d=2.06, L22 d=1.22 — сильные; **L18 d=0.39 — слабый** (разрыв на этом слое не превышает шумы между бинами; «гладкое» при L18 опирается на C(σ_d)=0.64, но поперёк-сэмпловый контраст здесь наименее надёжен). (3) Self-bridge 0.8B: 4B не загружается, токен-сет — из 0.8B (отклонение от параметрической таблицы, зафиксировано в PLAN).

**Практический итог:** Мост как многоточечная метрика допустим; пул Якобианов по доменам — нет (sample-local только).

### E-27.5/27.6. Значимость, кластеры и изоляция доменов поля J (Exp 27, N=8/домен, всего 32; K=128; 0.8B, слои 6/12/18/19/22/23, GPU T4)

E-0.1 показал, что Грамианы sample-local: вдоль сэмпла (соседние позиции) $C \approx 0.14$–$0.93$, а поперёк сэмплов (разные сэмплы домена) $C \approx -0.003$–$0.30$ (обычно 0.003–0.05) — почти ортогонально. Оставались три вопроса: (1) статистически ли значима когерентность $C_a$ относительно null-моделей, (2) существует ли в кросс-сэмпловом спектре кластерная структура (в т.ч. доменная), (3) каков честный шумовой пол $F$ вместо $1/\sqrt{D}$.

**Локальные определения.** $C_a = \mathrm{mean}\ \cos(J^{(p_1)}_{t1}, J^{(p_2)}_{t2})$ по position-парам одного образца; $C_b = \mathrm{mean}\ \cos$ по sample-парам одного домена (pos 0); $T_{domain} = C_{within} - C_{cross}$ ($C_{within}$ = 112 пар в доменах, $C_{cross}$ = 384 междоменных, N=32 = 4×8). $r_{eff}$ — энтропический ранг: $r_{eff} = \exp(-\sum p_k \log p_k)$, $p_k = \sigma_k^2/\sum\sigma^2$. Шумовой пол: $F = 1/\sqrt{r_{eff}\,(K + D - r_{eff})}$; вердикты: $C < F$ — ORTHOGONAL, $F \le C < 3F$ — WEAK, $C \ge 3F$ — COHERENT. Конвенции пар: **pos-pk** (каноническая), **same-pk**, **raw**. T-блоки: T1 (degenerate-J exclusion), T2 (Bock 4×4 на $K^G$), T3 (bootstrap CI), T4 ($T_4(L) = C_a(L) - C_b(L)$, block-permutation по доменам, Bonferroni по слоям $p_{adj} = \min(1, p_4 \cdot n_{layers})$), T5 (Hartigan dip + β-null, moment-match), T6 (eigengap $K^F$, $K^G$), T7 (ρ(layer, $C_a$) + perm-null), T8 (ковариаты: $E, r_{eff}, r_{stable}, H, g_{uni}$).

**Данные и метод.** Exp 27 (v11, 0.8B, T4): 4 домена × 8 сэмплов, $S=64$, $K=128$, pos=0, 6 слоёв {6,12,18,19,22,23} (GDN + full-attention, контроль L23 ≈ lm_head). Gauge-free $J^{(p)}$ кешируются в jcache; post-processing — только CPU. Exp 27.5 (`experiments/exp27_5_postprocess.py`): перестановочный тест доменных меток (B=1000), spectral null (хранящие собственные значения ротации, B=100), half-split, корреляции с осями (entropy quartile), agglomerative clustering на $D^G = 1 - K^G$ (silhouette, gap, $\rho_{NN}$, cophenetic). Exp 27.6 (`experiments/exp27_6_isolation.py`): P0-приложение — T1–T8. Два раунда ревью (коллега + внутренний аудит) выловили 6 P0-багов; все закрыты, финальный прогон — run12.

Selfcheck: T3-дедуп + T5 (unimodal не отклоняется, bimodal отклоняется).

**Оговорки.** (1) T5 dip на грани критического значения (0.006–0.011 vs null_p95 ~0.005): маржа 1.1–1.5×, вердикт «pass» — минимальный, би-модальность слабее, чем заявлено selfcheck-бимодальностью. (2) N=32: разрешение $T_3$ — CI ±0.011, эффекты меньше неотличимы от нуля. (3) L23 = контроль (≈ lm_head, pre-final-RMSNorm, $\sigma_d \approx 96$–104 — норма для residual stream). (4) S=128 dip (ctx 127) — эффект длины контекста, не mid-context (пара (32,33)@S128 выше S64 pos0 на всех слоях); гипотеза GDN chunk-boundary @128 не проверена.

**Строго установленные факты** (следуют из данных без дополнительных предположений):

1. Внутридоменная когерентность Якобианов статистически неотличима от междоменной (p_perm > 0.05 на всех слоях; все bootstrap CI включают ноль).
2. Спектры матриц сходства $K^F$ и $K^G$ не содержат заметных разрывов (eigengap ratio < 1.5 для всех $i \in \{2,3,4\}$); эффективный ранг $r_{eff} \approx 24.4$–31.6 из 31.

4. Распределение попарной когерентности отвергает гипотезу унимодальности (Hartigan dip, $p < 0.05$ на всех слоях для обоих срезов $S=64$ и $S=128$).

6. Корреляция $\rho(C, \Delta h)$ отрицательна на поздних позициях (pos=8: от $-0.07$ на L6 до $-0.40$ на L22), но слабо положительна или около нуля на ранних (pos=1–4).

**Интерпретации (с оценкой вероятности).**

*Высокая (>80%):*
- **Глобальная доменная геометрия отсутствует.** Все тесты (permutation, bootstrap CI, ARI-null, eigengap) согласованно показывают отсутствие сигнала. Альтернативы: эффект $N=32$ — маловероятно (CI с ростом $N$ сужаются, но остаются широкими); math-домен маскирует сигнал — отвергнуто (T1: исключение math не улучшает сигнал); **ротационная структура** (одинаковые грамианы $JJ^T$, различие — ортогональные вращения в hidden-пространстве; vec-$C$ в ней нулевой) — отвергнута фактом 5: для неё нужно $K^G_{dd} \approx 1$, наблюдаемо 0.033–0.042. Проверка: $N=64$–128, повтор T3.
- **Кластерная структура в спектральном смысле отсутствует.** Плоский спектр (факт 2) ⇒ silhouette и gap statistic измеряют шум, а не структуру. Альтернативы: структура в нелинейном многообразии (средняя вероятность — проверка UMAP/t-SNE); размытие из-за усреднения по позициям (средняя — per-position кластеризация).
- **Readout-pull имеет фундаментальный потолок** для кросс-сэмплового выравнивания: без кросс-сэмпловой когерентности (факт 1) глобальная правка $W$ не может выровнять разные «листы» траекторий. Наиболее вероятно, что readout-pull работает только внутри траекторий (согласуется с фактом 3). Проверка: ограничить readout-pull парами одной траектории (intra-sample).

*Средняя (40–80%):*
- **Бимодальность связана с внутри-/междокументным разделением.** Факт 4 (бимодальность) при отклонённой доменной оси (факт 1): естественная альтернатива — разделение на пары внутри одного документа (высокая $C$) и между разными (низкая $C$). Альтернативы: позиция в документе (средняя), синтаксические паттерны (низкая — code-домен не выделяется). Проверка: split пар на intra-/inter-document.
- **Отрицательный $\rho(C, \Delta h)$ на поздних позициях — эффект «листов».** Близкие точки в $h$-пространстве могут принадлежать разным листам: траектории расходятся. Альтернативы: масштабный эффект (низкая — косинус масштабно-инвариантен); нелинейность поля $J(h)$ (средняя — анализ вторых производных). Проверка: локальные тангенциальные подпространства, когерентность внутри/между листами.
- **Math-домен имеет специфическую структуру** (символьная запись, формулы). Альтернативы: больше шума (короткие формулы, мало контекста) — средняя; особый набор токенов — средняя. Проверка: распределение токенов, контроль на длину контекста.

*Низкая (<40%):*
- **Латентные оси кроме доменов существуют** — но ARI с доменами не значим (T4), что снижает вероятность сильных латентных осей. Проверка: unsupervised кластеризация + атрибуция (энтропия, длина, позиция).
- **Бимодальность связана с синтаксисом** — code-домен не отличается от wiki/chat, что противоречит этой гипотезе.

**Открытые вопросы (требуют экспериментов).**
1. Механизм отрицательной корреляции с $\Delta h$ (тангенциальные подпространства, вторые производные $\nabla^2 J(h)$).
2. Природа бимодальности (intra-/inter-document split, per-position, кластеризация + атрибуция).
3. Эффект размера выборки ($N=64$–128, повтор T3; если CI не сужаются — эффект реальный, но слабый).

**Итоговая формулировка.**
- *Основной вывод:* глобальная доменная геометрия Якобианов отсутствует — внутри- и междоменная когерентность неотличимы, спектр плоский, кластерная структура в спектральном смысле не обнаружена.
- *Вторичный вывод:* $C_a$ монотонно растёт с глубиной (формирование устойчивой локальной геометрии в поздних слоях); бимодальность, вероятно, отражает внутри-/междокументное разделение.
- *Практический вывод:* readout-pull ограничен для кросс-сэмплового выравнивания; рабочая парадигма — per-sample / leaf-oriented геометрия, а не глобальная доменная.
- *Ограничение:* $N=32$; увеличение выборки может выявить слабые эффекты, но основные выводы (отсутствие доменной оси, плоский спектр) устойчивы.

### E-28. Листы и локальная кривизна поля $J$: Δ_SVD и голономия Procrustes (exp27b dense, N=32, K=128, S=128, 0.8B, слои 6/12/18/19/22/23, CPU)

E-27.5/27.6 показали fibered-структуру (когерентность вдоль сэмпла, ортогональность между) и отсутствие глобальной доменной геометрии. Oставался вопрос **листной структуры**: является ли локальная геометрия $J$ $r$-мерным многообразием (листом) с гладкой поверхностью и границами (картина ТЗ), и как она меняется с глубиной.

**Метод (CPU, на exp27b dense-кэше).** $J_t$ — gauge-free Якобиан в позиции $t$ ($t = 0 \dots 127$), 32 документа, 6 слоёв. Метрики (basis-invariant, т.е. инвариантны к выбору базиса внутри подпространства — Haar-ротация данных не меняет метрику):
- $\Delta_{\mathrm{SVD}}(t) = \max$ главный угол между топ-$r$ **правыми** подпространствами (V-подпространства сингулярных векторов) $J_t$, $J_{t+1}$;
- $\kappa(t) = \|R_{01} R_{12} R_{02}^{-1} - I\|_F$ — голономия Procrustes на тройках позиций (остаток параллельного транспорта вокруг малого треугольника) — мера локальной **кривизны** (не просто вращения);
- $r = 16$ основной, sweep $r \in \{8, 16, 32\}$; baseline — $B = 200$ случайных подпространств $\mathbb{R}^{1024}$ (Haar); границы — MAD-детектор; дегенерации (вырожденные SVD) → NaN и исключаются.

**Пространство кривизны (явное).** Обе метрики построены в **hidden-пространстве** — правых сингулярных векторах `V ⊂ R^D`: `Δ_SVD` — угол между топ-$r$ правыми подпространствами, `κ` — голономия поворотов в `R^D`. Это кривизна листа **в направлении скрытых состояний** $h$ (вопрос E-28 — структура $\mathcal{H}$). Токен-пространственный аналог (левые подпространства `U ⊂ R^K`) не вычисляется — отложен (токен-геометрия покрывается ESG-спектром `JJ^T`, §6, E-9/E-14).

**Результат (среднее по 32 документам × 126/125 позиций):**

| --- | --- | --- | --- | --- | --- | --- |
| L6  | 1.549 | 3.960 | 1.565 | 5.449 | 0/1248 | 0.000 |
| L12 | 1.542 | 3.469 | 1.565 | 5.429 | 0/1248 | 0.000 |
| L18 | 1.495 | 2.356 | 1.565 | 5.443 | 0/1248 | 0.000 |
| L19 | 1.483 | 2.170 | 1.565 | 5.434 | 0/1248 | 0.000 |

**Выводы.**
1. **L6–L22 листов нет.** Топ-16 правое подпространство $J_t$ повёрнуто на ~90° от токена к токену — в пределах случайного подпространственного baseline (1.549 vs 1.565 rad на L6). Картина ТЗ «гладкий лист с границами» **не подтверждается** в промежуточных слоях: поле $J$ там **локально случайно как подпространственное поле**.
2. **L23 (pre-final-RMSNorm / lm_head режим) — настоящий лист.** $\Delta = 0.266$ rad (15.3°), $\kappa = 0.018$ — в ~300× ниже случайной голономии, профиль **плоский** на всём документе (трети 0.261/0.269/0.268). 277 MAD-границ распределены **равномерно** по документу (средняя позиция 63.9; 78/107/92 на треть) — это **локальные шероховатости, а не сегментные границы**.
3. **Нет TZ-плоских заплаток нигде.** По порогу ТЗ 10.3 ($\kappa < 10^{-3}$) $\kappa_{\mathrm{flat}} = 0.000$ на **всех** слоях включая L23 — пол голономии L23 = 0.0175 (в 17.5× выше порога). Лист L23 — **жёсткий-но-кривой** (rigid-but-curved): локальный ремень почти не поворачивается ($\Delta \approx 0.27$ rad) и мало скручивается ($\kappa \approx 0.018$) относительно случайного, но **не закрывается**.
4. **Соотносимо с exp27.** $C_a$ (когерентность gauge-free $J$ вдоль сэмпла, 8–41×$F$ на L6–L23) — это нормировочно-направленная корреляция отдельных строк $J$; случайная скорость вращения подпространства означает, что «лист» — **не** $r$-мерный лист в промежуточных слоях, а **тонкая нить** (filament): коррелированная статистика направления, случайный локальный ремень. Листовая структура ($r=16$ лист) возникает **только в выходном режиме** (L23).
5. **Глубинный градиент = раскручивание.** $\kappa$ падает 3.96 → 0.018 от L6 к L23 (монотонно: 3.96/3.47/2.36/2.17/1.56/0.018) — локальный ремень перестаёт скручиваться с глубиной и **жёстковит** на L23. $\Delta$ держится на случайном уровне до L23, где падает в 5×. Промежуточной границы нет: изменение — **резкий переход на последнем блоке**, согласовано с прыжком $\sigma_d$ на L23 (pre-final-RMSNorm, exp27 findings).
6. **r-sweep стабилен.** $\Delta$: 1.533/1.549/1.557 (L6) и 0.253/0.266/0.303 (L23) для $r=8/16/32$ — вердикт не зависит от $r$. $\kappa$-random масштабируется ~$\sqrt{r}$ (2.75/3.96/5.43 на L6), data-$\kappa$ на L23 растёт лишь 0.012/0.018/0.028 — плоское поле с $r$-растущим числовым шумом, а не кривое.
7. **Нет вырожденных позиций** (0 из 4032), нет доменных различий на L23 ($\Delta$ 0.247–0.293 по доменам).

**Оговорки.** (1) L23 $\Delta = 0.27$ rad ≠ 0: лист **гладкий, не жёсткий**; попозиционный профиль (в JSON) не показывает систематического роста к концу последовательности. (2) Типы токенов: не в кэше (пункт ТЗ пропущен, зафиксирован в params). (3) Открыто: проверка $\kappa$ на **левой** (U-side) стороне подпространств — функциональная сторона поля — это $K=128$ токены; правая (hidden) сторона на случайном уровне может быть артефактом hidden-пространства, а не утверждением о самом отображении.

### E-34. Pre-flight 1: где сидит cross-coupling токенов (exp34, N=32, K=128, слои 6/12/18/22/23, 0.8B, CPU)

**Цель.** Локализовать источник off-diagonal структуры ESG: равномерный сдвиг (gauge), доминирующий токен или распределённый cross-talk между токенами. Результат определяет, спасаема ли per-token защита (P1) в первом порядке, и, следовательно, статус E-32 (центральный vs уточняющий).

**Метод.** Три последовательных уровня снятия cross-talk на per-sample $ESG_l^{(i)} = J_l^{(i)}(J_l^{(i)})^T$: **raw** (как есть), **gauge-free** $ESG^{(p)} = P(p^{(t)}) \cdot ESG \cdot P(p^{(t)})$ ($P$ — gauge-оператор §8, **не проектор**), **top-1 removed** $ESG - \lambda_1 u_1 u_1^T$. Основная метрика — K-инвариантная: $\rho = \mathrm{RMS(offdiag)}/\mathrm{RMS(diag)} = r/\sqrt{K-1}$; пороги: $\rho \ll 0.1$ — диагональ доминирует, $\rho \sim 0.3$ — сравнимо, $\rho \gg 0.3$ — offdiag доминирует. Нуль-модель: $J_{rand} = Q^T \mathrm{diag}(\sqrt{ESG_{ii}})$, случайный ортогональный $Q$ (16 seed-детерминированных $Q$); решающее правило — $\rho/\rho_{null}$. Агрегация: отношение считается на каждом сэмпле отдельно, затем медиана по 32 сэмплам (пул $ESG$ по сэмплам до отношения некорректен — смешивает масштабы, см. §6 «Семантика пулляции»). Слои {6, 12, 18, 22, 23}: L0 в dense-кэше нет, L19 исключён для консистентности с E-14. Sentinel: позиции с сырой (sub-stochastic) суммой $p_{128} < 0.5$ (поле $P128_{RAW}$) исключаются из медиан; доля зафиксирована в таблице.

| Слой | $\rho_{raw}$ | $\rho_{gf}$ | $\rho_{top1}$ | $\rho_{null}$ | $\rho_{raw}/\rho_{null}$ | $\rho_{gf}/\rho_{null}$ | IQR $\rho_{raw}$ | excl. fraction | uniformity$_0$† |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| L6  | 0.223 | 0.069 | 0.155 | 0.071 | 2.98 | 0.98 | 0.033 | 0.507 | 0.640 |
| L12 | 0.211 | 0.067 | 0.136 | 0.049 | 4.31 | 1.34 | 0.027 | 0.507 | 0.749 |
| L18 | 0.171 | 0.064 | 0.112 | 0.028 | 6.03 | 2.22 | 0.007 | 0.507 | 0.786 |
| L22 | 0.162 | 0.064 | 0.111 | 0.031 | 4.76 | 2.07 | 0.011 | 0.507 | 0.493 |
| L23 | 0.180 | 0.067 | 0.087 | 0.019 | 9.63 | 3.61 | 0.001 | 0.507 | 0.738 |

† uniformity$_0$ при K=128 (внутри E-34); E-10a (K=32) даёт 0.85–0.97 на L6–L18 и 0.503 на L23 — расхождение по K, не влияет на вывод (колонка контрольная). $\rho_{top1}$ отчитан на всех слоях: при $p \ne$ uniform (фокусированные сэмплы) второй и третий уровни **не совпадают** — расхождение $|\rho_{gf} - \rho_{top1}|$ само по себе сигнал.

**Контроль $\rho$ vs $|\Delta p|$.** Spearman-корреляция $\rho_{raw}$ (per-layer) с $|\Delta p|$ на том же слое, медиана по 32 сэмплам: 0.09 (L6), 0.11 (L12), 0.15 (L18), 0.29 (L22), 0.36 (L23) — часть coupling в поздних слоях сидит там, где $p$ прыгает; интерпретация $\rho$ на L22–L23 — с этой оговоркой. (Пермутац. p-value, B=1000, не вычислялись — отклонение от ТЗ, зафиксировано.)

**Выводы.**
1. Паттерн по матрице интерпретации: **$\rho_{gf} \approx 0.064$–$0.069 < 0.1$ на всех слоях** — «первый порядок диагонален». Следствие: **E-32 остаётся центральным** (уточняет второй порядок); P1 в первом порядке спасаема.
2. $\rho_{raw}$ = 0.16–0.22 — «comparable» зона: сырой offdiag значителен, но gauge-free снимает его в 3–4× — coupling в основном в gauge + доминирующем токене, не распределённый cross-talk.
3. $\rho_{gf}/\rho_{null}$ растёт с глубиной: 0.98 (L6 — остаток на уровне нуль-модели) → 3.61 (L23) — остаток cross-talk усиливается к выходу (совпадает с паттерном L18→L23 в E-13).
4. **Sentinel: 50.7% позиций** (2077/4096, одинаково по слоям — raw sum не зависит от слоя). Крупный побочный факт: top-128 токенов несут < 50% массы на половине позиций; порог 0.5 для raw-sums, видимо, слишком строг. Все медианы отчитаны по оставшимся 49.3% («уверенным» позициям); пересчёт при переосмыслении порога дешёвый (только маски).

**Оговорки.**
1. $P(p)$ — не проектор (§8 [L-gauge]): $\rho_{gf}$ нормирован, но интерпретация «сколько энергии в off-diagonal после снятия gauge» приблизительна.
2. Диагональ $ESG_{ii} = \|J_i\|^2$ — не «токен $i$ защищает себя», а «насколько логит $i$ чувствителен к $h$».
3. Малые N (N=32): bootstrap-CI широкие; отчитан IQR, не только медиана.
4. Sentinel-строки: $diag \to 0$ даёт $\rho \to \infty$; `excluded_fraction` зафиксирован (0.507, $P128_{RAW}$, порог 0.5).

**Postscript (гейт E-30).** Вывод «первый порядок диагонален → E-32 центральный» — **предварительный**: E-34 меряет $\rho_{gf}$, агрегированный по всем K=128 модам ESG, и не показывает, *где* сидит остаток ($\rho_{gf} \approx 0.064$–$0.069$). E-30 (mode decomposition) его разбирает: если сигнал несёт хвостовые моды (r > 32), картина смещается в «диагонален в топ-модах, но не в хвосте», и статус E-32 переопределяется. E-30 запускается до E-32 (`docs/run_sequence.md`). **Закрыт:** E-30 выполнен (entry ниже, §18; `results/exp30_mode_decomposition.json`); E-30b локализует остаток — он сидит в 10–20 наименьших модах ESG (хвост спектра, не в топ-модах и не равномерно).

### E-11a. Fidelity реконструкции через defrag (N=4; 0.8B, слои 6/12/18, K=32)

**Цель:** проверить, мал ли эффективный ранг $J^{(p)}$ (гипотеза дефрагментации, §11).

Метод: возмущаем $h_l$ на $\pm\varepsilon \cdot v$ (gauge / semantic / random направления, $\varepsilon \in \{0.5, 1.0, 2.0\}$), мерим KL($p_{\text{true}} \| p_{\text{pred}}$) для трёх предикторов:

- **Raw:** $z_{\text{pert}} = z_0 + J \cdot \delta$ (только по token_set)
- **Gauge-free:** $p_{\text{pert}} = \text{softmax}(\log p_0 + J^{(p)} \cdot \delta)$ на token_set
- **Defrag-r:** $p_{\text{pert}} = \text{softmax}(\log p_0 + U_r J_r \cdot \delta)$, $r \in \{4, 8, 16, 32\}$

| Perturbation | Scale | KL(raw) | KL(gf) | KL(dr4) | KL(dr8) | KL(dr32) |
| --- | --- | --- | --- | --- | --- | --- |
| gauge (L6) | 1.0 | 13.43 | 10.47 | 10.47 | 10.47 | 10.47 |
| sem_0 (L6) | 1.0 | ~13.5 | ~10.6 | ~10.6 | ~10.6 | ~10.6 |

**Выводы:**

1. **Gauge-free значительно лучше raw** (10.5 vs 13.4) — softmax-weighting убирает gauge-артефакты из линейной аппроксимации.
2. **Defrag сходится при $r=4$** — KL(dr4) = KL(dr8) = KL(dr32) = KL(gf). Эффективный ранг $J^{(p)}$ действительно мал.
3. **Но KL(gf) всё ещё ~10.5** — линейная аппроксимация ломается при $\varepsilon=1.0$. Нелинейности оставшихся слоёв доминируют. Это не баг реконструкции, это предел первого порядка.

### E-12a. Пертурбационный тест: gauge vs differential (N=8, K=64; 0.8B, слои 6/12/18)

> **Params:** N=8, K=64, ε=1.0 (`results/exp12a_perturbation_test.json` → `params`; round-3 пересчёт: добавлены `sigma_g/sigma_d`, `norm_h`, `KL_lin_*`).

Для каждого слоя находим:

- $v_g$ = правый сингулярный вектор $J$, чей левый вектор ≈ равномерен (gauge direction)
- $v_d$ = топ-правый сингулярный вектор $J^{(p)}$ (дифференциальное направление)

Возмущаем $h_l \leftarrow h_l \pm \varepsilon \cdot v$ при одинаковой норме $\|v\|=1$, $\varepsilon=1.0$. Мерим KL($p_{\text{orig}} \| p_{\text{pert}}$) и сравниваем с линейным предиктором $\mathrm{KL}_{\text{lin}}(v) = \tfrac12 \|J^{(p)} v\|^2$ ([L-fisher]).

| Слой | uniformity($u_g$) | KL$_g$ (avg ± std) | KL$_d$ (avg ± std) | ratio KL$_d$/KL$_g$ | ratio$_{\text{lin}}$ (геом. средн.) | σ$_g$/σ$_d$ (геом. средн.) | ‖$h$‖ | ε/‖$h$‖ |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 6 | 0.67–0.93 (ср 0.88) | 7.13 ± 0.72 | 7.41 ± 0.60 | 1.04× | 7× | 42× | 1.89–2.42 | 41–53% |
| 12 | 0.61–0.96 (ср 0.90) | 7.62 ± 0.58 | 7.79 ± 0.57 | 1.02× | 16× | 41× | 2.09–2.76 | 36–48% |
| 18 | 0.94–0.98 (ср 0.96) | 6.39 ± 1.02 | 6.61 ± 1.01 | 1.03× | 59× | 40× | 6.47–6.99 | 14–15% |

($u_g$ — левый сингулярный вектор в token-пространстве; $v_g$ живёт в hidden-пространстве, uniformity определён только для $u_g$.)

**Результат и честная интерпретация (round 3):**
1. **Тест НЕ в линейном режиме.** ‖δ‖ = 1 при ‖h‖ = 1.9–2.8 (L6/L12) и 6.5–7.0 (L18), т.е. ε/‖h‖ = 14–53% — это не «ε ≤ 0.1». Прежнее утверждение «в линейном режиме направления неразличимы» (ratio = 1.00×) **не подтверждено данным прогоном** и удалено.
2. **Линейный предиктор** (первый ненулевой порядок — квадратичный, [L-fisher]) даёт ratio $\mathrm{KL}_{\text{lin},d}/\mathrm{KL}_{\text{lin},g}$ = **7–59×** (растёт с глубиной): в первом порядке направления **различимы**, согласуется с [L-gauge] + [L-fisher].
3. **Полный decoder** даёт ratio = 1.02–1.04 — gauge «просачивается» через нелинейности оставшихся слоёв: квадратичный член gauge ($\|J^{(p)}v_g\|^2 \approx 0$) компенсируется высшими порядками, сравнимыми с затуханием differential-сигнала при ε/‖h‖ ~ 0.15–0.5.
4. **σ_g/σ_d ≈ 40×** — первое сингулярное число сырого $J$ (gauge-направление) на порядок больше первого сингулярного числа $J^{(p)}$: gauge-режим доминирует в сыром Якобиане. **Измерено** (JSON: поля `sigma_g`/`sigma_d`), а не предположено.

**Что подтверждено:** (а) uniformity левого сингулярного вектора $u_g$ = 0.61–0.98 (ср 0.88–0.96) — gauge direction существует; (б) в линейном (квадратичном) режиме направления **различимы** (7–59×, [L-fisher] работает); (в) «неразличимость» (ratio ≈ 1.02–1.04) — свойство **полного forward при больших возмущениях** (ε/‖h‖ ≥ 0.14), а не линейного режима. (Последующий E-0.1, §15, исключил альтернативное объяснение — фрактальности поля $J$: на масштабах $\sigma_d$ поле когерентно, первый порядок корректен.)

> **Рефрейм:** map — **направление минимальной чувствительности**. При равном destruktive budget (KL≈15) map-квантование даёт меньшее возмущение hidden space (Δh 0.24–0.84 vs 0.95–3.34), чем uniform — но **оба варианта разрушают модель полностью** (PPL 10⁶–10⁸). Это не «map сохраняет модель», а «map направляет разрушение эффективнее» (см. E-12b).

### E-12b. Квантование по карте (N=4, K=32; 0.8B, слои 6/12/18)

> **Params:** таблица — из сохранённого JSON (N=4, K=32). Скрипт уже обновлён до K=64; следующий run перезапишет значения.

Симуляция направленного квантования $h_l$:

- **Map-based:** gauge (2 бита) + 5 дифференциальных направлений (8 бит) + остальные (6 бит). Число 5 согласовано с E-11a: эффективный ранг $J^{(p)}$ мал (defrag сходится уже при $r=4$), PR(L6) ≈ 5.9 — то есть «5 направлений» — это спектральный ранг, а не фиксированная конвентация.
- **Uniform:** 4 бита на всё

| Слой | KL(map) | KL(uniform) | $\Delta h_{\text{map}}$ | $\Delta h_{\text{uniform}}$ | PPL(map) | PPL(uniform) |
| --- | --- | --- | --- | --- | --- | --- |
| 6 | 14.91 | 15.00 | 0.24 | 0.95 | 1.25M | 2.47M |
| 12 | 15.09 | 15.09 | 0.26 | 1.00 | 14.8M | 50.8M |
| 18 | 15.02 | 15.01 | 0.84 | 3.34 | 1.69M | 2.14M |

> **PPL note:** Значения PPL ~1.25M-50.8M соответствуют exp(15) ~ 3.3e6. Это ожидаемо: KL ~15 означает полное разрушение распределения (random perturbation), а не реальное квантование. Симуляция проверяет *направление* dH, не абсолютный PPL.

**Вывод:** KL одинаков (оба ~15), но map-based достигает этого при $\Delta h \approx 0.24$ vs uniform $\Delta h \approx 0.95$. Map-based квантование создаёт в 4× меньшее возмущение в hidden space при том же KL.

> **Оговорка:** оба варианта непригодны (PPL 10⁶–10⁸, полное разрушение распределения). Меньший Δh не означает «лучше сохраняет модель» — карта лишь эффективнее направляет разрушение в чувствительные направления. Это предельный тест, не практическое применение.

### E-12c. Мост оригинал ↔ квантованная (N=4, K=32; 0.8B, слои 6/12/18)

> **Params:** таблица — из сохранённого JSON (N=4, K=32); скрипт `experiments/exp12c_bridge_quantized.py` на K=64.

Softmax-мост между оригиналом и каждой схемой квантования (cosine similarity градиентов):

| Слой | $\mathcal{L}$(orig ↔ map) | $\mathcal{L}$(orig ↔ uniform) | $\mathcal{L}$(map ↔ uniform) |
| --- | --- | --- | --- |
| 6 | 0.001 | 0.020 | 0.021 |
| 12 | 0.001 | 0.015 | 0.016 |
| 18 | 0.001 | 0.014 | 0.015 |

**Вывод:**

1. **Map-based ≈ идентичен оригиналу по НАПРАВЛЕНИЮ ЯКОБИАНА** — мост 0.001 (почти ноль). *Оговорка: это направление градиента, не функция — по E-12b обе схемы полностью разрушают PPL (10⁶–10⁸); map лишь 15–20× меньше искажает Jacobian-направление.*
2. **Uniform далеко** — мост 0.014–0.020, в 15–20× больше.

## 19. Causal lever и поведение

**Главный вывод (наверх секции).** Геометрический bridge и поведенческая top-p retention **антикоррелированы**: readout-редакция монотонно «улучшает» мост (0.60→0.921), одновременно разрушая поведение. Точечных якобианов недостаточно — оптимизация по одной точке = Goodhart на геометрическом прокси.

### E-16a. Readout-pull как доза-ответ (0.8B → target, пара 31_23; Exp 16 v2)

> **Params:** lm_head-only edit (readout), loss = (1−cos(J_S_p, J_tgt_p)) + 0.1·KL(leash), Adam lr=1e-3, 100 steps, eval every 10, K=256, N=4 (paired by input_ids), device=cuda. GPU T4, 126s.

Доза = ‖ΔW‖_F (Frobenius norm readout-редакции); bridge = cosine readout (exp16-метрика, ≠ exp19 per-token), KL = leash-метрика (full-vocab, base vs edited). База при ΔW=0: **bridge=0.599965** (= exp19 baseline — совпадает), KL=0.

|---|---|---|---|
| 0 | 0.0 | 0.599965 | 0.0 |
| 10 | 61.8 | 0.6173 | 0.4808 |
| 20 | 77.4 | 0.6460 | 0.5970 |
| 40 | 91.6 | 0.6843 | 0.3627 |
| 60 | 98.6 | 0.7137 | 0.2836 |
| 80 | 100.2 | 0.7359 | 0.2608 |

**Вывод:** readout-редакция (lm_head-only) — **causal lever**: bridge монотонно растёт 0.60→0.754 (т.е. мост к target-подпространству **улучшается**), при этом KL leash держит (0→0.24, damage bounded). **Коло (knee, перестановка bridge gain ниже knee_tol=0.001) в пределах 100 шагов не достигнуто** — bridge продолжает расти, поэтому **α* не определена**; 0.3207 — просто доза при step 100 (не «оптимальная»). Т.е. readout-редакция — самое дешёвое управление (1 матрица ‖W‖≈314, не вся сеть), и она движет мост в сторону target с ограниченным collateral (KL). **V4 (1000 шагов)** — continuation этого прогона, bridge достигает **0.921** (‖ΔW‖=128.8); см. E-16b (поведенческая проверка). V1 (alpha sweep как trust-region caps) **VOID** — caps ≥0.1 не bind, α не был дозой (его 'α*=0.01' = артефакт первого slope); v2 чинит определение дозы. **Оговорка:** exp16 (analytical last-layer readout, bridge 0.60→0.754) и exp19 (per-token full-path, baseline 0.600) — **разные величины bridge**, напрямую несравнимы (structural, не bug).

### E-16b. Поведенческая проверка LORA: top-p retention (Exp 16 v4)

> **Params:** финальный ΔW из exp16 v4 (‖ΔW‖_F=128.8, ‖W‖≈314, bridge@end=0.921) накладывается на lm_head 0.8B; поведение измеряется на **held-out** запросах (≠ training queries) тремя путями — base 0.8B / 0.8B+LORA / 4B-учитель. Метрика — **top-p retention** (p=0.9): доля массы вероятностей модели, попадающая в top-p регион учителя (top-p set = минимальный префикс, покрывающий 0.9 массы). Т.к. топ-k (top-10) — хрупкий индикатор (малейший шов двигает конкретный член), оценка построена на top-p retention как на робастной массовой метрике.

**Single-edit (s=1, чистые held-out вопросы, n=6):**

| Метрика (vs 4B-учитель) | base 0.8B | 0.8B + LORA |
| --- | --- | --- |
| Масса модели в top-p(0.9) регионе учителя | **0.841** | **0.016** |
| Масса учителя в top-p(0.9) регионе модели | **0.888** | **0.173** |

**Доза-ответ top-p retention (s ∈ {0.1, 0.25, 0.5, 0.75, 1.0}, C4-heldout, n=6):**

| s (доля ΔW) | top-p retention | bridge (exp16-metric) |
| --- | --- | --- |
| 0 (base) | **0.837** | 0.603 |
| 0.10 | 0.809 | (растёт) |
| 0.25 | 0.746 | ↑ |
| 0.50 | 0.666 | ↑ |
| 0.75 | 0.523 | ↑ |
| 1.00 | **0.416** | **0.921** |

(Метрики top-k: agreement k=10: 0.733→0.067; garbage k=10 (вне top-200 учителя): 0→0.450 — оба монотонны.)

**Вывод.** LORA exp16 **не улучшает** поведение, а **ломает** его. Уже при **s=0.1** (10% финального edit) top-p retention падает 0.837→0.809; при полном edit — до 0.016 (чистые вопросы) / 0.416 (C4), т.е. модель выводится **с manifold** (масса уходит в нереалистичные для учителя токены). Критично: это происходит **одновременно** с **монотонным ростом bridge** (0.603→0.921) вдоль той же траектории. Т.е. **геометрический bridge и поведенческая top-p retention антикоррелированы**: мост «улучшается», поведение деградирует.

**Почему (механизм Goodharta).** Эксперимент 16 тянет **одну точку** (один last-layer hidden state → одно направление ΔJ, одна метрика bridge по одной паре слоёв). Оказалось, что такую точку можно «подогнать» (bridge 0.60→0.92) **без улучшения — а с разрушением** реального поведения. Точечный якобиан не несёт ограничения на **остальные** точки/домены, поэтому оптимизация по нему = **Goodhart на геометрическом прокси**: метрика растёт, качество гниёт. Чтобы это исправить, метрика/ограничение должны быть **многоточечными**: не точка, а **гиперповерхность из якобианов по доменам** (и по глубине), т.е. нельзя подогнать одну точку, не сломав другие. Это направление — следующая работа (после exp16/exp19).

### Практические следствия

1. **Карта $J^{(p)}$ работает для направленного квантования** (E-12b,c): map-based при 4× меньшем Δh даёт тот же KL, мост ≈ 0. Оба варианта непригодны как реальные схемы (PPL 10⁶–10⁸).
2. **Defrag экономит backward** (E-11b), но для bridge-моста нужен полный ранг (E-11c) — defrag и мост решают разные задачи.
3. **Gauge-direction реален и поведенчески активен** (E-12a): нелинейности decoder пропускают gauge-сигнал; он «невидим» только в линейном приближении.
4. **Мост не заменяет KL, но дополняет его:** KL — один номер, мост — послойная карта расхождения.
5. **Рабочая парадигма — per-sample / leaf-oriented геометрия** (E-0.1, E-27.5/27.6, E-28), а не глобальная доменная: Грамианы sample-local, доменная ось — шум.
6. **Первый порядок P1 решён E-34:** статус per-token защиты (P1) в первом порядке определяется $\rho_{gf}$; при $\rho_{gf} \ll 0.1$ (наблюдено 0.064–0.069) защита спасаема, при $\rho_{gf} \sim 0.3$ — нет. Это не отменяет E-32 (второй порядок), но переопределяет его рамку: E-32 остаётся центральным, хвостовая структура остатка $\rho_{gf}$ — задача E-30.

### Что это значит для читателя

Мост — рабочая послойная метрика выравнивания: она монотонна, доменно-робастна, не артефакт фазы архитектуры, и её можно двигать readout-редакцией. Но (1) метрика чувствительна к полным Якобианам — defrag её ломает; (2) «улучшение» моста в одной точке не улучшает поведение — E-16b показывает Goodhart на геометрическом прокси; (3) все количественные оценки предварительны (N ≤ 32, без CI) — см. §21.

## 21. Ограничения

Свод всех ограничений v3.3 (§6 «Известные ограничения», оговорки §11, оговорки §13.1). Сгруппированы: (a) методологические, (b) статистические, (c) инфраструктурные. Дубли убраны.

### (a) Методологические

1. **Локальность Якобиана.** Якобиан — касательная в конкретной точке. Агрегация по $N$ сэмплам частично решает проблему, но не полностью. **E-0.1 уточняет границу:** поле $J$ когерентно вдоль последовательности ($C(\sigma_d) = 0.33$–$0.87$ по глубине) и не когерентно поперёк распределения сэмплов ($C \approx -0.003$–$0.30$, обычно 0.003–0.05) — Грамианы строятся sample-local, без пулляции по домену.
2. **Неортогональность $E$.** Матрица эмбедингов не ортогональна. Проекция $J \cdot E^T$ не изометрична. Проверяется E-8.
3. **Ранние слои.** Для $l < n/4$ градиент может затухнуть: строки с $J_S[i] = 0$ маскируются (относительный порог, §9, E-1), что порождает sentinel 1.000 (см. §17, E-6).
4. **Линейный предиктор.** В линейном (квадратичном, [L-fisher]) режиме gauge и differential **различимы** (ratio$_{\text{lin}}$ = 7–59× в E-12a). При ε/‖h‖ ~ 14–53% (полный forward, ε=1.0) ratio сжимается до 1.02–1.04 — нелинейности оставшихся слоёв доминируют, и линейный предиктор по этому полному-decoder KL ненадёжен (E-12a, E-11a: линейный предиктор ненадёжен в глубоких слоях). Якобиан корректен в первом (квадратичном) порядке; для возмущений масштаба ‖h‖ нужны higher-order методы.
5. **Сравнимость моста.** Абсолютная величина моста между доменами несравнима (разные распределения вероятностей); монотонность — сравнима (E-13). Trace значения при разных K не сравнимы.
6. **Goodhart на геометрическом прокси.** Точечный bridge оптимизируем без улучшения поведения (E-16b); многоточечная метрика — следующая работа.
7. **E-6 L18 SNR (вынесен из секций).** Эксперимент «Spektrum vs depth r» (N=8, K=256, слой 18: SNR = 2.803 r-инвариантен, PR 2.15→16.91, gauge share 0.602→0.199) сознательно не перенесён в секции v4.0 — его вывод (спектр L18 не low-rank) дублируется E-14 (§17) на K=64. Данные и вывод — в Приложении B.1.

### (b) Статистические

8. **Малая статистическая мощность.** N = 1–32 в зависимости от эксперимента (E-6 — N=16, E-0.1 — N=8/домен, E-27 — всего 32 = 8/домен); ключевые утверждения валидированы на N=16–32, большинство таблиц — N≤8. ### (c) Инфраструктурные

13. **Точность.** Модели на CPU — float32 обязателен (fp16 на CPU в 10× медленнее; применение fp16 требует отдельной валидации); матрица $J$: $|\mathcal{S}| \times D$ (256×2560 = 655 360 float32 = 2.5 MB) — приемлемо. GPU-прогоны (E-0.1, E-10b, E-11b, E-16, E-27) — T4.

Полный список — Приложение B, колонка «примечания».

## C.1. Вычисление Якобиана (из §9)

```python
def compute_jacobian_for_tokens(
    model,
    layer_idx: int,
    input_ids: torch.Tensor,       # [1, S]
    attention_mask: torch.Tensor,   # [1, S]
    token_set: list[int],           # глобальный набор 𝒮, K = len(token_set)
    prefix_cache=None,              # опциональный переиспользуемый кэш префикса (v23.1)
) -> torch.Tensor:
    """
    Якобиан логитов по скрытому состоянию слоя layer_idx
    для последнего токена, только для токенов из token_set.
    Возвращает: J [K, D] (ненормализованный, dtype модели).
    """
    model.eval()
    S = input_ids.shape[1]

    # ============================================================
    # ПРОХОД 1: Префикс (все токены кроме последнего) -> кэш.
    # КРИТИЧНО: кэш = состояние ДО последнего токена (§9).
    # Переиспользуется, если вызывающий передаёт prefix_cache
    # (exp17: h из KL-forward не дублируется).
    # ============================================================
    if prefix_cache is None:
        with torch.no_grad():
            prefix_cache = model(
                input_ids=input_ids[:, :-1],
                attention_mask=attention_mask[:, :-1],
                use_cache=True,
                output_hidden_states=False,
            ).past_key_values

    # ============================================================
    # ПРОХОД 2: Полная последовательность -> скрытое состояние
    # ============================================================
    # hidden_states[0] = эмбеддинги, hidden_states[l+1] = выход слоя l
    h = model(input_ids=input_ids, attention_mask=attention_mask,
              output_hidden_states=True).hidden_states[layer_idx + 1][:, -1:, :]
    # dtype модели (fp16 на GPU; .float() дал бы mismatch в декодере)
    model_dtype = next(model.parameters()).dtype
    h = h.to(model_dtype).detach().requires_grad_(True)

    # enable_grad: декодерный проход и batched backward обязаны работать
    # даже из torch.no_grad() вызывающего (eval-циклы exp18/19).
    with torch.enable_grad():
        logits = _run_decoder_pass(model, prefix_cache, h, S, layer_idx)
        J = _compute_jacobian_rows(logits, h, token_set)
    return J  # [K, D], ненормализованный


def _run_decoder_pass(model, prefix_cache, h, S, layer_idx):
    """Декодит h через оставшиеся слои с клоном кэша префикса."""
    # ручной клон прямым присваиванием атрибутов (C.2); in-place запись
    # в сохранённый узел графа чинит _clone_gdn_states_on_entry (§9)
    cache_clone = _deep_clone_cache(prefix_cache)
    text_model = _lm_module(model)  # flat: model.model; mm-wrapper: .language_model

    # MRoPE: 4 компонента, все = S-1 (позиция последнего токена, 0-indexed)
    pos = torch.full((4, 1, 1), S - 1, dtype=torch.long, device=h.device)
    text_position_ids, rope_position_ids = pos[0], pos[1:]
    position_embeddings = text_model.rotary_emb(h, rope_position_ids)

    x = h  # [1, 1, D]
    n_layers = model.config.num_hidden_layers
    start = layer_idx + 1

    # Маски строится ЯВНО (create_causal_mask для full_attention,
    # create_recurrent_attention_mask для linear_attention/GDN) —
    # не "mask=None": при seq_len=1 с кэхом это путь, на котором
    # трансформеры 5.15 ожидает маску по layer_type.
    causal_mask_mapping = _build_causal_masks(text_model, text_position_ids, cache_clone, x)

    with _clone_gdn_states_on_entry():  # in-place copy_ vs сохранённые узлы графа (§9)
        for i in range(start, n_layers):
            layer_type = model.config.layer_types[i]
            x = text_model.layers[i](
                x,
                position_embeddings=position_embeddings,
                attention_mask=causal_mask_mapping[layer_type],
                position_ids=text_position_ids,
                past_key_values=cache_clone,
            )

    x = text_model.norm(x)
    return model.lm_head(x[:, -1, :])  # [1, V]


def _compute_jacobian_rows(logits, h, token_set):
    """ОДИН батченный backward вместо цикла по токенам (3–15x на T4).

    grad_outputs=eye(K) даёт все K строк за один проход (vmap-style);
    верифицировано идентичным циклу на синтетических графах.
    """
    K = len(token_set)
    J = torch.autograd.grad(
        outputs=logits[0, token_set],
        inputs=h,
        grad_outputs=torch.eye(K, device=h.device, dtype=h.dtype),
        is_grads_batched=True,
        retain_graph=False,
    )[0]
    return J[:, 0, 0, :]  # [K, D]
```
## C.2. _deep_clone_cache (GDN in-place мутации; из §9)

```python
def _deep_clone_cache(cache):
    """Deep-клон DynamicCache. КРИТИЧНО: прямое присваивание атрибутов,
    НЕ конструкторские kwargs.

    Оба типа слоёв глотают незнакомые kwargs: DynamicLayer(keys=...) и
    LinearAttentionLayer(conv_states=..., ...) молча ОТБРАСЫВАЮТ состояние
    и дают пустой кэш (каждый слой видит только текущий токен / GDN считает
    токен первым в последовательности). Поэтому — атрибуты напрямую.

    * DynamicLayer (full attention): keys / values / is_initialized / dtype /
      device. Без них update() лениво инициализирует пустой кэш.
    * LinearAttentionLayer (GDN): все state-поля КОПИРУЮТСЯ ДИНАМИЧЕСКИ
      через обход vars(layer) (не хардкод имён полей 5.15.1 — другие
      версии transformers называют часть полей иначе): тензоры — clone+detach,
      словари тензоров (conv_states, recurrent_states, ...) — поэлементно,
      скаляры/flag-dicts (has_previous_state и т.п.) — deepcopy.

    Объектные атрибуты САМОГО кэша (vars(cache): на 5.15.1 — offloading, в 4.x
    — _seen_tokens) копируются после цикла по слоям; assert get_seq_length()
    после клона — тихую порчу на версии с объектным учётом длины превращает
    в громкий сбой.

    deepcopy(prefix_cache) на 5.15.1 ТАКЖЕ даёт независимые копии (мутации
    изолированы); ручной клон нужен для (а) detach (нет паразитных
    CopyBackwards-узлов в enable_grad-декоде) и (б) устойчивости к
    переименованию полей слоёв. Ни один клон не чинит in-place-запись в
    сохранённый узел графа — этим занимается _clone_gdn_states_on_entry.
    """
    import copy as _copy

    def _cl(t):
        return t.clone().detach() if t is not None else None

    new_cache = DynamicCache()
    for idx in range(len(cache.layers)):
        layer = cache.layers[idx]
        if isinstance(layer, DynamicLayer):
            # НЕ vars()-обход: поля full-attention стабильны между версиями,
            # переименование падает ГРОМКО (AttributeError), а не тихо.
            # GDN-ветка ниже ОБЩАЯ — поля GDN действительно дрейфуют.
            nl = DynamicLayer()
            nl.keys = _cl(layer.keys)
            nl.values = _cl(layer.values)
            nl.is_initialized = layer.is_initialized
            nl.dtype = getattr(layer, "dtype", None)
            nl.device = getattr(layer, "device", None)
            for k, v in vars(layer).items():       # forward-compat safety net
                if k not in vars(nl):
                    setattr(nl, k, _copy.deepcopy(v))
            new_cache.layers.append(nl)
        else:  # LinearAttentionLayer (GDN): generic vars()-обход
            nl = LinearAttentionLayer()
            for k, v in vars(layer).items():
                if isinstance(v, torch.Tensor):
                    setattr(nl, k, _cl(v))
                elif isinstance(v, dict) and v and all(
                    isinstance(x, torch.Tensor) for x in v.values()
                ):
                    setattr(nl, k, {kk: _cl(xv) for kk, xv in v.items()})
                else:
                    setattr(nl, k, _copy.deepcopy(v))
            new_cache.layers.append(nl)
    # Объектное состояние кэша (offloading на 5.15.1; 4.x: _seen_tokens):
    # свежий DynamicCache() сбросил бы его; list-атрибуты не копируем
    # (layers уже собран заново; алиасинг чужого списка не допустим).
    for k, v in vars(cache).items():
        if k == "layers" or isinstance(v, list):
            continue
        setattr(new_cache, k, _copy.deepcopy(v))
    # Страховка: клон отчитывается о той же длине последовательности.
    assert new_cache.get_seq_length() == cache.get_seq_length()
    return new_cache

# Детач: префиксный кэш — чистые данные (построен под no_grad); detach убирает
# бессмысленные CopyBackwards-узлы в enable_grad-декоде. НО in-place copy_ из
```

## C.3. jacobian_gap (из §7; из `prism/bridge.py`)

```python
def jacobian_gap(
    J_L: torch.Tensor,       # [K, D_L] — Якобиан старшей модели
    J_S: torch.Tensor,       # [K, D_S] — Якобиан младшей модели
    E_L: torch.Tensor,       # [V, D_L] — эмбеддинги старшей
    E_S: torch.Tensor,       # [V, D_S] — эмбеддинги младшей
    probs_L: torch.Tensor,   # [K] — вероятности токенов в старшей модели
    threshold: float = 0.0,  # абсолютный порог на ОБЕ norms; дефолт 0.0 =
                             # sentinel-only (маскируются только нулевые строки).
                             # Decay-маска: вызывающий сам передаёт абсолютный τ;
                             # относительный τ_l = 0.01·median(‖J_S[i]‖) (§7, E-6)
                             # вычисляется вызывающим.
) -> float:
    """Gap (lower=better) = weighted (1 - cos) по валидным строкам.

    Терминология v4.0: gap = 1 - bridge при равных весах. Вызывающий,
    отчитывающийся по «bridge», инвертирует: bridge = 1 - jacobian_gap(...).
    Legacy-алиас `jacobian_bridge` удалён (имя bridge + направление GAP —
    ловушка инверсии метрики); инверсия живёт в экспериментальных ядрах.
    """
    G_inv = _inverse_gramian(E_S)       # pinv(E_S^T E_S), диск-кэш (§5)
    J_L_proj = _project_to_vocab(J_L, E_L)      # [K, D_L] @ [D_L, V] → [K, V]
    J_S_target = _project_to_small(J_L_proj, E_S, G_inv)  # [K, V] → [K, D_S]
    mask = _valid_mask(J_S, J_S_target, threshold)
    if mask.sum() == 0:
        return 1.0  # sentinel (§7)
    return _weighted_cosine_loss(J_S, J_S_target, probs_L, mask)


def _inverse_gramian(E: torch.Tensor) -> torch.Tensor:
    """(E^T E)^{-1} через torch.linalg.pinv (SVD); кэш: память + диск
    (results/.gramians/), ключ = SHA-256(shape|device|E[0]|E[-1]|10 mid-rows) — см. §5."""
    key = _gramian_key(E)
    if key not in _gramian_cache:
        path = os.path.join(_GRAMIAN_DIR, f"{key}.pt")
        if os.path.exists(path):
            _gramian_cache[key] = torch.load(path, weights_only=True)
        else:
            _gramian_cache[key] = torch.linalg.pinv(E.float().T @ E.float())
            os.makedirs(_GRAMIAN_DIR, exist_ok=True)
            torch.save(_gramian_cache[key], path)
    return _gramian_cache[key].to(E.device)


def _valid_mask(J_S, J_target, threshold):
    """Маска по обеим нормам: (‖J_S[i]‖ > τ) & (‖J_target[i]‖ > τ)."""
    n1 = J_S.float().norm(dim=1)
    n2 = J_target.float().norm(dim=1)
    return (n1 > threshold) & (n2 > threshold)


def _weighted_cosine_loss(J_S, J_target, probs, mask) -> float:
    cos_sim = torch.nn.functional.cosine_similarity(
        J_S.float()[mask], J_target[mask], dim=1,
    )  # eps=1e-8 по умолчанию
    w = probs[mask] / (probs[mask].sum() + 1e-8)   # нормировка по незамаскированным (§7)
    return (w * (1.0 - cos_sim)).sum().item()
```

```python
def run_layer_diagnostics(
    model_large, model_small,
    token_set, layer_mapping, samples,
    results_dir="results", exp_name="exp2_heatmap",
) -> dict[str, float]:
    """Gap (lower=better) для всех пар слоёв; E-1 (identity) и E-2 (heatmap).

    E-1 — run_identity_test: ta же модель и как large, и как small,
    uniform_layer_mapping → gap ≈ 10⁻⁸. Результат сохраняется в
    results/<exp_name>.json.
    """
    E_L, _ = extract_embeddings(model_large)
    E_S, _ = extract_embeddings(model_small)
    results = {}
    for l_L, l_S in layer_mapping.items():
        losses = []
        for sample in samples:
            input_ids = sample["input_ids"].to(model_large.device)
            attention_mask = sample["attention_mask"].to(model_large.device)
            J_L = compute_jacobian_for_tokens(
                model_large, l_L, input_ids, attention_mask, token_set)
            J_S = compute_jacobian_for_tokens(
                model_small, l_S, input_ids, attention_mask, token_set)
            # Вероятности токенов из token_set в старшей модели (§7)
            with torch.no_grad():
                logits_L = model_large(input_ids=input_ids).logits[:, -1, :]
                probs_L = torch.softmax(logits_L[0, token_set], dim=-1)
            loss = jacobian_gap(J_L, J_S, E_L, E_S, probs_L)
            losses.append(loss)
        results[f"{l_L}->{l_S}"] = sum(losses) / len(losses)
    _save_results(results, exp_name, results_dir)
    return results
```

## C.5. ESG (из §11)

```python
def compute_esg(jacobians: list[torch.Tensor], n_components: int = 32):
    """ESG от списка Якобианов ОДНОЙ траектории (позиций одного документа).

    Пул: G = (1/N) Σ_i J_i J_i^T,  J_i: [K, D] → G: [K, K].
    Пул ВНУТРИ сэмпла валиден (C_a = 8–41× F, E-27.6); междосеамплыный
    пул НЕВАЛЕН (E-0.1: C_b ≈ 0.003–0.05, J почти ортогональны) —
    по сэмплам агрегируем только скаляры (λ, PR, SNR, r_eff).

    Returns: eigenvalues [min(n_components, K)] (по убыванию), eigenvectors [min(n_components, K), K]
    """
    _validate(jacobians)  # формы и device
    G = _build_gramian(jacobians)  # (1/N) Σ J_i J_i^T
    return _spectral_decomposition(G, n_components)


def compute_esg_per_sample(sample_jacobians, n_components=32):
    """Sample-local ESG: один Грамиан на сэмпл, без междосеамплыного пула.

    Args: sample_jacobians: list по сэмплам, каждый — list по позициям, J: [K, D]
    Returns: (eigenvalues: list[n_samples] × [n_components],
              eigenvectors: list[n_samples] × [n_components, K])
    """
    eigenvalues, eigenvectors = [], []
    for Js in sample_jacobians:
        ev, evec = compute_esg(Js, n_components=n_components)
        eigenvalues.append(ev); eigenvectors.append(evec)
    return eigenvalues, eigenvectors


def _build_gramian(jacobians):
    U, device = jacobians[0].shape[0], jacobians[0].device
    G = torch.zeros(U, U, device=device, dtype=torch.float)
    for J in jacobians:
        G += J.float() @ J.float().T
    return G / len(jacobians)


def _spectral_decomposition(G, n_components):
    eigenvalues, eigenvectors = torch.linalg.eigh(G)
    idx = eigenvalues.argsort(descending=True)
    return (eigenvalues[idx][:n_components],
            eigenvectors[:, idx][:, :n_components].T)  # [n_components, K]
```

## C.7. Глобальный набор токенов 𝒮 (из §12)

```python
import torch
from collections import Counter

def build_global_token_set(model, calibration_samples, K=64):
    """Собирает глобальный набор токенов из top-K логитов на всех сэмплах."""
    token_counter = Counter()
    model.eval()

    device = next(model.parameters()).device
    with torch.no_grad():
        for sample in calibration_samples:
            outputs = model(
                input_ids=sample["input_ids"].to(device),
                attention_mask=sample["attention_mask"].to(device),
            )
            # Берём логиты последнего токена
            logits = outputs.logits[:, -1, :]  # [1, V]
            top_indices = logits.topk(K, dim=-1).indices[0]  # [K]
            token_counter.update(top_indices.tolist())

    # Топ-K самых частых токенов (most_common(K) ограничивает K сам)
    U = [token_id for token_id, _ in token_counter.most_common(K)]
    return sorted(U)
```
