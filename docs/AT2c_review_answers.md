## MAJOR 1 — «b̂ ≡ 0 ТОЧНО» ложно для k≥1 (закрыто)

Подтверждено (включая независимую симуляцию ревьюера: k=1 → 2.0e-3,
k=8 → 2.3e-2 rel max|W|): X центрирован по t=0..127, фит — по t=0..127−k ⇒
1ᵀX_slice = −Σ_{t≥128−k} X_c ≠ 0 ⇒ b̂ = −(1ᵀXf·W)/n ≠ 0 при k>0
(1ᵀyf = 0 для centered-цели).

Правки в ТЗ:
- Преамбула C2: «intercept ≡ 0 точно» → «mean training target = 0 ⇒
  intercept: при k=0 ≡ 0 ТОЧНО; при k>0 — малая коррекция порядка
  1e-3…1e-2 (≪ DELTA_MIN, ≪ C2-сдвиг)».
- §3 Estimator: переформулировано полностью: k=0 — ≡ 0 ТОЧНО (X и фит на
  одном наборе позиций); k>0 — b̂ = −(1ᵀXf·W)/n с числами симуляции;
  «НЕ конфаунд, report-only»; числовая проверка — смок §11 (k=0: < 1e-10;
  k>0: < 1e-2) — ссылка на «гейт S6» убрана (S6 = P-zero только).
- §11 Centering-smoke: порог 1e-10 заменён раздельным: k=0 → < 1e-10;
  k>0 → < 1e-2 (превышение = STOP — claim сломан). designed-сценарий
  больше не проваливается по построению.

Согласен с оценкой влияния: смещение ~1e-3…1e-2 ≪ DELTA_MIN = 0.01 и ≪
C2-сдвиг 17–28 — на ответ T2 не влияет; C2-фикс (исчезновение per-док
сдвига) действует в полном объёме.

## Pre-smoke фикс (после r3-PASS, до запуска): k=0 intercept-порог

**Обнаружено целевым f32-экспериментом** (34 с, реальные данные L6,
стационарный top/weak-tail/haar, centered-цель, LOO-ridge r=7 α=1, f32-данные +
f64 Gram/solve — тот же pайплайн, что в T2.1b/диагностике; `np.ones` в
`hstack` апкастует Xb до f64 — идентично T2.1b и диагностике):
**|b̂|/max|W| при k=0 = 4.4e-8 (top), 6.4e-8 (weak-tail), 5.9e-8 (haar) — max по 32 дока.**

Следствие: TZ-claim «k=0: b̂ ≡ 0 ТОЧНО» верен только в реальной арифметике; в
f32 — уровень округлений ~1e-8 (1ᵀyf ≠ 0 строго из-за f32-складки centered-дока).
Симуляция r1-ревьюера (k=0 → 1.7e-16) была f64 — misleading для реального
pайплайна. Порог «k=0 → < 1e-10» (TZ §3/§11.2) был бы невыполним ПО
КОНСТРУКЦИИ — S6c-гейт остановил бы main-прогон на старте.

**Фикс (4 места TZ, код — S6c-порог):**
1. L19 (преамбула C2): «при k=0 ≡ 0 ТОЧНО» → «при k=0 — по сути нулевой
   (f32-уровень округлений, pre-smoke замер: |b̂|/max|W| ≤ 6.4e-8)».
2. L91 (§3 Estimator): «при k=0: b̂ ≡ 0 ТОЧНО (…1ᵀyf = 0)» → «при k=0:
   b̂ ≈ 0 (в реальной арифметике 1ᵀyf = 0; в f32 — уровень округлений:
   pre-smoke замер 4.4e-8…6.4e-8)».
3. L102 (§3): «k=0: < 1e-10» → «k=0: < 1e-6 — f32-уровень округлений,
   pre-smoke замер ≤ 6.4e-8».
4. L296 (§11.2): «k=0 → |b̂|/max|W| < 1e-10 (≡ 0 ТОЧНО)» → «k=0 →
   |b̂|/max|W| < 1e-6 (f32-уровень округлений; pre-smoke замер ≤ 6.4e-8;
   «≡ 0 ТОЧНО» — только в реальной арифметике)».

**Почему 1e-6 (а не 1e-7/1e-8):** зазор 15× над max замера (6.4e-8) —
smoke на ДРУГОМ пуле (2 дока) может дать чуть больший шум; при этом 1e-6
всё ещё на 3 порядка ниже k=1 значения (2.0e-3) — разграничение
«k=0 — по сути ноль / k>0 — реальная коррекция» сохранено. S6 (P-zero,
L194) НЕ тронут: там f64-блок-солвер (Xf = zeros(f64)) — W_X = 0 и
intercept = mean — тождества в f64, резидуал ~1e-16, порог 1e-10 исполним.

Код: S6c-гейт `thr = 1e-6 if k == 0 else 1e-2`.

## Pre-smoke r6 (S6c-дизайн: cos-вклад вместо весового proxy)

**Проблема, пойманная pre-main замерами** (2 скрипта, ~3 мин, реальные данные,
точный pайплайн T2.1c — stationary J-базис r=7, centered-цель, LOO-ridge):

1. Весовое отношение |b̂|/max|W| (TZ-proxy r4) НЕ гатится единым порогом на
   J-слоях: k=0: pca-арм 1.2e-6…3.4e-6 (> 1e-6); k>0: pca до 5.4e-2,
   top L22 k=8 до 1.8e-2 (> 1e-2). Proxy arm-зависим (шкала/условия фич).
2. L23-контроль: k=0 pca 3.95e-5, k=1 pca 4.4e-1 — контроль вообще не в
   клетке T2 (§5: «L23 — контроли, не в вердикт»), claim §3 на него не
   распространяется.
3. РЕАЛЬНОЕ количество (TZ §3 claim про cos): |cos(ŷ+b̂·1, y_c) − cos(ŷ, y_c)|
   per позиция, weighted mean, max по докаМ:
   - J-армы: k=0 ≤ 5.2e-8; k=1 ≤ 2.0e-3; k=2 ≤ 4.0e-3; k=4 ≤ 7.6e-3;
     k=8 ≤ 1.26e-2 (max: L18 k8 weak_mid).
   - Попарный конфаунд (|dcos_a − dcos_b|, J_ARMS): max = 8.7e-3 (L22 k8
     top−weak) < DELTA_MIN = 0.01.
   - uniform: до 3.92e-2 (L6 k8) — 1-D фича, intercept механически велик;
     uniform — floor, не в вердикт/дерево.

**Решение (TZ r6, 3 места):**
1. §3 Estimator: claim переформулирован на измеренные cos-значения
   (k=1 ≤ 2e-3 … k=8 ≤ 1.26e-2; попарный конфаунд ≤ 8.7e-3 < DELTA_MIN);
   весовое отношение — report-only (arm-зависимый proxy); «≪ DELTA_MIN»
   заменено честным «≤ 1.3×DELTA_MIN per-arm; конфаунд < DELTA_MIN».
2. §11.2 Centering: S6c-гейт = cos-вклад b̂ на J-армах (L ∈ {6,12,18,22}):
   per (L,k,arm) max_d weighted-mean |dcos| ≤ 0.02 (×1.6 над замером 1.26e-2)
   И попарный конфаунд (J_ARMS) ≤ DELTA_MIN (замер 8.7e-3). Uniform/L23 —
   report-only. ybar-check (< 1e-5) — без изменений.
3. Преамбула C2: sync с §3.

**Почему пороги безопасны:** smoke-пул (2 дока) — подмножество пула 32 доков
тот же pайплайн → замер smoke ≤ 32-док замера (max по меньшему множеству ≤
max по большему). Main-прогон = те же 32 доки = замер (бит-в-бит при том же
thread-pinning).
Код: S6c пересобран (dcos per (L,k,arm), гейт J-армы + конфаунд, остальное
report-only; uniform/L23 без гейта).
