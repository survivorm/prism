# Часть III. Метод

## 9. Вычисление Якобиана

**Один обратный проход на всё поле J.** Вычисляем `J = ∂z/ ∂z_𝒮/∂h`, `|𝒮| ≤ 512`, одним `backward(create_graph=False)`. `create_graph=False` — критично для производительности и корректности: в `torch` второй обратный проход требует `create_graph=True` с первого прохода, но мы этого не делаем, т.к. `∂z/∂h` — первая производная.

**KV cache и prefix forward.** Forward по prefix `x[0:S−1]` с `use_cache=True` и `past_key_values`; forward только последнего токена с `past_key_values=prefix_cache`. KV cache — **иммутабилен**: не мутировать `key_cache`, `value_cache`, `conv_state` или `recurrent_state` (модель не idempotent относительно мутаций кэша).

**Глубинные hook-и.** `register_forward_hook` на `self.layers[idx]` (не на `model.layers[idx]` — `self.layers` — это `Qwen3_5DecoderLayer`, а `model.layers` — `nn.ModuleList` без hook-подписки). Для последнего слоя `idx = n_layers − 1`. **Глубинные hook-и не влияют на forward/backward** (независимо от `retain_grad`), но требуют ручного `torch.save` для сохранения `J`.

**Мутация cache — почему не `copy.deepcopy`.** `torch_causal_conv1d_update` мутирует `conv_state` in-place; GDN обновляет `recurrent_state` через `cache_params.update_recurrent_state(...)`. Поэтому `copy.deepcopy(prefix_cache)` не работает для GDN-слоёв. Используется `_deep_clone_cache()` (Приложение C).

**GDN-специфика.** Обратный проход идёт через рекуррентную цепочку `S_t → S_{t-1} → …`, а не через attention-матрицы. Якобиан `∂z/∂h` для GDN-слоёв — корректен, но медленнее на ~30%.

**Position ids.** MRoPE: `position_ids = S − 1` для последнего токена при вычислении Якобиана с кэшем.

## 10. Jacobian bridge

**Алгоритм.**

```
JacobianBridge
  вход:  M_S, M_L, 𝒮 (набор токенов), l (слой), t = S−1
  выход: J_S_target ∈ R^{|𝒮|×D_S}, 𝓖_gap, 𝓑_bridge, s(l)

  1. J_L = ∂z_𝒮/∂h_L^l (одни forward + один backward, §9)
  2. J̃_L = J_L · E_L^T                       # проекция в пространство словаря
  3. J_S_target = J̃_L · E_S · G_S^-1          # Gramian-коррекция (§5 [L-gram])
  4. J_S = ∂z_𝒮/∂h_S^l
  5. 𝓖_gap, 𝓑_bridge, s(l)                    # §7
```

`G_S^-1` кэшируется на диск с хешем (см. §5). Выравнивание строк: строки `J_L`, `J̃_L`, `J_S_target`, `J_S` соответствуют **одним и тем же токенам** из `𝒮` (упорядочены по возрастанию индекса в `𝒮`).

**Свойство (identity).** При `M_S = M_L` и `E_S = E_L`: `J_S_target = J_L` точно (`[L-dim]` + `[L-gram]`, см. §5), и `𝓖_gap = 0`, `𝓑_bridge = 1`, `s(l) = 0`. Это — базовая самопроверка корректности всей цепочки (E-1).

## 11. Диагностика P0 и ESG P1

**P0 (диагностика).** Вычислить `𝓖_gap(l)` и `𝓑_bridge(l)` для всех слоёв `l` младшей модели. Выход: тепловая карта по слоям. Направления: `gap` — меньше = лучше, `bridge` — больше = лучше (§7).

**P1 (карта чувствительности для квантования).** Для каждого слоя `l`:

1. `J_S(l)` — Якобиан, §9.
2. **Защита** (hidden space): правые сингулярные векторы `J_S^T J_S` — направления в `h`, которые наиболее чувствительны к изменениям.
3. **Эксплойт** (token space): собственные векторы ESG `Ḡ_l = JJ^T` — направления в логитах.

**ESG-вычисление.** `N` калибровочных сэмплов, по одному `J^(i)` на сэмпл, усреднение: `Ḡ = (1/N) Σᵢ J⁽ⁱ⁾ (J⁽ⁱ⁾)^T`. Спектральное разложение — стандартное (матрица симметричная, размер `K×K`).

**Связь с P2/P3 (гипотезы, не валидированы).** Если P2 (трансформация младшей модели) реализовано, лосс: `L_p2 = Σ_l α_l · 𝓖_gap(l)`. Если P3 (регуляризатор), лосс: `L_p3 = Σ_l β_l · ‖J_S(l) − J_S_target(l)‖_F²`. Коэффициенты `α_l, β_l` подбираются вручную.

> Статус валидации: P0 ✅ (E-1, E-2), P1 частично ✅ (E-12b,c), P2/P3 — гипотезы (H4), см. Приложение B.
