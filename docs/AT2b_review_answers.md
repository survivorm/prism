## V1. centred-метрика в дереве вердиктов — ПРАВКА (явка в schema)

Код **уже центрированный** — это не legacy raw-cos. AT2b.py:486-494:

```python
ym = y_all[d].mean(0)              # ȳ per (doc,k)
pc = pred - ym                     # предиктор центрирован
yc = y_all[d] - ym                 # цель центрирована
cosv = (pc * yc).sum(1) / (norm(pc) * norm(yc) + 1e-12)
```

`cos_median` (строка 502) — медиана именно этого cos_c; дерево (716-717, 735-736,
749) и все CI (фазы 1-2, строки 646-661) работают на этих же `cos_doc`/`agg`.
Ложного SCRATCHPAD на DC-полу быть не может: DC-пол вычитан и из предиктора, и из цели.

Формулировка «ключ ambiguous» — справедливая: **ключ переименовывать не стал**
(пре-рег §7 использует нотацию `cos_median` для cos_c, пре-рег неизменяем после
записи), а **зафиксировал в schema**: новое поле артефакта `metric` (строка 829):
`cos_median = центрированная метрика cos_c (пре-рег §2): cos(pred_t - ybar, y_t - ybar)`.
Пре-рег §7 — уточняющая строка о нотации (fix-до-прогона, допустимо: прогон не
стартовал).

## V2. односторонность k=0-контроля — ВОЗРАЖЕНИЕ (код уже односторонний)

AT2b.py:708:

```python
control_ok = all(ctrl_ci[L][0] > 0.0 for L in LAYS)
```

— ровно требуемая формула `ci[0] > 0` (нижняя граница > 0, AND-over-l). Цитата ревью
«пре-рег: CI top−weak исключает 0 на всех 4 слоях» не соответствует актуальному
пре-регу: §4 гласит «pass = НИЖНЯЯ граница CI > 0 на ВСЕХ 4 слоях» и прямо
запрещает формулировку «исключает 0» (D2-артефакт r1). Инверсия (top < weak с
отрицательным CI) гейт не пропустит: `ctrl_ci[L][0] > 0` ложно. Правки не требуется.

## V3. a_scratchpad — ПРАВКА (только обоснование n_a≥2; код уже корректен)

Код (строки 711-720): `a_per_k` по **k ∈ {2,4,8}** (k=0 и k=1 не участвуют — k=0
это контроль, k=1 в r1 был вырожден), каждый k требует **И** `win_ci` (нижняя
граница CI > 0, односторонне) **И** `median > DELTA_MIN` (отдельный effect-size
гейт — вариант «> 0 + отдельный effect-size gate», предлагаемый ревью).
`n_a >= 2` — как в пре-реге.

Отсутствовало только **обоснование n_a≥2** — добавлено в пре-рег §7(a): один
k-уровень с noise effect-size+CI = forking threshold; два независимых k-уровня
(разные горизонты будущего) — минимум подтверждения; ≥3 не выбран (мощность).
Дизайн не менялся — пре-рег уже фиксировал ≥2, ревьюер требовал обосновать.

## V5. DELTA_MIN-калибровка — ПРАВКА (явный блок в артефакте)

DELTA_MIN = 0.01 пререгистрирован (пре-рег §7: 1% абсолютного уровня; на r1-полосе
0.004 всё ушло бы в METRIC_UNINFORMATIVE — честно). Требуемый ревью отчёт — уже
в артефакте (`metrics` per arm = центрированная полоса; `floor_uniform` = floor c CI;
`delta_min_calibration` — теперь явно): **фаз 5** (строки 683-699) — безусловный
блок `delta_min_calibration`: `max_pairwise_spread_Jarms` (max |разности медиан|
между {top,weak,pca,haar} per (l,k)), `floor_CI_width_max`, и два булева
`delta_min_gt_spread` / `delta_min_gt_floor_width`. Если DELTA_MIN съест всю полосу —
это видно в артефакте одним полем, без постфактум-догадки; исход
METRIC_UNINFORMATIVE остаётся честным (не NOT_RESOLVED по формальному признаку).

## M1. QR-знаки / кросс-машинный детерминизм — ВОЗРАЖЕНИЕ

Скрипт — CPU, **одна машина** (Kaggle/T4 на нём не гоняется — пре-рег §12, §10).
S9 (smoke ×2 bit-identical) закрывает именно локальную LAPACK-зависимость — это и
требуется. Межмашинная воспроизводимость не в scope; кроме того, знаковые флипы
столбцов V линейны: ridge перефитит веса со знаком, предикции инвариантны —
перенос на другую машину меняет внутренние базисы, но не readout-медианы.
Фикс знака QR не вношу (изменил бы hash базисов и поток pre-reg §3).

## M2. uniform-floor CI — ВОЗРАЖЕНИЕ (уже есть)

Фаз 3 (строки 663-669): `floor_out[f"{L}|k{k}"]` = `uniform_cos_median` +
`uniform_cos_CI` (doc-bootstrap B=1000 per-doc медиан). Пре-рег §2: «медиана +
doc-bootstrap CI (B=1000) — floor это полоса с неопределённостью, не одно число».
Сравнение readout с floor CI в дереве не нужно: ветка (d) использует DELTA_MIN
(пререгистрированный effect-size гейт), а floor CI отчитан для калибровки (V5).

## M4. ker-J статус — ПРИНЯТО (флаги в артефакте)

`kerJ_in_verdict: false`, `kerJ_in_per_position: false` (строки 838-839). ker-J —
descriptive-контроль (норма проекции h на null-J), в дереве не участвует;
высокое будущее-значение ker-J не сделает SCRATCHPAD автоматически (дерево —
только 4 J-арма).
