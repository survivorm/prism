## 🔴 A1. E-48b генерирует токены БЕЗ гейна финальной нормы w — политика выборки не является greedy модели

**Файл:** `exp48b_lfm3_gen_kinematics.py:159–162`
```python
xn = h.float() * torch.rsqrt(h.pow(2).mean() + eps).float()
nxt = int((xn.to(dev) @ W.to(dev).T).argmax())     # ← g = w потерян
```
Собственный route-чек этого же скрипта (`:131–134`, сошёлся 1.5e-6 **на декоде**) доказывает, что настоящие логиты модели — `xn @ (W⊙w)ᵗ`, т.е. w применяется. Я измерил обученный `w` из официального чекпоинта LiquidAI/LFM3-1.7B (`modeling_lfm3.py`: `logits = lm_head(embedding_norm(x))`, вес обучаемый):

```
embedding_norm.weight [2048]: min 0.013  max 4.00  mean 1.93  std 0.17
|w−1| > 0.25 у 99.4% каналов
```

То есть argmax без w — это argmax логитов, масштабированных ×0.52 с канальной модуляцией до +100%/−99%. На любом шаге с малым top-2 гэпом (коих большинство) токен **отличается от настоящего greedy модели**. Для сравнения: exp47b (Qwen) делает `argmax(out.logits)` — правильно.

**Задето:** весь поток генерации LFM3 → `loops`, `gen_sha`, `eq_prev_rate`, a/s/p в генерации, «freeze micro-loop a=0.007», wiki/math-collapse режимы, и через onset-маски — LFM3-сторона E-47c. Поле `params.decoding: "greedy"` фактически ложно (это greedy ungated-readout). В self-audit §10 это **не зарегистрировано** (10.2 чинил только ent/top1-фичи, не политику). Дополнительный вопрос: TRIV_FIX (`/tmp/e48b/…`, файл **вне репозитория**) пересчитывал full-vocab фичи из сохранённых u — применялся ли там w, проверить невозможно.

**Фикс:** одна строка — `(xn * g_n) @ W.T` (или `out.logits[0,-1].argmax()`, как в 47b) + перегенерация E-48b + пересчёт LFM3-стороны E-47c. Если режимы (freeze/collapse/петли) переживут — оговорка однострочная; если нет — часть выводов §9/§10.4 про «перенос u-механики» измерена на другой политике.
