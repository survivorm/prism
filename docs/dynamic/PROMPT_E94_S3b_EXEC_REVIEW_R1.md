**Задача руки (одна, не про M1/M2)**: применяется ли `top_k` к
пост-сэмплированному набору кандидатов на этом форке (post_sampling_probs=true).
7 запросов: лестница top_k 1/2/4 + off (поле опущено) на пробе (Q2 w4 k=70) и
1/2/4 на контроле (Q2 w13 k=101); T=1.0, seed=8181, n_predict=1, n_probs=20,
один запуск SYCL-сервера.

**Правило решения (предрегистр, порядок 4 → 3 → B3 → 1a → 1b → 2 → 5):**
- 4: halt ассертов (транспорт/эхо) → mech_invalid (echo_no_topk/echo_no_psp — mech_void);
- 3: N=0 на любой строке → mech_invalid, report_empty;
- B3: компонент > 20 или N_off > 20 → правило 5 (отчёт ≤ n_probs=20);
- 1a: ОБА вектора ∈ {(1,2,4),(2,3,5)}, ОДИН набор, N_probe(4) ≤ N_off ≤ 20 →
  mech_ok, «top_k применяется к пост-сэмплированному набору (механика установлена)»;
- 1b: лестница + потолок B4 (форма min(k+c, N_off), c∈{0,1}, c-формы контроля) → mech_ok;
- 2: оба плоские, max(v) ≥ 3, v_p == N_off, гейты ≤20 → mech_flat «не применяется»;
- 5: catch-all → mech_void, no_preregistered_reading.

**Ключевой факт структуры (факт, проверенный диагностическим прогоном 13.11):**
при `post_sampling_probs=true` отчёт `/completion` приходит в ДРУГОЙ схеме:

как в pre-sampling режиме). N = len(top_probs); sum_p0 = Σ prob (без exp).
**История (честность):** v1-прогон (артефакт S3b_v1.json, заменён) читал только

**Контекст линии E94 (не ревьюится здесь, для понимания):** аномалия
