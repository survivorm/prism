## 2. N1 — статистика конфаунда S6c: модуль внутри среднего ⛔ (единственный потенциальный флиппер)

Пре-рег определяет:

$$\text{wmean}_a=\frac{\sum_{d,t}w\cdot|dcos_a(d,t)|}{\sum w},\qquad \text{конфаунд}=\max_{a,b}|\text{wmean}_a-\text{wmean}_b|$$

Но вердикт-количество — `wcos_a − wcos_b`, а intercept входит **аддитивно в cos**:

$$\text{конфаунд}_{\text{истинный}}=\frac{\sum w\,(dcos_a-dcos_b)}{\sum w}$$

Это **знаковая** разность. И

$$\Big|\overline{dcos_a}-\overline{dcos_b}\Big|\le\overline{|dcos_a|}+\overline{|dcos_b|}$$

— то есть граница через **сумму**, а не через разность модульных средних. Разность модулей может быть нулём при ненулевом конфаунде:

```
dcos_a ≡ +c ,  dcos_b ≡ −c
wmean_a = wmean_b = c  ⇒  статистика гейта = 0
истинный конфаунд = 2c
```

При measured `max wmean = 1.44e-2` худший случай даёт **2.88e-2 > DELTA_MIN = 0.01**. То есть гейт, который остановил r3 на 1.03e-2, мог быть пройден в r4 за счёт статистики, занижающей конфаунд.

**Что проверить — одна строка кода:**

```python
# dcos_wdot = Σ w·dcos  (ЗНАКОВЫЙ)  → гейт корректен, формулировка пре-рега неверна
# dcos_wdot = Σ w·|dcos|            → гейт занижает, нужен пересчёт
```

Имя `wdot` намекает на знаковый скалярный продукт, а пре-рег пишет `|dcos|`. Одно из двух неверно. Решающий замер:

```python
conf_signed[(L,k)] = max_{a,b} | Σ_d (dcos_wdot_a − dcos_wdot_b) / Σ_d dcos_wsum |
```

Если ≤ 0.01 — гейт подтверждён properly, и надо поправить формулировку пре-рега. Если > — r7-обоснование («статистика = verdict-количество») не работает, и r4 должен был остановиться.

Отмечу: сама замена статистики в r7 **концептуально верна** — гейтить надо то количество, которое входит в вердикт, а `max_d`-pairwise не соответствует ничему в дереве. Проблема только в модуле внутри.

## 3. N2–N5 — числовые несогласованности в F1-сводке

### N2. Профиль weak L12 противоречит своим же decay-отношениям

Ответка цитирует: «шумный non-монотонный профиль weak L12: 0.137→0.094→0.047→0.045».

Но из её же таблицы: `decay k2/k1 = 1.090`, `k4/k1 = 0.281`, `k8/k1 = 0.536`, и raw `k8 = 0.045`. Отсюда (ручной счёт):

```
k1 = 0.045/0.536 = 0.0840
k2 = 1.090 × 0.0840 = 0.0915
k4 = 0.281 × 0.0840 = 0.0236
профиль: 0.084 → 0.092 → 0.024 → 0.045
```

Первые три числа цитаты (0.137/0.094/0.047) **совпадают с weak L22** — похоже на copy-paste. Вывод «L12 — исключение, weak спадает медленнее на k8» сохраняется (0.536 > 0.312), но числа в тексте не те.

### N3. k=4: «L6/L18 медленнее» — для L18 неверно

```
decay k4/k1:  top 0.479 / 0.479 / 0.457 / 0.482
              weak 0.547 / 0.281 / 0.432 / 0.343
```

L18: weak 0.432 **<** top 0.457 ⇒ weak спадает **быстрее**. Медленнее только L6 (0.547 > 0.479). То есть на k=4 — **1/4**, не 2/4. Ошибка в консервативную сторону, но сводка неверна.

### N4. k=2: «на всех 4 слоях» — L22 на грани

```
L22: top 0.683, weak 0.689  ⇒  разница 0.006 (0.9%)
```

Остальные три — 0.721/0.619, 1.090/0.684, 0.895/0.676 — разрывы 17–59%. L22 в 0.9% — внутри шума. Честно: **3 ясных + 1 маргинальный**.

### N5. «Отношение top/weak ≈ константа на k=0..4 (2.3–5.5)»

2.3 → 5.5 — это рост в **2.4 раза**, не константа. По L22: 2.30 (k0) → 2.86 (k1) → 2.85 (k2) → 4.02 (k4) → 18.6 (k8). Правильная формулировка: «отношение растёт медленно до k4 и взрывается на k8». Для scratchpad-подписи нужно **падение** отношения — его нет ни на одном горизонте. Вывод стоит, формулировка нет.

## 4. N6 — k=2-«намёк» не относится к H1 даже в принципе

Ответка оставляет k=2 как «post-hoc наблюдение, не достигающее пре-регистрационного критерия». Это точнее, чем нужно: **оно не может поддержать H1 ни при каком критерии.**

H1 требует `weak > max(pca, haar)`. На k=2 измерено:

```
weak_vs_maxPCAHaar_wCI:  L6 [−0.182,−0.102]  L12 [−0.198,−0.128]
                         L18 [−0.368,−0.267]  L22 [−0.323,−0.223]
```

weak **ниже контролей** на k=2 с большим отрывом. То, что weak спадает медленнее **top**, не делает его выше floor'а. Два сравнения независимы, и одно не спасает другое.

Формулировка: «k=2 decay-намёк не относится к H1: на том же горизонте weak ниже PCA/Haar по CI. Он описывает форму спада top↔weak, а не превышение над контролями».

## 5. N7 — усреднение по армам не исключает разреженный scratchpad ⚠️

Формальная T2 в аддентуме — **per-direction** обобщённая задача:

$$O_H^{fut}v=\lambda(C+\varepsilon I)v$$

AT2c (и F1-decay) мерят **среднее по 7 координатам** арма. Scratchpad в 1–2 направлениях из 7 будет разбавлен усреднением. G̸-проба это усиливает: `weak_Gbar` — нижние 7 из 1024, но top-обобщённые собственные векторы **не обязаны** лежать в нижнем хвосте C; они максимизируют отношение, а `O_H^fut` в клетке не считается вовсе.

Ответка правильно ограничивает: «ratio-вопрос закрыт F1-замером **на readout-уровне**». Добавлю: и **на уровне подпространственного среднего**.

Дешёвый дозамер из артефакта — per-coordinate decay:

```python
# X = H @ V, r=7 координат; W: 7 → 128
# вклад координаты j в wcos на (L,k): через W[j,:] и X[:,j]
decay_j(L,k) = contrib_j(L,k) / contrib_j(L,1)
```

Если все 7 координат weak спают сопоставимо — разреженный scratchpad внутри тестированных подпространств исключён. Если одна держится — это кандидат, и он адресный (можно назвать направление). Без этого «T2 закрыта» покрывает подпространственную форму, но не per-direction.

## 6. N8 — «matched d_eff» не выровнен на r=7 ⚠️ (в консервативную сторону)

Rematching выбрал r=7 по `min d_eff` при R=32 (argmin L6/d22/top = 7.424). Но на r=7 отношения не равны 1:

```
weak / max(pca,haar):  med 1.19 / 0.96 / 0.96 / 0.93
top  / max(pca,haar):  med 1.11 / 0.77 / 0.74 / 0.72
```

То есть процедура выравнивает **номинальный r**, а не d_eff. Формулировка гипотезы «при matched d_eff» не выполнена буквально. Направление дисбаланса — против top (он анизотропнее и всё равно выигрывает), поэтому вывод консервативен. Но текст должен говорить «matched nominal r, d_eff отчитан; дисбаланс против top», а не «matched d_eff».

## 7. Что публикуемо

> T2.1c: стационарный per-layer J-базис, центрированная цель, weighted cos. k=0-контроль пройден на всех 4 слоях (S8-якорь bit-for-bit, `max|diff| = 0`). Качество readout следует энергии спектра: top > weak_mid > weak-tail на всех (L,k). **H1 отклонена по CI**: `weak_vs_maxPCAHaar_wCI` целиком < 0 на всех 12 (L,k)∈{6,12,18,22}×{2,4,8}. Отклонение robust к определению спектра: истинно слабо-наблюдаемые направления (`weak_Gbar`, энергия в 20–150× ниже) читают будущее **на уровне floor или ниже** на всех k≥1, тогда как `top_Gbar ≈ top_Gagg`. Размерностный конфаунд работает против top (d_eff 0.72–0.77× контролей) — топ-доминирование не артефакт ранга. Decay-профиль с нормировкой на k=1 не даёт scratchpad-подписи ни на одном горизонте.
>
> Зарегистрированный вердикт `NOT_RESOLVED` — метка неполного дерева; научный вывод (anti-scratchpad, post-hoc) вынесен отдельным блоком; ветка «top-dominance» — в следующий пре-рег.

**Нельзя:** «конфаунд S6c ≤ DELTA_MIN» до проверки N1; «weak медленнее на k=4 в L6/L18» (N3); профиль weak L12 как процитирован (N2); «отношение ≈ константа» (N5); «T2 закрыта в per-direction форме» (N7); «matched d_eff» (N8).
