## 0. Библиотечность (требование v5, главный принцип)

Результат — библиотека, а не «ядро с обвязкой»: человек БЕЗ контекста проекта,
знающий только несколько строк из AGENTS.md, должен ЛЕГКО прочитать доку и
ЛЕГКО (как torch/numpy) написать новый эксперимент на ней.

1. **Имена и сигнатуры — как torch/numpy** (не в ущерб скорости):
   | sycl | torch-аналог | семантика |
   |---|---|---|
   | `ps.gemm(A, B)` → np f32 | `A @ B` | C = A@B, row-major |
   | `ps.eigjac(A, max_sweeps=12, tol=1e-5, curve=None)` → (vals f64, vecs f32, offdiag f64) | `torch.linalg.eigh` (порядок: vals по возрастанию) | полный спектр симм. A (сигнатура v5.3 F6) |
   | `ps.eigtop(A, r, max_iter)` / `ps.eigbot(A, r, max_iter)` → (vals f64, vecs f32, resid f64) | eigh → top-r / bottom-r | r пар |
   | `ps.svd_top(A, r)` → (U f32, S f64, Vh f32) | `torch.linalg.svd` (только top-r; Vh = Vᵀ) | SVD через малую сторону |
   numpy-входы/выходы; torch-тензор → numpy прозрачно (`.numpy()` без копий,
   contiguous-проверка с понятным исключением).
2. **Core-диспетчер `prism/backend.py`** (в core по допуску пользователя):
   `B.matmul(A, B)`, `B.eigh(M)`, `B.svd_top(A, r)` — в `PRISM_BACKEND=cpu`
   (дефолт) ВЕЗУТСЯ ТОЧНО torch (A@B, torch.linalg.eigh, torch.linalg.svd —
   бит-в-бит, dtype-поведение torch); в `PRISM_BACKEND=sycl` — ps.* (fp32).
   Эксперимент пишет ОДИН вызов, режим — env. `B.name` ("cpu"/"sycl") — для
   report-only гейтов.
3. **Документация**: docstrings с формами, dtypes, ограничениями и кодами
   ошибок (PS_ERR_ARG / PS_ERR_LOCAL / PS_ERR_DEVICE); `sycl_prism/README.md`
   — quickstart (5 строк: import → gemm → eigjac → сверка с numpy, БЕЗ
   GPU-контекста проекта); в корневой AGENTS.md — 3-5 строк (что есть, где,
   как запустить тест, PRISM_BACKEND).
4. **Ошибки — громкие**: PS_ERR_* → python-исключения с сообщением (форма,
   причина), не тихий мусор, не abort. **Нет устройства/SYCL-рантайма** —
   явное `PS_ERR_DEVICE`-исключение при import/первом вызове с причиной
   (n-32: quickstart обязан определять это поведение, не тайный сбой).
5. **Детерминизм**: in_order-очередь, фиксированные порядки (чанки K,
   MGS, sweep'ы Jacobi, LCG-сиды) ⇒ бит-в-бит повторный запуск (тест).

## 2. Операции (C ABI + python-библиотека)

### 2.1 `ps.gemm` / `prism_sycl_gemm_f32`
- Семантика: C[M,N] = A[M,K] @ B[K,N], row-major fp32, аккумуляция fp32.
  Только fp32 (f64-вход в `B.matmul` кастится с явным one-shot warning;
  `ps.gemm` напрямую — PS_ERR_ARG на не-fp32).
- Ограничения: 1 ≤ M ≤ 65536, 1 ≤ K ≤ 4096, 1 ≤ N ≤ 262144, иначе PS_ERR_ARG.
- **Чанкинг по hang-check (жёсткое требование, найдено 17.11)**: драйвер
  (Iris Xe, Level-Zero 1.17) имеет ВРЕМЕННОЙ hang-check на compute-команду —
  **~20с при недогрузе** (данные пользователя); при нагрузке (перегруз) окно
  ДРУГОЕ (короче) — точная величина не определена. Эвристика 17.11: 13.7с OK
  (недогружено), S1-проба 4096×1024×65536 = 550 GFLOP на 6.5-20 GF/s одним
  launch — рантайм 15+ мин в спине, CPU 98%, GPU idle. Значит, БОЛЬШОЙ GEMM
  (AT2c `z_full @ E.T` = 4096×1024×248320 = 2080 GFLOP) НЕЛЬЗЯ отдавать
  одним launch. Библиотека режет N на блоки (кратные тайлу), каждый launch ≤
  **бюджета 32 GFLOP** (запас ~3-5× от худшего ожидаемого окна: на самом
  медленном измеренном конфиге 6.5 GF/s это ≤ 5с; на реальном 50-100 GF/s —
  0.3-0.6с; при 2× деградации под нагрузкой — всё равно в окне). N_chunk =
  floor_to_tile(32e9 / (2·M·K), TC=64); для M=4096,K=1024 → 3814 → 3776 (59 тайлов) →
  ~66 чанков на 248320 (overhead launch ~66×100мкс ≈ 0.01с — ничто). Сигнатура НЕ меняется
  (один вызов — чанкинг ВНУТРИ); детерминизм сохраняется (in_order, порядок
  N-блоков фиксирован, каждый блок пишет в несомещаемую часть C). **Отключать
  hang-check ЗАПРЕЩЕНО** (пользователь пробовал — плохо). Точный бюджет
  фиксируется в коде после пробы: цель — per-launch wall ≤ ~5с на худшем
  конфиге БЕЗ нагрузки, т.е. с запасом на перегруз. Проверка чанкинга —
  тестом §2.7 (форма 4096×1024×248320: детерминизм + сверка с torch).
- Алгоритм: тайлованный, **зафиксированный тюнингом (17.11, probe/RESULTS_tuning.md)**:
  ядро `gemm_usm4/5<TR=128, TC=64, WGR=4, WGC=64, KC=16, double-buffer=true>`
  (тайл C 128×64, WG=256 тредов, CPT=32 FMAs/тред/kk, 1 колонна/нить). Измерено:
  sustained @1250 MHz: 168–170 GF/s (N=4096, 2 прогона, разброс 0.8%); на реальном
  wide-N (4096×1024×248320): 116.6 GF/s → 2.06 TFLOP ≈ 17.7с vs ~29с CPU.
  SLM = (128·16 + 16·64)·4·2 (double-buffer) = 24 KB ≤ 65536 — явный хост-бюджет
  (PS_ERR_LOCAL при нарушении). Большие тайлы (128×128, 256×128, 512×*) тюнингом
  НЕ подтверждены (register spill / без выигрыша) — не использовать.
- Детерминированность: in_order-очередь, порядок чанков K фиксирован ⇒
  бит-в-бит повторный запуск.
- Обход OOB (края тайлов, M не кратно 128 / N не кратно 64): A-строки m≥M читают 0 (guard),
  B-столбцы n≥N — нулевые входы; **запись C[m,n] ТОЛЬКО при (m<M ∧ n<N)**
  (по ОБЕИМ размерностям — ревью m-15).
- Уроки v17 (жестко): хостовые массивы-параметры НЕ читаются ядром (константы
  в захвате); USM-указатели, не accessor'ы; **wait() ОБЯЗАТЕЛЕН** после D2H
  (n-21: асинхронный D2H дописывает в переразделённый glibc-чанк ⇒ tcache-abort).

### 2.2 `ps.eigtop` / `ps.eigbot` (r пар, n до 1024)
- eigtop: power iteration + Modified Gram-Schmidt (MGS). eigbot: inverse
  iteration с Cholesky: M = A + μI (μ = 1e-12·‖A‖_F — trade-off в §5),
  фактор L[batch,n,n] на ХОСТЕ (numpy batched cholesky: 16384×128×128 ≈ 1–4с;
  (1/3)·128³·16384 ≈ 1.2e10 FLOP — n-26), в ядре два triangular-сolves
  M W = V за итерацию (≈ 2·n²·r FLOP: n=128, r=7 → 0.23 MFLOP; n=1024, r=7
  → 14.7 MFLOP (2·1048576·7 — m-27)). H2D-трансфер L — заметная часть wall при batch=16384 (§5).
  Почему НЕ сдвиг S·I−A (v1, отклонён прототипом): при близком нижнем кластере
  (jcache L6: λ₇=8.1e-8, λ₈=9.9e-8, ratio 0.81) сдвиг не сходится
  (300 ит → resid 1.1e-4, нужно ~10¹² ит). Inverse iteration сходится
  (прототип fp64, 5 матриц, 150 ит: subdist 3e-12…3e-4, Ritz-max = λ₇ точно).
- Выход: vals[batch,r] f64, vecs[batch,n,r] f32, resid[batch] f64
  (подпространственный остаток ‖AV − V(VᵀAV)‖_F/‖A‖_F на последней итерации —
  ЧЕСТНЫЙ отчёт, НЕ критерий остановки для кластерных спектров; стоп — по
  max_iter).
- Ограничения: 1 ≤ batch ≤ 65536, 1 ≤ n ≤ 1024, 1 ≤ r ≤ 32 (r < n),
  1 ≤ max_iter ≤ 512, иначе PS_ERR_ARG. Бюджет local memory (явное вычисление
  на хосте, иначе PS_ERR_LOCAL; m3, само-аудит r4 — формула = фактическому
  составу ядра eig_iterate: lv/lw по n·r каждый + sh = WG+1 элементов;
  члена r²·4 в ядре НЕТ): 2·n·r·4 + (WG+1)·4 ≤ 65536 (WG=64).
  n=1024: r ≤ 7 (r=8 ⇒ 65796 > 65536 — м-12b).
  eigbot: вход обязан быть SPD после сдвига (jcache-Граимиан таков;
  вырожденный вход ⇒ Cholesky упадёт на хосте громко).
- Алгоритм eigtop (матрица, один WG=64): (1) V₀ — LCG (a=1103515245, c=12345,
  m=2³¹; сид = batch_idx*7919 + col*104729 + 12345; c≠0 и сид≠0 при
  batch=0/col=0 — m-13), перезапуск вырожденной колонки — с сидом +7919;
  (2) W = A·V (A в GLOBAL USM, построчно); (3) MGS + нормировка
  (‖w‖<1e-12 ⇒ w_j = V₀[j]); (4) λ_j = Rayleigh ⟨v_j, Av_j⟩; (5) V/vals/resid
  в global. eigbot: шаг (2) = два triangular-сolves L Z = V, Lᵀ W = Z
  (L в GLOBAL USM; n=128: 2 строки/нить, n=1024: 16 строк/нить).
- Сходимость (прототип на реальных jcache, не домысл): eigtop 9–130 ит,
  subdist ≤ 1.6e-2 (тесный верхний кластер), relλ ≤ 1.2e-1 внутри кластера
  (векторы определены до вращения — тест по ПОДПРОСТРАНСТВУ); рассеянный спектр
  relλ ≤ 2.5e-4. eigbot 2–150 ит, subdist ≤ 3e-4.
- **В AT2c smoke НЕ используются** (AT2c: Gagg 1024×1024 ранг ≤ 128 — через
  Gsmall+lift, §2.4/§2.8; 128×128 — eigjac) — только unit-тесты. Поверхность
  интеграции минимальна: gemm + eigjac (+ host-lift).

### 2.3 `ps.eigjac` (cyclic Jacobi, полный спектр, n ≤ 256) — новая операция v5
- Зачем: реальный спектр jcache (L6, 3 (d,t)): gap top-32 λ₃₂/λ₃₃ = 1.023,
  1.182, 1.065; gap bottom-32 = 1.253, 1.135, 1.046 ⇒ power/inverse для r=32
  не сходится в бюджете max_iter=512 (1.023 ⇒ ~700 ит до 1e-6). Jacobi —
  детерминированная фиксированная стоимость, не зависит от gap.
- Семантика: полный спектр симметричного батча A[batch, n, n] f32:
  vals[batch,n] f64 (по возрастанию — сортировка на хосте, порядок torch),
  vecs[batch,n,n] f32, offdiag[batch] f64 (относительная ‖offdiag(A)‖_F/
  ‖A‖_F на остановке — ЧЕСТНЫЙ отчёт сходимости).
- Алгоритм (матрица, ОДИН work-item; батч — между матрицами): A, V — в GLOBAL
  USM. ПОСЛЕДОВАТЕЛЬНЫЙ циклический Jacobi (v5.2, в v5.3 — с batch-чанкингом):
  sweep = для d = 1..n-1: для i = 0..n-1-d: rot(i, i+d) — классический
  циклический порядок, ровно n(n-1)/2 ротаций, каждая пара (i,j), i<j, один раз;
  (c,s) — малый корень t = (A_jj−A_ii)/(2·A_ij), t = sign(t)/(|t|+√(1+t²)),
  fudge-guard XLA (|A_ij| ≤ 0.1·eps_f32·min(|A_ii|,|A_jj|), eps_f32 = 1.1920929e-7
  (F5) ⇒ ротация не применяется). **Batch-чанкинг (v5.3, F1 — MAJOR):**
  «1 sweep ≈ 3с (n=128, iGPU)» замерен на ОДИНОЧНЫХ матрицах (batch=1);
  без чанкинга 1 sweep = 1 запуск на весь батч (лимит 65536, AT2c — 16384)
  и время sweep не ограничено hang-check ~20с: 1 sweep = ⌈batch/C⌉ запусков,
  каждый launch ≤ C матриц (work-item обрабатывает свою матрицу); C —
  фиксируется ТЮНИНГОМ на прогоне AT0_3 (замер t_sweep по чанкам
  {1,16,64,256,1024,4096} на iGPU, n=128; правило: C = наибольшее чанк с
  t_sweep(C) ≤ 4с — 5×-запас к hang-check; начальное C=1024; твёрдый тест-
  гейт §2.7). **n=256 (F9): стоимость sweep на матрицу ∝ n(n−1)/2 —
  ×9.5 к n=128 (замер 19.11, не ×4.02 спеки v5.3) ⇒ чанк для n > 128 =
  C/16** (EIGJAC_CHUNK/16) — тот же 5×-запас (консервативно: измеренное
  ×9.5 > расчётного ×4.02); твёрдый тест §2.7 — оба n (128: чанк C; 256:
  чанк C/16). Sweep-луп на хосте: после каждого sweep (все чанки) хост читает
  offdiag[b] (USM, **4·batch B — f32 на устройстве**: iGPU без fp64-aspect,
  f64-преобразование только на хосте; в v5.2 было «8·batch B» — несовместимо
  с устройством) и останавливается при offdiag_rel < tol (умолчание 1e-5) ИЛИ
  max_sweeps (умолчание 12, максимум 64). offdiag_rel — f32-расчёт на
  устройстве (редукция по ~n²/2 членов: bound ~2e-3 rel, типично ~1.5e-5;
  F11) — влияние на стоп-критерий: максимум лишний sweep; ЧЕСТНЫЙ отчёт =
  f32-значение, записанное в f64 (host). Суммарное время вызова (F10):
  ≈ max_sweeps × ⌈batch/C⌉ × t_sweep (worst 64×16×4с = 4096с; AT2c:
  16 launch/sweep × 12 sweep ≤ 768с) — hang-check на compute-КОМАНДУ, не
  на вызов (формулировка v5.2-ревью) — строка для планирования стоимости. Почему НЕ параллельный матчинг (замер v5.2, 6 реальных jcache 128×128,
  f64 и f32, механизм дословно XLA eigh — openxla/xla eigh_expander.cc):
  L6 d0t0: 64 sweep'а → offdiag_rel 0.589 (старт 0.743); L6 d0t1: 0.433
  (старт 0.715); L6 d1t0: 0.135 (0.532); L23 d0t0: 0.286 (0.376); L23 d0t1:
  0.395 (0.473); L23 d1t0: 0.069 (0.492) — ratio ~0.997–0.9999/sweep, НИ ОДНА
  НЕ ДОСТИГАЕТ 1e-4 в бюджете 64 (тест §2.7). Причина:
  simultaneous-приложение disjойнтных ротаций одного раунда = J_allᵀ·A·J_all
  с (c,s) от состояния НАЧАЛА раунда — Jacobi-итерация по парам: линейное
  схождение с фактором → 1 при росте n/конд. (реальные jcache — почти
  вырождены: λmin ~ 1e-9..1e-7, конд. ~ 1e8–1e9). Любая intra-матричная
  параллельность либо race (кросс-ячейки {i,j}×{i',j'} — реплика
  /tmp/jac4_replica.cpp), либо этот simultaneous-механизм — свободного
  ускорения нет; последовательный порядок — единственный корректный+быстрый
  (замер: 4–5 sweep'ов до 1e-4, 4–6 до 1e-5 на всех 6 реальных jcache; f64/
  f32 идентично; квадратичный хвост до 0.00e+00 к sweep 13). Ожидаемая
  сходимость fp32 (m-28): ЗАМЕРЕНА — см. выше; при остановке по max_sweeps
  БЕЗ tol — ЧЕСТНЫЙ offdiag-отчёт (не тихий мусор; тест §2.7 требует < 1e-4).
- Детерминизм: один work-item на матрицу, фиксированный порядок ротаций,
  локальной памяти НЕТ, редукции — только offdiag (фиксированный порядок
  суммирования в одном work-item) и host-MGS (фикс. порядок) ⇒ бит-в-бит
  повторный прогон (тест §2.7) — по строению; watchdog: 1 launch = 1 чанк ≤ C
  матриц; т_sweep(C) ≤ 4с по твёрдому тест-гейту §2.3/§2.7 (5×-запас к
  hang-check ~20с; v5.3 F1 — в v5.2 было «1 sweep ≈ 3с (n=128, iGPU)» без
  привязки к batch — замер на одиночных матрицах).
- Постобработка (хост, f64, v5.2; write-back — v5.3 F4): (1) сортировка пар
  (λ, v) по возрастанию λ (порядок torch); (2) финальная ре-ортогонализация V
  — modified Gram-Schmidt (1 проход, хост f64, результат ЗАПИСЫВАЕТСЯ ОБРАТНО
  в vecs f32): ошибка ортогональности f32-Jacobi при n=128
  ~2.5e-4 (замер, 6 реальных jcache) — ПРЕВЫШАЕТ допуск теста 1e-4; цифры
  «MGS восстанавливает ortho ~5e-15 и УЛУЧШАЕТ subdist (1.4e-4 → 8.4e-5, замер
  L6 d0t0)» относятся к f64-расчёту; после f32-cast замер: ‖VᵀV−I‖ ≈ 3e-7
  (n=128, 6 реальных jcache) ≤ допуска 1e-4; пер-векторная точность сохраняется
  (relλ ~6e-7). Без MGS тест §2.7 (ortho ≤ 1e-4) провален по строению.
- Ограничения: 1 ≤ batch ≤ 65536, 1 ≤ n ≤ 256, 1 ≤ max_sweeps ≤ 64,
  1e-6 ≤ tol ≤ 1e-3, иначе PS_ERR_ARG. Local memory: НЕТ (v5.2: один
  work-item на матрицу; явный хост-бюджет 0 ≤ 65536 — форма проверки
  сохранена для единообразия с eigtop/eigbot; PS_ERR_LOCAL в eigjac
  невозможен по построению). A/V — в GLOBAL USM.
- C-ABI (v5.2; типы явные — v5.3 F7): `prism_sycl_eigjac(const float* A,
  int64_t batch, int64_t n, int64_t max_sweeps, double tol, double* vals,
  float* vecs, double* offdiag, double* offdiag_curve, int64_t curve_len)` —
  offdiag_curve/curve_len опциональны (NULL/0 — без кривой). **Контракт curve
  (v5.3 F3, явные индексы):** curve[s−1] = offdiag_rel матрицы 0 ПОСЛЕ sweep s
  (s = 1..k, k = число реально выполненных sweep'ов); если k < curve_len —
  curve[k..curve_len) = offdiag[0] (= curve[k−1]) — ЯВНЫЙ fill до конца буфера
  (не «неопределено», не дубль на границе: финальное значение пишется с
  индекса k, не k−1).
  **Тип curve (само-аудит r4, m1):** только `np.ndarray(float64)` и
  C-contiguous — потому что контракт «на месте». Прежний `np.asarray(curve,
  f64)` для f32-массива/списка создавал КОПИЮ ⇒ буфер пользователя молча
  оставался нулевым; теперь — ValueError (f32-буфер — явный
  `curve=np.zeros(k, np.float64)`).
- **Симметрия входа — КОНТРАКТ, не проверяется (n8, само-аудит r4):** sweep
  опирается на A[k,i] = A[i,k] (ядерный итератор читает ТОЛЬКО верхнюю пару).
  Не-симметричный A даёт МОЛЧА неверный спектр — проверка не добавлена
  сознательно (хост-скан O(batch·n²) на каждом вызове был бы соизмерим с
  самим расчётом); требование явно записано здесь и в docstring `ps.eigjac`.

### 2.4 `ps.svd_top` (host-композиция, m/n до 1024, min(m,n) ≤ 256) — новая операция v5
- Семантика: SVD A[m,n] f32 (m ≤ 1024, n ≤ 1024, m<n или m>n — симметрично)
  → top-r: U f32 [m,r], S f64 [r], Vh f32 [r,n] (Vh = Vᵀ — конвенция torch).
- Ограничения (m-29a): 1 ≤ m ≤ 1024, 1 ≤ n ≤ 1024, 1 ≤ r ≤ min(m,n), иначе
  PS_ERR_ARG (r > rank — НЕ ошибка: вырожденные σ ниже).
  **M2 (само-аудит r4): дополнительно min(m,n) ≤ 256** — малая сторона
  диагонализируется eigjac'ом, а его лимит n ≤ 256 (большая идёт в gemm
  ≤ 1024). Дефект r3-состояния: guard заявлял 1024/1024, а вызов падал из
  ЧУЖОГО слоя («eigjac: PS_ERR_ARG ... n=300») на 256 < min(m,n) ≤ 1024;
  случай A[128,1024] (AT2c) — в лимите.
- **Выходы C-contiguous без отрицательных шагов** (M1, само-аудит r4):
  torch-конвенция (S descending) требует REVERSE столбцов; view с шагом −4
  ломал потребителя `torch.from_numpy` (ValueError) — теперь копия через
  `_pos_strides` (проверка по ШАГАМ, а не по флагу C_CONTIGUOUS: у вырожденных
  осей numpy считает view «contiguous» и ascontiguousarray не копирует).
  Красный тест-канарейка: `tests/test_backend.py::test_sycl_svd_top`.
- Реализация (ВСЁ на хосте из ps.gemm + ps.eigjac; нового ядра НЕТ):
  m < n (случай AT2c: 128×1024): (1) G = A·Aᵀ [m,m] (gemm); (2) (λ, U) =
  eigjac(G) — полный спектр, top-r (λ по возрастанию → взять r последних);
  (3) σ: clamp ДО sqrt (n-30: fp32-шум G=A·Aᵀ даёт λ_i ≤ 0 ⇒ NaN):
  σ_i = 0 при λ_i ≤ 1e-12·λ_max, иначе √λ_i; (4) V = Aᵀ·U_r / σ (gemm
  [n,m]@[m,r], деление по колонке, σ=0 ⇒ V_i = 0-вектор).
  **Порядок выхода (m-29b, конвенция torch — S descending)**: после выбора
  r последних (λ по возрастанию) строки U/S/Vh REVERSE-ятся ⇒ σ по
  убыванию, U[:,i] ↔ σ_i ↔ Vh[i,:].
  m > n: зеркально через G = AᵀA [n,n] (те же правила clamp/reverse).
  Правильность: собственные векторы A·Aᵀ = левые сингулярные (U);
  V_i = AᵀU_i/σ_i — правые (тест §2.7 сверяет с np.linalg.svd).
  Вырожденные σ (λ ≤ 1e-12·λ_max): соответствующий V_i = 0-вектор (сигнал;
  в AT2c r_final ≤ rank — не случается; тест-деградация §2.7).
- Связь с Gagg (AT2c): Gagg = Jaggᵀ·Jagg (1024×1024, ранг ≤ 128) — bottom-7
  Gagg = нуль-пространство (λ=0), НЕ weak-tail (мат. ошибка дизайна v4,
  исправлена v5): weak-tail = bottom-7 НЕНУЛЕВЫХ = bottom-7 малого Грамиана
  Gsmall = Jagg·Jaggᵀ (128×128, полный ранг), lift v = Jaggᵀu/√λ
  (аналог `_lift_arr` в AT2c). top-r Gagg — тот же lift (top-r Gsmall).
  Весь Gagg-блок AT2c = gemm(Gsmall) + eigjac + host-lift — БЕЗ eig 1024×1024.

### 2.6 `prism/backend.py` — core-диспетчер (по допуску пользователя)

  причина). Lazy-import sycl (в cpu-режиме библиотека не поднимается).
- Тест core: `tests/test_backend.py` — cpu-режим == torch (бит-в-бит на
  мелких), sycl-режим == torch ≤ 1e-3 (только если DEVICE_OK; skip иначе).

  чанк C) ≤ 4с И 1 launch (n=256, чанк C/16) ≤ 4с И C_measured ≥ C_FIXED
  (иначе — громкий fail: GPU медленнее худшего зафиксированного состояния —
  не тихое замедление). C зафиксировано тюнингом 19.11: C = 64 (тест
  C_FIXED = src EIGJAC_CHUNK). **Консервативная фиксация (v5.4, замер 19.11):**
  iGPU-состояние нестабильно (деградация 1.5–1.9× за день + восстановление:
  c256 = 4.3–6.9с → 3.843с) — C_FIXED выбрано под ХУЖОЕ измеренное состояние;
  если GPU быстрее (C_measured > C_FIXED; замер 19.11-день восстановления:
  C_measured=256) — остаёмся на C_FIXED (стоимость на матрицу при c64/c256
  идентична в замерах, 14.8/15.0 мс); константу НЕ перетюнить вслед за
  iGPU-состоянием (flip-flop).
  + curve (v5.3, F3): curve=np.empty(64), max_sweeps=64: curve НЕУБЫВАЕТ
  в смысле не-возрастания (f64): curve[s] ≤ curve[s−1] для s=1..k (F13);
  curve[k−1] == offdiag[0] (k = число sweep'ов до стопа), curve[k..64) ==
  offdiag[0] (явный fill), curve[0] > 0 (после 1-го sweep).
  + fudge-guard designed-тест (v5.3, F12; AGENTS.md — guard обязан быть
  протестирован): (a) диагональная матрица — все ротации skip (off = 0 со
  2-го sweep), vals = диагональ, без NaN; (b) пара с |A_ij| ≤
  0.1·eps_f32·min(|A_ii|,|A_jj|) (A_ii, A_jj = 1e10, A_ij = 0.05) —
  ротация НЕ применяется (без неё off_rel = 5e-12 < tol ⇒ стоп, vals =
  диагональ), без NaN.
- svd_top: реальные H-доки [128,1024] (exp27b): σ rel ≤ 1e-3, подпространства
  U и V (span ‖(I−VVᵀ)V_ref‖_F) ≤ 1e-3 против np.linalg.svd (f64);
  m>n-случай (1024×128) — то же; вырожденный вход (ранг < r): σ-нуль +
  V_i=0 — явное, не мусор.
- Gagg-композиция (weak-tail + top, v5-математика): Jagg реальные L6/L23
  [128,1024] (f64 → f32 как в AT2c); Gsmall = Jagg·Jaggᵀ; eigjac(Gsmall) →
  lift v = Jaggᵀu/√λ; сверка с torch.linalg.eigh(Gagg, f64): top-7,
  weak-7 (bottom-7 ненулевых), weakmid (позиции r..2r по убыванию) —
  подпространства ≤ 1e-3; S5b-аналог: max_j ‖Gagg v_j − λ_j v_j‖/|λ_j| ≤ 1e-5
  (f64, на хосте).
- eigtop/eigbot: random-SPD (рассеянный: relλ ≤ 1e-3, subdist ≤ 1e-3) +
  реальные jcache (d,t) 128×128 top-7/bottom-7: подпространство ≤ 5e-2 +
  Rayleigh-Ritz: Ritz-max(top) ≥ λ_r(1−1e-3), Ritz-max(bot) ≤ λ_r(1+1e-3);
  ортогональность ‖VᵀV−I‖_F ≤ 1e-5 (один проход MGS в fp32: попарные
  ~√n·eps ≈ 1e-5 при n=128 — на грани; провал ⇒ двойной MGS — n-14);
  eigbot — ТОЛЬКО на full-rank SPD (не на Gagg).
- Деградация: NaN в A → resid/offdiag NaN (не тихий мусор); r ≥ n →
  PS_ERR_ARG; 2·n·r·4 + (WG+1)·4 > 65536 → PS_ERR_LOCAL (n=1024, r=8 ⇒
  65796 — m-12b; m3 r4: члена r²·4 в ядре нет); n > 256 в eigjac → PS_ERR_ARG;
  не-fp32 в gemm → PS_ERR_ARG.

### 2.8 Backend-switch в AT2c smoke (приёмочная интеграция)

Цель: smoke AT2c T2.1c (245с/прогон, r1–r4 считались на CPU) прогоняется в
двух режимах с совпадающими числами и выигрышем в скорости.

- Механика: `PRISM_BACKEND=cpu|sycl` (дефолт cpu) + `prism.backend`. В AT2c —
  3 точечные замены вызовов (один вызов в обоих режимах, БЕЗ веток по режиму
  в местах вызова):
  | строка | операция | вызов (оба режима) |
  |---|---|---|
  | L307 | z_full [32,128,1024]@[1024,248320] | `B.matmul(H23, E.T)` |
  | L390 | eigh(G) 128×128 per (d,t) ×16384 | `B.eigh(G)` |
  | L401/497/551 | svd(Hc) 128×1024, top-r | `B.svd_top(Hc, r)` (r = R/r_final) |
  + 1 структурная ветка (единственная): L446-459 Gagg-блок. cpu — как сейчас
  (f64 eigh 1024×1024); sycl — helper `_gagg_subspaces_sycl(Jagg, r_final)`
  (В АТ2c, ~20 строк): Gsmall = B.matmul(Jagg.float(), Jagg.float().T);
  lam, U = B.eigh(Gsmall); lift v = (Jagg.T @ U[:, idx]) / σ (gemm на хосте,
  f64); возвращает те же Vtop_a/Vweak_a/Vweakmid_a (f32), что torch-путь;
  S5b — тот же f64-прогон (report-only в sycl, §2.9).
  CPU-путь (deft): B.* = точные torch-вызовы ⇒ бит-в-бит (проверка фазы R).
  Всё остальное (softmax, KL, ridge np, bootstrap, lk4, eigvalsh [r,r] L215) —
  на хосте в обоих режимах.
- Точность в sycl-режиме (честно, не «выключить гейты»):
  * Гейты < 1e-3 → **report-only** (значение в артефакт + метка
    `"sycl_relaxed": true`): S2 (KL < 1e-5), S5b (1e-9), S6 (1e-10),
    S8 (1e-6). Причина: fp32-шум операций ~1e-7·cond; пороги — для
    CPU-бит-идентичности.
  * Жёсткие гейты в обоих режимах: S1 (sha), S4 (точные счётчики), S5a
    (r_final: smoke — report, main — гейт), S7 (exact set), verdict
    (weighted cos, DELTA_MIN=0.01 — робастен к 1e-4-шуму).
  * Совпадение CPU/GPU: max rel diff ≤ 1e-3 по всем числам артефакта
    (metrics, d_eff, per_pos, bootstrap, verdict); verdict и жёсткие гейты
    — идентичны. (вывод: fp32-суммирование K=1024 + eigh-подпространства;
    не подгоняется)
- Замер: tstage-степси уже в коде (load/subspaces pass1/pass2/ridge/lk4/
  verdict) → per-stage таблица wall (CPU и GPU отдельно) в артефакт.

## 5. Риски
- Кластерные спектры (jcache: нижние 8 λ в 10×): отдельные значения в
  кластере определены до вращения — прибор отдаёт подпространство
  (lift/проекция/SVD инвариантны к поворотам в кластере). Тест — span + RR.
- eigjac fp32-дно ~ n·eps_fp32 ≈ 1.2e-5 (n=128): tol < 1e-5 недостижимо;
  offdiag честно отчитывается; тест не требует полной сходимости
  (подпространство + RR, §2.7).
- eigbot: вход SPD после сдвига (jcache-Граимиан: rank 128, λ_min 7e-9 > 0;
  96/96 L6 проверено ревьюером); вырожденный вход ⇒ громкий хост-упадок.
- **Hang-check драйвера (время на compute-команду)**: ~20с при недогрузе
  (данные пользователя); **под нагрузкой (перегруз) окно ДРУГОЕ/короче** —
  поэтому бюджет чанкинга §2.1 = 32 GFLOP/launch (запас ~3-5× от худшего
  окна). Эвристика 17.11: 13.7с OK, S1 550 GFLOP одним launch — рантайм 15+
  мин в спине. Митигация — чанкинг ВНУТРИ gemm. Отключать hang-check
  ЗАПРЕЩЕНО (пользователь пробовал — плохо). eig*/svd на batch 16384 не
  задевает: каждая итерация — отдельный launch на десятки MFLOP
  (миллисекунды), а не один длинный.
- GEMM на iGPU vs OpenBLAS-4тр: CPU z_full ≈ 25с ≈ 83 GFLOP/s; iGPU тайлованный
  ≈ 61.5 GFLOP/s ⇒ GEMM-стадия ~1×. Выигрыш от eigh/SVD (main: pass1 68с→~1с,
  pass2 104с→~16с; smoke: ~10с→~2с). Если суммарный smoke-выигрыш < 1.1× —
  честный результат (smoke GEMM-доминирует) — per-stage в артефакте,
  extrapolation на main — в отчёте.
- Batch=1 вызовы eigjac ×16384 (pass1): overhead submit (~50-100мкс) ≈ 1–2с
  на все 16384 — учитывается в per-stage замере; батчирование (сборка
  [16384,128,128] = 1 ГБ) — будущее, не в этом TZ.
- f64-входы AT2c (Jagg, Hc) в sycl → f32: точность ~1e-7·cond — для
  1e-3-совпадения OK; f64-гейты (S5b 1e-9, S8 1e-6) — report-only.
- μ = 1e-12·‖A‖_F (~1e-10) — ниже fp32-шума (~1e-7): SPD — «по факту» на
  данных (проверено), не «по построению»; альтернатива μ~1e-6 замедлила бы
  inverse iteration (ratio → 1.005 ⇒ >512 ит). Выбор: малый μ + громкий
  хост-фолл (n-23).
- H2D L [batch,n,n] (1 ГБ при 16384×128×128): ~0.5–2с на iGPU (n-25) —
  только если eigbot применится; в AT2c smoke eigbot НЕ вызывается.
- Cholesky-хост: batch·n·n·4 ≤ 2 ГБ, иначе PS_ERR_ARG (n-26; Gagg: 16 МБ).
