## Общий вывод

Код **частично соответствует ТЗ**, но содержит **критические ошибки**, из-за которых:
- random baseline **не является random** и фактически равен data-baseline;
- не реализованы ключевые требования ТЗ: **профили Δ_SVD(t), κ(t), поиск границ, порог median+2·MAD, per-document сводки**;
- нет фиксации seed для torch, поэтому результаты недетерминированы;
- `B_RAND=200` не используется.

В текущем виде код — это не реализация Exp28, а **сокращённый агрегатор средних** по нескольким фиксированным парам/тройкам. Для интерпретации leaf structure / curvature его недостаточно.

---

## Что соответствует ТЗ

- Используются gauge-free `J` из кэша.
- Берутся **правые** сингулярные векторы `V` (скрытое пространство), не левые.
- Реализован top-r SVD, principal angles через `arccos` сингулярных чисел `V_a^T V_b`.
- Есть sign convention для SVD: первый ненулевой элемент колонки делается положительным.
- Формула Procrustes и holonomy в целом совпадает с ТЗ:
    - `R_ab = argmin ||V_b - V_a R||_F`;
    - `H = R01 @ R12 @ R02^T`, `κ = ||H - I||_F`.
- Есть r-sweep `{8,16,32}` и main `r=16`.
- Учтено, что token types отсутствуют в кэше — этот пункт пропущен и зафиксирован.
- Есть selfcheck для flat/curved на data-κ (но не на random baseline).

## Критические ошибки

### 1. Random baseline не random

В `sample_delta_svd`:

```python
d_rand = principal_angles_max(V1, V2 @ haar_random(r, V1.device))
```

`V2 @ Q`, где `Q ∈ O(r)`, — это **другой базис того же самого r-мерного подпространства**. Principal angles между подпространствами инвариантны к смене базиса внутри подпространства. Значит:

```text
d_rand == d_data
```

В `sample_kappa`:

```python
V1r = V1 @ haar_random(r, V1.device)
k_rand = hol(V0, V1r, V2)
```

Можно показать, что holonomy тоже инвариантна к смене базиса среднего подпространства:

- `R01' = R01 Q`
- `R12' = Q^T R12`
- `H' = R01' R12' R02^T = R01 Q Q^T R12 R02^T = H`

То есть:

```text
k_rand == k_data
```

В результате колонки `delta_rand_mean`, `kappa_rand_mean`, `excess` **бессмысленны**: excess всегда ≈ 0.

**Как надо:** генерировать случайное r-мерное подпространство в ambient `R^D`, например:

```python
Q_D = haar_random_D(D)      # D x D orthogonal
V_rand = Q_D[:, :r]         # D x r random subspace
# или
V_rand = Q_D @ V2
```

### 2. `B_RAND=200` не используется

В ТЗ: `B=200` random baselines на пару/тройку.  
В коде baseline считается **один раз** на сэмпл, без усреднения по 200 реализациям. Даже если исправить random subspace, всё равно нет среднего и std по baseline.

### 3. Нет фиксации seed

В `main` создаётся:

```python
rng = np.random.default_rng(a.seed)
```

но `rng` нигде не используется.  
`haar_random` использует `torch.randn`, но `torch.manual_seed(a.seed)` не вызывается.  
Значит random baseline недетерминирован, а `--seed` фактически не работает.

### 4. Не реализованы профили и поиск границ

ТЗ требует:
- профиль `Δ_SVD(t)` для каждого документа и слоя;
- профиль `κ(t)`;
- список позиций-границ;
- порог `median + 2·MAD`;
- per-document сводку.

Код вместо этого считает **средние по доменам и сэмплам** для нескольких фиксированных пар/троек.  
Нет:
- per-document массивов;
- пиков;
- относительного скачка;
- порога median+MAD;
- списка границ.

Это не выполнение основной цели Exp28.

### 5. Кривизна только для одной тройки на S

`TRIPLES` содержит только `(S, 0, 1, 2)` для `S ∈ {32,64,128,256}`.  
Нет профиля `κ(t)` вдоль последовательности, нет mid/gap троек, нет анализа затухания.

### 6. Другие ошибки

- **dt mislabels:**  
  `(64,1,2,2,'end')` — разница позиций `|2-1| = 1`, а не 2.  
  То же для `(256,1,2,2)`, `(32,1,2,2)`.  
  Это влияет на ключи JSON и интерпретацию.

- **`TRIPLE_ZONES`, `n_tot`, `rng`, `B_RAND` не используются.**

- **`haar_random` делает det-fix**, то есть генерирует Haar на `SO(r)`, а не `O(r)`. Для random subspace это не критично, но формально расходится с ТЗ.

- **Нет обработки вырожденных случаев** `rank(J) < r`. Для `K=128, r=16` маловероятно, но ТЗ требует пропуск/дополнение.

- **`selfcheck` не проверяет random baseline**, поэтому баг №1 не ловится.

- **Нет проверки наличия ключей в кэше** — возможен `KeyError`.

- **Не обрабатываются несколько моделей в одном кэше**, если такое предполагалось.

## Рекомендации по исправлению

1. **Исправить random baseline:**
    - генерировать случайное `D × r` ортонормированное подпространство;
    - для этого использовать `Q_D @ V` или QR от `torch.randn(D, r)`.

2. **Ввести цикл `B=200`:**
    - для каждой пары/тройки считать `B` random baselines;
    - сохранять mean/std по baseline.

3. **Зафиксировать seed:**
    - `torch.manual_seed(a.seed)`;
    - использовать `rng` или отдельный torch-генератор.

4. **Реализовать профили:**
    - для каждого `(dom, si, layer, S)` сохранять массив `Δ_SVD(t)` по всем доступным `t`;
    - для троек — массив `κ(t)`;
    - вычислять границы по `median + 2·MAD`;
    - сохранять список позиций-границ.

5. **Добавить per-document сводки:**
    - среднее `κ`, доля `κ > 1e-3`, число границ и т.п.

6. **Расширить triples:**
    - добавить mid и gap-тройки, если позиции есть в кэше.

7. **Исправить dt в `PAIRS`:**
    - `(64,1,2,1,'end')`, `(256,1,2,1,'end')`, `(32,1,2,1,'end')`.

8. **Добавить selfcheck для baseline:**
    - для flat/curved проверить, что `k_rand >> k_data` и `d_rand > d_data`.

## Итог

Код **не является полной реализацией Exp28** и содержит **критический баг с random baseline**, который делает сравнение с null бессмысленным.  
Математика principal angles и Procrustes/holonomy в основном корректна, но из-за baseline, отсутствия профилей и недетерминизма результаты нельзя использовать для выводов о leaf structure и локальной кривизне.

После исправления baseline, добавления профилей и поиска границ код можно будет считать соответствующим ТЗ.
