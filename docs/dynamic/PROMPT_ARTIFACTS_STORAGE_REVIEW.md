# Ревью: правила хранения артефактов + `tools/artifacts.py` (read-only, ≤15 минут)

Ты — независимый ревьюер. Единственный файл, который ты создаёшь: `docs/dynamic/ARTIFACTS_STORAGE_REVIEW.md`.
Править репо, git, запускать эксперименты, выгружать что-либо в сеть — **запрещено** (это read-only
проверка; `push` в HF не запускай вообще).

## Что ревьюится

1. `docs/ARTIFACTS_STORAGE.md` — политика (пороги, где хранить, что не архивировать).
2. `tools/artifacts.py` — утилита: `scan / gate / add / verify / push / pull`.
3. `artifacts/registry.json` — реестр (1 запись, заведена для проверки механики).
4. Соответствие `AGENTS.md` (раздел «Git-гигиена») — правило про >10MB не должно противоречить
   остальному репо (например, `docs-hygiene`, `results/*.json` в `.gitignore`).

## Обязательные проверки (командами, из корня репо)

1. `sha256sum docs/ARTIFACTS_STORAGE.md tools/artifacts.py` — зафиксируй.
2. `python3 -m py_compile tools/artifacts.py` — синтаксис.
3. `.venv/bin/python tools/artifacts.py gate; echo rc=$?` — на чистом staged ожидается `rc=0`.
4. **Негативный тест гейта** (главное): создай в /tmp файл 12 МБ, `git add -f` его НЕ надо — вместо
   этого проверь логику чтением кода + прогони `gate` после `git add` любого **существующего** файла
   >10 МБ из `results/` (например `results/exp45b_leaf_table.npz`, 131 МБ): `git add -f <файл>`,
   `gate` должен вернуть rc=1, затем **обязательно** `git restore --staged <файл>` и проверь
   `git status --short` (в staged не должно остаться ничего лишнего). Если файла нет — найди свой
   `find results -size +10M | head -1`.
5. `.venv/bin/python tools/artifacts.py scan --top 3` (через `--mb 100`) — числа должны совпасть с §7
   политики: 50 файлов >10 МБ / 5.3 ГБ / крупнейшие `exp27_jcache.pt` 1.7 ГБ, `exp48b_…npz` 1.6 ГБ.
6. `add` → `verify` на временном файле: скопируй мелкий json в `/tmp/x.json`, `add /tmp/x.json --name tmp_test`,
   `verify` (должно быть 0 проблем), затем **удали** запись `tmp_test` из `artifacts/registry.json`
   (правка реестра — единственное разрешённое изменение в репо) и `git diff artifacts/registry.json`
   покажи в ревью (ожидается пусто). Если удалить не выходит — напиши это как дефект утилиты.
7. `hf`-часть: проверь чтением, что `push` не может утечь наружу без явного `--repo`/`hf_repo`, что
   `pull` сверяет sha, и что при отсутствии `huggingface_hub` — внятная ошибка, а не трейсбек.
   Токен не ищи, в сеть не ходи.

## Что искать как дефекты

- **Гейт можно обойти** (`git commit --no-verify`, файл добавлен до установки хука, `git add -A`):
  где это записано в политике? Обязан быть явный пункт «хук — не единственная защита».
- **Порог в одном месте** (10 МБ) vs «≤10MB можно в git»: граница `>` vs `>=` — согласована ли в коде
  (`sz > mb*1e6`) и в тексте; нет ли файла ровно 10.0 МБ, который «и в git, и в реестре».
- **Неверная семантика реестра**: `sha256_16` — усечённый хэш; достаточно ли для сверки (да), но есть
  ли риск коллизии для двух разных версий одного артефакта; что происходит при перезаписи файла.
- **Регенерируемые кэши в §6** — не противоречит ли §1 («10–200 МБ → HF»); должен быть приоритет
  «регенерируемое → не архивируем».
- **`.gitignore`**: `results/*.json` игнорируется, но `artifacts/registry.json` — нет; проверь
  `git check-ignore -v artifacts/registry.json` (должно быть пусто) и что `results/e*` не приведёт
  к случайному коммиту гигабайтов (`git status --short | head`).
- **Kaggle** упомянут как «дубликат»: есть ли критерий, когда именно; если нет — дефект (важно/мелкое).

## Формат файла

```
# Ревью: хранение артефактов + tools/artifacts.py
sha256 политики/tool: …

## Проверки
| # | команда | результат | ожидание из доков | совпало? |

## Дефекты
1. [блокер/важно/мелкое] … → что исправить (файл:строка)

## Итог
VERDICT: PASS | REVISE | FAIL

ARTIFACTS_STORAGE_REVIEW_DONE
```

Файл пиши один раз в конце. Если не успеваешь — `VERDICT: REVISE` + список «не проверено».
Маркер `ARTIFACTS_STORAGE_REVIEW_DONE` — последняя строка файла.
