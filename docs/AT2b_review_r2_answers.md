## Валидация диагностики (обязательная, все пройдены)

Диагностика — не новый эксперимент, а **бит-в-бит воспроизведение** прогона r1 + новые
статистики поверх той же реконструкции:

- **V1 (z-маршрут)**: S3-ориентация 0.3814/0.4904/0.0137/0.0172 = лог прогона
  (0.381/0.490/0.014/0.017) — z_U128 восстановлен верно.
- **V4 (базисы)**: d_eff rematching max/min = 2.13 → **r_final = 7** — в точности как в
  прогоне (лог-строка «max/min = 2.13 > 1.2 -> r = 7»).
- **V2 (полный readout)**: RAW-вариант (сырая цель, как в AT2b.py) vs `per_pos_cos`
  артефакта: **max|diff| = 0.000e+00, 860000/860000 — бит-в-бит** (после совмещения
  thread-фиксации: AT2b.py шепчет OMP/MKL=4 + torch.set_num_threads(4); другой count
  тредов даёт f32-шум GEMM ~1e-5 в cos — поймано на первом запуске диагностики).
- **V3 (контроль)**: RAW-контрольный CI = CI артефакта, diff = 0.0 по всем 4 слоям
  (те же rng-потоки, B=1000, SEED=0).

Следовательно: все новые числа (CD-вариант, C1b/C1c) стоят на той же реконструкции,
что и вердикт r1. Любая интерпретация ниже опирается только на артефакт диагностики.

## C1 (⛔) вращающийся per-t базис + общий ridge — **ПОДТВЕРЖДЕНО**

Двухчастная проверка по ревью + доп. часть:

1. **C1a — «решающая проверка без ridge» (Eckart–Young)**: min over 16384 (l,d,t)
   отношения Σλ(top-r)/Σλ(weak-r) = **3899.6** (≫ 1). Алгебра split/eigh верна —
   бага в eigh/lift/J-селекции НЕТ. Как и предупреждал ревьюер, это тождество:
   top-r подпространство обязано давать больше энергии, чем weak-r.
2. **C1b — локальный per-(l,t) контроль (без пула по t; 32 дока на (l,t),
   per-doc LOO ridge, центрирование по докаМ)**:

   | слой | mean(top−weak) | frac t: top>weak |
   |---|---|---|
   | L6 | −0.0147 | 0.49 |
   | L12 | −0.0591 | 0.34 |
   | L18 | +0.1498 | 0.80 |
   | L22 | +0.2472 | 0.95 |

   Тот же слойный градиент, что и пул-контроль. Вывод: пулинг по t — НЕ основной
   конфаунд (локальный контроль повторяет картину); при этом базис остаётся
   per-(l,d,t) — вращение по докаМ здесь не снято.
3. **C1c — стационарный per-layer J-базис** (J_agg = mean_{d,t} J_{d,t}, top/weak из
   eigh(J_aggᵀJ_agg), полный пул-ridge, центрированная цель, k=0):

   | слой | cos_median top / weak | CI top−weak |
   |---|---|---|
   | L6 | +0.708 / +0.400 | [+0.271, +0.314] |
   | L12 | +0.734 / +0.524 | [+0.210, +0.265] |
   | L18 | +0.786 / +0.444 | [+0.302, +0.387] |
   | L22 | +0.825 / +0.503 | [+0.340, +0.384] |

   **top > weak на ВСЕХ 4 слоях с огромным маржином** (в 6–35 раз выше порога гейта).

Следствие: разделение top/weak **функционально валидно**; провал пререг-контроля —
артефакт конструкции «вращающийся per-(l,d,t) базис + один общий ridge на 31×128
позиций». Haar-аномалия (C4) — симптом того же: фиксированный стационарный базис
(Haar/PCA) читает текущий логит лучше, чем нестационарные J-координаты, которые
общий ridge не может по-разному взвесить на каждом t.

## C2 (⛔) нецентрированная обучающая цель — **ПОДТВЕРЖДЕНО, но не флиппер**

Код: `yf = vstack(y_all[d2] ...)` — сырые z-логиты, без центрирования; S6 проверяет
`intercept == mean(y_f)` (не `== 0`) и не детектирует этого. Механика (r1-анализ):
Xf t-центрирован ⇒ для k=0 веса W у сырой и центрированной цели одинаковы, и вся
разница — пер-док константный сдвиг **c(d) = ȳf − ȳ(d)**, добавленный к pc.

Масштаб (артефакт диагностики, `c2.offset_scale`):

| k | ‖c(d)‖ max / med | med ‖yc_t‖ | ratio med / max |
|---|---|---|---|
| 0 | 27.96 / 16.97 | 36.19 | 0.469 / 0.773 |
| 1 | 28.27 / 17.08 | 36.16 | 0.473 / 0.782 |
| 2 | 28.56 / 17.13 | 36.16 | 0.474 / 0.790 |
| 4 | 28.74 / 17.32 | 36.17 | 0.479 / 0.795 |
| 8 | 28.41 / 17.79 | 36.16 | 0.492 / 0.786 |

Сдвиг — почти половина типичной цели: он сжимает cos_c всех арм к ~0 (это и есть
«R²_c 0.72–0.78 при cos_median ≈ −0.01…−0.04» — см. C3).

**Но вердикт не переворачивается.** Контроль (k=0, top−weak, та же bootstrap-конвенция)
с **центрированной per-doc целью** (вариант CD):

| слой | RAW CI (прогон) | CD CI (центрированная цель) | pass (lower>0) |
|---|---|---|---|
| L6 | [−0.0131, −0.0004] | [−0.0356, +0.0208] | нет / нет |
| L12 | [−0.0066, +0.0033] | [−0.0085, +0.0242] | нет / нет |
| L18 | [+0.0133, +0.0315] | [+0.0710, +0.1145] | да / да |
| L22 | [+0.0406, +0.0740] | [+0.0676, +0.1241] | да / да |

`control_ok`: RAW = False, CD = **False**. Т.е. пререг-вердикт `SUBSPACE_CONTROL_FAIL`
**устойчив к C2**: даже с починенной целью per-t-контроль не проходит на L6/L12.
(C2 всё равно реален и исказил числа: cos_median top на L18/L22 выросли с +0.006/+0.086
до +0.163/+0.292, weak с −0.019/+0.012 до +0.019/+0.132 — маржа top>weak на глубоких
слоях была занижена.)

## C3 (⚠️) cos_median vs R²_c — **частично подтверждено**

Per (L,arm) k=0 (артефакт, `c2.per_arm_k0`; J-армы):

| L\arm | top: raw/CD cos_med | weak: raw/CD cos_med | R² raw/CD (top) | wcos raw/CD (top) |
|---|---|---|---|---|
| L6 | −0.029 / +0.041 | −0.010 / +0.056 | 0.775 / 0.995 | 0.031 / 0.035 |
| L12 | −0.011 / +0.061 | −0.018 / +0.047 | 0.773 / 0.993 | 0.035 / 0.060 |
| L18 | +0.006 / +0.163 | −0.019 / +0.019 | 0.752 / 0.972 | 0.070 / 0.158 |
| L22 | +0.086 / +0.292 | +0.012 / +0.132 | 0.715 / 0.935 | 0.126 / 0.243 |

- Разброд «R²_c 0.72–0.78 vs cos_median ≈ 0» — в основном **следствие C2** (offset
  вращает направление pc per док; R² по нормам живёт, медиана cos — нет).
- Weighted cos (веса ‖yc_t‖²) не меняет картины: он трекит cos_median (top ≥ weak на
  L18/L22 в обоих вариантах). «Metric-driven fail» как отдельная причина провала
  L6/L12 — НЕ подтверждён: и raw, и CD, и weighted-варианты дают тот же результат
  (L6/L12 — не проходят).

## C4 (⚠️) функциональный гейт J-кэша — **частично закрыто диагностикой**

- S3 (ориентация z-кэша) воспроизведена в точности (V1); S5 (lift-алгебра) пройден в
  прогоне; C1a показал, что split/eigh без бага.
- C1b/C1c показывают, что J-базисы **носят сильный функциональный сигнал** (стационарный
  top: cos_median 0.71–0.82 на k=0): J/lift в правильной ориентации, иначе этого
  быть не могло бы.
- Остаток: пересчёт J напрямую из форварда (полная функциональная проверка) — вне
  disk-only; отмечен как опциональный гейт T2.1c.

## Мелкое — принято (зафиксировано в results-доке)

- **S2 KL min = −3.14e-06** — численный артефакт (clamp/normalization при p≈q), не
  «отрицательная KL»; гейт на 2 доках (1.885e-08) от этого не зависит. Помечено в
  results-доке.
- **Floor uniform CI 0.100**: METRIC_UNINFORMATIVE — реальный риск, если бы control
  прошёл; сейчас дерево останавливается раньше — согласен.
- **N8** без сравнения с non-hit — неспецифичен (J-армы глобально тоже ≈0 на raw-
  метрике); report-only корректен.
- **lk4** немонотонный coverage (n=17/17/16/11/5) — non_informative корректен.
- **L23 k≥1 ≈ 0/отриц.** — sanity; намёк, что centered cos будущего ≈ 0 по
  конструкции metric/estimator — принят, учитывается в T2.1c (k≥1 там — уже
  «ответ на T2», а не sanity).

## Итог

1. **Прег-вердикт `SUBSPACE_CONTROL_FAIL` — стоит и устойчив**: воспроизведён
   бит-в-бит (V2/V3) и переживал бы замену цели на центрированную (CD: control_ok=False).
2. **Но интерпретация «разбиение top/weak функционально не работает» — неверна**
   (и ревьюер это правильно сказал, и диагностика это подтвердила): проваленный
   контроль конфаундирован (C1 — вращающийся базис + общий ridge; C2 — сырая цель).
   Функциональная валидность разбиения теперь **поддерживается доказательством**:
   стационарный per-layer J-базис — top>weak на всех 4 слоях, CI +0.21…+0.36 (C1c).
3. **Haar-аномалия объяснена** (симптом C1, не «случайный базис несёт смысл»).
4. **T2 не хоронить** — согласен; следующий шаг — **T2.1c с исправленным контролем**:
   - стационарный per-layer J-базис (J_agg = mean_{d,t} J_{d,t}; top/weak из
     eigh(J_aggᵀJ_agg)) — основной контроль;
   - локальный per-(l,t) контроль (C1b) — гейт против in-place вращений;
   - per-doc центрированная обучающая цель (C2);
   - primary: weighted cos (веса ‖yc_t‖²) рядом с median (C3);
   - k=0-гейт как в пре-реге (односторонний lower>0, AND-over-l); k≥1 — ответ на T2.
   Ожидание (из C1b/C1c, НЕ пререгистрация): контроль пройдёт на всех 4 слоях.
5. C5 — возражение (провенанс цел); мелкое — принято, зафиксировано.
