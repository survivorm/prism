## 1. Почему S0.1 в написанном виде даёт ложное «подтверждение»

S0.1 предписывает сравнивать «по позициям, где абсолютный индекс префикса совпадает». Но руки
берут **разные префиксы** уже после точки расхождения:

* Q1 — свободная генерация, контекст = prompt64 + **поток самого llama** (canon: `cache_prompt:
  false`, `n_predict: 384`; проверено в `results/e94/Q1.json` → `body_template`);
* Q2 — teacher forcing по **fp32-эталону**: `ids448 = prompts.ids(64) + REPLAY.gen_ids(384)`,
  `prompt = ids448[:k]`, `n_predict: 1`, `cache_prompt: true` (проверено в `experiments/exp94_q2.py:5-9`
  и дословно в запросе `raw_q2.json.tar.gz :: e94raw/q2_w4_k100.json`: `cache_prompt=True`,
  `n_predict=1`, `len(prompt)=100`).

Значит «совпадение абсолютного индекса» НЕ означает совпадения контекста. Контексты тождественны
только при `j < prefix_len` (где `j = k - 64`), потому что `prefix_len` — это и есть длина
совпадения потока llama с эталоном (`experiments/exp94_q1.py:99`, `pl = prefix_len(stream, cpu_gen)`).
За пределами этого окна срез меряет реальное расхождение потоков, а не «два прогона модели», и
первичный критерий `median|Δ| (Q1 vs Q2) > 3 × median|Δ| (r1 vs r2)` выполняется на нём сам собой.

## 2. Измеренные числа (raw_q1 + raw_q2, только id-совпадающие кандидаты из `top_logprobs`)

Докуки, у которых есть raw Q2: w0, w2, w4, w9, w13, w14 (2304 запроса).

| срез | n | совпадение эмиссии | флипов | медиана \|Δ logprob\| | max |
|---|---|---|---|---|---|
| контекст тождественен (`j < prefix_len`) | 502 | **502/502** | 0 в Q1, 0 в Q2 | 1.69e-03 | **4.79e-03** |
| контексты разные (`j >= prefix_len`) | 1522 | 159 | — | 4.55 | 18.4 |
| калибровка: повтор того же запроса r1 vs r2 | 122313 id | 6144/6144 | — | 5.75e-04 | 9.53e-03 |

Контаминированный срез (первая строка без ограничения) даёт медиану 2.079 — т.е. написанный S0.1
рапортовал бы «два прогона живы» с запасом в 3600 раз выше порога, и это была бы **артефактная
находка**: она целиком объясняется тем, что префиксы разные.

Чистый срез даёт отношение 1.69e-03 / 5.75e-04 = **2.94×** — чуть НИЖЕ порога 3×, при max 4.79e-03
против 9.53e-03 у простого повтора запроса. То есть численный вариант гипотезы «отчёт и выбор
считаются из разных прогонов, поэтому малое возмущение» **не подтверждается**: чтобы аргмакс уехал
на #2/#3, нужно перекрыть `log(p1/p2)` с медианой 0.6479 и минимумом > 0.4 по докукам (§11
анализа) — на два порядка больше наблюдаемого.

Побочный факт, который надо нести в артефакт: **до точки расхождения флипов нет** (0/502; правило
трёх даёт оценку сверху ~0.6%), а эмиссия двух рук совпадает 502/502. Порядок такой: пока отчёт
самосогласован, жадный выбор воспроизводит эталон; первое нарушение самосогласованности стоит
ровно там, где поток отделяется от эталона (`results/e94/Q2rank.json`, `divergence_alignment`,
11/11).

## 3. Что меняется в задании

1. **S0 остаётся, но с исправленным срезом.** Первичный критерий — отношение медиан **только по
   `j < prefix_len`**; контаминированный срез (`j >= prefix_len`) и общий срез reporteся отдельно
   и ни при каких значениях не трактуются как доказательство двух прогонов.
2. **Гейт покрытия «>= 1000 префикс-пар» недостижим законным путём** и потому не может блокировать
   руку B: легитимных пар ровно 502 (6 докуков, окно 1–53 позиции у разошедшихся + 384 у
  неразошедшихся). Новая формулировка: «>= 400 легитимных пар, и они должны быть выложены по каждому документу отдельно»; блокировка руки B по покрытию снимается.
3. **S0 понижается из прегейта в калибровку масштаба.** Он больше не может «усилить H2»: измеренное
   отношение 2.94× ниже порога. Различающая работа целиком на S1 (`post_sampling_probs: true`) и на
   руке B (`-ngl 0`). H3 (дефект конкретного GPU-пути) от этого не страдает: предсказание
   `F_cpu = 0` остаётся.
4. **Обязательная проверка поля в скрипте S0.** Первое воспроизведение дало 384 «флипа» на докуке:
   у `top_logprobs[i]` два поля — `token` (строка) и `id` (число), а верхний уровень — `id` (число);
   сравнение `c["id"] != c["top_logprobs"][0]["token"]` истинно всегда. Скрипт обязан иметь
   самопроверку на заведомо известной позиции (w4, `j = 6`: отчёт 318, выбор 310) и падать, если
   она не сходится.
5. **Масштабная оговорка в артефакт, дословно:** измеренная величина — «движок в двух режимах
   вызова» (у Q2 `cache_prompt: true` + `n_predict: 1`, у Q1 `cache_prompt: false` + декод на 384),
   а не «две копии одного вызова»; приписывать число 1.69e-03 конкретному механизму нельзя.
6. Окно S0 ограничено 6 докуками, у которых лежит raw Q2; расширять руку S0 новыми запросами
   **не** разрешается (иначе это уже новая рука со своим ревью).
